# 子代理协作方法

本技能帮助选择低协调成本的组织方式，不另设审批、完成或等待协议。角色所有权、实质停工、可靠报告和资源责任遵循共用系统合同；工具调用以当前声明为准。

## 先选工作单元，再选代理

- 用可独立验收的交付切分，而非按文件数量或为了填满容量拆分。比较省下的工作与新增上下文、启动、交接、审查和合并成本；紧密串行的小工作通常直接处理更快。
- 只在真实依赖存在时记录依赖图。先确定共享接口、输入输出与错误语义，再划分互斥写范围；探索只回答具体未知问题，不重做已有调查。
- 限制同时在途的工作，以可及时接收、审查和整合为准，不把代理全部忙碌当成效率。优先解除关键路径阻塞、完成已开始的工作；独立成果就绪后无需无理由等整批。

## 选择执行环境

从实际可用目录按职责、工作区模式、工具能力与冻结权限选择 Profile，不靠名称猜能力。模型选择服从当前分发模式和偏好，不在这里维护模型清单或价格表。

派发参数的必填条件以工具声明为准，不猜默认值。失败先核对原回执、当前声明与已知路由，只纠正有依据的差异。相同原因没有新证据时停止重试，不通过放宽写范围、创建空任务探针或扫描用户 home、配置与日志碰运气；需要未获授权的诊断或目录信息不足时，报告阻塞。

| 工作关系 | 可考虑的组织方式 | 主要代价 |
| --- | --- | --- |
| 互斥文件、共同基线、低集成风险 | directory 分工，明确写范围 | 必须协调共享依赖及 Git 写入 |
| 需要物理隔离、独立编译或提交 | worktree | 基线、合并冲突与工作树回收成本 |
| 跨模块耦合、难以拆开验收 | 先收敛契约，再集中实施或接管 | 交接范围与责任必须清楚 |
| 需要独立审查 | review 绑定实际交付者 | 被审版本必须能核对 |

这些不是固定阶段或人数配方。没有可绑定的执行者时，不为获取 review 工作区虚设交付；主代理直接核对自己的成果，必要时只读探索提供事实意见，不冒充正式审查批准。

## 自包含派发与交接

消息可按以下结构组织，只展开相关部分，不用空模板凑篇幅：

1. **交付**：目标、非目标、可观察的完成标准。
2. **事实与契约**：基线、入口、已确认决定、接口及错误语义；必要时给关键状态转换伪代码，明确哪些只是建议。
3. **所有权**：依赖、允许改动的范围、禁区、Git 与外部操作授权；不要只给父会话链接。
4. **验证预算**：需证明的行为、已有证据、必要检查及各自唯一执行责任方。最终入口已覆盖的同一行为，不再默认给每个模块追加导入断言或重复样例；可将子任务限定为静态核对、由整合方执行集中验证。尊重用户给定范围，把“未执行”与“失败”分开。
5. **交付证据**：实际版本、差异、结果与原始产物定位；用当前会话的产物位置，不要求写入父代理临时目录。

探索补充来源和时效要求；正式审查提供完整适用计划及调整、目标身份和版本。接管时移交上述信息及未解决事项，明确原责任人停止哪些写入。资料调查可提供建议，不能将角色保留的架构与方向性写入伪装成“草稿任务”。

## Git 与验证的短反馈循环

- 从核实的基线使用短期主题分支；开始前检查脏改动和 worktree 占用，不通过强制切换、重置或暂存他人成果消除障碍。同一 checkout 的 Git 写操作由明确责任方串行处理。
- directory 交付核对实际差异，不做模拟合入。worktree 交付按真实提交及依赖整合，保留返工现场；只在必要时更新基线，不无限追赶与任务无关的主线变动。
- 共享源码在相对稳定窗口集中执行昂贵构建、生成和检查；构建锁不证明版本稳定。独立且不受其他修改影响的验证可先行，不把小批成果重新攒成大批等待反馈。
- 交接证据说明“范围、版本、环境、命令和结果”。新差异、依赖、生成输入或配置影响原结论时，只补受影响证明；换阶段或换代理本身不是重跑理由。测试设计方法使用适用的测试技能，本技能不维护另一份测试清单。
- 有明显跨模块风险时尽早核对接口，低风险小改动可集中审阅；审查和验证以解决实际风险为目的，不按每个 commit 或代理机械增加轮次。问题交最适合且明确接管的责任方，避免在原作者间反复转述。

需要解释以上方法的依据和适用限制时，再读[工作流与 Git 研究依据](references/flow-and-git.md)；普通协作不必加载。
