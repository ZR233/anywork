# 测试设计与分层

配合 [技能正文](../SKILL.md) 使用。以下方法按行为和执行边界组织，使用当前项目已有的语言、框架和测试入口实现。

## 把契约变成数据与断言

契约已经明确为“到达截止时刻即过期”时，从规则独立列出边界：

| 场景 | 当前时刻 | 截止时刻 | 预期是否过期 |
| --- | --- | --- | --- |
| 截止前 | 9 | 10 | 否 |
| 恰好截止 | 10 | 10 | 是 |
| 截止后 | 11 | 10 | 是 |

这组数据能识别遗漏等号的错误。使用框架已有的参数化能力或简单遍历，调用真实被测入口并比较结果。
重复的准备与调用可以收拢到帮助函数，但期望值仍明确留在数据中；失败时显示场景、输入、期望和实际值。
不同场景需要不同环境或诊断时保留独立用例，不为减少函数数量强行合并。

对具备通用不变量的行为，可补充属性验证。例如分页完整遍历应保持约定顺序、无遗漏、无重复；
仍需独立样例确认游标包含/排除等语义，不能仅用生产排序或分页逻辑计算“正确答案”。
随机测试记录可复现输入，不能用偶然未失败代替确定性边界证据。

## 验证操作及其后果

有状态行为按“准备初始状态 → 执行真实操作 → 观察结果与副作用”组织。
例如契约要求非法修改被拒绝且原状态不变，就同时核对错误、完整相关状态及未发生的副作用；
只验证收到任意错误，可能放过先破坏数据再报错的实现。

中间状态、事件顺序或交互次数只有在消费者可观察或属于协议承诺时才作为判定。
保留必要的提交、回滚、取消、重试与释放规则，不逐步断言内部容器和辅助调用。
历史数据测试使用真实历史编码，分别判断迁移成功后的语义保全和失败后的回滚责任。

## 选择能够发现目标错误的最小层级

| 目标风险 | 合适的边界 | 无法由该证据自动推出的结论 |
| --- | --- | --- |
| 解析、算法、规则、不变量 | 可独立调用的模块或组件 | 真实部署、存储或服务连接正确 |
| 多组件装配、调用与错误映射 | 使用真实内部组件的集成 | 外部环境兼容、完整用户流程正确 |
| 两端对消息、格式、顺序或版本的理解 | 双方实际使用的协议契约 | 全部业务副作用正确 |
| 数据库、文件、网络、进程或平台行为 | 对应真实系统边界的隔离集成 | 未运行的其他平台或第三方服务兼容 |
| 用户关键流程 | 正常用户或命令入口上的少量端到端验证 | 全部局部规则组合已覆盖 |
| 视觉判断或仍在探索的体验 | 实际环境的人工操作与观察 | 自动回归保护已经建立 |

层级按风险选择，不由语言、文件夹或框架名称决定；表格不是必跑流水线。
低层适合枚举局部边界，上层保留低层无法提供的装配、协议、真实时序和用户流程证据。
界面测试复用生产组件并执行实际输入、点击或滚动，提供受控数据；不要复制简化界面或直接改私有状态绕过被测操作。
截图或快照只锁定需要保护的稳定呈现，不自动成为所有界面变更的交付条件。

## 控制异步推进与资源

- 先确定任务、时钟、事件队列和资源各由谁拥有；使用项目已有控制点注入时间、输入或失败。
  不为测试新增通用调度框架或复制生产状态机。
- 等待明确事件或完成条件，超时只负责暴露无法完成。虚拟时间只推进其控制的调度器，
  不证明真实网络、外部进程或其他时钟已经推进；界面渲染静止也不证明后台任务完成。
- 验证“取消后没有提交结果”时，先确认任务进入目标阶段，取消并等待契约约定的确认，
  再受控释放迟到结果并推进到可确认处理完成的阶段，核对状态、事件与资源。
  刚发出取消就立即检查没有结果，可能只证明错误尚未来得及发生。
- 每用例独立管理目录、数据库、端口、进程、订阅和任务，避免共享全局配置或依赖执行顺序。
  失败路径也要保留原始错误并释放所属资源，不通过吞异常、提前完成或抛弃后台工作制造成功。

## 使失败和跳过可见

使用当前框架明确支持的跳过或分组机制记录原因，并保留实际执行入口。
显式选中的用例缺少必要环境时清楚报错；不要提前返回成功，也不要将发现数量为零当作验证通过。
调整测试组织或运行器后核对发现、选择、实际执行和失败传播；参数化与拆分不能丢失独特场景。
