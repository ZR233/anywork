# 测试审计与成本

沿用 [技能正文](../SKILL.md) 的契约与风险判断。审计目标是保持必要失败信号并降低长期成本，
不是删除固定比例、把全部测试移到某一层或追求某个覆盖率分数。

## 审计一个完整行为

先读被保护的契约、正常调用方、已有回归背景和 CI/发布入口，再决定：保留、增强/重写、下移、移出日常门禁或删除。
用一句话说明目标风险、现有判定及去向即可，不要求为每条断言建立台账。

| 现有形态 | 默认处理 | 需要保留的真实例外 |
| --- | --- | --- |
| 构造后回读原字段、无逻辑字段访问 | 删除独立测试或由已有行为覆盖 | 转换、校验、默认策略、权限等独立语义 |
| 每个函数一个用例、逐项复制生产配置清单 | 按规则与等价类重组 | 真实部署兼容与历史特殊边界 |
| 固定私有调用顺序、内部字段或中间容器 | 从稳定行为边界重写 | 事务、协议、事件顺序本身是契约 |
| 只调用 fake，或者在测试中重做算法 | 让输入经过真实生产逻辑，独立推导期望 | 独立参考实现有明确来源且比对真实实现 |
| 无断言、恒真、只求非空或任意成功 | 补可识别目标错误的结果判定，否则删除 | 明确只负责启动/存活的探针 |
| 几十个同构正常样例 | 保留等价类与边界，数据化重复准备 | 不同样例保护了不同故障 |
| 巨大日志/对象快照、每次自动更新 | 收窄到稳定契约并审查差异 | 完整格式确实是用户承诺 |
| 高层重复低层所有规则组合 | 下移组合，高层保留装配与关键旅程 | 高层增加协议、并发、跨语言或平台证据 |
| 固定休眠、共享目录或全局环境、随机重跑才绿 | 隔离资源与同步条件，修复根因 | 独立统计/压力实验有明确判定 |
| 已无功能或消费者的旧用例 | 连同专属支撑删除 | 仍承诺的数据迁移、外部版本或平台支持 |

用合成名称和最小夹具验证发现、优先级、解析与失败传播，不镜像当前产品名称/数量列表。
但用例选择器、必要运行配置、协议完成条件和零用例检查是执行保障，不能当作清单冗余删掉。
历史问题的独特触发条件不能因名称含平台、配置或问题编号而删除。

## 判断跨层是否重复

只有行为、判定与可发现故障实质相同，且高层没有增加真实装配、协议、并发、部署或生命周期证据时，
才按重复处理。纯规则测试能定位算法错误，真实数据库测试能发现约束/事务问题，它们执行相同代码仍有不同价值。
保留最低成本的充分证明，也保留有价值的快速定位信号；不简单地“已有端到端就删全部单测”。

先增强替代用例，确认仍能发现原错误，再删除被替代用例。无法确认等价时保留并记录不确定性，
不要以少了几行断言声称完成去重，也不要用泛化命名掩盖没有泛化的实例检查。
必要时对受影响的少量分支做局部反例或变异抽检，不要求每次全仓运行变异测试。

## 清理闭环

- 删除失去消费者的测试数据、替身、帮助函数、空测试入口、测试依赖和失效命令/文档引用。
- 核对保留用例的发现、过滤、实际运行和失败状态传到最外层，不能只看退出码为零。
- 移出日常门禁的性能、压力、真实服务测试保留执行条件、负责人和结果判定，明确在何时运行。
- 功能风险与执行矩阵分别审计；不能以“相同测试在多平台重复”为由删掉独有的操作系统行为验证。

## 先区分慢在哪里

固定源码、工具版本、启用功能、目标平台、运行配置、机器与缓存状态，分别观察；仅测量项目实际存在的阶段：

| 耗时来源 | 先找证据 | 只在确有收益时调整 |
| --- | --- | --- |
| 构建或加载 | 依赖图、重复构建/初始化、冷/热启动与阶段耗时 | 减少无用测试依赖和无关模块加载，缩小受影响范围 |
| 编译或链接（如有） | 多入口是否反复编译或链接同一依赖集合 | 在相容边界调整目标组织；检查局部重编译与隔离代价 |
| 测试执行 | 慢用例、等待方式、资源竞争与失败日志 | 控制时间、隔离数据、减少重复流程、调整运行器调度 |
| 环境准备 | 数据库/服务启动、外部工具准备与产物复用 | 复用已有可靠准备机制，保持状态隔离和失败传播 |
| CI | job 依赖图、相同源码/平台/参数是否重复执行 | 删除确实重复的工作，保留各平台或发布独有风险 |

静态分析、类型检查或构建通过不等于测试通过。使用项目已有的计时、性能分析或运行报告，
区分测试准备与实际执行；不要仅凭一个总耗时就断言某阶段必然是瓶颈。
比较冷启动和增量迭代，不能拿不同缓存状态宣称提速；需要冷缓存时使用隔离目录，不清掉用户正在使用的缓存。

测试框架、运行器、构建工具、并行和缓存配置的调整遵循当前平台能力与实测收益。
不默认安装工具，不修改系统安全排除项，不统一关闭文档示例、测试入口或平台验证。
合并入口可能减少准备或构建成本却拖慢局部运行；并行可能减少等待却增加内存和资源争用，需比较真实使用场景。

## 报告结果

说明新增/增强或删除了哪种风险证明、选择了什么层级、实际命令/环境/结果，以及未验证部分。
性能优化只有同口径测量后才给提升数字；只改规范时说明规范已统一，不宣称编译或 CI 已实测提速。
找到足够证据后停止扩测；代码覆盖率只帮助发现盲区，不代替行为判定。
