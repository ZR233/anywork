# Dart 与 Flutter 测试

配合 [技能正文](../SKILL.md) 使用。采用项目已有状态管理、Client 接口、fixture 和官方测试工具，
具体路径与启动命令由当前项目决定；不为写测试替换框架或建立另一套应用。

## 按目标选择边界

| 要保护的风险 | 首选验证 | 该结果不能证明什么 |
| --- | --- | --- |
| Dart 解析、数据转换、分页、状态计算 | 纯 Dart 单元/组件测试 | 原生插件、FRB 与真实存储 |
| 组件布局、输入、选择、加载/错误呈现 | 使用生产组件的 `flutter_test` widget 测试 | 系统窗口、IME、原生资源与真实后端 |
| 受控请求/事件与 Client 状态协作 | 在稳定传输边界注入响应，运行真实 Client | 真实服务/桥接协议与部署 |
| Flutter 到原生/FRB、存储、进程的接线 | 项目原生入口上的官方 `integration_test` | 未执行的其他平台与真实第三方账号 |
| 视觉判断、平台窗口与探索中的流程 | 官方预览、Inspector/MCP 或实际平台操作 | 自动回归保护已经建立 |

UI 测试通常不需要编译或启动 Rust bridge。通过已有 Client/Provider 边界提供受控数据，
保留真实组件、状态变化与用户操作；不要复制一套简化 widget 来测，也不要通过直接改私有 store 绕过被测操作。
跨层用例保留少量主路径和独特失败边界；局部输入组合放到能真实识别该错误的低层。

## 断言用户行为

先创建场景，执行输入/点击/滚动，再断言可观察内容、交互结果或语义。
例如提交失败时，检查错误呈现、输入保留和能否重试；只找到一个按钮并不能证明提交功能。
名称描述场景及结果，使用稳定的语义或项目现有 key；不把组件内部树结构、无关文案或框架自带行为写成契约。
无障碍、焦点、翻译或文案本身是要求时，可直接验证它们。

不同视口、文字缩放或加载状态用于覆盖确有差异的布局风险，不复制相同点击路径凑平台矩阵。
golden 只保护需要逐像素对比的稳定呈现，固定相关字体/尺寸并审查差异；不把每个 UI 改动都变成图片基线。
人工截图说明场景与来源，不能替代行为断言，也不能证明未实际操作的原生层。

## 异步与生命周期

- 等待明确的 Future、事件或目标控件状态；用有界 pump 推进需要的帧，超时给出未满足条件。
- `pumpAndSettle` 只等待调度帧收敛，不保证所有 I/O、原生任务或数据已经就绪；持续动画也可能使它永不收敛。
- 区分 FakeAsync 与真实事件循环。`tester.runAsync` 适合确需真实异步的操作，不能机械包住任何关闭 Future；
  若该 Future 等待的微任务仍需测试区推进，会形成等待环。先核对 Zone/任务 owner，复用项目已有等待工具。
- 不在被另一个 pump 驱动的回调中嵌套受 guard 保护的操作或断言；等待完成后再断言并传播原错误。
- 每用例独立创建并释放 Provider/Client 容器、订阅和流；按真实所有权卸载 widget、等待在途任务并确认资源收束。
  不通过提前 complete、丢弃 Future、吞异常或重新创建对象伪造正常关闭。
- 惰性列表通过真实滚动建立所需子树，不为测试去掉生产懒加载；最终结果断言不能掩盖异步错误。

## 回归与真实集成

复用已有 fixture 和生产入口。fake 负责模拟协议输入或环境故障，不负责实现本应由产品完成的分页、合并或恢复。
边界变更同时核对序列化、错误传递、取消和资源所有权；规则测试与真实跨桥接线测试即使覆盖相同行也不一定重复。
需要原生环境的用例在相应 runner 中实际执行，不能因缺环境而从测试函数提前返回 PASS。

使用 `test` / `flutter_test` 官方 skip 机制时写明原因，并提供启用条件与实际执行入口。
检查过滤条件、发现数量、失败及跳过结果；没有运行的真实设备/平台/供应商保持未验证。

框架行为核对 [Flutter 测试概览](https://docs.flutter.dev/testing/overview)、
[`pumpAndSettle`](https://api.flutter.dev/flutter/flutter_test/WidgetTester/pumpAndSettle.html) 与
[`runAsync`](https://api.flutter.dev/flutter/flutter_test/WidgetTester/runAsync.html) 的当前官方契约。
