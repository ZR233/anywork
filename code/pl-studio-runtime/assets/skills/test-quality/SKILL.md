# 高价值测试

用最少且充分的证据保护真实行为，让错误实现失败，让不改变行为的重构容易进行。
这是糊来帮提供的通用测试技能；具体命令、工具链、测试目录、平台与授权范围读取当前项目约定。
不以测试数量、覆盖率或固定测试比例为目标，不因采用本技能而增加审批、依赖或全仓检查。

## 先确定要保护什么

动手前结合需求、调用方和已有测试，明确以下三点；简短说明即可，不建立额外表单：

1. **可观察契约**：给定什么输入或操作，应该返回什么、改变什么，失败或取消后必须保持什么。
2. **具体错误**：哪种合理的错误实现会破坏契约，例如漏掉阈值等号、吞掉错误、重复提交或未释放资源。
3. **已有保护与最小边界**：已有用例能否捕获该错误；能增强已有用例时直接增强，缺少独立信号时才新增。

从需求、协议、独立手算样例或已确认的正确行为推导期望值。当前输出只能提供线索，不能自证正确。
不要把测试组织成生产函数清单、配置清单或 issue 清单；也不要为减少数量把无关行为塞入一个巨型用例。

## 按契约选择开发轨道

| 当前情况 | 执行动作 | 留下的保护 |
| --- | --- | --- |
| 输入、规则和期望已明确，有边界或状态裁决 | 轨道 A：先写代表性失败用例，再实现 | 数据驱动的规则、边界与不变量测试 |
| UI、业务编排或外部集成仍需探索才能确定行为 | 轨道 B：先在隔离环境跑通并确认，再锁定稳定边界 | 最少的主路径与关键失败回归证据 |
| 复杂裁决与文件、网络、时钟、进程混在一起，难以稳定验证 | 先寻找已有接缝；必要时局部拆开纯裁决与 I/O，再分别用 A/B | 纯逻辑证据与真实连接证据各自清楚 |
| 无条件赋值、无语义转发、格式或说明文字调整，没有独立风险 | 使用适用的静态检查和已有行为证明 | 通常不新增独立测试 |

按**契约是否明确**分流，不按“业务代码”“有 I/O”或文件名机械判断。明确的集成契约也可先写失败测试。
代码短不等于风险低：协议字段、默认策略、权限、迁移、错误传播与资源释放仍可能需要行为保护。
拆分仅服务本次风险，不把全局重构、引入依赖注入框架或增加一圈 trait 设为修复前置条件。

## 轨道 A：数据驱动的契约 TDD

1. 先列少量等价类和关键边界：典型成功、空/零、阈值及两侧、非法输入，以及失败后的状态。
   只选择该契约实际存在的情况，不机械凑齐分类或穷举所有正常值。
2. 在实现前运行这些用例，确认失败指向尚未满足的行为。接口尚不存在造成的编译失败是准备阶段，
   补齐可编译入口后再检查断言；编译失败、环境错误与零用例不算行为失败证据。
3. 实现规则并使测试通过。同构调用已经重复时，用数据表或一个 `check(input, expected)` 隔离调用细节；
   单个简单用例直接写清楚，保留样例标签与失败诊断，不为形式增加帮助函数。
4. 有可独立描述的不变量时，按需使用已有属性测试工具；保留失败 seed/最小样例。
   只验证编码再解码的往返一致性可能漏掉双方共有的错误，还需独立样例或协议判定。
5. 重构后保留稳定行为测试，删除只服务编码探路的临时断言、重复样例和无人使用的夹具。

表驱动循环是正常组织方式；不要在测试里复制生产算法，或根据实际输出动态选择期望值。
测试完整的有意义行为，不为每个私有辅助函数建立绑定实现结构的测试。

## 轨道 B：探索后锁定行为

1. 先用项目现有预览、调试或隔离集成入口验证实际流程，确认正确输出与错误边界。
   不用真实用户数据或付费服务替代可控环境；真实外部验证遵循当前任务授权。
2. 主路径确认后，复用或补充最窄稳定入口上的自动保护，例如命令结果、持久化状态或用户交互。
   已有测试能证明时无需再加一条端到端用例；不默认录下完整日志、整个文件树或全屏快照。
3. 发现故障时，优先把最小复现放进已有行为测试，或新增确实缺少的回归用例。
   能稳定复现时，先确认修复前因目标断言失败，再修复并通过；探路日志/断点帮助找风险，
   不意味着每个观察点都应永久变成测试。
4. 按本次影响补充必要的失败、取消、重试、提交/回滚和释放证据，不把成功路径通过当作全部正确。
5. 无法稳定自动化时，给出实际人工操作、观察结果、限制和剩余风险；修复可以继续，
   但不能用缺少断言的测试、静默跳过或模型自述冒充自动回归已建立。

同一修复不必永久增加一个函数；把触发条件并入已有用例时，仍保留独特的失败能力和可定位诊断。

## 让断言识别错误

- 验证返回内容、错误类别、对外事件、落盘状态、必要顺序及资源后置条件。
  `is_ok()`、非空或“未崩溃”只在接受/存活本身就是目标契约时足够，通常还须核对业务结果。
- 从正常消费者入口或稳定模块边界进入真实生产逻辑。Rust 模块内可测试私有纯算法与不变量；
  不为测试扩大生产可见性，不通过复制或重新包含生产源码绕开真实装配。
- 只锁定契约相关内容。快照应短小、确定、可审查；只规范化不影响契约的时间/随机字段，
  不删除有意义的顺序、身份或错误信息。先确认行为变更，再更新快照，禁止批量接受当前输出凑绿灯。
- 不用源码文本搜索证明运行行为，不只验证 fake 自己，也不复制生产计算生成期望。
  文件布局、生成格式或命令选择本身就是产品契约时，才在对应边界验证这些内容。
- 自问“把什么行为改坏，这条测试会失败？”对缺陷回归优先取得修前/修后对照；
  对仍有疑问的高风险断言按需做局部故障注入或变异抽检，不把全仓变异测试设为默认门禁。

## 替身与真实边界

优先使用快速、确定、可隔离的真实对象；环境难以控制时，在已有稳定边界使用 fake（轻量有状态实现）、
stub（固定输入/失败）或 mock（交互判定）。替身负责提供环境，不能把被测决策也替换掉。

- 不把内部方法调用顺序和次数翻译成测试脚本；重构后行为没变，测试应尽量不变。
- 当交互本身是契约时可以断言，例如取消后不再发请求、不重复产生副作用、缓存避免访问、协议顺序。
  能观察结果时同时验证结果，不只核对“调用过一次”。
- 复杂存储/协议 fake 可能与真实实现漂移，保留相应真实集成或共享契约验证；简单输入 stub 无需另建体系。
- fake 的通过不证明真实数据库事务、FRB 接线、子进程退出或供应商兼容。需要保护该边界时保留少量真实验证。

## 确定性与执行可信度

- 每个用例拥有并回收自己的临时目录、数据库、端口、进程、订阅和任务；不依赖顺序或其他测试残留。
- 用明确通知、屏障、状态条件或适用的虚拟时间推进；超时是失败兜底，不用任意 `sleep` 猜测就绪。
  验证取消、异步错误和关闭的最终状态，不能丢弃 Future、后台任务或错误只让外层返回成功。
- 慢、联网或依赖专用设备的测试应显式标记、分组或移到有条件的入口，并说明如何实际执行。
  禁止环境变量未设就直接 `return` 显示 PASS；显式选中的测试缺前置条件应清楚失败。
- 区分 passed、failed、ignored/skipped、cancelled、未执行。核对选择器确实发现并运行目标用例；
  编译通过、零用例、日志采集完成与预算耗尽都不能代替测试通过。
- 不用放宽断言、无限重跑、延长等待或串行整个套件掩盖问题；需要隔离不稳定测试时记录原因、修复责任与恢复条件。

## 清理与成本

按契约、故障类型和真实边界判断重复，不按覆盖到相同行或长时间未失败删测。
去掉无风险的字段回读、清单镜像、替身自测和实现脚手架；保留或迁移仍独有的回归信号。
删除时同步清理只服务该测试的夹具、依赖、目录入口和失效文档，确认其他消费者仍可发现并执行。

区分编译、链接、运行、环境准备与 CI 重复调度。先测瓶颈，再选择合并目标、调整并行或降低环境成本；
不统一关闭 doctest、测试 target 或平台检查，不为采用本技能更换运行器、链接器或构建参数。

## 交付

简要说明保护了什么、采用或复用了哪些证据、运行了什么及结果，并列出未验证范围。
删除/下移测试时说明独特信号由谁继续保护；只改技能、文档或低风险胶水时说明为何相关静态检查已经足够。
选择足以解决具体风险的验证后停止，不把参考命令展开成每次任务的全量清单。
