# 17 - Studio 存储、迁移与诊断

本文是 Studio 文件布局、目录加载、会话激活、历史/调用数据库、迁移和恢复诊断的唯一权威源；
Thread checkpoint 与 writer 合同见 [15](./15-session-storage.md)，安全边界见
[04](./04-security.md)。

本次是大版本的会话存储断代：旧版本的会话目录、目录摘要、产品库、调用统计与迁移状态
保留在旧路径，**不导入、不激活、不自动归档或清空**。新运行时在独立的 `v2/` 数据根
创建新的会话与目录。`config.toml` 与用户 Agent Profile 等非会话配置沿用原位置，
account 配置升级继续由配置模块负责并保护凭据引用；旧会话转换不属于本版本的启动
路径或验收目标。

## 17.1 数据布局

Studio home（`~/.anywork/`）的布局为：

```text
~/.anywork/
├── config.toml                     # account/model/Skill 配置
├── agents/<agent-id>.toml          # 用户 Agent Profile
├── modes/<mode-id>.json            # 自定义 Mode 定义，沿用用户级配置边界
├── v2/
│   ├── settings.toml               # 本版本 UI 与产品设置
│   ├── workspaces.toml             # 本版本 Project/Workspace 定义
│   ├── catalog.toml                # 本版本新会话目录摘要
│   ├── model-catalogs/<account-key>/<query-key>/model.json # 各账号最后成功模型声明
│   ├── bots/<bot-id>/              # 机器人管理根；稳定 ID，不使用平台身份作路径
│   │   ├── config.toml            # 版本化非敏感配置与独立 config revision
│   │   └── state.sqlite           # 版本化会话映射、受理身份、配对及发送操作
│   ├── projects/<project-key>/     # project-key = 稳定 Project id 的 sha256
│   │   ├── project.toml            # 版本化项目身份与归属清单
│   │   └── sessions/<thread-key>/  # thread-key = 稳定 Thread id 的 sha256
│   │       ├── session.toml        # 会话身份、父子归属与固定工作区绑定
│   │       ├── history.sqlite      # 历史、当前配置/上下文与 checkpoint 同事务
│   │       ├── attachments.toml    # 会话附件目录，持久路径相对于本会话
│   │       ├── blobs/              # 可靠附件正文，旧 checkpoint 子目录迁移后回收
│   │       ├── thread-resources/   # 内容寻址的可靠工具输出和媒体
│   │       └── scratch/            # 宿主自有传输和处理暂存，不供模型直接操作
│   ├── calls/
│   │   ├── calls.sqlite            # 有界调试索引与轻量统计投影
│   │   └── logs/                   # 版本化滚动 JSONL 调试日志
│   └── migrations/                 # 仅本版本迁移状态
├── migrations/                     # 旧版本迁移状态，保留但不读取
│   ├── session-migration.json
│   ├── layout-publication.json     # 仅布局切换在途时存在
│   └── session-archive/
├── startup-recovery.toml           # 可接续的整体启动恢复记录
├── startup-backups/                # 不可覆盖的整体启动备份
└── studio/                         # 产品库与进程级资源
    ├── v2/
    │   ├── studio.sqlite           # 本版本产品库
    │   └── attachment-drafts/      # 尚未归属 Thread 的附件草稿
    ├── studio.sqlite               # 旧版本产品库，保留但不读取
    ├── runtime.lock                # 跨进程独占锁
    └── skills/.system/             # 构建期预置系统 Skill
```

canonical 会话、调用与迁移目录位于 `~/.anywork/v2/`；产品库位于
`~/.anywork/studio/v2/`，进程级锁与 Skill 仍位于 `studio/`。
`<project-key>` 与 `<thread-key>` 分别是 Project id、Thread id 的 SHA-256 十六进制摘要，
不是显示名称、工作目录或原始 id。项目改名不移动数据；本地、SSH 及不同 SSH 别名的同路径
项目按各自稳定 Project 身份隔离。root、child 与 reviewer 各有独立的 Thread 目录。
`<account-key>` 与 `<query-key>` 是账号和查询身份的安全摘要，不作为可逆凭据表示；账号 ID
原值不变时保留已有账号目录摘要，不因术语迁移另起缓存命名空间。
旧共享库 `studio/sessions.sqlite`、旧逐产品 `studio/calls.sqlite`、旧全局
`studio/attachments/` 及旧迁移 staging 目录原样留在旧数据根，本版本不读取或切换它们。

会话数据库始终位于应用 home，不写入本地或 SSH 项目工作区。进程启动前取得
`~/.anywork/studio/runtime.lock` 的跨进程独占锁；锁文件 PID/宿主/启动时间只用于诊断，所有权
由 OS 文件锁决定。

产品库、历史库与调用库共用原生文件路径的连接边界。数据库文件名通过驱动的类型化文件参数
传入，不拼接为连接地址，也不剥离 Windows 规范路径前缀；目录中的非 ASCII、百分号和地址
保留字符按真实文件名处理。打开前只解析已存在的父目录，写入方负责创建目录，读方保持只读。
只读、读写已有文件与可创建三种打开模式必须显式区分，路径解析不改变连接池、事务或保存语义。

桌面宿主在创建 Flutter engine、窗口及业务资源前取得同一把锁，并将锁租约交给运行时使用。
锁的宿主所有权持续到桌面进程结束；启动失败、重试和运行时 Clean 收束只释放各自引用，
不会提前放开目录。Server 与测试宿主仍在其运行时收束完成后释放锁。锁文件存在不表示占用，
崩溃后由 OS 释放锁，不通过删除文件抢占实例。

桌面实例 key 来自整个 Studio home 的物理目录身份（Windows 卷与文件 ID、Linux 设备与
inode），不含程序位置、版本或构建模式；指向同一目录的符号链接、junction 与路径别名
属于同一实例。该 key 只用于原生窗口激活路由，数据独占仍只由上述文件锁裁决。

`catalog.toml` 只保存轻量目录摘要：Thread/parent/workspace 身份、title、mode、role、工作区
模式和地址、创建/更新时间、归档状态与 `status`。它不保存当前上下文、完整 Turn、历史正文、
请求/工具结果或执行状态，也没有独立的活动摘要字段：侧栏活动指示由内存热集合覆盖，持久
`status` 只反映最后一次已提交的目录状态。目录摘要可用于侧栏，不可用于判断工具或 Turn 当前
是否仍在运行。

会话目录另保存可空的 `last_user_message_at`（wire/TOML 为 `lastUserMessageAt`，Unix 秒），
表示服务端最近一次成功受理用户消息的时间。已受理的排队输入计入，拒绝的输入不计入；
用户主动回答提问或确认/修订计划所产生的已受理续接也计入，不因其模型呈现为 hidden 而排除。
权限决议、程序自动生成的续接及无新输入的重复决议不作为用户新消息。
代理通知、系统注入、工具结果及恢复重放均不推进它。`updated_at` 仍表示普通更新，不能用于
列表排序。目录冷分页、搜索与 GUI 列表统一按 `(last_user_message_at.unwrap_or(created_at), id)`
降序排列；同秒以 ID 稳定破平，无用户消息的新会话按创建时间排列。分页游标使用独立的新版本，
不将旧更新时间游标解释为新排序键。普通元数据或运行状态写回须保留最新的用户消息时间，
迟到快照不得使该字段回退；它通过现有目录事实发布和保存链路传播，不建立 GUI 本地事实源。

当前 v2 目录与 SQLite 镜像的结构升级保留全部已有数据。旧目录缺失最近用户消息时间时，
迁移为缺失值，不以普通更新时间伪造用户发送时间；旧会话按创建时间排序，直到下次用户
消息成功受理时更新元信息。排序时间仅由发送受理链维护并经现有目录保存链路持久化；
保存失败通过已有错误和重试机制暴露，正常重启直接读取目录元信息。
不为排序扫描历史记录，也不在打开会话时读取历史推导或回填时间，不新增历史查询或索引，
不批量激活会话，不读取隔离的旧版本数据根。

`workspaces.toml` 保存 Project/Workspace 定义和稳定引用；物理 worktree ownership 使用版本化
lease 记录，保留 `prepared | active | preserved | cleanupRequested | cleaned`、owner Thread、
repo/path/branch/base/revision。目录展示与物理 ownership 是不同职责，不能互相推导。

机器人独立管理根 `v2/bots/` 位于同一 v2 备份范围，每个 `config.toml` 保存版本化 desired
配置及独立 revision，`state.sqlite` 保存版本化会话映射、可靠受理身份和发送操作记录。
配置中的凭据版本引用和必要的提交恢复身份不含 secret；实际版本化材料仍只在系统凭据
或进程 lease。配置引用发布、结果待确认与未引用材料回收分别恢复，不能假定原子写入
报错就代表目标文件从未被替换。未决提交收敛前保留所需版本并封闭该机器人准入，见
[27.2](./27-bots.md#272-管理配置与凭据)。备份普通数据不备份系统凭据或 lease；恢复历史
配置也不隐式回退/选择其他密钥版本，所选材料不可用时明确要求恢复凭据。
平台消息身份不是 Studio checkpoint 的替代事实源；机器人关联的 Thread 继续保存到普通
`projects/<project-key>/sessions/<thread-key>/`。App Secret、租户 token 和长连接票据不进入上述文件；单机器人损坏保留现场并
局部隔离，不触发全局恢复。生命周期和发送未知结果契约见 [27](./27-bots.md)。

项目和会话清单只描述版本、稳定身份与固定归属，作为目录自描述和绑定校验，不是第二套可编辑
配置。项目名称、会话标题、归档与列表排序等可变摘要仍归全局轻量索引；当前模型 route、Mode、
指令快照、Plan 与会话笔记仍归 checkpoint/扩展。清单不复制 account secret 或历史正文。
新建资源在发布目录事实前准备清单，校验失败不得发布错误归属；冷读不为补清单创建历史库。
旧 v2 的 `state.toml`、`state.prev.toml` 可随原会话目录暂留为迁移源，仅在既有按需 checkpoint
转换边界读取并在验证后回收；它们不是新会话的第二套配置或正常保存格式。

### 执行侧会话文件

模型可操作的临时文件位于实际 workspace 内，而非上述宿主数据库目录：

```text
<workspace>/.anywork/sessions/<thread-key>/
├── scratch/                       # 临时脚本、中间文件和探针
├── artifacts/                     # 尚未放到用户指定位置的输出
└── commands/<call-key>/output.log  # 命令原始 capture；call-key 为安全身份摘要
```

所有执行环境使用同一身份映射和相对布局；共享 checkout 的 Thread 也不共用临时目录。
SSH 的路径属于远端 workspace，不能拿本地 home 路径代替。会话宿主的 `scratch/` 是文件
传输暂存，执行侧 `scratch/` 是模型任务中间文件，两者不承担可靠历史的保存责任。
命令与媒体在可靠资源归档后才发布稳定引用，执行侧文件消失不应破坏历史读取。

执行目录不是代码交付位置。最终代码、正式文档写入用户要求的项目目录；非项目交付物须报告
实际路径。默认不在仓库根、`/tmp` 或任意其他会话目录写中间产物。运行时提供准确路径事实，
提示词与 Skill 示例消费这些事实，不从旧对话或进程 cwd 猜测。

`sessions/`、`worktrees/` 运行池在各自目录内以不覆盖方式建立忽略全部池内容的 `.gitignore`。
同池并发首次创建应按安全的普通文件后置条件收敛，不依赖错误文案；目录、链接或无法确认
类型的入口不能当作已准备完成。文件工具原有 Create 的不覆盖/已存在报错语义不因此改变。
已有忽略文件保留，不改用户仓库根规则或全局 Git 配置；项目 Skill 与 AGENTS 等可共享文件
不被新的全局忽略规则隐藏。不扫描、搬迁或清除项目内旧 `target/pure/`、未知文件和隔离旧版本
数据。关闭/归档只回收已确认 ownership 的资源；不按 TTL 删除活跃 scratch、可靠历史或附件。

## 17.2 启动与按需激活

历史库升级会纠正旧投影提前写入的输入 Turn 绑定：只有 Turn 的 `input_id` 明确指向该条目，
且同事务维护的终态输入索引尚无该身份时，才证明它仍未消费。迁移清除其展示绑定并推进内容版本，
保留正文、附件、排序、时间戳、执行记录和保存水位；已消费及无法证明的条目保持原样。
该迁移在激活投影读取种子之前由历史库 writer 事务完成，普通冷分页仍只读。

统一启动协调器执行：取得锁 → 接续未完成的恢复 → 准备并校验全局配置与独立存储 →
装配服务 → 装载缓存、workspace/catalog 摘要与资源归属 → 启动后台任务 → 发布就绪与 GUI 首屏。
独立准备步骤并行，依赖步骤在汇合后执行；所有步骤成功前不发布运行时，不启动持久化 writer。
此时加载的会话状态、打开的会话数据库和历史条目均为零。
模型目录的本地默认/成功缓存在配置引用校验之前准备；各实例启动在线探测是独立后台观察，
只在初始化阶段提交一次、各实例并行且互不等待，不属于等待全部网络结果才发布首屏的条件。
运行期没有第二次自动同步或手动刷新命令。读取缓存失败仅产生该实例诊断，见 17.3。

步骤优先执行已知版本迁移、索引重建与可恢复尾记录修复。无法处理的数据损坏、未知版本或
无效引用返回类型化持久化错误；权限、容量、占用、凭据服务和内部错误不触发数据重置。
失败或取消须等待全部在途步骤并关闭文件与数据库；回收失败禁止进入备份。

无法恢复的数据错误由协调器持锁整体备份 `config.toml`、`agents/`、`v2/` 与 `studio/v2/`，
完整保留 SQLite 主库、WAL/SHM、日志和附件。备份位于独立且不可覆盖的启动备份目录；
持久化操作记录标识待移动、已移动、备份完成与初始化完成，中断后接续同一次恢复。
仅在全部备份完成后以默认值重新完整初始化，每次启动最多自动恢复一次；再次失败直接报告。
备份失败保留原件与已归档现场，不发布混合状态，不覆盖已有备份。
系统凭据、隔离的旧版本目录、全局 SSH 配置和实际项目/worktree 保留；恢复摘要提供备份位置与
脱敏原因。首屏后的逐会话读取及运行期存储故障不触发全局重置。

启动不遍历全部 `state.toml`，也不在首屏之后后台激活全部历史会话。全局恢复只处理本版本的
数据根目录级资源和孤立物理 lease。GUI 首个可用画面出现后，若展示的是已选中 Thread，
由 GUI 对该 Thread 发起一次普通打开；无选中 Thread 时不打开。其他会话的内部恢复推迟到
显式打开、执行或需要人工处置该会话时。

打开 Thread 时：

1. 校验 catalog 身份和祖先关系；
2. 合并同 Thread 并发打开；
3. 先由该会话的唯一历史 writer 完成既有 v2 SQLite 结构与检查点迁移，再在短 SQLite 读事务读取并验证最新 checkpoint 与上下文；旧 v2 TOML 同样先按需迁移；
4. 纯恢复内存 owner，不执行模型/工具；
5. 建立增量订阅；
6. Session 尾部订阅在同一边界取得当前内存首帧（最近最多 32 条）；共享缓存按需
   从历史 keyset 查询补齐最多 100 条，活跃/待保存条目直接按同一身份合并，无需等待 writer。

显式继续父会话会先核对子会话的终态通知。未加载的子会话也须先由其唯一历史 writer 完成
既有 v2 结构与检查点迁移，再读取当前检查点和终态历史；此过程不激活子会话，不重放模型或工具。

读取历史页面不激活 owner。离开 GUI 页面只释放订阅和远离窗口的 GUI 数据，不自动停止仍在执行
的 Thread。空闲、无订阅、无待保存数据且没有必须存活资源的 owner 在最终 checkpoint 后可释放。

## 17.3 配置和目录文件

`config.toml` 保存 account、模型 route、指令、Skill/MCP 等配置；`settings.toml` 保存 UI 和
产品设置；`workspaces.toml` 保存 workspace/project；`catalog.toml` 保存会话目录。所有文件使用
版本化 schema、CAS revision 与统一原子写入，不在正常路径双读旧格式。

更新下载进度不属于产品设置，不写入 `settings.toml`；下载恢复和安装资格遵循 [23](./23-release-update.md)。

用户 Agent Profile 继续一个稳定 ID 一个 TOML 文件。系统 Profile 不写用户文件。Account secret
保存在 OS 凭据库；配置迁移改变 account ID 时必须先写入并验证目标凭据，再切换引用。

目录变更与会话 checkpoint 不共享伪造的跨文件事务。创建/归档等跨资源命令使用显式可恢复
步骤和迁移/操作记录：目标文件全部验证并持久化后才发布新 catalog revision；失败保留可重试
状态和原资源。

### 模型目录成功缓存

在线模型目录是可重建的 account 观察，不是用户 desired config 或会话数据。每个实例、查询身份
独立保存版本化 `model.json`：身份、成功/检查时间（Unix 秒）、可选 ETag 与统一模型声明；
不保存明文认证信息；价格保存该厂商适配明确声明并归一化的 token 价格，未声明或不支持的
格式保持 Unknown。计价来源与同账号路由的价格回填由 [06](./06-model.md) 定义，不改写历史账单。
缓存保存服务端返回的完整模型声明（含生图、嵌入与语音等非对话 slug）；有效目录保留全部
成员，对话路由按模型类型过滤，非对话名单是协议 endpoint 服务能力的数据来源，见
[06](./06-model.md) §6.7。
成功文件的读取与写入共用 8 MiB 上限；规范化后的声明超过上限时保留上一份成功观察，
不写入下次启动无法读取的文件。
查询身份覆盖账号、完整 base URL 路径、厂商协议适配及影响查询的 header/凭据身份；旧身份文件不
用于新地址或其他实例，也不因删除、改名或切地址顺带删除。

查询指纹 v2 显式包含厂商协议适配，避免相同地址和目录在切换协议后复用不同解析语义。
成功缓存格式升级至 3；旧格式 1/2 及 v1 查询指纹只在明确的缓存升级边界读取，保留原文件、
成员、元数据和最后成功时间，并为同账号的旧查询身份记录唯一迁移目标，不能在后续协议切换时
反复导入同一旧快照。无法证明旧快照的厂商解析来源时，只作为历史成功快照保留，不冒充当前
协议的新观察；该快照可作有标记的缓存失败回退，但不能作为新协议解码的前次声明参与字段
继承，完整响应重新验证前不得发送旧 ETag。升级失败只报告该账号的缓存故障并保留
可重试状态，不清空缓存或通过全局重置绕过。

仅在查询/解码/声明与身份校验成功后使用单文件原子替换，再发布对应内存观察。写失败保留上一份
已发布目录和成功文件，报告失败而非持久成功；取消和迟到结果不得提交。ETag/304 只有相同身份
已有成功快照时可更新检查时间。文件 schema 独立于 config.toml 与普通程序版本；不按 TTL 或
普通升级拒绝失败回退，不把派生缓存写入 settings.toml 的权威配置载荷。
缓存另记录目录归一化规则版本。旧文件缺少该记录时仍用于失败回退，但刷新不发送其 ETag，
直到成功获取完整目录并按当前规则保存；这样缺失模态可采用当前默认，历史明确声明仍由新响应
决定，不从缓存中的文本值猜测原始字段是否缺失。仅改变归一化规则不改变查询身份或删除旧文件。
缓存原子提交支持用户指定的长数据根；Windows 提交路径须使用系统认可的完整路径形式，
避免临时文件路径长度使已成功解析的目录无法保存。

启动配置引用校验前读取同身份成功缓存。缺失、损坏、不兼容或读取失败只产生该实例诊断并回退
账号默认定义，保留文件现场，不触发全局备份重置。后续探测失败不改写或清空成功缓存；
动态模型选择暂不可解析时的 unavailable 语义见 [20](./20-config.md)。既有配置/凭据服务本身的
环境错误仍沿用原启动边界，不冒充缓存缺失。

在线任务必须纳入启动取消与 shutdown：先拒绝新发布，取消网络，等待在途原子提交及全部任务
终态，再关闭资源。不存在无人持有的刷新任务或关闭后的缓存写入。缓存布局在 v2 备份边界内，
但自身错误不能成为触发全局恢复的理由。

## 17.4 历史、调用与实时流

附件记录在新提升、目录加载、运行时传递与新写入的输入历史载荷中始终保存相对于所属会话
的 blob 引用。只有附件存储边界可结合记录的 Thread 身份解析宿主完整路径，供资源归档、
完整性校验和读取使用；正常附件读写拒绝绝对引用及会话 blob 根之外的引用，旧绝对引用只在
附件目录迁移边界转换。已保存的历史载荷仅提供附件展示元信息，不参与文件路径解析。
调用方不自行拼接或按进程当前目录、本地及 SSH 项目的工作区路径解释附件位置。
Rust 附件记录以 `blob_relative_path` 明确此语义；持久化字段仍为 `storagePath`，已有目录和
历史载荷无需改写。原先直接读取记录路径的调用方须改用附件存储的读取或物化能力。

附件 staging 与已受理输入的可靠附件分属两个 ownership 域。受理在可靠 session 资源中
promotion 后，不自动删除同一 draft ID 的 staging 对象；较新的逻辑草稿可能仍引用它。
Client 记录逻辑草稿与冻结提交引用，仅最后一个 owner 释放后显式请求删除 staging；删除失败
保留登记和原文件，不先清索引再吞掉 I/O 错误。未知受理结果继续持有冻结引用。活动草稿不能
因观察者消失或固定闲置时长过期而删除；可靠历史引用的附件不参与 staging 清理。
应用退出不删除旧目录、v2 历史、配置或凭据。Client 关闭只收束在途资源任务，不能用清空数据
代替生命周期确认。草稿协议见 [25](./25-frontend-state.md)。

每个会话由会话管理器持有可靠的未提交 effect 队列，history writer 借用队头并写入
`history.sqlite`，事务确认后才释放；同一事务记录任务身份、终态工具交付和交互回执。
全局 call recorder 独立、尽力而为地写滚动日志及有界索引；其积压和故障不阻塞执行或历史确认。
旧调用库不进入本版本的历史库，旧用户数据原样留在旧数据根。writer 退出后原队列由会话
管理器保留，待旧写任务结束后按历史水位重试。
观察窗口错过实时 effect 后，累计统计从可靠 checkpoint 的绝对摘要恢复，不回读调试日志。
队列已受理但尚未落盘只标记待写入，不能直接锁存统计缺口。

普通问答与计划确认的 typed 历史是 canonical interaction 的派生投影，不建立第二份回答账本。终态交互
回执与原工具条目的问答更新在同一可靠历史写入中提交；已解决交互从 resident checkpoint
回收后，历史仍能完整回看。当前版本 v2 旧历史通过受版本控制的迁移从已有 durable interaction
回执补齐原工具条目，保留条目身份、顺序、创建时间和原内容，不重放交互、模型或工具，不清空
历史。迁移幂等且事务化，损坏或矛盾事实显式失败；缺少证据不凭工具成功伪造回答。公开投影
中的敏感回答遵循 [18](./18-studio-state.md) §18.8 脱敏，私有原始回执不被破坏性改写。
该 schema 升级在交付内容基线之前完成，补齐只改写派生载荷、保留原条目内容版本，不借迁移
占用后续正常提交的版本；升级后的实际交互变更仍由既有内容版本机制推进。
计划确认沿用同一版本迁移边界，从既有计划提问与决定回执补齐发起它的 `plan_submit` 条目；
批准、修改意见、取消及其原顺序均以保存的交互事实为准，不从当前计划文档或工具结果猜测。
迁移失败必须回滚整个升级，保持原 schema 与原条目可重试，不以重建空库、清空记录或默认
批准替代迁移，也不把派生回填写入私有原始答案或模型上下文。

子 Thread 的终态通知先按父 Thread 的持久身份索引裁决重复；若相同身份的通知已受理
但仍在父 Thread 待消费队列中，实时通知须唤醒原消息对应的等待，不能因去重跳过
唤醒，也不能为了唤醒再受理第二条消息。已消费通知不得重新启动模型。
终态事件以子 Thread 的写入序号为身份；报告含观察时状态，重建的正文不作为同一事件
的冲突依据。父 Thread 已受理时保留首次正文，仅按原受理序号唤醒；普通用户或代理
消息仍按正文摘要严格判定身份冲突。
实时 effect 窗口缺口只按缺失的 write_seq 区间恢复终态通知，通知身份使用原 effect
的 write_seq，不得用历史 ordinal 替代；本次运行中新完成的子 Thread 与正常实时投影
一样唤醒父 Thread，冷恢复旧事实仍只补历史而不启动模型。

核心后台任务结果的消息身份由同次消息准入的持久递增序号确定，不能从有界消息窗口中
寻找可复用编号。消息身份窗口裁剪和 checkpoint 恢复均不回收编号；已有历史身份保持原样，
后续结果沿现有准入水位继续分配，历史库仍严格拒绝同一身份的不同内容。

设置页的性能历史读取当前统计口径下已记录的成功调用；没有可用计时的调用仍显示，但相应
时延或速度标记为未采集。性能样本保存同一成功 inference 的输出词元与单调计时摘要；有效性
遵循 [06](./06-model.md) §6.12，缺失、零输出或无效用量不能只贡献总响应分母，缺失或不一致
计时也不能参与速度汇总。TTFT 与首字后耗时可独立于总响应耗时未知。原始调用记录仍保留，
不因不适用速度而删除或改写。Thread 最近已确认
速度的成对摘要遵循 [18](./18-studio-state.md) §18.8，与 checkpoint 同步保存，不依赖有界全局
性能样本或调用日志恢复。计费观察的身份由实际执行的 Thread ID 与 inference ID 共同确定；
根 Thread ID 仅用于会话树费用归集和缓存清理，不能代替执行 Thread 参与去重。不同子 Thread
内同号的 inference 分别记入调用历史与性能统计，同一 Thread 内重复投递仍须幂等。
调用库快照
可在写入未完成时返回已提交部分，同时明确标记待写入；受理后 writer 提交或明确拒绝时
再次发布查询结果及新的展示 revision。读库错误不得伪装成空统计；统计缺口独立显示，
且不反向阻塞 Thread。关闭人工模拟 GUI 时临时 home 与常用 GUI 互不共享。

调用明细遵循日志保留期；性能汇总使用独立的全局有界样本集合，按完成时间和调用身份稳定排序，只保留
最近 3000 条成功调用，每批统计事务提交前清理更旧的样本成员；可靠累计费用、执行幂等身份和
会话正文不随速率样本淘汰。样本是独立投影，不保留对已退役调用表的外键。
本次从 decode TPS 切换到含首字等待的 TPS 时，旧性能样本直接丢弃，不换算、不迁移；性能历史
及汇总只读取新口径样本，不能从旧 JSONL 或旧账单回填复活旧统计。旧 checkpoint 中的最近速度
派生缓存也作废，新有效样本重新建立；其余累计用量、费用、原始调用日志、账单与会话历史均保留。
样本自带模型、用量和计时摘要，
不回读已经过期的日志正文。统计 writer 每批共用一个 SQLite 事务，单条失败
通过保存点隔离，成功记录的完成水位不早于整批事务提交；可重试失败保持顺序重新排队，
不可恢复失败显式记录统计缺口并结束对应 ticket。

新 Session 首次分配 ordinal 前，只读一次本会话 `history_items` 中已持久化条目的最大 ordinal
作为 seed（空库为 0）。Session 在内存中按身份分配唯一、正数、处于 SQLite 整数范围内的
ordinal；重试同一身份保持原值，未落盘的分配在进程重启后不恢复。实时预览和 writer 共用
同一个 Session 分配结果；writer 只持久化已赋值的 ordinal，缺失、改变或重复均失败关闭，
不使用数据库自增键、预留表或写入时回退分配。旧库中的预留表不参与 seed，也不被迁移。

模型透明恢复的展示事实随模型所有者的最终回执保留，观察契约见 [16](./16-core-contracts.md)
§16.3。观察代次扩展不重写既有 Item 身份或历史顺序；旧 v2 回执缺少观察代次与失败子尝试时，
在其 producer 解码边界解释为首次尝试且没有恢复事实，旧正文和计费原样保留。新增字段必须
明确缺省或版本迁移语义，不因缺失恢复字段清空历史、恢复默认配置或读取隔离的旧数据根。

保存确认只释放该事务实际提交的 Item 身份与 revision。模型尝试仍在运行时，其保存确认
不得清理随后发布的当前观察或已收束的失败代次预览；这些事实由模型所有者的最终回执
负责持久化。只有尝试终态已提交，才可释放该尝试残留的推测性 account 预览，且不得
删除本事务已提交的身份或改变它们的历史窗口位置。

已写入但尚未关联 Turn 的消息条目，随后可以用同一身份与 ordinal 绑定到它的 Turn。若它
早于该 Turn 已持久化的首项，writer 必须在更新该条目的同一事务中向前扩展
`history_turns.first_ordinal`；除此合法绑定之外，Turn 首项不能被任意改写。

输入身份索引与消费它的历史 effect 在同一事务中保存展示属性。可见输入必须有对应的
`history_items` 条目；隐藏输入只保留最小身份及隐藏属性，不写展示正文。后续 Turn 在输入
正文离开有界状态后引用它时，writer 以可见条目或已提交的隐藏身份判定完整性；实时
投影还可使用自身有界窗口中刚受理的隐藏事实，直到 writer 追平。只有隐藏身份可免除
展示条目要求，缺失、未知属性或属性与展示条目冲突仍失败关闭。
旧 v2 历史库升级时，仅根据已提交交互回执中与输入身份一致的 continuation 和原始展示
选项回填隐藏属性，不通过缺少展示条目推断隐藏，也不清空旧历史或未提交队列。
冷历史分页可继续只读 v2；活跃投影首次需要隐藏身份判定时，由唯一 history writer 在
版本事务内升级已有库，冷读不能为升级而创建会话或改写数据库。

产品投影在 effect 提交时形成 canonical Turn/Item/Interaction 条目变更；同一身份
同时进入 core 的 TimelineState 与历史 writer：

```text
Thread owner
├─ 当前状态 snapshot → 状态订阅
├─ Item/Turn/task effect → reliable history channel → history writer
├─ TimelineState → keyset 页 / 有界尾部订阅 / 详情 → GUI 与 HTTP
└─ model/tool statistics → lossy call recorder
```

首次 Thread snapshot 只包含当前状态、pending interaction、runtime、workflow 和目录引用，
不含完整 Timeline。core Session 是热／冷历史页、最新端订阅和详情的同一权威内容源，
接口、预算与 Live/History 见 [26](./26-timeline-content.md)。没有几何窗口、Around 聚焦、
对端裁剪或 canExtendLatest；页查询不改变任何消费者的阅读位置或订阅版本。

HistoryStore 只提供顺序键／身份读取与保存，不额外维护 GUI SQL 页缓存。活跃 reader 与
writer 复用同一数据库身份与初始化状态；新库 schema/meta 尚未完成时等待本句柄 writer，
冷读缺失库仍为空且不创建文件。损坏继续报错，不能重试后当作空历史。
此共享义务也覆盖 checkpoint 与恢复栅栏的读取，以及尚未打开 writer 的冷读句柄；不能
在同一 Thread 内另开独立初始化状态绕过正在进行的首次初始化。共享句柄本身不创建库、
不升级 schema，不以全局强引用缓存延长冷会话资源寿命。

查询先保留内存未保存引用，再读短 SQL 事务，返回前重新合入最新事实；并发 commit
重叠按身份版本收敛，不漏行或回退内容。打开尾部订阅在同一同步边界登记接收者及建立
首帧，首帧不等待当前 effect 的 history/checkpoint 水位。普通分页不经过执行 owner、
不 flush writer、不激活冷会话。存储故障使用独立状态观察，不被 GUI 内容缓冲阻塞。

前端按需保留已访问的轻量消息，不等于加载完整可靠历史；读取原文和详情均有明确预算。
本次内容 API 变化不重写历史 payload 或清库，任何实际 schema 变化按既有 v2 事务迁移执行。

## 17.5 保存与诊断

完整模型回放作为内存提交的冻结载荷保存，活动会话不从历史页、调用日志或展示投影回读
组装请求。重开时使用同事务保存的 checkpoint 和有序 current context，校验身份、哈希、
条数和保存水位后恢复到内存。物理模型连接与 WebSocket continuation 缓存不跨进程恢复；
重新执行的首次请求发送完整历史，成功后建立新的增量续接条件。打开会话不重新执行已
完成的模型和工具，也不以当前指令重渲染已保存上下文。旧会话缺少的回放不回填。

每个已加载 Thread 只有一个可靠 writer。历史、当前上下文、恢复 checkpoint 和累计统计
同事务提交；固定 flush 水位只在事务确认后完成。不再运行独立 TOML snapshot scheduler。
当前上下文只保留最新集合，普通追加增量写入，压缩替换不保留旧上下文快照。

公开保存诊断保留 dirty/saving/durable revision、历史和诊断的 admitted/durable 水位、
待保存数量/字节、最老等待时间、故障代次及暂停状态。可靠保存失败保留批次并在安全点暂停
新模型/工具准入，按现有显式重试和继续协议恢复。日志故障单独报告，不加入可靠屏障。
聊天顶部只提示可靠存储故障、执行暂停或存储背压；诊断日志缺口由统计页展示，
不能因全局调用日志曾失败而常驻会话保存横幅。
关闭和 shutdown 等待相关 Thread 的固定可靠水位，不能将未保存事实报告为成功。对外水位取所有
owner 的最小值（全局确认要求每个 owner 都推进到该值），不用单个 owner 的最大值冒充全局确认。

关闭的持久化收束以 writer ack 为准：writer 确认之前保留 owner 与句柄；只要仍有运行中的
writer，就不得关闭数据库，也不得释放实例锁。关闭按有向顺序推进写入链——后台任务 / Turn /
Agent / title 等生产者的停止 ACK 先于可靠保存 drain 与 writer 停止，writer 真实 ack 先于关闭
数据库与释放实例锁——但彼此独立的 owner（后台 watcher、MCP、LSP、订阅与更新操作）与该
写入链并发收束，共享同一首次绝对期限的剩余预算，不逐个串行等待而相互抢占等待预算。SSH
transport 不是与它们独立的 owner：它承载远端 MCP / LSP / 工具的通信，其真实关闭（关闭连接即
终止本地 SSH 子进程）必须晚于这些远端依赖的停止请求与结果处理、以及驱动远端工具的生产者停止
ACK，否则会先切断通信、把健康远端资源的正常退出误判为失败。SSH 回收仍与写入链并发，不等与它
无关的持久化 / 数据库提交；依赖停止超时或失败时按有界降级照样请求回收，只放弃等待其 ACK、
owner 仍由常驻槽位保留。退出报告
携带的保存 fence 与待保存状态只反映
真实进度，未知即报未知，绝不用「已排空」或「Clean」掩盖未保存事实；degraded 或超时都不释放
实例锁，锁在进程退出时才由 OS 语义兜底释放，避免与仍在写库的 writer 竞争（报告形状见
[18](./18-studio-state.md) §18.5.1）。诊断收尾独立于 runtime 初始化状态：即使 runtime 从未
安装或安装失败，也通过独立收尾命令回收诊断资源；退出错误通过同步 error 日志、临时应急文件与
stderr 兜底持久化，记录 `code`、`correlation_id`、待保存事实与保存 fence，不含凭据或正文，
且写入不得延误退出期限。

调用日志容量、轮转和清理契约见 [15](./15-session-storage.md) §15.7。旧 v2 数据按职责
迁移后才回收已替代文件；附件和工具归档按可靠历史引用保留，不适用调试日志过期策略。
所有回收只作用于本版本已确认拥有的资源，不触及隔离的旧版本数据根。

旧 v2 费用迁移按 purpose 与币种核对 checkpoint 与调用库水位；模型与压缩费用已包含在
checkpoint，标题和自动审批费用单独补入，绝不直接相加两套累计值。后续辅助计费通过可靠
扩展事件与会话一起提交。当前压缩回执仅保留最新一份；历史压缩条目以独立调用身份保留。

v2 checkpoint 在按需激活时迁移：验证版本、外置正文完整性及历史水位，在 SQLite 事务中
发布精简状态，并重新读取校验。成功后才回收主备 TOML 与专属 checkpoint 正文；清理记录
支持中断重试。旧调用库按批保全累计摘要和保留期诊断，发布迁移版本后回收旧正文目录，
包括未登记的孤儿；旧运行中工具参数与终态交付在迁移边界分别解码。

## 17.6 worktree 与资源恢复

v2 Turn 失败记录新增可选模型失败事实。缺少该字段的既有记录在持久化解码边界恢复为无
结构化事实，保留原诊断文本与身份；新记录原样保存模型事实，不从旧错误文本猜测账号分类。

worktree lease 是物理资源唯一 ownership。会话的 `workspace_mode` 与 `workspace_path` 是目录
展示事实，不因 lease 缺失自动改为 local。激活时 lease 或物理身份缺失/不匹配明确失败并发布
Recovery preview；不静默切换到项目根目录。

Recovery preview 包含 revision、branch/base/head、dirty/changed files 和缺失/冲突原因。只有
`preserved`、孤立 lease、清理失败或身份不匹配资源进入人工清理列表；活动 Thread 的 active
lease 不是清理候选。显式 cleanup 在服务端重新验证前置条件后执行。

物理资源创建、变更和清理必须在对应 checkpoint/catalog fence 前耐久化其 ownership 记录。
文件系统或 Git 操作成功而目录保存失败时保留资源和补偿记录，不删除现场冒充回滚。

## 17.7 大版本隔离与配置迁移

账号迁移只保全转换非会话配置与本版本 v2 的模型接入身份，不是新一次会话断代。
配置、Profile 和系统凭据的可恢复转换见 [20](./20-config.md)。账号 ID 原值保留，显示名不
参与绑定隔离身份；迁移不得因命名从 provider 改为 account 而把同一绑定当成另一账号。

已有 v2 的产品模型路由与 Agent Profile 扩展在持久化解码边界按版本转换 provider/model 字段，
保留原 ID、effort、扩展 revision、checkpoint fence 与历史；在唯一 writer 的事务内发布当前
结构，迁移失败不激活模型、不前移版本。按需打开、恢复和继续父子会话使用相同边界，不批量激活。
冻结 Profile 的旧字段按其序列化契约 `providerId`/`model` 转为 `accountId`/`modelId`，不能套用
模型路由的 `provider` 字段名。新旧字段同时存在且身份冲突时拒绝迁移并保留原检查点。
typed 账单和调用记录只转换已知账号字段，不改写厂商不透明正文或以当前配置猜测历史身份。

恢复 owner 前的 checkpoint 维护同时覆盖根会话模型路由与子会话冻结 Profile：仅在内存中
解码旧字段不算完成升级；事务内比较已读检查点，再持久化当前扩展载荷，水位、扩展 revision
和业务状态不因表示升级而变化。原生压缩来源恢复消费相同的版本化回执解码边界，不能在旧
压缩回执中直接反序列化当前账号绑定；解码或提交失败均保留原检查点并阻止不安全激活。

调用库列、索引与投影在版本事务内转换为 account_id/account_display_name/model_id 语义，
调用主键和全部费用事实保留。性能顶层用冻结的配置模型与账号聚合，effort 为二级；缺少配置模型
证据的旧样本保留未知而非使用发送模型冒充。会话及 purpose/币种累计费用不重算、不清空。
成功目录缓存保留同账号同查询身份的回退，字段或归一化升级只在明确版本边界转换；旧文件和
最后成功声明保留，不能通过清空缓存或拒绝所有历史缓存来完成账号改名。

本版本不运行旧会话 journal、旧产品库或旧调用库的转换、导出与归档，也不提供
`migrate-legacy-storage` 命令。`~/.anywork/studio/sessions.sqlite`、旧产品数据库、调用库、
附件与旧迁移报告均保留在原路径；新会话只读写 `v2/` 和 `studio/v2/` 下的独立数据。
旧数据不可作为新会话缺失条目的补全来源。只有全局 account 等非会话配置按配置契约升级；
配置和 OS 凭据关联优先安全迁移；无法恢复的数据错误按 17.2 完整备份后重建，凭据始终保留
（见 [20](./20-config.md)）。

### v2 平铺会话到项目布局的迁移

已有 `v2/sessions/<thread-key>/` 必须保全迁往对应项目目录，不构成再次断代。迁移在持有
home 独占锁、校验 catalog/workspaces 后、会话 writer 与服务发布前执行；迁移计划只由现有
目录身份生成，不打开全部历史库、不激活模型或工具。未归属 catalog 的遗留目录原位保留并
诊断，未物化 Thread 不伪造历史库。

版本化布局记录位于 `v2/migrations/`，逐项记录准备、移动与验证事实。整目录原子移动保留
SQLite 主库、WAL/SHM、旧 checkpoint、可靠正文和未知普通文件；必要小清单的转换使用现有
原子写入能力。附件目录中的已知旧绝对路径只在迁移边界校验所属源根后改为会话相对引用，
正常路径不继续兼容旧绝对存储位置；不改写历史正文、工具参数或提示词中的任意路径字符串。

中断后接续同一布局记录，已完成步骤幂等，正常读写只消费已发布的新布局。目标存在但不能由
本次记录证明归属时不得合并或覆盖；目标及小清单验证成功前不回收源资源。未知布局版本、
坏清单、目标冲突、symlink/reparse 越界、权限、容量或文件占用等迁移失败保持可重试现场并
停止初始化，不把布局迁移错误当作整体启动恢复的依据，不备份后清空来代替迁移。
迁移错误保留原始原因；权限、容量和占用仍属于环境故障，不能为抑制重置而丢弃其分类。
可恢复的布局数据转换失败使用启动迁移故障分类，与账号配置及 Mode 定义迁移一样停止并
保留现场；布局迁移中的底层 I/O 环境故障仍按环境类别报告。物理布局升级不替代按需的
检查点表示升级：恢复继续由同一 history writer 保全转换账号路由、冻结 Profile 与 Mode
定义快照，保持扩展 revision、历史水位和业务状态，不因目录已移动就跳过这些转换。
迁移记录的源/目标键和项目、Thread 归属必须与稳定身份及当前目录一致；完成标记必须可验证，
不能仅凭文件存在跳过记录校验。建立目标目录前先校验已有祖先的链接边界，失败不能先在
归属外创建目录。附件转换验证的是本条迁移记录指定的会话源根，不是任意同名 `blobs/`。
原子移动前先在源会话物化可校验的固定归属证明；rename 成功而记录尚未推进时，只有目标
保有匹配证明且源已不存在才允许接续，不能仅凭目标目录存在接管。已验证条目及完成标记
恢复时还核对源已不存在、目标为安全普通目录；该检查只读目录元信息，不逐库打开或重新
扫描历史正文与附件。附件缺失、非普通文件或长度与清单不符均保留现场并拒绝完成，不能
用重定位、空内容或忽略完整性差异来使迁移通过。
读取附件清单、检查每条 blob 之前，校验从受信根到目标的全部已有路径组件；仅检查末级
文件的元数据不能证明 `blobs/` 或其分片父目录没有链接越界。该校验按清单中实际引用逐项
进行，不递归扫描未引用文件。
新项目目录和布局记录纳入已有安装状态判定及 v2 整体备份边界；重复启动不得重置迁移水位。

## 17.8 数据库和发布验收

新 history/calls 数据库启用 WAL、FULL、foreign keys 与 busy timeout。打包时记录并验收实际
链接的 SQLite 版本；不能只依据 ORM crate 版本宣称具备某个 WAL 修复。本次迁移和发布验收至少覆盖：

- 旧会话、调用库和产品库在原路径保持字节不变，既不导入也不自动归档；
- 账号配置、凭据关联等非会话配置安全迁移，无法恢复时完整备份后初始化，原始字节和凭据保留；
- 新建 v2 会话的数据在 WAL 中已提交、重复启动和写入中断恢复；
- checkpoint 不越过 history/blob fence；
- writer busy/失败/确认不明时不丢批次；
- 大历史启动不扫描会话，分页成本不随历史前缀线性增长；
- 冷历史查询不激活 owner、不执行模型/工具、不修改文件。

## 17.9 诊断与脱敏

错误包含 operation、Thread/Turn/Interaction/call identity 和脱敏 correlation ID，不记录 token、
Mode Prompt 正文、用户 credential 或未授权请求正文。失败 artifact 可包含 migration 状态、schema、
数据库 quick check、写入水位、队列压力、GUI/Driver 日志和文件 diff；敏感原始备份受权限保护。

Timeline 的工具 item 在开始时分配稳定身份；account identity 后到只更新同一 item。历史缺口、
重复 ordinal、同 revision 内容冲突、checkpoint fence 越界或 blob hash 不匹配必须失败关闭，不能
用当前工作区内容或当前工具渲染器补回。

## 上下文来源与升级

当前检查点和会话数据库结构升级采用显式事务迁移，保留既有 v2 数据、历史及未知来源材料。旧用量不能恢复来源时标为未知。旧原生检查点只从身份可核对的生产回执恢复来源；无可靠来源则保留数据并明确拒绝不安全执行或切换。上下文回退继续保留最新计划、工作流及其他当前业务状态，不构成业务回滚。

## 17.10 模型观察迁移

模型成功缓存升级时保留原始成员、元数据、时间与身份，迁移未知的字段来源不冒充在线明确声明。
旧 ETag 不用于正文缺失的升级；下次重新取正文，失败继续使用迁移快照。
成功顺序随缓存原子持久化，304 不改变字段优先级；不清空缓存，也不修改旧会话目录和历史计价快照。

## 17.14 Mode 定义快照升级

Mode 扩展保存完整执行定义及图 revision，随 Thread checkpoint 与指令、工作流状态原子持久化。
删除配置后，冷恢复和归档恢复都从该快照恢复，不依赖全局目录；快照不会重新发布到模式目录。
旧版本仅保存 Mode ID 的扩展在显式 checkpoint 恢复边界升级：从可用定义及已保存的 Mode 指令
恢复完整定义。缺少原指令或旧工作流与现有图身份无法安全对应时，保留原数据并报告恢复错误，
禁止重置历史或工作流状态。升级在激活 owner 前经原 history writer 的事务比较原检查点并立即
持久化；不等待下一轮或退出保存，不改动历史水位、正文及工作流状态。正常运行只消费完整快照；
不以删除配置、终态或归档删除历史数据。
