# 21 - LSP 运行时与语义查询

## 21.1 目标与边界

LSP 为智能体提供代码语义查询，并向 GUI 与智能体提供同一份服务器状态。LSP 协议、路由与状态所有者驻留 Studio 宿主，服务器进程可在本地或 SSH 执行侧运行，不经 MCP 暴露。服务器全部来自独立配置文档，格式与发现位置见 [20.13](./20-config.md#2013-lsp-服务器配置)；不内置 rust-analyzer，不自动安装语言服务器。

LSP 是可选服务。配置、探测、初始化及运行失败只影响相应服务器，不能阻塞会话创建、恢复、普通对话及非 LSP 工具。

## 21.2 所有权与宿主边界

`pl-lsp` 拥有服务器定义、通用命令适配、JSON-RPC 客户端、文档同步、诊断、查询路由和运行注册表。工作区宿主提供执行侧文件读取、目录列举、路径语义、带环境变量的 stdio 进程启动、取消和退出等待；SSH 复用现有 helper 的受监督进程与流，不在远端重复实现 LSP 协议。

运行注册表是服务器配置、连接、初始化任务、进程租约及状态的唯一所有者。目录资源由稳定执行端点与 canonical 实际工作区根标识，目录内以配置 ID 和连接代次区分服务器。worktree 不能被原项目目录替代，相同路径的不同执行宿主不得共享服务器。工具实例各自绑定 Thread 的执行工作区与授权；同一目录的多个 Thread 共享物理服务器与磁盘文档事实，不共享调用授权或取消信号。

工作区身份是稳定执行端点与 canonical root 的组合，不能只用路径或临时连接代次作为键。本地端点与各 SSH 配置身份具有独立注册分区；Thread 的语义、状态、能力及文件变更通知持有同一分区绑定。产品所有者只聚合各分区快照、转发事件并协调关闭；不能通过“切换全局当前宿主”服务并存会话。重连只替换同一端点内的传输代次。

Thread 建立启用 LSP 的执行资源时取得目录使用租约，工具目录刷新延续该租约；一轮结束不释放仍激活的 Thread，未加载历史不持有引用。Thread 关闭、停用或装配失败时释放自己的租约；更换目录先取得新绑定，再释放旧绑定。关闭一个使用者不能停止其他使用者的服务器。最后一个使用者释放时立即取消准备并等待目录资源回收，不使用空闲计时器；获取与最终释放由目录所有者协调，旧任务不能覆盖重新获取后的状态。

项目列表、项目切换和设置观察不保活目录、不因浏览启动服务器。显式探测使用短期租约，完成后释放；没有智能体引用时只保留不持有进程、文件宿主或文档缓存的配置／结果摘要。GUI 和工具观察同一所有者，不另建服务器目录。

helper 仅通过已有受监督进程通道透传服务器的原始 stdin/stdout/stderr 字节，不解析 LSP、不维护服务器注册表或诊断。协议状态只在宿主 `pl-lsp` 中维护；本地与 SSH 的差异限于执行侧文件、路径和进程适配。执行绑定身份使用逻辑 helper 会话与 canonical 目录，不使用临时 workspace lease 的分配地址。短暂传输重连不等于服务器实例被替换，实际替换才失效相应连接状态。

## 21.3 数据驱动服务器

服务器声明语言、扩展名、项目检测条件、操作集合、程序/参数/环境、初始化选项和工作区设置。所有语言使用通用客户端；语言特有设置由配置传递，不通过内置语言分支或安装驱动实现。

初始化选项通过 `initialize.initializationOptions` 发送；`settings` 通过 `workspace/didChangeConfiguration` 与 `workspace/configuration` 交付。后者按请求 section 从嵌套对象取值，未声明 section 返回 null；不猜测第三方服务器的私有结构。命令与参数按独立参数传递，环境按键值传递，路径以执行侧为准。

同一工作区允许多个服务器声明相同语言；重复服务器 ID 仍是配置错误。查询可用 `serverId` 显式选择服务器，并校验其语言及协商能力；未指定时零匹配返回不可用、多匹配返回带候选的类型化歧义错误，不按配置顺序猜测或自动合并结果。工作区符号查询始终限定在调用者绑定的目录。

## 21.4 并行异步准备

Thread 取得目录租约及已有使用者的配置变更发起受管理的异步准备，不等待所有语言服务器就绪。配置发现先发布状态，各服务器随后并行探测、启动、完成 initialize/initialized 握手。每服务器独立超时和失败；一个慢服务器不能延迟另一个健康服务器，初始化不进入普通对话的等待链。

可观察阶段包含配置加载、探测、启动、初始化、就绪、失败、停止及检测不匹配的禁用状态；未配置的工作区返回明确的空目录状态。就绪后的索引、忙碌、进度百分比与诊断继续沿原活动状态交付。探测成功不等于握手成功，不足以注册语义查询能力。

配置内容指纹涵盖程序、参数、环境、初始化选项及设置；变更只取消并回收受影响成员，再建立新代次。旧代次完成不得覆盖新代次。没有配置变化时不反复探测或重启。配置修复可在同一 Thread 中恢复，无需重建会话。

执行侧文件变更及安全运行时更新边界负责发现配置变化；显式 GUI 重载允许重新尝试失败配置。状态读取只克隆最新快照，不扫描配置、启动进程或等待初始化。

普通配置重扫保留内容未变的健康或失败成员，不产生自动重试循环；显式重载则重试失败或已退出成员，即使 TOML 未改也能在安装程序、修正外部环境后恢复。内容未变的健康成员不因显式重载重启。

## 21.5 状态与失败隔离

GUI 和只读 `lsp_status` 工具可以在未配置、加载中、初始化中、失败及就绪时读取当前工作区状态。状态包含配置来源、服务器 ID、阶段、活动、错误及修复线索，不返回环境值、初始化原文或其他可能含凭据的配置内容。查询不隐式执行探测或修复。

非法 TOML、不支持版本、冲突、程序缺失、探测失败、启动失败、握手失败/超时与运行后退出都保留为局部诊断。单文件错误不丢弃其他健康服务器。LSP 目录故障不得沿项目激活或工具组装链终止会话，也不得触发全局配置重置。

状态工具独立于语义能力常驻。`lsp_capabilities` 与语义查询工具仅在当前工作区至少一个服务器握手成功且仍存活时注册；报告和路由只包含健康服务器。运行后失败通过目录更新撤下能力，冻结声明不因此整批失效。已接受调用在执行前逐一验证当前授权；已撤下工具不执行，记录调用失败并交回模型，未受影响调用可继续。服务器内部错误同样返回真实局部失败，模型下一步使用当前有效目录继续，不取消会话或重新执行已完成调用。

## 21.6 查询与文档同步

工具输入遵循工作区路径授权。对外源码位置为从 1 开始的行号和字符位置，内部转换为 LSP 从 0 开始的 UTF-16 位置。查询操作覆盖定义、引用、hover、符号、实现、调用层级和诊断，受实际服务器声明与协商能力共同约束。

查询前按协商的 `textDocumentSync` 发送必要的 didOpen/didChange；增量同步的替换范围按旧文档 UTF-16 位置计算。磁盘读取与版本更新位于同一同步顺序，失败返回调用者，不继续查询过期文档。本地和远端成功的文件写入、移动、复制与删除通知同一目录所有者；通知所有受影响且已启动的服务器，不仅通知扩展名唯一匹配者。删除清除相应文档与诊断，诊断按精确文件 URI 筛选，不按文件名后缀匹配。

URI 使用执行侧路径语义，Windows 扩展长度路径先转为常规路径。ContentModified 和启动阶段的暂时空结果可有界重试，不伪造文档变化，不以空结果冒充查询成功。请求级错误、超时或取消只影响该调用，取消清除其待处理请求；连接及进程真实退出才使服务器不可用，不能因一个 Thread 查询失败取消共享服务器。

客户端只声明实际支持的能力。配置、工作区和进度请求按协议响应，未知请求返回协议错误；不声明未实现的动态文件监听注册。服务器自行支持的文件监视由服务器负责，不在 helper 或宿主另建递归监听框架。

诊断属于单个服务器成员代次。成员被替换后，新代未发布诊断时不得回显旧代结果；旧 dispatcher 的迟到发布也不能污染新代。当前查询与计数只汇总当前健康成员拥有的诊断。

会话 `activeLspServers` 是该轮冻结的健康服务器集合；产品当前态通过 `readLspState` 与 `LspStateChanged` 交付。工具目录更新遵循现有冻结、授权及退役契约。

## 21.7 关闭与非目标

目录最后一份租约释放及全局关闭停止相应初始化，取消并等待所属后台任务，向进程执行 shutdown/exit，必要时终止并确认进程树回收。成功后释放目录宿主、文档与诊断运行态；未确认回收保留资源所有权和失败事实，不报告干净退出。全局退出等待尚未完成的目录回收。显式重载只替换选定目录／服务器，不扩大到其他目录或端点；状态读取和查询不隐式重启。

不提供 LSP 市场、自动下载、IDE 虚拟文档或终端输出面板。智能体在语言开发及代码理解任务中加载适用语言技能，通过独立的 `lsp-code-navigation` 执行状态检查、准备和语义查询；需要配置时由该技能引导读取 `studio-config` 的当前配置指南。使用状态查询确认阶段，再用与问题相关的真实语义查询确认可用；失败时仍继续可以独立完成的普通开发工作。只读角色或显式禁止写入的任务只能复用现有配置、报告缺口，不因技能建议扩大权限。

Rust 语义分析必须对应问题涉及的 Cargo 项目、工具链、目标平台和 feature 组合，不能把检查任务的目标或构建输出目录误当成分析目标，也不能默认启用全部 features。Dart 语义查询使用执行侧 SDK 的语言服务器；Dart/Flutter MCP 的运行时交互与此配置、状态、能力链独立，MCP 查询成功不能证明原生 LSP 已配置。`studio-config` 维护 anywork 自身的文档结构与生效机制；第三方服务器启动参数和分析选项按开发需求、安装版本及官方手册选择，技能不内置固定参数组合，不在运行时增加语言专用配置分支。
