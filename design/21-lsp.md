# 21 - LSP 运行时与语义查询

## 21.1 目标与边界

LSP 为智能体提供代码语义查询，并向 GUI 与智能体提供同一份服务器状态。LSP 协议、路由与状态所有者驻留 Studio 宿主，服务器进程可在本地或 SSH 执行侧运行，不经 MCP 暴露。服务器全部来自独立配置文档，格式与发现位置见 [20.13](./20-config.md#2013-lsp-服务器配置)；不内置 rust-analyzer，不自动安装语言服务器。

LSP 是可选服务。配置、探测、初始化及运行失败只影响相应服务器，不能阻塞会话创建、恢复、普通对话及非 LSP 工具。

## 21.2 所有权与宿主边界

`pl-lsp` 拥有服务器定义、通用命令适配、JSON-RPC 客户端、文档同步、诊断、查询路由和运行注册表。工作区宿主提供执行侧文件读取、目录列举、路径语义、带环境变量的 stdio 进程启动、取消和退出等待；SSH 复用现有 helper 的受监督进程与流，不在远端重复实现 LSP 协议。

运行注册表是服务器配置、连接、初始化任务、进程租约及状态的唯一所有者。配置按会话实际执行工作区隔离，worktree 不能被原项目目录配置替代。相同路径的不同执行宿主不得共享服务器进程。工具实例各自绑定 Thread 的执行工作区与授权；GUI 和工具读取同一个所有者的状态，不维护第二份服务器列表。

工作区身份是稳定执行端点与 canonical root 的组合，不能只用路径或临时连接代次作为键。本地端点与各 SSH 配置身份具有独立注册分区；Thread 的语义、状态、能力及文件变更通知持有同一分区绑定。产品所有者只聚合各分区快照、转发事件并协调关闭；不能通过“切换全局当前宿主”服务并存会话。重连只替换同一端点内的传输代次。

## 21.3 数据驱动服务器

服务器声明语言、扩展名、项目检测条件、操作集合、程序/参数/环境、初始化选项和工作区设置。所有语言使用通用客户端；语言特有设置由配置传递，不通过内置语言分支或安装驱动实现。

初始化选项通过 `initialize.initializationOptions` 发送；`settings` 通过 `workspace/didChangeConfiguration` 与 `workspace/configuration` 交付。后者按请求 section 从嵌套对象取值，未声明 section 返回 null；不猜测第三方服务器的私有结构。命令与参数按独立参数传递，环境按键值传递，路径以执行侧为准。

同一工作区中 ID 或语言冲突必须有可定位的诊断，冲突成员不能进入查询路由，其余不冲突成员仍可用。文件路径路由零匹配返回不可用、多匹配返回类型化歧义错误；不按配置顺序或名称猜测。

## 21.4 并行异步准备

项目激活、Thread 执行工作区准备及配置变更只发起受管理的异步准备，不等待所有语言服务器就绪。配置发现先发布状态，各服务器随后并行探测、启动、完成 initialize/initialized 握手。每服务器独立超时和失败；一个慢服务器不能延迟另一个健康服务器，初始化不进入普通对话的等待链。

可观察阶段包含配置加载、探测、启动、初始化、就绪、失败、停止及检测不匹配的禁用状态；未配置的工作区返回明确的空目录状态。就绪后的索引、忙碌、进度百分比与诊断继续沿原活动状态交付。探测成功不等于握手成功，不足以注册语义查询能力。

配置内容指纹涵盖程序、参数、环境、初始化选项及设置；变更只取消并回收受影响成员，再建立新代次。旧代次完成不得覆盖新代次。没有配置变化时不反复探测或重启。配置修复可在同一 Thread 中恢复，无需重建会话。

执行侧文件变更及安全运行时更新边界负责发现配置变化；显式 GUI 重载允许重新尝试失败配置。状态读取只克隆最新快照，不扫描配置、启动进程或等待初始化。

普通配置重扫保留内容未变的健康或失败成员，不产生自动重试循环；显式重载则重试失败或已退出成员，即使 TOML 未改也能在安装程序、修正外部环境后恢复。内容未变的健康成员不因显式重载重启。

## 21.5 状态与失败隔离

GUI 和只读 `lsp_status` 工具可以在未配置、加载中、初始化中、失败及就绪时读取当前工作区状态。状态包含配置来源、服务器 ID、阶段、活动、错误及修复线索，不返回环境值、初始化原文或其他可能含凭据的配置内容。查询不隐式执行探测或修复。

非法 TOML、不支持版本、冲突、程序缺失、探测失败、启动失败、握手失败/超时与运行后退出都保留为局部诊断。单文件错误不丢弃其他健康服务器。LSP 目录故障不得沿项目激活或工具组装链终止会话，也不得触发全局配置重置。

状态工具独立于语义能力常驻。`lsp_capabilities` 与语义查询工具仅在当前工作区至少一个服务器握手成功且仍存活时注册；报告和路由只包含健康服务器。运行后失败通过目录更新撤下能力，冻结声明不因此整批失效。已接受调用在执行前逐一验证当前授权；已撤下工具不执行，记录调用失败并交回模型，未受影响调用可继续。服务器内部错误同样返回真实局部失败，模型下一步使用当前有效目录继续，不取消会话或重新执行已完成调用。

## 21.6 查询与文档同步

工具输入遵循工作区路径授权。对外源码位置为从 1 开始的行号和字符位置，内部转换为 LSP 从 0 开始的 UTF-16 位置。查询操作覆盖定义、引用、hover、符号、实现、调用层级和诊断，受实际服务器声明与协商能力共同约束。

查询前发送必要的 didOpen/didChange；文件写入、移动或删除通知已启动服务器。URI 使用执行侧路径语义，Windows 扩展长度路径先转为常规路径。ContentModified 和启动阶段的暂时空结果可有界重试，不伪造文档变化，不以空结果冒充查询成功。

诊断属于单个服务器成员代次。成员被替换后，新代未发布诊断时不得回显旧代结果；旧 dispatcher 的迟到发布也不能污染新代。当前查询与计数只汇总当前健康成员拥有的诊断。

会话 `activeLspServers` 是该轮冻结的健康服务器集合；产品当前态通过 `readLspState` 与 `LspStateChanged` 交付。工具目录更新遵循现有冻结、授权及退役契约。

## 21.7 关闭与非目标

重载、取消和关闭停止新初始化，取消并等待所属后台任务，向进程执行 shutdown/exit，必要时终止并确认进程树回收。未确认回收保留失败事实，不报告干净退出。

不提供 LSP 市场、自动下载、IDE 虚拟文档或终端输出面板。智能体按系统提示与 `studio-config` 技能配置服务器，使用状态查询确认阶段，再用真实语义查询确认可用；失败时仍继续可以独立完成的普通开发工作。
