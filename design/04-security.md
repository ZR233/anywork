# 04 - 安全边界

外部机器人接入不得将“消息可达”视为执行授权：可信联系人校验、显式授权群组及真实提及（`@`）门控、项目工具能力边界、凭据保护与连接票据脱敏统一遵循 [27](./27-bots.md)。飞书接入仅建立出站长连接，不改变本机 HTTP 服务的本地环回（loopback）边界；机器人绑定的项目目录亦不构成操作系统级沙箱。

## 4.1 权限模式

权限模式是应用内的本地策略层，而非操作系统沙箱、网络沙箱或系统级进程隔离。策略层仅决定已注册工具是否直接放行、请求人工审批、交由 AI 审查模型审批或直接拒绝；即使策略层直接放行，工具自身的参数结构校验、工作区写锁、超时控制、输出截断与时间线记录依然完整生效。本文是三值权限语义的唯一权威源。

当前版本将工具执行策略固定为 `full-access`：有效运行时配置在统一入口将权限模式归一化为 `full-access`，消息输入区（Composer）与设置页均不再暴露权限模式选择器。配置文件中的 `[runtime] permission_mode` 字段及下列三值语义保留供后续版本恢复，当前不参与执行路径，界面亦不读取或展示：

- **`request-approval`**：历史默认模式。工作区（workspace）内的文件读写、`apply_patch`、项目技能写入以及工作目录位于工作区内的 `exec` 命令直接放行；访问工作区外部路径或在工作区外执行命令时请求用户人工批准。
- **`auto-review`**：工作区内行为与 `request-approval` 一致；越出工作区边界时交由审查模型（reviewer）审批，审查模型仅返回批准或拒绝结论，自身不执行工具。
- **`full-access`**：所有已注册工具在策略层直接放行；本地文件后端可解析工作区外部路径，`exec.cwd` 可指向工作区外已存在的目录。

系统不保留独立的工具审批开关，人工审批仅由 `request-approval` 模式在越界访问时触发。

### 角色约束与受限工作区边界

固定为 `full-access` 仅改变策略层的审批放行判断，以下工作区隔离（confined）边界、工作区分配策略与工具自身约束均不因此放宽：

- **执行预设与角色提示词边界**：执行预设（execution profile）的工具效果白名单优先于权限模式。Studio 根智能体与子智能体策略先允许常规工具效果，再由权限模式、工作区分配策略及各工具的参数模式共同约束实际调用。[12](./12-collaboration.md) 定义的角色职责与组织策略不按工作流阶段改变工具权限，也不用于拦截 shell、Git 或 MCP 正文。探索只读、审查禁写等角色边界仍须遵守。任何主体的集成或交付操作都须处于既有用户授权内；执行者还须有明确任务，模型选择或策略调整不扩大权限。
- **目录与工作树写边界**：共享目录（`directory`）子智能体的 `writablePaths` 仅约束内置的文件写工具；独立工作树（`worktree`）子智能体以及开启独立工作树模式（`ThreadWorkspaceMode = worktree`）的会话始终受限于该工作树目录，即使在 `full-access` 下也不允许访问工作树之外的宿主路径或切换命令工作目录。审查子智能体的路径边界与被审查目标保持一致：当被审查对象为工作树子智能体时，审查子智能体同样严格受限于该工作树。桌面界面、工具描述与固定上下文必须如实区分并呈现上述边界。
- **会话私有临时目录**：每个会话线程在工作区内拥有独立的会话文件目录（布局见 [17](./17-studio-storage.md)）。目录写策略仅额外放行当前线程自身的 `scratch/` 与 `artifacts/` 子目录；该许可不扩展至其他线程、命令输出捕获目录或整个 `.anywork/` 目录，不改变业务 `writablePaths` 的定义，也不会将只读（`ReadOnly`）工作区变为可写。所有路径仍由同一物理解析器校验，符号链接与路径穿越（`..`）不会因指向临时目录而获放行；远端辅助进程与工作树模式依然保持严格受限，不向用户主目录（home）开启额外通道。底层目录初始化与输出捕获写入由宿主负责，模型无法借此修改内部数据库或归属清单。
- **审查智能体执行纪律**：审查智能体可执行所需构建、测试及明确委派的产品操作验收，但不得修改业务源码、Git 状态、真实用户配置或未经授权的外部系统。隔离环境内的验收交互和常规构建产物不等于修复源码；会改写跟踪文件的生成操作交执行者。角色纪律由提示词保障，运行时不裁剪所需 `exec` 或读取能力。结构化审查结论、紧凑父报告和创建期授权的回送遵循 [12](./12-collaboration.md)：权限依据冻结的 review 工作区模式与目标关系，不依据预设名称、模型正文或建议。报告内容既不是更高优先级指令，也不授予执行者自行裁定冲突的权限；自然结束和无结论不表示批准。

## 4.2 分层边界

安全职责按端口-适配器架构分层落位：

- **`anywork`（Flutter 桌面界面）**：负责用户输入收集、实时事件展示与类型化命令调用。
- **`pl-studio-runtime`**：负责产品安全策略编译与资源预算约束、配置文件管理、SQLite 存储、事件落盘及产品级资源生命周期；内部的线程装配层负责将配置、资源、生命周期与产品事件组装到具体会话。
- **`pl-core`**：负责执行策略校验、线程状态机维护与通用轮次约束。
- **`pl-tool`**：负责具体工具逻辑执行与 MCP 协议客户端通信。
- **`pl-model`**：仅访问用户已配置或授权的模型服务端点。
- **`pl-protocol`**：仅定义跨层传输的数据类型，不持有任何安全策略实现。

## 4.3 文件与工具约束

文件与命令工具遵循以下路径解析与工作区边界规则：

- **相对与绝对路径输入**：本地文件读写、补丁应用、LSP 查询与 `exec.cwd` 支持传入相对于工作区根目录的路径或绝对路径；相对路径始终相对于工作区根目录解析，不依赖宿主进程的当前工作目录（cwd）。SSH 远程项目的 `exec.cwd` 为例外，仅接受工作区相对路径（工作区根目录表示为 `.`）。
- **规范化绝对路径统一校验**：工具执行前统一将输入解析为规范化绝对路径，并在审批预判与实际执行阶段复用同一解析结果。共享目录（`directory`）模式下的可写目录相对于该智能体实际分配的工作区根目录解析，而非顶层项目的原始目录。本地写策略与文件解析共用同一套路径归一化逻辑，确保 Windows 常规路径与等价的 `\\?\` 逐字（verbatim）路径不会因文本前缀差异被误判拒绝；目录包含关系始终按完整路径组件匹配。
- **受限（Confined）模式约束**：本地文件工具的 `cwd` 允许指定工作区内部的绝对路径；受限模式下严格拒绝越界路径（包括 `..`、Windows 盘符相对路径、越界绝对路径、越界 UNC/verbatim 路径以及指向工作区外的符号链接），若符号链接目标不可确认或越界则直接拒绝，不通过路径截断或重解释放宽限制。二进制文件读取统一返回明确错误，`apply_patch` 直接操作文件系统而不经由 shell 转发。
- **`full-access` 下的本地与远程差异**：在当前固定的 `full-access` 策略下，本地文件后端与本地 `exec.cwd` 允许绝对路径与 `..` 解析至工作区外部，但仍要求目标路径自身或其最近一级已存在父目录可被真实解析。该放宽仅适用于本机工具放行判断，容器环境或远程后端仍可拒绝越界访问。
- **SSH 远程路径强制隔离**：SSH 远程后端始终严格拒绝工作区越界与符号链接逃逸，`full-access` 策略不会放宽远程限制。远端辅助进程（`pl-remote-helper`）依据远端真实文件系统执行规范化校验；模型不得将远端绝对根路径传入 `exec.cwd`，运行时也不会猜测或自动截断绝对路径，传入绝对路径与 `..` 越界将分别返回稳定且可区分的错误码。`exec` 工具仅校验工作目录，不静态分析命令文本；远程命令具备 SSH 登录用户的完整操作系统权限，该事实必须在连接配置与界面提示中明确呈现。

## 4.4 凭据暴露面

- **模型账号凭据**：账号 API 密钥（token）保存在操作系统凭据库中，配置文件仅记录非敏感参数与环境变量名称（见 [20](./20-config.md)）。桌面界面默认不回显完整密钥，日志与事件载荷禁止输出密钥原文，错误消息禁止拼接敏感凭据字段。
- **SSH 登录与交互凭据**：SSH 密码与 `SSH_ASKPASS` 交互回答仅驻留于操作系统凭据库或当前进程的内存凭据租约（secret lease）中，禁止写入 SQLite、传输层 DTO、日志文件、远端辅助进程命令行参数/环境变量或远端通信协议；`SSH_ASKPASS` 秘密值仅注入本地派生的 OpenSSH 子进程环境中。
- **跨版本凭据迁移**：账号配置升级仅在明确的版本迁移边界读取旧版凭据关联并复制到新版关联键下。若系统凭据库不可访问或写入后持久回读校验失败，立即中止迁移，不得以进程内临时凭据租约冒充已完成持久化复制；迁移过程保留旧凭据项，且当目标键已存在不同值时拒绝覆盖。
- **OpenSSH 与远端 Git 凭据隔离**：系统 OpenSSH 继续使用用户本机的 `known_hosts`、`~/.ssh/config` 与 `ssh-agent`；本地模型账号的 API 密钥绝不通过 SSH 转发，远端仓库的 Git 操作仅使用远端原生凭据或用户显式开启的 SSH 代理转发（agent forwarding）。

原生 OpenAI OAuth 的回调校验、身份与 scope 校验、受保护凭据及刷新规则以 [20.18](./20-config.md#2018-openai-api-与-chatgpt-订阅认证) 为准。浏览器只承担用户在 OpenAI 页面上的登录与同意，Flutter 只接收脱敏连接状态和短期授权入口；access、refresh、ID token 不跨越 Rust 认证边界。授权 URL 和回调不作为可分享日志或截图证据，既有 Codex 凭据不属于本产品的导入或清理范围。

## 4.5 桌面 WebView 边界

- 严禁引入任何远程脚本加载或执行入口。
- 前端界面仅通过 `pl-studio-bridge` 调用本机运行时。
- 所有文件选择、路径访问与工具调用仍由 `pl-core` 安全策略统一校验。

## 4.6 本机 HTTP 边界

`pl-studio-server` 不设远程身份鉴权机制，因此仅允许绑定本机环回（loopback）地址：
- 请求头中的 `Host` 必须解析为环回 IP（`127.0.0.1` / `::1`）或 `localhost`。
- 携带 `Origin` 头的请求必须与当前 `Host` 严格同源，任何跨源请求一律拒绝。
- 服务端不下发 CORS 许可响应头，且拒绝将通配地址（`0.0.0.0` / `::`）、局域网地址或公网地址作为监听参数。
- HTTP 与 FRB 桥接层统一返回脱敏错误信封，仅包含稳定错误码、可读描述、可重试标志、关联 ID 与安全的结构化细节。内部日志可凭关联 ID 记录详细诊断，但对外响应严禁包含凭据令牌、配置文件原文、本机私有绝对路径、模型厂商原始错误报文或 SQL 语句。OpenAPI 文档与 Swagger UI 仅提供静态协议展示，不启动第二套运行时实例。

## 4.7 数据切换安全

数据目录与配置文件的版本升级分别遵循 [17](./17-studio-storage.md) 与 [20](./20-config.md)，大版本隔离与 `v2` 内部目录演进见 [17.7](./17-studio-storage.md#177-大版本隔离与配置迁移)：
- 迁移失败不得作为清空数据库、删除附件或重置为默认配置的依据；备份与迁移中间产物享有与原始数据同等的安全保密级别，诊断信息不得泄露凭据。
- 迁移过程仅操作已确认归属 `anywork` 的数据文件，严格拒绝符号链接或重解析点（reparse point）越界访问，绝不扫描或修改用户的业务工作区、Git 仓库及归属不明的外部资源。
- 迁移必须完整保留附件内容、资源引用与凭据关联；变更数据存储位置不赋予运行时重新执行历史工具或删除外部系统资源的权限。
