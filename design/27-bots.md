# 27 - 外部机器人与飞书接入

本文是机器人管理、飞书协议边界、首配、授权、会话工具和资源生命周期的权威契约。
Thread、历史、权限、配置与前端所有权分别遵循 [14](./14-runtime-host.md)、
[15](./15-session-storage.md)、[04](./04-security.md)、[20](./20-config.md) 与
[25](./25-frontend-state.md)。本篇描述新增目标契约；功能与平台兼容性以实际验收证据为准。

## 27.1 目的与组件边界

外部机器人把已授权的飞书用户消息送入现有 Studio Thread，并把正式回复送回原会话。
渠道接入不是模型 provider、可派发的 child Agent Profile、MCP server 或另一套会话引擎。
飞书会话和普通会话一样由统一 Agent 定义装配根 Thread（见 [12](./12-collaboration.md)）。Studio runtime 是配置、
连接、消息受理、会话映射与发送操作的唯一 owner；GUI、HTTP 与模型工具共享这些能力。

本版本仅接入飞书中国版的自建应用，采用原生 Rust HTTP/WebSocket 适配，无 Node/npm、
OpenClaw 或第三方飞书 SDK 运行依赖。HTTP、WebSocket、Protobuf 分别复用成熟组件，
产品只维护所需的飞书协议。微信、Lark 国际版、公网 webhook、用户身份 OAuth、媒体发送、
卡片交互审批和文档/日历能力不在本次范围。出站支持 Markdown 与 JSON 2.0 流式卡片，
使用官方消息与 CardKit HTTP 能力，不引入额外 SDK 运行时或自研 Markdown 渲染器。

协议以飞书开放平台文档为准；文档未展开的注册与长连接细节参考官方
[Node SDK](https://github.com/larksuite/node-sdk) 的 `1.76.0` 发布内容
（revision `1889911f0841e669de0be5bd02c737a3f1fd20fa`）。引用或改写其 MIT 内容须保留
相应归属和许可。已调查第三方 `openlark` 的发布能力，但本次不依赖它，也不以未发布的
高层 API 代替已核实契约。
可访问的官方仓库参考快照另固定为
[`b188be60134d409b61259546bcf69c731d2b0b7c`](https://github.com/larksuite/node-sdk/tree/b188be60134d409b61259546bcf69c731d2b0b7c)，
协议事实须注明对应来源，不将仓库快照与 npm 发布包的 commit 身份混用。

## 27.2 管理、配置与凭据

机器人管理根为 `<StudioHome>/v2/bots/`，随 Studio home 参数及环境变量解析，处于
[17](./17-studio-storage.md) 的 v2 备份边界内。它不是项目的 `.anywork/worktrees/`。
每机器人使用运行时生成且经过校验的稳定 ID，不把显示名称、App ID、会话 ID 或平台消息
ID 直接拼作物理路径。单个机器人保存版本化非敏感配置与可靠状态，具体布局归 [17](./17-studio-storage.md)。

通用配置包含稳定身份、名称、存储项目、启停、模型路由和独立 `configRevision`；
平台配置通过枚举分支保存，当前飞书分支持有应用 ID、可信用户与群身份。
旧的平铺平台字段仅在版本迁移边界解码，包括凭据恢复记录中嵌入的旧配置。
配置 revision 只随 desired 配置推进，
不因心跳、重连或查询推进；保存、启停和授权变更携带预期 revision。重复 App ID 不得建立
第二个活动机器人，因为飞书同应用的多条连接会分流事件。

首版不把已有业务会话迁移到另一应用或项目：已有 Thread 映射或已受理输入后，关联项目
不可原地更换；已有平台会话、受理/发送记录或可信范围后，App ID 不可原地更换。
尚未投入使用的配置可更正，成功后旧项目工具权限立即失效；校验与新准入相互排斥，
不能在检查为空后被在途消息跨越。名称、凭据轮换、授权与启停不受此身份约束代替。
拒绝身份变更须保留原配置、关联与服务，不删除旧数据，也不暗中搬移 Thread 工作区。
管理快照提供应用与项目是否可更正的权威能力事实，Client 不从本地缓存或连接状态猜测。

App Secret 使用独立的系统凭据 account `bot:<bot-id>`，不写普通配置、SQLite、日志或
工具结果。该账户的受保护载荷按版本保留当前材料与在途候选，非敏感配置只保存所选版本
引用；配置中的引用是当前凭据关联的唯一事实，系统载荷不另立一个可独立切换的当前指针。
引用由 runtime 生成并校验，绑定机器人与应用，不由产品请求或模型指定。正常运行只解析
当前载荷结构，旧原始 secret 仅在明确的配置/凭据迁移边界转换，迁移中断可恢复且保全原关联。
引用区分持久材料与仅当前进程的租约关联，两者不能在读取或重启恢复时自动互换。
转换前先持久化不含 secret 的迁移意图及目标版本身份；恢复通过该身份与实际配置/材料
核对已完成的步骤，不能在多版本载荷中猜测当前版本，也不能仅因原值能解析成结构化文本
就把它当作已迁移材料。无法证明关联时保留现场、封闭准入并提示本地恢复，不覆盖原值。

凭据替换沿用 Preserve/Replace/Clear 语义。Replace 先准备有界候选并确认其实际持久性，
再原子提交配置引用；提交确定前原引用及其材料保持可用，不提前发布候选配置、撤销原授权
或启动新连接。失败不切换关联；若原子替换可能已发生而后续同步失败，须保留两侧材料，
封闭该机器人准入并明确报告提交待确认，由同一 owner 核实/恢复，不能假报已回滚或盲目重做。
恢复记录须能区分本次操作的原配置、目标配置与候选身份；准备中断、配置替换后尚未推进
记录，以及清理中断都依据实际配置裁决，不能仅凭记录阶段判定未提交。确认原或目标配置
仍须完成对应持久性确认；未知、缺失证明或不匹配的现场保全并保持待确认，不能永久只有
“待确认”标签而没有可接续的核实路径。
恢复时的准备记录不能证明配置写入已经成功：目标替换后记录推进也可能失败，读回目标
不代替持久性确认。只有本次调用已取得的确定提交事实可以直接沿用；重新恢复须补齐所
识别配置的持久性证明。原配置不存在且裁决未提交时，当前引用仍为空，不能把候选目标
当作原配置来保护材料或发布机器人。
系统凭据与进程 lease 均按精确版本选择，缺少所选版本不得回退到其他旧值。
允许更正 App ID 时，Preserve 保留当前所选 secret 的值，但须为新应用关联准备新版本，
不能直接复用绑定旧应用的引用；原引用仍保留到提交确定。当前没有凭据引用时，Preserve
保持空关联，不从系统中遗留的未引用材料恢复旧密钥。

Clear 先确定提交空引用并失效旧认证租约，再回收不再引用的系统材料。清理未完成与配置
已生效分别表达，保留可重试 owner 和诊断，不宣称物理删除已完成，也不恢复旧关联。
候选、迁移与回收有资源上限，不删除仍被当前引用或未决提交所需的版本。
系统凭据不可用时仅能使用现有进程 secret lease，并显式标记 `sessionOnly`，不能宣称已
永久保存；重启丢失 lease 后，即使系统中还存在旧版本也不得据此报告 `stored` 或启动连接。
系统关联暂不可读取时，只可借用同版本、同机器人及应用的现有进程 lease，并报告
`sessionOnly`；没有可用 lease 时区分系统不可访问的 `unavailable` 与材料确实缺失的
`missing`，不把读取失败当作缺失。仅进程关联始终只选进程 lease，不能转读系统材料。
材料损坏或其他读取失败不改变已经确定的配置提交结论：凭据可用性保守表达为
`unavailable`，另以安全诊断区分服务不可访问与材料无效，不据此将无效材料自动降级为
lease。后续明确 Clear 仍可撤销已经确定的关联。
两个材料来源独立保留，不能由“系统优先”的合并读取遮蔽所选进程版本；准备与回收也按
所选引用及未决操作分别保护来源。清除不以系统材料可读取为前提，配置确定为空后即撤销
本地认证，系统回收失败继续表达为待清理，不删除仍被进程关联选中的材料。
准备新候选遇到系统不可访问时，可在独立进程 lease 中追加该候选并如实选择进程引用，
不能把不可访问的系统载荷当成空值覆盖，也不能把读取已有引用的规则放宽为任意旧值。
系统写入失败的降级不得整包覆盖另一来源的 lease，尤其不能在配置提交前丢失当前选中
的进程版本；两侧材料的保全须覆盖故障和中断，不依靠事后补写恢复旧值。
凭据能力继续由现有配置基础设施持有；机器人只取得其窄作用域能力，不另建凭据服务。
机器人事务与恢复属于每个机器人自己的配置 revision、数据目录和生命周期，不复用主配置
迁移的全局操作目录，也不改写账号或 SSH 凭据格式。阻塞凭据访问由受控工作 owner 隔离，
取消或关闭后须观察真实终态，不能遗弃晚到写入。
配置及凭据修改由每个机器人的操作 owner 串行推进；跨机器人应用唯一性使用短认领，
冲突检查与保留认领必须在同一原子裁决中完成，不能先检查成功、释放边界后再登记候选。
不能持有全局配置或 registry 锁等待凭据访问、文件同步或网络回收。最终提交阶段封闭该
机器人的新准入，重核配置 revision、身份约束与操作所有权；准备阶段不提前发布候选配置。
应用切换、停用及授权范围更新先隔离旧回调并等待旧连接真实停止，再释放旧应用占用；
代次失效不代替 socket 与任务回收。回收失败保留旧占用及恢复义务，不妨碍如实发布已经
确定保存的配置与独立诊断。恢复准入前须确认旧连接已收束、当前配置已核实；新连接沿
现有生命周期登记并使用该配置，不让旧连接携带的可信范围在提交后继续受理。
身份复核针对完整目标应用与项目，覆盖准备期间新增的 Thread、受理、平台会话、发送及
可信范围事实；这些事实不推进配置 revision，不能用 revision 未变代替占用复核。
准备完成与配置提交之间有明确的所有权交接：只有最终准入重核成功、认领提交后才能写入
目标配置。重核拒绝或关闭先获胜时，未提交候选仍由原操作回收或保留可恢复义务，不能
依靠提前封闭整个准备期、长期持有准入锁或事后发现冲突来代替裁决。
操作 owner 拥有准备、提交核实、权威状态发布及后续连接协调的完整工作，而不只持有一次
阻塞调用。调用方停止等待不撤销该 owner，也不遗弃晚到提交；任务创建与登记在同一
生命周期边界裁决。退出先封闭管理操作的受理，再等待已经受理的操作到可恢复的真实终态。
启停、可信联系人和群授权的配置修改同样服从该串行与恢复边界，不能绕过未决提交直接
覆盖配置文件。配置已确定后，连接协调或清理失败独立报告，不把保存结论改回未保存。
已受理命令的完成结果与本次操作身份绑定，并为尚未取走结果的等待者独立保留；后继
操作或注册本地保存不能重置、替换这些结果，也不能只过滤身份却丢掉原结果而永久等待。
工作任务异常终止时同样结束这些等待，返回安全的提交待核实错误；不能把异常当作回滚，
也不能让仍由记录持有的完成通道永久没有结果。提交错误按原 journal 与实际文件核实后
再决定准入、认领和恢复投影；已确定保存后的配对清理失败单独诊断并保留重试义务，
不得因清理失败永久封闭已确定配置或撤回其保存回执。
日志与实际文件已证明的既有保存结论不再次作为新提交授权：恢复准确同步该结论、核实
当前归属与占用并协调连接，不因后来占用或版本变化把已经确定的 Applied 改报为未保存。
尚未提交的候选仍必须经过最终准入；不能以恢复既有事实为由绕过新副作用的裁决。
准备失败同样依据实际 journal 核实已发生的步骤：确认未提交后归还临时应用认领，存在
未决义务则保留相应认领与可恢复状态，不能把普通错误留成永久占用。
未提交候选仍待清理时，即使原配置可正常发布，也继续保留候选目标应用的占用；恢复事实
须保留该目标，不能用回退配置的应用替代或丢失它。
封闭受理与任务登记共享生命周期裁决，关闭已扫描完的 owner 不能再被迟到调用登记新
工作。连接状态观察者也保留到真实 join 终态；取消信号只表示请求退出，不代替等待，
关闭 future 被取消后仍须能接续回收，不以“之后会退出”接受遗失的句柄。
后台恢复与状态发布遵守相同的登记、封闭和回收约束，不能先创建任务再以非阻塞登记失败
为由遗弃句柄；重复加载也不能覆盖尚未回收的恢复 owner。
成功关闭并确认全部工作与连接真实终态后，解除 runtime 与长期 owner 之间的强引用环，
释放持有数据库、HTTP 客户端和凭据租约的运行时记录；保留普通不可变快照不等于保留这些
资源。关闭失败仍保留必要 owner 供再次回收，不能为打破引用环提前清空未解决任务。
此释放仅针对进程内所有权，不删除机器人配置、数据库、历史或未决恢复材料。
成功后的重复关闭保持幂等；释放资源记录不把已保存的机器人改报为已删除，也不使最后
发布的普通快照依赖仍然存活的数据库、连接或凭据 owner。

读取所选凭据也受运行时所有权约束。启动恢复、显式重试、令牌准备与连接协调的阻塞读取
不得直接占用异步执行线程；读取完成后使用前重新核对当前机器人、应用、所选引用与操作
代次，不能以晚到材料恢复已清除或被替换的认证。只有 journal 而尚无确定配置的目录同样
进入原操作的恢复与诊断，不能在重启时因缺少普通配置而永久丢弃未完成义务。

凭据可用性与操作状态分别表达。管理快照提供 typed `credentialOperation`：`idle`、携带
`operationId` 的 `preparing`、`commitUncertain`、`cleanupPending`；清理待完成另带
`configCommitted`，区分本次配置已生效与未提交候选的回收。操作状态只含非敏感身份，
不暴露 secret、候选材料或内部版本引用。读取失败、提交待确认与清理未完成分别保留诊断，
不能将它们折叠成“未配置”或“保存成功且已物理删除”。
保存命令只在本次配置确定生效时返回已应用的持久回执；此时材料不可读、连接失败或
清理待完成仍保留各自诊断，不撤回该回执。已确定未提交或仍待确认时，命令准确返回
失败或待确认原因，同时保留 canonical 操作状态；错误响应不隐含回滚，也不代替后续
核实。恢复后的认证失效与连接协调按实际已确定配置及所选引用推进，不依赖一次临时
调用是否曾走到普通成功分支。
尚无可发布的确定配置时，操作通过管理快照的 `pendingCredentialOperations` 表达，只含
`botId`、同一 typed `credentialOperation` 及安全诊断；不能为展示进度把候选加入已配置
机器人列表。已有确定配置的操作状态仍随该机器人的快照提供，两者投影同一个操作 owner，
不另建命令状态事实源。本地重试可按该机器人身份核实原保存操作；未确定配置前不启动
连接，也不向项目工具暴露未完成机器人。
租户 access token 使用[当前官方 OAuth 接口](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/authentication-management/access-token/tenant_access_token)
（2026-10-14 更新）：`POST https://accounts.feishu.cn/oauth/v3/token`，以
`application/x-www-form-urlencoded` 提交 `grant_type=client_credentials`、`client_id`
和 `client_secret`，只使用 `client_secret_post` 一种认证方式。自建应用不传 `tenant_key`，
不额外申请 scope，沿用应用已开通的应用身份权限。复用现有 reqwest、url 编码和 TokenLease，
不引入第二套 OAuth 客户端、缓存或运行依赖。
成功只消费 `access_token`、正数 `expires_in` 和 `Bearer` 类型；JWT 按完整字符串保存与传输，
不假定旧 token 长度。HTTP 400/500 中的 OAuth 业务错误仍保留平台码，认证、未启用/未安装、
参数错误与可重试的服务错误分别分类，不回显原始响应或凭据。不再调用旧 token 接口，
也不在失败时自动回退。
租户 access token 只在 Rust 内存按实际过期信息管理，同账号刷新合并；失败不猜测 token
有效期。后续连接或清理失败不把已确定提交的配置改报为未保存。

每个机器人配置和状态都带版本，读取失败只产生该机器人诊断；不得触发全局重置、删除
目录或丢弃其他机器人。现有版本内结构变化仍须迁移，不以重新建空状态代替。
安全目录身份须与普通配置及 journal 中的原配置、目标配置身份一致，并在凭据访问、
恢复发布和连接启动前核对；不一致时保留现场并以该安全目录的本地诊断隔离。非法目录名
不构造可操作的机器人身份，继续安全隔离并记录固定诊断，不回显其原始内容。

## 27.3 首次配置与注册

GUI 提供“创建并连接飞书应用”和“连接已有应用”两条入口，均先确认名称、关联项目、模型可用性
与远程执行风险。扫码流程参考 OpenClaw 的首用户绑定体验，但不依赖其网关。

注册开始后，当前尝试独立展示在机器人页顶部，不被首配表单或设置页导航隐藏；返回页面
继续观察同一 canonical 尝试。等待期间提供“打开飞书继续”、手机扫码与浏览器继续三种
本地入口，并保留可见的取消操作。只有用户点击才打开外部应用，不由轮询状态反复唤起。
外部链接统一通过 Flutter 官方 [url_launcher](https://pub.dev/packages/url_launcher)
打开；使用 `canLaunchUrl` 检查系统是否注册飞书协议，不自行维护安装路径或注册表判断。
仅检测成功时显示客户端入口；未安装、检查中或检查失败时直接引导手机飞书扫码，二维码
始终保留。检测结果不代表登录或授权状态，也不声称检查失败一定是未安装。
采用官方 [AppLink 结构](https://open.feishu.cn/document/common-capabilities/applink-protocol/applink-introduction/applink-structure)
定义的 `feishu://applink` 直接唤起协议，通过
[端内网页协议](https://open.feishu.cn/document/common-capabilities/applink-protocol/supported-protocol/open-the-web-view-in-feishu-to-access-the-specified-url)
在独立窗口打开当前可信验证链接；原始链接作为整体 query 值编码，不改写授权参数。
只有生产允许的 HTTPS 授权来源可传入真实客户端；隔离 fixture 保留自身网页和二维码入口。
操作系统接受唤起请求不等于客户端已打开，更不等于授权成功；仍保留扫码、浏览器入口及
服务端轮询结果。链接打开失败不回显含授权材料的底层异常。

保存后的机器人详情提供官方
[打开机器人会话](https://open.feishu.cn/document/common-capabilities/applink-protocol/supported-protocol/open-a-bot)
入口，按当前 App ID 打开飞书聊天，并提供 HTTPS AppLink 网页入口。
打开聊天不授予入站信任、不代替发送消息，也不证明应用已发布或对当前用户可用。

原生注册使用官方 SDK 所采用的设备授权接口，支持验证链接、二维码、服务端轮询间隔、
`authorization_pending`、`slow_down`、拒绝、过期、取消与失败。二维码和验证链接是敏感的
短期授权材料：只交付当前注册 UI，不写日志、普通机器人配置或公开证据；设备码不进入
产品 DTO。每次注册拥有独立身份与代次；取消、过期和替换先使旧代次失效，晚到结果不得
保存凭据、发布机器人或再启动连接。平台侧可能已完成的应用不由本地取消自动删除。
轮询使用本次授权返回的间隔；每次 `slow_down` 按 RFC 8628 及固定官方 SDK 的约定在
当前间隔上增加五秒，并用于之后的轮询，不能固定重置为五秒。授权截止时间同时约束
等待与在途轮询响应，响应到达后仍须在完成认领前核对期限，不能以请求结束重算授权期。
准备授权请求也属于该尝试的生命周期。本地取消与完成提交通过同一原子裁决边界确定先后：
取消先得到确认，则晚到的准备或轮询结果不能重发等待状态、创建本地机器人或保存凭据；
完成先认领提交，则取消不能再承诺已取消，须准确表达提交中或已确定的结果。只有配置与
凭据关联确定提交后才发布完成。外部请求、持久化与任务回收不阻塞裁决边界；从准备到
提交、取消及关闭始终保留真实工作 owner，不以占位任务或遗弃任务冒充完成。
注册完成的业务认领不替代 27.2 的配置最终准入：关闭先封闭最终准入时仍回收尚未提交的
候选；配置提交已获准时才继续真实提交与核实，不把更早的注册认领当作忽略封闭的许可。
同一开始操作在当前尝试内重复提交时复用该尝试，不重复请求平台创建应用；同一操作身份
携带不同名称或项目时拒绝冲突。并发开始也遵守此约束：新尝试的准入身份与真实工作登记
在同一生命周期边界确定，门外回收完成后不能无条件覆盖期间已登记的后继尝试。替换等待
中的尝试与运行时整体封闭分别裁决；替换、终态或调用方停止等待都不能永久禁止后续首配。
已确定完成的尝试不因替换改报取消；尚未终结的连接协调尾段仍有可接续回收的持久 owner，
后继登记或回收等待被取消不能覆盖、遗失该 owner，也不累积无界退休工作。
使旧尝试失效或取消的状态转换有独立于调用方等待的发布责任；调用方停止等待后仍须发布
安全的 canonical 状态，不能长期保留已经失效的等待状态或授权链接。
开始与取消的回执只确认瞬时注册动作，不冒充持久配置
保存。完成认领后对外发布不含授权链接的 typed `committing` 状态，携带 `attemptId` 与
用于本地保存/恢复的 `botId`；此时取消返回明确的忙碌原因，不发布 `cancelled`。
本地保存已确定未提交或仍待确认时不发布 `completed`，以失败诊断及同操作身份的凭据
恢复投影说明本地义务；重试这些义务不重新注册平台应用。终态清除设备码与验证链接，
已有配置的连接失败仍单独通过连接状态表达，不撤回已确定的注册保存结果。

注册返回的验证链接在进入 UI 前校验来源。生产只信任默认 HTTPS 来源
`https://accounts.feishu.cn` 与 `https://open.feishu.cn`，拒绝用户凭据、非默认端口和
fragment；保留返回的 path 与必要 query，不按未经核实的路径白名单改写链接。不接受
Lark 国际版来源，也不以整个 `*.feishu.cn` 后缀作为授权链接的信任范围。此集合是产品的
保守安全策略，并非官方承诺所有返回链接只来自这些来源；遇到其他来源明确拒绝，并保留
手工连接已有应用的入口，不静默放宽。官方 SDK 固定快照的
[注册实现](https://github.com/larksuite/node-sdk/blob/b188be60134d409b61259546bcf69c731d2b0b7c/scene/registration/index.ts)
只解析服务端链接而不验证 origin，因此不能仅以“官方响应”代替本边界。
debug fixture 只接受当前描述绑定的同一 loopback HTTP 来源，不能借此接受其他本地端口
或生产来源。拒绝与错误诊断不回显原链接，也不跟随重定向来放宽来源。
响应明确标识 Lark 国际版租户时拒绝本地接入，不仿照多区域 SDK 自动切换轮询域名。
缺少品牌或明确为 `feishu` 时按中国版端点继续；其他未识别的显式品牌按协议不支持拒绝，
不把未知值、空白值或未来品牌猜成中国版。拒绝诊断不回显原始品牌或授权材料。

注册成功返回有效扫码用户身份时，可将其设为该机器人的首位可信用户；缺少身份时不得
回退为开放访问。手工输入已有 App ID/Secret 同样默认拒绝所有尚未批准的远程用户。
配置与凭据保存成功和真实连接成功是两件事。

扫码注册使用显式的应用身份权限模板，不启用平台预设权限包，也不请求用户身份权限。
默认模板包含 `im:message:send_as_bot`、`im:message.p2p_msg:readonly`、
`im:message.group_at_msg:readonly`、`im:chat:readonly`、`im:message:readonly`、`im:resource`
与 `cardkit:card:write`，
订阅 `im.message.receive_v1`；分别用于统一发送、接收单聊与真实提及、群目录及按需历史
读取、既有图片/文件资源接收，以及流式卡片创建与更新。新增 CardKit 权限不替换或撤销
既有 `im:resource` 能力。不以通用读写权限 `im:message` 替代这些能力，也不默认请求 `im:message.group_msg`。
首次配置如实说明这些申请范围；声明权限不等于管理员已经批准或应用已经可访问数据。
[获取历史消息的官方权限要求](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message/list)
（文档标注更新于 2026-04-10）将单聊历史所需的消息只读权限与群历史额外权限分别列出；
群历史仍需本地用户在平台单独开通相应权限，产品不能在遇到拒绝时自动扩大授权。

手工配置指引明确机器人能力、`im.message.receive_v1` 事件、长连接接收方式、IM 查询/发送
权限、`cardkit:card:write` 与发布要求。既有应用缺少卡片权限时明确提示管理员补充授权，
不将声明权限视为已经批准，也不悄悄改用普通消息掩盖卡片失败。群历史等额外权限单独说明，
不自动申请读取全部群消息。企业租户仍受
管理员审批和应用可用范围限制；没有获准发布时保留配置、呈现待办，不假装已可使用。

### 27.3.1 机器人工作区、模型与会话操作

机器人名称、模型路由、工作区和状态属于通用产品配置；平台专属应用与连接参数由带平台
标签的枚举承载，目前只支持飞书中国版。页面遵循总览、详情、聊天逐级导航，进入下一层
后隐藏上一层列表，返回保留位置。连接、模型与最近聊天优先展示，凭据及排障按需进入。

每个机器人拥有 `v2/bots/<botId>/workspace/` 受管本地工作区。其聊天仍分别绑定独立根
Thread；执行文件复用工作区内按 Thread 划分的会话目录，上传文件、scratch、产物和
按需建立的 uv 环境不写入业务项目。可靠历史与附件仍使用统一会话存储，工作文件是执行
物化。受管工作区采用其规范化物理路径，不进行普通业务项目的向上 Git 根发现；即使
StudioHome 位于仓库子目录，根会话、子会话及冷恢复也必须保持机器人目录为执行根。
工作文件不是第二份附件目录。已有机器人迁移保留 Thread、输入、回复和凭据身份，迁移中断
必须可接续；不搬移归属不明的项目文件，也不重新执行旧输入。

机器人模型路由是所有绑定聊天的配置来源，当前模型请求保持冻结，后续执行应用新配置；
普通会话页面显示该归属并跳转机器人配置，不为同一聊天提供相互竞争的模型配置。
桌面提交先校验调用方观察到的会话路由 revision，再在同一受理锁内应用机器人配置；
不能把本次受理自身产生的模型更新误判为过期提交。历史身份尚未落盘时，驻留 pending
输入和精简的 terminal identity 都表示已受理、待持久化，不重新生成附件草稿并再次提交。

机器人根 Thread 安装 Studio 产品工具 `list_sessions`、`get_session`、
`search_session_messages`、`read_session_messages`、`send_session_message`。
查询覆盖所有项目，目录与内容复用现有 owner；正文搜索支持中文、按有界游标接续，不能
把截断预览或局部扫描当成完整搜索。读取不启动执行 owner。发送通过普通用户输入受理链，
稳定操作身份防止重复执行，附件只能引用来源会话已归档的资源并导入目标会话；代发来源
保持可见，不取得系统或审批身份。暂不提供创建、停止、归档等管理工具。
机器人根 Thread 另安装会话交互决议工具 `read_session_interaction`、`approve_session_plan`、
`revise_session_plan`、`answer_session_questions` 与 `decide_session_tool_approval`，用于在可信
入站用户显式指示下代为处理其他会话的待决交互；契约见 27.7。

## 27.4 入站授权与会话映射

机器人关联项目不构成 OS 沙箱；界面必须说明当前工具有效策略为 full-access，参见
[04](./04-security.md)。以下是机器人准入约束，而不是对 shell 的安全隔离承诺：

- 私聊仅允许可信用户；未知用户形成有界、可在本地确认的配对请求，不触发模型或工具。
  批准和撤销是显式本地操作，不能由远程消息自授权限。旧未授权消息不因批准自动执行，
  用户批准后按提示重新发送。
- 群聊默认关闭；只有显式授权的群、来自用户而非机器人的消息，且真正提及本机器人时才
  进入执行。`@全体成员` 不代替对本机器人的提及。
  群授权作用于该群中的用户消息，不额外叠加私聊的可信联系人名单；本地启用群时须说明
  群内用户的真实提及可触发本机智能体。私聊配对不作为群授权或群目录的替代。
- 入站可信范围与项目的 `toolsEnabled` 分别配置：后者允许该项目的智能体查询/发送，
  不隐含信任所有远程发送者；改变项目或撤销授权后，旧工具调用不得借缓存扩大访问。

其中 `trustedChatIds` 只控制群消息是否能发起智能体执行；`toolsEnabled` 控制关联项目是否
能访问机器人本身可见的会话。查询/发送必须验证平台会话可见性：群来自平台成员关系，
单聊来自已观察的单聊身份，不能把群写进单聊目录作为授权捷径。撤销项目工具授权或改变
关联项目立即撤销相应查询/发送；关闭群入站授权不会隐式改变另一项项目工具授权。首配
界面须分别说明这两项范围，不能为了向群发消息而要求用户同时开放该群的远程执行。
`toolsEnabled` 不是机器人功能总开关：桌面所有者显式查询/发送，以及已授权入站消息在
原会话的正式自动回复，不以此开关作为额外前提；它们仍需各自的本地/入站来源与目标
可见性验证。不能把这些来源的权限借给模型工具，也不能要求用户为了收到自动回复而
给项目开放跨会话的机器人工具能力。

映射以机器人和平台会话身份隔离，关联一个现有 Studio 根 Thread。首次创建和后续受理使用
同一 Thread 工厂与用户输入链，复用 model route、历史、计费和目录时间。平台消息 ID 形成
稳定输入身份；重推、重连、重启重复消息命中原身份，内容冲突显式失败，不能重复启动模型。
同一平台会话的不同消息是独立输入，交给同一 Thread 的非打断串行驱动逐条消费；后到消息
不取消正在生成的回复，也不将两条独立正文合并成一次执行。仍使用统一的资源准备、授权、
路由与持久幂等边界，不新增机器人队列或绕过待决交互的专用决议入口。
归档或缺失的目标 Thread 不偷偷映射到其他会话，应报告需要恢复或显式新建。
新建飞书根会话选择固定的飞书 Agent 定义，不增加逐机器人提示词编辑或 Profile 选择入口。
定义指导模型直接输出适合飞书的 Markdown：标题、段落、列表、引用、链接、行内代码、
带语言的围栏代码块与简洁表格；区分普通消息和卡片能力，不输出 CardKit JSON、不把整段
答复包装成代码块，也不承诺任意 HTML。自动回复由宿主发送，模型不得为同一答案重复调用
发送工具。提示词只指导内容，不授予权限或替代大小和完整性校验。
Agent 指令与 Mode 分离，冻结及迁移遵循 [20](./20-config.md#206-提示词配置)。已有会话
保持原指令；采用新定义使用既有显式新建本机会话动作，不因升级自动重建 Thread。
首次创建与绑定之间的失败必须可恢复到同一创建身份，不能留下永久占位或在每次重试时
创建孤立 Thread。可靠受理记录须能恢复尚未交接的输入，并从既有 Thread 受理事实判断
是否已经交接，不能把身份去重命中直接等同于执行和回复完成。
连接代次只隔离旧连接回调，不是会话绑定的 revision；受理记录固定应用、项目及绑定创建
身份/版本，连接重建不改变已受理工作的归属。受理、映射切换与身份变更校验共享同一权威
准入边界；Thread 创建和网络请求不能占用该边界而阻塞平台 ACK。取消、预算暂满或恢复
失败须保留可恢复工作及诊断，不得借普通成功返回把未完成义务标记为完成。
入站冻结使用实际已认领绑定的创建身份与 revision，包括显式切换后仍在创建中的绑定；
不能以首次创建的默认身份或固定初始水位代替当前绑定事实。

本地所有者可针对已核实可访问的会话显式“新建本机会话”，用于归档、缺失或异常关联的
恢复，也可明确开始新的本地上下文。该动作携带操作身份、预期配置及绑定 revision，
在当前应用和项目内创建新的根 Thread 并切换后续消息的映射；不接受任意外部 Thread ID。
旧 Thread 与已受理事实保留，旧输入及旧在途回复不转移到新上下文，也不重新执行；已提交
输入的结果仍可在原 Thread 查询。动作重复受理须复用同一次创建，失败可恢复，不能每次
重试创建新 Thread。普通连接重试、平台重推与归档后的新消息不代替该本地明确意图。
已完成操作的重试仍核对其持久创建身份及 Thread；若当前绑定已被后继显式操作替代，
明确报告原操作已被替代，不把后继绑定冒充原操作的幂等结果，也不切回旧绑定。

首次接受该创建意图时，在权威准入内重新核对配置 revision、应用与项目；写入前的联网
核验不能代替此最终裁决。初始绑定的 revision 切换与创建操作记录必须原子生效，不能
留下无法识别所属操作的创建中占位。已持久受理的同一操作按原身份接续，不因名称、
授权或启停等非身份配置变化重复创建；接续仍须核实当前应用、项目及操作与绑定的归属。
已有部分记录仅在创建身份、项目与恰好下一绑定 revision 均能证明属于本次请求时补齐，
不重复切换绑定。无法证明归属时保留记录，明确报告需本机恢复，不覆盖其他创建，也不
把无可接续证明的记录永久报告为正常进行中。关键身份与水位解码失败不得默认化或回退。
该约束覆盖绑定认领、绑定投影、操作回读及重复/到期入站工作恢复，不能用当前请求或
当前配置替换无法解码的已存身份；读取所得键须与查询身份一致。尚无记录、契约允许的
空值与已有行损坏分别处理，不因严格解码丢弃合法待定事实或重建空账本。
不可恢复的持久状态错误须在回复与工作收束边界保留不可重试语义，直接呈现需本机恢复；
不能因跨层错误转换将其改为暂时故障，再消耗自动重试预算后才要求人工处理。

接收文本、富文本正文、图片和文件；授权通过后通过消息资源接口下载图片与文件，复用会话
附件校验、可靠归档和用户输入链。未支持的媒体明确提示，不把占位文本当附件。平台内容
保持用户来源，不解释为系统指令、审批或子代理通知。

## 27.5 HTTP 与长连接

普通 API 区分 HTTP 失败与业务错误。错误保留安全类别、平台错误码、可重试性和关联身份；
不得透传含 secret、正文或票据 URL 的任意原始错误。工具不接受任意 API host。
普通成功须同时满足成功 HTTP 状态与该端点的业务成功条件；非成功状态不能因正文可解析
而成为成功。注册轮询按官方协议识别 HTTP 400 中的等待、降频和拒绝等状态，不把异常
状态中的凭据字段当作注册完成。JSON 类型或语法错误只公开安全类别与位置，不回显原值。
各端点按自身响应结构进行类型化适配，不能把普通 IM 的 `data` 包装强加给其他端点。
[`GET /open-apis/bot/v3/info`](https://open.feishu.cn/document/client-docs/bot-v3/obtain-bot-info)
使用顶层 `code`、`msg`、`bot`，当前机器人身份取 `bot.open_id`；缺失身份是协议错误，
不尝试其他字段或动态 JSON 兜底。此结构亦由官方
[CLI 固定快照](https://github.com/larksuite/cli/blob/017b19a793ad71794a02887ede04757f3d82e10d/shortcuts/common/runner.go)
核实；它仅是协议参考，不增加运行依赖。

长连接使用官方 `/callback/ws/endpoint` 发现地址，校验地址后握手；只有实际握手完成才发布
`connected`。每机器人单一连接 owner 持有 socket、心跳、重连、分包缓存和取消信号。
同一连接 owner 的启动、替换、停止与关闭必须有序裁决，任务句柄从创建到 join 始终有唯一
所有者；并发重试不能覆盖尚未回收的句柄，关闭开始后不能借在途启动再次创建任务。
发现响应的 WebSocket URL 可携带官方连接所需的 query，包括服务身份和短期票据；校验
安全来源后保留这些连接参数，并按官方类型读取所需身份，不能因为 HTTP 基址禁止 query
而拒绝合法的发现结果，也不能将含票据的完整 URL 写入诊断。

此处握手指 WebSocket HTTP upgrade 成功，并已检查该响应携带的协议拒绝信息，不要求先
收到业务消息才算连接。后续明确的认证/协议拒绝须立即更新为失败并关闭，不把 socket
可达等同于消息权限、发布或应用可用范围已经满足。
握手、重连与失败等异步状态变化须主动进入同一 canonical 机器人 topic，不能只改变
连接内部状态，再由 GUI 轮询或一次无关管理动作偶然触发发布。状态传播同样受连接代次
和 runtime 生命周期约束，不能占用平台接收与 ACK 路径等待全局快照或其他机器人工作。
配对等入站状态可靠记录后，以有界、可合并的通知交由受控发布 owner 主动更新 topic；
该通知不等待全局快照收集，也不为每个事件创建未登记任务或无界待办队列。
控制帧、ping/pong、服务端动态参数、事件 ACK 与 Protobuf 字段参考固定的官方协议，不
手写通用二进制 codec。注册与连接都有代次，旧代次不得覆盖新状态。
发现与 pong 的 `PingInterval`、`ReconnectInterval`、`ReconnectNonce` 线值单位为秒，
`ReconnectCount` 是次数；官方参考快照的 `ws-client/index.ts` 在应用这些值时转换为
JavaScript 定时器毫秒，Rust 不得把线值再误当毫秒。

事件分包按消息身份校验数量、顺序和一致性，缓存必须有字节、分包数、数量及期限上限；
非法或超限帧产生可观察错误，不无界分配。受理与执行分离：平台应答期限内只做有界校验、
准入和可靠记录，随后 ACK；模型及工具执行不占用 ACK 等待。可靠记录失败不能返回成功
受理；重复消息的 ACK 与首次受理引用同一持久身份。
应答预算覆盖 upgrade 后平台即可推送事件的整个窗口；不能在握手成功后、启动接收之前
同步等待 token 或机器人身份 HTTP 请求，再宣称接收循环没有联网。准入所需身份应已准备
好，或由独立受控初始化与立即运行的接收路径协调；身份未就绪不能冒充成功受理或丢弃事件。

临时网络问题遵循有界等待与退避，消费服务端有效重连参数；凭据、协议或配置的不可恢复
错误停止自动重试并提供修复入口。断开/停用/退出封闭新准入，取消注册、HTTP、心跳和
重连，等待任务与 socket 真实终态；关闭失败保留 owner 和诊断，不以丢弃 handle 代替 join。

## 27.6 会话查询与统一发送

`GET /open-apis/im/v1/chats` 仅列机器人所在的群。产品会话列表由这份平台可见群目录与已
收到事件的本地单聊目录组成，标注来源；分页 cursor 区分两种来源并绑定机器人/查询身份。
不承诺全平台最近消息排序，也不宣称能枚举全部私聊。历史使用官方 IM 接口按会话、时间
范围和游标查询，机器人不在会话或缺权限时显式失败，不切换为用户凭据。
历史接口的 `start_time` / `end_time` 线值本身为 Unix 秒，直接映射产品的时间范围，不乘
1000；返回消息的 `create_time` 则为毫秒，转换为产品 Unix 秒。这两类字段分别遵循
[获取会话历史消息](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message/list)
的字段契约，不能假定请求与响应单位相同。

GUI、自动正式回复和模型工具使用同一机器人发送边界与授权规则。普通发送在首次 await 前固定 bot、chat、正文和
operation ID，发送前按来源验证项目工具权限或本地/入站授权，并验证目标访问范围。
按平台大小限制验证或分段，逐段使用稳定
身份，分别记录已发消息、失败与未知结果；只有全部成功才表示完整送达。

普通发送的公开 `text` 字段承载 Markdown，使用官方 `post` 消息中的 `md` 节点；纯文本
同样作为 Markdown 正文发送，接口形状不变。内容结构遵循
[发送消息内容结构](https://open.feishu.cn/document/server-docs/im-v1/message-content-description/create_json)，
CommonMark/GFM 的解释由飞书负责。按真实序列化请求的 UTF-8 大小计量，包含 JSON 转义
开销；分段优先自然段或行边界且拼接原文无损，不截断字符。超过既有总发送预算明确拒绝。
消息发送遵守[发送消息](https://open.feishu.cn/document/server-docs/im-v1/message/create)的
30 KB 限制与同一目标 5 QPS 限制；不能把原文字符数当成实际请求大小。

官方发送 UUID 的去重窗口为一小时，不代表永久 exactly-once。超时、网络断开、取消等待或
重启时遗留的在途发送都可能已发生：保存为 `unknown`，不自动重放；明确拒绝与已成功结果
分别保留。操作身份相同但正文不同必须拒绝。只读请求可按其失败性质重试，不能把同一策略
套在非幂等发送上。
相同操作的原结果回读不是再次发送：先核对持久指纹与归属以及当前本机/项目来源权限，
再返回原回执，不以重新联网、刷新 token 或读取 keyring 作为旧结果存在的前提。撤销项目
工具权限后不得借结果重放继续访问机器人；原已受理入站回复仍保持其既有来源语义。
已持久受理的本地创建按同一原则先识别原操作再接续本地义务；新意图仍执行实时目标
可见性核验，不能把旧操作记录借给新的请求或不同正文。

自动回复以单张 JSON 2.0 卡片展示原 Thread 目标 Turn 的用户可见 Final 内容；生成中的正文
只是预览，不能作为完整送达事实。隐藏推理、commentary、工具原始结果和 secret 不出站。
需要本地确认的 Interaction 保持等待并提示用户处理；宿主不通过聊天文本自动批准。
可信入站用户在聊天中显式指示时，由机器人会话模型经 27.7 的交互决议工具执行决议，
等价于该用户在桌面的决议操作。
目标 Turn 的完整性必须从统一内容源证明，有界尾部基线不能当作该 Turn 的全量正文。
尾部重同步或重新打开观察后，正式发送前重新补齐并核对目标 Turn 的覆盖范围；不能证明
完整时保留需处理状态与诊断，不发送残文或标记完成。单次正文恢复最多检查 16,384 条内容
条目，累计正文最多 800,000 UTF-8 字节；超过资源边界时明确报告，不能静默截断。

本地解决交互后，回复关联沿原交互的 canonical continuation input 延续，而不是只匹配
最初的 bot input，也不能转发该 Thread 中任意后来的本地用户输入。通用问答与 Plan 的
continuation 身份由现有 Studio 交互提交边界提供，机器人只观察并记录原消息到该身份的
关联；问答或 Plan 取消、或终态决定没有 continuation 时结束该续接等待。工具权限决定
若在原 Turn 内恢复执行，仍只观察原 Turn，不把它当成新的用户输入。
不能因为同 Turn 保留了已决议的权限记录而结束后续问答或 Plan 的续接等待；边界交互的
终局只由对应的用户输入类交互决定，已决议权限不是该边界的终局。
提示与后续正式回复使用各自稳定操作身份；提示按交互身份分别去重，既不能占用正式回复的去重键，也不能由
一次提示抑制同一入站消息后续的新交互提示。窗口缺帧、正文补齐失败或超限须保留可恢复记录与
诊断，不能永久等一个不再到来的帧、发送残缺正文或静默丢弃已受理消息。

状态流负责唤醒观察，不单独证明目标输入或 Turn 的结局。缺帧、观察重开及进程重启后，
须从统一的驻留与持久输入身份、Turn 和交互事实恢复原关联；当前没有 active Turn 不等于
原输入未执行，也不等于可以重复执行。续接关联只记录可核实的 canonical 身份，不复制
另一份历史正文；尚未可读或尚未持久的事实保持待定，不能解释成取消或无 continuation。
恢复先核对原输入的持久路由与消费身份，再读取该目标 Turn 的 typed 状态；不得用最新
终态 Turn 代替目标，也不得为定位状态无界加载整段正文。交互身份与结局复用统一内容源
及其持久回执；权限决定、明确无续接的终态决定、取消与事实未就绪分别表达。旧的仅驻留
读取路径由这一恢复边界替代，不并存另一套结局判断。交互与权限回执可以合法记录待定
状态，不是只含终局的账本；合法待定保持等待，不视为读取故障或消耗故障重试预算。
驻留已见终局而持久终局尚未可读时仍属事实未就绪，不能把旧的待定回执解释成无续接；
真实读取、IO 与解码错误仍须传播。canonical 持久屏障及后续补齐等待
同时响应 runtime 停止观察，不能因等待存储而阻塞任务回收。

已受理工作的执行认领有明确持有者，活跃期间续约；续约和状态收束核对同一持有者，失去
认领的旧任务不能再发布终态或发起新副作用。恢复按失败性质受控退避，预算耗尽或不可恢复
失败保留需处理记录与诊断，不固定频率无限重试。平台发送的未知与部分结果仍遵循原操作
事实，不能借恢复再次发送。本地明确结束交互与 runtime 停止观察分别表达，后者保留未解决
义务，前者不能被恢复循环当成重新执行原输入的理由。
活跃续约覆盖存储屏障、历史补齐、输入受理及发送等全部在途等待，不只覆盖空闲观察。
续约、进度与终态写入同时核对认领仍在有效期内；已过期的旧持有者不得只凭原身份续权，
必须由新的认领身份经过到期竞争重新取得义务。
认领与退避状态属于现有入站工作账本并按版本迁移；故障或接管不重建空账本。认领失效后
不再受理该旧持有者的新动作；已经按稳定身份受理的动作仍按原操作核实，不因接管重放。

### 27.6.1 流式卡片协议与可靠收束

自动回复采用官方[流式更新卡片](https://open.feishu.cn/document/cardkit-v1/streaming-updates-openapi-overview)
流程，而非反复创建消息。仅在有非空、可验证的 Final 正文时开始卡片；空 Final 不产生空卡片。
若已展示过非空预览，随后正常 Turn 的 canonical Final 为空或仅空白，关闭已知卡片并明确
标记“未生成最终答复，所示内容仅为未完成预览”，保留需处理结局，不冒充交互结束或完整
送达。该状态与从未创建卡片的空答复分别表达，不能给最后预览补造最终正文。
卡片正文采用 [JSON 2.0](https://open.feishu.cn/document/feishu-cards/card-json-v2-structure)
的 [Markdown 组件](https://open.feishu.cn/document/feishu-cards/card-json-v2-components/content-components/rich-text)，
声明 `streaming_mode=true`、`update_multi=true` 与稳定且唯一的 `element_id`。

| 操作 | 官方边界 |
| --- | --- |
| [创建实体](https://open.feishu.cn/document/cardkit-v1/card/create) | `POST /open-apis/cardkit/v1/cards`，`type=card_json`，`data` 为序列化卡片 JSON，返回 `card_id` |
| 发送实体 | 普通 IM 发送接口，`msg_type=interactive`，`content` 为包含 `type=card` 和 `data.card_id` 的 JSON 字符串 |
| [更新正文](https://open.feishu.cn/document/cardkit-v1/card-element/content) | `PUT /open-apis/cardkit/v1/cards/{card_id}/elements/{element_id}/content`，提交累计完整 `content`、`sequence` 和稳定 `uuid` |
| [更新配置](https://open.feishu.cn/document/cardkit-v1/card/settings) | `PATCH /open-apis/cardkit/v1/cards/{card_id}/settings`，`settings` 为序列化配置，同时携带 `sequence`、`uuid` |

创建、发送和更新使用同一应用身份。每实体只发送一次；实体可操作期为 14 天，过期不自动
创建替代卡片。`sequence` 是同一卡片所有更新与配置操作共用的严格递增正 int32；
UUID 按原操作稳定绑定，不把它解释成永久 exactly-once。完整文本的前缀扩展才对应平台
打字效果，替换不是增量追加。最终完整正文确认后，再将 `streaming_mode` 设为 `false`；
最终确认操作可以在更高序号提交与最后预览相同的完整正文；预览合并不意味着省略正式
收束义务。序号严格递增，不要求每次提交的正文长度严格增长，也不允许无界重复提交。
完成、等待本地交互、中断和失败的 `summary.content` 是产品显式文案，不依赖平台自动猜测。

单卡最多每 200 ms 提交一次正文更新，未发送变化合并为最新可验证版本；同一卡片只允许
一个受管发送 owner 串行推进。末次正文与关闭也经过同一有界速率和顺序边界，不用并发
请求追赶内容。CardKit 的设置和内容操作共享序号；平台所述流式限频豁免不取消产品背压。
卡片实际序列化后不得超过 30 KB；内容接口的 100,000 字符字段上限不扩大整卡限制。
正文超限保留本地完整历史并发布需处理诊断；已展示预览不得被标记为成功全文，不能静默
截断，也不无限追加卡片规避上限。平台 HTML/表格展示限制不由产品自行渲染或重写。

预览只取 canonical 目标 Turn 的 Final 文本，尾部连续性、条目身份和 revision 必须一致；
断链、重同步或详情版本变化后重新读取，不把截断预览或跨版本片段拼成正文。预览不推进
正式送达状态；只有完整 Final 校验、最终更新与关闭均确认后才成功。交互续接仍由原输入的
canonical continuation 决定，卡片归属不变，不能借同一 Thread 的其他 Turn 推进卡片。
续接输入被消费后，卡片的目标 Turn 与 watch input 必须同步对应该 canonical 消费身份；
新 Turn 在首段正文前立即失败、取消或耗尽预算也不能沿用上一 Turn 身份。未消费输入的
结束与已消费 Turn 的终态分开表达，不从旧卡片状态猜测新输入的目标。

可靠卡片进度属于现有机器人状态库与原入站工作的回复 owner，不建立第二套执行队列。
记录原 bot/chat/message、Thread 与输入关联、卡片和平台消息身份、已确认及待确认操作的
序号/内容身份，以及创建、发送、更新、关闭和最终结局。副作用前先持久认领其阶段，
结果保存核对认领仍有效及同一操作版本；失租 owner 不发起新操作或覆盖后继结果。
迁移保留旧入站、绑定与发送事实，不清空用户数据，也不把旧普通文本发送误识别为可重发卡片。

未知创建、未知消息发送、未知更新或未知关闭均保留原操作事实并明确需核实，不自动重试、
换 UUID、提升序号或新建卡片掩盖不确定性。只有已知实体且无未知在途操作的进度可从同一
入站 owner 安全续接；恢复不能重复模型输入、卡片发送或已经确认的终态。模式关闭/超时的
明确拒绝可通过官方配置接口有界重新开启，过期、无权限、序号冲突或超限不作为网络重试。
本地明确取消或模型失败收束已知卡片并保留真实结局；运行时停止只结束当前观察并保留
可恢复义务，不伪造任务完成。已经在途的操作按真实结果或未知事实落账，资源随原 owner
取消和 join，不派生无人负责的网络任务。无法安全关闭时保留诊断，不以界面不再等待代替成功。
canonical Turn 的 `Interrupted` 取消原因表示定向中断或新输入打断，不是机器人观察者
停止的证据。已消费输入的该终态按取消收束，不能反复释放回待处理或在重启后重新执行；
观察者停止则由其自身生命周期信号判定，恢复时仍核对原输入与目标 Turn 的实际结局。

## 27.7 产品 API、topic 与工具

公共 DTO 使用 camelCase 字段、String ID 与 Unix 秒时间戳。机器人独立 `Bots` 产品 topic
发布 `BotsStateChanged`，snapshot 至少包含领域 revision、机器人配置/连接/凭据可用状态、
当前注册和有界配对诊断；不把正文历史装进状态快照。配置 CAS 使用各机器人独立
`configRevision`，不是 topic revision。
每个 topic 水位标识一份不可变的已发布快照，包含固定的更新时间；读取、命令回执与
订阅基线消费同一已发布事实，不能在异步收集后借用另一次发布的最新水位。并发发布须
保持水位与内容身份一致且发射顺序单调，不能用一次原子递增代替完整发布裁决；快照
收集和发布协调不得把全局 registry 或消息准入边界持到 I/O，也不得阻塞平台 ACK。
camelCase 约定同样覆盖 tagged enum 的变体内字段，HTTP/OpenAPI 与后续 typed 适配不能
各自采用不同字段名。携带 Secret 的保存请求仅作为命令输入消费，不进入状态、回执或
诊断；该请求及其嵌套类型的调试表示也须脱敏，不能由自动派生的输出暴露输入材料。

产品命令覆盖保存、注册开始/取消、启停/重试、联系人/群授权、按需会话/消息获取和发送。
另提供本地 `createBotConversationThread`，HTTP 适配为
`POST /api/v1/bots/conversations/thread`。请求包含 `operationId`、`botId`、`chatId`、
`expectedConfigRevision` 与独立的 `expectedBindingRevision`；响应为 typed 绑定与命令回执。
绑定投影包含机器人/平台会话/项目/Thread 身份、独立 revision 与创建中、已绑定或需处理
状态；尚无绑定使用初始 revision。会话查询附带该绑定投影，Client 按绑定资源水位与请求
身份归并，不用 topic revision 或配置 revision 冒充绑定水位。此管理动作不开放给模型工具。
命令携带 operation ID，配置 mutation 另携带 expected config revision；响应携带权威
snapshot 或 typed 查询/发送结果，不要求成功后聚合回读。注册状态、连接状态和查询状态
分别表达。普通 `read` 与订阅基线不联网、不激活模型，也不自动注册或重连。

工具使用与 GUI 相同的宿主端口，只有项目已授权的机器人可见：

| 工具 | 输入与输出边界 |
| --- | --- |
| `list_bots` | 返回当前项目授权机器人的 ID、名称、连接状态及能力，不含凭据 |
| `list_bot_conversations` | `botId`、分页/种类；返回群与已知单聊、来源及 next cursor |
| `read_bot_messages` | `botId`、`chatId`、时间范围及 cursor/limit；返回 typed 消息页 |
| `send_bot_message` | `botId`、`chatId`、Markdown 文本；返回 operation ID、发送状态和已知消息身份 |

工具不提供注册、凭据修改或远程授权管理，不借协作消息接口发送；发送是外部写操作，不
取得只读 programmatic 资格。每 Thread 独占工具实例，物理机器人服务通过宿主能力共享。
上述四项对外机器人工具仅在关联项目的根 Thread 安装，子代理不自动继承该工具目录；这只是工具
能力的装配边界，不是 full-access 执行环境中的 OS 或网络沙箱。

机器人聊天的根 Thread 另外安装十项 Studio 会话工具：目录分页、状态读取、正文搜索、
历史分页与消息提交，以及交互读取与决议——读单个待决交互全文、批准计划、要求计划修订、
回答提问与决定工具审批。它们覆盖所有项目，归 Studio 产品层；不会创建、停止、归档会话。
单次列表或历史页最多 100 项；正文搜索每次最多扫描 32 个内容页或分块，
返回最多 10 个命中，长正文按 32 KiB 分块读取。搜索游标绑定查询条件并保留跨块匹配尾部；
`complete=false` 必须继续查询，不能报告为完整无结果。发送输入身份取自调用 Thread、
Turn、工具调用与目标，受理后重试返回原结果。附件参数只接受来源 Thread 的可靠附件 ID。

交互决议工具只对其他会话仍处于待决状态的 Interaction 产生新决议，并与桌面共用同一
`resolve_interaction` 提交边界：答案解释、continuation 与幂等回执由该边界唯一持有，
工具不另立第二套语义或账本。计划决议按 Plan 确认问题构造 `Approve` 或 `Revise` 加反馈
的答案，反馈为必填且沿用 Plan 状态机的长度上限；普通提问把答案按问题 ID 映射到所选
选项 label 与/或自由文本（自定义回复），问题与选项全文先经交互读取工具获得；工具审批
决议携带批准或拒绝及拒绝理由。`get_session` 的待决列表提供交互种类、用途、问题概要与
选项摘要，完整正文只经 `read_session_interaction` 按身份读取，不进入会话快照。工具校验
目标会话非来源会话自身、非归档、交互归属与待决状态；决议操作身份取自调用 Thread、
Turn、工具调用与交互身份，重复决议沿用统一边界的幂等回执。已决议交互退出待决快照后，
仍可依据统一交互事实核对归属、种类与原决定；相同决定返回原终态，不重复续接或授予权限，
不同决定明确冲突，不因待决列表缺失而阻断终态回执。全文读取仍仅返回待决交互。
决议仅在可信入站用户显式
指示时执行，等价于该用户在桌面的决议操作；宿主自动回复路径仍不自动批准任何交互。

## 27.8 GUI 与 Client

机器人设置采用“总览 → 详情 → 聊天”的独立页面。进入详情后隐藏总览和设置切换列表，
聊天复用现有会话时间线与附件；返回保留上一页的滚动和筛选。总览展示名称、平台、
连接与最近活动；详情优先展示连接、打开聊天、模型和最近聊天。联系人与群授权、凭据、
工作目录及排障位于次级设置；平台消息查询和人工测试发送是单独页面，不显示 Unix 输入。
流程为名称及风险说明 → 扫码或已有应用 → 注册/连接真实状态 → 首用户
授权/首条消息 → 会话查询与发送。失败留在当前步骤，保留非敏感草稿和明确重试入口；
Secret 不回显。窄窗口、长名称、分页和错误不得隐藏关键操作。
历史权限提示同时提供飞书中国版[开发者后台](https://open.feishu.cn/app)的可操作入口，
明确由用户选择当前 App ID 对应的应用并进入权限管理。入口仅打开固定官方 HTTPS 页面，
复用既有外链能力；不携带凭据或授权票据，不预选权限、不自动申请，也不切换用户身份。
打开失败须给出可重试的安全提示，不能仅显示不可操作的申请说明。
机器人入口追加到现有设置导航末尾，不重排既有入口；窄窗口分组保持同一完整入口集合。
沿用 Studio 的主题、文字层级与组件，分别呈现本地配置、真实连接和入站授权事实，不能
把它们合并成一个“已就绪”提示。首配展示默认申请的权限及 full-access 风险，未完成的
本地保存义务单独提供核实入口，不以重新扫码创建应用代替原操作恢复。
验证链接与二维码数据属于在途授权材料；二维码编码失败只呈现安全的通用提示，保留当前
可信验证链接的本地操作，不把原始数据、底层异常或组件默认错误详情送入日志、Driver
投影和验收证据。编码容量不足不是重新创建应用的理由，不自动开始新的注册尝试。
已有业务身份的应用/项目字段只读并说明原因；需要恢复本地上下文时使用会话上的显式
新建操作，确认旧历史保留且旧输入不会移入新上下文，不把它混入连接重试或普通发送。
字段可变性来自真实持久占用；可靠受理入站或建立会话绑定改变占用后，由领域 owner
通过既有受管发布生命周期主动更新 canonical snapshot/topic，不等待其他管理动作偶然
刷新，也不由 GUI 轮询或本地猜测补齐。此类能力变化不冒充配置 revision 变化，聚合发布
不得阻塞平台 ACK 的有界受理路径。
占用写入及其后续本地绑定接续由有界受管任务持有至真实终态；调用方取消仅放弃等待，
不丢弃已受理的事务。事务确认与后继保存失败都按真实持久占用重建发布，不能只覆盖正常
返回，也不能在数据库提交尚未结束时以调用方析构通知冒充收尾。写入前的联网权限核验
与占用事务分开；关闭封闭新准入，先等待在途占用任务并完成发布，再关闭发布器和存储。
这里的占用任务承接首次配对、首次入站受理、本地显式创建及首次发送认领的必要持久接续，不是另一套
回复执行队列。已持久入站工作的回复、绑定恢复与中断处理继续归原回复 owner；其占用
不会因后继状态变更消失。保守占用派生也包含入站工作记录，不能因异常缺少身份或绑定行
而误允许跨项目迁移。
发送认领写入应用占用后同样主动发布；后续网络发送与逐段结果继续由统一发送服务负责，
不能为能力刷新把整段网络发送搬入本地占用排空队列，也不自动重放未知或部分发送。
占用任务预算同时覆盖等待登记与执行中的任务：至多 32 项，额外冻结文本总量至多
64 MiB。只持有所需身份、标题与事件字段，不捕获整份配置及无关可信集合；任务内必要
配置标量和派生身份跨等待保留时同样纳入预算，不能仅计量任务入口结构，或在任务内部
重新克隆整份配置绕过限制。持久化边界由项目显式构造并跨等待持有的文本输入副本也在
此范围内，不能以数据库驱动内部瞬时分配为由排除；必要接续的可知副本在首次新写前
一并预留。不把此冻结预算冒充进程总内存上限。此预算独立于传输大小与入站正文
账本，不截断输入，也不增加字段语法限制；暂时无容量明确返回可重试背压，单项无法放入
总预算则在首次持久写前返回不可重试的资源错误，提示本机调整材料后重试。
关闭中已观察到的任务异常须由 owner 保留，直到排空并完成真实状态发布后再上报和消费；
中途取消或后继等待不能抹掉该事实。任务终态句柄只回收一次，安全诊断不包含原 panic
载荷；已观察到取消类 join 终态与尚未完成资源回收须明确区分。
其他关闭任务在观察异常后仍需跨等待继续收束时也保留异常事实；若已无额外等待而直接
将该错误返回调用方，即算完成一次上报，不要求下一次关闭重复上报同一异常。
单机器人配对列表读取失败必须显式诊断不可用，保留已有已发布列表而不是把失败发布为
正常空列表；没有历史列表时明确不可读取。该故障不重置配置，也不影响其他机器人。
详情同时呈现已发布的机器人安全诊断与连接状态，不让独立清理义务被连接错误覆盖或只
存在于不可见字段中。配对请求提供保持当前信任值的明确清理动作，与批准信任区分；
清理携带同一 canonical 快照的当前信任值及配置 revision，旧快照冲突时不改变授权。
批准后的清理失败不能要求用户先撤销信任；原配对行保留到明确清理成功，重启后仍可操作。

连接失败必须呈现平台错误码，保留原有安全消息；不得回显可能含凭据的原始响应。
消息和机器人 OpenAPI 的非成功 HTTP 响应同样解析其业务错误码；无结构化业务码时才使用
HTTP 分类。权限拒绝不得一概改写为缺少群历史 scope：机器人不在群、用户不可见、未开启
机器人能力和应用权限不足各自保留原因。消息/群组继续使用官方当前的 `im/v1`，机器人
身份使用 `bot/v3/info`；路径中的版本号并不表示这些接口已经过时。
飞书访问控制拒绝 `21001` 按不可自动重试的权限错误处理，与临时服务不可用区分，
对照[官方 CLI 错误分类](https://github.com/larksuite/cli/blob/main/internal/errclass/codemeta.go)。
界面明确提示联系组织管理员检查应用访问策略，并提供开发者后台入口；注册成功、凭据
已保存与平台允许 API 访问仍是独立事实。协议升级按官方当前契约整体迁移，不以错误触发
端点回退、伪装请求身份或忽略 token 错误绕过访问控制；策略获准后可由用户显式重试。

每 AppGraph 的 Client 持有机器人 topic/read model、请求及草稿，canonical reducer 是唯一
writer。Riverpod 仅适配观察，Widget 只呈现与提交意图；设置往返不关闭机器人或当前聊天
Session。查询冻结 bot/chat/参数与尝试身份，迟到结果不覆盖新选择；发送未知结果不得因
Widget 重建自动重试。状态由 topic/回执推进，无 GUI 接口轮询。
会话、时间范围、游标和页大小共同构成查询身份；响应的机器人与会话归属须与请求一致。
选择失效只结束旧的展示等待，不能丢弃真实在途请求的所有权；Client 关闭仍等待它们的
实际终态，资源预算也到实际终态才释放。分页、授权和显式新建本地上下文均由用户操作触发，
新建前明确确认旧历史及在途工作仍保留，绑定结果按独立水位归并到当前查询投影。
发送草稿按机器人与会话隔离，由 Client 持有并受既有草稿预算限制；界面最近发送结果为
有界镜像，权威操作账本仍由 Rust 持久化。淘汰显示镜像不触发重发，也不删除操作记录。

## 27.9 验收边界

使用本地隔离平台 fixture/人工观察验证原生 HTTP、WS、ACK、幂等、取消、授权、查询与
发送路径，遵守 [24](./24-testing.md) 的测试布局，不为测试公开生产私有接口。原生 GUI 用
真实 bridge 与 Driver 核对截图、快照、错误和退出回收。平台模拟与 demo 不等同于真实
飞书授权或兼容；真实账号验收需单独手机授权/测试应用，证据不得包含可用二维码、凭据、
真实联系人或私聊正文。

Markdown 与流式观察必须保留独立平台收到的 post/卡片 schema、同一实体的递增操作与

授权、Agent 装配、正文筛选、认领或恢复判断。Linux 隔离 GUI 截图只证明本地原生界面的

### 隔离平台与宿主边界

人工验收平台属于 `pl-provider-fixture`，只提供所需飞书 HTTP/WS 环境与独立请求校验，不
链接机器人生产私有模块，也不代替产品执行授权、幂等、会话映射或发送结果判定。
注册环境可控制返回链接、等待间隔、过期时长及租户品牌，以观察产品的来源拒绝、时间
边界和中国版限制；这些是合成响应材料，peer 不访问或跟随所配置的链接。
平台独立校验注册权限模板与事件，使用所需的细粒度发送、接收、目录和历史只读能力，
不要求产品额外申请通用读写或全部群消息权限才能通过模拟。权限样本不导入生产常量，
既不能把能力缺失误报为通过，也不能用过宽授权掩盖模板偏离。
挂起与释放控制按代次保存真实条件；释放时没有在途请求也不能丢失已释放事实，使后续
请求误等旧代次。切换响应脚本不代替显式释放已经挂起的请求。
平台环境可对会话目录请求作有界挂起与显式释放，使已完成令牌准备的只读请求跨越公开
配置提交；此能力只控制合成 peer 的响应时机，不绕过生产令牌代次校验，也不为验收修改
生产凭据生命周期。挂起登记、释放、取消与 peer 关闭共享现有代次和资源回收边界。
非 GUI 观察从现有 Studio 产品 API 进入；GUI 观察使用同一 runtime 和真实 bridge。
非 GUI 入口由 `pl-studio-acceptance` 的显式 Rust example
`bots_protocol_observe` 拥有，通过真实 `pl-studio-server` 的公开 HTTP 接口驱动，不调用
私有机器人协议或替换业务宿主。该 example 不改变既有 `manual-gui` 命令与模型场景，
也不进入常规自动化测试门禁。模型环境复用现有脚本化模型 fixture，飞书环境使用独立
平台 peer；两者只提供环境，不替产品判定授权、幂等和送达结果。
该私有凭据观察环境仅在 Linux 启用；平台专属模块须在编译边界隔离，非 Linux 保留可编译、
明确拒绝运行的入口，不使工作区 Windows 的 all-targets 检查因 Unix 专属接口失败。
topic 观测从真实产品 SSE 订阅接收 typed 基线与事件，复用工作区已有的
`eventsource-stream` 解码组件，不在验收入口自建通用 SSE parser，也不以状态轮询冒充
订阅传播。观察流有独立的时间、事件及接收字节预算，结束或失败时显式关闭接收资源；
证据仅保留所需的安全状态与水位，不记录 raw 帧、授权链接或设备材料。
显式本地创建的独立观察从无入站、无绑定的隔离状态开始，核对首次占用主动发布且配置
revision 不变；并通过平台请求的受控挂起，验证联网准备期间配置先提交时，陈旧创建在
首次写入前拒绝。该观察只经公开命令产生业务事实，以只读账本核对，不改写绑定或增加
生产故障 hook，也不把已有占用上的重复创建当作首次占用传播证明。
首次占用发布证据使用不自动回读的严格订阅路径：动作后遇到 stale/缺帧就保留失败，
不能由状态 GET 重同步补成主动发布通过。独立本地创建场景无需启动 WS 连接，避免连接
状态发布混入该观察；项目切换与改名均核对公开回执中的真实身份及配置 revision。
注册观察的独立成功路径使用各自隔离运行，不依赖前一场景留下的应用、授权或机器人；
仅支持独立选择的注册场景在组合选择时明确拒绝，不静默忽略选择或放宽应用唯一性。
回复恢复观察通过公开 Thread 状态订阅取得原交互身份，由本地 owner 通过公开决议接口
续接；同一隔离数据根重启 Studio 时，平台与模型环境保留，不能重建环境或改写账本来
模拟恢复成功。未知与部分发送结果从授权入站和正式回复链触发，核对重启后的原操作事实，
不以单独的管理端发送幂等代替自动回复恢复。独立重启场景不进入默认批次，明确选择与预算，
并分别记录模型执行、提示、正式回复及所属资源的真实终态。
覆盖缺口按实际选择与场景结论表达；失败或未到达的后继仍保留缺口，不能以已实现的观察
入口代替行为通过，也不把已成功验证的范围继续标为本次未覆盖。
观察运行持有隔离数据与全部进程/任务，错误和取消同样收束；只有真实回收后才输出最终
资源结论。场景失败必须传到最外层非零退出；可以保留尚未修复生产缺陷的失败证据，
不能把“验收入口已就绪”写成“生产行为已通过”。
该观察入口可显式使用 `--server-binary` 指定已保全的本地 Studio server 构建产物，以比较
修复前后同一公开操作；未指定时仍构建当前 server。观察记录实际可执行文件身份及产物
来源，不仅凭当前工作区 HEAD 为旧产物声称源码归属。固定旧产物的失败属于被观察版本，
不得通过放宽判定把它改写为验收成功，也不向生产配置增加此覆盖入口。

正式运行仅使用官方 HTTP/注册端点；发现的 socket 地址仍须按正式环境校验，不能以
“来自发现响应”代替地址验证。只有启用 debug assertions 的显式人工验收运行可读取
`ANYWORK_BOTS_FIXTURE_MANIFEST` 指向的临时、版本化描述。该描述必须属于本次隔离
Studio home，并把 HTTP、注册与 socket 限定在同一个 `http://127.0.0.1:<动态端口>` /
`ws://127.0.0.1:<同端口>` 来源。不得接受任意 host、重定向到其他来源、用户提供的工具
URL，或在 fixture 出错时回落到真实平台。描述无效、与 home 不符，以及非 debug 运行
收到此显式设置时，均拒绝启动该验收路径；不静默忽略。普通配置与公共产品 DTO 不开放
此传输设置，不因此新增生产协议的测试专用公共接口。
描述中的 `baseUrl` 表示来源，不是完整 socket 地址；发现结果可带该 peer 的路由 path 和
连接 query，但 scheme、host、port 必须符合上述来源约束。禁止 query 和非根 path 的规则
只用于描述中的 HTTP 基址，不能据此剥掉连接参数或拒绝合法的 WS 路由。

Linux 验收复用私有 D-Bus/Secret Service 与隔离 HOME/XDG 目录，或既有的真实进程 secret
lease，不能读写操作者的凭据服务与文件。平台只接受合成应用/联系人数据；secret lease
仍如实呈现 `sessionOnly`。debug 原生验收的通过不外推为 release/profile 构建或真实
飞书兼容，截图与报告明确标注本地模拟范围。

原生首配验收使用显式 opt-in 的 `cargo xtask manual-gui --scenario gui --bots-fixture`，
默认不启用，不改变既有模型场景与场景目录。验收宿主持有平台 peer，在本次 home 内准备
描述并在真实 GUI 启动前注入；模型环境继续复用现有 fixture。平台状态由合成脚本或明确的
本地环境动作推进，不能替代 GUI 操作、授权或产品结果判定，不增加公网控制入口。
配对与重发的原生验收使用固定合成联系人、不同平台消息身份及既有模型场景输入，由平台
事件进入真实连接；分页使用有界合成目录与历史样本。环境动作仅提供输入，不能直接改
信任、会话绑定、Thread 或发送账本，也不接受任意凭据、目标地址或业务正文。
固定合成单聊须同时是平台 peer 已声明可访问的单聊，不能混入群目录，也不能扩大为任意
聊天 ID 放行；未声明的目标仍明确拒绝，避免入站环境可达而回复目标被环境自身误拒绝。
目录外的已声明单聊在发送与历史查询中共享目标知识；没有历史样本时返回合法空页，
不伪造消息，也不把无数据误报为无效会话。未声明目标仍拒绝，群历史权限拒绝保持独立。
该凭据隔离路径使用 Linux 私有 D-Bus/Secret Service；未提供等价隔离的平台明确拒绝该
验收模式，不回落到操作者凭据。正常完成、失败、取消与部分初始化失败均回收 peer 和
所属服务/进程，保留主错误与清理错误；平台报告、GUI 快照、截图与真实退出共同构成证据。
初始人工结论仍为待评审，环境成功启动不等于首配、模型执行或发送已经通过。

该显式模拟模式提供固定的 stdin 环境动作：`bots-env registration pending`、
`slow-down`、`denied`、`expired`、`complete` 与 `complete-without-user`（后五项同样使用
`bots-env registration ` 前缀）。它们只通过现有平台 control 设置本次 peer 后续注册轮询
的合成回包；`complete` 携带合成首用户身份，`complete-without-user` 不构造用户身份。
动作不创建正式应用、不读取凭据、不调用产品保存或授权命令，也不把模拟过期当作 GUI
本地取消。未知环境动作安全拒绝且不改变平台脚本，原普通 GUI 动作仍只记录。
证据区分环境推进与产品操作，只记录固定安全动作码与执行结果，不回显任意原始输入。
