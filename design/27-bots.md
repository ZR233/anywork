# 27 - 外部机器人与飞书接入
本文规定外部机器人管理、飞书协议边界、首次配置、授权、会话工具与资源生命周期的权威契约。会话线程（Thread）、历史存储、权限模型、配置与前端所有权分别遵循 [14 - 运行时宿主与会话驱动](./14-runtime-host.md)、[15 - 会话存储与工作区状态](./15-session-storage.md)、[04 - 安全与权限策略](./04-security.md)、[20 - 配置与凭据管理](./20-config.md) 与 [25 - 前端状态与生命周期](./25-frontend-state.md)。本文描述目标架构契约，功能与平台兼容性以实际验收证据为准。
## 27.1 目的与组件边界

外部机器人负责将已授权的飞书用户消息送入现有 Studio `Thread`，并将正式回复发回原飞书会话。渠道接入不属于模型供应商（Provider）、可派发的子智能体配置档（Profile）、MCP 服务器或另一套独立会话引擎；飞书会话与普通桌面会话一样，由统一智能体定义装配根 `Thread`（详见 [12 - 多智能体协作与子线程委托](./12-collaboration.md)）。Studio 运行时是机器人配置、长连接、消息受理、会话映射与发送操作的唯一所有者（Owner），桌面界面（GUI）、HTTP 接口与模型工具共享同一套底层能力。

当前版本仅接入飞书中国版企业自建应用，采用原生 Rust HTTP / WebSocket 适配，无 Node.js / npm、OpenClaw 或第三方飞书 SDK 运行时依赖。HTTP、WebSocket 与 Protobuf 分别复用成熟组件，产品仅维护所需的飞书协议层。微信、Lark 国际版、公网 Webhook、用户身份 OAuth、富媒体出站发送、卡片交互审批及飞书文档／日历能力均不在本版本范围内。出站消息支持 Markdown 与 JSON 2.0 流式卡片，直接调用飞书官方消息与 CardKit HTTP 接口，不引入额外 SDK 运行时或自研 Markdown 渲染器。

协议实现以飞书开放平台官方文档为准；文档未展开的扫码注册与长连接细节参考官方 [Node SDK](https://github.com/larksuite/node-sdk) `1.76.0` 发布版（提交版本 `1889911f0841e669de0be5bd02c737a3f1fd20fa`），引用或改写其 MIT 许可内容须保留相应归属声明。团队已调研第三方 `openlark` 的发布能力，本实现不依赖该库，也不用未发布的高层封装替代已核实的协议契约。可访问的官方仓库参考快照固定为 [`b188be60134d409b61259546bcf69c731d2b0b7c`](https://github.com/larksuite/node-sdk/tree/b188be60134d409b61259546bcf69c731d2b0b7c)；引用协议事实时须注明具体来源，不混用仓库快照与 npm 发布包的提交标识。

## 27.2 管理、配置与凭据

### 存储布局与身份不可变性

机器人管理根目录为 `<StudioHome>/v2/bots/`，随 Studio 主目录参数及环境变量解析，纳入 [17 - Studio 存储、单实例与恢复](./17-studio-storage.md) 的 v2 备份边界，与业务项目的 `.anywork/worktrees/` 相互独立。每个机器人使用运行时生成并校验的稳定 ID，不将显示名称、`App ID`、会话 ID 或平台消息 ID 直接拼接为物理路径。单机器人目录保存版本化非敏感配置与可靠状态，具体磁盘布局归属 [17 - Studio 存储、单实例与恢复](./17-studio-storage.md)。

通用配置包含稳定身份、显示名称、关联存储项目、启停开关、模型路由及独立的 `configRevision`；平台专属配置通过枚举分支保存，当前飞书分支包含应用 ID（`appId`）、可信用户集合与已授权群组身份集合。旧版平铺平台字段（含凭据恢复记录中内嵌的旧配置）仅在版本迁移边界解码。`configRevision` 仅随期望配置（Desired Configuration）变更推进，不因心跳、重连或只读查询递增；保存、启停和授权变更均须携带预期 `configRevision`。由于飞书同一应用的多条长连接会分流事件，系统禁止使用重复 `App ID` 建立第二个活动机器人。

本版本不支持将已有业务会话原地迁移至其他应用或项目：

- 一旦产生 `Thread` 映射或已受理输入，关联项目即锁定，不可原地更换；
- 一旦产生平台会话、受理／发送记录或可信范围，应用的 `App ID` 即锁定，不可原地更换。

尚未投入使用的初始配置允许更正，更正成功后原项目的工具权限立即失效；资格校验与新消息准入互斥执行，防止在检查为空后被在途消息跨越。显示名称修改、凭据轮换、授权增删与启停切换不受此身份锁定限制。拒绝身份变更时完整保留原配置、关联与在线服务，既不删除旧数据，也不暗中搬移 `Thread` 工作区。管理快照直接提供应用与项目是否允许更正的权威布尔标记，客户端不从本地缓存或连接状态猜测。

### 凭据引用与事务恢复

`App Secret` 存储在独立的系统凭据账户 `bot:<bot-id>` 中，不写入普通配置文件、SQLite、日志或工具返回结果。该账户的受保护载荷按版本保存当前密钥材料与在途候选，非敏感配置文件仅保存所选版本的引用；配置中的版本引用是当前凭据关联的唯一事实源，系统凭据载荷内部不维护可独立切换的当前指针。版本引用由运行时生成并校验，严格绑定机器人与应用身份，不由外部产品请求或模型指定。正常运行仅解析当前载荷结构；旧版原始密钥仅在明确的配置／凭据迁移边界转换，且迁移中断后支持幂等恢复并保全原有关联。

版本引用严格区分持久化系统材料与仅限当前进程的内存租约（Secret Lease），二者在读取或重启恢复时不自动互换。迁移转换前先持久化不含密钥明文的迁移意图及目标版本身份；恢复流程通过核对该身份与实际配置文件／凭据材料来判定已完成步骤，既不在多版本载荷中猜测当前版本，也不因原值恰好可解析为结构化文本就将其当作已迁移材料。无法证明关联一致性时保留现场、封闭准入并提示本机恢复，不覆盖原值。

凭据变更遵循保留（`Preserve`）、替换（`Replace`）与清除（`Clear`）三种语义：

1. **替换（`Replace`）与两阶段提交**：先准备有界候选材料并确认其实际落盘持久性，再原子提交配置文件中的版本引用；提交确定前，原引用及其材料保持可用，不提前发布候选配置、撤销原授权或启动新连接。准备失败时不切换关联；若原子替换可能已发生但后续同步失败，则保留新旧两侧材料、封闭该机器人准入并明确报告“提交待确认（`commitUncertain`）”，由同一操作所有者核实与恢复，不伪报已回滚或盲目重做。恢复日志（Journal）须区分本次操作的原配置、目标配置与候选身份；准备中断、配置替换后尚未推进日志及清理中断均依据实际配置文件裁决，不单凭日志阶段断定未提交。确认采用原配置或目标配置后，仍须补齐对应的持久性确认；遇到未知、缺失证明或不匹配的现场时予以保全并维持待确认状态，同时提供可接续的核实路径。原配置不存在且裁决未提交时，当前引用保持为空，不将候选目标当作原配置来保护材料或发布机器人。
2. **保留（`Preserve`）与应用更正**：系统凭据与进程内租约均按精确版本号选择，缺失所选版本时不回退至其他旧值。在允许更正 `App ID` 的前置状态下，`Preserve` 保留当前所选密钥明文，但须为新应用关联生成新版本引用，不直接复用绑定旧应用的引用；原引用保留至提交确定。若当前无凭据引用，`Preserve` 维持空关联，不从系统遗留的未引用材料中恢复旧密钥。
3. **清除（`Clear`）与异步回收**：先确定提交空引用并使旧认证租约失效，再回收不再引用的系统凭据材料。清理未完成与配置已生效分开表达，保留可重试所有者与诊断信息，既不宣称物理删除已完成，也不恢复旧关联。候选、迁移与回收均设有资源上限，绝不删除仍被当前引用或未决提交依赖的版本。
4. **系统凭据降级与双源隔离**：系统凭据服务不可用时，仅可使用当前进程的内存密钥租约并显式标记 `sessionOnly`，不宣称已永久保存；进程重启丢失内存租约后，即使系统凭据库中仍残留旧版本，也不据此报告 `stored` 或启动连接。系统关联暂时不可读时，仅允许借用同版本、同机器人及同应用的现有进程租约并报告 `sessionOnly`；无可用进程租约时严格区分系统不可访问（`unavailable`）与材料确实缺失（`missing`）。仅绑定进程租约的配置始终只读取进程租约，不转读系统材料。凭据材料损坏或读取失败不改变已确定的配置提交结论，此时可用性保守表达为 `unavailable`，并附带安全诊断区分服务不可达与材料无效，不将无效材料自动降级为内存租约；后续显式 `Clear` 仍可撤销已确定的关联。系统凭据与进程租约两个来源独立维护，不通过“系统优先”的合并读取遮蔽所选进程版本；准备与回收同样按所选引用及未决操作分别保护各来源。准备新候选遇到系统凭据服务不可访问时，可在独立进程租约中追加该候选并如实选择进程引用，既不将不可访问的系统载荷当成空值覆盖，也不在写入失败降级时整包覆盖另一来源的租约。

### 操作所有者与生命周期串行化

启动时先由现有机器人操作、凭据与存储所有者完成持久状态准备，再启动连接、入站恢复和公开投递。持久准备复用原凭据日志裁决与正式 SQLite 迁移，不建立另一份机器人归属表；在准备完整前，查询不到运行态记录不构成“无机器人归属”的证明。无法核实的有效机器人目录或未确定的配置必须保留诊断，并阻止依赖该归属证明的历史身份迁移，不能先按普通根身份转换。会话新历史库导入在完整的持久归属准备之后、外部服务与执行准入开放之前完成；历史身份同时核对持久绑定和会话冻结 owner，二者冲突拒绝，正常显式恢复沿用同一证明。

准备阶段不启动外部连接、模型、工具或 SSH，也不启动入站与公开投递任务；内部状态投影及资源所有权可以建立，但不因此授予外写。准备、导入或服务启动失败仍由原启动所有者真实排空已取得资源，错误保留迁移分类和底层原因，不以备份重置或清空产品数据代替恢复。服务启动前重新核对当前配置与原操作归属，不用较早准备结果授权已失效的连接或投递。

凭据底层能力由现有配置基础设施持有，机器人模块仅获取窄作用域接口，不另建凭据服务。机器人事务与恢复归属各机器人自身的 `configRevision`、数据目录和生命周期，不复用主配置迁移的全局操作目录，也不改写模型账号或 SSH 凭据格式。阻塞式凭据访问由受控工作所有者隔离执行，取消或关闭后必须等待其到达真实终态，不遗弃迟到写入。

配置与凭据修改由每个机器人的操作所有者串行推进：

- **跨机器人应用唯一性认领**：采用短认领机制，冲突检查与保留认领在同一原子裁决中完成，避免先检查通过、释放锁边界后再登记候选；等待凭据访问、文件同步或网络回收期间不持有全局配置锁或注册表（Registry）锁。
- **准入复核与所有权交接**：最终提交阶段封闭该机器人的新消息准入，重新核对 `configRevision`、身份锁定约束与操作所有权；准备阶段不提前发布候选配置。身份复核针对完整的目标应用与项目，覆盖准备期间新增的 `Thread`、消息受理、平台会话、发送记录及可信范围事实（这些运行期事实不推进 `configRevision`，不能以版本号未变代替占用复核）。只有最终准入复核通过且认领提交后，才允许写入目标配置；若复核拒绝或系统关闭先获胜，未提交候选仍由原操作回收或保留可恢复义务。
- **旧连接隔离与占用释放**：切换应用、停用机器人及更新授权范围时，先隔离旧回调并等待旧长连接真实停止，再释放旧应用占用；代次失效不能代替底层套接字（Socket）与异步任务回收。若回收失败，则保留旧占用及恢复义务，同时如实发布已确定保存的配置与独立诊断。恢复消息准入前须确认旧连接已完全收束且当前配置已核实；新连接沿既有生命周期登记并消费新配置，防止旧连接携带的过期可信范围在提交后继续受理消息。
- **命令完成通道与关闭排空**：操作所有者统管准备、提交核实、权威状态发布及后续连接协调的完整闭环。调用方中途放弃等待不会撤销该所有者，也不遗弃迟到提交；任务创建与登记在同一生命周期边界内裁决。系统退出时先封闭管理操作受理，再等待已受理操作到达可恢复的真实终态。启停切换、可信联系人增删与群组授权修改同样服从该串行与恢复边界，不绕过未决提交直接覆盖配置文件。已受理命令的完成结果与本次操作身份绑定，并为尚未取走结果的等待者独立保留；后继操作或本地注册保存不会重置或替换该结果，工作任务异常终止时也会结束等待并返回安全的“提交待核实”错误。日志与实际文件已证明的既有保存结论不再作为新提交授权重放，而是准确同步该结论、核实当前归属与占用并协调连接；准备失败同样依据实际日志核实已执行步骤，确认未提交后归还临时应用认领，若存在未决清理义务则继续保留候选目标应用的占用。
- **引用环解除与幂等关闭**：成功关闭并确认全部工作任务与连接到达真实终态后，运行时解除与长期所有者之间的强引用环，释放持有数据库、HTTP 客户端和凭据租约的运行时记录；保留普通不可变快照不等于驻留这些底层资源。若关闭失败，则保留必要所有者供后续再次回收，不为打破引用环而提前清空未决任务。该释放仅针对进程内内存所有权，不删除磁盘上的机器人配置、数据库、历史或未决恢复材料；关闭成功后的重复关闭保持幂等。

读取所选凭据同样受运行时所有权约束：启动恢复、显式重试、令牌准备与连接协调中的阻塞读取不得直接占用异步执行器线程；读取完成后、投入使用前须重新核对当前机器人、应用、所选引用与操作代次，防止用迟到材料恢复已清除或已替换的认证。仅有事务日志而尚无确定配置文件的目录同样纳入原操作的恢复与诊断流程，重启时不因缺少普通配置文件而丢弃未完成义务。

### 状态投影与租户访问令牌

凭据可用性与凭据操作状态分开表达。管理快照提供强类型的 `credentialOperation`（包括 `idle`，以及携带 `operationId` 的 `preparing`、`commitUncertain`、`cleanupPending`，其中 `cleanupPending` 另带 `configCommitted` 以区分配置已生效后的旧材料回收与未提交候选回收）。操作状态仅含非敏感身份标识，不暴露密钥明文、候选材料或内部版本引用；读取失败、提交待确认与清理未完成分别保留诊断。保存命令仅在本次配置确定生效时返回已应用的持久回执；尚无可发布的确定配置时，未决操作通过管理快照的 `pendingCredentialOperations` 列表暴露（仅含 `botId`、`credentialOperation` 及安全诊断），不将未决候选混入已配置机器人列表。未确定配置前不启动长连接，也不向项目工具暴露该机器人。

飞书租户访问令牌（`tenant_access_token`）调用[飞书官方 OAuth 令牌接口](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/authentication-management/access-token/tenant_access_token)（2026-10-14 更新）：向 `POST https://accounts.feishu.cn/oauth/v3/token` 提交 `application/x-www-form-urlencoded` 表单（含 `grant_type=client_credentials`、`client_id` 与 `client_secret`），仅使用 `client_secret_post` 认证方式。企业自建应用不传 `tenant_key`，也不额外申请权限范围（Scope），直接沿用应用已开通的应用身份权限。实现层复用现有 `reqwest`、URL 编码与 `TokenLease`，不引入第二套 OAuth 客户端或缓存依赖。响应仅消费 `access_token`、正整数 `expires_in` 与 `Bearer` 类型，令牌字符串按原样完整保存与传输，不假定固定长度。HTTP 400 / 500 响应中的 OAuth 业务错误保留平台错误码，按认证失败、未启用／未安装、参数错误与可重试服务端错误分别归类，不回显原始响应体或凭据；不再调用旧版令牌接口，失败时也不自动回退。令牌仅在 Rust 内存中按实际过期时间管理，同一机器人的并发刷新请求自动合并。

每个机器人的配置与状态文件均携带版本号，单机器人读取失败仅生成该机器人的隔离诊断，不触发全局重置、删除目录或影响其他机器人。安全目录名称须与普通配置及事务日志中的身份一致，不一致或非法的目录名均予以安全隔离并记录固定诊断，不构造可操作的机器人身份，也不回显非法目录名原文。

## 27.3 首次配置与扫码注册

GUI 提供“创建并连接飞书应用”与“连接已有应用”两条首次配置入口，均先由用户确认机器人名称、关联项目、模型可用性及远程执行风险。扫码流程参考 OpenClaw 的首用户绑定体验，但不依赖其网关服务。

扫码注册启动后，当前注册尝试固定展示在机器人页面顶部，不随首次配置表单切换或设置页导航而隐藏；离开后返回页面继续观察同一权威注册尝试。等待扫码期间提供“打开飞书继续”、手机扫码与浏览器继续三种本地入口，并保留显式取消按钮。外部应用仅在用户主动点击时通过 Flutter 官方 [`url_launcher`](https://pub.dev/packages/url_launcher) 唤起，不由轮询状态自动触发。客户端使用 `canLaunchUrl` 检测系统是否注册了飞书协议，不自行维护安装路径或注册表判断；仅当检测通过时才显示桌面客户端唤起入口，未安装、检测中或检测失败时直接引导手机飞书扫码，且二维码始终保留。客户端唤起采用飞书官方 [AppLink 协议结构](https://open.feishu.cn/document/common-capabilities/applink-protocol/applink-introduction/applink-structure)定义的 `feishu://applink`，通过[端内网页打开协议](https://open.feishu.cn/document/common-capabilities/applink-protocol/supported-protocol/open-the-web-view-in-feishu-to-access-the-specified-url)在独立窗口中打开当前可信验证链接；原始验证链接作为整体查询参数编码，不篡改授权参数。仅生产环境允许的 HTTPS 授权来源可传入真实客户端，隔离测试夹具（Fixture）仅保留自身网页与二维码入口。操作系统接受唤起请求不代表客户端已成功打开或完成授权，界面继续保留扫码、浏览器入口及服务端轮询状态；唤起失败时不回显包含授权材料的底层异常。

机器人配置保存后，详情页提供官方[打开机器人会话](https://open.feishu.cn/document/common-capabilities/applink-protocol/supported-protocol/open-a-bot)入口，按当前 `App ID` 唤起飞书聊天窗口，同时提供 HTTPS AppLink 网页入口。打开聊天窗口本身不授予入站信任、不代替发送消息，也不证明应用已在企业内发布或对当前用户可见。

原生扫码注册调用官方 SDK 采用的设备授权接口，完整处理验证链接、二维码、服务端轮询间隔、`authorization_pending`、`slow_down`、用户拒绝、过期、本地取消与请求失败：

1. **短期授权材料保密与轮询退避**：二维码内容与验证链接属于敏感短期授权材料，仅交付当前注册 UI 渲染，不写入日志、普通配置文件或公开验收证据；底层设备码（Device Code）不进入产品 DTO。每次注册尝试拥有独立身份与代次；取消、过期或被新尝试替换时先使旧代次失效，迟到响应不得保存凭据、发布机器人或启动长连接（平台侧可能已创建的应用不由本地取消自动删除）。轮询间隔遵循服务端返回值；每次收到 `slow_down` 时，按 RFC 8628 及官方 SDK 约定在当前间隔基础上累加 5 秒并用于后续轮询，不重置为固定 5 秒。授权截止时间同时约束等待休眠与在途轮询响应，响应到达后仍须在完成认领前校验是否超时。
2. **取消与提交的原子裁决**：授权准备请求同样纳入尝试生命周期。本地取消与完成提交通过同一原子裁决边界确定先后：若取消先获确认，则迟到的准备或轮询结果不得重发等待状态、创建本地机器人或保存凭据；若完成先认领提交，则后续取消请求返回明确的忙碌原因，不再发布 `cancelled`，而是对外发布不含授权链接的强类型 `committing` 状态（携带 `attemptId` 与用于本地保存／恢复的 `botId`）。仅当配置与凭据关联均确定提交后才发布 `completed`；若本地保存确定未提交或处于待确认状态，则不发布 `completed`，改以失败诊断及同操作身份的凭据恢复投影展示本地待办义务，重试该义务无需重新向平台注册应用。进入终态后立即清除设备码与验证链接；后续连接失败通过独立连接状态表达，不撤回已确定的注册保存结论。
3. **验证链接来源与品牌校验**：注册返回的验证链接在进入 UI 前严格校验来源（Origin）。生产环境仅信任默认端口的 `https://accounts.feishu.cn` 与 `https://open.feishu.cn`，拒绝包含用户凭据、非默认端口或 URL 片段（Fragment）的链接，保留服务端返回的路径与必要查询参数，不按未经核实的路径白名单改写链接，也不将整个 `*.feishu.cn` 后缀纳入信任范围。官方 SDK 固定快照的[注册实现](https://github.com/larksuite/node-sdk/blob/b188be60134d409b61259546bcf69c731d2b0b7c/scene/registration/index.ts)直接解析服务端链接而未校验来源，产品层在此之上实施保守安全边界；遇到其他来源或 Lark 国际版租户标识时明确拒绝接入，并提供手工连接已有应用的入口，不自动切换多区域轮询域名，也不跟随重定向放宽来源限制。调试夹具仅接受当前清单绑定的同一本地回环（Loopback）HTTP 来源。当响应缺少品牌标识或明确为 `feishu` 时按中国版端点继续，其他未识别品牌一律按协议不支持拒绝，且拒绝诊断不回显原始链接或品牌字符串。

扫码注册成功并返回有效的扫码用户身份时，系统可将其设为该机器人的首位可信用户；若未返回有效用户身份，则保持默认关闭，绝不退化为开放访问。手工配置已有 `App ID` / `App Secret` 时同样默认拒绝所有未经批准的远程用户。

扫码注册使用显式的应用身份权限模板，不启用平台预设权限包，也不申请用户身份权限。默认权限模板包含 `im:message:send_as_bot`、`im:message.p2p_msg:readonly`、`im:message.group_at_msg:readonly`、`im:chat:readonly`、`im:message:readonly`、`im:resource` 与 `cardkit:card:write`，并订阅 `im.message.receive_v1` 事件，分别用于统一消息发送、接收单聊与群内真实提及、读取群目录与按需历史、下载消息中的图片／文件资源，以及创建和流式更新卡片。新增 `cardkit:card:write` 不替换或撤销既有的 `im:resource` 能力；系统不申请宽泛的 `im:message` 读写权限，也不默认申请读取全部群消息的 `im:message.group_msg`。[获取历史消息的官方权限要求](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message/list)（文档更新于 2026-04-10）将单聊历史所需的只读权限与群聊历史额外权限分开列出；群聊历史需用户在飞书后台单独开通，产品遇到权限拒绝时不自动扩大授权申请。

手工配置指引明确列出机器人能力启用、`im.message.receive_v1` 事件订阅、长连接接收方式、IM 查询／发送权限、`cardkit:card:write` 权限及应用发布要求。既有应用缺少卡片权限时明确提示管理员补充授权，不将声明权限视为已获批，也不暗中退回普通文本消息以掩盖卡片创建失败。企业租户下的应用仍受管理员审批与可用范围限制；尚未获准发布时保留本地配置并展示待办提示。

### 27.3.1 机器人工作区、模型与会话操作

机器人名称、模型路由、工作区和启停状态属于通用产品配置；平台专属应用参数与连接配置由带平台标签的枚举承载（当前仅支持飞书中国版）。设置页面遵循“总览 → 详情 → 聊天”逐级导航，进入下一层级后隐藏上一层列表，返回时保留原滚动位置与筛选条件；连接状态、模型路由与最近聊天优先展示，凭据管理与故障排查按需展开。

每个机器人拥有受管的本地工作区目录 `<StudioHome>/v2/bots/<botId>/workspace/`。各飞书聊天分别绑定独立的根 `Thread`；执行期产生的文件复用该工作区内按 `Thread` 划分的会话子目录，上传文件、`scratch/`、待交付产物和按需创建的 `uv` 环境均不写入业务项目目录。可靠历史与附件仍存于统一会话存储中，工作区文件仅作为执行期物化副本。受管工作区直接使用其规范化物理路径，不执行普通业务项目的向上 Git 仓库根发现；即使 `StudioHome` 位于某个代码仓库的子目录内，机器人根会话、子会话及冷启动恢复也始终以机器人工作区目录作为执行根。已有机器人升级迁移时保留原 `Thread`、输入、回复与凭据身份，且迁移中断后可幂等接续，既不搬移归属不明的项目文件，也不重新执行历史输入。

机器人的模型路由是其名下所有绑定聊天的唯一模型配置来源：当前在途模型请求保持已冻结的路由不变，后续新执行轮次自动应用更新后的机器人模型配置；普通会话页面显示该机器人归属并提供跳转入口，不为同一飞书聊天维护相互竞争的会话级模型配置。桌面端向该会话提交输入时，先校验调用方观察到的会话路由修订版本，再在同一受理锁内应用机器人模型配置，避免将本次受理自身触发的模型路由同步误判为过期提交。当历史条目身份尚未完成异步落盘时，驻留内存的待处理输入（Pending Input）与精简终态身份（Terminal Identity）均代表“已受理、待持久化”，前端不重新生成附件草稿或重复提交。

机器人根 `Thread` 默认挂载两类 Studio 产品级会话工具：

- **跨项目会话查询与代发工具**：包括 `list_sessions`、`get_session`、`search_session_messages`、`read_session_messages` 与 `send_session_message`。查询覆盖所有本地项目，目录与内容复用现有所有者；正文搜索支持中文并按有界游标分页接续，不将截断预览或局部扫描当作全量搜索结果，且只读查询不启动执行所有者。`send_session_message` 走标准用户输入受理链，通过稳定操作身份防止重复执行；附件仅允许引用来源会话已归档的可靠资源并导入目标会话，代发来源保持可见，不赋予系统级或审批级特权。系统不向模型提供创建、停止或归档会话的管理工具。
- **跨会话待决交互决议工具**：包括 `read_session_interaction`、`approve_session_plan`、`revise_session_plan`、`answer_session_questions` 与 `decide_session_tool_approval`，供可信入站用户在飞书聊天中显式指示时，代为处理其他本地会话的待决交互（具体契约见 §27.7）。

## 27.4 入站授权与会话映射

### 入站信任与项目工具授权隔离

机器人关联项目不构成操作系统级沙箱；界面显式说明当前工具的有效执行策略为完全访问（`full-access`，参见 [04 - 安全与权限策略](./04-security.md)）。入站授权规则属于机器人消息准入控制，不构成底层 Shell 的安全隔离承诺：

- **单聊（私聊）准入**：仅允许已加入可信列表的用户触发执行；未知用户发来的消息仅生成有界、可在桌面端确认的配对请求，不触发模型推理或工具调用。批准与撤销配对均为显式本地操作，远程消息无法自行提权；批准配对前收到的未授权历史消息不会自动补执行，用户获批后需按提示重新发送。
- **群聊准入**：群聊触发默认关闭；仅当群组已获显式授权、消息发送者为真实用户而非机器人，且消息中真实提及（`@`）本机器人时，才进入执行链（`@全体成员` 不视为提及本机器人）。群授权直接作用于该群内的用户提及消息，不额外叠加单聊可信联系人白名单；本地启用群授权时界面明确提示群内任何用户的真实提及均可触发本机智能体，且单聊配对不替代群授权或群目录可见性。
- **入站触发与项目工具访问分离**：`trustedChatIds` 仅控制哪些群聊消息能发起智能体执行；项目的 `toolsEnabled` 开关则控制关联项目的桌面智能体能否调用机器人工具查询或发送飞书消息。查询与发送操作必须校验平台会话可见性（群聊依据平台群成员关系，单聊依据已观察到的单聊身份，禁止将群 ID 写入单聊目录作为授权捷径）。撤销项目的 `toolsEnabled` 或更换关联项目后，旧工具调用立即丧失访问权；关闭某群的入站触发授权不会隐式撤回项目的工具查询／发送授权。此外，`toolsEnabled` 并非机器人总开关：桌面所有者的显式管理查询／发送，以及已授权入站消息在原飞书会话中的正式自动回复，均不以 `toolsEnabled` 为前提，各自独立验证本地／入站来源与目标可见性。

### 会话映射、指令装配与显式重建

会话映射按机器人身份与飞书平台会话身份严格隔离，每条映射关联一个 Studio 根 `Thread`。首次创建与后续消息受理共用同一 `Thread` 工厂及用户输入链，统一复用模型路由、历史存储、用量计费与目录活跃时间。飞书平台消息 ID 构成稳定的输入幂等身份：平台重推、断线重连或进程重启后的重复消息命中原身份时直接幂等收束，若同一消息 ID 的正文内容发生冲突则显式报错，绝不重复启动模型。同一飞书会话的多条不同消息作为独立输入，交由同一 `Thread` 的非打断串行驱动逐条消费；后到达的消息既不取消正在生成的回复，也不将两条独立消息合并为单次执行。当目标 `Thread` 已归档或缺失时，系统明确报告需恢复或显式新建，不暗中重定向至其他会话。

新建飞书根会话时，系统依据已核实的机器人归属自动绑定内置飞书智能体声明，与普通根会话及子会话采用同一套定义、冻结与指令装配机制；渠道适配层不直接拼接系统角色提示词，也不设逐机器人的提示词编辑器或配置档选择器。内置飞书智能体指令指导模型直接输出适配飞书渲染的 Markdown（标题、段落、列表、引用、链接、行内代码、带语言标识的围栏代码块与简洁表格），明确区分普通消息与流式卡片能力，不输出原始 CardKit JSON，不将整段回复包裹在单个外层代码块中，也不生成任意 HTML；正式自动回复由宿主统一发送，模型不为同一回答重复调用发送工具。智能体指令与会话模式（Mode）相互独立，其冻结与升级迁移遵循 [20 - 配置与凭据管理](./20-config.md#206-提示词配置)；已有会话保持创建时冻结的指令，若需应用新版指令定义，可通过显式“新建本机会话”操作开启新上下文。

首次创建 `Thread` 与写入映射绑定之间的故障支持按同一创建身份幂等恢复，避免留下永久占位或每次重试产生孤立 `Thread`。可靠受理记录保存尚未完成交接的输入，并依据目标 `Thread` 的真实受理事实判定交接是否完成，不将消息 ID 去重命中直接等同于模型执行与回复发送已完成。长连接代次仅用于隔离旧连接回调，不充当会话绑定的修订版本；受理记录固定记录所属应用、项目及绑定的创建身份与版本号，长连接重建不改变已受理工作的归属。消息受理、映射切换与身份锁定校验共享同一权威准入边界，而耗时的 `Thread` 创建与网络请求均在准入锁外执行，确保不阻塞平台事件确认（ACK）。

创建中的绑定路由必须有确定的终局，不能只靠重试期望它自行消失：同一创建身份对应的 `Thread` 已存在却不可用（归档、归属其他项目）属于不可辩驳的身份冲突，立即收敛为需处理；其余失败按有界退避重试，只有在受理记录的退避预算真正耗尽且仍由本次认领持有时，才把创建中的路由收敛到既有的需处理状态。收敛复用同一状态值与同一诊断列，保留原创建身份、不切换新身份、不新建替代 `Thread`，并与受理记录的终态诊断一致对账；重复收敛幂等，失租的旧所有者不得把路由判定为终局。收敛后的会话对平台入站明确报告需处理而不执行模型，并可被本地显式新建会话按当前绑定修订版本替换为新意图，不被永久挡住。

桌面所有者可针对已核实可访问的飞书会话显式执行“新建本机会话”，用于从归档、缺失或异常关联中恢复，或主动开启全新的本地上下文：

1. **原子切换与历史保留**：该命令携带 `operationId`、预期 `configRevision` 及独立的预期绑定修订版本（`expectedBindingRevision`），在当前应用和项目内创建新的根 `Thread` 并原子切换后续入站消息的映射目标，不接受外部传入任意 `Thread ID`。原 `Thread` 及其已受理事实完整保留，旧输入与旧在途回复不迁移至新上下文，也不重新执行；已提交输入的结果仍可在原 `Thread` 中查询。
2. **幂等接续与替代判定**：重复提交同一操作身份时复用同一次创建；若当前绑定已被后继显式新建操作替代，则明确报告原操作已被替代，既不将后继绑定冒充为原操作的幂等结果，也不倒退回旧绑定。首次接受新建意图时，在权威准入边界内重新核对 `configRevision`、应用与项目归属；初始绑定的版本切换与创建操作记录原子落盘，不留下归属不明的创建中占位。
3. **严格解码与不可恢复故障隔离**：绑定认领、绑定投影、操作回读及入站工作恢复中的关键身份与水位若解码失败，一律禁止回退为默认值或用当前请求参数覆盖；不可恢复的持久化状态损坏在回复与工作收束边界直接呈现“需本机恢复”，不转为可自动重试的临时错误。

入站消息支持接收纯文本、富文本（Post）、图片与文件；通过准入校验后，宿主调用飞书消息资源接口下载图片与文件，并复用统一的会话附件校验、可靠归档与用户输入链。遇到不支持的媒体类型时明确提示，不将占位文本伪装成附件；所有入站平台内容均保持普通用户来源属性，不解释为系统指令、工具审批或子智能体通知。
可信且真实提及机器人的 unsupported-only 首条消息只创建原入站及辅助提示义务，不创建
Thread、不调用模型、不生成卡片或文件。提示按稳定操作身份发送一次有界 `post`；原
提示被平台接受并可靠保存后，入站记为 completed，这不表示模型已执行。失败或不可证
结果按原账本显式保留，不能把 needs_attention 与成功终态互换；暂停、关闭与撤权的

## 27.5 HTTP 接口与长连接协议

普通飞书 OpenAPI 调用严格区分 HTTP 传输失败与平台业务错误。错误对象保留安全错误类别、平台数字错误码、可重试标记及关联身份，绝不透传包含密钥、消息正文或带票据 URL 的原始响应文本；模型工具也不接受外部传入任意 API 主机名。普通请求须同时满足 HTTP 2xx 状态码与端点业务成功条件（如 `code == 0`），非成功 HTTP 状态码即使响应体可解析为 JSON 也一律按失败处理。扫码注册轮询按官方协议识别 HTTP 400 响应体中的等待、降频与拒绝状态，不将异常状态下的字段当作注册完成。各端点按自身响应结构进行强类型反序列化，不将普通 IM 接口的 `data` 外层包装强加给其他端点；例如 [`GET /open-apis/bot/v3/info`](https://open.feishu.cn/document/client-docs/bot-v3/obtain-bot-info) 直接读取顶层 `code`、`msg` 与 `bot.open_id`（该结构已对照官方 [CLI 仓库快照](https://github.com/larksuite/cli/blob/017b19a793ad71794a02887ede04757f3d82e10d/shortcuts/common/runner.go)核实），缺失 `bot.open_id` 直接报协议错误，不尝试其他字段或动态 JSON 兜底。

长连接通过官方 `/callback/ws/endpoint` 接口发现服务端地址，校验来源合法后发起 WebSocket 握手；仅当 HTTP Upgrade 握手成功且响应未携带协议拒绝信息时，才对外发布 `connected` 状态（无需等待首条业务消息到达，但后续一旦收到明确的认证或协议拒绝帧即刻转为失败并关闭连接）。发现响应返回的 WebSocket URL 允许携带官方连接所需的查询参数（含服务标识与短期连接票据）；校验安全来源后完整保留这些连接参数，但绝不将含短期票据的完整 URL 写入诊断或日志。

每个机器人由唯一的连接所有者统管底层套接字、心跳、重连、分包重组缓存与取消信号：

- **生命周期与主动状态发布**：同一连接所有者的启动、替换、停止与关闭有序裁决，异步任务句柄从创建到汇合（Join）始终由唯一所有者持有；并发重试不会覆盖尚未回收的句柄，关闭流程开始后也不会借在途启动再次派生任务。握手成功、重连与失败等异步状态变化主动发布至权威 `Bots` 产品主题（Topic），不依赖 GUI 轮询或无关管理操作顺带触发；配对请求等入站状态可靠落盘后，同样通过有界、可合并的通知交由受控发布所有者更新主题，既不阻塞平台事件接收与 ACK 路径，也不为单条事件派生无界任务。
- **控制帧与时间单位契约**：控制帧、Ping / Pong、服务端动态参数、事件 ACK 与 Protobuf 载荷字段严格遵循固定官方协议，不手写通用二进制编解码器。端点发现与 Pong 帧中的 `PingInterval`、`ReconnectInterval`、`ReconnectNonce` 线协议单位均为**秒**，`ReconnectCount` 为次数（官方 Node SDK 的 `ws-client/index.ts` 在设置定时器时才将其乘以 1000 转为毫秒，Rust 实现直接按秒消费，避免误作毫秒）。
- **分包重组与有界应答预算**：事件分包按消息身份校验总包数、序号顺序与一致性，重组缓存设有严格的字节数、分包数、并发消息数及存活期限上限；非法或超限帧直接报错并丢弃，防止无界内存分配。事件受理与模型执行解耦：在平台应答期限内仅执行有界校验、准入判定与可靠落盘记录，落盘成功后立即返回 ACK，模型推理与工具执行不在 ACK 等待路径上运行；若可靠落盘失败则不返回成功 ACK，重复消息的 ACK 与首次受理引用同一持久化身份。此外，由于平台在 WebSocket Upgrade 完成后即可立即推送事件，准入所需的机器人身份须在启动接收循环前准备就绪，或由独立受控初始化与接收路径协同配合，不得在握手成功后同步阻塞等待令牌或机器人信息 HTTP 请求。

遇到临时网络故障时，连接所有者按服务端下发的有效重连参数执行有界等待与指数退避；遇到凭据无效、协议不兼容或配置损坏等不可恢复错误时，立即停止自动重连并在界面提供修复入口。断开、停用或应用退出时先封闭新消息准入，取消在途注册、HTTP 请求、心跳与重连定时器，并等待所有任务与套接字到达真实终态；若关闭失败则保留所有者与诊断供后续接续回收。

## 27.6 会话查询与统一发送

### 会话目录与历史查询

飞书官方接口 `GET /open-apis/im/v1/chats` 仅返回机器人所在的群聊。产品层的机器人会话列表由该平台可见群目录与本地已收到入站事件的单聊目录组合而成，并显式标注各条目来源；分页游标区分两类来源并绑定机器人与查询条件身份。系统不承诺提供全平台跨会话最近消息全局排序，也不宣称能枚举未发生过交互的全部私聊。会话历史通过官方 IM 接口按会话 ID、时间范围与分页游标查询；当机器人不在目标群内或缺少相应只读权限时显式报错，不切换为用户个人凭据。根据[获取会话历史消息文档](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message/list)，请求参数 `start_time` 与 `end_time` 的线协议单位为 **Unix 秒**（直接映射产品时间戳，无需乘以 1000），而响应消息中的 `create_time` 单位为 **Unix 毫秒**（需转换为产品的 Unix 秒）。

### 普通 Markdown 发送与去重边界

桌面 GUI、入站消息正式自动回复与模型工具共用同一机器人发送边界与授权校验。普通发送在首次 `await` 前冻结 `botId`、`chatId`、正文与 `operationId`，按调用来源校验项目工具权限或本地／入站授权，并核实目标会话可见性。

普通发送接口的公开 `text` 字段承载 Markdown 文本，底层封装为飞书官方 `post` 富文本消息中的 `md` 节点（纯文本同样作为 Markdown 正文发送），具体结构遵循[发送消息内容结构](https://open.feishu.cn/document/server-docs/im-v1/message-content-description/create_json)，由飞书客户端负责渲染 CommonMark / GFM 语法。请求大小按实际序列化后的 UTF-8 字节数计量（含 JSON 转义开销），严格遵守[发送消息接口](https://open.feishu.cn/document/server-docs/im-v1/message/create)的单条 30 KB 上限与同一目标会话 5 QPS 限频。超长正文在不超过既有总发送预算的前提下，优先按自然段或换行边界无损分段，每段分配稳定子操作身份，分别记录已发送消息 ID、失败与未知结果；仅当所有分段均确认成功时才标记整体送达。

飞书官方发送 UUID 的服务端去重窗口为 1 小时，不等同于永久精确一次（Exactly-Once）投递。请求超时、网络断开、调用方取消等待或进程重启遗留的在途发送均可能已在平台侧生效，因此统一持久化为 `unknown` 状态且不自动重放；明确拒绝与已成功结果则各自如实保存。同一操作身份若携带不同正文内容则直接拒绝。相同操作身份的原结果回读不属于重新发送：系统先核对持久化指纹、归属及当前本机／项目来源权限，直接返回原回执，无需以重新联网、刷新令牌或读取系统凭据库作为回读前提；但项目工具权限被撤销后，模型工具不得借结果回读继续访问机器人。

### 会话公开投递与输入交接

飞书前端的公开范围、授权起点与暂停／关闭语义统一遵循 [29 - 会话公开输出与前端受众](./29-conversation-publication.md)。有效授权后的公开进展（`Commentary`）、最终答复（`Final`）与显式产物由独立投递所有者消费；来源可以是飞书输入、桌面端后续输入或规范续接。入站所有者只负责将原消息按稳定身份可靠交给 Studio，不为等待模型答复、卡片更新或文件发送长期持有入站认领。

入站交接完成依据规范输入的可靠受理事实，不以消息去重命中、模型已开始或平台已发送代替。交接前先核对既有输入身份与首次就绪事实，再准备附件；同次受管处理中的可重试提交保留已准备附件的所有权，不先销毁再重复下载。确认受理、明确拒绝或受管退出后才释放附件准备责任，受理确认不明时先核实原输入，不重新执行模型。

遇到待决交互时，投递所有者只呈现安全的等待状态，不广播敏感问题、答案或原始权限载荷，也不解析普通聊天文本自动批准交互。可信入站用户显式要求决议时仍使用 §27.7 的既有工具。状态流只负责唤醒；输入、轮次、交互与保存结论来自各自的规范事实，持久化未就绪与确定无续接分别表达。

存量有限回复仅沿已证明的原输入及规范续接追踪 `Final`，不扩大到旧进展或无关本机输入；这些义务迁移至同一投递所有者，不保留第二套旧回复执行器。旧卡片保持原实体和操作身份，不因新前端采用逐项卡片而拆分重发。迁移与未知结果保全遵循 [17](./17-studio-storage.md)。

### 27.6.1 流式卡片协议与可靠收束

公开文本采用飞书官方[流式更新卡片](https://open.feishu.cn/document/cardkit-v1/streaming-updates-openapi-overview)机制。同一公开文本项的修订更新原卡，不随 token 创建消息；不同文本项独立呈现。只有真实正文或必要的安全状态才产生呈现实体，空 `Final` 不补造答复，已有预览不能因轮次结束就冒充完整权威内容。卡片正文采用 [JSON 2.0 结构](https://open.feishu.cn/document/feishu-cards/card-json-v2-structure)中的 [Markdown 富文本组件](https://open.feishu.cn/document/feishu-cards/card-json-v2-components/content-components/rich-text)，声明 `streaming_mode=true`、`update_multi=true` 及稳定唯一的 `element_id`。

| 卡片操作 | 官方接口与参数边界 |
| --- | --- |
| [创建卡片实体](https://open.feishu.cn/document/cardkit-v1/card/create) | `POST /open-apis/cardkit/v1/cards`，传入 `type=card_json` 与序列化卡片 JSON `data`，返回 `card_id` |
| 发送卡片消息 | 调用普通 IM 发送接口，`msg_type=interactive`，`content` 为含 `type=card` 与 `data.card_id` 的 JSON 字符串 |
| [流式更新正文](https://open.feishu.cn/document/cardkit-v1/card-element/content) | `PUT /open-apis/cardkit/v1/cards/{card_id}/elements/{element_id}/content`，提交累计完整 `content`、递增 `sequence` 与稳定 `uuid` |
| [全量更新同一卡片](https://open.feishu.cn/document/cardkit-v1/card/update) | `PUT /open-apis/cardkit/v1/cards/{card_id}`，提交完整 `card`、递增 `sequence` 与稳定 `uuid`；用于正文与独立宿主状态区需要一起变化的呈现修订 |
| [更新卡片配置](https://open.feishu.cn/document/cardkit-v1/card/settings) | `PATCH /open-apis/cardkit/v1/cards/{card_id}/settings`，传入序列化 `settings`，同时携带 `sequence` 与 `uuid` |

卡片创建、消息发送、正文更新与配置关闭共用同一应用身份。每个卡片实体仅发送一次，平台可操作期为 14 天，过期后不自动创建替代卡片。`sequence` 为同一卡片所有正文更新与配置修改共用的严格递增正 32 位整数（`int32`）；飞书端通过比较完整文本的前缀扩展实现打字机效果，因此每次更新均提交当前累计完整正文。最终完整正文确认送达后，再调用配置接口将 `streaming_mode` 设为 `false`（允许在更高序号上提交与末次预览相同的完整正文以完成正式收束）；完成、等待本地交互、中断和失败状态下的卡片摘要（`summary.content`）均由产品显式设置。

单张卡片的正文更新至多每 200 ms 提交一次，窗口内的多次增量合并为最新可验证版本，由唯一受管发送所有者串行推进，末次正文提交与流式模式关闭同样经过该速率与顺序边界。组件内容接口 100,000 字符的单字段上限不扩大下述完整序列化预算；超过显示预算按有提示的呈现截断处理，而不是平台错误或自动分片的理由。

每个真实公开文本项单独呈现为一个稳定卡片实体：同一文本项的修订更新原卡，不同 Commentary 与 `Final` 按统一内容源顺序各自成卡，使进展不会占满最终答复的卡片；空正文且无需状态提示时不创建空卡。

单条正文的显示上限取两个约束中的更严格者：最多 **4000 个 Unicode 标量**，且包含宿主状态与截断说明的完整序列化卡片及适用发送请求仍须满足既有的 **30,000 字节**预算。字符按 Rust `char` 计数，不按标记（Token）、UTF-8 字节或 UTF-16 长度计算；截断在合法 UTF-8 边界进行，优先在可用换行处结束。达到上限后停止扩张该项的显示正文，并在独立宿主状态区明确提示“内容已截断，以下不是完整答复或代码；全文保留在 Studio，可要求导出 Markdown 文件”；该提示不与正文拼接在可能未闭合的代码块或链接内部。截断只影响平台呈现，不截断模型输出、本地会话历史、桌面界面全文与可靠原件，也不因超限取消执行或再次调用模型。
内容完整性（`Full`／`Truncated`）与平台结果（`Accepted`／`Rejected`／`Unknown`）分别表达：截断是已知的呈现结果，不冒称全文已送达，也不阻塞后续文本项与公开产物；文件字节永不截断。系统不为超长正文自动导出转录文件、自动分片续发或换用另一种消息形态重发。

平台卡片与消息身份必须有非空白的真实返回值，非空身份原值保留，不擅自裁剪或重写。新请求的成功响应缺少有效身份时按结果未知处理；迁移来源或当前账本若把空白身份保存成已接受事实，须保留原材料并明确拒绝不可信恢复，不能解释为尚未发送、清空身份后重发或据此推进已送达状态。

正文与宿主提示使用独立组件。常规正文进展沿组件内容接口更新；需要同步改变宿主提示
的修订使用全量更新同一卡片的官方接口，保持 JSON 2.0、稳定组件身份和当前流式配置。
两种更新共用原实体、序号和操作账本，不是失败后的换形态重发。请求意图须同时冻结
具体操作目标和准确请求正文，恢复不能依据最新内存状态把旧操作改投另一接口。

可靠卡片进度持久化在现有机器人状态库中，由独立投递所有者持有，记录授权作用域、稳定呈现身份及内容修订、卡片与平台消息 ID、已确认和待确认操作的序号与指纹，以及创建、发送、更新、关闭和最终结局。存量有限回复另保留原输入与续接关联，不伪造新的公开文本项身份。未知创建、发送、更新或关闭均保留原操作事实并标记为“需核实”，不通过自动重试、更换 UUID、递增序号或新建卡片掩盖不确定状态。仅当实体已知、没有未知在途操作且当前授权与认领有效时才可安全续接。

每次平台新写入，包括流式重新开启、末次正文更新与关闭，均经过同一授权和认领复核；封闭授权后不能为“收尾”再发关闭请求。已启动请求的结果仍归原操作保存，不能因撤权丢弃，也不能授权下一次发送。平台过期、无权限、序号冲突或协议拒绝不作为普通网络错误重试；权威轮次已消费输入的取消终态不在重启后重新执行。

## 27.7 产品 API、主题与工具

公共 DTO 统一采用 `camelCase` 字段名（含带标签枚举变体内的字段）、字符串 ID 与 Unix 秒时间戳。机器人模块拥有独立的 `Bots` 产品主题（Topic），对外发布 `BotsStateChanged` 事件；状态快照包含领域修订版本、各机器人配置／连接／凭据可用性状态、当前扫码注册进度及有界配对诊断，不携带会话消息历史。配置并发控制（CAS）使用各机器人独立的 `configRevision`，不混用主题水位。每个主题水位对应一份带固定更新时间戳的不可变已发布快照，单次读取、命令回执与订阅首帧共享同一已发布事实，且快照收集与发布协调不持有全局注册表锁或消息准入锁跨越 I/O，也不阻塞平台事件 ACK。携带密钥明文的保存请求仅作为命令输入消费，其自身及嵌套结构的 `Debug` 输出均经过脱敏处理。

产品管理命令覆盖配置保存、扫码注册启动／取消、机器人启停／连接重试、可信联系人／群组授权管理、按需会话／消息查询、人工消息发送，以及显式创建本地会话线程命令 `createBotConversationThread`（HTTP 端点为 `POST /api/v1/bots/conversations/thread`）。`createBotConversationThread` 请求包含 `operationId`、`botId`、`chatId`、`expectedConfigRevision` 与独立的 `expectedBindingRevision`，返回强类型绑定投影与命令回执；该管理命令仅面向桌面所有者，不开放给模型工具。所有写命令均携带 `operationId`，配置变更命令另带 `expectedConfigRevision`，响应直接返回权威快照或强类型查询／发送结果，无需调用方在成功后二次轮询聚合。普通只读查询与主题订阅首帧不发起外部网络请求、不激活模型，也不自动触发注册或重连。

项目智能体工具与桌面 GUI 共享同一宿主端口，且仅当关联项目开启 `toolsEnabled` 时向该项目的**根 `Thread`** 暴露以下四项外部机器人工具（子智能体不自动继承该工具集）：

| 工具名称 | 输入与输出边界 |
| --- | --- |
| `list_bots` | 返回当前项目已获授权的机器人 ID、显示名称、连接状态及能力标记（不含任何凭据信息） |
| `list_bot_conversations` | 接收 `botId`、分页游标与会话种类；返回可见群聊与已知单聊列表、各自来源标记及下一页游标 |
| `read_bot_messages` | 接收 `botId`、`chatId`、Unix 秒时间范围及 `cursor` / `limit`；返回强类型历史消息页 |
| `send_bot_message` | 接收 `botId`、`chatId` 与 Markdown 文本；返回 `operationId`、发送状态及已知平台消息 ID |

上述工具不提供扫码注册、凭据修改或远程授权管理能力，也不借用内部智能体协作消息通道发送；`send_bot_message` 属于外部写操作，不具备只读程序化调用（Programmatic）豁免资格。每个 `Thread` 持有独立的工具实例，底层物理机器人服务通过宿主能力安全共享。

与之相对，**飞书机器人聊天自身的根 `Thread`** 额外挂载十项跨项目 Studio 会话工具：

1. **五项会话查询与消息提交工具**：`list_sessions`（目录分页）、`get_session`（状态读取）、`search_session_messages`（正文搜索）、`read_session_messages`（历史分页）与 `send_session_message`（消息提交）。单次列表或历史分页上限为 100 条；正文搜索单次最多扫描 32 个内容页或分块、返回最多 10 条命中，长正文按 32 KiB 分块读取，游标绑定查询条件并保留跨块匹配尾部（当返回 `complete=false` 时调用方须继续分页查询，不得提前报告无结果）。`send_session_message` 的幂等身份由调用方 `Thread`、`Turn`、工具调用 ID 与目标会话共同派生，附件参数仅接受来源 `Thread` 已归档的可靠附件 ID。
2. **五项待决交互读取与决议工具**：`read_session_interaction`（读取单个待决交互全文）、`approve_session_plan`（批准计划）、`revise_session_plan`（要求修改计划）、`answer_session_questions`（回答提问）与 `decide_session_tool_approval`（裁决工具审批）。这些工具仅对其他非归档会话中仍处于待决状态的交互产生新决议，并与桌面端共用同一个 `resolve_interaction` 提交边界：
   - `get_session` 的待决列表仅返回交互种类、用途、问题概要与选项摘要，完整正文须通过 `read_session_interaction` 按交互身份按需读取；
   - 计划决议按计划确认问题构造 `Approve` 或 `Revise` 加必填反馈（遵循计划状态机长度上限）；普通提问将答案按问题 ID 映射至所选选项标签及／或自由文本；工具审批决议携带批准或拒绝及拒绝理由；
   - 决议操作身份由调用方 `Thread`、`Turn`、工具调用 ID 与目标交互身份共同派生；交互完成决议退出待决快照后，重复调用仍可依据统一交互事实核对归属、种类与原决定，相同决定幂等返回原终态，不同决定明确报冲突错误。

## 27.8 桌面界面（GUI）与客户端状态

机器人设置界面采用“总览 → 详情 → 聊天”三级独立视图：进入详情页后隐藏总览列表与左侧设置导航栏，聊天视图直接复用现有会话时间线与附件组件，返回上一级时完整保留滚动位置与筛选状态。总览页展示机器人名称、平台、连接状态与最近活动；详情页优先展示连接状态、打开飞书聊天、模型路由与最近聊天列表，而可信联系人与群授权、凭据轮换、受管工作区路径及故障排查则归入次级设置区域；平台消息查询与人工测试发送设有独立子页面（界面使用友好时间选择，不直接暴露原始 Unix 时间戳输入框）。机器人设置入口追加在现有设置导航列表末尾，不打乱既有导航顺序。界面严格区分并独立呈现“本地配置已保存”“长连接已建立”与“入站用户／群组已授权”三项事实，不将其合并为单一笼统的“已就绪”标签。

关键交互与状态收敛约束如下：

- **开发者后台外链与二维码容错**：遇到历史消息权限不足提示时，界面同时提供飞书中国版[开发者后台](https://open.feishu.cn/app)的可操作外链入口，引导用户选择当前 `App ID` 对应的应用开启相应权限；该入口仅打开固定官方 HTTPS 页面，不携带本地凭据或票据，打开失败时给出可重试的安全提示。扫码注册的验证链接与二维码数据属于在途短期授权材料；若二维码编码失败（如容量超限），界面仅展示安全的通用提示并保留本地链接打开操作，既不将原始授权数据或底层异常写入日志、Driver 投影与验收证据，也不因二维码编码失败而自动发起新的注册尝试。
- **持久占用（Occupancy）的主动发布与有界任务预算**：应用与项目字段的可编辑性取决于真实的持久化业务占用。当首次配对记录、首次入站受理、本地显式新建会话或首次发送认领改变占用状态后，领域所有者通过受管发布生命周期主动更新权威快照与主题，无需等待后续无关管理操作顺带刷新，也不由 GUI 轮询猜测。此类占用能力变化不推进 `configRevision`，且聚合发布不阻塞平台事件 ACK。占用落盘及其后续本地绑定接续由有界受管任务持有至真实终态（调用方取消仅放弃等待，不中断已受理事务）。占用任务池同时约束等待登记与执行中的任务：并发任务数上限为 **32 项**，跨等待持有的额外冻结文本总量上限为 **64 MiB**（仅持有必要身份、标题与事件标量，不克隆整份配置或无关可信集合；持久化边界显式构造并跨等待持有的文本副本一并计入预留）。当任务池暂满时返回可重试背压错误；单条输入超出总预算时在首次落盘前直接返回不可重试的资源超限错误。
- **关闭异常保留与配对列表隔离**：系统关闭期间已观察到的任务异常由所有者保留，直至排空在途任务并完成真实状态发布后再上报消费，不被中途取消或后续等待抹除；任务终态句柄仅回收一次，安全诊断不包含原始恐慌（Panic）载荷。单个机器人的配对请求列表若读取失败，则显式报告不可用并保留已发布列表，不将读取失败发布为空列表，也不重置机器人配置。配对请求行提供保持当前信任状态的显式“清理”操作（与“批准信任”相区分），清理请求携带同一权威快照的当前信任值与 `configRevision`，若快照已过期冲突则拒绝修改；批准后的清理若失败，原配对行保留至下次明确清理成功，无需用户先撤销信任。
- **平台错误码透传与 `21001` 访问控制处理**：连接失败、消息接口与机器人信息接口的非成功响应均解析并展示飞书平台业务错误码，仅在无结构化业务码时才回退至 HTTP 状态码分类；权限拒绝按“机器人不在群内”“用户不可见”“未开启机器人能力”与“缺少对应接口权限”如实区分，不一概改写为缺少群历史权限。遇到飞书访问控制拒绝码 `21001` 时，对照[官方 CLI 错误分类](https://github.com/larksuite/cli/blob/main/internal/errclass/codemeta.go)按**不可自动重试的权限错误**处理，明确提示联系企业组织管理员检查应用访问策略并提供开发者后台入口，待策略获批后由用户显式重试。
- **客户端单向数据流**：每个 `AppGraph` 的客户端实例持有机器人主题读模型、在途请求与发送草稿，权威归约器（Reducer）是唯一状态写入者；Riverpod 仅适配只读观察，组件仅负责渲染与提交意图，进出设置页不会关闭机器人连接或当前聊天 `Session`。会话查询冻结 `botId`、`chatId`、过滤参数与尝试身份，迟到响应不覆盖新选择；发送草稿按机器人与会话隔离并受既有草稿预算约束，界面展示的最近发送结果仅为有界镜像，淘汰镜像不触发重发，也不删除 Rust 侧持久化操作账本。

会话标题与输入区持续显示当前同步目标与状态：绑定会话显示机器人与飞书会话，群聊明确标注群受众，暂停显示为“恢复后补发”并保留原代次与游标，关闭同步或需要升级时明确说明不再外发；已截断的呈现与仍在生成中的预览分别标注，不把预览、截断结果或本地保存状态合并成“已就绪”。

## 27.9 验收边界


系统通过本地隔离平台夹具（Fixture）与人工观察入口验证原生 HTTP、WebSocket、事件 ACK、幂等去重、请求取消、入站授权、历史查询与流式卡片发送路径，严格遵循 [24 - 测试策略与门禁](./24-testing.md) 的测试分层，不为测试暴露生产私有接口。原生桌面 GUI 通过真实桥接层与 Flutter Driver 核对窗口截图、状态快照、错误呈现与退出资源回收。本地平台模拟与演示模式（Demo）不等同于真实飞书服务端授权或客户端渲染兼容；真实飞书账号验收需使用独立的手机扫码授权与测试应用，且提交的验收证据不得包含可用二维码、真实凭据、真实联系人身份或私聊正文。

Markdown 出站与流式卡片观察必须留存独立模拟平台收到的 `post` 消息或卡片 JSON 结构、同一卡片实体的严格递增序号操作序列及最终正文证据，并证明至少一次流式正文更新早于模型轮次（Turn）完成。模拟协议对端（Peer）仅提供环境响应，不代替生产代码执行授权校验、智能体装配、正文过滤、工作认领或恢复裁决。Linux 隔离 GUI 截图仅证明本地原生界面的 Markdown、生成中与终态渲染，不可标注为飞书客户端渲染截图，也不能单凭界面截图替代底层流式协议证据。已脱敏的原生界面验收展示见[飞书原生界面截图说明](./assets/feishu-native/README.md)。

真实飞书平台验收分两层：协议事实由本地模拟对端（Peer）与 `bots_protocol_observe` 显式观察入口核验，真实平台事实则通过官方 CLI 直接核验 Markdown `post` 消息的读回结构、CardKit 流式卡片的创建／递增序号更新／关闭，以及文件的双向往返（上传、按目标消息实际资源键独立下载、字节与摘要一致）。平台接口返回的卡片 JSON 与资源摘要不构成飞书客户端渲染证据，也不冒充产品自动投递链路已经通过。

### 隔离平台夹具与宿主边界


人工验收使用的模拟飞书平台位于 `pl-provider-fixture` crate 中，仅提供飞书 HTTP / WebSocket 协议环境与独立的请求格式校验，不链接机器人生产私有模块：

1. **合成注册、权限校验与受控挂起**：模拟注册环境支持配置返回的验证链接、轮询等待间隔、过期时长及租户品牌标识，用于验证产品层的来源白名单拒绝、超时边界与中国版品牌限制（模拟对端不主动访问或跟随所配置的链接）。平台独立校验扫码注册提交的权限模板与事件订阅集合，确认其仅申请所需的细粒度发送、接收、目录与历史只读权限及 `cardkit:card:write`，既不将权限缺失误判为通过，也不要求产品申请宽泛读写权限。模拟平台支持按代次对会话目录等只读请求执行有界挂起与显式释放（释放时若无在途请求也会持久记录已释放事实，防止后续请求误等旧代次），从而验证已完成令牌准备的只读请求跨越公开配置提交时的代次隔离行为。
2. **非 GUI 协议观察入口（`bots_protocol_observe`）**：由 `pl-studio-acceptance` 中的显式示例程序 `bots_protocol_observe` 承载，通过真实 `pl-studio-server` 的公开 HTTP 与 SSE 接口驱动，不调用私有机器人模块或替换业务宿主，也不纳入常规自动化测试门禁。该入口复用工作区既有的 `eventsource-stream` 组件解码产品 SSE 主题流，不自建通用 SSE 解析器，也不以状态轮询冒充订阅主动推送（首次占用发布验证采用不自动回读的严格订阅路径，遇到缺帧即判定失败）。支持通过 `--server-binary` 显式指定已留存的本地服务端可执行文件以对比修复前后的公开行为，并在报告中如实记录二进制文件身份。观察运行持有隔离数据目录与全部子进程／异步任务，仅在全部资源真实回收后才输出最终结论，任何场景失败均传导至最外层并以非零状态码退出。
3. **测试清单注入与本地回环约束**：正式运行仅连接飞书官方端点。仅当启用调试断言（`debug_assertions`）的显式人工验收运行时，才允许读取环境变量 `ANYWORK_BOTS_FIXTURE_MANIFEST` 指向的临时版本化清单文件。该清单文件必须位于当前隔离的 `StudioHome` 内，并将 HTTP 基址、注册接口与 WebSocket 端点严格限定在同一个 `http://127.0.0.1:<动态端口>` / `ws://127.0.0.1:<同端口>` 本地回环来源下（清单中的 `baseUrl` 仅代表来源基址，禁止携带查询参数或非根路径；而端点发现返回的 WebSocket URL 允许在该来源下携带路由路径与连接票据参数）。若清单无效、不属于当前 `StudioHome`、或非调试构建收到该环境变量，系统均直接拒绝启动验收路径，绝不回落至真实飞书平台。
4. **Linux 凭据隔离与原生 GUI 模拟验收**：Linux 验收环境复用私有 D-Bus / Secret Service 会话与隔离的 `HOME` / `XDG` 目录（或进程内密钥租约），不读写操作者本机的系统凭据库；未提供等价凭据隔离机制的宿主平台明确拒绝运行该验收模式。原生 GUI 首次配置与配对验收通过显式命令 `cargo xtask manual-gui --scenario gui --bots-fixture` 启动，由验收宿主在启动真实 GUI 前注入隔离清单与合成模型环境。模拟模式支持通过标准输入（`stdin`）下发固定环境控制指令：`bots-env registration pending`、`slow-down`、`denied`、`expired`、`complete` 与 `complete-without-user`（后五项同样带 `bots-env registration ` 前缀），用于切换模拟对端后续注册轮询的合成响应；环境指令仅改变模拟对端脚本，不代替 GUI 点击、本地授权或产品保存裁决，且验收证据严格区分环境推进指令与真实产品操作。
