# 06 - 模型层

本文是厂商协议适配、账号模型目录、传输层（transport）、流式事件归一化、模型可调参数与调用计量的唯一权威源；账号、模板与持久化配置迁移见 [20](./20-config.md)。账号是具备稳定身份标识的接入实例，不等同于模型厂商或底层线协议（wire API）。

## 6.1 职责与边界

### 核心定位与职责域

`pl-model` 是模型目录、账号端点（endpoint）与模型协议适配层，负责将核心层的统一完成请求转换为具体的厂商 API 请求，并将流式响应归一化为厂商无关的模型事件与完成回执。Studio 显式构造模型适配器并注入 `pl-core` 的模型会话契约；`pl-core` 不代理账号或模型配置。`pl-model` 不维护产品层的智能体或会话历史、不解析命令行参数、也不决策产品工作流阶段；它仅维护与单个会话线程（`Thread`）同生命周期的模型会话（包含物理连接、脱敏请求指纹与 Responses 协议续接状态）。`pl-model` 可直接消费上层已解析的自定义模型列表，自身不直接读取本地配置文件。

内部职责划分为五个稳定领域：
1. **模型定义与内置目录**：描述模型元数据、能力矩阵与可调参数声明。
2. **账号、账号模板及路由配置**：管理接入实例与模板默认值。
3. **厂商协议与已解析端点**：封装协议方言、鉴权与网络传输参数。
4. **厂商无关的规范完成接口（Canonical Completion）**：统一请求、流式事件与完成响应。
5. **单模型运行时（`ModelRuntime`）**：绑定一个已解析的账号模型：模型绑定描述线协议、连接策略、请求与媒体编码、参数映射及计价规则；已解析路由将这些绑定材料与稳定的账号身份组合。序列化时可组合上述值对象，但禁止将裸模型名称直接当作账号或厂商身份。

### 流式归一化与历史推理回放

- **统一流式事件**：OpenAI Responses WebSocket、Responses HTTP/SSE、OpenAI Chat Completions、DeepSeek 及智谱/GLM 等兼容接口，在进入唯一累积器（accumulator）前必须先归一化为统一的规范事件：响应开始及 ID、正文增量、思考内容、推理概要（reasoning summary）、工具参数增量、工具就绪/完成、用量报告以及完成/失败终态。`pl-core`、Studio 时间线与外部集成方均不解析厂商原始 JSON。
- **单点类型化归一化**：同一协议族的用量字段别名、缓存明细、推理明细与工具身份只能由共享的类型化归一化器（normalizer）解析一次；SSE、WebSocket 与非流式测试解析器仅负责提取各自的外层传输信封（envelope），不得各自维护字段优先级或回退逻辑——相同的用量或工具报文无论经由哪种传输通道进入，都必须产出完全一致的规范用量与工具身份。底层事件流、解码器与累积器仅服务于单模型运行时及只读诊断投影，不作为宿主公共 API；外部宿主通过运行时的路由构造入口获取模型绑定或辅助请求客户端，执行器接收已构造的运行时及冻结的推理参数。
- **历史推理字段出站规则**：历史推理文本的出站字段严格遵循目标模型的能力声明，分别映射至 `reasoning_content` 或 `reasoning`；目标模型未声明交错推理（interleaved reasoning）能力时不发送额外推理字段。结构化的 `reasoning_details` 严禁从纯文本伪造，若缺少原始结构数据则在请求准备阶段明确拒绝，内部已保存的响应材料不会因此丢失。
- **会话请求诊断**：每个模型会话独立维护请求诊断状态，记录实际规范请求的指令、工具和上下文散列值及其变化原因。诊断世代（generation）递增不会触发厂商提示缓存键轮换；缺乏诊断数据的历史旧回执保持为未知状态。

### 工具调用身份

完成模块内部的流状态机负责生成稳定的工具调用身份。工具调用一经解码即具备必填的双重标识（条目标识 `item_id` 与调用标识 `call_id`）：
- **Responses 协议**：直接使用事件携带的 `item_id` 与 `call_id`，两者同时缺失视为协议错误。由于 Responses 可能先下发仅含上游 `item_id` 的 `output_item.added` 事件，在后续增量或完成事件中才补齐独立的 `call_id`，因此同一工具调用一旦通过任一非空标识进入累积器，后续迟到的元数据必须原地升级该累积器并归并至同一未闭合的工具调用中，严禁拆分为第二个工具调用或第二个追踪片段（trace part）。
- **Chat Completions 协议**：按分块索引（chunk index）确定性构造流内标识与 `item_id`，并令 `call_id = item_id`。系统不存在可选的 `call_id` 或将两个标识互作回退的归一化路径。
- **追踪锚点**：追踪记录的工具片段标识以最早稳定的上游条目或运行时工具 ID 为锚点，`call_id` 仅作为元数据写入工具快照，用于后续协议回放与上游工具结果匹配。

## 6.2 依赖与公开 API

`pl-model` 实现并依赖 `pl-core` 的模型会话与模型请求契约，而 `pl-core` 不依赖 `pl-model`。产品 DTO 与适配器内部消息可依赖 `pl-protocol`；`pl-trace` 仅只读消费内核观察接口，不充当模型执行门面。厂商协议适配层内部可使用 `reqwest`、`eventsource-stream`、`tokio-tungstenite` 与 `serde` 处理底层网络传输、类型化协议请求及流事件解析，但不得将这些第三方依赖类型暴露给 `pl-core`。

公开 API 按五个稳定领域模块组织：`completion`、`config`、`model`、`protocol`、`runtime`。消费方统一通过领域模块前缀访问类型；crate 根模块仅重导出基础错误类型与 `Result`，确保同一公开接口仅有一条规范导入路径。各领域模块精确重导出其公共签名中直接引用的 `pl-protocol` 类型，使消费方仅依赖 `pl-model` 即可完整命名公开签名，同时禁止与公共签名无关的成套镜像转发。

## 6.3 模型能力矩阵

模型能力声明统一采用结构化的 `capabilities` 对象，不使用位标志（bitflag）或扁平的输入模态列表：

- **基础能力**：流式输出（`streaming`）、采样温度控制（`temperature`）、推理思考（`reasoning`）、联网搜索（`web_search`）。
- **输入与输出模态**：`input` 与 `output` 集合，取值为 `text`、`image`、`audio`、`video`、`pdf`。
- **工具调用能力**：函数调用（`function_calling`）、并行工具调用（`parallel_tool_calls`）、自定义工具（`custom_tools`）、自由格式工具（`freeform_tools`）、编程式工具调用（`programmatic_tool_calling`）。
- **交错推理字段**：`interleaved.field`，当前支持 `reasoning`、`reasoning_content`、`reasoning_details`。

Studio 读取能力矩阵用于会话装配校验与界面展示：图片输入要求目标模型声明 `image` 输入能力，工具调用需匹配工具能力，推理强度配置需匹配 `reasoning` 能力；厂商私有差异封装在 `pl-model` 内，不扩散至 `pl-core`。

两项外部服务能力与模型自身能力严格解耦：
- **提示词缓存（Prompt Cache）**：不由 `model_id` 隐式推断。账号服务能力声明端点的缓存方言，模型目录声明该模型是否上报缓存写入词元（token），模型层将两者与线协议合成为穷尽的有效缓存策略。未声明缓存能力的自定义端点默认不发送任何缓存专属字段。
- **图像生成（Images）**：属于账号端点的服务能力而非对话模型能力。端点声明图像方言、生图模型标识前缀（slug prefix）与首选模型；目录中的生图模型仅作为该服务可用性的核验依据，不进入对话能力矩阵、模型路由选择器或附件输入校验（见 §6.13）。

模型协议配置归属模型绑定：传输配置声明连接方式，请求选项严格区分 Responses 与 Chat Completions。Responses 仅携带最大输出词元字段与编程式工具调用配置；Chat Completions 仅携带最大输出词元字段、并行工具开关、用量包含标志（`include_usage`）与工具流（`tool_stream`）配置。厂商原生扩展选项在具体客户端上公开，通用调用与原生调用共用同一底层执行器；参数映射与原生扩展仅在协议适配边界解析，`pl-core` 不拼接任何厂商私有字段。例如 MiMo 使用 `max_completion_tokens`，智谱按显式模型能力开启 `tool_stream` 并保留思考内容，通用兼容客户端则仅发送所选协议的标准字段。

## 6.4 厂商协议、账号与运行时

原生 OpenAI 账号的 API Key 与 ChatGPT 订阅认证遵循 [20.18](./20-config.md#2018-openai-api-与-chatgpt-订阅认证)。认证与厂商协议、Wire API、连接方式和计费意图是独立维度；订阅令牌由账号共享凭据所有者按请求解析和刷新，不建立平行模型执行路径，也不把 API 模板的全部服务能力自动授予订阅账号。

### ChatGPT 订阅的 Responses HTTP 方言

ChatGPT 订阅请求在既有协议编解码与唯一模型运行时中适配，依据已解析账号的 ChatGPT 会话能力选择方言，不按模型名称、显示名或 URL 猜测。API Key 及其他厂商的既有编码保持不变；线上限制以 [SIWC 预览限制](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations) 为依据。

- **基本形状与上下文**：HTTP 请求使用 `store: false`、`stream: true` 和数组形态的 `input`，发送本次所需完整上下文，不使用 HTTP `previous_response_id` 或服务端会话保存。受信指令仍按本产品的单一 `developer` 消息契约发送，不新增并行的顶层 `instructions` 通道。
- **流式响应媒体类型**：已验证的官方 ChatGPT 会话路由允许成功 HTTP 响应缺少 `Content-Type`，以兼容官方端点已观察到的无媒体类型 SSE 流；这是该路由的窄传输适配，不是对其他 API 或 Compatible 端点的通用回退。响应头明确存在时仍必须是 `text/event-stream`，空值、非法值或其他媒体类型均按原有有界错误路径处理。缺失头时直接复用现有 SSE framing、事件解码与终态校验，不嗅探正文选择新解析器，不把 JSON、空正文或无完整终态的流当成功，也不新增自动重试。推理成功仍须取得 `response.completed`；`response.failed`、`response.incomplete` 和断流保持原失败语义。
- **本地工具声明**：采用官方 [`additional_tools` 输入项](https://developers.openai.com/api/docs/guides/tools-tool-search#add-tools-at-a-specific-point-in-the-input)，以 `role: developer` 提供当前步骤冻结的 function/custom `ToolSpec`。该项位于受信指令之后、已有对话输入之前；相同工具计划保持声明顺序与前缀位置稳定。复用现有工具名称、参数 schema、自由格式 grammar、调用身份和调用者限制，不为订阅账号建立新工具目录、重命名工具或补造 namespace 身份。该项只是本次请求投影，不改写 canonical 历史；既有用户、助手、工具结果及不透明回放项的顺序与配对身份不变。
- **能力准入**：账号服务能力不授予此路由不支持的 hosted coordinator、Responses `tool_search`、图像生成、文件检索、Code Interpreter、原生 computer use 或 hosted MCP/connectors。自动装配只选择该账号实际支持的能力；显式请求不支持的工具、仅能由 programmatic 调用的声明或无法安全回放的原生工具项时，在网络前明确拒绝，不静默删除工具、降为 direct、切换账号或改走 API Key。普通本地工具和子代理仍由原有工具计划与调度器执行；受支持的 hosted web search 仍受模型与账号权限约束。
- **自动派生值与显式意图**：普通 Thread 不把模型目录中的输出上限自动编码成此路由不接受的 `max_output_tokens`，该元数据仍可用于本地容量判断。调用者显式提供的温度、输出上限及固定请求体、参数映射或 native options 中的禁用字段不得被静默丢弃或改写，须返回指向字段路径的配置／协议错误。既有受支持的推理强度等参数继续按声明编码。
- **最终校验**：在模型固定 body、参数 wire 与 native options 全部合并之后、请求捕获及网络之前检查最终形状。禁止字段包括 `background`、`conversation`、`max_output_tokens`、`max_tool_calls`、`metadata`、`moderation`、`multi_agent`、`prompt`、`prompt_cache_retention`、`safety_identifier`、`temperature`、`top_logprobs`、`top_p`、`truncation`、`user` 和 HTTP `previous_response_id`；字段存在但为 `null` 也不视为省略。错误的 `store`／`stream`、非数组 `input`、显式 `system` 消息、未采用本实现工具投影的声明及不支持的原生工具同样拒绝，不通过删改历史或后置覆盖掩盖冲突。
- **失败诊断**：复用现有错误读取边界与类型化失败，兼容官方直接准入的字符串 `detail` 形状；该文本只是诊断，不从文案推导稳定错误码。保持实际 HTTP 状态、请求 ID、阶段和既有重试分类，缺失值保持未知；400 不因缺少标准 `error` 对象而变成可重试错误。只允许有界且完成统一脱敏的诊断摘要进入错误消息，当前请求可知的凭据值须先剔除，不能仅依赖 API Key 前缀规则保护 OAuth token；未知形状保留安全提示，不回显原始响应体或把未捕获的历史响应补写成已知原因。

### 协议栈分工与执行器单点所有权

协议栈按「调用编排 → 厂商协议适配 → OpenAI 基础编解码（`OpenAiBase`） → 网络传输」四层分工：
- **同级封闭厂商变体**：OpenAI、DeepSeek、智谱（Zhipu）、xAI、MiMo 与自定义 OpenAI 兼容协议为同级的封闭枚举变体。各适配器通过组合方式复用 `OpenAiBase` 的 Chat Completions 与 Responses 编解码能力，同时保留各自的请求选项、目录解析规则、原生扩展能力与错误分类边界。所有请求准备、流事件解析与目录同步必须经由所选厂商适配器处理，而非仅给同一执行器套上不同名称的薄包装。
- **执行器与传输复用**：`ModelRuntime` 独占持有底层执行器与已解析的模型绑定，具体厂商客户端仅借用该执行器。同步窄协议能力使用 `enum_dispatch` 静态分派，异步生命周期仍由唯一执行器管理，不通过宏隐藏 `Future` 的 `Send` 约束。Responses 的 HTTP 与 WebSocket 模式共享请求组装与事件归一化逻辑，Chat Completions 则保留独立的线协议编解码器。HTTP JSON、SSE 与 `multipart` 上传由共享的 `reqwest` 传输层执行，重试预算、取消令牌、连接池、续接状态与最终计量均由单一所有者管理。
- **SSE 增量行扫描**：SSE 传输层按完整行向事件解析器交付数据，流式读取时仅增量扫描新到达的网络字节，避免超长 `data:` 行在每个网络分块到达时重复扫描已知前缀。LF、CRLF 与 CR 行尾语义一致，允许 UTF-8 多字节字符跨网络分块；当下游提前停止或取消时，读取器与未完成行缓冲区立即一并释放，不残留后台读取任务。
- **窄接口与类型化客户端**：统一推理入口仅负责模型生成；各厂商拥有独立的类型化客户端，动态路由返回借用共享执行器的封闭客户端视图。单模型运行时与辅助请求客户端显式提供类型化的厂商访问入口，不使用 `Any` 动态向下转型或包含所有可选操作的大而全 trait。余额查询、套餐配额与远程上下文压缩均为独立能力对象，仅在端点实际支持时暴露；使用 Responses 协议本身不代表支持远程压缩。

### 附件准备与文件输入协议

附件输入在核心层仅描述资源来源（远程 URL、Base64、共享字节块或宿主资源引用），在模型请求准备阶段才解析为具体发送形态（远程 URL、Data URL 或上传后的文件 ID）：
- **会话级上传缓存**：持久化历史仅保存资源引用与快照，上传所得的 `file_id` 作为按「端点、凭据身份、内容摘要」隔离的可重建会话缓存维护。DeepSeek 文件上传使用 `user_data` 用途与 24 小时租期；遇到用户取消或上传结果未知时严禁盲目重复发起 `POST`，仅当端点明确不支持文件上传时才允许在推理请求发出前回退至内联（inline）编码。
- **OpenAI Responses 文件输入**：采用官方 `input_file` 结构（参考[官方文件输入规范](https://developers.openai.com/api/docs/guides/file-inputs)），根据已冻结的媒体表示发送 `file_data`（附 `filename`）、`file_url` 或 `file_id`，与图片输入共享资源解析、体积限制及重放链路。内置视觉文本模型显式声明支持 PDF 与 UTF-8 文本文件，单文件及单次请求文件总大小上限均为 50 MB；未声明支持的文件类型在附件准入阶段直接拒绝，禁止将普通文档伪装成图片发送。若历史资源缺失文件名，则按明确的媒体类型补齐 `.pdf` 或 `.txt` 默认后缀。当同一账号的在线目录缓存未显式声明输入模态能力时，继承当前本地目录的模态声明及同协议缺失的媒体编码规则；若在线目录已显式声明则以在线声明为准，禁止跨账号或跨线协议借用编码规则。

### 账号身份绑定与历史载荷版本解码

- **强制稳定账号 ID**：模型绑定必须显式携带稳定的账号 ID（`account_id`），即使直接构造运行时的调用方也不得以端点名称或 URL 替代。`AccountModelKey` 的两个组成字段严格源自冻结的账号路由；实际发送的模型别名与服务端返回的模型名归属诊断维度。提示词诊断同样记录稳定账号 ID，其账号指纹由该 ID 与影响请求的端点属性合成，显示名称不参与身份计算；即使两个账号的端点 URL 相同，也不共享诊断身份。
- **生产者载荷版本边界**：模型层生成的持久化载荷在明确的版本边界内解码升级：`pl.model.assistant`（2→3）、`pl.model.failure`（1/2→3）、`pl.model.prepared-request`（1→2）以及携带冻结绑定的原生压缩载荷 `pl.model.compaction`（2→3）。升级旧版原生压缩载荷时，完整保留加密正文、兼容族标识与冻结隔离事实，仅转换归属模型层的绑定元数据，不重新发起压缩请求或从当前目录回填来源。旧版已准备请求（prepared request）中非空的提示词诊断快照同步执行该转换：账号 ID 严格取自同一回执冻结的模型绑定，不使用旧快照中的显示名称；原有诊断水位、散列值与时间戳保持不变，待下一次实际调用时再按当前指纹规则判定是否轮换，全过程不改写不透明的厂商原始输出，也无需批量激活冷历史会话。

### 工具下发与账号模板路由

`pl-core` 负责冻结每步的工具计划（`ToolPlan`）并管理权限审批、并发调度与结果提交；`pl-model` 厂商适配边界负责落实原生的函数/自定义工具、编程式调用方（programmatic caller）、托管搜索（hosted search）、思考开关与工具流优化。启用厂商原生优化不得丢失其他已注册工具，且推理内容、调用方标识、不透明上下文与工具结果的配对关系在多轮对话、自动重试与冷恢复中必须保持完整。是否启用特定优化严格取决于模型与端点的显式能力声明，不根据 `model_id` 或 URL 字符串猜测。

每个账号实例保存模板身份、端点覆盖项、凭据关联、自定义请求头、工具线协议策略、服务能力与模型目录绑定；具体使用哪个模型由角色路由（route）指定，账号自身不维护第二份默认模型。唯一有效模型目录由统一解析入口产出，每个目录成员均标记明确来源（内置默认 `bundled`、在线同步 `online`、用户手动添加 `manual`），不由外层投影或界面自行推导。

账号声明允许暂时没有模型，宿主可以保存和重载未被路由引用的空账号；声明校验成功不授予模型选择或执行资格。严格可用性校验仍拒绝空目录，新增或改变路由必须解析到该账号的真实可用模型。空目录不豁免名称、模板、模型声明及覆盖引用的其他校验，已有 Explicit 路由引用缺失模型仍为配置错误，不借用在线目录撤下后的不可用保留策略。

各内置账号模板与自定义协议约束如下：
- **OpenAI 兼容（OpenAI-compatible）自定义模型**：每个已添加的模型成员必须显式声明完整的传输配置（Chat 模型仅允许 `ChatCompletions + HTTP`；Responses 模型可声明 `Responses + HTTP` 或同时支持 `HTTP/WebSocket` 并指定默认连接模式），基础 URL、请求头、工具策略与端点能力由所属账号提供；账号创建时可以尚未添加模型。
- **智谱（Zhipu）与智谱 Coding Plan**：共用智谱协议适配器。普通智谱模板指向通用 Chat Completions 端点及通用目录；Coding Plan 模板默认指向官方 Responses 协议端点（`https://open.bigmodel.cn/api/v1`）并绑定独立的智谱 Responses 目录（含 `GLM-5.3` 与 `GLM-5.3-Flash`）。
- **MiMo**：MiMo API 与 Token Plan 为两个独立账号模板，共享同一份 MiMo 模型目录。
- **xAI**：默认指向 `https://api.x.ai/v1` 并绑定独立的 xAI Responses 目录；官方规范端点声明支持 Responses `prompt_cache_key`（用户覆盖自定义 `base_url` 后自动关闭该继承能力），不声明托管搜索、文件上传、远程压缩或 WebSocket。

## 6.5 协议与传输层（Transport）

### 协议维度与连接模式覆盖

`pl-model` 内部支持 Responses API 与 Chat Completions API 两种线协议，核心层仅消费统一绑定后的运行时、规范完成请求/响应及厂商无关的模型事件。厂商适配器、线协议与物理连接模式是三个正交维度：Responses 支持 WebSocket 或 HTTP（SSE），Chat Completions 仅支持 HTTP；线协议由模型绑定声明，厂商适配器由账号选择，因此同一账号下的不同模型可各自使用不同的线协议而不改变账号身份。

每个模型声明必填的传输档案（`transport profile`），包含协议类型（`protocol`）、支持的连接模式集合（`supported_connection_modes`）与默认连接模式（`default_connection_mode`）。账号模型目录支持按 `model_id` 保存连接模式覆盖项（`connection_overrides`）。配置保存阶段严格拦截非法组合（如 `Chat + WebSocket`、支持列表为空、默认模式不在支持列表中、或覆盖项指向未知/不支持的连接模式），校验失败返回携带 `model_id` 与涉事模态/协议上下文的类型化错误。若在线目录更新导致用户原先保存的合法选择变为不可用，系统保留该用户配置并报告外部绑定不可用，不将其判为用户数据损坏，也不静默篡改用户选择。

各厂商默认连接绑定如下：
- **OpenAI**：使用 Responses 协议，同时支持 WebSocket 与 HTTP 且默认采用 WebSocket；当切换为 HTTP 时仍调用 `/responses` 端点消费 SSE，绝不隐式降级为 Chat Completions。
- **GPT-6.1 Terra**：作为 OpenAI 目录的独立型号沿用上述 Responses 绑定，工具调用不走 Chat Completions；支持文本、图片及已声明的 PDF/文本文件输入，输出为文本。其 `effort` 候选为 `none`、`low`、`medium`、`high`、`xhigh`、`max`，独立默认值为 `medium`，不因 `none` 排在首位而改变默认推理强度。模型未预设自动压缩阈值，按 §6.7 安全输入上限推导，不继承其他型号的预设；新增目录成员不改变推荐型号或已有路由。能力与参数依据 [Terra 模型说明](https://developers.openai.com/api/docs/models/gpt-6.1-terra)及 [GPT-6 指南](https://developers.openai.com/api/docs/guides/latest-model)，价格及核验时间由内置目录维护。
- **DeepSeek / xAI / 智谱 Coding Plan**：使用 `Responses + HTTP`。
- **智谱通用目录 / MiMo**：使用 `Chat Completions + HTTP`。

### 连接生命周期与超时边界

- **Responses WebSocket 会话管理**：通过 `/responses` 端点完成 WebSocket 握手并发送固定 `store: false` 的 `response.create` 帧。物理连接与续接状态（continuation）归属当前线程的模型会话，按「模型、协议、连接模式」严格隔离；一旦发生断线、取消、流未完整消费或续接状态失效，立即丢弃旧连接，并在新连接上发送冻结的完整输入与附件。建连过程保留系统 DNS 解析、IPv4/IPv6 双栈交错竞争（Happy Eyeballs）及 15 秒握手超时上限。
- **物理连接与会话生命周期分离**：重置物理连接仅丢弃当前套接字与续接状态，不会清除该模型会话内已触发的 HTTP 粘性回退状态。若空闲连接已断开，则在发送新请求前自动重建；一旦开始发送请求即建立取消安全的连接独占责任，若发送中途被取消，严禁复用状态不明的旧连接。WebSocket 收包任务须及时响应 `Ping` 帧并维持有界消息队列，协议错误、队列满溢与网络断开均收束为可观察终态；显式关闭模型会话时，必须等待当前在用及已退役的收包任务全部退出。
- **超时与缓冲区硬上限**：
  - **响应空闲超时（Idle Timeout）**：WebSocket 为 300 秒（`Ping`/`Pong` 控制帧不重置业务空闲计时），HTTP 为 180 秒（每成功读取到响应体字节即重置计时，不要求解码出完整 SSE 事件，且不设流式请求总时长上限）。
  - **建连与首包上限**：TCP/TLS 建连上限为 15 秒；HTTP 请求发出至收到响应头上限为 180 秒；WebSocket 握手与帧发送上限各为 15 秒。
  - **缓冲与附件上限**：SSE 单行缓冲与单事件累计缓冲上限各为 64 MiB；非成功 HTTP 错误响应正文最多读取 16 KiB、总等待最多 15 秒；附件下载与上传总时限为 300 秒。
  - **取消与关闭**：用户主动取消独立于超时机制立即生效，且绝不自动重试已被用户停止的调用；会话关闭时先封闭新请求准入，再取消在途调用并等待所有调用与连接任务退出。

### 重试预算与透明恢复

每次逻辑模型请求在首次发送之外最多允许重试 **5 次**：
- **统一预算与粘性回退**：建连失败、流式传输中断、续接状态失效以及连接模式切换共用这 5 次重试预算，内部严禁嵌套重试，底层 HTTP 客户端与第三方网络库的自带重试一律关闭。瞬态故障采用带稳定抖动的有界指数退避（优先遵循服务端返回的 `Retry-After` 等等待提示），退避等待与建连过程均可随时取消。当 WebSocket 模式完整重试一次后依然失败，且当前模型明确声明支持 HTTP 时，该模型会话自动切换至 HTTP 模式并在后续请求中保持 HTTP（粘性回退）；切换操作本身计入剩余重试预算，不重置计数器。仅声明支持 WebSocket 的模型绝不发起未声明的 HTTP 请求。
- **永久错误与瞬态传输故障判别**：鉴权失败、配置错误、请求参数非法等永久性错误立即返回，不消耗重试预算。HTTP 流式请求首先按本节规则校验响应媒体类型：除上述官方 ChatGPT 会话的缺失响应头适配外，非 `text/event-stream` 的响应即使状态码为 `2xx`，也必须从有界响应体中提取厂商结构化错误并保留业务错误码与消息，未识别的非流式响应直接报告协议不匹配。在响应流建立后，底层字节流读取中断或传输层分块解码失败归类为**瞬态传输故障**（不因底层网络库报错文案含“body decode error”而误判为永久协议错误，亦不依赖英文错误文本匹配）；而完整字节交付后的 JSON 语法错误或模型事件结构错误仍归为永久协议错误。已建立响应流读取失败时，诊断记录保留实际 HTTP 版本、已接收字节数、读取耗时、清洗后的请求标识（至多 128 字节安全字符）及至多 8 层底层错误类别（仅记录已知网络库与系统 I/O 错误分类，不输出原始错误正文、URL 或鉴权头）。
- **安全重放边界与副作用保护**：普通文本、推理思考及尚未交付执行的本地工具参数在流式传输中断时，允许在剩余预算内重试同一冻结输入。若请求包含厂商托管工具（hosted tools）且已产生流事件，或服务端已下发用量报告（usage），则禁止自动重放，防止重复触发远端副作用或丢失计费事实。原生上下文压缩请求遵循同一重试预算：仅收到响应开始或模型身份元数据不代表压缩已完成，可在中断后安全重试；一旦收到压缩结果条目、用量报告或完整终态则不再重放。
- **观察代次隔离**：透明重试维持同一份已准备输入（prepared input）与核心尝试身份（core attempt），内部每次子尝试分配独立的观察代次（遵循 [16](./16-core-contracts.md) §16.3）与独立累积器。失败子尝试已输出的可见片段保留为独立展示项并封闭其流状态；重试启动时通过运行时进度项展示“连接中断，正在重试（n/5）”（仅进入界面与冷历史，不注入模型上下文）。最终仅将成功子尝试的产出交由核心层执行本地工具并推进模型上下文，前序已完成轮次的工具结果保留在冻结输入中，不重跑整轮。

### 请求组装与系统指令分发

- **可调参数通用透传**：推理强度（`effort`）等可调参数通过声明式规则写入请求体，协议层不为特定厂商硬编码字段映射。组装请求时，先将强类型核心字段（`model`、`messages`、`stream`、`tools` 等）序列化为基础 JSON 对象，再依次叠加上模型的固定请求体（`base body`，如 DeepSeek 固定注入 `thinking.type = enabled`）以及参数线协议映射（`parameter wire`，见 §6.8），覆盖优先级严格为：`parameter wire` > `base body` > 协议默认字段。
- **模型身份三元观察**：每次推理在请求体完成全部字段覆盖后冻结三项模型身份：`configuredModel`（目录中选中的 `model_id`）、`sentModel`（请求体实际发出的 `model` 字段值，缺失或空白则在发送前以协议错误拒绝）以及 `reportedModel`（服务端响应中实际声明的模型名，归一化为 `ResponseModelObserved` 事件，去除首尾空白后须非空、无控制字符且不超过 256 字节，无效或缺失则记为未知）。三项观察随成功回执、失败报告与只读诊断统一传播，各业务路径不再自行推断。
- **思考概要请求与回放**：OpenAI Responses 的 `reasoning.summary` 由推理配置的概要选项独立驱动（`Auto` 与兼容层 `Enabled` 均发送 `auto`，`Disabled` 不发送该字段）；当路由选择了非 `none` 的思考强度时，HTTP 与 WebSocket 统一同步请求 `summary: auto`。思考概要与原始思考正文分别进入各自独立的规范内容域，概要专属响应中的空 `content` 不会抹除已有概要；服务端未返回原始思考正文时保持缺失，不从词元计数或回答正文反推。Chat Completions 协议下，模型返回的 `reasoning_content` 归一化为规范推理事件，并在后续历史回放时写回助手消息的 `reasoning_content` 字段。
- **受信系统指令（`SystemPrompt`）角色映射**：完成请求通过类型化的 `SystemPrompt` 表达厂商无关的受信指令正文，调用方不直接指定线协议角色（role）。Studio 预先组合基础指令、智能体角色指令与其他受信规则，`pl-core` 冻结该指令记录，最终由 `pl-model` 的厂商协议适配器按明确协议契约决定发送角色（参考 [OpenAI Responses 规范](https://developers.openai.com/api/reference/resources/responses/methods/create)与 [DeepSeek Responses 规范](https://api-docs.deepseek.com/guides/responses_api/)，后者将 `developer` 视为普通用户角色）：
  - OpenAI Responses 及其他标准 Responses 适配器使用 `developer` 角色；
  - DeepSeek Responses 与所有 Chat Completions 适配器使用 `system` 角色。
  基础指令不再通过独立的顶层 `instructions` 字段与历史消息双轨发送；若固定请求体或参数映射试图重新注入顶层 `instructions`，在请求准备阶段直接报错拒绝。
- **工具规格（`ToolSpec`）与延迟暴露（Deferred Reveal）**：每个模型步骤携带当前工具计划中全部可见工具的 `ToolSpec`（厂商无关的唯一线协议事实）。`pl-core` 保存不透明工具声明与稳定工具 ID，在每步开始时冻结声明与执行租约；`pl-model` 仅负责将其编码为厂商请求体并还原助手调用的工具名与原始参数，不自行发现、过滤或注入智能体工具。厂商托管工具仅在 `pl-model` 内部配置，不向 `pl-core` 注册占位执行器。延迟暴露工具由线程保存稳定的声明身份，重连不改写模型可见前缀，历史调用保留当时的完整参数与名称，后续请求编码不会按当前工具目录篡改历史记录。容量预览与正式推理调用共享完全相同的可见工具计划与独占调度约束。
- **工具调用解析拒绝**：助手工具名与本地稳定工具 ID 分属不同身份空间，仅允许通过本次冻结声明精确解析。未知名称和已知工具的参数转换失败分别向内核提供类型化拒绝事实，保存原始工具名、调用 ID、原始参数与转换原因，不将未知名称用作执行身份，不将转换错误吞并为未知工具。内核统一负责整批拒绝与有限纠正（见 [16](./16-core-contracts.md) §16.3）；模型适配层不另行重试。纠正请求从已提交上下文重建并提供当前有效工具声明，被拒绝响应的协议回放材料与私有续接状态不参与后续请求，正常工具结果继续按原供应商调用身份配对。

## 6.6 多模态消息

### 持久化形态与模型媒体能力校验

消息内容统一采用有序的多部分（`parts`）列表形态，持久化协议仅允许**文本部分**与**附件引用部分（`attachment_id + modality`）**，其中 `modality` 取值为 `image`、`video` 或 `file`（PDF 归入 `file`）。持久化消息严禁直接存储本机文件路径、外部 URL、原始 Base64、账号 `file_id` 或请求期临时 Data URL。

模型输入能力显式声明支持的模态、允许的来源与文件格式、最大数量、单项字节上限、单批总字节上限及图像宽高限制；模型请求档案（request profile）为每种模态声明有序的发送表示方式（枚举值：远程 URL、账号上传文件 `account file`、内联 `data URL`）及线协议映射规则。每个受支持的模态必须至少具备一条首发可用路线和一条基于持久化快照的重放路线；未知模型或缺少完整请求档案的模态一律视为不支持。

在模型路由变更或新输入受理前，系统按目标模型能力校验当前上下文及待消费输入中的所有留存媒体；请求准备阶段复用同一校验逻辑，并通过资源访问端口将附件引用物化（materialize）为已校验字节、瞬时 URL 或已上传的 `file_id`。同一模态批次采用同一种发送表示；若账号文件上传失败，仅允许在推理请求发出前整批切换至下一候选表示路线，流式请求一旦建立便不再自动重发。

### 工具读取图像与 MCP 媒体归档

智能体通过直接可见的 `view_image` 工具主动读取工作区图像（无需先经由 `discover_tools` 探测），本地与 SSH 远程工作区共用同一套工具声明、图像归一化与媒体归档流程。对于 MCP 工具返回的类型化图像内容（image content），仅当调用该工具的当前模型声明支持图像输入、具备完整快照重放档案且当前线程已挂载附件运行时，才进入相同的媒体归档通道；否则仅生成有界诊断文本，不持久化为仅供界面展示的孤立附件。MCP 图像在持久化前必须通过编码长度检查、严格 Base64 解码、声明 MIME 与真实文件魔数（magic bytes）比对以及尺寸上限校验；单次 MCP 结果中任一图像校验或写入失败则整批不发布，工具结果、追踪日志与 SQLite 库均不保存原始 Base64 字符串。

工具成功读取图像后，先以常规的类型化工具结果闭合该次工具调用；待同一批次的全部工具调用闭合后，`pl-core` 再按调用顺序追加一条**工具媒体上下文条目**（仅保存 `call_id`、安全展示标签与归属当前线程的附件元数据）。该条目不属于用户消息，不进入用户时间线；Responses 与 Chat Completions 适配器均将其投影为一条内部的多部分用户消息（按“标签文本 → 图像内容”顺序排列），从而保证 Chat 协议下并行工具消息（tool messages）的连续性。图像字节在请求准备期由宿主附件加载器从归档存储物化，同轮次后续推理、失败重试与冷恢复均不再读取原始工作区文件路径。

### 各厂商图像传输路线

- **OpenAI**：Responses 协议使用 `input_image`，Chat Completions 协议使用 `image_url`。
- **智谱（GLM-5.3-Flash）**：当前声明支持 `text` 与 `image`。通用 Chat API 下远程图片首发优先使用 URL，本地图片及历史重放统一使用 Data URL；Coding Plan 的 Responses 端点则使用 `input_image`。
- **DeepSeek（DeepSeek V4.1 Flash）**：声明支持 `text` 与 `image`，通过 Responses `input_image` 发送。首发优先级依次为「账号文件上传（`file_id`） → 远程 URL → Data URL」，历史重放优先级为「账号文件上传 → Data URL」。受支持的快照格式固定为 JPEG、PNG、GIF、WebP；针对官方对图片数量与边长的分档限制，规范档案统一采用全批次通用的 4096 像素最大边长与 32 MiB 单批快照总字节上限，确保转换为 Data URL 重放时不会突破接口的 48 MiB 请求体上限。

## 6.7 模型目录、启用资格与远程压缩

### 复合模型身份与在线目录合成

产品宿主负责读取并校验本地配置文件，解析出完整的模型路由后再交由 `pl-model` 构造运行时；`pl-core` 与 `pl-model` 均不直接读取 `~/.anywork/config.toml`。可调用模型统一使用 `AccountModelKey(account_id, model_id)` 复合身份，其中 `model_id`（JSON 协议字段为 `modelId`）按原始字符串大小写敏感精确匹配。内置只读模型定义可被多个账号模板引用，但在线目录观察、用户覆盖项、显示名称、上下文预算、模态能力、可调参数候选及默认值、凭据、传输方式与价格均严格限制在各自账号内部解析，绝不跨账号借用或覆盖。

每个账号的唯一有效目录由 `pl-model` 的统一合成入口产出，合并优先级如下：
1. **用户手动附加模型（`manual`）**：通过 `additional_models` 配置，享有最高优先级；当与在线名单或内置目录同名时，手动条目优先，在线同名条目不进入有效目录。
2. **在线发现目录（`online`）与内置定义（`bundled`）**：按「本次在线探测成功 → 同一查询身份最近一次成功缓存 → 从未成功时回退内置默认定义」的顺序选择在线观察。每次成功的在线名单整体替换上一份 API 名单，不累加历史已下线的在线独有模型；管理目录始终保留账号绑定的内置定义，在线名单缺失的内置项以 `bundled` 来源展示，但不因此自动获得选择资格。成功空名单同样构成有效观察。在线声明仅进入内存覆盖层（overlay），不写回用户的 `additional_models` 配置。
3. **字段级合并规则**：在同一账号内，在线明确声明的字段优先于本地配置与内置定义；缺失字段继承本地定义，而显式的 `false`、空集合或可空字段的 `null` 均视为有效在线声明。HTTP `304 Not Modified` 仅刷新检查时间戳。当目录归一化规则升级时，旧缓存的实体标签（ETag）自动失效并重新拉取完整报文。

`Explicit` 目录只包含用户声明的成员，允许为空；空目录不获得在线发现能力，不回退到内置或其他账号的模型，也不提供可选候选。该状态与在线发现得到的成功空名单分别保留各自来源语义。

展示名称按「已有手动模型定义的名称 → 在线名称 → 同账号内置名称 → 原始 `model_id`」解析。手动定义复用现有 `additional_models` 或显式模型定义的 `display_name`，不新增独立的内置或在线模型改名设置；在线名称不能覆盖已有手动名称。没有手动名称时，在线 `display_name` 或其协议别名明确提供的非空白值优先，即使该值恰好等于原始 `model_id` 也原样展示；仅在在线未提供名称、为空或仅含空白时回退内置名称。字段是否由在线明确声明与解码器的默认名称须区分，不能仅凭名称与 ID 相同判定缺失。不改变有效名称的大小写、空格或标点，不根据模型 ID 猜测命名，也不得从其他账号补齐名称。此规则同时适用于新发现与既有成功缓存，直接账号查询和规范目录重建须保持一致；不重写在线观察、用户配置、路由或历史快照，模型身份与其他字段的合成规则不受影响。

在线发现请求直接调用账号端点下的 `/models` 路径（保留自定义反向代理路径前缀、查询参数与鉴权头），单次请求总超时为 10 秒、响应体上限为 4 MiB，禁止自动重试与重定向。各厂商协议各自解析返回报文（OpenAI 解析标准 `data/id` 及 Codex 富声明 `models/slug`；DeepSeek 解析 `data/id`、推理强度与显式能力；xAI 解析 `data/id`、`context_length`、原生能力与计价单位；智谱通用 API 与 Coding Plan 在未声明公开列表接口时直接使用内置目录）。在线成员在发现与缓存阶段不按模型家族、模态或工具能力预先裁剪，生图、向量嵌入、语音等非对话模型完整保留在有效目录中，作为端点服务能力的核验依据。

### 模型启用状态与统一选择资格

账号配置通过 `model_enabled_overrides` 保存按精确 `model_id` 标识的显式启用意图：`true` 表示明确开启，`false` 表示明确关闭，缺项表示自动。自动规则由模型层统一解析：手动成员与当前在线成员默认开启；从未取得成功在线观察时内置成员默认开启；存在成功在线观察（包括最后成功缓存与空名单）时，线上缺失的内置成员默认关闭。管理目录的 `enabled` 是上述规则与账号覆盖合成后的权威结果，界面不自行猜测默认值。

用户可在配置列表中显式开启线上缺失的内置项，使用当前内置定义进入正常选择与路由解析；不修改在线观察、不转换成手动模型，也不将上游是否列出它等同于实际调用是否受支持。显式开关在来源变为 `online` 或 `bundled`、重启及模型重新出现后继续生效；覆盖本身不能创建未知成员，也不能保留已撤下的在线独有模型。内置成员的只读资料可供配置页查看，与选择资格独立。

对话模型的选择资格由**文本类型过滤**与**用户启用状态**先后叠加决定：
1. 首先筛选最终合并结果同时支持文本输入（`text` input）与文本输出（`text` output）、且已解析上下文容量为正整数的模型；
2. 再排除 `enabled == false` 的被禁用模型。

会话路由、智能体预设与自动子智能体派发共用该资格入口。禁用某个模型不会中断已在途的请求，但后续新轮次、冷恢复激活与子智能体派发将在准入边界拒绝使用该模型，并保留用户的原始配置选择（标记为不可用状态，不自动替换为其他模型）。

### 选模参考资料与账号计费类别

- **只读选模资料**：模型目录可附带与协议能力及系统提示词分离的只读参考资料（包含简短定位、适用任务、局限性，以及来自官方文档、独立基准测试或社区反馈的出处、核验日期与测量条件）。内置参考资料严格绑定具体目录型号，不按名称模糊匹配，也不作为系统提示词发送给模型。带有数值分数的基准测试必须同时注明非空的评测集版本与推理强度档位，不将不同口径拼凑为综合总分。
- **账号计费类别（`billing_kind`）**：取值为按量计费（`metered`）、订阅制（`subscription`）、不计费（`noCharge`）与未知（`unknown`），是账号计费意图的唯一事实源。当用户配置省略该字段时，仅在账号模板与官方规范端点完全匹配时自动推导，自定义端点地址默认保持为 `unknown`；用户的显式选择始终优先。仅当生效类别为显式 `noCharge` 时，后续调用才按零费用记账（但仍完整保留词元用量与性能统计）；模型目录中的参考单价仍按规范计价定义展示，用于跨模型资源成本横向对比，不因订阅制或不计费而隐藏或清零。

### 上下文窗口、自动压缩阈值与远程压缩

模型的上下文容量以 `context_window` 为准，缺失时回退至 `max_context_window`（严禁以更大的最大容量覆盖当前有效窗口）。自动压缩阈值（`auto_compact_limit`）的解析规则如下：
- **安全输入上限**：取「有效上下文容量的 90%（向下取整）」与「有效上下文容量减去模型声明的最大输出词元数」两者的较小值（若未声明最大输出词元数，则仅取 90%）。
- **默认与用户覆盖**：默认阈值优先取模型显式声明的 `auto_compact_token_limit`，未声明时取上述安全输入上限（不再使用硬编码的固定词元数兜底；内置 `GPT-6.1 Sol` 的 475,000 词元为产品目录预设）。用户可按 `(account_id, model_id)` 配置自定义阈值覆盖默认值，最终生效阈值取「所选阈值」与「安全输入上限」的较小值。若模型上下文容量未知或计算出的安全输入上限非正，则不启用本地阈值压缩。
- **请求期冻结**：每次模型调用在请求准备阶段将已解析的 `context_window`、`max_context_window` 与 `auto_compact_limit` 一并冻结到请求及结果回执中，历史记录解码时若缺失这些可选字段则保持为未知，绝不读取当前目录或当前配置回填历史。
- **远程压缩能力**：完成请求输入支持携带含 `encryptedContent` 的专用压缩条目（`Compaction`），该条目可映射为 Responses 原生输入，而在 Chat Completions 协议下会被明确拒绝。端点是否支持远程压缩须显式声明，执行时复用共享执行器并固定走 HTTP 通道。

## 6.8 模型可调参数（推理强度机制）

推理强度（`effort`）并非全局固定的静态枚举，而是由模型自身声明的可调参数（通用参数机制的首个应用，同一结构可扩展至 `thinking`、`verbosity` 等参数）。模型目录独占维护参数的候选值域、显示名称、默认候选值以及线协议写入规则表（`wire` 规则），角色路由仅保存当前选中的候选值：

- **声明结构与选择优先级**：每个参数声明包含参数名（如 `effort`）、可选显示名、有序候选值列表、可选默认候选值以及按候选值索引的静态写入规则表。生效候选值的选择优先级依次为：有效的用户显式选择 > 配置默认值 > 模型声明默认值 > 候选列表首项。若模型未声明 `effort` 参数，则角色路由中的对应选择必须为空，最终请求体亦不注入任何默认推理字段。
- **点分路径写入与移除规则**：每条写入规则由 `set` 列表（形如 `reasoning.effort`、`thinking.type` 的嵌套点分路径及目标字符串值）和 `remove` 列表（待移除的点分路径）组成。组装请求体时按点分路径逐层写入或移除 JSON 字段，移除不存在的字段时静默忽略。

各厂商协议的 `effort` 线协议映射规则如下（本文为唯一权威源）：

| 厂商协议 / 模型系列 | 候选值域（`candidates`） | 字段写入规则（`set`） | 字段移除规则（`remove`） |
| --- | --- | --- | --- |
| OpenAI | 模型有效声明的候选集（内置源自 `model.json`，在线源自 API） | `reasoning.effort` = 选中值 | — |
| DeepSeek | 模型有效声明的候选集（内置源自 `model.json`，在线源自 API） | `reasoning_effort` = 选中值（存在 `effort` 时固定注入 `thinking.type = enabled` 作为基础请求体） | — |
| 智谱通用模型 | `none` / `enabled` | `thinking.type` = 选中值 | — |
| `GLM-5.2` | `none` / `high` / `max` | `high` / `max`：设置 `reasoning_effort` + `thinking.type = enabled` + `thinking.clear_thinking = false`；`none`：设置 `thinking.type = disabled` | `none` 时移除 `reasoning_effort` |
| `GLM-5.3` / `GLM-5.3-Flash`（通用 Chat API） | `low` / `high` / `max` | 三档均设置 `reasoning_effort` + `thinking.type = enabled` + `thinking.clear_thinking = false` | — |
| `GLM-5.3` / `GLM-5.3-Flash`（Coding Plan Responses） | `low` / `high` / `max` | `reasoning.effort` = 选中值 | — |
| MiMo | `disabled` / `enabled` | `thinking.type` = 选中值 | — |

内置模型的候选值按思考强度从弱到强排列，在线发现的候选集保持服务端返回的原始顺序。内部摘要类辅助请求（如会话自动生成标题）复用探索智能体（`explorer`）路由所绑定的模型，并固定选取该模型候选列表的首项（最轻量档位）。

## 6.9 模型家族预设与完整助手回放

### 模型家族预设

同一厂商旗下的模型通常共享能力矩阵、截断策略、可调参数声明与基础请求体。保留在 Rust 源码中的内置目录使用模型家族（`ModelFamily`）预设封装共性配置，具体型号仅声明差异字段（如 MiMo、智谱文本及视觉系列、智谱 Coding Plan Responses 系列）；OpenAI 与 DeepSeek 的内置默认定义则直接以统一模型声明数据文件发布。模型计价（`ModelPricing`）独立于模型家族定义。

### 完整助手回放（Assistant Replay）

模型完成响应中的回放数据（`AssistantReplay`，挂载于 `CompletionResponse.replay`）是独立于最终回答正文与界面展示投影的冻结事实：
- **协议保真**：Responses 协议按原始 `output` 顺序完整保留消息、阶段标识（`phase`）、推理项、工具调用身份及参数原文；Chat Completions 协议保留可见标签解析前的完整助手正文（其完成态展示项由同一标签解码器从完整回放派生，区分 `commentary` 与 `final` 通道，但展示层段落身份不反写回模型回放）。
- **单点提交流转**：仅成功完成的子尝试在通过校验后随线程上下文提交至内存，供后续常规请求、摘要生成、原生压缩与输入容量估算直接消费；失败、取消或被拒的候选输出不进入已提交历史。Responses 的 HTTP 与 WebSocket 模式共用同一套原生历史转换逻辑；仅当「上次完整请求输入 + 已提交完整原生输出」恰好构成当前请求输入的精确前缀时，WebSocket 才启用增量续接（设置 `previous_response_id`），其余情况一律发送完整冻结上下文。
- **跨模型与跨账号隔离校验**：线程保存的响应帧同时记录产生该原生回放的账号隔离身份（由 `account_id` 与端点连接参数派生的命名空间）及原生上下文兼容族标识。下一轮出站投影时，仅当来源账号、隔离命名空间、协议适配器、线协议及模型完全一致，或跨模型双方显式声明了相同的非空兼容族时，才逐字回放加密推理项（`encrypted_content`）；若无法证明兼容性，则仅从出站 `input` 中剥离该加密推理项，助手文本、工具调用身份、工具输出及其他原生事实保持不变。

## 6.10 提示词缓存（Prompt Cache）

### 稳定指令前缀与工作上下文追加

- **稳定指令前缀**：由统一组装的基础指令、智能体角色指令、工作模式指令、平台与全局受信规则以及稳定的技能目录共同构成。工作区与项目文档（如 `AGENTS.md`）保持捕获时的用户/运行时事实归属，不会因为参与前缀复用而提升为系统级受信指令；每轮激活的技能与推荐信息写入当轮规范上下文，不插入历史记录之前的固定前缀。
- **隐藏工作上下文快照**：模型可见的工作上下文（working context）在内容发生变化时，以隐藏的用户角色（`user-role`）运行事实快照形式追加到对话历史末尾；内容未变化时不重复追加，内容清空时追加显式失效声明。同一轮次内的多次状态更新同样采用只追加（append-only）策略，不原地篡改模型此前已观察到的历史记录，从而保护服务端前缀缓存命中率。上下文压缩时先移除旧的工作上下文快照，再将最新状态注入压缩后的新窗口。证据账本（Evidence Ledger）与会话笔记的完整正文不进入模型上下文。
- **工具计划线协议指纹**：工具定义由每步冻结的工具计划提供，其与缓存的关联仅通过工具计划的线协议指纹（wire fingerprint）表达——即将实际发送的全部工具规格按模型可见名称排序，并对 JSON Schema 递归采用确定性字段顺序后计算的规范散列值；注册表修订号、分组标识或内部执行器代次均不参与散列。DeepSeek 依赖服务端隐式共同前缀匹配，不发送 `prompt_cache_key` 或断点标记；支持显式会话级缓存键的厂商可透传宿主提供的稳定键，但该键仅作路由提示，不能替代请求前缀字节级一致。

### 上下文压缩与超窗恢复

系统在每次采样前估算完整物化请求的词元数：当达到当前模型路由的生效压缩阈值（`auto_compact_limit`），或服务端上次返回的实际词元用量已达阈值时，触发版本化的上下文替换（Compaction Replacement），随后将当前工作上下文重新注入新窗口。压缩过程严格保持工具调用与工具结果的配对完整性以及当前用户任务描述。

若服务端明确返回上下文超限错误，模型适配器保留原始错误并将其归类为 `ContextLimit`；当前执行轮次可在剩余步数预算内执行一次强制压缩，并以新的请求尝试（attempt）继续执行。若压缩后上下文未缩短、再次触发超限、用户取消或压缩调用自身失败，则轮次明确终止，不重复消费用户输入或重跑已完成的工具。当历史记录包含原生 Responses 专属材料（如加密检查点）而当前路由切换至 Chat Completions 模型时，容量估算与请求准备统一以 `IncompatibleContext` 拒绝。

### 6.10.1 上下文准备与指令修订

- **冻结预览与最近工具批次保留**：输入容量检查基于包含本步待消费输入的冻结预览执行，而压缩仅替换已提交的历史记录（准备期间新到达的消息留待下一步处理）。压缩结果在生成摘要的同时，完整保留本轮最近一次工具调用批次及其执行结果、当前用户任务与显式派发输入，使模型可直接依据刚获取的执行证据继续推理，无需为核实摘要而重复调用查询工具。
- **指令更新策略（前缀替换与历史追加）**：有效系统指令的发送角色与更新方式由已解析的协议分发策略决定。仅当目标模型明确声明支持完整快照历史覆盖（如 DeepSeek Anthropic Messages API 的 `in-history` 能力，归属 `api_capabilities.anthropic_messages`）且端点接受当前发送角色时，才在历史中追加携带修订号、内容散列与替代关系的指令快照；当前 DeepSeek Responses/HTTP 绑定及未知能力模型默认采用**前缀替换**策略，即在指令变化时直接更新首部系统指令，不保留已废止的旧版权限、角色或模式规则。宿主将最后投影的路由身份与指令更新策略保存在会话扩展中，在候选准备提交时一并原子更新。
- **启发式容量估算与实测下界**：当上下文中包含无法在本地按纯文本分词估算的原生加密材料或媒体时，模型层先调用内核的前缀与工具计划校验并核对来源绑定，将该路由最近一次服务端实测的输入与输出词元数作为**实测下界**，再叠加新增的可估算文本。完整文本估算值、有效实测下界与未知状态分别明确标记：实测下界可用于触发自动压缩，但不能作为“完整请求必定未超窗”的保证。

## 6.11 联网搜索（Web Search）与账号边界

联网搜索支持多后端并存，三条路径彼此独立且可同时装配：
1. **OpenAI 独立搜索接口（`/alpha/search`）**：向支持函数调用的模型暴露 `web_search` 工具。
2. **DeepSeek 官方搜索与抓取工具接口**：向支持函数调用的模型暴露 `deepseek_web_search`（支持 1–4 个查询词并发扇出、按位次轮询合并与 URL 首现去重）与 `deepseek_web_fetch`（抓取单页正文）。
3. **Responses 协议托管搜索（Hosted Search）**：通过携带方言声明的 `WebSearch` 工具规格下发（OpenAI 方言支持外部/索引访问模式、上下文大小、域名白名单与近似地理位置；DeepSeek 方言严格仅序列化 `{"type":"web_search"}`，不附加未承诺的过滤或位置字段）。托管搜索可与独立搜索工具、普通函数、MCP、LSP 及文件命令工具同批共存。

此外，通用 MCP 搜索服务（含智谱 MCP）作为独立的附加工具接入，不因上述三条内置搜索路径可用而被隐藏。

### 独立搜索服务规划与 DeepSeek 工具客户端契约

独立搜索服务的可用性由设置页的服务规划器（service planner）仅依据账号服务能力声明与凭据可用性独立解析，不受当前会话所选对话模型的影响：OpenAI 独立搜索优先选取该账号目录下的 `gpt-6-sol`（缺失则取首个有效模型），DeepSeek 独立搜索直接调用原生工具端点。

DeepSeek 搜索与抓取客户端位于公开模块 `pl_model::protocol::deepseek::tools`：
- **端点构造与请求规范**：基于账号 `base_url` 移除末尾 `/` 及单层 `/v1` 后，分别拼接 `/v1/tools/search` 与 `/v1/tools/fetch`（若地址指向 `/anthropic` 兼容端点则直接报配置错误；覆盖非官方规范 `base_url` 时默认撤销继承的 `DeepSeekToolsApi` 能力，须显式声明方可启用）。请求仅发送 `Authorization: Bearer <key>`，不跟随重定向、不自动重试，默认整体超时 60 秒、默认单次返回上限 `count = 10`（允许范围 `1..=50`），固定 `need_content = false`。发起请求前严格校验查询词非空且不超过 128 个 Unicode 字符、抓取 URL 非空且不超过 8192 字符并含有效主机名。
- **响应解析与无损取证**：严格校验 `results` 数组结构，将 `date` 映射为 `published_at` 并按 `url` 首现去重。已完整接收的响应正文一律通过 `ToolsError::observed_response()` 留存进不透明历史载荷（若非合法 JSON 或非 UTF-8 字节则以 Base64 封装保留），对外错误消息截断至 512 字符以内且严禁包含凭据。`pl-tool` 层对搜索与抓取结果统一应用 12,000 字节的模型可见输出预算截断。

### 托管搜索回放

DeepSeek 与 OpenAI 的 `/responses` 端点返回的 `web_search_call` 共用同一套规范 SSE 解码器、时间线展示与原生历史回放链路：将完整的原生条目（含未知扩展字段与不透明结果）随响应帧持久化，并在下一轮出站请求中剥离仅属输出期的 `status` 字段后按原序投射回 `input`。

## 6.12 计量与价格

### 单次调用计量与吞吐速度口径（TPS / TTFT）

单次模型调用的规范计量结果（`InferenceAccounting`）包含服务端用量报告、完整性标志、计价状态与冻结的价格快照。无论调用成功、失败、截断或取消，均保留已收到的服务端用量（Chat Completions 必须消费末尾独立的 `usage` 数据块后方能终结），未收到报告则保持为未知。

客户端性能指标严格定义如下：
- **总响应耗时**：从产生最终结果的传输尝试（transport attempt）发出请求开始，至收到归一化终止事件为止；取消、空闲超时、直接传输错误或缺少终止事件的 EOF，则在执行器实际观察到该 attempt 结束的边界冻结终点。已收到终止事件时不改写原终点（透明重试的每次子尝试独立使用单调时钟计时，不混入失败尝试、退避等待或工具执行耗时；终态后的展示与落盘开销不计入）。
- **首内容延迟（TTFT）**：从同一传输尝试起点至客户端首次观察到非空文本、推理或工具参数内容为止。首次通过完整工具参数完成项交付的内容也构成观测，但必须区分增量观测、完整工具项观测与历史来源未知，不能冒充供应商生成首 token 的时刻。元数据、空增量、工具名称与无内容终态不构成观测；重复完成项不重置首内容边界。终态补齐首次交付工具内容时，观测可与总响应结束重合。首内容后耗时由 `总响应耗时 - TTFT` 派生，仅作诊断展示，不作为吞吐率分母；没有内容边界时保持未知。
- **平均输出吞吐率（TPS）**：仅采用服务端上报的输出词元数（含未逐词元流式下发的内部推理词元，不重复累加，亦不用输入词元或字符/字节数估算），表示**包含首字等待在内的客户端实测平均输出吞吐率**（参考 [sub2api 的含首字等待输出速率定义](https://github.com/Wei-Shaw/sub2api/blob/8f2cbb53d9d1c40e1865b07ac460571f7d4c48de/frontend/src/utils/latencyHealth.ts#L79-L91)）：
  $$\text{TPS} = \frac{\text{输出词元数} \times 1000}{\text{总响应毫秒数}}$$
  多样本聚合吞吐率必须使用成对加权公式 $\frac{\sum \text{输出词元数} \times 1000}{\sum \text{总响应毫秒数}}$，禁止对单次速率做算术平均或单侧累加。平均 TTFT 仅在已知首字延迟的有效样本上独立求均值。

主推理、标题和压缩共用模型执行器产生的计量事实，辅助结果转换不得丢弃已测得的计时，也不得在产品层重新包围投影或保存过程计时。成功、失败、取消、拒绝与中断保留真实终态及已收到的用量；原始报告中的总量不能被推导值覆盖，只有缺少总量时才允许另行派生。通用用量分析与累计边界见 [16.7](./16-core-contracts.md#167-用量计量与调用回执)，持久化与来源诊断见 [15](./15-session-storage.md)。

`InferenceTiming.firstOutputSource` 明确区分 `incremental`、`completedToolInput`、`unobserved` 与 `legacyUnknown`。来源与首内容时刻作为同一观测保存；宿主只透传执行器测量，不根据响应内容、调用 ID 或历史耗时补造来源。完成项首内容观测与终态重合时允许首内容后耗时为零。

### 本地费用估算与历史账单不可变性

模型计价定义（`ModelPricing`）声明币种、输入/输出长度分档费率及可选的每周时段倍率（如 OpenAI 的普通输入、缓存读取与缓存写入互斥计费，DeepSeek 按输入缓存命中与未命中计费）。每次调用在启动时冻结当前价表与账号计费策略（`billing_kind`），按产生最终结果的请求发送时刻匹配时段，按最终总用量匹配长度分档（跨时段不拆分词元）。

计量结果明确区分「显式不计费（`noCharge`）」「价格或用量不足（未计价）」「已估算费用」与「估算为零费用」四种状态。所有已持久化的历史记录直接读取调用时冻结的账单快照（绑定 `(account_id, model_id)` 复合身份，并以推理强度 `effort` 作为二级细分维度），后续模型下线、目录来源切换或单价调整均不会触发历史账单重算。会话自动生成标题等无独立上下文的内部辅助推理，其冻结账单归入所属根线程的内部账单并随累计费用一并原子提交，但不覆盖主会话的上下文窗口用量。

## 6.13 图像生成协议边界

图像生成属于账号端点的外部服务能力，由目录声明图像协议方言、生图模型标识前缀（slug prefix）与首选模型。生图工具的注册可用性由三项条件共同决定：**目录声明了该服务能力**、**当前在线观察名单中存在匹配前缀的生图模型**、且**账号凭据可正常解析**；任一条件不满足时不向模型注册生图工具，观察名单或凭据更新后通过热目录刷新动态重规划（见 [09](./09-tool-runtime.md)）。

后端模型选择按账号稳定顺序执行：若在线名单中存在声明的首选模型则直接锁定，否则解析模型标识前缀后的语义化版本号 `N[.M[.P]]` 择优录取（高版本优先 → 无变体后缀优先 → 字典序）。请求直接发送至账号 `base_url` 拼接方言路径，仅携带提示词、模型名与可选背景模式（尺寸、质量、张数交由服务端默认处理），且只接受内联 Base64 图像响应。

图像生成作为线程后台任务运行：调用受理后立即返回运行中回执，生成完毕后将图像经由工具媒体归档写入资源库与时间线，并通过邮箱在后续轮次准入时交付终态结果。配套的**图像展示工具**仅从当前冻结上下文已有的类型化附件或 `image/*` 资源引用中提取已归档图片，生成带说明文案的独立时间线卡片（这是唯一不依赖当前对话模型具备图像输入能力的界面图片附件来源）。
