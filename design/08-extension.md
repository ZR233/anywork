# 08 - 扩展点索引

系统的扩展机制优先遵循**数据驱动**原则：新增能力应尽量表达为目录（catalog）、模板（template）或结构化配置数据，而非堆叠新的硬编码代码分支，且严禁根据名称或地址猜测厂商能力。各扩展方向的完整契约见对应专篇，本文仅汇总扩展入口与职责边界。

| 扩展方向 | 职责与边界摘要 | 权威专篇 |
| --- | --- | --- |
| 账号与厂商协议 | 账号模板提供创建期默认值；同级厂商协议适配器通过组合方式复用 `OpenAiBase` 的 Chat Completions 与 Responses 编解码能力，同时保留各自的原生扩展特性与目录解析逻辑。模型能力声明与账号覆盖项由数据驱动；单实例的在线目录成功缓存由 Studio 管理，不反写回用户的期望（desired）配置文件。 | [06](./06-model.md)、[20](./20-config.md) |
| 普通技能（Skill） | 按目录优先级扫描发现，由 `skills_list` / `skill_view` 工具按需加载；前置元数据（YAML frontmatter）与 Markdown 正文由 `pl-skill-core` 统一解析，非法技能资源仅产生自身诊断告警；普通技能禁止使用保留的 `mode.` 前缀。 | [10](./10-skills.md) |
| 工作模式（Thread Mode） | 采用显式注册制扩展，不复用技能、账号或文件系统发现目录。内置模式 `mode.simple` 与 `mode.task` 随二进制分发；外部文件加载器将配置转换为相同的所有权结构后按来源原子注册（不同来源禁止注册同一 ID，内置 ID 不可覆盖）。注册输入可携带预设工作流状态图，运行时在发布目录快照前完成静态图编译；模型仅能通过拆分的查询与转换工具读取和推进状态图。 | [11](./11-thread-mode.md) |
| 智能体定义与预设（Profile） | 所有根智能体（`root`）与子智能体（`child`）共用同一声明模型；内置定义由编译期代码声明表与 `include_str!` 提示词提供，产品入口绑定可信身份。仅子智能体向用户开放 TOML 配置与任务派发，派发目录即统一定义下的可派发视图。新增角色无需修改框架角色枚举或添加快照特判；系统子智能体的专属路由默认继承全局默认模型。协作派发工具仅接受 `profileId`，不开放任意临时系统提示词注入入口。 | [12](./12-collaboration.md)、[20](./20-config.md) |
| 工具（Tool） | 新增带持久化状态的工具须采用强类型参数与返回值、稳定错误码、显式比较并交换（CAS）及操作幂等标识（operation identity），在工作状态克隆副本上完成计算后随线程检查点原子提交；批处理调度策略显式声明为共存（`Coexist`）或独占（`Solo`）。业务工具严禁绕过线程所有者写入第二套事实源。 | [09](./09-tool-runtime.md) |
