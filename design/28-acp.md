# 28 - ACP 接入、服务器准备与认证

本文定义外部 Agent 的 ACP 接入与认证边界。crate 职责以 [02](./02-crates.md) 为准，配置和
凭据以 [20](./20-config.md) 为准，运行态订阅与退出遵循 [18](./18-studio-state.md)。
本阶段只允许按需准备并运行产品指定的 Antigravity server 1.4.1，提供受管账号配置、连接与登录；
不提供用户自定义程序、argv 或版本，也不承诺 ACP 聊天、模型选择、宿主工具或子代理已实现；
实际完成情况以验收记录为准。

## 28.1 接入与所有权

Native 模型账号与 ACP 接入在同一产品入口展示，但使用封闭类型分支保存各自语义。ACP 不是
HTTP 模型协议，不能以空 endpoint、空目录或假 API key 进入 Native route。协议客户端只
消费受监督 IO、已验证请求、进度与取消能力，不读取配置、不创建进程、不持有产品状态。

Studio 认证 owner 拥有接入配置与固定受管发行的冻结身份、操作代次、探测工作区、进程树、管道、取消和 join。
启动命令只来自产品发行清单及经完整验证的受管安装，不接受账号配置、API 或客户端提交的
程序路径/argv，不搜索 PATH，也不回退执行历史自定义路径。文件验证由现有安装边界承担，
认证任务持有验证、取消与 join 责任；长 IO 不进入 Settings 提交锁，不复制第二套校验器。
Linux 复用既有受监督 worker，其他平台复用统一后台进程工厂；不使用裸 shell 后备路径。
官方 SDK 负责 codec、请求路由和错误，stdout 只作为协议流。stderr 独立有界消费并脱敏，
不原样发布到 UI，不从中提取认证 URL 或状态；环境与日志不得携带可公开的凭据副本。
必要运行环境包含官方程序打开登录窗口所需的宿主显示认证上下文。Linux X11 的
`DISPLAY` 与继承的 `XAUTHORITY` 必须保持配对；只传递已有路径，不读取或记录认证文件内容，
不放宽显示服务访问控制，也不通过浏览器 shim 绕过官方认证流程。
同时保留宿主已有的 `XDG_SESSION_TYPE` 与 `XDG_CURRENT_DESKTOP`，让官方程序及其浏览器
遵循实际显示平台和桌面服务选择；缺失时不推测、不合成值，不替浏览器强制平台或凭据后端。
这些非凭据上下文仍走精确白名单，不能借此继承任意宿主环境。隔离显示验收使用与目标显示
一致的会话上下文，不能把用户桌面标识误用于另一显示会话。

## 28.2 认证观察与操作身份

认证状态是独立版本域：未检查、检查中、需要登录、登录中、验证中、收束中、认证通过、取消中、已取消
和失败。运行阶段携带 operation 身份，需要登录保留服务端实际方法，失败保留阶段、类型化
原因和可恢复动作。认证通过记录服务器身份与检查时间，仅证明当时的观察，不表示永久在线。
重启后重新检查，不能从旧成功或 authMethods 列表推断当前凭据有效。
协议层的服务端身份仍可选，但产品接入要求实际 server 版本精确为 1.4.1；缺失或不匹配
必须明确失败，不能用本地账号名称或内置版本补造服务器报告，也不能显示认证通过。
未知或未实现的认证方法保留为明确的不支持类别，不能归类为另一种真实认证方式。

保存/删除与认证分开：配置成功返回 canonical 设置，随后连接失败不改变已保存事实。检查、
登录和取消是显式命令；查询、订阅、页面进入与重建不能启动外部程序。命令快速返回受理身份，
owner 在后台推进并通过独立 topic 发布状态，不能让 FRB/HTTP 请求挂起等待人工登录。

每接入同一时刻最多一个操作。重复 start 不创建第二个进程；取消必须命中当前 operation。
operation 身份绑定账号、连接代次和完整意图；同一身份不能用于不同操作。当前运行时保留
已受理身份以阻止完成后的重试产生副作用，容量耗尽时拒绝新操作，不能静默淘汰身份再重放。
provider、固定发行连接身份变化、删除或退出撤销旧代次，名称编辑不撤代；迟到结果不得发布。旧资源未收束时不能偷偷启动
新一代覆盖其句柄；失败保留 owner 供明确清理重试。
配置观察携带 Settings revision，只能单调推进，旧读取不能回写新身份。配置改变后若旧资源
仍在收束，新配置显示忙的收束状态；资源释放后再显示未检查。终态与准入占用的释放在同一
owner 提交中完成，不能出现界面已空闲而操作仍被 Busy 拒绝的窗口。
配置提交、身份撤代与认证准入共享串行提交边界；Settings 投影只读，不能补建或复活认证槽位。
取消与关闭截止点在同一 owner 锁下裁决：已进入收束的请求拒绝新的业务取消；此前受理的取消
在收束完成后不得被认证成功覆盖，清理失败仍必须如实报告。

## 28.3 成功判定

客户端只协商已实现的 ACP v1 能力。先验证受管安装，连接检查 initialize 后核对 server 版本
为产品指定的 1.4.1，再在接入专属的空工作区调用
session/new，mcpServers 为空；成功是认证可用的证据，AuthRequired 是需要登录，其他错误
保持原类别。没有通用 get_auth_state；authMethods 存在、进程存活或浏览器关闭都不是登录证明。
宿主向通用 ACP 认证请求传入必需的 expectedServerVersion；协议客户端在 initialize 响应
之后、任何 authenticate 或 session/new 之前按原字符串精确核对。缺失或不相等立即返回
typed server-version-mismatch，不 trim、不使用显示名代替。协议客户端不内置 Antigravity
版本常量；产品 runtime 从唯一固定清单提供期望值并映射错误，不能等认证终态后才补做检查。

登录先核验实际 method，再对 agent 类型调用 authenticate，等待协议成功并以 session/new
再次校验。terminal 类型必须有专门实现才声明支持，不能向它发送 agent 认证请求。
URL elicitation 也只能在 typed handler、安全 URL 与明确用户同意齐备后声明；不做浏览器
劫持、自制 OAuth 服务或凭据抓取。官方程序管理登录凭据，产品不解释 token。

探测不发送 prompt、不调用模型、不访问用户项目或安装可执行工具。外部 session 是真实资源，
检查结束按已协商能力关闭，并收束连接与进程；没有 close 能力时仍须由宿主回收独占进程。
结果未知不自动重发 session/new；关闭进程不等于删除供应商 session 或撤销凭据。

## 28.4 取消、失败与退出

协议 dispatch、配置锁和 UI 调用不等待用户、长 IO 或进程终态。外部请求、管道消费和监督
任务必须有可观察 owner；请求取消或 future drop 不是进程退出证明。取消关闭准入并发送信号，
在有界期限内终止和等待进程树及管道任务，保留已观察协议结果。清理失败不能伪造成功收束，
不能因认证已经成功而忽略尚未退出的资源。
已获得探测 session 身份后的协议关闭尝试独立于业务取消，仍受关闭预算约束。远端 session
关闭失败与本地进程收束失败分别保留其阶段，不能误报为输出预算超限。
协议请求预算与 SDK 连接排空预算分别有界；底层 IO 故障保留传输类别。连接排空超时后
释放其局部 IO future，并将物理进程和剩余管道的终止、等待责任交回原宿主 owner。
普通进程等待的系统错误不是退出证明；已观察的管道收束错误跨重试保留，不能被后续成功覆盖。

接入删除、运行时 early-exit 与应用关闭进入同一认证 owner 的取消/join 路径，共享已有
shutdown 预算。页面只拥有观察租约；离页不取消已启动的登录，回到设置消费当前 canonical
状态。关闭失败进入 typed Degraded/Failed 并保留重试责任，不发布假的 Clean。
收束未完成时，账号状态保持携带 operation 身份的非终态，可附安全清理问题；进程与管道
确认停止后才发布认证终态。退出必须在登记操作的同一 owner 锁下先封闭准入，再取消并 join。

错误至少区分需要准备、安装损坏/不合格、宿主不支持、server 版本不符、启动、协商、认证要求、方法不支持、认证失败/取消、探测失败、协议断开、超时、
过期操作、资源关闭失败；原始原因仅作安全诊断，不以字符串解析决定恢复。UI 呈现与截图
验收分别见 [19](./19-studio-ui.md) 与 [24](./24-testing.md)。
不可信 RPC 错误仅由私有脱敏包装持有；对外的格式化与错误链只暴露安全类型和码值，
不能通过调试输出或嵌套 source 泄露原始消息、认证 URL 或凭据。

Antigravity server 1.4.1，不提供通用 marketplace、任意版本/下载地址或 shell 安装脚本。

## 28.6 安装操作、观察与终态

`read_acp_install_state` 读取独立安装快照，`start_acp_install` 和 `cancel_acp_install` 表达
显式意图。命令快速返回 operation 回执和 canonical 快照，长网络/文件 IO 不持 Settings
提交锁，也不占用认证状态。安装 topic 为 `acpInstall`，回执资源为 `acp-install`；拥有独立
revision 和运行时 owner epoch，不复用 Settings 或 `acpAuth` 的水位。

安装状态区分未准备、解析固定发行、等待资产锁、下载、校验、解压、发布、收束、就绪、取消中、
已取消和失败。重试次数与当前下载进度可观察；阶段进度是实际已处理字节与可选总量，未知
总量不合成为百分比。缓存校验和新下载使用同一操作链；就绪结果携带安装身份、版本/平台、
只读诊断 program、来源信任、准备时间和是否复用；固定 argv 留在内部启动边界，不进入账号
编辑/保存 DTO。所有已受理操作的终态保留 operation
身份，供草稿与迟到回执正确关联；就绪不是账号已保存或已认证的证明。

每 provider/宿主目标同时最多一个操作。相同 operation 身份和意图幂等；身份冲突拒绝，
不同新意图在忙时不能覆盖当前任务。运行时最多保留 4096 个已受理身份，容量耗尽拒新，
不淘汰后重放。任务登记、关闭准入、取消裁决、最终状态和准入释放共享同一 owner 提交边界。
当前操作槽位表达业务准入，任务回收登记表达真实 join 责任，两者不能互相替代。终态提交
并释放准入后，后继操作不再因前一任务的尾部退出而被 Busy 拒绝；前一任务仍由 runtime
持有直至观察到真实 join 终态，不能因替换当前槽位丢失句柄或失败结果。回收登记受已受理
操作数量预算约束；资源尚未收束的操作仍保持 Closing 与准入占用。

安装属于共享资产而非某个账号：多个观察者可观察同一操作，显式取消命中当前 operation，
并说明其共享影响。跨进程同一资产由文件锁互斥，等待可取消；取消本进程等待不终止另一
持锁进程。账号删除不取消无关的共享安装，也不删除安装目录。

安装 owner 持有下载、校验/解压任务、文件和锁的回收责任。进度采用有界合并，不能以无界
队列存储大包的逐块事件。下载库负责续传、重试与文件关闭，取消必须等待其实际返回；不能
以丢弃 future 或 join handle 冒充收束。校验与解压有协作取消点，阻塞任务仍由 owner join。
固定清单解析不联网；下载总预算 60 分钟、最多自动重试 3 次，并有独立连接/读取超时。

发布进入不可被业务取消回滚的提交阶段，已发布安装必须如实保留；发布后的诊断或暂存清理
错误与安装已生效的事实分开。收束未完成保持非终态，保留清理问题与重试责任。退出在同一
owner 边界先关闭准入再取消/join，纳入统一 early-exit 与 shutdown 预算，不能虚报 Clean。

错误保留阶段以及不支持平台、来源拒绝、网络、超时、大小超限、摘要不符、非法 ZIP、
程序缺失、缓存损坏、IO、忙、过期操作、取消和资源关闭失败等类型；对外错误链不暴露原始
网络 URL、代理凭据或无界库错误。页面只观察，离页不取消、不重启；前端绑定见 [25](./25-frontend-state.md)。

## 28.7 安装资格与内容边界

包内安全成员须完整保存，不能只提取 cmd 而漏掉辅助程序。压缩元数据与实际输出均检查：
ZIP 不超过 1 GiB，解压总量不超过 4 GiB，单成员不超过 2 GiB，
成员数量不超过 512。未知传输长度仍受实际字节上限约束，计数溢出是错误。

成熟 ZIP 解析器负责格式和 CRC；产品额外拒绝绝对路径、父目录越界、Windows 路径别名与
保留名、重复或大小写冲突、加密、符号链接及非普通文件/目录。只向新建私有 staging 写入，
不得通过已有链接越出安装根；回执保留名不能与包成员冲突。Unix 文件仅保留必要执行权限，
不携带 setuid/setgid 或不必要的宽写权限。

ZIP 内容完整性以 central directory 声明与实际解压数据的 CRC、压缩/解压大小核验为准；
local header 的路径、方法、适用 flags 和非占位大小仍须一致。对于使用 data descriptor
的条目，仍由成熟组件解析尾部结构并传播解析失败，不额外比对 descriptor 中重复的 CRC
与大小字段；这不是关闭 ZIP 数据 CRC、
发行方 SHA256（若提供）或安装回执完整性检查。ZIP64 local 占位由成熟组件解析，不自行
解释格式或推测错位字段。该取舍允许尾部重复字段不一致但实际数据与 central 一致的包，
不承诺检测这类仅发生在重复元数据中的不一致；路径、成员类型、预算和权限边界不变。

本机威胁边界采用标准桌面应用模型：防护不可信分发内容、预先存在的符号链接/reparse、
路径越界及损坏安装，不承诺抵御能够同时修改当前用户配置、安装管理树或进程权限的同
权限恶意进程或管理员。它不是 OS 沙箱，见 [04](./04-security.md)。Studio home 及其祖先
必须是宿主选择的受信产品路径；任意可被其他主体并发改写的共享目录不因名称符合布局就
成为可信锚点。不得以同权限对手不在范围内为由跳过实际链接、权限或完整性检查。

所有产品自有管理目录与暂存按用户私有权限建立。Unix 创建目录显式限制权限，不依赖
umask 才避免宽写；复用检查真实文件/目录权限，不先归一化实际权限掩盖危险写位。
Windows 依托受信用户目录及其 OS 继承 ACL，并在使用新建或既存受管对象前核验实际所有者
和 DACL。私有访问只允许当前用户、SYSTEM 与 Administrators；仅供后代继承的 CREATOR OWNER
模板按其不作用于当前对象、继承时替换为对象所有者的语义处理。继承标记本身不是权限证明。
只支持可明确判断的普通允许/拒绝条目；空 DACL 指针、未知或复杂权限形态、无法查询及额外
主体授权均明确拒绝，不静默修改既存 ACL、不提权，也不宣称完整 ACL 审计或共享目录隔离。
该有限策略可能拒绝特殊企业 ACL 配置，不能把常见默认配置的预期当作所有 Windows 环境
均已验证。目录创建后必须先完成核验，才能在其中下载或解压资产；既存文件亦不能绕过
受管路径的权限检查。当前用户或管理员并发改 ACL 仍不属于上述威胁模型的防护承诺。
固定下载目标、库派生的 part/sidecar、锁、回执及发布目录均在同一受管路径边界内校验，
不能只检查最终 ZIP；目录枚举不得静默过滤掉本应拒绝的链接或额外成员。

目录解析必须逐条保留原始成员，以有界缓冲和成员计数限制元数据处理，不能先按不可信声明
物化全部成员后才检查上限，也不能在校验前折叠重名条目。完成遍历后核对声明数量与实际
数量，格式、数据定位及 CRC/大小验证仍由成熟组件承担，不在产品内复制 ZIP 格式解析器。

完整验证、可执行入口确认和版本化回执落盘后才原子发布。已有发布目录不覆盖，复用须核对
回执与完整成员；损坏时保留现场并明确失败，不静默替换可能被账号使用的版本。暂存和稳定
安装的所有权、目录与保留边界由 [17](./17-studio-storage.md) 定义。

发布完成依据目标平台的真实能力，不伪造跨平台相同的断电耐久性。Unix 在权限更新后同步
文件，并同步嵌套目录、移动两端及新建祖先的必要目录项；Windows 同步文件并使用同卷
write-through 移动的原生保证，不把空操作的目录同步称为 Unix 等价确认。平台调用失败
保留已提交或待确认事实，不报告就绪；重启或显式重试须重新验证既有安装，不能因上次
发布成功就跳过完整性检查。平台差异不授权覆盖旧目录或删除未知现场。

## 28.8 准备与账号配置的边界

自动下载先准备服务器，成功后由用户显式保存并连接。准备失败不创建账号，准备成功但保存
失败不撤销安装；保存成功但连接失败不撤销配置。账号只持久化稳定 ID、provider、名称，
安装归固定发行资产事实；不存在 Managed/Local 选择，不通过路径前缀推断合法安装。

配置 schema 24→25 显式迁移旧 ACP 账号，保留 ID、provider 和名称，移除 program/args 的
执行语义。旧字段只在迁移边界读取；备份/恢复材料保留，不删除旧目录或官方凭据，也不静默
下载。缺少固定 1.4.1 受管安装时保留账号并提示准备；已有同描述符完整安装可验证后复用。
名称编辑不下载、不认证、不改变连接代次。自动升级、卸载及旧版本清理不是当前能力。

### 跨层接口收敛

- `AcpAccountUpdate` 只有 accountId、name、provider；`AcpAccountSettings` 另有 connectionRevision。
- `AcpAccountTemplate` 以 supportedVersion 代替 defaultArgs，保留宿主安装能力和官方说明/条款。
- `AcpInstalledServer` 保留只读 program 诊断，不再向客户端返回 args；回执内部仍记录固定启动身份。
- 认证增加 `preparationRequired`、`installationInvalid`、`unsupportedPlatform`、`serverVersionMismatch`
  类型化失败；前置安装验证属于 `prepare` 阶段，ACP 协议版本不符仍是独立的 unsupportedVersion。
- 保存、安装和认证的 revision/ownerEpoch 仍独立。任何 HTTP/FRB/config 的旧 program/args
  输入都不得恢复自定义执行能力；正常当前 schema 不隐式吞掉旧执行字段。
