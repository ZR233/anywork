# 28 - ACP 接入、业务会话与认证

本文定义外部智能体的 ACP（Agent Client Protocol）接入、受管服务器准备、认证、账户额度查询、业务会话和 Host MCP 边界。各 crate 职责遵循 [02 - Crate 边界与职责](./02-crates.md)，用户级定义与迁移遵循 [20 - 配置与凭据管理](./20-config.md)，运行资源所有权遵循 [14](./14-runtime-host.md)。任意符合稳定 ACP v1/stdio 的用户配置服务进入同一实际运行分支；Antigravity 是内置受管启动模板，固定发行限制仅属于该模板，不限制通用 command。本文定义目标契约，实际完成度和具体服务的真实工具能力以验收记录为准，协议 fixture 不代表所有供应商兼容。

## 28.1 接入边界与所有权

原生（Native）模型账号与 ACP 接入在同一个产品设置入口展示，但在数据模型中通过封闭类型分支各自独立存储。ACP 不属于 HTTP 模型协议，不得通过空端点、空模型目录或伪造 API 密钥混入原生模型路由。底层协议客户端仅消费受监督的标准输入输出流（I/O）、已校验请求、进度通知与取消信号，自身不读取配置文件、不派生操作系统进程，也不持有产品级状态。

Studio 的账户连接所有者（Owner）按接入 ID 与连接代次持有已解析启动定义、专属空工作目录、子进程树、通信管道、唯一 SDK 连接驱动、取消令牌与汇合句柄（Join Handle）。认证操作与业务成员引用同一连接，但分别拥有操作身份和独立 SDK session；单个操作完成或会话关闭不终止账户连接。下述固定发行安装、专用登录帮助与额度能力只适用于 Antigravity 模板，通用服务按实际协议方法与能力准入：

- **受管启动来源**：统一解析 [20](./20-config.md) 的用户定义。command 按最终环境的 PATH、实际 cwd 和官方平台查找规则在准备边界解析一次并冻结绝对程序路径，参数独立传递；模板解析到原已验证安装及固定参数。两者进入同一本地执行器，不增加模板/供应商运行时或另一关闭通路，也不从旧备份恢复已退役程序字段。安装包完整性校验仅归模板安装边界；耗时 I/O 不进入 `Settings` 提交锁。各平台复用公共 `Executor / Command / Child` 及原生进程工厂，一律不使用裸 Shell 后备路径。白名单宿主环境之后再应用用户显式 env，不扩展为整个宿主环境继承，不记录覆盖值。
- **标准流隔离与脱敏**：官方 SDK 负责协议编解码、请求路由与错误分类，子进程 `stdout` 仅作为纯协议字节流消费；`stderr` 由独立有界缓冲区消费并脱敏，不原样发布至界面，也不从中正则提取认证链接或登录状态；进程环境变量与日志中不得携带可公开的凭据副本。
- **宿主环境白名单**：子进程按平台白名单原样透传官方程序启动、定位用户配置及打开登录浏览器所需的既有环境值，不复制其他凭据类变量。Windows 保留系统目录、用户配置目录、临时目录与标准命令查找上下文，包含初始化 Winsock 所需的 `SystemRoot`；变量查询遵循 Windows 原生的大小写无关语义。Linux X11 环境下，`DISPLAY` 与继承的 `XAUTHORITY` 必须成对传递（仅传递既有文件路径，不读取或记录认证文件内容，不放宽显示服务器访问控制，也不通过浏览器垫片绕过官方认证流程）。同时按原样透传宿主既有的 `XDG_SESSION_TYPE` 与 `XDG_CURRENT_DESKTOP`，使官方程序及其唤起的浏览器遵循实际显示平台与桌面服务；若宿主未设置则保持缺省，不猜测或合成环境变量，也不强制指定浏览器凭据后端。隔离显示验收使用与目标虚拟显示一致的会话上下文，不混用操作者真实桌面的显示标识。
- **代理环境**：原样透传宿主既有的 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`、`NO_PROXY` 及其小写形式，由官方程序的网络库解释；不记录其值、不修改宿主环境，也不将 Windows 系统代理或自动代理脚本转换成另一套规则。服务器下载使用产品 HTTP 客户端的系统代理能力，官方程序自身仅支持环境变量代理时，登录验收必须明确配置并记录该运行条件。

### 账户连接与后台准备

Studio 启动及有效配置提交后，为已启用且安装已就绪的 Antigravity 模板账户异步准备连接并检查已有登录态，不阻塞产品启动，不自动下载、调用模型或发起交互登录。普通 command 保持按需启动，不根据程序名猜测品牌。同账户同连接代次的并发请求共享同一准备结果；进程只启动一次、`initialize` 只协商一次，后续检查、额度和业务会话复用该连接。连接初始 cwd 是账户专属空目录，真实业务 cwd 随各个 session 请求传入，不因共享进程而共享工作区或工具权限。

协议层只负责宿主提供的 I/O 与官方 SDK 驱动。各业务会话通过 SDK 官方动态 handler/guard 注册自己的类型化接收，在 load/resume 请求发布前绑定原 State；回调仅按本会话身份认领消息，直接短处理现有有界观察和权限状态，未匹配消息交回 SDK，不建立自有 JSON-RPC 或全局 session-ID 分发表。guard 由会话 owner 持有至收束，撤销后迟到消息不能重新激活该实例。控制响应继续通过 SDK 有序结果回调写同一 State，保留响应前回放、setup/set 与通知入站顺序及观察窗口上限。当前 SDK 的 ActiveSession 在加载响应前使用不可由应用消费的无界队列，不用于业务接收；不能同时安装两条消费同一消息的通路。认证/额度仅在保持相应预算与隔离的条件下复用 SDK session 能力。

宿主的账户连接所有者负责实际进程，业务成员仍独占运行状态、权限 responder、观察窗口、工作区租约及 Host MCP。连接级失败终止所属会话并撤销新准入，不自动重放或无限重启；显式重试只能在原资源真实收束后创建新代次。

名称编辑不撤代。command/args/env/模板解析身份变化、禁用、删除及应用退出立即封闭旧连接的新准入并取消其所属操作和会话，迟到结果不能发布到新代次；不保留继续使用旧定义的活动业务分支。旧进程、SDK 与管道未完成回收前不抢跑替代连接。只读查询和订阅仍不触发准备；后台准备是启动/配置提交的显式生命周期责任，不属于读取副作用。

## 28.2 认证观察与操作身份

认证状态构成独立的版本域，包含十种状态：`未检查`、`检查中`、`需要登录`、`登录中`、`验证中`、`收束中`、`认证通过`、`取消中`、`已取消`与`失败`。运行中阶段携带操作身份（`operationId`），`需要登录`阶段也持有原 `operationId`、活跃连接与服务端实际声明的认证方法列表，`失败`阶段保留发生阶段、类型化错误原因与可恢复操作指引。`认证通过`状态记录服务端身份与检查时间戳，仅代表该次探测时刻的观察结论，不代表永久在线；进程重启后需重新检查，不能由历史成功记录或 `authMethods` 非空直接推断当前凭据有效。

协议层允许服务端身份字段可选，通用 command 不要求品牌、agentInfo 或固定版本；所有连接都核验实际协商协议版本。Antigravity 模板强制要求实际服务端版本精确匹配 `1.4.5`，缺失或不符明确失败，不用本地账号名称或常量修补。认证方法名称、ID、类型来自 initialize；只广告和执行宿主已实现的 agent 流程，terminal/未知未实现方法不误传给 authenticate，也不映射为其他方式。

配置保存／删除与连接认证解耦：保存配置成功后立即返回权威设置快照，后续连接失败不推翻已保存事实。连接检查、发起登录、额度刷新与取消操作均通过类型化命令准入；只读快照查询和主题订阅本身不会触发外部进程启动。账号列表卡片创建后主动发起一次额度命令，普通组件重建不重复发起，具体生命周期见 [28.9](#289-账户额度查询)。命令调用快速返回已受理的操作身份，由认证所有者在后台推进并通过独立的 `acpAuth` 主题发布状态，避免阻塞 FRB 或 HTTP 请求等待人工完成登录。

每个接入账号在同一时刻至多运行一个认证操作：

- **幂等受理与有界去重**：重复发起相同 `start` 或 `continue` 命令不会重复执行；`continue` 绑定原操作且不派生进程；取消命令必须命中当前活动操作。`operationId` 绑定账号、连接代次与完整操作意图，同一标识不得复用于不同意图。运行时保留已受理操作身份以阻止完成后重试产生重复副作用；去重缓存达容量上限时直接拒绝新操作，不静默淘汰旧身份引发重放。
- **代次撤销与串行收束**：供应商类型变更、固定发行连接身份变化、账号删除或应用退出均会撤销旧连接代次（仅修改账号显示名称不撤销代次），旧代次的迟到结果一律丢弃。在旧代次资源尚未完全收束前，不抢跑启动新代次覆盖旧句柄；清理失败时保留所有者供显式重试。配置观察携带单调递增的 `Settings` 修订版本，若配置变更后旧资源仍在收束，新配置状态显示忙碌的`收束中`，待底层资源完全释放后再转为`未检查`。终态发布与准入槽位释放在同一所有者锁提交中原子完成，消除“界面显示已空闲但新操作仍被 `Busy` 拒绝”的时间窗。
- **取消与关闭截止边界**：配置提交、身份代次撤销与认证准入共享串行提交边界；`Settings` 只读投影不补建或复活认证槽位。业务取消与关闭截止点在同一所有者锁内裁决：已进入`收束中`的操作拒绝新的业务取消请求；此前已被受理的取消在资源收束完毕后保持`已取消`终态，不被在途认证成功结果覆盖，且若收束清理自身失败仍须如实报告。

## 28.3 认证成功判定与探测闭环

`initialize`、`authenticate` 与 `session/new` 不设固定墙钟超时。取得进程和标准流不代表服务端已经就绪；冷启动、外部浏览器授权与会话验证均持续驱动官方 SDK，并按实际响应、连接关闭、进程退出、显式取消和连接代次撤销推进。取消和资源关闭具有独立的生命周期预算，不能用关闭预算截断正在进行的登录，也不能用延长固定超时代替协议事件。

协议客户端仅协商已实现的 ACP v1 能力。首次准备验证模板安装、启动进程并执行一次 `initialize`，按模板要求核对实际版本精确为 `1.4.5`；后续操作复用该初始化结果和连接。检查在账户专属空目录创建独立 `session/new`（空 `mcpServers`）；成功只证明此刻认证可用，`AuthRequired` 表示需要用户继续登录，其他错误保留分类。协议无通用 `get_auth_state`，不能用 `authMethods`、子进程存活或浏览器关闭判定认证成功。

宿主向通用 ACP 认证请求传入必填的 `expectedServerVersion`；协议客户端在收到 `initialize` 响应后、发起任何 `authenticate` 或 `session/new` 调用前，按原始字符串精确比对服务端版本（不裁剪空白字符，也不用显示名称替代）。若字段缺失或不相等，立即返回强类型的 `server-version-mismatch` 错误。协议客户端内部不硬编码 Antigravity 版本常量，由产品运行时从唯一固定清单注入期望版本并映射错误。

`AuthRequired` 是当前登录流程的可继续阶段，携带原始 `operationId`、服务端身份与实际认证方法；所有者保留同一 SDK 连接、通信流和官方进程。继续登录是单独的类型化命令，绑定账户、连接修订、目标操作身份和方法 ID，不能重新启动另一个认证进程。仅对当前连接实际声明的 `agent` 方法调用 `authenticate`，等待协议返回成功后再调用 `session/new` 完成复核；若仍要求认证则回到同一流程的需要登录阶段。浏览器窗口关闭或用户自述授权完成不能替代该响应和复核。

`terminal` 类型认证必须具备专门实现后才允许声明支持，不得向其发送 `agent` 认证请求；URL 引导认证（Elicitation）同样仅在强类型处理器、安全 URL 校验与用户显式同意机制齐备后才可声明。产品不劫持浏览器、不自建本地 OAuth 回调服务，也不抓取或解析官方程序管理的登录令牌。

认证探测不发提示词、不调用模型、不访问用户项目或挂载工具。Windows 外部协议 cwd 使用可无歧义表达同一目录的常规路径形式，文件系统校验仍持有原始路径。探测 session 是真实服务端资源：结束时按已协商能力关闭并释放本地 session 接收责任，保留账户连接和进程供后续使用。不支持 session close 时只报告该限制，不为回收单个探测而杀死其他业务会话；账户退出时仍须回收整个进程树，不能声称已销毁远端 session 或吊销凭据。`session/new` 结果未知不自动重发。

## 28.4 取消、失败分类与退出回收

协议分发、配置锁与界面调用不等待人工操作、耗时 I/O 或进程退出。RPC、管道和监督任务均有可观察的所有者；取消请求或丢弃 Future 不代表资源停止。单次认证/额度取消只取消其操作并关闭专属 session，不杀死共享连接或其他业务会话；不支持独立取消的协议请求保留原完成责任，迟到结果受操作资格检查。账户撤代和应用退出则封闭账户准入，收束其全部 session、SDK、进程树和管道；清理失败保留真实错误与所有者，不伪报正常完成。

已取得探测身份后的 session 关闭独立于业务取消并受关闭预算约束；远端 session 关闭错误与本地连接/进程回收错误分开记录。人工登录不设墙钟期限；会话关闭仅消耗该会话预算，不能启动共享连接的全局排空。账户关闭时 SDK 排空与物理回收共享原关闭预算；等待者退出不丢失 join 责任，重试汇合同一任务。进程 wait 报错不是退出证明，既有管道错误不被后续成功掩盖。

账号删除、运行时提前退出（Early-Exit）与应用关闭统一走账户连接所有者的取消与汇合路径，共享全局关闭预算。设置页面仅持有观察租约，离开页面不终止已受理登录或空闲服务。操作完成只证明该操作与专属 session 的结算，账户进程继续由连接 owner 持有；账户关闭失败保留强类型错误和原资源责任，不发布虚假 `Clean`。若有操作正在收束，其非终态继续携带原 `operationId`，不能为无操作的空闲连接伪造操作身份。

错误分类严格区分以下场景：`需要准备`、`安装损坏或不合格`、`宿主平台不支持`、`服务端版本不符`、`启动失败`、`协议协商失败`、`需要认证`、`认证方法不支持`、`认证失败或已取消`、`探测会话失败`、`协议连接断开`、`操作超时`、`操作已过期`及`资源关闭失败`。不可信的底层 RPC 错误由私有脱敏包装器持有，对外格式化与错误链仅暴露安全错误枚举和错误码，防止通过 `Debug` 输出或嵌套错误源（`source`）泄露原始消息、认证链接或凭据。界面呈现契约见 [19](./19-studio-ui.md)，观察能力与证据边界见 [24](./24-testing.md)。

## 28.5 官方服务器来源与受管准备

受管服务器准备属于 Studio 产品层能力，独立于 ACP 协议客户端与原生模型适配器。产品仅内置支持 Antigravity Server `1.4.5`，不开放通用扩展市场、任意版本／下载地址或自定义 Shell 安装脚本。目标包按运行 Studio 后端的受支持操作系统（Windows / Linux）与处理器架构（`x86_64` / `aarch64`）匹配，不以远程客户端的显示平台决定下载目标。账号模板仅描述静态能力与官方条款说明；读取模板、设置、安装状态或订阅主题均不发起网络请求。

内置固定发行清单基于官方注册表快照 `02b460362cfedf4d43b03df7aad6d79a353fe064` 中的 `1.4.5` 描述生成，运行期不访问远程 `latest` 注册表。各宿主目标的归档路径均相对于官方基址 `https://dl.google.com/agy-extensions/releases/`：

| `windows-aarch64` | `windows/agy-acp-server-1.4.5-windows-arm64.zip` | `agy_acp_server.exe` | `[]` |

显式准备操作按当前宿主平台冻结清单中的供应商标识、版本号、目标平台、归档路径、摘要策略、可执行文件名与固定 `argv`。后续版本升级只能通过更新产品代码清单并完成验证来交付。模板的 `supportedVersion` 字段与内部启动资格校验消费同一份清单，客户端不硬编码第二份映射表。

分发包下载仅接受 `https://dl.google.com/agy-extensions/releases/` 下的 HTTPS ZIP 归档；每次 HTTP 重定向均重新校验来源域名与路径前缀，拒绝携带用户凭据、非默认端口、越权来源或非 ZIP 格式的响应。包内可执行入口必须为普通文件，固定 `argv` 直接作为进程参数数组传递而不经过 Shell 字符串拼接；禁止将下载元数据注入子进程环境变量，启动环境遵循 28.1 的平台白名单。

官方固定清单为上述四个目标提供 SHA-256，准备流程在解包前强制核对发行摘要。它证明归档与固定注册表描述符一致，不将其称为发行方数字签名。ZIP CRC、本地成员 SHA-256 与安装回执继续负责落盘完整性。版本和摘要进入安装身份，新版安装保留旧资产，不覆盖旧目录。产品不复制、解析或重置官方登录凭据，也不分发专有二进制。

## 28.6 安装操作、进度观察与终态收束

客户端通过 `read_acp_install_state` 读取独立安装快照，通过 `start_acp_install` 与 `cancel_acp_install` 提交显式安装或取消意图。命令调用快速返回操作回执与权威快照，耗时的网络下载与磁盘解压不持有 `Settings` 提交锁，也不占用 `acpAuth` 认证状态。安装状态主题为 `acpInstall`，回执资源名为 `acp-install`，拥有独立的修订版本号与运行时所有者纪元（Owner Epoch）。

安装状态机包含：`未准备`、`解析固定发行`、`等待资产锁`、`下载中`、`校验中`、`解压中`、`发布中`、`收束中`、`就绪`、`取消中`、`已取消`与`失败`。当前重试次数与下载字节进度对外可观察（进度汇报实际已处理字节数与可选总字节数，当服务端未返回总长度时不伪造百分比）。已有缓存校验与全新下载走同一操作链；`就绪`状态携带安装身份、版本／平台、只读诊断程序路径、来源信任级别、准备完成时间戳及是否复用已有安装标记（固定 `argv` 保留在内部启动边界，不进入账号编辑或保存 DTO）。所有已受理操作的终态均保留 `operationId` 供前端草稿与迟到回执关联；安装`就绪`不代表账号已保存或已通过认证。

每个供应商与宿主目标组合在同一时刻至多运行一个安装操作：

1. **准入槽位与任务回收分离**：相同 `operationId` 与相同意图的重复请求幂等返回；同一 `operationId` 携带冲突意图或忙碌期间收到不同新意图均直接拒绝。运行时最多保留 4096 个已受理操作身份，容量耗尽时拒绝新请求。任务登记、关闭准入、取消裁决、终态提交与准入释放在同一所有者锁边界内完成。当前操作槽位代表业务准入占用，任务回收登记代表底层汇合（Join）责任：当安装终态已确定提交并释放准入槽位后，后继操作不再因前一任务的尾部清理而被 `Busy` 拒绝，但前一任务句柄仍由运行时持有直至观察到真实汇合终态；若资源尚未收束完毕，则继续维持 `Closing` 状态与准入占用。
2. **跨账号共享与跨进程文件锁**：受管安装属于宿主级共享资产而非单一账号私有属性。多个观察者可同时订阅同一安装进度，显式取消会作用于当前共享安装操作并在界面说明其影响范围。跨进程并发安装同一资产通过文件锁互斥，等待文件锁的过程支持取消；取消本进程的锁等待不会终止另一个正在持锁安装的进程。删除单个 ACP 账号不会取消正在进行的共享安装，也不删除已就绪的安装目录。
3. **有界进度合并与发布提交点**：安装所有者统管下载、校验、解压任务及临时文件／文件锁的回收。下载进度采用有界合帧更新，不建立无界队列积压逐块字节事件。底层下载器负责断点续传、重试与文件句柄关闭，取消时必须等待下载与解压任务实际返回，不以丢弃 Future 冒充收束。固定清单解析不联网；单次安装下载总预算为 60 分钟，最多自动重试 3 次，连接与读取超时独立受控。一旦进入原子`发布中`阶段即越过业务取消截止点，已成功发布的安装如实保留；发布完成后的暂存目录清理错误与“安装已就绪”事实分开报告。

安装错误保留发生阶段及细分类型：`不支持的平台`、`来源拒绝`、`网络故障`、`超时`、`体积超限`、`摘要不符`、`非法 ZIP 归档`、`入口程序缺失`、`缓存损坏`、`磁盘 I/O 错误`、`系统正忙`、`操作已过期`、`已取消`与`资源关闭失败`。对外错误链不暴露原始下载 URL、代理服务器凭据或未裁剪的底层库异常。

## 28.7 安装包资格校验与本地文件系统边界

安装包内的所有安全成员文件均须完整提取保留，不能仅提取主程序而遗漏同目录下的辅助文件。压缩包元数据与实际解压字节流双重受控：ZIP 归档体积不超过 **1 GiB**，解压后总大小不超过 **4 GiB**，单个成员文件不超过 **2 GiB**，成员总数不超过 **512 个**；未知传输长度同样受实际写入字节上限约束，计数器算术溢出直接按失败处理。

格式解析与 CRC32 校验复用成熟 ZIP 组件；产品层在此之上显式拒绝绝对路径、父目录越界（`..`）、Windows 路径别名与设备保留名、重名或大小写折叠冲突、加密条目、符号链接（Symlink）及非常规文件／目录。解压过程仅写入新建的私有暂存目录（Staging），严禁跟随预先存在的链接跳出安装根目录，且安装回执保留文件名不得与包内成员冲突。Unix 平台落盘文件仅赋予必要的用户读写与可执行权限，剥离 `setuid`、`setgid` 及组／其他用户写权限。

ZIP 内容完整性以中央目录（Central Directory）声明与实际解压数据流计算出的 CRC32 及压缩／解压大小一致为准，局部文件头（Local Header）的路径、压缩方法、通用标志位及非占位大小同样须保持一致。对于采用数据描述符（Data Descriptor）或 ZIP64 局部占位的条目，由底层成熟组件解析尾部结构并传播格式错误，产品层不手写二进制解析器，也不因数据描述符中的重复元数据字段与中央目录存在无害差异而关闭实际解压数据的 CRC32、SHA-256 及安装回执完整性校验。

本机安全边界遵循标准桌面应用威胁模型（详见 [04 - 安全与权限策略](./04-security.md)）：重点防范不可信网络分发内容、预先存在的符号链接／重解析点（Reparse Point）、路径遍历越界及损坏安装，不承诺抵御已获得当前操作系统用户同等权限或管理员权限的本地恶意进程。`StudioHome` 及其祖先目录必须位于宿主选定的受信任路径下；任何可被其他非特权主体并发改写的公共共享目录均不可作为受信任锚点。产品自有管理目录与暂存目录的权限遵循宿主平台机制：

- **Unix 权限核验**：创建目录时显式指定私有权限模式，不依赖进程默认 `umask`；复用已有目录或文件前直接检查真实权限位，不先自动修改权限来掩盖已被篡改的宽泛写权限。
- **Windows 目录权限**：受管资产使用受信任用户数据目录及 Windows 原生继承的访问控制列表（ACL），实际文件访问失败按磁盘 I/O 错误传播。产品不自行枚举或限制所有者与 ACL 主体，不因父目录包含系统、企业管理或工具设置的其他继承项阻断准备，也不改写既有 ACL。链接／重解析点、路径范围、文件类型及安装完整性仍由同一受管路径与归档边界检查；该目录不构成操作系统沙箱。
- **全路径覆盖与有界目录遍历**：固定下载目标、下载器派生的分片／旁路文件（`.part` / Sidecar）、文件锁、安装回执及最终发布目录均纳入同一受管路径与适用平台权限检查范围，枚举目录时不静默跳过异常链接或未知成员。ZIP 中央目录解析以有界缓冲区逐条处理并统计成员数，不在校验上限前一次性按不可信头部声明分配全量数组，也不在校验前自动合并同名条目。

所有成员通过完整性校验、确认主程序入口存在且版本化安装回执落盘成功后，才执行原子目录发布。发布操作绝不覆盖已存在的就绪目录；复用既有安装前须重新核对回执与全体成员完整性，发现损坏时保留现场并明确报错，不静默覆盖可能正被某个账号使用的目录（暂存与稳定安装目录的具体布局与保留边界见 [17 - Studio 存储、单实例与恢复](./17-studio-storage.md)）。

目录发布的持久化同步遵循目标操作系统的真实文件系统原语：Unix 在更新权限后对文件、嵌套子目录、重命名源目两端及新建祖先目录项执行 `fsync`；Windows 对文件执行刷盘并依赖同卷穿透写入（Write-Through）移动语义，不以空操作伪装 Unix 目录同步。若底层同步调用失败，则保留已提交或待确认状态而不报告`就绪`；进程重启或用户显式重试时重新校验既有安装完整性。

## 28.8 服务器准备与账号配置的边界

ACP 账号使用同一编辑草稿选择本机 agy、自定义命令或受管安装。前两者保存普通 command 与独立 args，受管来源保存 template 且不另带 command/args；共同的名称、enabled 和 env 随用户级定义保存，稳定 `accountId` 对应文件 ID，完整文件契约见 [20](./20-config.md)。只有受管来源要求安装就绪及编辑器认领，不以路径前缀猜测安装合法性，也不将该资格强加给本机程序。准备失败不创建账号，准备成功后未保存或保存失败不卸载已就绪资产；配置保存已确认但连接检查失败保留原账号与真实错误，不回滚或重复创建。

已有账号详情与新建页面自行读取实际需要的受管安装能力目录，不依赖先访问其他页面。读取失败可显式重试，但不会隐式安装、检查连接或登录；显式准备若遇模板加载在途，先等待并核对同一草稿再发起。添加页为一屏左对齐的 API/ACP 与三种 ACP 来源选择，仅显示当前方式所需字段；参数逐行、环境默认折叠，不使用标题下二级说明、阶段副标题、步骤卡片或重复提示段落。新建主动作“添加并连接”，编辑主动作“保存”且检查连接独立；保存不自动登录，认证只按对端真实 Required 和用户显式操作继续。详情的状态、模板专用额度与高级身份信息仍来自只读 Presentation，不把模板专用能力展示为任意服务通用能力。页面及草稿规则分别见 [19](./19-studio-ui.md) 与 [25](./25-frontend-state.md)。

安装就绪与编辑器认领不构成账号保存确认。Client 的保存并连接编排须将本次保存的操作身份及结算事实完整交回：明确拒绝、结果未知和同步失败与已确认保存分别表达，保存未确认时不发连接检查、不允许界面重新发送同一冻结意图。已确认保存后检查失败仅作为部分成功反馈，不抹除账号身份；检查受理本身也不代表已连接或已认证。类型化结果、观察屏障及退出收束遵循 [25.3](./25-frontend-state.md#253-版本域与资源戳stamps)，不将安装、配置和认证合并成事务或以通用异常推断配置未写入。

历史配置模式 `24 → 25` 曾保留旧 `accountId`、`provider` 与名称，并剥离旧版 `program` / `args` 的执行语义；这些旧字段只在对应迁移解码边界读取。当前主配置 `32 → 33` 再将旧内嵌账号迁为同 ID 的用户级受管模板定义，保留原件、备份、安装资产、凭据及 Profile 引用，不恢复旧字段双读或在迁移时下载。当前普通 command 的独立 args 是新定义的合法字段，不与历史字段混同。仅受管模板要求匹配的 `1.4.5` 安装，缺失时保账号并提示准备，完整匹配则校验后复用；名称修改不触发下载、认证或连接代次变化。联合迁移及冲突恢复遵循 [20](./20-config.md)，自动升级、卸载和历史版本清理仍不在当前范围内。

### 继续登录接口

`start` 仅接收 `check` / `queryUsage`，不再提供启动新认证进程的 `authenticate` 动作。`continue` 接收命令 `operationId`、`accountId`、`expectedConnectionRevision`、`targetOperationId` 与 `methodId`；当前状态必须为同一流程的 `Required`，方法必须是该连接实际声明的 `agent` 方法。HTTP 路由 `/api/v1/runtime/acp-auth/continue`、FRB `continue_acp_auth` 与 Client `continueAcpAuth` 表达同一契约。旧动作已删除，外部调用方须迁移到先检查、再继续原流程。Client 在 `Required` 期间保留原业务观察租约；继续登录和取消采用独立命令通道，不被慢速开始请求阻塞，也不建立第二份登录事实。

### 跨层接口收敛清单

- **`AcpAccountUpdate` 与 `AcpAccountSettings`**：账号更新包含 `accountId`、`name`、`enabled`、互斥的 `template` 或 `command` / 独立 `args` 以及 `env`。命令携带 Settings 修订和文档 CAS：创建时 `expectedDocumentRevision=null`，更新时为真实文档修订；设置投影另交付 `documentRevision` 与仅运行期的 `connectionRevision`，后者不持久化到定义、Profile 或 Catalog。
- **文档 CAS 的精度**：ACP 文档修订是完整 `u64` 内容摘要，不是有符号计数。Dart Client 的已保存账户模型、Port、Service 及保存/删除参数统一使用 `BigInt`，FRB 入出站直接传递生成 DTO 已有的 `BigInt`，不得经过 `toInt()` 截断、低位掩码或负数编码。已保存账户显式携带其真实文档修订，构造时不补零；只有创建请求的预期文档修订为空。Settings 与连接修订保持各自现有语义，不在本次扩为其他修订域迁移。
- **`AcpAccountTemplate`**：以 `supportedVersion` 取代旧的 `defaultArgs`，保留宿主平台安装支持标记及官方说明／条款链接。
- **`AcpInstalledServer`**：仅保留只读的 `program` 路径用于诊断展示，不再向客户端暴露 `args`；安装回执内部仍完整记录固定启动身份。
- **认证失败枚举扩展**：新增 `preparationRequired`、`installationInvalid`、`unsupportedPlatform` 与 `serverVersionMismatch` 四类强类型错误；前置安装校验归入 `prepare` 阶段，而 ACP 协议层版本不兼容则保持独立的 `unsupportedVersion` 错误。
- **独立版本域与旧字段拒绝**：配置保存、服务器安装与连接认证保留各自的资源修订和所有权；文档 CAS、连接资格和认证代次不可互换。当前 HTTP、FRB 与配置文件拒绝旧 `provider` / `program` 保存形态；普通 command 接受独立 `args`，受管 template 则拒绝 command/args，不因历史迁移删除当前合法能力。

## 28.9 账户额度查询

官方固定发行版原生处理 `/usage`：该命令在服务端模型执行路径之前被截获，读取同一官方进程当前登录账户的配额，不调用模型。产品通过 ACP `session/prompt` 传递固定的 `/usage` 文本，不把它开放为任意提示词入口，也不读取官方凭据或另启 `agy` CLI。普通连接检查与登录仍不发送提示词。

额度刷新使用 `AcpAuthAction.queryUsage`，沿用账户操作身份、连接修订和串行准入，复用已准备连接与版本结果，在空目录创建独立 session；需要登录时发布 `Required`，不自动认证或发送 `/usage`。通过官方 SDK 接收该 session 的文本，限定报告大小和查询时间，不挂载文件、终端、MCP 或权限执行能力。查询结束关闭专属 session 后发布终态，保留共享服务；取消不影响其他会话，资源超限与清理失败保留真实类别，迟到结果不能写回新代次。

ACP 所有者在每个 `AcpAuthAccount` 上独立持有可空 `usage` 观察，随同 `acpAuth` 快照发布。空值表示本运行代次尚无查询结果；观察包含查询时间及 `ready`、`notApplicable`、`unavailable`、`failed` 类型化结果。查询中的界面保留最近观察并显示操作忙碌，新的有效终态替换该观察；账户删除、连接身份变化或应用重启撤销旧观察，名称编辑不撤销。该运行态不写入用户配置或数据库，不与 Native 账号 ID 或其 API 密钥用量缓存混用。

同一账号的 `acpAuth` 快照还携带可空 `activeOperation`，由认证所有者从当前操作槽位与状态在同一提交边界投影，包含操作 ID、该操作冻结的连接修订号和启动动作类型（`check` 或 `queryUsage`）；无在途操作时为空。操作类型来自真实准入意图，不从忙碌阶段、已有额度或查询时间猜测；HTTP、FRB 与 SDK 原样传递，其他客户端启动的操作也适用。忙碌状态的操作 ID 必须与此活动操作一致。若连接已替换而旧进程仍在收束，快照中的当前连接修订与活动操作修订可以不同：只能等待旧资源收束，不能把旧查询复用为新连接的结果。认证终态发布及活动操作撤销在原所有者同一提交边界完成。

启动认证动作因账号槽位已占用而被明确拒绝为 `Busy` 时，错误的结构化详情 `acpAuthBusy` 在同一准入锁内携带 `accountId`、当前 `connectionRevision`、`snapshotRevision` 及当时的 `activeOperation`。这是拒绝时的权威切面，不表示本次请求已准入；HTTP、FRB 和 SDK 保留并类型化这些字段，缺失或不合法时保留原错误，不猜测占用类型或重发。调用方只在原来源仍有效时使用该切面，不能把稍后其他来源的版本附在其上。占用操作可能在错误送达前已经完成，观察允许跳过中间快照，因此不能只等待一个未来的忙碌帧来判断是否应复用。

SDK 中的 ACP 所有者为卡片初始额度刷新提供按账号和冻结连接修订登记、可撤销未发出意图的窄入口，并沿用其已有本地准入与业务操作所有权协调同账号调用。本进程的预留发生在权威槽位发布之前，必须等待或复用该真实本地尝试的受理结果，不能把本地预留伪装成 Rust 快照；同账号同连接的额度查询已在途时共享原查询与观察，其他动作在途时等原操作收束后再检验身份并至多准入一次。结果未知继续绑定原操作，不以新的操作 ID 重发。等待者取消只撤销其尚未发出的意图，不取消已准入或其他等待者共享的操作；最后一个等待者离开后不保留无界等待。不同账号仍独立推进。

`ready` 保留服务端报告的全部模型组和额度窗口。每个窗口携带显示名、可空 UTC 重置时间，以及百分比、剩余单位、数值未知或停用的封闭数量类型；不从“可用”推导剩余 100%，不把空组解释为无限额度。官方报告的“认证方式不适用”“暂无数据”“未报告限制”和查询失败分别表达。Rust 供应商适配边界只解析固定版本额度段，不将会话词元统计当作账户配额；格式不符或数值越界返回明确失败，不发布部分解析值或原始错误文本。额度查询本身失败不推翻已成功的认证观察，取消或底层连接与清理失败仍遵循认证操作的收束规则。

HTTP、FRB 与 SDK 传递同一类型化观察，Flutter 只做本地化和格式化，在列表与详情复用共同额度读数组件呈现剩余量、进度及重置时间。列表中的每个 ACP 卡片呈现所有者创建后对该账号自动请求一次额度刷新；这可能启动受管进程及探测会话。搜索过滤和普通 Widget 重建不重复启动查询；重新进入列表并创建新卡片资源时可以再次查询。单卡和全部刷新也可显式发起额度动作，账号之间独立推进。相同账号已有额度查询时复用其观察；其他认证操作占用时，初始刷新等待该操作收束，仅在原卡片身份、连接修订和来源仍有效时至多发起一次。离开列表或身份替换撤销尚未发起的意图，不取消已准入操作；既有取消入口和进程收束责任不变。自动查询不安装或登录，准备不足、需要登录、失败与清理失败均保留真实状态。


## 28.10 登录验收

协议回归通过官方 SDK 对端与 Tokio 虚拟时间覆盖超过原初始化、探测和人工授权上限的成功响应，断连、取消竞争、授权后仍要求认证和关闭失败。业务等待不以虚拟时钟触发超时，结果未知时不重发。

Flutter 受控回归使用官方 `flutter_test` 与 `WidgetTester`，通过 `cargo flutter test test/ui/acp_auth_test.dart` 运行生产路由、Client、账户观察与组件。外部端点的 ACP 响应和账户提交回执由夹具控制，验证同流程继续、授权后复核仍要求登录、页面离开后返回、重复输入、取消及删除，不使用 Driver、`requestData` 或宿主脚本作断言。这条旅程无需原生桌面构建；夹具不证明实际持久化或进程行为，真实边界由下述供应商验收覆盖。旧合成分发包的 Driver 旅程与独立观察脚本已移除；固定官方 SHA-256 不允许合成包冒充官方安装。

真实供应商验收使用 `integration_test/acp_real_login_test.dart`，设置进程环境 `ANYWORK_ACP_ACCEPTANCE=login` 和独立 `ANYWORK_HOME` 后运行 `cargo xtask test-project --suite desktop --case acp_real_login`；`ANYWORK_ACP_EVIDENCE` 可指定真实组件渲染截图目录。显式准备固定发行、保存/检查账户、用户完成官方浏览器授权、等待原流程自动验证，随后显式查询额度。已有凭据使检查直接通过时，须由用户通过官方入口退出，或为验收进程使用独立用户配置目录；不得删除或改写原有凭据，也不把复用登录状态计为首次浏览器授权。重复运行可复用已保存的验收账户和受管安装。结束后以同一产品及用户配置目录、`ANYWORK_ACP_ACCEPTANCE=restart` 再次运行，验证重启后重新检查及额度读取。人工授权不设测试时限，Google 账号选择、验证码、同意和官方退出由用户完成，工具不操作其凭据。截图导出只遮蔽包含 Windows 用户名的本机安装路径，保留实际认证、版本和额度结果。

通过判据同时要求：真实 `session/new` 成功、服务端实际报告 `1.4.5`、GUI canonical `verified`，以及关闭结果 `completed` / `clean` / `drained`、官方原生测试 runner 成功退出、所属进程全部回收。单独握手、模拟对端和仅启动进程不构成真实通过。报告注明实际平台、代理条件、未覆盖平台和证据位置。

## 28.11 ACP 业务会话与原生内容通路

Host MCP 与混合协作沿本节同一业务会话资源实现，不另建协议连接或 transcript；补充边界见 [28.12](#2812-host-mcp-与宿主指令)。

### 本机 agy 便利发现

官方 CLI 的 ACP 启动方式是 `agy acp`，已有 CLI 登录态由官方程序自行复用；不使用未经确认的 `--acp` 参数，也不复制凭据或保证所有机器已经登录。进入添加 ACP 编辑流程或显式重新检测时，Rust 宿主沿原 executable 解析与进程监督能力检查 `agy --version`、`agy acp --help`。整个探测共用最多 10 秒预算及合计 64 KiB 输出上限，不创建业务会话、不发 prompt、不下载或登录。取消、超限、错误和退出都必须真实收束进程/管道；探测不能成为注册表外的长期进程。

结果区分可用、未找到、不支持 ACP 与检查失败，绑定该编辑实例，普通目录/账户读取不会触发它。本机 agy 入口仅生成 `command="agy"`、`args=["acp"]` 的普通用户定义，或用户明确选择的实际路径；不新增供应商、模板或运行时种类，不将安装状态、检测成功或当前登录缓存写成永久认证保证。缺凭据时沿真实 AuthRequired 指引，已登录不再要求下载受管 server 或重复登录。

检测沿既有显式命令、资源快照与订阅入口接入：start 携带新的 operation ID，cancel 另带其目标 operation ID；客户端同时核对编辑实例、草稿意图与检测操作，迟到结果只作原操作事实，不覆盖新草稿。宿主仅有一个本机检测操作槽位及最近结果，尚未收束时新检测明确 Busy；读取与订阅不派生新操作，取消受理不冒充清理完成。这个具体短操作 owner 在启动前登记责任，持有监督任务 join、进程和管道直到真实收束，纳入原 Studio 关闭流程；等待者退出不能丢失资源，清理未完保留原 owner 供关闭重试。失败/未知结果不自动重发，显式重新检测使用新操作身份；不增加通用任务管理器或永久检测账本。

### 会话与历史

一个 ACP 成员独占一个真实 SDK session，租用同账户连接代次的受管进程与已初始化连接，不独占进程，也不复用认证/额度的探测 session。`pl-acp` 仅消费宿主 I/O 和正式协议类型，不读配置或启动进程。Studio 从唯一用户定义准备账户连接，模板复用原安装校验和进程监督器；业务 cwd 只消费工作区所有者确认的本机目录及已有 worktree，不由连接启动器创建、不从工作区发现服务。SSH 在资源副作用前 Unsupported；AuthRequired 返回真实登录指引，不后台登录。单个成员关闭释放其 session 和租约，不排空共享 SDK 或终止其他成员。

历史、内容及能力完全遵循稳定 ACP v1：New 创建新身份，Load 在响应前通过 `session/update` 回放对端历史，Resume 不回放，List 直接读对端目录。只有实际声明能力才允许发送对应请求，不自动降级或重试。Anywork 只持久化 [17](./17-studio-storage.md#171-数据布局) 的最小产品关联，不保存 transcript、Native history/checkpoint 或完整外部目录，也不以缺少历史猜测对端 idle。

### 唯一协议接收与有界观察

官方 SDK 的类型化回调是唯一 session 更新和权限接收入口，正式会话请求、prompt 结果与 responder 继续使用 SDK；`PreparedRequest.on_receiving_result` 在请求发布前注册有序响应处理，setup/set 结果与通知在同一实例按入站顺序短处理。不能按普通 future 完成时间覆盖协议状态，不同时透传回调和 `ActiveSession` 中的同一批更新，不自建 JSON-RPC 路由表、连接管理器或通用 Thread actor。单一实例只绑定自己的会话，打开失败、取消及迟到事件均校验该实例和当前操作资格；未知会话不能通过任意通知取得成员资格。

Open 在发送 new/load/resume 前交付本次观察入口，同一流保留回放/实时更新及 Ready/Failed，不能先等待 load 完成再订阅。协议源保持原内容块、工具调用更新、配置和权限选项，不伪造 Native review 或重执行 ACP 私有工具。观察待交付窗口最多 64 项、累计 8 MiB；超限或断开明确终止该失效观察并交付内容缺口，不能等待容量阻塞协议驱动、权限、控制或关闭，也不因此取消后台 prompt。缺口不能用持久回放队列、自动 load 或重发补齐。已有活动产品成员取得原实例句柄，不重复启动进程或 new。

同次初始化成功并通过版本门槛后，在业务打开请求前向这条原观察流发布 `Initialized`，携带本次对端声明的正式 `AgentCapabilities`；HTTP 保留官方能力形状，FRB 与 Client 只做显式类型映射，供会话 owner 判断实际 prompt 附件和 load/list/resume 能力。未知能力不推导为支持，未取得初始化值时不启用相应入口；不增加能力探测会话、静态供应商能力表、轮询或第二条显示通路。该事件不代表认证或业务打开成功，原 Ready 与 Settled 的含义保持不变。

业务 `OpenRequest.expected_server_version: Option<String>` 消费准备阶段冻结的版本门槛：通用命令为 `None`，受管模板为已验证发行的精确版本。initialize 成功后、任何 new/load/resume 发送前核对；缺失或不匹配以 `ServerVersionMismatch` 明确失败，不发业务打开请求、不重启补探测，协议 V1 校验不受该可选值影响。

准备 owner 通过 `Session::opened() -> Result<schema::SessionId, Error>` 取得同一次 open 的最终结算，结算只保留真实对端 ID 或真实失败，不复制内容更新或配置列表。它由原有序 setup/fail_open 写入口完成，观察窗口失效不丢结算，重复等待返回原结果，等待者取消不撤销 open；连接先断开或关闭等未成功路径也必须结束等待。观察入口仍在请求前交付，owner 不能消费或转发显示 Observer 来等待 Ready，显示缺口也不能驱动目录提交。这个结算只证明协议打开结果，不证明产品发布、进程或租约已收束。

Studio 的 `AcpSessionOpen` 同时交付 target、可选的唯一观察入口及 `completion: AcpSessionCompletion`；`completion.wait()` 可重复等待原 Preparation 的产品发布结果，不另建协议结算或第二结果状态机。并发冷重开共享同一准备结果，已发布实例返回已完成句柄；`observation=None` 只表示没有新观察流，不能推断发布成功或触发重新 new。接收方先取得完整 open 返回并开始消费回放，不先等待 completion 再开放观察；等待取消不撤销已受理准备，失败仍返回原准备错误。

传输使用 `AcpSessionFrame` 薄封装：首帧 `Accepted { target, has_observation }`，原准备结果只映射一次 `Settled { result }`，原观察逐项映射 `Event { event }`。`Settled` 表示产品发布完成，不冒充带官方 setup 载荷的 Ready；回放事件可早于 Settled。HTTP open 直接返回同次 POST 的 SSE 流，不另建观察注册表、内容缓存或先返回 ID 再重开连接；其他控制和查询使用 target 的独立类型化请求。FRB open 返回持有同一准备与观察资源的具体句柄，逐次读取上述帧；并发 next 明确 Busy，不建立转发生产任务或无界队列。关闭/丢弃观察只释放该观察与等待，不等同于关闭业务成员；真正关闭仍须显式调用原 Session close。无新观察的 resident 流仍交 Accepted 和原准备 Settled，不制造回放或 Ready。Client 归约相同帧、原结果和资格，不建设第二业务状态机。

业务启动失败保留安全且可操作的类型分类：`InstallRequired`（模板尚未准备）、`InstallationInvalid`、`UnsupportedPlatform`、`MissingExecutable`、`InvalidWorkingDirectory`、`InvalidDefinition`、`Io` 和 `Cancelled`。原启动边界的 `Template(PreparationRequired)` 对应 `InstallRequired`，其他模板准备及普通 command 错误分别映射上述类别，不能全部压成 `Preparation`；后者仍表示未进一步分类的产品准备失败。HTTP、FRB 与 SDK-only Client 保留同一类别和固定安全说明，不暴露原始路径、env、凭据或错误输入，不自动安装、重试或重新打开。

### 提交、控制与完成

普通 submit 消费正式 `ContentBlock`，按对端 prompt 能力校验，最多一个活动 prompt，busy 明确拒绝。独立业务驱动同时推进更新、有限命令、控制请求完成和 EOF；配置/权限 RPC 的等待不持有整个会话锁，权限只保留 SDK responder、合法选项及当前请求资格，回答后释放，cancel/close 按协议回答 Cancelled。待决权限独立受最多 64 项、保留数据合计 8 MiB 的资源上限约束，消费观察事件不会释放仍待回答的权限额度；回答后归还额度，超限请求立即回答 Cancelled。权限事件无法交付或观察已失效时，取消失去有效观察通路的待决权限，后续请求不再积存；活动 prompt 与其他控制仍按实际协议结果继续。

中断发送前在原 owner 核对已观察的 runtime/运行资格，取消通知只有 session ID 也不能迟到命中新 prompt。后续 send 的替换输入由原受管操作持有：cancel 当前运行、消费合法尾部并真实收束后再提交，已有替换在途返回 Busy，不建立可靠输入队列。只有真实 PromptResponse 或错误才结束运行，输出文本或 idle 不构成成功，不自动重发。

唯一运行对象只保留一个 `last_completed`：本次实例、递增完成序号、实际结果/错误及最多 16 KiB 的可见摘要与截断标记，供后续结果读取使用；不保留第二执行日志或 transcript。公开 Native 创建/提交请求仍只表达 Native；ACP 使用独立 open/prompt/config/permission/interrupt/close 及会话查询操作，由 HTTP/FRB 做薄类型转换，不经过 Native 模型路由或历史 materialize。关闭与准备责任统一见 [14](./14-runtime-host.md#141-统一装配与激活)，不因远端关闭失败复制另一套资源回收框架。

跨层载荷复用与 SDK 同次锁定的官方 `agent-client-protocol-schema` 数据类型；产品 wire 只补会话/成员身份、实例与运行资格、观察缺口和操作回执。HTTP 保留官方 ACP 序列化形状，FRB 在桥内转换为可生成的显式联合值，SDK-only Client 消费同一业务事件与结果；保留配置缺失/空列表及 select/boolean 的类型差异。产品层不重新解析 JSON-RPC，也不以不透明 JSON 字符串代替内容和配置类型。

### 会话配置与旧模式

模型、思考强度和其他选项只来自当前 session 的正式 `configOptions`，保留 ID、名称、描述、类别、select/分组选择/boolean 类型、候选值、currentValue 和顺序；缺失与明确空数组不同。setup、set 成功结果及 config_option_update 都是完整列表，按上述入站顺序接纳，不把 load 响应前的通知滞后应用。配置变化不写用户服务文件、Profile、目录或 Native 模型路由。

set 的 `configId` 是选项 ID，select 使用原字符串值、boolean 保留 bool；权限响应才使用 optionId。一次最多一个配置修改在途，prompt/权限/控制继续处理；失败只清本次 pending，保留等待期间已接纳的推送，不恢复发起前快照、不重发、不增加配置 revision、ACK 或回读事务。只有跨桥、请求与实际显示闭环完整时才广告 boolean 能力，不因预留类型而提前声明。未知类别原样保留，未知类型沿 SDK 按项容错，不另写配置 schema parser。

仅在 configOptions 缺失时消费真实旧 modes；通过正式 session/set_mode 和 current_mode_update 处理，不把 modeId 填进 configId 冒用 set_config_option。没有配置选项时沿 Agent 默认，不建设静态 ACP 模型目录、专用 effort 接口或 Native workflow 映射。Client 呈现边界见 [25](./25-frontend-state.md#2521-acp-协议内容与目录消费)。

## 28.12 Host MCP 与宿主指令

Host MCP 在原领域运行时之上提供传输无关的服务。`AgentHost` / `SessionRuntime` 继续唯一拥有成员、权限、派发、报告、工作区及生命周期；`pl-studio-mcp` 的共享 handler 通过 `HostTools` 端口读取原工具目录并执行领域调用。HTTP 与 stdio 是并列入口，复用同一 handler，不互相转发。

initialize 后，真实声明 `mcpCapabilities.http` 时准备实例独占的 rmcp Streamable HTTP 服务，监听 `127.0.0.1:0` 的 `/mcp`，handler 在原进程直接调用领域端口。否则准备原实例本地 IPC 端点，并注入 ACP v1 标准 stdio 定义，由 Agent 启动宿主原生 `pl-studio-mcp --stdio`；该程序是正式 MCP server，通过 IPC 调用原运行时，stdio 路径不创建 HTTP MCP listener。HTTP/SSE 为 false 不等于没有 MCP，外层 ACP stdio 与内层 MCP stdio 是独立通道。new/load/resume 共用准备与选择逻辑，resume 仍受其真实能力约束；准备失败明确返回错误。能力声明、接收配置、实际连接与真实工具调用分别核对，不以注入成功推断可用。

领域端口仅交付工具目录和执行调用；`HostOperation` 为现有九项操作的封闭集合，`HostInvocation` 携带操作和参数，`HostResult` 携带结构化结果及业务错误标记。目录由原声明投影，不回解作者侧 `ToolDefinition`，不另写 schema。MCP 握手、request ID、通知和结果封装由各入口的官方 rmcp server 处理，不跨 IPC 传递 JSON-RPC envelope、HTTP MCP session 或协议控制消息，不进行第二次 MCP 握手。

IPC 在 Linux/macOS 使用私有短路径 Unix socket，在 Windows 使用拒绝远程连接并限定本机用户的 named pipe，复用锁定 Tokio、h2 与 prost。每个 h2 stream 对应一次目录读取或执行调用，protobuf 外层承载原 JSON 参数/结果；收发上限为 4 MiB，超限明确失败，不截断。h2 负责并发关联、流控、reset 和连接关闭，不新增请求账本、业务 deadline、重放、重连或结果缓存，也不把产品调用塞入 SSH helper 协议。

原实例固定可信 caller、具体运行代次及原 Session 的弱访问入口；成员发布前允许发现、拒绝域调用，发布后逐次校验原资格。HTTP bearer 经标准 header 校验；stdio 只从 `ANYWORK_HOST_IPC_ENDPOINT`、`ANYWORK_HOST_IPC_CAPABILITY` 临时环境取得本地 IPC 端点与每实例随机 capability，不放入 argv。IPC 每次请求验证 capability，连接不能更换调用者；调用参数不能提供可信 caller 或 call ID。真实 call ID 由原运行时生成，MCP/IPC request ID 不充当持久消息 ID。凭据不进入模型内容、参数、持久配置、历史或日志，实例关闭后失效。

桌面安装包分发并校验当前 Linux/Windows/macOS 宿主原生 `pl-studio-mcp`，资源在 `data/host-mcp/<target>/`，由显式 `HostMcpSource` 解析。bundled 缺失或校验不符明确失败，不回退 PATH；非打包入口使用显式 external 来源。复用原工程的摘要、压缩及映像租约能力，传给 Agent 的绝对命令路径必须可跨进程使用，原实例持有映像直至进程树回收。ACP 本机进程沿统一 native Executor 创建和回收；SSH helper 的两种 Linux 前台 server 资产保持独立职责，不代替 MCP 服务程序，也不承担本地监督 worker 角色；不在业务会话下载代理或复制临时凭据到资源包。

宿主 MCP 工具统一使用 `anywork_` 前缀：`spawn_agent`、`send_message`、`list_agents`、`wait_agent`、`interrupt_agent`、`close_agent`、`list_agent_profiles`、`list_delegation_models`、`get_delegation_model`。具体声明按 root/child、派发模式与可执行目录裁剪；模型查询仅为 Native 自动选模服务。Native 工具名称及用户配置的外部 MCP 保持原定义。协作、查询与参数资格复用 [12.3](./12-collaboration.md#123-子智能体派生spawn_agent与动态参数模式) 的业务入口，不增加 MCP 专用协调器、能力管理器或另一成员目录。

宿主指令由共享项目指令、实际角色、工作区与已提供的协作能力组成，不套用未支持的 Native workflow。对端声明 `sessionCapabilities.systemPrompt` 时，通过正式 `systemPrompt` 的 `append` 模式传入；未声明时，在用户 prompt 内容前附独立的宿主指令文本块，用户原内容与附件保持独立。两种传递方式使用同一内容来源；不使用 `override` 替换 agent 原指令。

宿主指令要求派发、成员管理、结果等待与关闭使用 `anywork_` 工具。前缀帮助识别，提示词引导选择，两者不构成权限控制。稳定 ACP 没有统一关闭 agent 自带工具的开关；客户端不声明文件或终端能力，只限制由客户端执行的 ACP 方法，不能禁止 agent 自己运行工具。`systemPrompt` 同样不改变工具可用性、MCP 服务、权限或会话配置；具体服务的私有选项不解释成通用禁用策略。

listener、handler、IPC 连接驱动和请求任务的 join 直接归原 ACP 实例资源，stdio 程序随原受监督进程树收束。MCP 取消、IPC reset/EOF 只结束等待与尚未受理的调用；原 `AgentOperations` 等 owner 已接管的操作继续由其收束，取消 `wait_agent` 只结束观察。断连可能发生在受理后，不宣称“未执行”，也不重放。关闭顺序遵循 [14](./14-runtime-host.md#142-输入受理与驱动)，部分失败保留原句柄供原流程重试，旧凭据不能控制重开实例。不建立共享 listener 租约表、持久 cursor 映射、ACP 结果数据库、Native 父伪装或旁路关闭；不提供公网或 experimental MCP-over-ACP。
