# 28 - ACP 接入、服务器准备与认证

本文定义外部智能体的 ACP（Agent Client Protocol）接入、受管服务器准备与认证边界。各 crate 职责遵循 [02 - Crate 边界与职责](./02-crates.md)，配置与凭据管理遵循 [20 - 配置与凭据管理](./20-config.md)，运行态订阅与进程退出遵循 [18 - Studio 状态、工作区与执行快照](./18-studio-state.md)。当前阶段仅支持按需准备并运行产品固定指定的 Antigravity Server `1.4.1`，提供受管账号配置、连接检查与登录能力；不开放用户自定义可执行程序、启动参数（`argv`）或任意版本，也不代表 ACP 会话聊天、模型选择、宿主工具或子智能体能力已启用。实际完成度以验收记录为准。

## 28.1 接入边界与所有权

原生（Native）模型账号与 ACP 接入在同一个产品设置入口展示，但在数据模型中通过封闭类型分支各自独立存储。ACP 不属于 HTTP 模型协议，不得通过空端点、空模型目录或伪造 API 密钥混入原生模型路由。底层协议客户端仅消费受监督的标准输入输出流（I/O）、已校验请求、进度通知与取消信号，自身不读取配置文件、不派生操作系统进程，也不持有产品级状态。

Studio 认证所有者（Owner）统一持有接入配置与固定受管发行版的冻结身份、操作代次、探测工作区、子进程树、通信管道、取消令牌与汇合句柄（Join Handle）：

- **受管启动来源**：启动命令严格取自内置产品发行清单及通过完整校验的受管安装目录，拒绝接受来自账号配置、公开 API 或客户端提交的程序路径与参数，不检索系统 `PATH`，也不回退执行历史遗留的自定义路径。安装包完整性校验由安装边界负责，认证任务持有运行前校验、取消与任务汇合责任；耗时 I/O 不进入 `Settings` 提交锁，也不复制第二套校验器。Linux 宿主复用既有受监督工作进程（Worker），其他平台复用统一后台进程工厂，一律不使用裸 Shell 后备路径。
- **标准流隔离与脱敏**：官方 SDK 负责协议编解码、请求路由与错误分类，子进程 `stdout` 仅作为纯协议字节流消费；`stderr` 由独立有界缓冲区消费并脱敏，不原样发布至界面，也不从中正则提取认证链接或登录状态；进程环境变量与日志中不得携带可公开的凭据副本。
- **桌面显示环境白名单**：子进程运行环境按精确白名单透传官方程序打开图形登录窗口所需的宿主显示认证上下文。Linux X11 环境下，`DISPLAY` 与继承的 `XAUTHORITY` 必须成对传递（仅传递既有文件路径，不读取或记录认证文件内容，不放宽显示服务器访问控制，也不通过浏览器垫片绕过官方认证流程）。同时按原样透传宿主既有的 `XDG_SESSION_TYPE` 与 `XDG_CURRENT_DESKTOP`，使官方程序及其唤起的浏览器遵循实际显示平台与桌面服务；若宿主未设置则保持缺省，不猜测或合成环境变量，也不强制指定浏览器凭据后端。隔离显示验收使用与目标虚拟显示一致的会话上下文，不混用操作者真实桌面的显示标识。

## 28.2 认证观察与操作身份

认证状态构成独立的版本域，包含十种状态：`未检查`、`检查中`、`需要登录`、`登录中`、`验证中`、`收束中`、`认证通过`、`取消中`、`已取消`与`失败`。运行中阶段携带操作身份（`operationId`），`需要登录`阶段保留服务端实际声明的认证方法列表，`失败`阶段保留发生阶段、类型化错误原因与可恢复操作指引。`认证通过`状态记录服务端身份与检查时间戳，仅代表该次探测时刻的观察结论，不代表永久在线；进程重启后需重新检查，不能由历史成功记录或 `authMethods` 非空直接推断当前凭据有效。

协议层虽允许服务端身份字段可选，但产品接入强制要求实际服务端版本精确匹配 `1.4.1`；缺失版本或版本不符均直接判定失败，既不用本地账号名称或内置常量修补服务端报告，也不发布`认证通过`状态。服务端返回的未知或未实现认证方法统一归入明确的不支持类别，不映射为其他既有认证方式。

配置保存／删除与连接认证解耦：保存配置成功后立即返回权威设置快照，后续连接失败不推翻已保存事实。连接检查、发起登录与取消操作均为显式命令；只读查询、主题订阅、进入设置页或组件重建均不会触发外部进程启动。命令调用快速返回已受理的操作身份，由认证所有者在后台推进并通过独立的 `acpAuth` 主题发布状态，避免阻塞 FRB 或 HTTP 请求等待人工完成登录。

每个接入账号在同一时刻至多运行一个认证操作：

- **幂等受理与有界去重**：重复发起相同 `start` 命令不会派生第二个进程；取消命令必须命中当前活动操作。`operationId` 绑定账号、连接代次与完整操作意图，同一标识不得复用于不同意图。运行时保留已受理操作身份以阻止完成后重试产生重复副作用；去重缓存达容量上限时直接拒绝新操作，不静默淘汰旧身份引发重放。
- **代次撤销与串行收束**：供应商类型变更、固定发行连接身份变化、账号删除或应用退出均会撤销旧连接代次（仅修改账号显示名称不撤销代次），旧代次的迟到结果一律丢弃。在旧代次资源尚未完全收束前，不抢跑启动新代次覆盖旧句柄；清理失败时保留所有者供显式重试。配置观察携带单调递增的 `Settings` 修订版本，若配置变更后旧资源仍在收束，新配置状态显示忙碌的`收束中`，待底层资源完全释放后再转为`未检查`。终态发布与准入槽位释放在同一所有者锁提交中原子完成，消除“界面显示已空闲但新操作仍被 `Busy` 拒绝”的时间窗。
- **取消与关闭截止边界**：配置提交、身份代次撤销与认证准入共享串行提交边界；`Settings` 只读投影不补建或复活认证槽位。业务取消与关闭截止点在同一所有者锁内裁决：已进入`收束中`的操作拒绝新的业务取消请求；此前已被受理的取消在资源收束完毕后保持`已取消`终态，不被在途认证成功结果覆盖，且若收束清理自身失败仍须如实报告。

## 28.3 认证成功判定与探测闭环

协议客户端仅协商已实现的 ACP v1 能力。连接检查流程依次为：先验证本地受管安装完整性，启动进程并完成 `initialize` 握手，校验服务端报告的版本号精确为 `1.4.1`，随后在接入专属的空探测工作区上调用 `session/new`（传入空 `mcpServers` 列表）。`session/new` 调用成功即证明当前认证可用；返回 `AuthRequired` 表示需要登录；其他错误则保留原错误分类。由于协议无通用的 `get_auth_state` 接口，`authMethods` 存在、子进程存活或外部浏览器窗口关闭均不能作为登录成功的证明。

宿主向通用 ACP 认证请求传入必填的 `expectedServerVersion`；协议客户端在收到 `initialize` 响应后、发起任何 `authenticate` 或 `session/new` 调用前，按原始字符串精确比对服务端版本（不裁剪空白字符，也不用显示名称替代）。若字段缺失或不相等，立即返回强类型的 `server-version-mismatch` 错误。协议客户端内部不硬编码 Antigravity 版本常量，由产品运行时从唯一固定清单注入期望版本并映射错误。

发起登录时先核验服务端支持的实际认证方法，仅对 `agent` 类型方法调用 `authenticate`，等待协议返回成功后再调用一次 `session/new` 完成复核。`terminal` 类型认证必须具备专门实现后才允许声明支持，不得向其发送 `agent` 认证请求；URL 引导认证（Elicitation）同样仅在强类型处理器、安全 URL 校验与用户显式同意机制齐备后才可声明。产品不劫持浏览器、不自建本地 OAuth 回调服务，也不抓取或解析官方程序管理的登录令牌。

认证探测过程不发送提示词（Prompt）、不调用语言模型、不访问用户业务项目目录，也不挂载可执行工具。探测创建的外部 `session` 属于真实服务端资源：探测结束时按已协商能力显式关闭该会话，并收束连接与子进程；若服务端未声明会话关闭能力，宿主仍须完整回收该独占子进程。当 `session/new` 结果未知时不自动重发；终止本地子进程不等同于在服务端销毁会话或吊销登录凭据。

## 28.4 取消、失败分类与退出回收

协议分发、配置锁与界面调用均不阻塞等待人工操作、耗时 I/O 或子进程退出。外部 RPC 请求、管道消费与进程监督任务均由可观察的所有者持有；取消请求或丢弃 Future 本身不代表子进程已退出。触发取消时先封闭准入并下发终止信号，在有界时限内终止并等待整个子进程树及管道读取任务退出，同时保留已观察到的协议结果；若资源清理失败，不得伪报正常收束，也不因认证逻辑已成功而忽略尚未退出的底层进程。

已取得探测 `session` 身份后的协议级会话关闭尝试独立于业务取消，受关闭预算约束；远端会话关闭失败与本地进程回收失败按各自阶段分别记录，不误报为输出预算超限。协议请求预算与 SDK 连接排空预算各自有界；当连接排空超时后，立即释放局部 I/O Future，并将物理进程与剩余管道的强制终止及等待责任交回宿主所有者。进程等待系统调用报错不代表进程已退出；已观察到的管道收束错误跨重试保留，不被后续重试成功掩盖。

账号删除、运行时提前退出（Early-Exit）与应用关闭统一走认证所有者的取消与汇合路径，共享全局关闭时间预算。设置页面仅持有只读观察租约，离开页面不会中断已启动的登录流程，返回页面时直接消费当前权威状态。关闭失败进入强类型的 `Degraded` / `Failed` 状态并保留重试责任，不发布虚假的 `Clean` 结论；在进程与管道确认完全停止前，账号状态维持携带 `operationId` 的非终态。

错误分类严格区分以下场景：`需要准备`、`安装损坏或不合格`、`宿主平台不支持`、`服务端版本不符`、`启动失败`、`协议协商失败`、`需要认证`、`认证方法不支持`、`认证失败或已取消`、`探测会话失败`、`协议连接断开`、`操作超时`、`操作已过期`及`资源关闭失败`。不可信的底层 RPC 错误由私有脱敏包装器持有，对外格式化与错误链仅暴露安全错误枚举和错误码，防止通过 `Debug` 输出或嵌套错误源（`source`）泄露原始消息、认证链接或凭据。界面呈现与截图验收分别遵循 [19 - Studio 界面与交互](./19-studio-ui.md) 与 [24 - 测试策略与门禁](./24-testing.md)。

## 28.5 官方服务器来源与受管准备

受管服务器准备属于 Studio 产品层能力，独立于 ACP 协议客户端与原生模型适配器。产品仅内置支持 Antigravity Server `1.4.1`，不开放通用扩展市场、任意版本／下载地址或自定义 Shell 安装脚本。目标包按运行 Studio 后端的受支持操作系统（Windows / Linux）与处理器架构（`x86_64` / `aarch64`）匹配，不以远程客户端的显示平台决定下载目标。账号模板仅描述静态能力与官方条款说明；读取模板、设置、安装状态或订阅主题均不发起网络请求。

内置固定发行清单基于官方注册表快照 `3d3e0b9ab789a64364c2e3e9df0acd689eb9a366` 中的 `1.4.1` 描述生成，运行期不访问远程 `latest` 注册表。各宿主目标的归档路径均相对于官方基址 `https://dl.google.com/agy-extensions/releases/`：

| 宿主目标（Target） | 相对归档路径 | 包内可执行入口 | 固定启动参数（`argv`） |
| --- | --- | --- | --- |
| `linux-x86_64` | `linux/agy-acp-server-1.4.1-linux-x86_64.zip` | `agy_acp_server.par` | `["--uid="]` |
| `linux-aarch64` | `linux/agy-acp-server-1.4.1-linux-arm64.zip` | `agy_acp_server.par` | `["--uid="]` |
| `windows-x86_64` | `windows/agy-acp-server-1.4.1-windows-x86_64.zip` | `agy_acp_server.exe` | `[]` |
| `windows-aarch64` | `windows/agy-acp-server-1.4.1-windows-arm64.zip` | `agy_acp_server.exe` | `[]` |

显式准备操作按当前宿主平台冻结清单中的供应商标识、版本号、目标平台、归档路径、摘要策略、可执行文件名与固定 `argv`。后续版本升级只能通过更新产品代码清单并完成验证来交付。模板的 `supportedVersion` 字段与内部启动资格校验消费同一份清单，客户端不硬编码第二份映射表。

分发包下载仅接受 `https://dl.google.com/agy-extensions/releases/` 下的 HTTPS ZIP 归档；每次 HTTP 重定向均重新校验来源域名与路径前缀，拒绝携带用户凭据、非默认端口、越权来源或非 ZIP 格式的响应。包内可执行入口必须为普通文件，固定 `argv` 直接作为进程参数数组传递而不经过 Shell 字符串拼接；禁止将下载元数据注入子进程环境变量，严格维持既有的 22 项必要宿主环境变量白名单。

由于官方 `1.4.1` 清单未提供发行方 SHA-256 摘要，产品在信任边界中如实标注为“官方 HTTPS 来源”（未来若固定清单提供发行方摘要则强制校验，且不通过网络动态修改该校验策略）。TLS 传输加密、ZIP 内部 CRC32、本地落盘后计算的 SHA-256 摘要及安装回执仅用于本地完整性核验，不包装成“发行方数字签名”或“上游发布摘要校验”。产品不复制、解析或重置官方程序的登录凭据，也不将专有二进制程序打包进产品安装包、源码仓库或验收截图附件。

## 28.6 安装操作、进度观察与终态收束

客户端通过 `read_acp_install_state` 读取独立安装快照，通过 `start_acp_install` 与 `cancel_acp_install` 提交显式安装或取消意图。命令调用快速返回操作回执与权威快照，耗时的网络下载与磁盘解压不持有 `Settings` 提交锁，也不占用 `acpAuth` 认证状态。安装状态主题为 `acpInstall`，回执资源名为 `acp-install`，拥有独立的修订版本号与运行时所有者纪元（Owner Epoch）。

安装状态机包含：`未准备`、`解析固定发行`、`等待资产锁`、`下载中`、`校验中`、`解压中`、`发布中`、`收束中`、`就绪`、`取消中`、`已取消`与`失败`。当前重试次数与下载字节进度对外可观察（进度汇报实际已处理字节数与可选总字节数，当服务端未返回总长度时不伪造百分比）。已有缓存校验与全新下载走同一操作链；`就绪`状态携带安装身份、版本／平台、只读诊断程序路径、来源信任级别、准备完成时间戳及是否复用已有安装标记（固定 `argv` 保留在内部启动边界，不进入账号编辑或保存 DTO）。所有已受理操作的终态均保留 `operationId` 供前端草稿与迟到回执关联；安装`就绪`不代表账号已保存或已通过认证。

每个供应商与宿主目标组合在同一时刻至多运行一个安装操作：

1. **准入槽位与任务回收分离**：相同 `operationId` 与相同意图的重复请求幂等返回；同一 `operationId` 携带冲突意图或忙碌期间收到不同新意图均直接拒绝。运行时最多保留 4096 个已受理操作身份，容量耗尽时拒绝新请求。任务登记、关闭准入、取消裁决、终态提交与准入释放在同一所有者锁边界内完成。当前操作槽位代表业务准入占用，任务回收登记代表底层汇合（Join）责任：当安装终态已确定提交并释放准入槽位后，后继操作不再因前一任务的尾部清理而被 `Busy` 拒绝，但前一任务句柄仍由运行时持有直至观察到真实汇合终态；若资源尚未收束完毕，则继续维持 `Closing` 状态与准入占用。
2. **跨账号共享与跨进程文件锁**：受管安装属于宿主级共享资产而非单一账号私有属性。多个观察者可同时订阅同一安装进度，显式取消会作用于当前共享安装操作并在界面说明其影响范围。跨进程并发安装同一资产通过文件锁互斥，等待文件锁的过程支持取消；取消本进程的锁等待不会终止另一个正在持锁安装的进程。删除单个 ACP 账号不会取消正在进行的共享安装，也不删除已就绪的安装目录。
3. **有界进度合并与发布提交点**：安装所有者统管下载、校验、解压任务及临时文件／文件锁的回收。下载进度采用有界合帧更新，不建立无界队列积压逐块字节事件。底层下载器负责断点续传、重试与文件句柄关闭，取消时必须等待下载与解压任务实际返回，不以丢弃 Future 冒充收束。固定清单解析不联网；单次安装下载总预算为 60 分钟，最多自动重试 3 次，连接与读取超时独立受控。一旦进入原子`发布中`阶段即越过业务取消截止点，已成功发布的安装如实保留；发布完成后的暂存目录清理错误与“安装已就绪”事实分开报告。

安装错误保留发生阶段及细分类型：`不支持的平台`、`来源拒绝`、`网络故障`、`超时`、`体积超限`、`摘要不符`、`非法 ZIP 归档`、`入口程序缺失`、`缓存损坏`、`磁盘 I/O 错误`、`系统正忙`、`操作已过期`、`已取消`与`资源关闭失败`。对外错误链不暴露原始下载 URL、代理服务器凭据或未裁剪的底层库异常。

## 28.7 安装包资格校验与本地文件系统边界

安装包内的所有安全成员文件均须完整提取保留，不能仅提取主程序而遗漏同目录下的辅助文件。压缩包元数据与实际解压字节流双重受控：ZIP 归档体积不超过 **1 GiB**，解压后总大小不超过 **4 GiB**，单个成员文件不超过 **2 GiB**，成员总数不超过 **512 个**；未知传输长度同样受实际写入字节上限约束，计数器算术溢出直接按失败处理。

格式解析与 CRC32 校验复用成熟 ZIP 组件；产品层在此之上显式拒绝绝对路径、父目录越界（`..`）、Windows 路径别名与设备保留名、重名或大小写折叠冲突、加密条目、符号链接（Symlink）及非常规文件／目录。解压过程仅写入新建的私有暂存目录（Staging），严禁跟随预先存在的链接跳出安装根目录，且安装回执保留文件名不得与包内成员冲突。Unix 平台落盘文件仅赋予必要的用户读写与可执行权限，剥离 `setuid`、`setgid` 及组／其他用户写权限。

ZIP 内容完整性以中央目录（Central Directory）声明与实际解压数据流计算出的 CRC32 及压缩／解压大小一致为准，局部文件头（Local Header）的路径、压缩方法、通用标志位及非占位大小同样须保持一致。对于采用数据描述符（Data Descriptor）或 ZIP64 局部占位的条目，由底层成熟组件解析尾部结构并传播格式错误，产品层不手写二进制解析器，也不因数据描述符中的重复元数据字段与中央目录存在无害差异而关闭实际解压数据的 CRC32、SHA-256 及安装回执完整性校验。

本机安全边界遵循标准桌面应用威胁模型（详见 [04 - 安全与权限策略](./04-security.md)）：重点防范不可信网络分发内容、预先存在的符号链接／重解析点（Reparse Point）、路径遍历越界及损坏安装，不承诺抵御已获得当前操作系统用户同等权限或管理员权限的本地恶意进程。`StudioHome` 及其祖先目录必须位于宿主选定的受信任路径下；任何可被其他非特权主体并发改写的公共共享目录均不可作为受信任锚点。所有产品自有管理目录与暂存目录均按当前用户私有权限创建并核验：

- **Unix 权限核验**：创建目录时显式指定私有权限模式，不依赖进程默认 `umask`；复用已有目录或文件前直接检查真实权限位，不先自动修改权限来掩盖已被篡改的宽泛写权限。
- **Windows ACL 与所有者核验**：依托受信任用户目录及其操作系统继承访问控制列表（ACL），在使用新建或既有受管对象前校验实际所有者与自主访问控制列表（DACL）。私有访问仅允许当前用户、`SYSTEM` 与 `Administrators` 组（仅供子对象继承的 `CREATOR OWNER` 模板按其不作用于当前对象本体的操作系统语义处理）。遇到空 DACL 指针、未知复杂权限条目、无法查询权限或存在其他主体授权时一律明确拒绝，不静默修改既有 ACL，也不将常见默认环境通过外推为所有企业域控环境均兼容。
- **全路径覆盖与有界目录遍历**：固定下载目标、下载器派生的分片／旁路文件（`.part` / Sidecar）、文件锁、安装回执及最终发布目录均纳入同一受管路径权限检查范围，枚举目录时不静默跳过异常链接或未知成员。ZIP 中央目录解析以有界缓冲区逐条处理并统计成员数，不在校验上限前一次性按不可信头部声明分配全量数组，也不在校验前自动合并同名条目。

所有成员通过完整性校验、确认主程序入口存在且版本化安装回执落盘成功后，才执行原子目录发布。发布操作绝不覆盖已存在的就绪目录；复用既有安装前须重新核对回执与全体成员完整性，发现损坏时保留现场并明确报错，不静默覆盖可能正被某个账号使用的目录（暂存与稳定安装目录的具体布局与保留边界见 [17 - Studio 存储、单实例与恢复](./17-studio-storage.md)）。

目录发布的持久化同步遵循目标操作系统的真实文件系统原语：Unix 在更新权限后对文件、嵌套子目录、重命名源目两端及新建祖先目录项执行 `fsync`；Windows 对文件执行刷盘并依赖同卷穿透写入（Write-Through）移动语义，不以空操作伪装 Unix 目录同步。若底层同步调用失败，则保留已提交或待确认状态而不报告`就绪`；进程重启或用户显式重试时重新校验既有安装完整性。

## 28.8 服务器准备与账号配置的边界

添加 ACP 账号采用“先准备受管服务器，就绪后由用户显式保存并连接”的分步流程：服务器准备失败不会创建残缺账号；准备成功但用户未保存或保存失败不会卸载已就绪的服务器资产；配置保存成功但后续连接认证失败不会回滚已保存的账号配置。账号配置仅持久化稳定 `accountId`、`provider` 与显示名称，可执行程序路径完全由固定发行资产决定，不设“受管（Managed）／本地自定义（Local）”切换开关，也不通过路径前缀猜测安装合法性。

配置模式版本 `24 → 25` 执行显式迁移：保留旧 ACP 账号的 `accountId`、`provider` 与显示名称，剥离旧版 `program` 与 `args` 字段的执行语义（旧字段仅在迁移解码边界读取，同时保留备份与恢复材料，不删除旧目录或官方凭据，也不在迁移期间静默发起网络下载）。迁移后若本地尚无匹配的 `1.4.1` 受管安装，则保留账号并在界面提示用户执行准备；若本地已有同描述符的完整受管安装，则校验通过后直接复用。修改账号显示名称不触发重新下载、重新认证或连接代次变更。自动后台升级、一键卸载及历史版本清理不在当前版本范围内。

### 28.8.1 跨层接口收敛清单

- **`AcpAccountUpdate` 与 `AcpAccountSettings`**：更新请求仅含 `accountId`、`name`、`provider`；设置快照另含单调递增的 `connectionRevision`。
- **`AcpAccountTemplate`**：以 `supportedVersion` 取代旧的 `defaultArgs`，保留宿主平台安装支持标记及官方说明／条款链接。
- **`AcpInstalledServer`**：仅保留只读的 `program` 路径用于诊断展示，不再向客户端暴露 `args`；安装回执内部仍完整记录固定启动身份。
- **认证失败枚举扩展**：新增 `preparationRequired`、`installationInvalid`、`unsupportedPlatform` 与 `serverVersionMismatch` 四类强类型错误；前置安装校验归入 `prepare` 阶段，而 ACP 协议层版本不兼容则保持独立的 `unsupportedVersion` 错误。
- **独立版本域与旧字段拒绝**：配置保存、服务器安装与连接认证各自维护独立的 `revision` 与 `ownerEpoch`。HTTP、FRB 与配置文件的当前模式均严格拒绝传入旧版 `program` / `args` 执行字段。
