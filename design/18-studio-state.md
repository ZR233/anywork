# 18 - Studio 状态查询与领域生命周期

本文是命令查询分离（CQS）边界、公共快照、按需激活、应用关闭、自动标题生命周期与产品投影的唯一权威源；存储与检查点契约见 [17](./17-studio-storage.md)，界面呈现契约见 [19](./19-studio-ui.md)。

## 18.1 命令查询分离（CQS）

Studio 遵循命令查询分离原则：查询只读取所有者已发布的权威快照；初始化、激活、扫描技能或配置模板（Profile）、故障修复、重连与关闭只能由显式类型化命令触发。组件重建（rebuild）、事件流重同步与 `read*` 查询不得写入 SQLite 或配置文件、访问网络或创建运行时所有者。进程运行期间，项目（`Project`）、会话（`Thread`）、智能体（`Agent`）、工作流（`Workflow`）、恢复（`Recovery`）及服务目录的内存所有者是活动事实源；会话 SQLite 的最新检查点提供按需激活基线，历史记录与累计计量在同一事务中保存，调用日志独立用于调试分析。

## 18.2 公共快照

### 通用错误与领域独立状态

- **通用错误契约**：`StudioError` 保持稳定的 `code`、`message`、`retryable`、`correlationId` 与可选 `details` JSON 错误体。Rust 动态详情字段定义为 `Option<Box<serde_json::Value>>`，避免协议 SDK 的 JSON 特性合并放大每条错误返回值体积；这不改变 JSON 序列化结构、空值省略规则或 FRB 的脱敏详情契约。
- **ACP 认证状态**：使用独立的 `acpAuth` 主题（topic）、权威基线与修订号（revision）；只读查询不启动外部程序、不检查凭据。保存或删除属于设置（Settings）命令，检查连接、登录与取消属于认证操作命令，返回稳定的操作身份并由状态流确认进展。认证后台先验证产品固定 `1.4.1` 版本安装，再派生进程；该前置验证不触发下载、不进入设置提交锁，缺失、损坏或平台不支持均返回类型化失败。同一接入在同一时刻只允许一个操作，相关配置变更、删除或进程退出会撤销旧代次，迟到结果不得回写。认证所有者纳入统一的早期取消与关闭汇合（shutdown/join）编排，页面观察不持有其关闭权；状态、成功判定及失败保存契约见 [28](./28-acp.md)。
- **ACP 服务安装准备**：使用独立的 `acpInstall` 主题、权威基线与修订号；只读读取不访问网络、不扫描或修复安装。显式开始或取消命令由安装所有者持有，同一供应商与宿主目标在同一时刻只允许一个操作，所有已受理状态（含终态）均保留操作身份。安装准备不保存账号、不启动认证，页面仅持有观察租约；应用退出必须锁闭准入并收束下载、阻塞文件任务及文件锁，纳入统一关闭报告。版本与来源仅由内置清单确定，命令不接受用户自定义程序路径、参数或版本。阶段、来源与发布成功条件见 [28](./28-acp.md)，文件保留边界见 [17](./17-studio-storage.md)。
- **账号用量检查**：按账号（`Account`）发布独立的成功、失败、缺少凭据或不支持状态。单个账号查询失败仍是本次观察的有效结果，不丢弃其他账号的新结果，也不升级为所有卡片共享的命令错误；仅当观察协调或持久化失败时才使整个刷新命令失败。用量检查以必填账号 ID 为目标，HTTP 命令入口为 `POST /api/v1/runtime/account-usage/{account_id}/check`，只读快照继续按领域查询。“全部刷新”是多个单实例检查的并发编排，而非等待所有账号返回后才发布的整批检查。联网阶段不持有全局配置或用量命令锁，结果在短提交边界合并至当前快照并仅更新所属实例。不同实例可并行执行并分别发布，同一实例同一查询身份的重叠检查自动合并；删除账号或修改查询输入后，旧结果不得写回。账号只读描述符的 `usageQueryRevision` 是配置所有者持有的非机密按实例查询身份，仅在额度查询输入（服务地址、模板、有效凭据）变化时推进。该身份与运行时所有者代次（`epoch`）共同解释，不同于全局设置修订号，不随名称、默认路由或在线模型目录观察推进，也不持久化为用户配置；严禁以凭据原文或凭据哈希作为公开查询身份。自动加载与手动刷新消费同一身份及结果归约器（reducer），客户端需求契约见 [25.7.1](./25-frontend-state.md#2571-账号用量需求)。
- **会话最近用户消息时间**：会话目录 DTO 的 `lastUserMessageAt` 为可空 Unix 秒级时间戳，仅由成功受理的用户输入推进，与普通 `updatedAt` 分离。Rust 协议、FRB DTO、Dart 领域模型与目录增量均传递同一事实；运行观察、标题更新与配置变更保留该值，不因迟到快照回退。已接受的排队输入计入推进，系统或智能体输入、失败提交与恢复重放不计入。目录排序与版本化游标仅消费会话元信息，不从历史记录回填；字段缺失与保存语义遵循 [17](./17-studio-storage.md)。

账号用量的查询阶段与结果必须独立表达：尚未查询、查询中、成功、不支持、缺凭据和失败均可观察；逐账号开始和结束均由既有用量所有者发布。失败保留同一查询身份下最近成功的金额/额度及时间，不以失败记录覆盖有效值，也不将旧身份的成功值冒充新凭据/端点的当前结果。计费策略与查询健康互不推导。缓存更新与加载继续归该所有者；结构变化在明确迁移边界保全，不由前端维护第二份 last-good。

### 启动聚合快照与会话工作区状态

服务端启动快照聚合 `projectDirectory`、`threadDirectory`、`agentDirectory`、`modeCatalog`、`settings`、`recovery`、MCP/LSP、`accountUsage`、模型统计、根会话费用、`agentProfiles`、持久化队列与更新器（`updater`）状态。会话工作区（`ThreadWorkspace`）单独包含当前状态、待处理交互（`pending Interaction`）、`ThreadRuntimeView`、工作流投影与计划（`Plan`）投影；时间线（Timeline）内容通过独立的小页查询、尾部订阅与详情读取交付，不放入工作区轻量状态，且不设独立的 `taskDirectory`。客户端仅将聚合读取用于一次性类型化引导（bootstrap）并拆入各自只读模型，正常命令成功后不重读聚合状态。运行时每次实例拥有独立的 `owner epoch`，引导快照与命令资源戳（`ResourceStamp`）引用同一 `epoch`；客户端订阅尝试次数与主题重连代次不得替代业务 `owner epoch`。

会话目录条目携带会话工作区模式（`local | worktree`）与会话工作区路径 `workspacePath`，只读投影作为侧栏与会话展示的权威事实；GUI 不自行推导、不本地改写，也不按模式分别读取项目路径或工作树路径。设置快照以 `modeModelRoutes` 暴露全局工作模式默认选择器，并继续以 `roles` 暴露四个系统子智能体路由；会话运行时快照另行暴露当前会话的类型化 `modelRoute`、`revision` 与 `available` 状态。两者职责独立，GUI 不使用模式默认值覆盖已有会话的路由。

项目目录同时发布工作区 `kind`（`project | standalone`），使所有消费者能明确区分用户项目与非项目会话的内部归属；内部归属仍可按稳定 ID 查询会话，不能在传输层过滤掉而使 Thread 丢失父归属。显式 `prepareStandaloneWorkspace` 命令返回包含已登记归属的版本化项目目录快照，并经既有项目目录事件发布；Client 通过同一目录归约入口按真实修订采纳，不能将没有目录修订的单个实体插入目录镜像或伪造修订。成功响应必须代表运行期目录已经发布；若调用方取消发生在持久化与发布之间，重试须补齐同一 canonical 归属的发布，不得仅凭存储存在返回假成功。该命令可重复调用，但不创建 Thread、不提交输入、不修改全局模型路由。用户项目的打开命令不将内部归属转换为普通项目。具体目录位置、创建与迁移契约见 [17](./17-studio-storage.md)。

设置快照另行暴露新会话分发模式与偏好默认值；会话目录与运行时投影保存实际的 `delegationMode` 与 `delegationPreference`，不随全局默认值变更而回写。智能体目录包含可空的类型化模型身份摘要（`accountId`、`modelId`、`effort`），子会话值仅取创建时冻结的绑定；冷目录同样消费已保存摘要，未知值不从当前配置模板推断。该字段贯通 HTTP、FRB 与客户端，用于智能体列表展示，不携带上下文或触发额外模型调用（存储与迁移见 [17](./17-studio-storage.md)）。

模型查询基于账号有效目录、统一资格与启用状态，计费类别与性能统计分别读取各自权威领域；本地评价通过按账号与模型的有界详情查询返回，不注入全局引导快照或设置快照。查询操作不刷新网络、不写配置、不生成评价。写入评价遵循 [12](./12-collaboration.md) 的父子授权及最终轮次（`Turn`）与修订号校验，提交成功后返回权威结果；旧查询不得回滚较新记录。

会话运行时快照同时派生只读计划投影（当前状态、修订号、含内容哈希的当前计划文档与更新时间），数据取自权威 `studio.plan` 会话扩展；扩展缺失时即无计划投影，不物化默认状态、不写入状态。该投影仅在 GUI 只读展示已批准计划与状态栏计划入口，不新增计划协议状态、持久化实体或第二套事实源（见 [13](./13-plan.md)）。

### 路由并发控制与命令回执

已有会话的模型切换请求须携带客户端已观察到的权威 `expectedModelRouteRevision`（对应模型路由扩展的版本号，既非订阅通知计数，也非所有者日志的提交序号）。运行时通过路由扩展的原子并发检查拒绝过期请求，不无条件覆盖或自动重试写入；失败时保留原路由并向会话输入区反馈错误。成功响应中的权威路由与设置更新直接反映选择状态，Flutter 不人为递增工作区订阅修订号；通知水位仍仅由状态流维护。

已有会话的新提示词提交同样携带已观察的 `expectedModelRouteRevision`。运行时在现有会话生命周期锁内先检查输入幂等命中，再校验路由扩展修订号，通过后才执行附件提升（promotion）与新输入受理。过期路由会被明确拒绝，不得将本地冻结选择器当作后端已采用的事实；该比较并交换（CAS）校验不限制后续显式路由更新对未来轮次生效。新建会话随创建请求直接携带完整路由，在目录发布与首次激活前作为该会话的初始化输入，不先修改全局工作模式默认值。
停止与继续共用同一命令回执边界。停止请求携带客户端已观察的执行编号（`expectedExecutionId`），由会话执行器的串行控制核对：不存在匹配执行时返回 `NoExecution`，已受理但清理未结束返回可继续观察的状态，受理不等于目标执行已经结束。继续请求携带操作编号、继续点编号与已观察的模型路由修订号；同身份同内容返回原回执，不同内容拒绝，重复查询或重发不重新授权，也不解除其间发生的停止。用户对子会话的提交与继续在激活执行器之前即以归属校验拒绝，父调度经协作工具进入同一核心能力。

业务变更命令返回携带 `OperationId`、`Applied/NoChange`、目标 `ResourceStamp` 与生效点（`effect point`）的类型化回执（receipt）。结果由实际所有者的提交点给出，不得通过响应与镜像修订号相等来推断 `NoChange`。已受理（`Accepted`）、已观察（`Observed`）、已生效（`Effective`）与已持久化（`Durable`）四个阶段分别确认；配置对下一轮次或未来会话生效与正在执行的模型调用切换不同，持久化确认仅来自真实落库回执。客户端对未知结果、观察失败的处理及最新意图（latest intent）隔离见 [25](./25-frontend-state.md)。

停止请求与交互确认使用明确的身份观察屏障：当回执声明 `requiresIdentityObservation` 时，空目标或资源版本相等均不能自动确认。客户端在发送命令前注册对应会话所有者的原子观察，仅当目标轮次已结束或目标交互已移除时才确认 `Observed`。停止确认（ACK）仅表示取消请求已受理，`Effective` 须等待目标轮次真正结束；交互受理可先标记 `Effective`，但仍须等待交互身份移除。普通受理不代表已持久化，仅命中真实落库的交互回执才确认 `Durable`。输入提交的 `Durable` 确认必须匹配 `ThreadId + inputId` 的对话轮次 `saved` 状态，执行终态、回执游标与其他资源修订号均不得替代。

### 领域事件、归档与统计合并

产品事件携带完整领域快照或明确修订号（如 `ProjectDirectoryChanged`、`ThreadDirectoryChanged`、`AgentDirectoryChanged`、`ModeCatalogChanged`、`ThreadRuntimeChanged` 等）。Dart 归约器拒绝旧修订号，并利用受影响领域的基线从流滞后（stream lag）中恢复，不自行推演工作流转换。单次目录命令可同时修改项目与会话，但每个实际发生变化的领域最多发布一次事件；空增量不得提升修订号或发布空事件。冷记录进入驻留或归档命令的内存索引属于所有者准备步骤，不单独构成产品事实或触发广播。归档装载目录及必要的可靠清理/保存状态，不遍历完整历史或恢复冷会话执行；最终业务变更才通过目录命令发布权威增量。

项目归档与新建根会话共用准入边界，最终会话树范围须包含归档获准前已完成准备的子会话，不得在枚举后遗漏并发创建的根会话或子会话。归档仅检查驻留所有者的活动工作，冷目录不因归档而恢复执行。若在资源关闭与目录提交之间发生失败，系统以权威目录及真实关闭事实保留可重试路径，既不将未归档项目永久封死，也不为回滚而重新执行已关闭的会话。

归档的停止、保存确认、临时目录清理、失败接续与成功发布遵循 [17.16](./17-studio-storage.md#1716-会话归档与临时数据清理)。此操作不调用子智能体最终关闭的 force 工作树删除；取消归档不重建工作树或已清理的临时内容。

领域重同步（Resync）按各自修订号合并已发布事实；本地已有快照不得遮蔽服务端更新，旧查询结果也不得覆盖已收到的新事件。统计桌面界面（GUI）不从聚合引导快照（Bootstrap）或全量重同步中获取统计数据，而是采用 §18.2.2 的独立观察与读取链路；根会话费用仍使用独立作用域快照。模型统计属于尽力而为的数据库投影：读取已提交数据与发布展示修订号串行化，待写事实的早期空读不得占用最终落库结果的版本号。写入结论到达后发布新快照；读取失败时保留上次可用数据并显式标记失败，待写状态与统计缺口分别可见。该投影由启动命令及计费或归档变化推进；基线查询仅读取所有者当前已发布的有界投影，不推进修订号、不写产品对象，也不通过全局查询补建作用域费用。未知根会话返回空费用，归档清除与读取失败由同一所有者发布，查询不得重新引入已清除费用。累计用量与费用仍归可靠历史与检查点所有；调用统计库保存绝对统计及有界性能投影，领域拆分不改变存储归属，也不以调试日志承担计费幂等或执行恢复。恢复归档会话的命令会重新发布已有统计投影的可见费用，但不执行历史工作。费用作用域的修订号在空状态缓存淘汰、重新订阅及恢复之间不得回退；空基线必须足以清除较旧费用。

### 18.2.1 按职责订阅

产品订阅以类型化主题（topic）表达领域职责，项目技能携带 `projectId`，会话费用携带 `rootThreadId`；系统不提供无作用域的 GUI 全量事件订阅。全局目录、设置、恢复、MCP、LSP、工作模式目录、账号用量、ACP 认证与安装、模型统计、更新器、持久化状态与队列、配置级智能体模板各自构成独立职责。无关领域不进入订阅者的有效缓冲区，不会因无关更新导致当前订阅滞后。通道仅分发所有者已发布的事实，不持有另一套业务投影。

机器人模块使用独立的 `Bots` 主题与 `BotsStateChanged` 事件，状态仅包含轻量配置、连接、注册与配对信息，不携带会话正文。产品领域修订号与各机器人 `configRevision` 相互独立；查询与发送均为显式动作，成功响应进入同一权威归约器，不以聚合回读或 GUI 轮询补偿（接口、授权、注册与连接关闭契约见 [27](./27-bots.md)）。

订阅遵循“先登记接收者，再读取当前领域基线”的顺序；期间到达的通知按载荷的领域修订号合并，旧基线不得覆盖较新事件。会话目录基线是带修订号与游标的分页窗口，不得以增量冒充全量页。过滤后的全局序号允许不连续，仅由显式 `lagged` 信号表达无法证明连续；系统不提供持久化重放（durable replay）。重同步仅读取受影响领域，不触发会话激活、文件扫描或状态变更。

Dart 侧接线遵循 [25](./25-frontend-state.md)：主题与作用域租约（lease）由应用实例的领域所有者持有与释放，事件帧进入对应领域唯一归约器，再由 Riverpod 与连接器派生读取。页面观察者只解绑自身观察，不能关闭仍有逻辑需求的资源；导航所有者则显式为当前可见会话声明 GUI 订阅需求，离开会话页时解除，返回时建立新基线。草稿与已受理操作不因此重建，飞书和 HTTP 的独立需求也不受影响。收到 `lagged` 信号时仅使对应主题或作用域进入局部重同步，取消旧句柄并重新建立“先接收后基线”的订阅；预算耗尽、`failure` 或 `closed` 时保留最后有效内容并暴露局部错误，不以静默空状态或无界快速重连掩盖缺口。旧租约的代次（generation）在关闭与新租约建立期间继续生效，防止迟到帧写入新观察者。

上述 Client 主题接线不包含已独立切片的统计与账号桌面界面：统计由 `StatisticsRepository` 持有观察与读取，账号由 §18.2.3 的分域仓储持有观察与命令。有效 HTTP 订阅仍消费相同 Rust 事实，不授权 GUI 保留旧输入旁路或第二份可写镜像。

设置领域保持清晰的职责边界：MCP、LSP、项目技能、账号用量、持久化队列与配置模板分别按当前可见页面或组件获取对应领域观察；模型性能由明确展开或查询意图按需读取，不建立常驻主题。不以笼统的 `services` 作用域替代独立领域需求；技能作用域始终携带当前项目身份。订阅生命周期与页面导航的关系遵循 [25](./25-frontend-state.md) §25.4 与 §25.8：导航不产生业务写入，当前时间线展示、费用与草稿归属不因页面往返而被清除或重建。

模型统计与根会话费用由同一计费所有者发布并分别交付，会话费用消费者不接收全局历史。模型统计快照按 `(accountId, modelId)` 给出唯一顶层汇总及组内推理强度（`effort`）细分，`modelId` 表示冻结的配置选择，不以 `sentModel` 或 `reportedModel` 替代；无法证明的旧身份保持未知（分组与存储契约见 [06](./06-model.md) 与 [17](./17-studio-storage.md)，消费者不在各层重新聚合另一套身份）。顶层 `summaries` 每项包含 `accountId`、`accountDisplayName`、`modelId`、该组总指标与 `effortBreakdowns`；每个细分项包含可空 `effort` 及同口径指标，不重复定义账号模型身份。历史样本的 `modelId` 可空，但仍保留冻结的发送模型、返回模型及推理强度诊断。未知身份不混入任何已知账号模型汇总，原有历史、用量与费用事实不因此删除；仅指标有效样本参与速度聚合的规则保持不变。

持久化队列由协调器发布真实队列深度、在途字节、存储压力与逐会话水位变化（含调用日志写入器进度）；进程级保存诊断不得替代队列状态。年龄读数仅作为通知时间基线的展示，不驱动接口轮询。账号用量等外部查询仍由类型化检查命令触发；账号标签页的自动可见需求同样通过该命令执行，不在查询或订阅基线中暗中访问网络。结果通过权威事件或响应更新，不虚构第三方推送。

### 18.2.2 统计观察与不可变读取

统计观察与按需读取属于既有统计所有者的只读能力，不新增数据库、聚合公式或第二个计费所有者。同一次发布原子捕获汇总指标、调用历史及 `statisticsPending`、`statisticsGap`、`readFailed` 状态标记；完整发布修订号（Revision）与汇总／历史材料修订号严格区分。未发生变化的统计材料保持原有身份；仅当状态标记变化时，无需重建统计材料或重新传输全部数据行。订阅建立时先获取当前已发布基线，再沿同一所有者的发布序列推进；读取过程既不通过查询最新态（`latest`）替换旧材料，也不通过直接回读 SQLite 建立订阅版本。

强类型头部包含所有者纪元（`owner epoch`）、订阅身份、发布水位、材料水位、条目计数与状态标记。汇总与历史的读取引用由该头部显式声明；读取作用域（Scope）固定绑定原发布材料，不得仅凭修订号相等而混用其他所有者或订阅的引用。作用域打开、分页返回与结果发布前均核对原身份及关闭状态，过期或跨来源访问一律明确拒绝。单页上限为 128 项；推理强度（`effort`）细分同样采用有界读取，不在单个顶层条目内夹带无界嵌套列表。分页游标与偏移量仅归属原读取作用域，读取终止由权威总量与续页事实决定，不得仅凭返回短页推断读取完整。

同一条统计推送流（Feed）在同一时刻至多持有两个未确认的发布材料与两个已打开的读取作用域，单个读取作用域同一时刻至多允许一个在途分页读取；请求准入先行扣减预算，打开失败或关闭途中仍保留所有权责任直至底层操作真实结束。读取载荷预算按本次源数据编码字节计量，单页上限为 256 KiB；若单个条目超出容量上限，直接返回类型化容量错误，不静默截断身份或统计指标（该预算属于确定性准入计量，不等同于 FRB 线编码长度或进程常驻内存 RSS）。

前端 `StatisticsRepository` 在完整物化原有有界统计窗口后原子发布视图状态，既不将其拆成需用户手动翻页的分页交互，也不缩减既有历史可见范围；当统计材料已完整物化且仍归属同一所有者时，可按材料修订号直接复用。发生读取错误时保留最近一次有效数据（`last-good`）及其原始来源，不得在部分读取途中清空筛选条件、伪造空状态或将旧材料包装成新所有者的已就绪数据。材料发布、传输确认、读取作用域寿命与统计落盘分属独立事实，关闭统计观察不会停止后台计费生产者。

### 18.2.3 账号领域摘要与按需详情

账号领域是现有配置、模型目录、用量与 ACP 所有者的类型化读写边界，不新建业务数据库或第二套状态机。各来源分别携带原所有者身份与修订水位，组合只读投影不把多个时钟压为单一可比版本。Native/ACP 使用带判别的账号身份；模型身份为账号与配置模型 ID，显示名不是主键。

配置领域列表摘要包含身份、类型、品牌、名称、默认关系、有效计费类别及显式覆盖、凭据就绪、查询身份与可执行能力，不携带所有模型配置。选中账号后按需读取该账号完整编辑事实；模型目录/同步、用量和 ACP 操作通过对应独立领域观察取得。模型能力与配置明细只为当前需要的账号/模型读取，性能与最近评价使用现有有界详情能力。列表与用量更新不物化、传输所有账号的完整模型资料。

完整领域帧可合并中间显示状态，但始终保留真实来源、目标和版本；先登记观察，再读取基线，以各自水位拒绝旧基线与迟到帧。详情切换、删除或配置查询身份变化使旧读取失去发布资格，不等于原任务已结束。不同来源的旧错误或 finally 不得清空新目标的加载/内容状态。

账号命令、模型同步和用量检查是显式动作；只读详情、订阅及重同步不发供应商请求。配置/模型窄命令沿 [20](./20-config.md) 的同一 CAS 与凭据事务路径，返回原 OperationId 和各自资源水位。无发现能力、配置/凭据问题、供应商失败、结果未知和观察失败均保持类型化，不用文案驱动重试。ACP 继续遵循 [28](./28-acp.md)，不伪造 Native 配置。

传输与仓储拥有打开、观察、查询、命令和关闭登记；退出封闭准入并真实汇合。显示观察的释放不取消已受理业务，未收束资源保留原所有权。分域 Dart 与呈现边界见 [25.14](./25-frontend-state.md#2514-账号分域与可预览呈现)，传输的有界交付见 [7.9](./07-streaming.md#79-账号领域观察与背压)。

## 18.3 按需激活（Activation）

### 启动初始化协调与进度流

启动流程通过唯一异步初始化入口返回已就绪的运行时，构造与初始化不分两次发布。桥接层与服务端仅安装成功结果，普通读取不改变启动状态，启动失败不由后续查询隐式重试。启动进度与恢复摘要来自同一协调器，展示并行准备、汇合、备份重建及终态（恢复规则见 [17.2](./17-studio-storage.md#172-启动与按需激活)）。`RuntimeSnapshot` 的可空字段 `startupRecovery` 携带 `backupPath`、脱敏 `reason` 与 Unix 秒级 `createdAt`，仅在本次恢复完成后发布；界面保留可关闭的备份提示，不被后台工作区审计覆盖。

启动阶段仅等待数据迁移、全局 TOML、轻量目录与本地预置资源就绪，不打开会话数据库、不读取会话检查点，也不调度全量会话恢复。全局工作树与数据根审计由运行时持有的后台任务完成：`Recovery` 使用 `ObservedResource` 发布加载中、就绪与失败状态；工具目录问题使用 `ToolCatalog/Retry`，保留诊断但不阻止打开会话、读取历史、停止或继续会话。侧栏会话菜单提供重试入口；显式重试会重新刷新工具目录（即使配置修订号未变），成功后才清除诊断。显式调用 `recovery.retry` 重新发起审计，`recovery.read` 仅读取当前状态。关闭运行时先停止并等待审计任务，再关闭会话与持久化层。

每条恢复问题携带独立的权威操作影响 `advisory | executionBlocked | accessBlocked`，与类别、可执行修复动作及对象归属分别表达。`advisory` 不阻止访问或执行；`executionBlocked` 阻止新执行但允许安全的只读观察；`accessBlocked` 拒绝受影响对象的访问及执行。类别 `Repository`、`Storage` 或 `ToolCatalog` 本身不决定影响。停止与诊断重试不因这些闸门被禁止；恢复动作自身仍校验授权、身份和修订。

作用域采用精确对象语义，不隐式按目录关系继承：`Application` 影响所有目标；`Project` 约束该项目自身的准备、访问与新根会话创建；已有 `Thread` 的操作只匹配 `Application` 和该 Thread 的问题，不因相同 `projectId` 直接继承 Project 问题。项目路径不可用仍发布 Project 执行阻断，不能降为提醒来掩盖新建失败；若该资源也影响已有会话，后端从同一审计事实按真实执行或迁移依赖发布对应 Thread 的阻断，保留原始原因及恢复动作，不另立诊断事实源。

审计依赖轻量目录、冻结物理身份、工作树租约和可靠迁移完成事实，不为分类打开全部历史或激活模型。冻结最终执行身份不单独证明迁移已完成；仍需读取旧源的迁移继续受旧源故障保护，已完成迁移且受管根健康的机器人不受旧业务路径故障连带阻塞。其受管根或实际 Git/迁移依赖故障仍由真实受影响 Thread 阻断。新根创建在发布目录前执行 Project 准入与实际资源校验；已有会话在执行受理前仍验证实际依赖，覆盖未扫描、冷绑定未知及扫描竞态，不能把暂无线索解释为健康。

保留的健康子工作树、未知归属的残留工作树及已归档成员清理待重试属于提醒；实际不可用的活动工作区阻止对应 owner 执行，无法安全读取的存储才阻止相应访问。问题绑定真实 owner，按 root 分组展示不扩大影响，子工作树问题不能禁止健康根会话。项目级问题亦须分别声明影响，不能因诊断范围较大就默认阻塞项目下所有会话。读取失败必须保留原始原因，禁止把所有预览失败折叠成“待清理”。

Client 的导航、草稿提交和执行命令及 GUI 禁用态统一消费该影响；拒绝时保留 issue ID、对象、原始原因与可用动作，运行期存储暂停另按存储状态解释，不能合并成无定位信息的裸恢复错误。

恢复项只发布实际具备产品入口的动作。当前通用动作是重新扫描/刷新诊断的 `retry` 与按身份和修订显式清理保留工作树的 `cleanupWorktree`；没有可执行动作时发布空动作集合并明确说明。未定义产品入口的 `cleanupThread`、`removeProject` 不作为可用动作保留，也不能在 Client 偷换为归档或删除用户数据。项目路径不可用时保留具体原因，用户修复路径或连接后通过 `retry` 重新检查；重试不等于自动修复或授权删除。已退休成员的清理重试遵循关闭领域的独立授权与进度契约。

启动阶段通过可在运行时未就绪前订阅的类型化进度流向桥接层推送存储打开、配置读取、目录读取、资源准备及终态事件，不依赖普通产品订阅预先建立。首帧提供当前真实阶段，遵循“先订阅再启动”顺序，成功或失败后结束流并释放资源；GUI 不轮询读取启动状态。进度订阅只是统一初始化协调器的传输投影，保留并行准备、备份恢复摘要与类型化启动失败，不另立初始化过程，也不把失败细节降级为单纯的阶段枚举。

每次显式启动尝试先获取进程级尝试令牌，再按该令牌建立进度订阅并执行启动命令。准备尝试、进度订阅与启动命令的身份必须一致：旧尝试的终态不得结束新尝试的观察，过期或重复的启动请求会被明确拒绝，旧观察者不接收新尝试的阶段事件。在途启动不接受另一尝试覆盖；已就绪（Ready）的运行时保持幂等成功，不重开服务或伪造存储打开阶段，订阅本身也不复位启动状态。

启动与关闭终止闸门（latch）是进程生命周期内的单向事实：应用退出开始后，当前进程在剩余生命周期内拒绝任何迟到的运行时安装，防止退出期间重新发布运行时；该闸门不因重复退出或启动重试而复位，也不通过复位触发新的初始化。正常启动且未进入退出的进程不受该闸门影响。关闭开始后，在途启动尝试立即失效并通知等待中的进度观察者结束；已停止的运行时不支持同进程再次启动，迟到的成功阶段不得作为有效启动结果交付。更新安装在安装包准备完成后进入普通应用退出流程，不要求会话空闲；退出提交后，在外部所有者取消或等待之前先使启动尝试失效，无需等待关闭全部完成后才发出通知。

### 会话按需激活与根会话创建

后台会话恢复与前台按需激活共用组装器（assembler）的逐会话准备预留（preparation reservation）；已有活动、正在准备或正在关闭的所有者不接受后台恢复写入。冷激活在发布所有者前完成持久化收束（durable settlement）。审计结果按当前租约修订号与已清理问题过滤，不得覆盖后续用户操作。

选择冷会话、提交用户输入或后台子会话继续执行时触发显式激活。运行时在一致读视图中校验并加载会话检查点、工作状态与待处理交互，全部成功后一次性安装所有者。工作模式快照与工作流投影随会话同时恢复，不设独立的任务运行时恢复扫描。时间线初始最新小页与尾部基线读取同一会话权威内容，历史分页与详情查询不激活执行所有者（契约见 [26](./26-timeline-content.md)）；产品交互回答前按已保存的父子顺序激活所需会话。已退役子会话的显式打开同样先迁移既有 v2 检查点，但仅发布冷状态与历史，不安装执行所有者；普通快照查询与历史分页不触发此步 SQLite 升级。GUI 首屏就绪后若已选中会话，则复用普通打开命令激活该会话，不遍历其他会话，也不自动继续模型或工具执行。

创建根会话是可失败的类型化命令，请求同时携带工作模式与会话工作区模式。`worktree` 模式在发布会话前完成仓库解析、工作树创建与租约落库；任一阶段失败均使命令整体失败，不留下已发布会话，GUI 保留输入草稿并展示失败原因。激活时若工作区资源缺失或身份不符，系统仅显式报错并发布该会话的 `Recovery` 诊断，不静默回退到项目根目录，也不在内存中改写已保存的工作区模式。若会话目录事实已发布但后续步骤失败，必须先按未启动会话执行补偿（关闭并归档）再返回类型化错误，不得遗留无法激活的已发布会话。

根会话创建过程可观察同一次命令的临时准备进度，按稳定 `inputId` 与 `projectId` 关联：检查项目、准备工作区、初始化会话与提交首条请求。工作树准备额外报告仓库解析及物理创建子阶段；路径仅在实际分配后发布，不为 detached checkout 伪造分支。进度由创建流程在真实阶段边界推进，不解析日志、不估算检出百分比，也不提前发布会话或写入聊天历史。FRB 通过单次调用的类型化事件流交付进度及唯一成功或失败终态；HTTP 继续消费同一创建命令的最终结果。观察断开不等于取消创建，已分配资源与失败补偿仍由原所有者收束；缺少确定终态的客户端按未知结果处理，不自动重复创建。仓库解析、`HEAD` 解析与工作树检出失败在对应边界提供可操作的类型化错误说明并保留内部错误链，不将原始 Git 输出直接作为用户错误文案；失败卡片同时保留最后确认的阶段。

## 18.4 配置目录

工作模式目录（`ModeCatalog`）直接投影 Studio 模式注册表的内存快照：内置工作模式在 Studio 启动时以静态描述注册，既不扫描技能目录，也不读取或复制用户目录资源；未来的外部加载器必须先将文件解析为拥有所有权的注册项，再调用公开注册接口。智能体模板目录（`AgentProfileCatalog`）合并 Rust 内置定义与用户 TOML 文件；配置所有者持有独立的权威 `AgentProfiles` 资源，通过 `AgentProfiles` 事件发布完整配置与诊断，与运行期智能体目录（`AgentDirectory`）严格区分。

启动、配置变更命令与显式重扫会采纳目录变化；查询与订阅仅读取已发布资源，不扫描文件系统、不周期重扫。工作模式目录在实际注册或装载变化时按修订号发布。系统智能体启停、系统路由更新、工作模式默认路由更新及用户配置模板保存均携带 `expectedSettingsRevision`；成功后返回最新完整权威快照并发布已更新的 `AgentProfiles` 资源，Flutter 原子采纳相关领域，不只修改本地草稿。

## 18.5 关闭编排（Shutdown）

### 阶段依赖图与并发收束

关闭流程统一采用一套阶段编排，区分桌面应用退出与进程内服务关闭。手动更新与正常退出共用同一桌面退出入口，主动停止运行中的会话而不等待自然空闲；仅当关停报告为真实 `Clean` 时才交接安装器。进程内服务关闭要求真实 `Clean` 才算成功；桌面退出接受 `Clean` 或 `Degraded` 并按退出期限终止进程。退出结果在关停报告之外独立承载安装交接结果，不将安装器启动失败改写为关停失败或予以隐藏。

宿主关停仅结束当次所有者与运行期资源，不将仍可续跑的子会话标记为显式关闭。重启后，新的显式输入可按既有冻结身份恢复未封口的子会话；已显式关闭的子会话则拒绝继续执行。持久意图、目录投影与旧记录语义遵循 [12](./12-collaboration.md) 与 [17](./17-studio-storage.md)，不根据核心层 `Closed` 状态或工作区回收结果推测关闭意图。按领域拆分的产品、启动与会话订阅继续纳入同一桥接订阅所有者与取消收束流程，不引入第二套退出机制；原有总期限、外部取消问题、类型化报告与严格调用方的 `Clean` 前置条件同样覆盖这些订阅，页面租约释放与应用退出均等待真实句柄收束。

关闭流程按固定依赖有向无环图（DAG）推进：
1. **锁闭准入**：拒绝新的变更命令与轮次提交。
2. **广播取消**：取消当前执行代次与在途操作。
3. **有界收束运行资源**：并发收束已启动的会话与标题任务、后台审计、MCP、LSP、订阅通道，以及依赖它们的 SSH 传输层。
4. **刷写持久化水位**：刷写所有会话检查点并等待固定可靠水位排空（drain）。
5. **关闭存储与释放锁**：仅在保存完全收束后关闭写入器（writer）与数据库，最后释放实例文件锁。

彼此独立的收束任务不在无依赖关系上相互等待，同一依赖层内的多个阶段共享同一期限并发推进。图中仅包含两条真实的有向依赖边：
- **持久化写入链**：`生产者停止确认（ACK） → 保存排空 / 写入器停止 → 关闭数据库 / 释放实例锁`。
- **SSH 传输层依赖链**：远端 MCP、LSP 与工具通信承载于 SSH 传输层之上，因此终止本地 SSH 子进程必须发生在远端服务停止请求与结果处理完成、以及驱动远端工具的生产者（轮次、智能体等）停止确认**之后**，防止提前切断通信而将健康远端资源的正常退出误判为失败。SSH 传输层的关闭仍与持久化写入链并发执行，不等待无关的数据库提交；若依赖停止超时或失败，则按有界降级策略照常请求回收 SSH 并放弃等待其确认，所有者仍由常驻槽位保留。

前序阶段失败时仍继续执行后续彼此独立的安全清理并合并错误，单阶段不可用不得阻断其余阶段。每个阶段具备稳定的诊断标签（含开始与完成耗时、资源及关联标识，SSH 的依赖等待与传输层停止分别计时），仅用于诊断边界，不替代既有类型化进度。

在同一 `agentFramework` 阶段内部，会话关闭遵循局部化并发原则：组装器先锁闭组装准入并广播所有准备任务取消，随后按真实依赖局部化并发推进——每个独立会话树、分支或兄弟节点仅等待自身依赖的子条目、未发布子资源与自身准备过程，某个根会话下卡住的子分支仅阻塞其自身依赖链，不会拖慢无关根会话的关闭；子会话关闭确认先于依赖它的父会话关闭，任一分支失败仅累计错误并保留其所有者，不阻止其他独立资源收到关闭或丢弃指令。锁闭准入后不再接纳任何新的创建或子会话准备所有者；`close_all` 仅在**全部**已准入的 `creating` 与 `preparing_children` 所有者真实排空后才返回成功，覆盖尚无条目的创建中根会话及未被树快照覆盖的准备过程。该全局最终确认与局部化收束并发推进，不前置阻塞独立会话关闭；排空后才可见的迟到条目或未发布资源由同一编排继续收束，清理失败时保留所有者并计入报告，不因根集合为空或阶段超时而伪报 `Clean` 或 `Stopped`。本地原生子进程树在退出或强制终止后必须回收；远端辅助进程（helper）的停止由单向关闭指令及 30 秒心跳租约保证，不将等待 SSH 断开作为退出条件，也不等待远端退出确认。Driver 验收框架仍须确认本地原生子进程树已完全退出。

锁闭准入后，独立所有者（后台监听器、标题任务、MCP、LSP 与订阅通道）先各自收到一次取消广播，再执行受总期限约束的有界汇合（join）；SSH 传输层回收在同一编排内待远端服务与生产者停止确认后发起。上述独立所有者并发发起并共享首次绝对期限的剩余时间预算（原生 30 秒总期限与桌面 28 秒清理上限共用同一份剩余时间），不逐个串行等待，任一所有者的收束等待均不抢占其他所有者尚未开始的预算；单个所有者收束超时仅放弃等待并记录诊断，不丢弃在途存储、写入器或任务句柄（`JoinHandle`）所有者。退出编排本身运行在独立拥有所有权的任务上，即使调用方等待超时或全部离开，后台仍会继续轮询（poll）直至收束结束。

桥接层与 Dart 持有的订阅及在途更新操作的取消结果，在同一退出编排内作为成功前置条件。彼此独立的所有者组并发观测并共享首次绝对期限；任一侧未确认均不得发布 `Stopped`、释放实例锁或启动更新安装。更新准备与进度流必须在请求退出前真实结束，不保留交接操作自等待的特殊路径。服务关闭作业仅启动一次并持久保留，等待超时不丢失所有者，严格重试仅重新观测进度而不重复发起停止。

### 18.5.1 报告结构

应用退出报告采用冻结的接口结构（对外序列化为 `camelCase`，Rust 内部为 `snake_case`），作为 CQS 边界上的类型化命令结果，不设平行的可选字段或第二套状态枚举：

- `StudioShutdownOutcome`：`NotStarted | Clean | Degraded`。未安装运行时为 `NotStarted`；所有阶段成功且持久化状态为 `Drained` 时方为 `Clean`；其余情况均为 `Degraded`。
- `StudioPendingPersistence`：`Unknown | Pending { count } | Drained`。`count` 表示尚无持久化确认的待保存事实数量；无法确定时必须返回 `Unknown`，严禁用 `Drained` 掩盖未知状态。
- `StudioShutdownIssue`：包含 `stage`、`code`、`message`、`retryable`、`correlation_id`。其中 `stage` 为已知阶段的稳定诊断标签；`code` 为稳定诊断码字符串（类型化失败原因仍由既有进度与错误通道承载）；`correlation_id` 关联同步日志与诊断记录。
- `StudioShutdownReport`：包含 `outcome`、`issues`、`persistence`。

最终报告由运行时阶段、桥接侧以及调用方（原生宿主或 Dart）在进入运行时关闭前已确定的订阅与更新取消结果在**同一编排**内聚合生成，而非两套清理逻辑的事后拼接，也不会先释放锁再补写第二份结论。已知的外部问题在运行时收束前作为本次关闭的成功前置条件注入：任一侧存在问题时整体结果不得为 `Clean`；只有当桥接层与运行时两侧全部确认真实收束后，才允许判定 `Clean`、发布 `Stopped` 并释放实例锁。报告仅如实表达诊断与退出结果，非真实 `Clean` 状态下一律不发布 `Stopped`，也不声称保存或实例锁已安全收束。

### 18.5.2 持久化收束与实例所有权

桌面宿主额外持有同一操作系统文件锁的进程期租约：运行时以 `Clean` 状态收束并释放自身引用后，数据目录锁仍由原生宿主持有直至进程终止。因此在退出过程中触发的重复启动仍只会激活原窗口，不会启动新运行时。服务端（Server）与测试宿主无额外桌面租约，直接遵循下述释放顺序。

保存收束以写入器确认（writer ACK）为准：在写入器确认前必须保留所有者与句柄；只要仍有运行中的写入器，即不得关闭数据库或释放实例锁。报告携带的保存围栏（fence）与 `StudioPendingPersistence` 仅反映真实落盘进度；运行时侧发生降级（`Degraded`）或超时均不释放实例锁，最终由进程退出时的操作系统文件锁回收机制兜底，防止新实例与仍在写库的写入器发生竞争。实例锁与数据库的释放仅由同一关闭编排的最终成功判定决定：写入器真实确认、存储确实关闭、待保存队列排空，**且**桥接层与调用方已知的所有外部取消均已确认，四者缺一不可。

### 18.5.3 应用退出期限

应用退出设有单一总期限 30 秒。原生宿主在首个应用退出请求前启动独立守护线程持有该期限，重复退出或重试均不延长：前 28 秒用于正常清理，剩余 2 秒用于诊断退出；到期后强制终止当前进程并返回退出码 `1`，正常完成则返回退出码 `0`。清理过程不受日志 I/O、Dart 或桥接层挂起阻断：期限由独立线程推进，不依赖 Dart 或桥接调用返回，日志写入亦不得延误退出期限。退出入口的剩余预算由原生宿主剩余清理时间决定，上限为 28 秒（见 [19](./19-studio-ui.md)）。

桥接层在首个退出入口同步锁闭单向退出闸门，并在任何异步等待（`await`）前固定同一首次绝对期限；闸门、生命周期门控、订阅与更新取消、运行时阶段及诊断收尾全部从同一期限中扣减。退出入口在接受原生剩余预算的同时，接收调用方已完成并观测到的类型化取消问题（含关机进度订阅），桥接层再并入自身取消结果，共同作为同一编排的成功前置条件。

运行时的“安装发布”与退出的“准入锁闭”由**单一线性化（linearization）事实源**原子裁决，二者严格互斥：关闭胜出后任何安装均不再发布；安装先胜出的运行时必定被早期退出入口与最终退出入口观察到并纳入同一编排收束。该裁决仅在无 `await`、无 I/O 的极短临界区内完成，不在初始化或任何异步等待期间持有锁，因而不会拖慢原生退出期限。初始化仍在进行时不得伪报 `NotStarted`；迟到安装即使已创建资源也必须被拒绝发布，其所有者由统一桥接生命周期强持有至真实 `Clean` 确认或进程终止，并由同一关闭编排在剩余预算内收束，不对上层可见也不推进为 `active/ready`。只要报告为 `Degraded`，实例锁与写入器、数据库、外部服务所有者即继续保留而不释放；确曾创建资源但未能完成收束时，报告 `Degraded` 并标记 `Unknown` 待保存状态。

原生宿主收到首个应用退出请求后，依次经过以下三步：
1. **早期退出入口（`begin_runtime_exit`）**：立即同步锁闭单向退出闸门、固定首次绝对期限，对已安装的运行时同步锁闭领域准入（拒绝新变更与新轮次），并向**所有**独立的在途所有者广播一次取消信号——涵盖后台监听器、标题任务、持久化观察者，以及每个驻留会话当前执行代次（活动轮次、模型调用与工具执行）的纯取消入口。早期入口同时预先广播桥接侧内容流订阅取消（不含自持令牌的关机进度流）与更新操作取消，将真实错误与诊断交由同一收集器作为成功前置条件。此步骤仅发送信号：不触发初始化、不启动 MCP/LSP/SSH 的阻塞停止或汇合、不关闭会话、不关闭数据库或释放实例锁，也不发布 `Stopped`。早期入口自身严格有界，不在生命周期门控、快照、订阅或标题锁上无界等待。
2. **Dart 侧有界取消收束**：有界取消并观测 Dart 自身持有的外部订阅与操作。
3. **统一运行时关闭（`shutdown_runtime(remaining_ms, external_issues)`）**：在同一编排内完成最终汇合、持久化排空与状态定稿。即使 Dart 侧取消阻塞，运行时的准入锁闭与全部独立取消信号也已在退出期限起始时刻下达。

### 18.5.4 诊断收尾

诊断收尾独立于运行时初始化状态：即使运行时从未安装或安装失败，也提供独立命令回收诊断资源，由 Dart 在安全释放（dispose）前或进程退出前调用。退出错误聚合真实原因（`code`、`correlation_id`、待保存事实数量与保存围栏），不包含敏感凭据或会话正文；错误通过同步日志、临时应急文件与标准错误流（`stderr`，Windows 另含调试输出）多路兜底记录，写入过程不得延误退出期限（落盘细节见 [17](./17-studio-storage.md) 与 [23](./23-release-update.md)）。

### 18.5.5 子进程树归属

本地原生子进程树必须随应用退出同步收束：Windows 通过统一后台进程工厂的单子进程作业对象（per-child Job Object）回收本地工具；Linux 本地 MCP 与 LSP 复用既有工作进程（worker）监督路径（LSP 通过宿主注入入口挂载至运行时，不另建第二套监督器），GUI 被强制终止时由控制通道 `EOF` 触发回收。远端辅助进程由单向关闭指令及 30 秒心跳租约保证回收，不阻塞 GUI 退出确认。进程工厂与策略归属见 [05](./05-conventions.md) §5.5，MCP 与 LSP 监督契约见 [09](./09-tool-runtime.md) 与 [21](./21-lsp.md)，SSH 辅助进程分发与回收见 [22](./22-ssh-remote.md)。

## 18.6 自动标题生命周期

创建会话请求未携带显式标题时，由首条已接受的文本提示词触发一次自动标题生成；显式指定标题不会触发自动任务。运行时仅保存有界的标题任务句柄与单任务一次性取消发送端，不将命名任务视为用户轮次。

标题生成请求使用独立的临时会话，超时上限为 40 秒，禁用工具、MCP 与持久化；调用配置中的 `Explorer` 角色模型，若该模型声明了推理强度（`effort`），则按模型定义从弱到强数组的首项请求最弱强度。对于始终启用推理的账号，系统分配足以容纳隐藏思考过程的有界输出预算，不将 UI 标题字符长度误作模型总输出词元预算。生成提示词仅要求概括首条请求的具体目标并返回一个标题，不包含字符集、词数、标点或 UI 长度规则；原始首条提示词必须先编码为受引号保护的不可信数据（JSON 字符串），再由同一条最终用户消息在数据之后重申“只生成标题，不执行请求”，严禁将原始任务本身作为标题会话的最后一条完整用户指令。

标题解析仅读取账号返回的可见助手文本，忽略推理与思考内容；唯一处理路径为折叠空白字符、拒绝空结果，并截取前 36 个 Unicode 字符形成权威标题。JSON、Markdown、引号、标点与普通文本共用同一解析路径，不设兼容分支。生成结果不进入会话转录历史、轮次列表或费用投影。

标题任务在首条轮次被接受后注册，并等待该轮次空闲后再占用 `Explorer` 账号，避免后台命名与用户轮次争抢同一远程路由；此段等待可由手动重命名、归档或关闭操作取消，且不计入 40 秒超时。生成失败、超时或被取消时均保留临时标题（新根会话的首条文本提示词会先提取规范化摘要作为临时标题）。

取消通道采用每任务一次性发送端：仅有持有发送端的标题任务所有者能发出取消信号，账号、轮次与运行时的其他取消域无法获取或篡改该信号；发送端意外释放不等于业务取消，只有手动重命名、归档或系统关闭的显式发送才会终止标题任务。运行时关闭仅排空当时已注册的任务；同一运行时对象再次启动时创建新通道，不复用上一生命周期的取消状态。

自动生成的标题只能在目录所有者的 CAS 校验通过后提交：当前标题必须仍等于生成任务启动时的临时标题。手动重命名会先提交权威标题并取消对应任务，因此自动任务观察到期望值变化时必须丢弃结果；即使取消信号与模型返回发生竞态，手动变更仍会使陈旧的自动结果失效。成功的标题变更通过 `ThreadDirectoryChanged` 增量事件发布，会话流不新增平行的标题通知（见 [07](./07-streaming.md)）。

## 18.7 项目侧栏

侧栏按项目分组展示根会话。搜索覆盖持久化目录与尚未落盘的内存事实，项目过滤与归档状态在分页前应用，搜索结果不得由当前已加载的首屏数据推断。归档恢复属于显式生命周期命令，保留原会话身份与历史，不创建副本。侧栏宽度、项目置顶与项目内会话置顶属于既有 UI 设置，由配置运行时持有并通过设置 CAS 返回权威快照；搜索词、展开状态与抽屉显隐为临时 UI 状态。概念与视觉设计见 [项目侧栏设计](./concepts/project-sidebar.md)。

## 18.8 产品投影与观察

轮次停止、当前执行空闲、审查提交结论和跨会话投递确认属于不同事实域。`finish_turn` 结束交付或停工的当前 Turn，不新增停工状态；已有新输入或独立后台活动照实投影，不为了显示空闲而丢弃活动。宿主在 Turn 后履行的可靠报告、反馈与异常通知责任不把已结束的 Turn 重新投影为 Running，也不能因 `wait` 被消息唤醒而投影为业务成功。

父终态报告固定原 Turn 结论，后续适用性或投递异常以独立可靠消息关联原身份；观察者不能用当前目标状态重写旧报告。异常应用事实沿原实时投影与写入确认链发布，不另起状态镜像或消息队列；保存与关闭义务见 [17.15](./17-studio-storage.md#1715-审查结论与独立投递异常的可靠交付)。

### 输入、模型正文与上下文容量投影

输入显示投影读取提交时保存的产品正文、附件元数据与展示描述（`presentation`），不将模型侧的附件注释反向当作用户输入。输入载荷中的原始请求仅用于幂等受理校验，不替代展示正文；其存在不得使正常消息降级为原始记录，展示解析仍校验已知字段类型并拒绝未知结构。通用文本片段直接拼接并保留原始空白；未知输入格式交由原始记录查看器展示，不得默认为空文本。

模型正文投影读取已保存输出与模型回执，保留文本分片的实际字节与推理正文；取消后返回或被拒绝的输出显示对应的非成功终态，不作为正常回复；不支持的模型内容明确暴露投影失败，不得静默变为空正文。轮次产品投影依据已保存的状态、提交时间与实测耗时生成，不以数据库写入时间或当前系统时间替代；仅当存在通用取消事实而无发起者证据时才显示 `unspecified`。

会话运行时的模型身份、有效上下文窗口 `contextWindow`、模型最大窗口 `maxContextWindow` 与最终自动压缩阈值 `autoCompactLimit` 取自最新模型尝试已保存的请求绑定，在请求准入后即可整体投影，无需等待成功响应；新绑定中未知的字段会清除前一模型的对应值，不得因失败、取消或历史回放而沿用旧值。窗口与阈值沿可选协议字段传给 GUI，前端不重新解析模型目录、不按当前设置回填，也不自行推导安全上限；辅助推理与压缩回执不覆盖主会话的绑定事实。最近有效账号用量与活动尝试的实时读数仍按既有用量契约更新；压缩准备阶段使用的输入估算并非账号真实用量，进度达到阈值不代表压缩已经发生。新请求尚未回报用量时可保留最近有效读数，但不得据此隐藏其超过新阈值的情况。快照、状态流、重订阅与冷恢复传递完全一致的绑定事实。

透明模型恢复按 [16](./16-core-contracts.md) §16.3 的观察代次投影，实时及最终回执遵循 [07](./07-streaming.md)。失败子尝试与当前子尝试分开呈现，原账号内容分片（part）身份不改写；不得因最终逻辑调用成功而将先前失败的片段收束为成功，也不得将旧预览的空占位当作正文。重试、恢复及重试耗尽显示为 `Runtime` 来源的说明条目（commentary item），与正文共用同一时间线内容源；提示文案从类型化恢复事实生成，不从账号错误原文反推状态。无 GUI 订阅时仍保留同一回执事实，慢消费者与历史重开可获得相同的失败边界，不在 Flutter 侧维护另一套重试计数或片段合并器。

智能体目录行携带该成员的执行投影：当前执行身份、阶段、是否可停止以及是否等待主智能体调度；目录对账只读，不为列举激活子会话，也不把上次进程的运行摘要当作当前运行。停止确认以目录的权威状态与运行实例身份为准，缺页或读取失败不得推断目标执行已结束。会话运行时快照同时发布继续点与执行投影，两者共同决定主输入区与目录行的可用操作。

### 时间线序号、工具交付与用户问答历史投影

产品时间线序号（`ordinal`）在效果（effect）首次创建条目时按输入、轮次、模型尝试与工具调用顺序统一分配；隐藏或暂时为空的投影保留槽位，后续正文出现或终态更新不得挤动已有条目；各投影的当前输出集合不作为历史排序的事实源。工具时间线从已提交的模型调用恢复原参数，从任务与许可事实投影执行状态，从交付记录（delivery）读取实际交付内容；业务载荷仅作为原始事实保存，不得被 UI 投影当作退出码、审批结论或成功状态的来源。成功且带有已保存结束轮次控制的 `complete` 工具交付，通过生产者的版本化解码器将原摘要投影为最终回复，并使用交付时固定的时间线位置；业务载荷中的 `"completed"` 字符串不能单独生成完成状态。输入区（Composer）仅在仍持有非空已接受输入身份时才消费对应轮次的提交结果；启动确认清除关联后，后续执行失败仅留在时间线中，不得将空身份相等误判为当前输入失败。

普通用户问答与计划确认在原工具条目上附带可选的类型化 `userInput` 历史投影，不新增第二条持久化问答记录。该投影包含交互身份、按原顺序排列的问题以及 `pending`、`resolved`、`cancelled` 等权威状态；已解决（`resolved`）的回答通过问题 ID 关联，保留答案列表及自由文本。状态取自同一权威交互事实，不从工具成功状态、隐藏续跑指令（continuation）或摘要文本推断。交互提交原位更新既有工具条目，保留条目 ID、`ordinal` 与创建时间，并按实际内容变化推进条目版本；实时流、持久化历史、分页与会话重开均消费同一投影，不在会话轻量状态中长期复制已解决的交互。

工具调用与交互的身份转换由核心层提供的统一身份函数负责，Studio 不复制身份前缀规则，也不通过时间戳或相邻条目猜测关联；解析出身份本身不证明记录存在或授予权限，仍须核对权威记录。交互更新需要原工具条目正文而非仅放置元数据。待回答交互可跨所有者回收或进程重启继续：当当前投影未持有该正文时，投影所有者按已验证的工具身份从可靠历史补齐所需条目，再发布同一交互变更，不扫描整轮历史、不激活模型或工具，也不建立第二份问答缓存；缺失、损坏或身份矛盾仍显式报错，不得因预览受限或热缓存已回收而跳过用户回答。

格式所有者在 Rust 边界解码原始提问与响应；FRB 与 Client 传递类型化数据，业务视图层不解析不透明 JSON。标记为 `isSecret` 的回答在公开历史投影中移除原值，仅保留足以表达“已回答且已隐藏”的状态，私有可靠回执及模型续跑指令保持原语义。问题与回答正文纳入既有内容预算与按身份回源契约，不得通过放入元数据绕过预算；未知格式保留诊断而不伪造已回答状态。计划确认复用格式所有者对计划正文哈希、修订号、问题身份及决定的校验，再转换为同一类型化历史结构，不在历史投影中另写一套计划状态机或解码约定。唯一的 `plan_confirmation` 问题标识该结构中的计划语义，回答列表保留批准或修订决定与用户反馈，GUI 仅将决定标记映射为本地化状态文案。计划运行时投影仍仅负责当前有效计划，不作为历史决定的事实源；待处理队列仅保留尚待处理的交互（既有 v2 历史的补齐规则见 [17](./17-studio-storage.md) §17.4）。

### 唯一实时投影发布者与存储压力协调

Studio 为每个活动会话运行专门的产品观察任务，作为该会话**唯一的实时投影发布者**：直接消费所有者发布的不可变效果（effect），持有该会话唯一的实时投影（live projection），将内容发布至共享会话并投影智能体目录、会话目录、显式进展与模型计费，再将历史与调用事实移交各自写入器。即使无 GUI 订阅，该任务也照常消费已成立事实；前端订阅仅读取该投影产出的帧，不驱动任何发布动作。

普通提交直接从内存效果投影，不逐批刷盘（flush），也不回读历史：终态报告与目录摘要均由这份可靠内存投影生成，使跨多批效果的长轮次能完整携带此前提交的正文。所有者命令队列中的刷盘指令仅在所有者空闲时处理，正在执行的轮次会使所有者停留在轮次异步任务中，若逐批刷盘会将实时产品事实阻塞至轮次结束。仅当内存投影无法证明自身已从该轮次第一条记录开始折叠时，才按 `items_for_turn` 从历史存储读取该轮次的有界切片以重建终态事实，这仅发生在两处冷边界：无驻留投影的冷恢复，以及投影安装时一次性播种该会话运行中及最新轮次的已提交条目（如轮次运行期间被重新激活或中途接管）。热路径不设缺口重播种或第二份字典兜底，每条事实仅投影一次。冷读保留所需的持久化屏障，但该屏障等待的是投影所有者自身的接管票据（即其已交回的最新提交），而非全局绝对提交水位，从而保证本进程新激活且早先提交已落盘的会话不会被不再推进的水位卡住。

除实时效果帧外，投影所有者还以可靠通道的水位变化为信号，补齐因存储压力而推迟到观察任务安装之后的初始化受理事实，确保其同样交回保存。终态报告仅携带已提交的条目身份，未经提交收束的流式预览不进入父级报告与目录摘要。实时投影为生成报告而常驻的数据是有界累积器（按身份归并的终态文本、有上限的可见说明条目、最新工具条目与已提交身份集合），而非整轮过程正文；可变正文仅在仍可能被改写时驻留，其余条目仅保留放置元数据。效果窗口的释放依据存储后端压力报告中的类型化持久化水位，所有者在提交后的内存安全边界将其折入并释放已覆盖批次，无需显式刷盘或额外租约。由于投影自身的表结构（仍可改写的驻留条目、放置元数据与报告累积器）在批次落盘后依然驻留，投影所有者会向同一可靠通道发布**绝对**驻留字节水位，会话预算与暂停判定将其与队列正文、在途预留一并计入；正常所需的报告结果因此不会被丢弃或静默截断，存储压力表现为在安全间隙暂停新的模型与工具准入。

无法完成投影的事实无法交接落盘，因而等同于一次保存失败：等待保存回执的屏障同时观察协调器水位与可靠通道自身的类型化故障，任一故障均以真实原因按失败关闭（fail-closed）返回，而非无限等待不再推进的水位。计费逻辑使用回执中的冻结模型绑定、单价与用量，恢复时从调用统计库按推理身份幂等读取；父级通知仅处理观察任务注册后的新增事实，并使用稳定消息身份防止失败重试导致重复送达。观察失败保留可重试状态并由同步屏障返回错误；同步屏障除等待最终提交的投影、目录保存及计费保存完成外，还必须确认该次提交的历史记录已落盘（冷恢复与未驻留子会话的终态修复直接读取历史库，因此“观察已应用”必须蕴含“已交回的提交已落盘”，且仅追溯投影所有者已交回的提交，不等待尚未投影的后续提交）。观察者更新产品目录时仅在目录所有者锁内修改运行状态与更新时间，不重写预先读取的完整会话记录；并发的标题修改、模式切换与归档操作保持当前事实，已移出热目录的条目不会被迟到的观察结果重新插入。智能体查询仅允许读取自身或同树后代，不通过查询激活冷会话；会话及进展分页游标绑定数据库 ID 与已应用写入水位，进展记录保留每次显式提交的完整详情，超大单条记录按带字节偏移的 UTF-8 JSON 分片继续读取，不得截断正文。冷目录读取遇到未知工作模式载荷时保留已有目录元数据，只读历史展示原始载荷，真正激活时仍严格校验所需的生产者编解码器。

### 缓存统计、模型吞吐率与工具媒体附件投影

会话运行时的缓存统计是独立的类型化投影 `cache_usage`，包含参与统计的输入总量、缓存读取总量、命中率及完整性标记，不复用总用量的完整性标记决定能否计算。有效样本要求输入与缓存读取均已报告且读取量不超过输入量；若同时报告缓存写入，则读取与写入之和必须无算术溢出且不超过输入量。输出计数缺失不影响缓存统计判定；缺失或矛盾的输入缓存计数不参与累计，并将缓存统计标记为不完整。零输入零读取属于有效样本，但零累计分母不计算命中率比例。未结束的调用不贡献样本；已中断且无回执的调用会将统计标记为不完整。已结束调用与压缩回执在各自权威身份下仅计入一次，重投影、重同步与冷恢复产出一致结果；新事实发布后使用当前样本重建累计投影，不在 GUI 侧另设增量账本。有效缓存样本使用受检算术（checked arithmetic）累加，溢出时显式报错，不发布回绕或截断的比例。既有总词元、原始缓存计数与费用保持原语义，派生缓存统计不改写持久化账单与日志。`ThreadRuntimeUsage` 的消费者统一消费 `cacheUsage`（命中率取 `hitRate`，未命中词元取同组 `inputTokens - cacheReadTokens`），不再保留旧字段。

模型性能历史以冻结账单中的账号与配置模型作为统计身份，并投影实际发送模型、账号返回模型以及 `matched`、`mismatched`、`unreported`、`legacyUnknown` 四态结果。返回模型不参与费用或速度汇总，无观察事实的旧账单统一标记为 `legacyUnknown`。速度样本的有效性、单调窗口与聚合公式遵循 [06](./06-model.md) §6.12；实时状态栏与历史汇总保持同一统计口径，不以展示层封顶或零时长伪造吞吐率。

会话的权威累计摘要同时保留最近一个拥有有效速度样本的轮次及其成对聚合计数。新轮次受理、模型准备、部分实时输出、工具等待及无有效速度样本的调用均不清空这组已确认事实；待新轮次首个有效完成样本到达时，才原子切换归属、重置并纳入该样本，同一轮次的后续有效样本继续成对累加。计数采用受检算术，溢出时不发布部分更新。该保持语义沿用现有摘要的持久化与幂等水位，重订阅、组件重建与冷恢复读取同一结果，不新增全会话速度账本。

实时用量（live usage）的输出词元与总响应时长仍可独立为未知。状态栏优先采用同一观察代次中成对有效的实时样本；若不成立，则完整采用权威摘要中最近已确认的聚合样本；二者均不成立时才显示未知。回退展示旧的完整样本并不表示当前在途调用已有测量结果，界面文案须明确标注“最近已确认速度”。严禁将实时值与权威值的分子、分母交叉配对，也不得使用组件私有快照或另一会话的数值补缺。状态栏读数仅呈现上述查询结果，不持有速度账本，页面释放亦不改变已确认统计。速度字段统一表达包含首字等待在内的总响应吞吐率（TPS），可空首字耗时与首字后耗时诊断遵循 [06](./06-model.md) §6.12。透明重试切换观察代次时原子清空当次代次的用量与耗时，防止旧代次的单调计数约束阻碍新代次计时。旧解码口径的检查点速度缓存不再展示或累加，新样本从空的成对摘要重新建立（不影响累计费用与词元用量）。失败、取消或恢复耗尽的模型观察必须在终态收束前的可发布窗口内撤销整组实时测量，同时保留部分正文、失败观察与最终计费事实。所有取消路径（含输入令牌的父子传播与直接中断）均须唤醒所有者发布撤销后的快照，不依赖下一条模型进度或函数返回；迟到进度与整份观察替换均不得重新打开已撤销代次，唯有明确进入下一重试代次方可恢复实时测量。

工具附件投影由 Studio 从持久化工具媒体经格式所有者的类型化解码生成，实时展示与历史恢复共用同一投影。附件身份沿用归档引用，MIME 类型、字节大小与可用尺寸必须对应实际归档变体，未知尺寸不作猜测；核心层不解释媒体格式，Flutter 不解析不透明载荷。附件读取入口同时支持用户附件与工具图片，但读取工具资源前必须校验会话访问权限并确认该资源属于该会话的持久化工具媒体引用——仅凭资源 ID 前缀、摘要或任意可访问会话均不足以授权，客户端路径亦不得作为文件读取入口；未引用、损坏或丢失的资源显式报错，不得使用原始工作区文件回退补齐。已完成的工具交付从会话历史中的完整交付记录读取；尚未落库的交付从当前未持久化效果读取，不依赖可能已被回收的驻留快照。

### 18.8.1 活动、时间线内容与存储状态

会话的活动摘要、时间线内容与存储状态各自拥有唯一所有者，互不替代：

- **活动摘要（`ThreadActivity`）**：表达当前会话“正在执行什么”的类型化轻量摘要，与时间线阅读内容正交。它由该会话唯一的投影所有者（观察任务中的 `ActivityProjection`）从刚发布的 `ThreadSnapshot`（涵盖轮次、模型尝试、工具任务、权限审批、交互、输入执行、`model_execution`、`model_progress`、`tool_progress`）通过**纯内存纯函数**派生：不读 `Session`、不查 SQLite、不整轮回读历史、不建第二份正文缓存。活动身份格式为 `activity:{turn_id}:{step}:{kind}`；身份不变时仅当摘要或详情内容实质变化才递增 `revision`，身份变化即代表新活动。阶段变化（含 `model_execution` 阶段推进）由所有者在提交新快照后随活动帧补发，不依赖 `effect.turn` 变化；常规后台落盘不会虚构 `persisting` 阶段。当上下文准备实际进入压缩执行（`compact_idle_context`、`recover_context`、容量超限强制压缩或 `StudioCompaction` 判定非 `Keep` 调用压缩模型）时，核心层将 `model_execution` 推进为 `CompactingContext`，活动阶段精确映射为 `Compacting`（界面展示“正在压缩”），与常规请求准备（`Preparing`）严格区分。`ActivityDetailOwner` 独立区分推理概要分片（`ObservedPartKind::SummaryText`）与推理正文分片（`ObservedPartKind::ReasoningText`），并在同一活动轮次（Turn）内跨工具执行步骤保留最近一次思考概要（`thinking_summary`）与思考秒数（`thinking_seconds`），直至新的思考概要产生、进入正文回复（`Responding`）或轮次结束。活动详情（推理过程、回复正文、工具参数与流式输出）按活动身份**按需**读取，同样仅从驻留所有者事实推导，活动结束后返回 `Superseded` 或 `Ended` 而不回退旧正文；驻留摘要与详情统一计入可靠保留预算。共享模型与工具进度的版本变化同样推进活动修订，详情所有者只更新共享快照句柄，正文仍在显式读取时物化。读取失败保留可见错误且不自动循环重试，用户收起后再次展开可重新读取同一活动。
  - **等待工具投影**：等待类工具使用共享的类型化等待投影，附加于活动工具与对应时间线工具条目上。等待意图区分事件等待（所选任务、最大等待时长及新消息唤醒观察）与定时器（定时时长）；任务来源携带稳定 `taskId`、可用工具名称、摘要及真实状态，等待结果区分等待中、就绪、正常超时、定时完成、取消、失败与中断。事件就绪额外保留 `messagesReady` 标记，不得将新消息唤醒误报为所有被等任务已完成。参数未完整合法解析时不生成猜测的等待投影，仅保留原始工具事实与错误。等待调用自身因失败收束时，条目的等待结果同步转为失败，不保留旧的“等待中”或消息就绪状态；目标任务的已观察状态则原样保留，不因等待调用失败而推断目标任务被取消。产品边界按已知工具契约从权威参数、任务与结果派生一次类型化信息，桥接层做机械映射，Client 与 Flutter 不再次解析等待参数或结果 JSON。实时活动的目标摘要仅读取驻留事实，不为显示名称查询历史数据库；活动组内的历史等待成员消费已保存的条目投影，缺失摘要与工具名称时主行显示通用任务标签，精确 `taskId` 留置诊断区，不用当前任务表改写历史结果。无真实开始时间时仅提供配置时长，不伪造截止时间或剩余进度百分比。每个目标摘要遵守活动摘要的统一字符上限并明确标记截断，不在轻量状态或静态元信息中复制完整长命令；原始参数与结果仍归原工具字段，诊断区通过既有预览与详情引用读取。旧 v2 数据缺失可选展示字段时保持为空，不重写旧正文或清库。
  - **运行中工具增量输出与启动序号**：运行中工具的实时输出采用共享不可变 `ContentBlock` 链，生产者仅将新增或替换部分封装为对应不透明身份（如 `command-output`）的 `Append { chunk }` 或 `Replace { text }` 提交给所有者（见 [07](./07-streaming.md) §7.4）。所有者将其存为该调用的 `ToolProgress`，实时投影直接共享最新分块并按该身份的 `version` 去重，不逐块复制或物化整段文本；权威落盘、展示预览交付与显式详情读取按各自契约物化文本。活动行与 `retained_bytes` 直接按 `ToolProgress::bytes()` 计量而不物化正文，自然纳入同一可靠保留预算。工具条目的 `ordinal` 取所有者记录在该任务上的真实启动序号（`TaskRecord.started_sequence`）；驻留会话的 `ActivityDetailOwner` 在首次观察到工具调用进入 `Running` 时记录当次运行的 Unix 秒 `started_at` 并跨同调用快照保持，冷快照无驻留观察事实时如实保持 `None`。最近启动任务（`latest_started`）严格按真实启动顺序选取：先比较所有者启动序号，同一提交批次内并发创建的任务若序号相等则按该轮次的实际调用次序（`call_rank`）破平，最后按 `call_id` 稳定排序，不依据最新输出到达时间或系统墙上时钟猜测。`TaskRecord.started_sequence` 定义为带 `#[serde(default)]` 的 `Option<u64>`，旧 v2 的 `state.toml` 或历史载荷缺失该字段时解码为 `None` 并回退至调用次序，无需升级数据库结构或清理旧目录。
- **时间线内容（Timeline）**：核心层 `Session` 的最新小页、更早小页、有界尾部订阅与版本化详情读取消费同一份权威已发布事实及历史存储，合并未落盘内容与持久化历史后按稳定顺序与身份交付。HTTP 与 FRB 共用 Studio 唯一的类型化映射，不再暴露几何窗口、焦点、对端裁剪或窗口操作回执。状态流不生成或转发正文条目帧，正文亦不因交付至尾部而重复进入轻量状态。条目内容修订号、尾部交付版本、保存确认与执行终态相互独立，热缓存淘汰不代表条目删除。数据源与单次查询设有明确预算，当前展示租约的唯一列表控制器保留本次实际加载的消息集合。历史浏览模式（History）冻结已展示内容，向前加载更早分页仅做前插而不裁剪另一端，后台执行与落盘继续进行；用户显式返回实时模式（Live）或发送新消息时触发最新小页读取，仅在新首帧成功后切换展示代次，不保存或恢复旧像素锚点。慢消费者与断流执行显式重同步，不得将错误当作 `EOF`，也不得以尾部重同步覆盖正在阅读的历史视图。超大字段经稳定字段身份显式分块读取，预览配额与原文完整性分别核验（完整契约见 [26](./26-timeline-content.md)，流式事实见 [07](./07-streaming.md) §7.4）。
- **存储状态（`ThreadStorageState`）**：作为类型化事实直接表达，不由错误文本反推。故障类别、故障代次（`fault_generation`）及历史记录的已接受与已持久化水位取自运行时持久化协调器的类型化报告；执行阶段（`running`、`pausing`、`paused`）与存储压力暂停取自核心层的存储执行事实；核心层的原始错误文本仅作为诊断字段透出。首帧随 `ThreadSnapshot` 携带权威存储状态，后续由协调器的独立类型化状态监听通道（watch）结合核心层执行阶段变化补发 `StorageChanged` 事件，正文更新不占用状态流。订阅端同时监听投影帧与存储状态通道，并按**值**去重比较已交付状态，确保存储暂停在无任何正文或活动帧时也能即时送达；所有者侧仅以无载荷唤醒帧标记快照内存储相关字段已变更，实际载荷仍由订阅者从类型化来源读取。
  - **显式继续闸门（`resume_required`）与自动压力暂停（`pressure_paused`）**：短暂存储压力（队列深度或字节预算触顶）在安全间隙自动等待并自动恢复，不改写执行阶段以外的事实；而真实保存故障（`queueFull`、`writeFailed`、`writerUnavailable`、`noProgress`、`checkpointFailed`、`blobFailed`）会锁闭核心准入闸门并将 `resume_required` 置为 `true`，使新的模型调用与工具执行在下一次准入前停止，已有在途结果在预留预算内收束（超出预留预算则取消操作并保留已产出内容）。在途输出超出可靠预留导致的截断本身即构成一条类型化故障：工具预览被拒或模型流按预留拒绝增量的当刻即由会话唯一所有者立即发布故障，无需等待调用返回。预留配额严格**按操作归属**：调用自身产出的中间及最终事实（含任务转 `running`、取消请求、模型尝试进入 `running` 等）在入队时接管该预留配额，调用结束时仅归还未被覆盖的余量，从而保证同一份输出仅计量一次，并发预留占满进程预算时在途结果仍能顺利交接；无归属事实（如新受理输入、轮次或生命周期提交）不得挪用其他在途操作的预留配额，必须装入真实可用余量，余量不足时返回类型化背压拒绝。
  - **两步显式恢复机制**：发生硬故障后，恢复分为两个独立命令，系统不会在重试落盘成功后自动续跑：
    1. `retryThreadHistory(thread_id, fault_generation)`：按故障代次重试保存，并等待该会话的检查点与历史持久化围栏（durable fence）确认。该命令仅将积压事实写入存储，**不**恢复模型或工具执行。
    2. `resumeThreadHistory(thread_id, fault_generation)`：将调用方核验过的故障代次提交给驻留所有者；所有者重新核对后端类型化报告，仅当故障代次匹配、硬故障已消除且每个已发布批次均已移交落盘时，才解除准入闸门并将执行阶段置回 `running`。所有者在首次观测到故障时即根据自身已发布事实固定本次恢复须达到的持久化围栏（取已移交最新提交与存储尚未接管的队首批次中的较大者），并验证该围栏已真实落盘。若代次过期（`ThreadError::StaleStorageRecovery`），或后端仍报告故障、仍有未移交批次、仍存在存储压力、围栏尚未落盘（`ThreadError::StorageRecoveryPending`），均返回类型化拒绝而非无界等待。显式继续命令经由所有者的**有界邮箱（mailbox）**投递：处于暂停状态的轮次停留在存储安全间隙并持续处理邮箱消息，因此即使轮次仍在运行中该命令依然可达，不会因外层命令队列等待轮次结束而死锁。未驻留的会话无活动所有者与准入闸门，`resumeThreadHistory` 直接返回成功而不激活会话；重新激活的会话不继承旧闸门。
  - **继续就绪判定（`ThreadStorageState.canResume`）**：由核心层存储所有者根据类型化事实唯一计算得出（`state.persistence.resume_ready`），要求准入闸门仍处于挂起状态、无活动硬故障、所有已发布批次均已移交、无字节阈值阻挡，且本次故障代次固定的恢复围栏已落盘（若后端命名了故障代次，还要求后端自身核验的恢复代次等于当前代次）。投影层直接采用该值，严禁与写入器自身的 `persistence.resume_ready` 取逻辑或（OR），防止旧代次的写入器恢复在核心层仍存有新故障时误点亮继续入口。写入器的类型化报告仅作为 `StoragePressure` 输入进入所有者的同代次核验。暂停中的轮次在安全间隙监听同一后端状态通道，空闲所有者亦将该通道作为独立唤醒源重算并发布就绪性，使重试落盘达成围栏后界面无需等待其他事件帧即可解锁“继续”按钮。

状态与内容由同一发布者（即该会话的产品观察任务）统一发布。投影所有者直接监听保存协调器的类型化状态通道与该会话自身的所有者快照，派生出唯一的 `ThreadStorageState` 并通过会话流的独立监听通道发布；慢速 GUI 订阅不进入任何门控，写入器的保留预算释放亦不等待前端订阅者。

## 18.9 顶栏工作区打开菜单

会话顶栏操作区（与智能体切换器、费用徽标同级）提供带图标与文字的「打开工作区」按钮，点击展开下拉菜单并列提供「VS Code」「Zed」与「终端」三个入口。只要存在当前会话及所属项目即显示该按钮，不因某个编辑器未安装而隐藏整个入口；三个菜单项独立探测可用性，不可用项置灰禁用并说明原因。菜单项仅显示应用原色图标与单行操作名称，不重复展示目标路径，也不为路径预留固定宽度；按钮与菜单项均提供本地化悬停提示（tooltip）、无障碍读屏名称及打开目标路径说明，不可用原因通过悬停提示与无障碍说明表达，不占用菜单列表第二行。

会话顶栏保留所属项目名称作为副标题，其悬停提示显示所选根会话的权威 `workspacePath`（普通会话显示项目目录，工作树会话显示实际工作树路径），不随子智能体切换而改用子智能体路径，也不由 GUI 推导工作树布局；未选择会话时回退至所属项目路径，侧栏项目路径则始终表示项目根目录。三个打开入口的目标均由会话权威 `workspacePath` 唯一决定。菜单读取宿主的 VS Code、Zed 与终端应用图标并保留品牌原色（Windows Terminal 使用已注册的打包应用图标，不使用执行别名的通用文件图标）；图标缺失或解码失败时显示明确文字与通用入口图标，不影响启动。

各外部应用的探测与安全启动契约如下：
- **VS Code**：直接启动宿主解析出的可执行文件，通过 `--folder-uri` 传递单个文件夹 URI，不经过 shell 或 `vscode://` 外部链接处理器，避免触发外部应用打开确认弹窗。本地项目使用 `file:` URI，远端 SSH 项目使用 `vscode-remote://ssh-remote+<Host 别名>/<远端路径>`（路径按 URI 规则做百分号编码，连接参数由 `~/.ssh/config` 的 `Host` 别名解析，不在 URI 中携带端口或密钥，见 [22](./22-ssh-remote.md)）。URI 构建与协议白名单校验为纯函数，专用启动器仅接受上述两类文件夹 URI 并作为独立参数传递。Windows 查询 `vscode` 协议关联，Linux 优先解析同一协议的 GIO 默认应用可执行文件，无关联时查找 `PATH` 中的 `code`；可用性探测与实际启动共用同一解析入口，结果缓存于进程内，演示模式与测试可覆写。
- **Zed**：通过官方命令行程序直接打开目标，不经过 shell 或 `zed://` 外部链接处理器。本地目标以单个权威目录参数传递；远端目标使用 `ssh://<Host 别名>/<远端路径>` 并按 URI 规则编码。Windows 从 `PATH` 解析 Zed 独立命令行程序（不将 `zed` 协议关联的图形主程序误作命令行入口，协议关联仅用于读取品牌图标）；Linux 依次查找 `PATH` 中的 `zed` 与 `zeditor`，品牌图标取自 `zed` 协议的 GIO 默认应用。参数按 `argv` 数组原样传递，失败时明确反馈且不自动重试或切换目标。
- **终端**：Windows 固定使用 Windows Terminal（`wt.exe`），本地工作目录设为会话工作区，不回退为独立 `cmd` 或 PowerShell 窗口；入口探测接受 `WindowsApps` 执行别名并交由操作系统在启动时解析。Linux 优先使用 `xdg-terminal-exec`，其次使用系统配置的 `x-terminal-emulator`，遵循各自的工作目录与执行参数契约，不猜测其他已安装终端，也不使用文件管理器替代；无可用默认终端时明确反馈不可用。对于远端 SSH 项目，系统在宿主终端中启动系统 OpenSSH 并复用项目的 `Host` 别名与 `~/.ssh/config`，分配交互式终端并安全切换至远端会话工作区后进入交互式 shell（切换失败时不得静默进入其他目录）。本地启动以参数数组传递而不经本地 shell 拼接；远端目录切换须正确转义空格、单引号及 shell 元字符，防止别名被解释为 SSH 选项或任意命令。这些由用户主动启动的外部应用拥有独立生命周期，不随 Studio 退出而终止，也不复用远端辅助进程的非交互通道。

## 18.10 权威状态新鲜度不变量（Canonical Freshness Invariant）

界面上每个用户可见字段都必须能沿唯一链路追溯：`生产所有者 → 事件或快照来源 → 桥接层唯一分发点 → 领域存储归约器（store reducer） → 修订号或水位（revision/watermark） → 职责内视图提供者（ViewProvider） → 组件订阅`，以及失败、重连与退出时的局部重同步与清理逻辑。组件不得通过一次性 `read`、切页重建或定时轮询获取本应由订阅提供的事实，也不得直接读取 FRB、原始 JSON、SQLite 或底层事件流（Dart 侧分层契约见 [25](./25-frontend-state.md) §25.7）。

设置、账号用量、会话费用、MCP、LSP、技能、智能体模板、持久化队列、更新器与恢复诊断等独立职责各自使用独立的类型化观察与租约；无关领域不得进入彼此缓冲区。订阅严格按“先登记接收者、再获取基线、后消费后续状态”建立，最后一个观察者释放时取消订阅，重新进入时先采纳最新基线。模型性能与评价通过模型领域的按需查询获取，结果绑定发起时的账号、模型与目录身份，不为查询另建旧 Client 缓存或常驻主题。会话的运行时状态、轮次、交互、工作流、活动摘要与存储状态则共用带 `epoch/baseRevision/revision` 的单一有序流；Dart 侧可细分只读 `ViewProvider`，但不得建立绕过同一水位的旁路流。序列缺口（gap）、流滞后（`lagged`）、旧代次与通道关闭均须遵循该领域既定的局部重同步、保留最后有效值与类型化错误语义，迟到帧不得覆盖较新事实。

违背该不变量的典型征兆是“界面数据需要经过一次路由往返才变新”：将页面导航、组件重建或浮层开关当作刷新前提，意味着该字段的事实源缺失了一条事件或响应归约路径。修复必须直接补齐该条数据链路，不得以页面级刷新、扩大订阅生命周期或重读整棵聚合状态来掩盖缺陷。

会话状态流的显示节流只用于合并尚未交付的观察变化，不应对已经等待过交付窗口的一批待发帧逐条重新施加完整窗口，使持续主动消费的订阅因自身节流无限积压。同身份合并不能跨越已确定顺序的其他事实，新的轮次或模型尝试保持独立；轮次、交互和缺口等权威变化不因显示节流被延后到下一窗口。队列仍有固定上限，消费者停滞或上游缺口仍通过真实 `lagged` 与新的 epoch 显式报告，不以无界批次、扩大缓冲或隐藏丢帧换取表面连续。取消观察等待不丢失已排队事实或重置已等待的交付期限，也不停止执行所有者。

保留终态观察与有序提交源之间也必须遵守顺序：只有订阅首帧已覆盖、或该订阅已消费到保留终态所属提交时，才能补发该终态。较新的保留值不能越过仍在有序源中的轮次开始、交互或完成事实；一次 watch 唤醒、暂时读空或达到有限读取配额都不单独构成已追平证明。提交身份与订阅通知的 `epoch/baseRevision/revision` 仍是不同版本域，不能拿通知水位替代提交覆盖，也不能靠取消去重制造重复或生命周期回退。

## 18.11 设置与模型目录的独立时钟

设置配置事实与在线模型目录观察属于两个独立资源，分别采用 `settingsRevision` 与 `modelCatalogRevision` 独立推进。桥接层的直接命令响应可同时携带多个领域事实，观察帧则按对应来源与目标交付；消费者必须分别比较各自水位：配置水位前进时仅更新配置字段，目录水位前进时仅更新账号的模型与目录状态。同一所有者生命周期、来源及具体目标内，相同水位作幂等丢弃，较低水位不得覆盖较新事实；其他账号或领域的高水位不能代替当前目标基线。直接响应、观察帧与基线读取按事实归属汇入对应领域的唯一归约器：一般设置与路由仍归 `SettingsStore`，账号配置、模型目录、用量与 ACP 分别归各自领域，不再写回通用设置中的账号整卡或目录副本。共享 CAS 协调只管理写入顺序，不持有这些业务镜像，调用方不得按到达先后顺序整体替换（Dart 侧分层与所有权见 [25.14](./25-frontend-state.md#2514-账号分域与可预览呈现)）。

静态账号模板目录由账号配置领域按需加载，不作为全应用启动屏障，也不写入通用 `SettingsStore`。其就绪状态由目录自身版本判断，与账号摘要是否已观察无关；未观察或加载失败不等于可用空目录。`BridgeStudioStateSnapshot` 不携带该静态目录，聚合快照转换不得以空目录覆盖已加载的静态目录。模板选择与编辑消费该唯一目录，账号品牌及共享选模使用对应领域已发布的摘要与模型事实，不为展示重新拼装整卡。

Flutter 的新会话草稿、会话路由与设置权威状态是三类职责不同的事实，所有权与组合展示规则遵循 [25](./25-frontend-state.md) §25.2、§25.5 与 §25.6：草稿由路由作用域控制器持有，不被权威快照覆盖；配置写入由设置命令通道串行化并以响应中的权威快照收敛；离开页面仅释放观察者租约，不取消在途命令，也不设返回前的等待或刷新步骤。

### 18.11.1 Thread 身份的单一来源

会话身份事实（`mode`、`title`、`status`、`workspace`）的显示值由目录所有者交付，并按目录的 `epoch/revision` 水位合并。会话状态流快照虽同样携带会话定位信息，但属于另一版本域，不得反写目录分页窗口；`updatedAt` 仅为业务时间戳，既不能用于排序这两个不同版本域的资源更新，也不能判定同秒载荷的新旧。即使会话流首帧快照晚于目录终态到达，也不得将 `idle` 状态、最新标题或工作模式回退为旧值。工作区视图、连接器（Connector）与验收驱动（Driver）统一从当前目录行组合会话身份与会话轻量状态；未进入目录行的独立会话镜像仅凭自身快照定位，不据此插入分页目录。工作模式变更必须由 Rust 提交目录增量并推进目录水位，前端不得以首帧快照合并、同水位基线或命令后回读来补偿缺失的目录事件。

会话路由变更的权威状态仅由会话有序流交付：Rust 原生层在提交 `model_route` 扩展变更时发布新的会话快照，Dart 侧按同一 `epoch/baseRevision/revision` 水位收敛。命令响应中的 `runtime` 字段仅服务于调用方 CAS 校验与就地错误提示，**不写入状态存储（store）**，也不通过与流事实比较修订号来择一采纳——同一事实不允许存在第二条合并路径。响应同时携带的设置快照属于另一独立资源，按 §18.11 的双时钟规则合并；工作模式变更由 `ThreadDirectoryChanged` 增量事件交付（见 §18.2 与 §18.8），工作模式默认路由的改写则属于设置事实。因此，命令成功后严禁重新读取聚合状态或会话快照来“补齐”显示值；任何缺帧问题必须在事件帧发布与归约链路上修复（见 [25](./25-frontend-state.md) §25.5），防止乐观投影清除后选择器回退至旧值。
