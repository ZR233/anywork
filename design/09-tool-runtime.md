# 09 - 工具调用运行时与线程边界

本文是通用工具身份、动态注册、并发调度与执行边界的唯一权威源；工作流（Workflow）专属工具契约见 [11](./11-thread-mode.md)，多智能体协作工具（`spawn_agent` 等）的参数与工作区语义见 [12](./12-collaboration.md)，会话后台任务交付机制见 [14](./14-runtime-host.md)。

自动派发模式下的候选模型查询工具（`list_delegation_models`、`get_delegation_model`）与子智能体最终评价工具（`evaluate_agent`）归属 Studio 产品层协作工具，仅挂载于主智能体（根智能体）：前两者为有界只读查询，后者为独占写操作。固定与自动派发模式下的 `spawn_agent` 参数声明、模型准入资格及评价授权详见 [12](./12-collaboration.md) §12.7。工具目录仅暴露当前派发模式允许的参数，请求容量预览与正式推理调用共享完全一致的工具声明与独占身份集合。

外部机器人会话工具遵循相同的不透明 `Tool` 接口与宿主端口装配模式，不同线程之间不共享可变工具实例；其项目级授权、会话查询与外部消息发送语义见 [27](./27-bots.md)（外部消息发送属写操作，不具备只读编程式调用资格）。

## 9.1 工具身份、所有权与历史落盘栅栏

`discover_tools` 只在当前 Thread 可见目录中按工具 ID 匹配：`query` 首尾去空白并忽略大小写，整串作为一个字面子串，不拆分空格、不解释自然语言意图或搜索工具描述；最多返回 20 个匹配并揭示相应声明。空查询匹配目录中的首批条目，不表示完整枚举；无匹配只说明该子串未命中，不证明相应能力全局不可用。工具声明直接说明查询方式，不依赖调用者事先读取某个领域技能。

### 不透明接口与单点状态所有权

具体工具实现 `pl-core` 的不透明 `Tool` 接口，通过注册句柄将工具实例所有权移交给所属会话线程（`Thread`）。工具声明与调用参数均为带格式与版本号的不透明载荷：参数模式（schema）、业务权限分类、JSON 解析、工作区路径约束与输出截断投影归属 `pl-tool`，模型可见声明编码归属 `pl-model`，`pl-core` 自身不解析工具 JSON。内置补丁工具是该契约的现役实例：其规范声明为带 lark 语法的 freeform 工具，输入是补丁原文而非 JSON 对象，形态投影与执行边界见 §9.8。

每次模型请求冻结同一份工具目录与执行器（executor）快照，并将稳定工具身份与原始调用参数写入日志。工具执行结果分别保存完整的原始载荷（payload）与裁剪后的模型可见上下文（context）；已产生外部副作用的失败调用同样携带已观测输出事实一并保存。会话笔记（Note）、待办事项（Todo）与技能（Skill）激活状态统一存储在线程扩展（Thread extension）中，工具实例自身不维护第二份会话状态。

模型返回的工具名称只允许与该请求的冻结声明精确匹配，未知名称不能被猜测、补全或直接当作内部稳定工具 ID 使用。未知名称与已知工具的参数转换失败分别保存类型化拒绝事实、原始名称、调用 ID 和原始参数；整批输出在准入前被拒绝，不启动其中任何工具。框架可在轮次内提供有限纠正机会，反馈明确说明本批没有执行工具、没有由本批产生副作用，并要求模型依照下一请求的当前可见工具声明重新选择名称和参数。可用名称、参数 schema 与自定义输入格式直接来自同一次请求的正式声明，不另维护提示清单，不恢复被隐藏或撤销的权限。纠正预算、身份校验及协议历史规则见 [16](./16-core-contracts.md) §16.3。

工具回执可声明专属的产品层展示投影：例如图像展示工具的回执携带归属当前线程的资源引用与有界说明文案，Studio 将该引用投影为时间线卡片的图片附件，使界面渲染与附件读取无需依赖当前对话模型的图像输入能力；而模型可见上下文中仅保留一条有界事实文本，既不重复注入图片字节，也不赋予该工具额外的控制权限。

`finish_turn` 的版本化交付保留完整 `message`，并可携带结构化 `review`；输入格式由工具层拥有，是否具备审查资格、结论是否有效及受限回送由 Studio 按冻结身份解释（见 [12](./12-collaboration.md)）。工具完成控制仍只表示结束本轮，不表示任务通过或授权跨线程发送。工具专用解码仅消费当前格式与版本，旧版和未知版本不生成新的报告语义，也不能从文本补成审查批准。历史原始载荷、已保存正文与资源引用原样保留，通用历史查询仍按原 `format`/`version` 返回，不改写载荷或重执行工具；内核继续只处理不透明载荷与通用 EndTurn。

普通执行者交付或判断需要停工均使用同一 `finish_turn`，停工不另设工具或执行状态。子智能体结束本轮、宿主路由报告、接收方 `wait` 被消息唤醒是不同边界；可靠交付及异常通知复用现有消息、应用扩展和历史能力，不新增查询回送或确认完成工具，也不从工具返回成功推断业务验收通过。

### 历史落盘栅栏（`history_fence`）

`CallContext.history_fence` 记录工具启动执行时刻该线程已提交的核心效果（effect）序号（至少覆盖该工具自身的“运行中任务”事实）：
- **副作用前置持久化屏障**：对于挂载了持久化存储（`ColdStore`）的线程，`pl-core` 在调用任何工具执行器之前，必须等待历史写入任务将不低于 `history_fence` 的效果序号可靠落盘。因此，即便是动态注册或未知副作用类别的工具，也绝无可能在运行记录落盘前产生外部副作用。
- **故障阻断与取消安全**：若效果受理或落盘失败，内核立即阻止工具启动、记录类型化存储故障并暂停后续准入；等待栅栏期间若收到取消信号，则直接中止且不启动工具执行器（未挂载 `ColdStore` 的纯内存线程无此落盘等待）。模型上下文的修订号（revision）不等同于核心效果序号，不能替代该栅栏；工具执行器仅接收序号值，不直接接触会话数据库或存储键。
- **显式控制权限授权**：工具不得凭工具名、MCP 注解（annotations）或输出文本获取执行控制权。结束轮次（`finish_turn`）、扩展 CAS 更新、发起用户交互、工具发现、后台任务等待与取消均须通过注册期的显式授权标志及类型化控制返回值触发。取消或失败的调用保留已观察输出，但严禁提交迟到的控制指令或扩展状态更新。计划（Plan）与工作流（Workflow）工具及状态机归属 Studio 产品层，不下沉至 `pl-core`。

## 9.2 动态注册、撤销与热目录刷新

### 原子替换与租约延续

工具的动态注册与撤销在线程所有者的串行边界内完成，准备失败时不发布残缺目录。连接重连不改变工具声明身份，已冻结的模型调用继续持有旧执行器租约；但在准入前、执行前与控制结果提交前，系统仍会再次核验该工具权限是否已被撤销。

热目录刷新机制订阅产品配置、MCP 代次（generation）、技能目录、智能体预设（Agent Profile）目录、SSH 配置/凭据以及语言服务器（LSP）目录变更事件，同时消费在线模型目录的观察更新：
- **仅重建声明与执行器**：热刷新仅重新构造具体工具声明与执行器，不重放历史消息、不重读系统指令、也不刷新 SQLite。内核工具注册表原子替换后，已在途的模型步骤继续持有旧执行器租约，而已被撤销权限的工具在新目录下拒绝后续准入。
- **跨刷新复用命令管理器**：同一线程的命令进程管理器跨工具目录刷新保持复用（内部缓存仅持弱引用），但相同线程 ID 新建的线程所有者实例绝不继承旧实例遗留的物理资源。若已冻结的工作区路径或 SSH 远程目标发生改变，系统立即清空不可再授权的工具目录并报告“需重新激活会话”，禁止隐式切换至新路径继续执行。
- **智能体预设与条件服务工具刷新**：当智能体预设目录发布新代次时，触发根线程工具刷新，`spawn_agent` 的分支参数模式与 `list_agent_profiles` 的执行视图同步更新（不会向子智能体赋予派发能力，也不改动存量子智能体身份，详见 [12](./12-collaboration.md)）。依赖账号外部服务能力的条件工具（如图像生成工具）在在线模型名单更新或凭据状态变化后，按最新观察动态重规划安装状态，确保模型不会看到必然失败的工具声明。

### 刷新故障诊断与退役资源回收

- **非破坏性故障恢复**：候选目录准备失败或扩展版本冲突不会清空当前仍有效的已安装工具目录（仅当底层物理目标、凭据或权限实质失效时才撤销对应工具能力）。目录刷新失败时发布 `ToolCatalog/Retry` 诊断信息，不将其判定为会话历史损坏，亦不阻塞历史浏览、停止轮次或继续发送消息；后续配置变更或用户显式点击恢复重试将触发新一轮准备，成功后自动清除诊断。
- **两阶段退役责任**：已被线程所有者接纳并替换下来的旧执行器，由核心会话所有者负责在全部使用租约释放后关闭并回收；而在移交前即被条件发布拒绝的过期候选执行器，若异步关闭失败，则由 Studio 持有原始可重试资源与拒绝原因（绑定原线程实例代次），在该失败候选清理完毕前不再为同一所有者重复构造新候选，也不将失败指纹标记为已安装。目录监听任务采用协作式停止，确保在途资源移交完毕后再退出；宿主关闭（shutdown）时会重试未完成的候选清理，若仍失败则返回明确错误并保留所有者现场。

## 9.3 并发调度声明与批处理

工具注册时将**执行等待策略**与**模型批次约束**分开声明，执行等待策略共分三类：

1. **前台独占（`foreground`）**：必须单独调用，禁止与同一模型响应中的任何其他工具调用混批。拥有真实控制权限的工具（如结束轮次、修改扩展状态、派生或控制子智能体）强制要求前台独占，不得降级为可同批前台工具。
2. **可同批前台（`foreground_coexisting`）**：允许与其他可同批前台工具出现在同一模型响应批次中，线程按模型给出的调用顺序依次等待前一个调用到达终态后再执行下一个，并继承当前轮次的取消令牌。`write_file` 与 `apply_patch` 采用此策略；该顺序仅约束当前线程内的前台调用次序，不构成跨后台任务或外部进程的文件系统事务。
3. **后台任务（Background Task）**：提供 1 秒的前台快速交付窗口；若命令或任务在 1 秒内完成则直接同步返回结果，否则立即返回运行中任务回执（receipt），实际任务继续在线程后台运行，并在到达终态后通过线程消息邮箱（mailbox）在后续请求准入时交付完整结果（见 [14](./14-runtime-host.md)）。
   - **标准输入工具（`write_stdin`）**：沿用此策略，避免背压、输入锁等待或 SSH ACK 等待阻塞模型继续调用取消工具。输入调用的任务身份与原 exec 分开；模型可取消该次输入并查询已接纳/远端已确认的前缀，原进程仍独立管理。同一进程的输入继续由既有输入锁串行处理；后台受理不构成输入已完成的屏障，后续依赖输入完成的动作须等待该输入任务终态。
   - **定时等待工具（`sleep`）**：作为标准后台任务工具注册，而非前台阻塞调用或独立调度器。若计时在 1 秒交付窗口内结束则直接返回；否则返回可查询、可取消且可传入 `wait` 工具的任务回执。当模型使用 `wait` 同时等待该计时回执与其他任务时，定时器到期或新消息到达均可提前唤醒，且单次 `wait` 调用超时不等同于底层 `sleep` 定时器已完成。
   - **图像生成工具**：同样作为后台任务运行，终态结果包含已归档媒体引用与完整载荷；模型通过 `wait` 等待就绪，或通过 `get_tool_task` 读取完整结果。后台任务使用独立的取消令牌，仅响应显式的 `cancel_tool_task` 调用或整轮中断，不随单步超时自动取消，且后台工具不得携带任何会话控制权限。

## 9.4 进度预览与物理身份映射

### exec 输入与失败事实

`exec` 的授权与执行共用严格的纯参数校验：仅接受 `command`、`cwd`、`timeoutSeconds`、`maxOutputChars`，在 FullAccess、审批和自动审查的权限判断前拒绝无效参数。字段路径来自 Serde 解码，保留原始诊断及行列；空白命令和零额度分别给出稳定分类。命令文本不改写，每次 cwd 独立，timeout 默认 60 秒，自进程管理器接纳开始计算，审批等待不计入。

模型必须依据执行事实恢复：参数错误明确 `processStarted=false`；已执行后的非零退出、超时、取消、捕获或归档失败保留原任务与已观察输出，不能把错误理解为可以重跑命令。物理 `task-<sha256>` 名称不能作为任务控制句柄，模型可操作的 taskId 仅来自 Thread 的真实任务记录。取消调用的部分事实保存在原 payload，通过该次调用的真实 taskId 查询。

stdout 与 stderr 的纯输出内容共用请求的 UTF-8 字节预算，默认和上限均为 65,536；历史字段名 `maxOutputChars` 保留。工具生成的省略标记也计入正文额度。任务身份、诊断、资源引用、后台完成通知及 JSON 转义和协议包装允许额外占用，不挤占正文额度，不要求整个序列化结果小于 64 KiB。模型投影保留与 immutable payload 一致的正文和元数据，不因编码或包装再次裁剪正文，也不以元数据过大为由替换为丢失任务身份的占位回执。原始双流另受共享 16 MiB 捕获上限约束。历史结果查询按原 format/version 做 8192 字节的 UTF-8 安全分页，resident 淘汰后读取同一 Thread 的 durable delivery，不重执行工具。

模型不得为满足 schema 而省略或替换用户明确指定的命令参数后执行；schema 无法表达的要求保持未执行并说明限制。数字 schema 保留零值的结构表达能力，正整数要求由同源语义校验在授权前拒绝，并返回字段诊断与未启动事实；不借 constrained decoding 将零值测试替换为 null/default 执行。成功输入仍只允许正值。真实模型观察区分“未能提交”和“已提交后拒绝”，不能把默认参数执行当作负向用例通过。

启动准备、worker Ready/configure 和业务 Start 共用接纳时建立的单调时钟期限与取消作用域。准备 I/O 完成后重新检查；Start 尚未尝试时清理并回收 worker，Start 可能已发送时保留原 owner 确认、取消与 join。SSH 仅传剩余毫秒，在重连后仅确认原 operation 未执行时允许更新剩余额度再提交；期限不重新计时。

展示字节数包含工具生成的省略标记，omittedBytes 仅计算省略的源字节；发生有损解码且同时截断时，无法精确映射的源字节省略量明确为 null，不能伪报为零。

新执行仅产生当前版本的 `pl.tool.exec`，同步交付与后台任务查询消费同一结果结构；退出码等工具专用投影只解释当前格式与版本，不再解码旧版结构。旧载荷仍可按原 `format`/`version` 通用查询，已保存展示文本与资源引用不变，不重写 payload，也不从旧字段补推退出码。当前结果给出真实 taskId、退出码/signal、双流展示字节与截断事实、执行侧 `stdoutFile`/`stderrFile`、确认前缀、捕获及归档状态和可用的下一步。原始双流按字节分别保存，共用 16 MiB 捕获额度；命令、cwd、流标签只属于记录与展示。捕获队列仍由一个 owner 顺序写入，按流推进确认偏移；失败后停止接纳，修复先恢复该流已确认前缀，再重放原始 pending chunks。归档双流合计受现有归档上限约束；部分资源保存成功仍保留引用，失败流分别挂现有可靠保存义务，不重跑 shell。SSH capture 失败不能覆盖同一终态中的退出码、signal 和已确认偏移；未保存的源字节不可承诺全部可恢复。

`write_stdin` 使用原 exec 的真实 taskId，必填 chars，新增默认 false 的 `closeStdin`。非空文本写入后可发送 EOF；空字符串仅在 `closeStdin=true` 时有效。锁等待、逐次 write 与 flush/ACK 等待均观察当前输入调用取消；接纳偏移逐次累加，SSH 确认只来自 helper 的 offset/CloseStdin ACK。回执区分 acceptedBytes、remoteConfirmedBytes、deliveryPending、closeState 和 outcome。取消输入不隐式终止 exec，也不重发已接纳字节；纯 EOF 到达终态任务时只回传现有事实，关闭状态已不可确认时不伪造 closed。

- **有界实时进度预览**：运行中的命令通过任务进度通道上报至多 **64 KiB** 的合并内容预览（超出部分标记截断，完整输出由归档服务独立保存）。预览数据仅归属原任务、原执行器及当前运行中的线程，不推进历史水位，也不写入模型上下文或持久化检查点；一旦轮次或任务终态提交即清除预览。
- **物理文件名散列映射**：模型或内核生成的工具调用 ID 在进入操作系统命令进程与文件归档边界时，统一转换为有界的 `task-` 前缀加 SHA-256 摘要作为物理标识，严禁直接将原始调用 ID 拼接为文件名。`exec` 与 `write_stdin` 共享同一映射规则，并在工具目录热刷新后继续引用同一线程的命令进程管理器（不同线程的进程管理器严格隔离）。
- **执行侧会话文件布局**：命令输出捕获（capture）文件与模型任务临时文件统一遵循 [17](./17-studio-storage.md) 定义的执行侧会话目录布局。路径由所属线程身份与调用身份单点派生，系统提示词、路径策略与本地/远端后端消费同一映射。`stdoutFile`、`stderrFile` 是相对工作区根的原始双流文件路径，不相对于原命令的 `cwd` 或会话临时目录；使用 `exec` 续读时省略 `cwd` 或设为 `.`，逐字使用回执路径。读取失败须先核对路径基准，不能将错误的工作目录判为捕获丢失或据此重执行命令。这些路径仅供执行期读取；历史重开以持久资源身份为准，没有重新物化的资源不能宣称旧路径仍有效。捕获/归档失败保留原字节及可靠保存义务，不重执行命令。

## 9.5 编程式调用（Programmatic Calling）资格

编程式工具调用资格由各工具在注册时显式声明：LSP 查询、只读 Git 工具、已确认为只读的 MCP 工具以及 MCP 资源读取工具可声明允许的调用方（caller）及结构化输出模式（output schema）。副作用未知的工具、写操作工具、用户交互工具与状态变更工具不具备该资格；模型协议适配层仅根据当前模型路由已验证的能力决定是否下发这些声明，不按工具名称猜测权限。

## 9.6 MCP 能力声明与轮次租约

- **非阻塞代次租约**：线程装配工具目录时直接获取当前已发布的 MCP 代次（generation）租约，不阻塞等待后台正在连接或探测中的 MCP 服务。尚未就绪的服务不进入本次冻结目录，待其初始化完成并发布新代次后，通过通用热目录刷新机制更新后续模型请求。慢速或失败的 MCP 服务绝不阻塞新建会话、保存账号配置或其他无关服务。
- **MCP 资源门面（Resource Façade）按需暴露**：运行时在 MCP 握手阶段（`initialize` / `server/discover`）读取服务端声明的 `resources` 能力标志，仅将明确支持该能力的服务纳入当前租约的资源分配表（resource assignment）。当没有任何已连接服务支持 `resources` 能力时，不向模型注册 `list_mcp_resources`、`list_mcp_resource_templates` 或 `read_mcp_resource` 工具。资源聚合查询仅访问分配表内的服务；若模型显式指定了未声明该能力的服务名，工具在发出网络请求前直接返回稳定的参数错误，不发送探测请求，也不会因此将正常的 MCP 传输连接标记为不可用。
- **执行器租约捕获**：每个 MCP 工具执行器必须捕获创建该执行器时的轮次租约（`McpTurnLease`）、服务端身份、原始工具名与代次号。即使全局已发布新代次，已冻结的旧工具计划仍通过原租约调用旧连接；直至持有该代次的所有执行器与工具计划全部释放后，底层旧连接才被正式回收。远端 MCP 服务返回的展示元数据不得提升本地工具的副作用分类、并发策略、编程式调用资格、缓存策略或安全权限。

## 9.7 文件发现与读取归属命令工具

工具目录不提供 `list_files`、`read_file` 或替代的独立目录搜索、文本读取工具。模型枚举、查找和读取文件统一通过 `exec`，根据任务与目标环境选择已有命令；命令方言以运行时注入的 `Platform` 段（`Runtime execution environment` 中的目标 OS、shell 方言与可执行路径）为准。提示采用原则与示例说明：优先考虑适合任务的工具，例如用 `rg --files` 发现文件、用 `rg` 搜索文本；命令不可用、版本或方言不同、不适合任务时，就地核实并选择平台已有替代方式，不规定唯一命令。

该路径沿用命令工具既有的工作区约束、输出截断与归档语义，不为同一操作维护第二套行范围分页、内容散列或读取缓存契约，也不以工具名区分读取与命令执行的权限分类。文件访问许可不隐式授予命令执行许可。宿主内部的技能发现、递归复制和目录选择仍使用各自的目录读取能力，不作为模型目录工具暴露。

工作区文件工具目录保留写入、元数据（`stat_path`）、建目录、删除、复制、移动与 `apply_patch`。`apply_patch` 为匹配上下文而读取目标文件属于其内部实现步骤，不单独暴露为工具，也不为模型提供绕过命令工具的独立读取入口。

## 9.8 补丁工具的声明、输入形态与应用语义

- **声明形态与投影条件**：内置 `apply_patch` 的规范声明是带 lark 语法的 freeform（custom）工具，语法定义由 `pl-patch` 单一维护，`pl-tool` 与 `pl-model` 复用同一份定义而不各自持有副本。实际下发形态由 `pl-model` 在请求准备阶段投影：仅当端点使用原生 custom tool 线协议、端点声明补丁工具类型为 freeform、且当前模型能力同时声明 custom 与 freeform 工具时保留 freeform 声明；任一条件不满足即投影为函数回退（`function-fallback`）声明，其参数为单个 `input` 字符串并携带完整补丁文本的格式说明。主请求与上下文压缩使用同一判定与同一投影结果，不得出现两条路径形态不一致。
- **输入形态与所有权**：freeform 形态下模型直接产出补丁原文，不包裹 JSON；函数回退形态下模型按函数参数填写 `input`，由 `pl-model` 解包还原为原始补丁文本后再移交执行器，无法合法解包的模型输出按被拒绝的尝试处理，绝不路由到可执行工具。执行器只消费补丁原文，目标路径相对工作区默认目录解析；补丁工具不再接受独立的 JSON 工作目录参数，也不为历史形态保留第二条输入通道。
- **应用语义**：逐级放宽的模糊匹配（依次忽略尾随空白、首尾空白与常见 Unicode 标点/空格差异）只用于定位应用位置，不决定写入内容。命中区段内，解析阶段标记为上下文（context）的行保留目标文件原有行文本与行尾，从而不改动未要求修改的空白；删除行与新增行一律写入补丁给出的原文，缩进属于内容，不得被匹配启发式回填为文件旧值。解析阶段即确定上下文行与改动行的角色，应用阶段不再按内容近似重新推断。
- **失败与部分应用语义**：上下文或改动行无法定位时该次调用失败并返回原因与重试指引（要求重新读取目标文件后提交更小的补丁），不得以“匹配到近似行”为由报告成功而实际未改变内容；多 hunk 补丁按序应用，失败时保留已应用变更并在失败摘要中明确列出，禁止把部分应用伪装为完整成功。
- **审批评估**：freeform 原文不经过 JSON 参数解析，宿主装配的访问评估器必须能从补丁原文提取受影响的 Add/Delete/Update/Move 路径并沿用与 JSON 参数相同的工作区/外部访问判定；仅当确实无法提取路径时才按保守策略处理，不得把可解析的补丁原文一律视为无路径的未知调用。
