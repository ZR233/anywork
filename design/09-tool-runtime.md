# 09 - 工具调用运行时与 Thread 边界

本文是通用工具身份、注册、调度与执行边界的唯一权威源；workflow 专属工具契约见
[11](./11-thread-mode.md)，协作工具（spawn_agent 等）的参数与工作区语义见
[12](./12-collaboration.md)，会话后台任务交付见 [14](./14-runtime-host.md)。

自动分发的 `list_delegation_models`、`get_delegation_model` 与最终评价 `evaluate_agent`
属于 Studio 产品协作工具，仅装配到主智能体；前两者是有界只读查询，后者为独占写入。
固定/自动模式的 spawn 声明、选模资格和评价授权归 [12](./12-collaboration.md) §12.7。
目录只暴露当前模式允许的参数，准备预览与正式调用使用同一声明及独占身份集合。

机器人会话工具沿用相同不透明 Tool 与宿主端口装配，不共享可变工具实例。其项目授权、
会话查询与外部发送语义归 [27](./27-bots.md)；发送不取得只读 programmatic 资格。
机器人根会话的 `submit_bot_file` 是仅向当前入站来源聊天提交文件的独占外部写工具。
目标与权限由宿主依据调用 Thread/Turn 的可靠入站事实确定，不能由参数、文件路径或
模型文本授予；它不开放项目的跨聊天发送，也不自动装配给子代理。具体契约归 [27](./27-bots.md)。

## 9.1 身份与所有权

具体工具只实现 core 的不透明 Tool 接口，以注册句柄将实例所有权转移给 Thread。工具定义和参数是
带 format/version 的不透明载荷：tool 解释参数，model 解释模型声明，core 不解析 JSON。参数
schema、业务权限分类、JSON 解析、工作区约束和输出投影属于 pl-tool。每次请求冻结同一工具目录
与 executor，稳定工具身份和原调用参数进入日志。工具输出分别保留完整 payload 与模型可见
context；已观察到副作用的失败携带输出事实保存。Note、Todo 和 Skill 激活使用 Thread 扩展，
工具不持有第二份会话状态。

工具回执可以声明自己的产品投影：图像展示工具的回执携带 thread-owned 资源引用与展示文案，
Studio 把该引用投影为时间线卡片的图片附件，使界面展示与附件读取不依赖 prepared 模型的图片
输入能力；模型可见上下文只保留一条有界事实文本，不重复图片字节，也不因此获得控制权限。

`CallContext.history_fence` 是工具开始执行时，Thread 已提交的 effect 序号；它至少覆盖
该工具的运行中任务事实。附加 ColdStore 的 Thread 在调用任何工具执行器之前，由 core 对此
固定序号等待持久化；因此动态注册及未知效果的工具也不能越过屏障执行外部副作用。受理或持久化
失败会阻止执行、记录类型化存储故障并暂停后续准入；等待期间的取消不会启动工具。没有附加
ColdStore 的纯内存 Thread 没有持久化保证。模型上下文的 revision 不是 effect 序号，不能
代替这个屏障。工具只收到序号，不接触会话数据库或其存储键。

工具不能由名字、MCP annotations 或输出正文取得控制权：结束 Turn、扩展 CAS、交互、发现、任务
等待与取消均使用显式注册授权及类型化控制值。完整 payload 与实际 delivered context 分开保存；
取消或失败保留观察结果，但不得提交迟到控制或扩展更新。Plan/workflow 工具与状态机属于
Studio，不进入 core。

## 9.2 动态注册、撤销与热目录刷新

动态注册与撤销在 Thread owner 中完成，失败不发布部分目录。重连不改变声明身份，已冻结调用
持有旧执行租约；准入前、执行前和控制提交前仍校验权限未被撤销。

热目录刷新订阅产品配置、MCP generation、Skill 目录以及语言服务目录事件。刷新只重新构造具体
工具声明与执行器，不重放历史、不重读指令、不刷新 SQLite；核心注册表原子替换后，旧模型 step
的执行器继续持有原租约，已撤销权限按新目录拒绝后续准入。一个 Thread 的命令管理器跨目录刷新
复用，缓存只持弱引用；同 ID 的新 owner 不继承旧 owner 的物理资源。已冻结的 workspace/SSH
目标发生变化时清空不可再授权的目录并报告必须重新激活，不能偷偷改为访问新路径。

工具目录安装代次与文件执行绑定身份是不同事实：前者用于拒绝陈旧目录候选，后者约束
在途附件准备可以发布的工作区及授权。仅替换工具声明、Skill 或模型目录时，若 Thread
生命周期、物理工作区租约及文件执行授权均未改变，应保留文件执行绑定身份，不使合法
在途物化失效。目录候选每次发布仍须校验其安装基线，不能为复用文件身份放宽候选 CAS。
工作区、SSH 目标或凭据、物理租约、执行权限发生变化，或 Thread 关闭时，旧文件绑定
必须失效；文件路径发布与该失效在同一同步边界裁决，不以目录刷新成功证明旧路径有效。

本地目录能力获取和受限文件读取属于显式 `LocalFileIoOwner` 生命周期。可取消的工厂
在调用前由 Thread、工具构造租约或已有宿主操作 owner 持有该 owner；不能等工厂返回
backend 后才登记。封口与任务登记互斥，关闭等待真实阻塞工作 join，取消关闭可继续等待。
同 Thread 的上传物化复用其 lifetime owner；工具退役只关闭自己独立的读取租约，不使
其他目录版本失效。普通无显式 owner 的构造入口要求调用方完整持有构造和关闭义务，
不承诺构造 future 被遗弃后宿主仍可找到它；可取消装配不得使用该入口。
Thread factory 的同一物理绑定登记覆盖 preparing、abandoned 与 ready 三种生命周期
状态。在任何本地根/工具资源工厂开始前先登记 lifetime；尚未确定的工作区不伪装为
ready binding。同步准备 guard 仅标记放弃和取消，不移除仍可能持有工作的 owner；
失败、同 ID 重试和最终 shutdown 均先真实排空，再按同一 lifetime 身份移除。
成功移交工具注册后才解除构造期保管；尚未形成注册的候选也必须能被宿主找到并关闭。
标准文件工具跨目录刷新共享 Thread 级 I/O owner，单个窄外写工具使用独立构造/实例
租约；租约成功移交后不永久保留已退役历史实例，关闭失败则保留同一可重试资源。
共享 worktree-pool 的目录准备属于现有 worktree 服务 owner，而非尚未发布的 Thread；
该服务在构造本地文件 backend 前持有其 I/O owner，关闭业务准入并排空 Thread 后仍须
等待相关目录能力工厂收束，布局写入仍遵循既有准备操作的生命周期。已被 core 持有
且完整等待终态的命令 capture 准备可沿用命令
任务生命周期，不为仅执行目录/stat/write 的短期 backend 重复建立全局登记。

SSH 配置或凭据变更单独通知目录刷新并撤销旧物理绑定；日志和信号不携带 secret。候选准备或
扩展版本冲突不清空仍有效的已安装目录；物理目标、凭据或权限失效则撤销不可再授权的能力。
目录刷新失败发布 ToolCatalog/Retry 诊断，不表示历史损坏，不阻止历史读取、停止或继续提交。
相关配置变更与显式恢复重试均触发新一轮准备，成功后清除对应诊断；过期或关闭的 owner 不得
发布迟到结果。刷新准备使用所属任务的取消信号，关闭观察 barrier 成功后回收绑定缓存，失败时
保留以便重试。

已接纳的过期候选由核心会话所有者承担退役责任；尚未移交的拒绝候选关闭失败由 Studio
持有原始可重试资源及拒绝原因，并绑定原 Thread incarnation；
失败候选清理完成前不再次构造同 owner 的候选，不把失败指纹标记为已安装。目录 watcher 采用
协作停止，完成在途资源移交后再退出；shutdown 重试未完成候选关闭，失败返回错误并保留
owner，取消 shutdown 等待也不得丢失资源。

热目录刷新同时消费模型目录观察发布：依赖 provider 服务能力的条件工具（如按在线目录注册的图像
生成工具）在名单出现、撤销或凭据不可用后按新观察重新规划，未受影响的线程不重建执行器，也不
重放历史。是否安装只由当前目录声明、在线观察与凭据可用性决定，模型看不到必然首次失败的工具；
撤销只影响后续准入，已冻结调用继续持有原租约。

## 9.3 调度声明与批处理

工具目录只拥有当前执行器；替换后旧实例进入退役。已冻结的模型计划、待执行和后台调用、
未提交结果通过明确使用租约保持原执行器，使用者全部释放后由 Thread owner 关闭并释放。
清理失败保留原实例和进度并公开运行期故障，不把全部历史实例保留至会话关闭。合法的失败或
取消重试保留冻结计划；成功接纳、重试失效和关闭释放计划。关闭先释放自身计划，再等待退役。
共享命令管理器与外部服务的物理寿命仍由各自租约决定，退役单个工具不能终止其他合法使用者。

注册的执行等待策略与模型批次约束分开声明，共三类：

- 前台独占（foreground）：必须单独调用，不能与任何其他调用混批。
- 可同批前台（foreground_coexisting）：可与其他前台工具同批，按模型给出的调用顺序等待每个
  调用终态，并继承本轮取消。
- 后台任务：一秒交付窗口后返回运行回执，结果经消息收件箱送达（见 [14](./14-runtime-host.md)）。

`sleep` 是已注册的普通后台任务工具，不是前台阻塞或独立调度器。计时在交付窗口内完成时直接
返回结果；否则返回可查询、取消并加入 `wait` 的任务回执。用回执与其他任务共同等待时，定时器
或消息先就绪即可唤醒，不把一次 `wait` 的超时当成计时器完成。

真正控制权限（结束 Turn、扩展变更等）始终要求前台独占，不可通过可同批前台能力降级。
`write_file`、`apply_patch` 和 `write_stdin` 使用可同批前台能力；现有 writer 互斥保持，不新增
跨后台或外部进程的读写事务保证——该顺序不是外部文件系统事务，不承诺阻止已有后台任务或外部
进程访问文件。`write_stdin` 只等待写入完成，不等待 exec 进程终态。

图像生成使用后台任务：受理后返回运行回执，执行 future 留在 Thread 后台，终态（含归档媒体与
完整 payload）经消息收件箱在后续请求准入时交付；模型用 `wait` 观察就绪，可用 `get_tool_task`
读取完整结果。后台调用的取消使用独立任务令牌，需显式 `cancel_tool_task` 或 Turn 打断，不继承
本轮取消。后台工具不得携带控制权限。

## 9.4 进度预览与物理身份

命令进度通过任务进度通道上报有界的通用内容预览。预览只属于原任务、原执行器和仍在运行的
Thread；更新不提升历史水位、不进入模型 context 或持久化状态。Thread 终态提交清除预览，
历史只保存已提交的完整结果。命令采集端合并至 64 KiB 预览并标记截断，完整输出仍由归档服务
保留；预览传输与命令执行同生命周期，不派生无 owner 的后台队列。

Provider/core 调用 ID 进入命令进程与归档边界时，转换为有界 `task-` 前缀加 SHA-256 的物理
身份，不能直接作文件名。`exec` 与 `write_stdin` 使用同一映射，目录重建继续引用同一 Thread
的进程管理器；不同 Thread 的管理器保持隔离。

命令 capture 与模型任务临时文件共用 [17](./17-studio-storage.md) 的执行侧会话布局，不再
把新的命令输出写入 `target/pure/`。路径身份由实际 Thread 和调用身份单点派生，提示词、
目录写策略、本地与远端 command backend 必须消费同一映射，不能各自拼目录或用不透明
process id 推测文件名。`outputFile` 是执行侧可读路径，可靠 resource 引用才是跨重开历史的
持久依据；capture 归档失败保持源文件及既有修复义务，不重复执行工具。

## 9.5 Programmatic 调用资格

Programmatic 调用资格由具体工具的声明提供：LSP、只读 Git、已解析为只读的 MCP 工具和 MCP
资源查询携带允许调用方及输出 schema。未知效果、写操作、交互和状态更新不自动获得资格；模型
适配只按已验证的 route/hosted capability 决定是否编码这些已声明资格，不按名字推断权限。

## 9.6 MCP 能力声明与租约

Thread 工具装配取得当前已发布 generation 的租约，不等待后台连接或目录准备。尚未完成的
server 不进入本次冻结目录；新 generation 发布后通过通用热目录刷新更新后续请求。慢或失败
MCP 不得阻塞创建 Thread、供应商保存或无关服务；此规则对系统与用户 MCP 相同。

MCP resource façade 属于本轮冻结工具目录。Runtime 必须读取 server 在 initialize/discovery 中
声明的 `resources` capability，只把支持该能力的 server 写入 lease 的 resource assignment；
没有任何此类 server 时不向模型暴露 `list_mcp_resources`、`list_mcp_resource_templates` 或
`read_mcp_resource`。聚合查询只访问 assignment 中的 server；显式指定未声明该能力的 server
必须在发送请求前返回稳定参数错误，不能用一次预期的 `Method not found` 探测能力，也不能因此
把正常 MCP transport 标记为 unavailable。模型可见 schema 与执行路径必须消费同一冻结
assignment，避免暴露必然首次失败的工具。

MCP tool executor 必须捕获创建它的轮次租约（McpTurnLease）、server identity、raw tool name
与 generation；旧工具计划即使在新 generation 发布后仍调用旧 lease，最后一个 executor/plan
释放后才能回收旧连接。远端展示 metadata 不得提升 effect、并行、programmatic、cache 或权限
策略。

## 9.7 文件读取缓存与可见内容

`read_file` 的精确请求可复用同一工作区 epoch 内的结果，但命中仍返回所请求的文件内容，不能只
返回"此前已读取"的摘要。不同的行范围按独立请求处理；模型可能是在输出截断或上下文压缩后补读，
不能把旧范围被覆盖等同于正文仍在模型上下文中。文件 IO 的精确请求去重及变更失效规则保持
有效。协作控制调用可能触发或观察 child 的文件变更，因此使父代理的 workspace 缓存 epoch
前进；不能跨 child 派发、续跑或交付边界复用旧文件视图。
