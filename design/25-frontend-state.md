# 25 - 领域仓储、呈现状态与资源生命周期

Rust 运行时持有业务权威事实；纯 Dart 领域仓储（`Repository`）归并只读镜像；生成式异步视图模型（`AsyncNotifier`）编排功能呈现；连接器（`Connector`）绑定观察与用户意图；纯视图（`View`）只渲染数据。本文是 Dart 分层、状态所有权、命令回执、输入草稿与页面导航的唯一权威契约。可靠历史见 [17](./17-studio-storage.md)，实时协议见 [07](./07-streaming.md)，产品资源见 [18](./18-studio-state.md)，界面与内容阅读见 [19](./19-studio-ui.md)、[26](./26-timeline-content.md)，验证证据边界见 [24](./24-testing.md)。

本文描述已批准的目标架构，迁移是否完成以生成一致性、契约测试与原生验收为准。

架构演进不得以兼容门面维持第二条业务路径，也不得因旧路径删除而丢失已有能力。
共享接口保持单一契约，具体迁移与交付记录由项目报告维护。

## 25.1 分层与应用实例

```mermaid
flowchart LR
  W["纯视图"] -->|类型化回调| C["连接器"]
  C -->|用户意图| V["生成式异步视图模型"]
  V -->|领域公共能力| D["领域仓储与会话服务"]
  F["FRB 适配器"] -->|类型化事件| D
  D -->|类型化端口| F
  F --> R["Rust 资源所有者"]
  R --> F
  D -->|不可变领域状态| V
  V -->|Freezed 视图状态| C
  C -->|呈现属性| W
```

`anywork_client` 是不依赖 Flutter、Riverpod、FRB、Ref 或 BuildContext 的 Dart 数据／领域包。
不可变领域值使用 Freezed；必要的纯 Dart 注解与代码生成依赖不破坏无 Flutter 边界。
运行时对象、资源许可、任务与连接不是 Freezed 值对象。FRB 生成 DTO、原生句柄与
生成异常只存在于适配器，进入仓储前转换为类型化领域模型或错误。
Timeline 与 Thread 域的已知失败分类和重试分类复用同一类型化枚举；不在 FRB 的另一条
路径保留布尔值与可空延迟的平行表示。字段变化不改变原可重试语义或缺省值含义。

领域错误详情保留协议已发布的类型化变体，不降级为通用错误、字符串或任意 JSON。机器人
详情包含非空 `code`、可空 `platformCode` 与 `guidance`；目录游标过期详情包含游标签发时
绑定的非空整数 `revision`，用于 delegation/statistics 目录查询。适配器逐字段保留取值与
可空语义，整数转换不得丢失精度；领域层新增详情变体时同步其协议对应关系，不新增第二套
错误表示。

数据包按配置、目录、模型、额度、会话、草稿、模式、资源和更新等真实领域组织仓储。
每个仓储封装本领域归并器、查询与写入，不通过一个巨型客户端暴露全部传输层、
可写状态存储和命令对象；不增加一层仅转发旧门面的仓储。应用只消费分域公共入口，
领域内部归并器和可写来源不对外导出。领域值只保留一条权威公共路径。

Flutter 按 workspace、conversation、settings 的功能划分呈现。每个功能区分页面／连接器、
视图模型、视图状态、视图／界面组件；数据／领域层已经位于独立 Dart 包，Flutter 侧不为目录
对称再建一套同构仓储。公共视觉组件、格式化、平台能力、适配器与诊断各有独立归属。
功能不穿透另一功能的私有视图模型或状态，也不让诊断反向依赖功能内部实现。

机器人领域同样由 Rust 所有者持有业务事实，每个 `AppGraph` 的机器人仓储独立拥有主题、
只读模型、首配／查询／发送动作和未完成操作。视图模型编排呈现，离开设置页不关闭物理
机器人，不清理当前聊天资源；注册取消是显式业务动作，退出须等待其真实收束。机器人
配置修订、领域修订、查询尝试和发送操作标识不互相替代，完整契约见
[27](./27-bots.md)。

会话模型路由的机器人归属来自原会话配置的具名读取：`botId` 以可空 `ReadText` 表达，
在同一读取作用域内按需物化为可空字符串，不从全局当前机器人或最新配置补齐。
无可用详情、读取中或失败不等于已确认 `botId` 为空；只有原详情证明不受机器人托管时，
呈现才可提供普通路由编辑。托管入口导航到该精确身份的设置，既有本地停止能力不因此
被禁止；Rust 仍执行最终写入权限校验。

应用装配入口只装配领域实例、适配器与展示资源，并协调启动装配／关闭编排，
不承载各领域业务方法。每个应用实例有自己的仓储、操作登记、草稿、资源登记表和
展示协调器；禁止模块级可写业务字典或跨 `ProviderContainer` 共享这些实例。
原生库的进程初始化不授权共享两个应用实例的观察、句柄或草稿。

## 25.2 唯一写入与职责

| 事实或资源 | 权威所有者 | Dart 唯一所有者 | 身份与结束条件 |
| --- | --- | --- | --- |
| 配置、模型目录、资源状态 | Rust 领域所有者 | 对应仓储归并器 | 资源键、所有者代次与修订号 |
| 执行、交互、上下文、指标与计划 | Rust Thread 的唯一投影 | 分域会话仓储 | Thread、状态域与事件流代次；无正文副本 |
| 正文与保存／终态 | Rust Session | 有界内容连接与唯一归并入口 | 订阅身份与内容版本；查询版本独立 |
| 当前业务工作区目标 | 应用意图 | 工作区会话协调器 | 目标代次；旧动作不能重定向新选择 |
| 页面与设置导航 | `go_router` | 路由所有者 | 路由；局部标签页不存第二份全局导航状态 |
| 输入框文本、路由与附件引用 | 逻辑草稿 | 草稿服务与附件账本 | `DraftStamp` 与 `OperationId`；显式转移或放弃 |
| 账号／模式等页面编辑 | 未提交的编辑会话 | 对应 `AsyncNotifier` 视图模型 | 编辑器身份与草稿修订；明确结束编辑 |
| 操作结果与水位 | Rust 变更事实与 Dart 操作登记表 | 操作记录 | `OperationId`；不随观察者消失 |
| 在途／错误／最新意图呈现 | 功能呈现 | 视图模型的 Freezed 状态 | 目标与操作身份；不写回权威 |
| 已加载 Message 与界面控制器 | 当前展示 | 展示协调器的租约 | Thread 与展示代次；子树解绑后释放 |
| 输入法组词、焦点、动画、局部展开 | 界面组件 | 界面控制器 | 草稿身份与阅读代次；组件销毁时释放 |

权威归并器不混入页面在途状态或表单错误。命令回执中的权威数据和推送事件进入同一
归并器，旧操作仍可结算自身事实，但不能清除较新的呈现意图。不存在成功后聚合回读、
第二份可写权威、第二选择控制器或第二附件账本。

多字段保存如仍由多个原生字段命令完成，就保留每一步独立结果、部分成功和未开始项，
不伪造父事务回执或回滚。字段意图在受理前完整冻结并归领域所有者；页面销毁不丢已
排队步骤。一次真实成功后的同步失败与不确定是否受理分别呈现，不能根据错误码或文案
决定自动重放。原生提交阶段须提供类型化结果证据；适配器不把任意桥接异常当作未受理。

交互编辑器以会话线程、投影实例代次、交互标识和修订号为完整身份；读取进度、问题游标、
答案／理由和反馈归同一视图模型，计划阅读组件不另持一份回应草稿或操作记录。
键盘和按钮共用提交准入；读取完整不收紧原有空答案语义。工作模式的图形、JSON 原文、
校验及撤销／重做同属一个编辑视图模型；图形控制器只管理界面坐标与交互并提交类型化编辑意图，不拥有
第二份可保存文档。异步保存仅更新它冻结的编辑基线，不清掉期间产生的新编辑。

## 25.3 身份与版本域

- `ResourceStamp` 由 `ResourceKey`、`OwnerEpoch`、`Revision` 组成，只在相同资源与所有者内比较。
- 事件流身份表示一次订阅；可靠数据基线与增量使用该事件流的连续性水位。
- `DeliverySequence` 只标记传输已交付前缀，用于归还 FRB 在途额度，不是业务版本或持久化确认。
- `AttemptId` 是一次异步绑定身份，不能替代所有者代次；展示代次也不能替代业务身份。
- `OperationId` 在首次异步等待前生成，未知结果不换 ID 自动重放。
- `DraftStamp` 标识逻辑草稿与字段／项目修订，不能用页面版本代替。

配置、模型目录、账号模板与模型路由修订各有所有者。路由 CAS 不是通知序号；
页查询不推进尾部订阅版本，保存确认与执行终态独立。所有者纪元更换必须建立新基线，
旧所有者的观察不满足新所有者的回执，反之亦然。数值转换保留精度与单位，不能钳制溢出。
产品读取引用离开事件流封套后必须携带原所有者纪元与实例代次；单独条目或修订号不能
证明来源。只读物化值和最近已知值同样保留原来源，旧命令响应不能从最新事件流补取
来源身份，跨所有者的旧值不能提升成当前就绪值或满足动作准入。
ACP 账号配置与认证观察也属于独立资源。仓储的“保存并连接”先消费权威配置回执，
再提交认证检查；后一步失败不得撤销前一步成功或清空草稿。认证帧与命令响应进入同一归并器，
按所有者/revision 与 operation 身份收敛，不靠界面组件的 loading 布尔值推断已登录。认证观察
投影到账号时还须匹配其 connection revision；跨资源帧乱序期间，不能把旧连接的成功用于新配置。
仓储必须实际持有相应主题订阅，不能以只观察本地状态存储代替订阅建立。Accounts
可见需求拥有 `acpAuth` 观察租约；离页、重建或返回不取消登录、不重启检查，重新观察读取
当前基线。交互呈现见 [19](./19-studio-ui.md)，认证语义见 [28](./28-acp.md)。
认证事件可先于 start 命令响应到达；一旦权威状态提供当前 operation 身份，取消必须
可独立提交，不能被 start 的本地 busy 标志或命令队列阻塞。命令回执仍经同一归并器收敛。
已加载认证快照的水位同时参与 MutationBoard 的 `acp-auth` 资源观察，使用当前运行时所有者
epoch；主题名 `acpAuth` 与回执资源名不混用。命令响应与先到事件都通过同一权威
观察满足回执，不能只更新画面而把已确认命令永久留在 awaiting-observation，也不能在退出时
直接丢弃 pending 操作或用人工成功标志伪造观察完成。

ACP 安装有独立类型化 domain、命令与 `acpInstall` 观察租约，回执资源为 `acp-install`。
已加载快照含 revision 0 也必须按当前所有者 epoch 提交 MutationBoard 观察。开始受理与
安装终态分开，取消走独立 lane；页面不等待长任务 future 推测状态，不拥有下载关闭权。
取消去重以 provider 与目标 operation 为键：同一目标的在途重复请求拒绝；若权威已
推进到新操作，旧操作尚未返回的取消回执不得阻止取消新操作。每个在途命令仍由仓储
拥有并在关闭时 join，旧回执不能清除新目标的 pending 或回退权威状态。
离页只移除自己的订阅，返回消费基线；运行时关闭才收束安装。进度不是 Settings、
认证或草稿事实，不能通过频繁推进设置版本模拟刷新。

准备结果按 provider、operation 和草稿意图绑定，终态保留 operation 身份。仅匹配当前
意图才能取得保存资格；草稿不持有可编辑 program/argv、来源或版本选择，取消表单或另建
草稿后的迟到结果不得回写。另一草稿可
通过明确的使用准备结果动作绑定当前已就绪安装，不因同品牌或路径相似自动认领。准备不
自动保存账号；保存与连接继续沿用既有动作与独立成功事实。UI 不补造未知总量、速度、阶段
或来源资格；固定版本来自模板 supportedVersion，不以客户端常量决定启动。已有账号的
安装缺失/损坏与认证错误分别表达，改名不改变连接代次、不自动准备。仓储/适配器必须
完整消费类型化状态与错误，不靠文本解析或 raw JSON 兼容。

## 25.4 观察、导航与需求

领域观察同步登记接收者并返回登记时的当前值；检查当前状态与登记观察条件之间不能异步等待。
观察接口只暴露读取与观察能力，不暴露发布或归并器写入能力。观察租约只拥有自身的
监听器和预算，取消它不能关闭底层会话。最新值观察只用于可覆盖的状态；可靠事件不能
套用暂停后只保留最新一条的语义。

共享资源层负责 `ReadText` 的连续 UTF-8 分块与产品来源状态的机械物化，各域复用同一
类型化读取规则。此能力无状态，不开关读取作用域、不另建任务/预算/缓存，也不取得新的当前来源；
调用始终处于原领域已登记工作与捕获的不可变读取作用域内。各域的成员顺序、增量、窗口、
空引用策略和权威归并器不并入通用读取框架。

Timeline 的状态观察与正文交接是两种能力。只读状态观察用于连接状态、诊断与可覆盖的领域
镜像，不承担展示正文的可靠交付。内容服务同步登记唯一的可等待正文消费者，返回只拥有自身
登记与在途回调的租约；登记返回前不重入回调，重复登记明确拒绝。消费者重新接入已有需求
时建立新基线，不重放最后一条 Patch。如果当前 attempt 尚未开始消费首个基线，新消费者
可以承接这个已登记 opening 的首基线，不为同一份未消费基线重复创建句柄；一旦基线已开始
归并，重新接入必须退役原 attempt 并建立新基线。关闭封闭消费者准入，不返回无工作可收束的
新租约。解绑消费者不改变业务 demand，不清草稿或关闭 Session。
没有展示消费者时可以继续归并领域事实并确认数据，但不积累供未来界面重放的正文队列。

Session 可用性、资源不足与恢复通过同一真实所有者的类型化状态发布。视图模型登记时立即
消费返回的当前值，不等待下一帧，不用页面跳转、菜单重开或局部 refresh 补漏。

目录选择有两个方向且都由同一选择所有者发布：**用户选择**把目标置为已打开，**冷恢复
选择**把目标置为待打开。恢复选择是同步、纯选择的入口：校验选择组合与 sealed 状态，
推进唯一 selection generation 使旧在途导航失效，但不读 metadata、不打开 Session/Timeline、
不恢复执行；只有用户显式打开后才读取原目标并开放。它没有原生写入或 CAS，因此不产生
提交回执。应用层不得自持第二份 `needsOpen` 或替代选择控制器，也不得只提供「打开」而
让待打开状态不可达。
尚未创建出 Session 的选择准入失败由 ConversationRepository 发布只读 activationFailure，
携原 threadId、selectionGeneration 与类型化错误；它是失败证据，不是第二个可写选择来源。
Workspace 呈现只接受与唯一当前选择身份匹配的失败，不能把 active=null 一律显示为加载中。
显式重试仍由原仓储核验同一选择及其失败后重新准入，不重选目标、不调用 ensure，
也不重放业务命令；已存在 Session 的域连接错误继续由各域状态负责。
同一会话的各域共享投影实例代次：新代次出现后旧域失去新帧准入，旧值只作为最近已知值
保留，不能跨代次混为当前就绪值。仓储封闭时结束选择与激活失败状态的观察准入，
但未决原会话的资源与清理责任持续保留至真实收束。

业务 demand 由 Workspace／Session coordinator 与领域资源服务管理。进入 Settings、切标签、
界面组件暂停不改变当前会话内容 demand，不清新会话或 Thread 草稿。显式切 Thread、归档项目、
放弃草稿与应用退出分别结束自己的需求。Provider keepAlive 不替代原生资源所有权，也不能
让每个曾访问会话永久保留正文；所有者、观察者、查询和镜像均受预算限制。

route 与当前业务目标有不同职责，不各自维护可写 selectedThread。路由若携带业务 ID，只将
它传给唯一 activation 入口；旧异步 activation 结果不反写新的路由或目标。局部 TabController、
焦点和菜单状态不放入跨页面业务 provider。

## 25.5 会话、事件流与资源关闭

实时状态与正文均消费 [07](./07-streaming.md) 的类型化推送。内容连接提供事件、分页、
详情读取、同步关闭准入及异步关闭能力，不提供 Dart 初始值／下一帧轮询泵。Rust 内部的异步事件等待不是
接口轮询。状态、指标、内容按各自版本域观察；某一事件流恢复不能把另一事件流的失败标为 ready。

执行域基线同时携带可空的执行身份与逻辑继续点，轻量字段贯穿协议、桥接、SDK 归并与呈现。
增量分别使用明确的未变化或替换状态，替换为空表示事实已清除；不能以可空字段同时表达
未变化与删除，也不从活动轮次、最后一条消息或旧聚合快照推断这些事实。

首次 await 前登记 attempt、demand、原始 open Future、候选句柄、查询、取消、close/join
与预算。句柄返回后立即归属于原 attempt；每次 await 后核对 Thread、attempt、generation 和
retired。页、详情与 frame 的迟到成功、失败和 finally 只能结算原身份。

原生订阅创建已确定失败时，适配层先发布创建决策已结束，再等待流关闭或消费端取消；
取消可以等待创建结束，创建路径不得反向等待依赖该决策的取消确认。类型化失败、迟到句柄的
唯一取消责任和预算归还边界保持不变，旧失败尝试不能永久阻止新订阅或应用关闭。

仓储完成类型化转换与领域归并后确认 delivery prefix；需要顺序应用内容的展示接缝还要
完成有界交接，不能在未 await 的 future 链中积累正文。ACK 不证明 operation observed、effective
或 durable。内容缺口只重同步受影响连接，不重放业务动作；History 保留已有展示，新基线不能
偷偷替换冻结消息。

同一内容连接至多一个在途正文消费回调；转换、连续性归并或展示写入失败均不 ACK。等待回调
后仍核对原 attempt 与消费者代次，只能确认原句柄。消费者租约的 requestClose 同步
封闭新回调，close 等已经受理的回调结束；回调不能等待自身所属租约／Session 的 close，
以免自等待。展示服务的可等待边界只包含消息写入与错误收束，不等待布局、绘制或动画。

retire 先封闭发布与新查询，再广播取消和 requestClose，随后等待生产者、sink、查询、
open 与句柄的真实 ACK。失败或超时保留 unresolved 所有者和资源许可，不清容器伪装完成。
关闭内容事件流不关闭 Rust Session、Turn 或 writer。容量不足只在真实释放后恢复准入，不轮询。
提交操作通过组合专用 demand 能力保留原具体 Session 的 execution 观察，不借路由选择
维持其寿命。已有 Thread 提交只借 ready 且原 incarnation 匹配的源；新建收到真实成功
回执后可在原 Session 建立 execution-only 基线，选择已改变也不需临时激活该 Thread
或打开 Timeline。借用释放只归还原需求，不能代表 Session／原生查询已完成关闭。
新建后的持续观察由原创建任务提供非激活源能力，固定原执行所有者／投影；它不是
普通 live 模式或 cold checkpoint 的别名。真实首基线提供来源身份，回执不补造它未携带
的版本字段；源已失效就保留已确认结果与读取失败，不按相同 ID 重建或换到 latest。
取消原生、等待 stream 结束、查询退出与正文回调收束可以并行推进；不能先等回调结束才发
原生取消。类型化 close 报告必须属于原连接；只有原生 Clean 且 Dart 已登记工作全部结束后
才 dispose opaque 和释放资源许可。Unresolved 保留完整类型化 issues、原句柄与资源所有者。
进行中的清理请求共享同一次真实收束；可重试的 Unresolved 不能被已完成 Future 永久封住。
普通关闭不追加重试。在途收束期间受理的显式重试保留为原所有者的一次后续清理；重叠的
显式重试共享这次已受理责任，同步重入也不能形成无界重试循环。调用方的观察期限结束
不撤销已受理的重试。无期限的关闭等待覆盖已受理责任的真实终态；较早的未完成报告
可以保留为历史事实，但不能在后续重试完成后覆盖当前关闭结果，也不能使再次关闭重复执行清理。
显式重试只继续原所有者的未完成清理，不新建连接、不重放业务命令，也不清除尚未解决的
诊断。已证不可恢复的终态故障保持明确的不可重试分类，不能仅改标签后宣称 Clean。
原始错误的 retryable 与清理动作能否恢复不是同一事实：关闭报告保留原始类型化诊断，并
分别表达继续等待原工作、显式重试原清理调用或不可恢复终态。不能因为原异常标为可重试，
就假定第三方 stream 的取消操作具有重试能力；也不能因此丢弃原始错误分类。

Timeline 失败诊断对外暴露具名只读身份 `TimelineFailureIdentity`（Dart 运行期类型，不是
协议／FRB 字段）：它绑定失败尝试与原始失败对象，以对象身份精确判定归属，
消息相同但引用不同的对象不为真；新尝试不继承旧身份，借出的诊断值在原尝试退役后
仍保持原身份。该身份只用于诊断归属，不打印、不序列化私有 cause，也不得替代类型化
`StudioFailure` 的错误码／可重试／correlation 语义。
同一身份同时提供诊断错误：类型化失败取其领域投影，未知异常取原始对象，
供读取运行时类型名使用。断连诊断只输出类型名与类型化三字段（未知异常的三字段为 null），
不把被捕获异常转换为字符串；类型名对 `StudioFailure` 取稳定公开名，其余取运行时
类型名，避免泄漏生成镜像的私有类名。

Rust 会话与产品读取作用域共用一个运行时生命周期内核和同一组 64 个在途读取责任，
但保留各自类型化 wire identity 与材料。读取作用域计费按真实 Thread 或产品资源／原业务读取作用域
分组，跨 incarnation 共用原 8 个额度，不能把新 ref／代次当作新配额。Thread 的 Cold 租约
与驻留 pin、产品的不可变材料 pin 都在真实查询 join 后释放；公共内核不解码业务载荷。
运行时关闭独立封闭并监督这组读取作用域，不以 Thread framework 关闭成功为执行前提，
所有未决问题仍进入原 finalizer 之前的同一次报告，不新增关闭协调器。

归档在首次异步边界和写 lane 等待之前捕获全部实际拥有的原对象，而非 Sidebar 窗口。
捕获能力只用于组合层：项目与 Thread 分型，准备原归属、接受真实归档结果与异步释放
准备责任分开；Unknown 保留原捕获，不重发。确认后的 UI 清理绑定原具体 Session 与选择
需求代次，不能关闭较新的 UI 需求或操作证据。草稿清理还核原所有者、版本戳与附件代次，
晚编辑完整保留；只释放原草稿一侧引用，不减少已冻结操作或 Unknown 的附件引用。

Conversation 的组合 context 以具名 ThreadMetadata 借用返回原目录读取能力，而非仅返回
值 Future；值就绪与读取资源真正收束独立。Session 在进入 Recovery 检查前可保留原纯
metadata 结果，但不能因此放开 UI、执行或恢复准入。UI 与归档准备借用同一实际工作时，
共享其原结果和真实关闭责任；关闭超时保原读取所有者，不由一个值返回推断 Clean。
单实体 metadata 的成功基线必须恰含目标实体；lookup／物化失败通过原目标的类型化
读取错误公开，即使还没有实体引用，也不能伪造引用或发布健康空值。
跨领域捕获由同 AppGraph 的具名类型化能力组合，所有绑定完成后才开放动作；不使用
当前 ID 回查、空 capture、另一个资源池或关闭协调器来绕过未完成的草稿与附件所有者。

## 25.6 视图模型、连接器与纯视图

页面与交互视图模型使用生成式 `AsyncNotifier`；初始化可登记只读观察或执行必要读取，不执行
提交、写配置或自动重放。同步、值相等的纯选择器仍用派生 Provider，不为类型名称堆叠包装。
视图模型只依赖领域公共能力，不认识界面组件、BuildContext、FRB、SQLite 或具体适配器。

`Freezed` 视图状态表达可渲染数据、编辑意图、校验及按目标／操作区分的呈现。
首次无数据可使用 `AsyncLoading`／`AsyncError`；有最近已知值的重连、局部保存失败不让整页
变成空白。不要用 `AsyncValue` 与平行加载标志表达同一个状态。领域同步错误与页面操作错误
分别表达，不能把未知改成空值或零。

图片展示工具产生独立的图片卡片呈现项，只派生所属调用、类型化附件和参数中的展示文案；
图片字节仍由 Thread 附件缓存按身份读取，呈现层不缓存字节，也不因卡片存在而改写工具条目。
活动、图片与重连的 GUI 分组由唯一展示租约派生，不改变后端逐条保存；组内定向观察与
展开意图不成为第二份正文缓存。正文归并、消息集合及显示预算以 [26](./26-timeline-content.md)
为准，不恢复旧客户端的正文副本。

设置页显式重试依据当前来源同步状态和真实读取需求，不以保留了旧 header 证明来源健康。
源失败后仍展示最近已知值时，恢复入口必须进入该领域已有的纯读取／订阅恢复路径；不能
只重试已满足的可见字段，也不能调用业务 reload／保存来代替恢复。重试保原 VM 会话与资源
责任，在途请求合并，恢复失败继续显示真实错误，不由源通知自动重复业务动作。

设置壳首次就绪要求所需公共配置均已完成读取，且各值的来源身份与读取引用匹配当前
配置投影；加载或失败状态保留的旧值不能代替这一证明。就绪记录绑定完整来源身份，
同一来源的后续刷新可以保留既有内容与编辑草稿；所有者、纪元或实例代次更换后须重新
准备，不能用前一来源的就绪记录放行。首次读取失败后，用户退出并重新进入设置构成
新的显式读取尝试，即使来源未变化也允许恢复；普通重建或重复通知不产生重试循环，
在途尝试仍合并，不用配置重载或保存命令代替读取恢复。

编辑视图模型在数据更新时只推进该目标的权威基线，保留未提交输入；不能每次失效后
重新初始化而丢失未保存草稿。提交在同步阶段冻结载荷、目标和修订号，旧完成不能清除新字段。
交互答案编辑同样遵守此规则：相同编辑目标重建观察不构成显式丢弃，原答案、后备文本、
理由和反馈不得被空初始值覆盖；不同完整目标不自动迁移这些输入。关闭确认绑定
具体编辑生命周期、完整目标、编辑修订和最新意图，不能仅比较 `Notifier` 对象或一个
可能跨重建复用的修订号；清草稿和关闭面板前分别核对原身份，旧确认不作用于新会话。
保活、参数化实例键、保留与丢弃规则按编辑会话明确；不把永久缓存作为“防止丢状态”的方案。
模式 JSON 与图共享同一 Freezed 编辑状态和最多 64 次撤销／重做历史；解析、校验或保存失败
保留输入，图形控制器只拥有坐标及交互投影，不成为另一业务所有者。

设置的局部标签切换与整页离开共用同一导航请求所有权和工作模式未保存修改确认入口。连接器在
等待确认前捕获原导航请求、具体模式视图模型、编辑会话代次、目标、编辑修订和最新意图；
确认返回后必须在任何保存／丢弃动作之前核对这些身份及请求仍有效，失效仅拒绝本次离开，
不得处置新草稿。同一个 `Notifier` 实例重新初始化不代表原编辑会话仍存活，须核对真实代次。
已准入的保存继续结算原操作，导航所有者在其完成后再次核对原请求，才交接编辑生产者并
隐藏／切换页面；界面组件销毁不自动保存或丢弃。跨功能入口由设置功能的具名公共呈现接口
提供，应用只将它注入唯一路由，不另建导航或退出所有者。

连接器通过静态依赖观察视图模型，依据监听结果或类型化动作结果执行导航、对话框和提示，
不直连传输层或可写状态存储。纯视图只接收不可变呈现属性、仅限界面的控制器与类型化回调，
不得接收 `Ref`、仓储、客户端、原生句柄或 Provider。
纯视图可保留焦点、输入法组词、局部展开及动画，不做业务查询或重试决策。

速度、上下文与稳定状态消费各自小型 state／值相等 selector。高频速度更新不携带 plan、
workflow、catalog 或正文，也不使这些消费者重建。页面级 VM 不持有第二份完整 Message 列表；
渲染、controller、租约与 Live/History 以 [26](./26-timeline-content.md) 为准。

## 25.7 命令、观察与效果

未选择项目时，模型和推理强度预选仍写入草稿仓储已有的按模式路由偏好；它们是提交意图，
不是已解析且获准执行的路由。呈现所有者只观察该偏好并发出已有草稿动作，不创建虚拟项目、
会话或项目草稿，也不把预选写成全局设置默认值。输入与发送继续禁用，工作模式只提示先选
项目，工作区和会话设置菜单不出现。选定项目后，原草稿路由准备沿同一偏好进行后端解析与
校验，保留明确的不可用与未知状态；界面不猜测默认模型或推理强度，也不另存一份选择。

停止是会话领域的独立操作，不归草稿发送、附件或路由写入通道。动作在首次等待前冻结
原所有者、目标会话及权威执行编号（`ExecutionId`），不以轮次编号替代准备期的执行身份，
不随选择切换、后继执行或同标识的新所有者重新定向。资源能力与观察句柄不进入不可变视图状态。
停止的受理、观察与生效分别呈现：受理不等于清理完成，不能由权威空闲补造丢失回执。
同一执行的重复停止最多保留一个在途请求和一个排队重试，并合并重复意图。

无内容继续冻结会话、继续点、操作编号和已观察的模型路由修订号；同一意图只拥有一个在途
请求，重复点击共享原 Future，不另发编号。失败、结果未知与已受理分别表达，在途期间禁用
对应入口，不提前显示生效；结果未知仍沿原操作身份回查，不换编号重发。

用户对子会话的唯一运行控制入口是智能体目录行中的停止。目标执行编号与资格来自该行的
权威执行投影，不要求先打开子会话，也不借用当前选中会话的状态。子详情只读，继续与消息由
主智能体调度；成员计数只包括未关闭成员，关闭成员仍可查看。页面卸载只退休本页观察，已受理
工作仍由原领域所有者收束。机器人归属不额外禁止停止，退休角色的既有只读提示保持不变。

目录停止由会话仓储拥有，不依赖当前选中的会话实例。它冻结原目录来源、成员身份与执行编号，
复用既有操作登记、预算及关闭责任，不临时选中目标、打开会话或创建草稿。主会话内部停止
仍绑定该会话原执行域来源；旧的按轮次停止入口随调用方迁移一并移除。

主会话交互索引只包含自身及直接子会话的可处理请求，保留有界分页和按需详情读取。
读取引用归属于主会话原索引，详情保留原请求的子会话归属；回应能力同时冻结主会话来源、
目标会话、原交互身份、版本与类型化决议。后端重新验证直接归属与准入，不删除同会话校验
来接受任意目标，也不恢复全局子交互存储或复制可写账本。子会话计划不进入主会话可决议集合。

继续控制使用专门的操作回查，待处理阶段也能证明原输入认领的实际保存；普通输入接受查询
不能冒充该证明。保存等待之后返回忙碌但已受理时，仍保留原操作身份与已提交事实，不能仅按
错误码或可重试标志判为未受理。结果未知与已提交但未观察分别呈现，均不换编号自动重发。
控制失败通过 `Control { reason, facts }` 保留稳定原因标签及封闭的类型化事实，贯穿原生协议、
桥接与 SDK 错误值；其中已受理事实必须匹配原会话与操作身份。适配层不丢弃事实而仅保留
原因文本，也不把无可用回执的已受理事实加工成虚构回执。
停止在执行所有者的同一裁决边界区分 `noExecution`（合法目标身份下已无执行）与 `staleExecution`
（目标身份为空或仍有执行但身份不匹配）；冷线程与驻留线程遵循相同分类，两者均不制造已成功停止的回执。继续已受理但尚无法取得原回执时，
使用 `continuationAccepted` 原因及原操作的受理事实，不报告为无可认领继续点；实际存储或
读取故障仍保留自身错误类别与原因链，不能统一伪装成正常等待。
SDK 停止准入先核验原来源、成员与执行身份；同一所有者的投影修订前进不使来源自动失效，
但目录必须完整且当前成员仍具有原身份，不得借用同标识的新所有者或重建成员。
同一目标已有未释放的停止操作时，重复请求返回原票据，即使当前执行已为空也不改写原操作的
未知、拒绝或受理事实。没有原票据且权威执行已为空时，直接返回非错误的 `StopNoExecution`，
不创建操作票据、不发送请求、不修改命令登记或草稿；有可停止执行时才登记新操作。
来源失效、空执行身份和另一个执行身份不匹配仍明确拒绝，不能借此把陈旧来源伪装成无执行。

恢复诊断公开类型化的可用动作集合（`availableActions`），读取值、领域值与视图均保留该集合，
不压缩为单一首选动作，也不由诊断类别猜测额外权限。重试与清理可以同时可用；未知工作树
检查结果仍是未知，不据此授予清理。每个动作继续冻结原来源与适用的租约修订，并由后端重新准入。

领域动作接收类型化 intent，立即冻结目标、expected revision 与 OperationId 并登记只读
operation ticket；UI 不能修改其归并器、资源许可或自动重放。相同资源冲突写串行，不同资源
可并行；停止不排在长写入 FIFO 后，分页／详情不占配置写 lane。

CommitReceipt 至少携带 OperationId、Applied／NoChange、目标 ResourceStamp 和 effect point。
Accepted、AwaitingObservation、Observed、Effective、Durable 独立。模型配置对 next Turn／
future Session 生效，不代表正在执行调用已切换；durable 只由真实保存确认推进。

领域所有者可在登记操作时冻结额外的显式身份观察要求；它与原生回执的身份观察
要求取并集，不改写回执、目标版本戳或已确认的 effect/durable。Configuration 的
两目标及 Profile/reload 的三目标必须全部实际同步后才发布该证据；仅回执中的
版本戳被覆盖不能提前推进公开 observed 或释放 pendingOperation 额度。要求默认为关闭，
不改变其它领域的原语义；无回执的确认仍须真实身份观察，不能因默认值自动满足。

身份回执按 [18](./18-studio-state.md) 的执行／交互身份判据观察；不能空目标自动满足。
输入提交的 durable 匹配原历史输入身份、接受序号与原生请求摘要，不以任一 Turn 的 saved
或终态替代。继续控制的认领回执在受理时即进入可靠保存索引，待处理期间也可回查；没有
实际落盘证据时仍保持未证明，不伪造提交即持久化。其证据只针对输入身份，不承诺未来全部输出已保存。真实存储持久化
通知只触发有界按需身份读取，不作保存证明或轮询；关闭等待该读取真正结束。
操作登记表保存每次真实结果，latest intent 单独标识；页面 overlay 不再混放在配置权威 state。

Rejected 表示明确未受理；UnknownOutcome 表示可能执行但缺少确定结果；SyncFailed 表示已知
结果的观察失败。未知结果不自动重放。只有已知冲突／缺口／明确重试才局部重同步；成功不
readStudioState 或聚合 reload。错误保留类型化 code／correlation 与原始 cause，不用文案推断。

自定义模型改名迁移原压缩阈值覆盖，并清除旧 ID 的连接覆盖；wire API 改变也清除该连接
覆盖，删除则清除该模型的两类覆盖。切换模板重建表单是显式的模型配置重建意图，才可清除
原手动声明与全部连接/阈值覆盖；即使切回原模板也不能把已发生的重建误判为普通字段编辑。
这些意图仍由 ConfigurationRepository 在最新权威账号上合并，不由 VM 回写旧全表；
最终容量、连接支持、重复 ID 与阈值有效性仍由 Rust 校验和解析。

账号模型启用开关是目标为 `(accountId, modelId)` 的独立字段意图，切换立即交给配置仓储
命令所有者，不等待账号编辑页保存。目标字段操作串行，CAS 冲突重读当前资源后只重施
本次意图，不能回传陈旧账号快照覆盖凭据、目录或其他覆盖。pending/failure 由 mutation
所有者持有，权威 enabled 仅由配置/目录响应和事件更新；旧完成不能覆盖新意图。
页面退出只取消观察，已受理操作参与仓储关闭 join，失败和未知结果沿用上述语义。
账号“不计费”开关与类别选择消费同一权威 `billingKind`/`billingKindOverride`，不另存
免费布尔设置。已有账号开启写入 `noCharge`，关闭清除覆盖；普通连接/凭据草稿保存不能覆盖
该窄意图。新账号初始类别随创建提交；失败不伪造开关成功，重开与其他观察者消费同一设置事实。

启用、计费类别和手动模型删除的窄请求均显式传递本次 OperationId；Runtime 回执原样返回，
仓储不改写不匹配的回执来强行关联。基于明确 CAS 拒绝的重试仍属于同一业务意图，
不因刷新 revision 丢失操作身份；未知结果不自动重放。

Configuration mutation 经具名调用资源交接结果，不只返回失去原生材料保活责任的纯
回执 Future。原调用持有同次提交的 Configuration／Models 配对材料，SDK 的原写入
所有者持有该调用，先取得纯值回执，再同步两个原 target，完成相应观察后才关闭调用。
适配器不在返回回执前等待消费者释放，也不在返回时提前释放 pin；原生结果已就绪
不等于 SDK 已取得读取材料。Unknown、同步未完成与关闭失败分别保留真实责任，正常
成功不把每次调用保留到应用退出。callId 区分每次调用，OperationId 保持原业务意图；
资源留存范围内的加入／冲突和显式关闭边界遵循 [20](./20-config.md#2022-模型启用计费类别与分发默认设置)。
调用的结果查询也属于原所有者的在途责任：与关闭封口原子登记，已接纳查询真正完成或
取消前，生产者已结束也不能单独使 close 报 Clean 或释放原 evidence/资源许可。
原调用存续期间可以重复查询它保留的结果；结果查询不会再次执行业务写入，也不要求适配器
另建结果缓存或把多次显式查询合并成一次原生查询。禁止重发的对象是结果未知的业务命令，
不能将查询次数与写入次数混为一谈。
同一次显式清理重试对同一原调用只推进一次原生 retry；失败保留为本次 Unresolved，
由下一次显式重试接续，不能因经过多个资源收束层而再次隐式重试或掩盖第一次失败。

已登记命令的真实执行收束与目标的呈现观察是两件事。应用退出会封闭普通来源、事件流与
读取准入；若原结果因此未完成观察，仍保留已提交／未观察的准确阶段与原操作证据，
加入原工作并单独报告清理结果，不能为了报告 Clean 而伪造 observed 或重新发送命令。
原退出协调器可据真实未决问题给出 Degraded，不能安装更新；该路径不授权恢复已关闭
的全局读取或把一份 material header 当成完整权威观察。正常开放来源下的成功
仍必须完成两个原 target 的同步与观察，不能借退出语义免除日常结果消费责任。

模型资料与评价详情是按账号模型身份有界的查询资源，不在界面组件或配置归并器
合成另一份模型目录、评分或可用性；迟到详情响应不得写入已切换的模型。智能体列表
直接消费类型化冻结模型标识，字段参与镜像比较，不以 Profile 当前值填补历史未知。
根会话的智能体成员集合由权威 AgentDirectory 的根归属与父子身份确定；侧栏
ThreadDirectory 的分页窗口和 session 热集合不代表完整成员，不能与它们取交集后再
渲染菜单或计数。仓储/展示投影按稳定身份消费目录成员，已有 Thread 元数据仅补充
相应展示，不伪造缺失 Thread、路由、权限或工作区事实。切换根会话保持成员隔离，
冷成员仅在显式选中时按需取得其会话数据；列举本身不激活所有者或订阅全部 Timeline。
导航以用户最新选择意图为准；新意图一经接收，就使旧的按需读取失去发布选择的资格，
不能等串行命令真正执行才使旧意图失效。迟到结果不得并入目录、改变选择或启动已过时
成员的历史观察；切项目、切根、选兄弟成员及新建会话遵守相同边界。当前有效选择的
读取失败保持原错误可见，但过时读取的错误不覆盖较新的导航结果。

账号详情模型列表的阈值编辑只拥有原始输入、短暂防抖与最新意图身份；原始覆盖由配置归并器拥有，
最终上下文解析结果由模型目录归并器原样接收。有效输入和恢复自动触发同一
account 原子保存，配置仓储在串行写 lane 内从最新权威 account 应用目标模型变更，
CAS 重试也重新构造，不携带未改动字段的陈旧副本。其余模型的持久覆盖必须完整保留，包括
因在线目录暂时撤下而不可见的覆盖。旧响应可推进自身操作记录及权威水位，不能覆盖
较新原始输入、清除较新 pending/error 或让不同模型的修改互相丢失。
页面离开前将已产生的有效意图交给仓储；已经提交或排队的操作由其持有并参与退出 join，
不能由界面组件 dispose 取消。输入无效时不提交、保留校验错误；已知保存失败允许显式重试，
未知结果按既有 UnknownOutcome 语义处理，不自动伪造成功。

原始阈值覆盖由配置 revision 所有，最终上下文解析策略由 catalog revision 所有；Rust 配置
所有者在同一锁内读取两者，影响策略的配置与目录更新推进目录水位。仓储独立合并
两个水位，只接收模型层解析的可用性、硬输入容量、最终压缩阈值与调整原因，不从容量、
最大输出或原始覆盖重算策略。配置旧响应不能回滚新目录策略，撤下模型的原始覆盖继续保留，
只在 Rust 显式写边界归一化。输入无效不提交，已知失败允许显式重试；未知结果不伪造成功。
空闲会话消费当前 catalog 结果，在途请求与历史保留各自冻结绑定；设置返回立即显示权威。

手动压缩通过会话领域动作进入与自动压缩相同的准备、提交、计量和持久化路径，不构造隐藏
用户消息。视图模型只呈现权威可执行资格、操作进度与错误，空闲且有可压缩历史时
发起一次请求，重复意图合并或拒绝；后端重查准入。压缩失败保留原错误，成功由 context
事件流更新当前读数，不用聚合刷新或本地估算阈值补偿。

会话域负责已有 Thread 的四类写入动作：手动压缩、Thread 模式切换、会话模型路由写入与
交互响应提交。四者都由领域动作发起，首次 await 前冻结 Thread、target 与 operation；
类型化结果只结算原操作，未知结果保留冻结输入且不自动重发。动作成功后由对应 facet/read
的权威更新生效，不用聚合刷新或本地推断替代。

四者的版本证据强度按原生能力如实区分，不把本地检查宣称为原子 CAS：模型路由写入与交互
响应提交携带调用方冻结的期望版本，原生在写入前原子校验，冲突按同一意图与新的期望版本
显式重试，`NoChange` 由回执说明而不从 revision 相等推断；手动压缩与模式切换的原生入口
只确认原操作被受理并执行，原生在自身执行时做并发检查，SDK 因此只报告原生确认与其回执，
不承诺不存在的外部期望版本校验、`NoChange` 判定或目标版本戳。

### 25.7.1 账号用量需求

额度事实只由 AccountUsageRepository 归并；同账号 ID、usageQueryRevision 与所有者 epoch 的
并发自动／手动查询去重，不同查询身份的旧结果不清新 pending 或覆盖新结果。

Usage 视图模型管可见需求与本轮已尝试身份。首次可见为当前身份分别发起检查，每个结果立即
呈现；可见时只补查新增／变化身份，隐藏时不产生新自动请求，重开只补未尝试或失效身份。
失败也计入本轮已尝试，不因 rebuild、名称／catalog 更新或默认值变化重试。显式刷新可以新尝试，
刷新全部复用单账号能力。不要在界面组件 build 中发请求或保存回调中等待全部额度。

已受理查询由仓储持有并参与退出 join；页面销毁不丢在途任务。删除账号结束需求，
迟到结果不得复活删除项。两个应用实例不共享请求、结果或已尝试集合。查询身份由 Rust 所有，
不暴露凭据或其哈希，定义见 [18](./18-studio-state.md)。

## 25.8 草稿与附件

新会话的本地文件、剪贴板图片与远端 URL 准入在意图发生时同步冻结草稿已经解析的完整模型
路由，通过 `newThread` 上下文的必填 `route` 传递，并与提交共用同一解析规则。不重新采用
工作模式默认模型，暂存或排队期间的选择变化不能改写这次准入；路由尚未就绪时明确拒绝，
不得猜测默认值。已有会话使用后端保存的会话路由。提交仍按最终冻结路由重新校验附件。

模态、来源、媒体类型或模型限制拒绝返回带安全提示的 `invalidArgument`，不伪装为配置损坏。
读取和解析失败保留内部原因供关联诊断，对外不暴露路径、凭据或远端 URL。已知拒绝释放
本次预留，保留草稿文本与已有附件，允许后续合法准入；未知结果继续保留原冻结责任。

附件入口消费所选模型的类型化输入能力，只做呈现筛选，不重新实现模型准入政策。现有会话
使用原会话路由的精确账号／模型身份，新建草稿使用其已解析路由身份；模型能力通过模型领域
已有的精确详情读取获得，不加载全目录、不借用委托详情，也不扩展会话创建命令。该能力表示
当前模型目录的可用输入方式，不承诺与会话路由属于同一个跨域快照。

读取前冻结具体草稿／会话、路由身份与版本、模型来源及呈现代次；读取期间任一绑定变化时，
旧结果只能结算原读取，不能启用新目标的入口。能力未读到或读取失败时不推测支持，不影响已有
草稿与附件归属；模型来源更新通过既有观察刷新当前精确详情。视图只接收不可变能力投影和
回调，不取得仓储、读取作用域或另一份可写能力缓存。Rust 对真实附件提交仍执行最终校验。

文件选择、拖放暂存和 URL 对话框等平台交互同样绑定最初的草稿与能力投影。异步交互结束、
实际发起附件准入前再次核对原能力是否仍有效；路由或模型来源已经变化时不准入、不重定向
到新目标，也不删除原草稿的附件。暂存资源仍按原借用与关闭契约回收。

新建草稿与会话输入草稿有独立逻辑寿命，不随页面观察者消失。提交在同步阶段冻结
`DraftStamp`、项目／会话身份、文本、模式、工作区、完整模型路由、解析后的分发模式与
偏好，以及附件 ID 集合。新建会话直接提交该路由，不先写全局默认设置再读取缓存。
已有会话提交携带所观察的路由扩展修订，受理 CAS 的语义见 [18](./18-studio-state.md)。

新会话的分发模式和偏好是项目草稿内两个独立可选覆盖；空值表示跟随权威设置，
不复制一份默认值保存为覆盖。创建提交在首次 await 前解析并冻结两者，之后设置变化
不能改写已提交值；成功只清理仍匹配 DraftStamp 的草稿，失败保留选择和附件。固定
模式保留偏好选择但不应用提示词。已有会话的分发策略只读，不因路由观察者销毁而重置。

提交中、已受理、已观察和已持久化各阶段均关联同一 `DraftStamp + OperationId`。
提交期间可继续输入和修改草稿；旧 ACK 只清理仍属于该提交且 revision 相符的字段。
`TextEditingController` 保存输入法组词与选择，草稿身份变化时替换；同一草稿的普通重建不反复
重写控制器文本，旧完成也不能直接清空当前控制器。

新会话环境准备属于冻结提交的临时状态，由草稿／提交服务按 `inputId`、项目及提交身份
维护唯一事实镜像，Composer 视图模型派生卡片呈现。Settings 往返或观察销毁不取消
创建命令。阶段来自同一次类型化创建流，成功／失败终态只结算一次；终态前断流保留
UnknownOutcome，不自动重发。旧提交的进度和 finally 不覆盖新尝试或较新的草稿，成功结果
仅在导航意图仍属于原提交时自动选择新 Thread。成功移除准备镜像，失败保留原阶段和原因；
准备信息不成为目录事实或聊天历史，也不承担取消与工作树资源释放责任。

附件 ledger 分开持有逻辑草稿引用和冻结操作引用；成功仅转移冻结引用，较新草稿仍引用的
附件继续有效。最后所有者释放后才原生删除；失败保留所有者、诊断与预算。未知结果保留
冻结引用，不能因页面退出、放弃另一个草稿或 orphan sweep 删除。clipboard 暂存、drop 回调
借用和迟到 admission 都由明确所有者收束，不持有平台临时路径到回调结束之后。
关闭过程等待在途创建和清理，不以销毁观察适配代替异步资源回收；可靠附件与旧数据保留
规则见 [17](./17-studio-storage.md)。

### 25.8.1 附件原文件读取

附件读取是无生产者的具名 query 读取作用域，不建立假事件流或 ACK。打开时冻结 draft 或
Thread/attachment 目标，Rust 先核验原资源权限，再持有同一个文件句柄及其长度；读取
不接受任意路径，工具媒体仍须来自该 Thread 的完整类型化 delivery 授权。完整性校验与
后续分块读取使用同一句柄，不校验路径后重新打开另一个对象。

读取身份包含真实读取作用域、运行时 epoch、incarnation 与类型化 target。每块默认 64 KiB、
上限 256 KiB，长度参数范围为 1..262144；offset 等于原长度时返回空末块，大于原长度
为 InvalidArgument，提前 EOF 或完整性破坏为真实 Storage 失败。字节缓冲归调用方独占，
不进入领域值、Freezed 视图状态、Driver 或常驻第二缓存；界面所需完整字节仅沿原作用域
组装，不得先整块读取再在 Dart 切片。

关闭校验使用打开时从原原生句柄取得的独立读取作用域标识，不依赖完整业务描述符能否
转换。描述符数值或目标不可表达时，原查询仍失败，但不能在已验证的原生 Clean 后
永久保留同一转换错误作为清理责任。适配器保留原读取作用域标识用于关闭前后核验；无法
取得真实标识时仍为 Unresolved 并保留句柄，显式重试只能读取该原句柄，不能从 close
报告反推期望标识、补造 epoch/incarnation 或新开替代对象。

Thread 读取计入该 Thread 的原读取作用域预算；所有 draft 在同一运行时共用 8 个读取作用域，
opening、校验和读取共用原 64 个 read-call 额度，不另建查询池。删除与打开按原资源所有者
线性化；删除路径不等于已有句柄已结束。requestClose 同步封准入，close/retryClose 真正
等待 late open、blocking IO 与在途调用结束，Unresolved 保留原所有者和完整 issues。

FRB 映射同一 opaque 读取作用域、身份、长度和类型化 chunk。HTTP 的
`POST /api/v1/attachment-reads/draft` 与 `/thread` 创建对应读取作用域；
`GET /api/v1/attachment-reads/{scope_id}/bytes` 接收 offset/maxBytes 并返回原始二进制，
`Anywork-Offset` 标记本块位置，非末块携带 `Anywork-Next-Offset`。合法 EOF 为 200 空 body，
不伪造 Range 语义。具名 `/close` 与 `/retry-close` 返回原关闭报告；请求断开不丢原生
责任。旧 whole-read 接口在消费者迁移后删除，不能以兼容转发保留第二条读取链。

### 25.8.2 草稿命令的实际完成与回收

附件准入与新建会话各自拥有具名运行时任务；进度观察不是命令本身。派发前冻结调用身份，
原生先登记责任再执行副作用，真实任务及结果在显式交接或收束前由原所有者持有。取得
句柄的回复丢失后，只能按原身份查询、加入原任务，不重新派发；查询暂无结果不证明拒绝。
这些能力是既有业务生命周期的窄适配，不建立新的通用调度、持久化去重表或消息总线。

HTTP multipart 暂存与 clipboard 暂存同属宿主输入准备，不冒充已经受理的原生附件命令。
Server 在读取上传体或创建临时文件之前，以调用方操作身份登记具名上传所有者，并持有
原普通请求名额、上传体任务及临时文件清理责任。完整 context／sources 形成并冻结后，
才向原生登记附件准入并计入原生 64 个命令名额；这两个阶段的责任和预算不可混称。
上传流不可重读比较，重复上传入口不凭相同 ID 接纳第二份 body，而是拒绝该次新请求；
恢复通过原上传身份的只读查询／结果加入，不重新上传、计算新摘要或重放原生准入。
关闭与断连不能丢失已登记的暂存或已受理原生工作；实际文件使用与清理 join 前不释放
宿主名额，清理失败保留原所有者和可重试报告。既有上传数量、字节与文件名规则不变。

附件仍按原模型策略整批准入，只有完整 batch 校验成功才发布全部元数据。失败回滚的
每个残余文件都必须保留实际清理责任和类型化 issue，不能吞错误或虚报资源已释放。
删除返回“目标已无 entry”是幂等结束，不是清理失败；真正 IO 失败保留原对象以供显式
retryCleanup。原生完成但交付未知时，Dart 保留 reservation，直到原任务结果与归属确定。

创建任务接受后，断开观察或关闭页面不取消创建；全局创建准入只在实际创建任务结算后
释放，不以 stream EOF 或界面组件 dispose 释放。成功回执和原执行源是两种证据：后续读取
执行源失败不撤销已受理输入。原创建所有者捕获真实投影，非激活借读只能附着该
原源，不能按 Thread ID 重新激活或借用新 incarnation。已打开事件流独立持有其原源 pin，
创建所有者收束不关闭已交接事件流。普通错误不自动证明未受理；提交阶段须有真实证据。

SDK 的附件 ledger 分别登记 draft 与 frozen operation 引用；移除草稿引用可以立即更新
本地草稿，但未清理责任仍通过 cleanupIssues 与原 operation 可见。创建、附件准入、临时
文件 staging、读取和删除均参与同一次关闭。临时文件清理错误不得只写日志后返回成功，
已知业务结果与后续清理结果分开记录。客户端沿原 pendingOperation 预算，原生附件准入
与创建共用每运行时 64 个未释放调用名额；它们不是读取作用域/read-call 配额，关闭
前不能只因已发出结果就归还。创建单提交准入仍独立保持，不以排队扩大原输入、上传
或模型限制。结果观察关闭不删除已交接给草稿的有效附件，也不取消已经受理的创建。

### 25.8.3 原提交的执行身份交接

输入观察属于原提交的 `SubmissionExecutionLease`，不属于 UI 选择或详情需求。原租约
可在其具体 Session、Execution attempt 与来源身份内读取该次交付的 Turn；公开 Session
详情读取仍须满足原 UI 准入，不能借提交修复放宽所有详情读取。提交读取与 UI 读取进入
同一 Session read 所有者和八个读取作用域限额，关闭与失败责任也在原所有者内登记。

Execution 的必要交接在 ACK 前完成：每次向原租约交付该帧的不可变 active/recent Turn
引用，去重后最多两项。消费者只读取原 header 与匹配冻结 inputId 所需的有界文本，不
物化失败正文或完整 Turn，不在 latest watch 中启动未等待的读取。交接只等待本次读取，
不等待未来 Turn、ticket 终态或同一基线完成后才会发布的 ready。读取或交接失败
保留原操作诊断，不 ACK 失败交付；不能用稍后的 latest、替换 attempt 或重开来源补证。

Composer 在派发前同步绑定消费者；Start 在原创建来源首次基线交接前绑定，
包括空 Turn 基线的来源初始化，不先等待 ready 再注册。已有 execution 基线只有
在其绑定来源与本次原创建来源为同一对象时才能复用；仅 Thread/incarnation
相同不够，普通 UI 事件流不能完成该创建租约的 ready。只消费真实收到且匹配原
Thread/来源/input 的类型化 Turn：queued 仅证明 observed，running 或带 startedAt 的
terminal 可证明 effective；任何 Turn.saved/terminal 都不证明 durable。durable 仍仅由
原 history input、requestDigest 与 accepted sequence 的一致证据推进。

当前原生输入在 gate 等待时尚无 Turn，开始时直接为 Running；ThreadStatus.Queued 不
证明某个 input，也不能改造为伪 queued Turn/ref/time。本修复保留 SDK 的类型化 queued
消费契约，但不新增原生 Pending 身份协议或声称其端到端已实现。

租约的同步关闭先封其 Turn read 准入，真正加入已登记的 late open、query、交接与
原 history 查询之后才释放观察责任。Unresolved 保原读取作用域、资源许可、issues 与显式重试；
不以 UI 退出、超时或 Future 取消意图当作工作完成。只关闭该租约的读取，不反向等待
正在等提交租约释放的整个 Session.close，避免形成关闭环。
观察者构造失败即使发生在创建结果已确认之后，Draft work 也必须加入失败构造所有者
的真实清理并保存报告；不能只靠后台释放资源许可，而让 work 永久停留在证据未收束状态。
原失败通知、观察取消或需求/资源许可释放抛错时，也须保留该步骤的显式重试责任；
已成功步骤不重复执行，失败步骤不能因为“曾尝试”就永久跳过。恢复成功只消除该步骤
的未完成 issue，原业务失败与首次结果保留；真实 terminal join 故障不能被顺带清除。

## 25.9 启动与应用退出

启动装配由应用生命周期明确发起，成功／失败由唯一启动状态发布。首个目录／catalog 基线
到达前的失败包含类型化 code 与 correlation，不困在界面组件的局部等待标志；显式 retry 不
创建第二套初始化。启动后局部目录失败保留可用 shell 和最后有效数据。

Updates 仓储构造不打开原生事件流，也不初始化库；原 RuntimeReady 后的显式读取需求才
开始订阅。自动更新 gate 同步登记观察后，等待与当前 header 的 origin／ref 匹配的完整
权威 value，不能只见 header ready 就派发自动任务。调用动作前再次核同一准入条件；
只读 gate 失败可以在显式启动重试时恢复，不自动轮询或重放业务。运行时已 Ready 而领域
attach 失败时，保留原 Ready 结果，显式重试只恢复未完成 attach，不重启原生或把提前
标记 attached 当成功；已受理自动任务始终复用原 ticket，包括失败与未知结果。

手动更新的操作与准备任务归更新领域服务，请求同步发布 pending，视图模型只编排并呈现，
页面不持有准备任务。已有后台下载时复用同一次准备；准备操作与进度流真实完成后，才把更新后
重启意图交给同一退出协调器。首次退出固定普通退出或更新后重启意图及绝对期限，应用 close
幂等并复用首次 future；后续请求只加入，不重新启动、延长期限或改变意图。

退出先封闭业务与编辑生产者，加入已受理操作；同时发布展示无绑定并卸载路由子树，不能等全部
close 完成后才解绑。独立 session、事件流、update 和附件任务并发取消，在首次期限内等待真实
完成及展示租约的释放确认，随后才销毁 UI 控制器。尚未解决的任务与资源出现在 CloseReport，
不能释放未确认的资源许可；provider container 与 opaque dispose 位于真实异步收束之后。

有真实阶段依赖的领域仍保持关闭顺序：Updates 先取消并 join 已受理任务，再收束其事件流／
read scopes。共享资源生命周期提供无副作用的当前责任报告快照，供前一阶段期限耗尽时
合并尚未收束的后一阶段；读取快照不封准入、不取消、不启动清理或释放资源。快照只说明
当时已登记的责任，不证明整个领域已关闭，也不替代原 future 的真实 join。

退出结果分别承载关停报告与安装交接结果；安装器启动失败不能改写可靠保存的结论，也不能
被关停 Clean 隐藏。更新退出先在原期限内恢复既有主窗口，确保托盘隐藏时提示仍实际可见。
界面显示更新版本、停止会话和保存提示；关停失败与安装交接失败均在
首次退出的剩余期限内留出一次渲染和最多 1.2 秒阅读时间，随后按既有退出期限结束。

退出提示在 `MaterialApp.builder` 内替换整个 Router 子树，促使当前及被覆盖的页面真实卸载，
再由原展示所有者等待租约的释放确认。被 Settings 覆盖的聊天页面可能因 Riverpod 的
`TickerMode` 暂停观察；不得依赖隐藏页面收到状态刷新才能退出，也不得在子树仍挂载时
提前销毁 controller 或伪造释放确认。退出提示与应用所有者位于 Router 之外，持续负责
进度、失败提示和同一次有界关停。

Dart CloseReport 在 Rust finalizer 前并入 externalIssues；只有真实 ACK 和可靠保存确认后才可
报告 Clean。超时不另起期限，不在运行时宣布 Clean 后追加失败掩盖提前释锁。原生进程退出
总期限与 Windows 托盘隐藏语义以 [19](./19-studio-ui.md) 为准。

### 25.9.1 生产与 Driver 的单一装配入口

生产启动与 Driver 启动共用同一个装配入口，只由调用方选择是否需要 Driver 装饰；
不建立第二套 AppGraph、第二份所有者或仅在某一入口补齐的分支。该入口只产出
composition 所有者（AppGraph、Bots 仓储、托盘控制器）与应用装配结果，不承载
任何领域业务方法，也不成为可变客户端门面。

框架绑定、Driver 扩展注册与首帧启动必须处于同一受保护的异步执行域，绑定只初始化一次。
需要专用绑定的验收入口先安装官方扩展及其绑定，再由共享入口确认绑定就绪；不能先创建普通
绑定后再安装第二个绑定，也不能把验收注册移到错误捕获域之外。生产入口不加载 Driver 扩展，
仍使用普通绑定；该顺序不改变应用装配、初始化失败恢复或退出所有权。

装配先建立共享预算与操作登记、领域端口与仓储，再连接生命周期、退出宿主和自动更新
准入。原生库只在这些所有者存在后由显式启动流程加载；运行时就绪后才接入领域需求。
进程入口不提前初始化，装配阶段不触发平台通道、不打开领域事件流、不发起业务命令。

退出协调器与装配共用同一批所有者，包括托盘与退出宿主；装配不得创建退出流程不会
回收的实例，也不得让退出流程另建替代所有者。自动更新 gate 的启用与否由装配决定，
不改变各自领域契约。

装配失败按启动装配的既有启动失败链发布类型化 code 与 correlation，由统一启动状态
呈现并可显式重试；不新增第二套错误通道，也不把装配异常降级为空所有者或默认实例。

## 25.11 模型目录一致性

Configuration 的类型化来源也由原 ConfigRuntime 发布边界捕获，不从旧聚合 Settings
订阅或异步 latest 消费重建。无密钥配置材料、账号成员身份、来源状态和相容模型引用在
同一提交边界确定；配置、目录、来源与投影水位各自独立。同 ID 删除后重建获得新成员
身份，凭据只公开存在性。配置命令回执指向该次原提交捕获的目标，不以随后 current
冒充原结果。配置字段、嵌套列表和长文本按具名不可变读取作用域读取，复用产品 8 scopes、
64 read calls 与既有交付窗口，不建立另一份 Settings 所有者或无限历史缓存。

配置／目录配对凭证持有原两份不可变材料，并由原生核验所有目标与双水位。只有 current、
未 ACK 交付、实际读取和尚待消费的命令调用所有者持有强引用；历史定位不延长材料寿命。来源或捕获失败必须
真实报告，不发布假相容 pair。Configuration 与 Profiles 仍是独立领域来源，不能因共享
设置页面把它们合并成一个事实源。

Models 的 Catalog、来源状态与精确详情在 FRB/HTTP 中均通过原 origin/ref 或完整配对
target 独立打开。HTTP 不得要求先取得活 Catalog 事件流，或从当前事件流补齐、替换请求
身份；命令结果所持原配对也可合法打开详情。运输层只持原 opaque、打开/查询/正文消费
责任及原额度，不保存另一份 Models 业务状态。事件流关闭不撤销已交接的独立读取作用域。

HTTP 句柄的能力类别与原身份必须保持可核验，不能用读取作用域 ID 前缀或同为 Value 的
版本种类区分 Catalog 与精确详情。错域请求明确拒绝，已释放身份不承诺永久保留。来源
状态的 revision 与目录业务 revision 独立；过期原材料不能用最新来源状态替换。
Catalog 沿原 2 未 ACK／1 latest 窗口，ACK 释放额度必须唤醒等待发送的 HTTP body；
最后 control 交付不等于正文消费者已结束。真实打开、查询、消费者与关闭全部 join 后
才释放原资源；同一应用退出仍沿既有绝对期限和 finalizer 汇总未收束责任。

产品 Dart 适配器复用同一个机械打开/资源所有者，通过明确的 ProductReadVersion
区分 value 与来源-status，不把所有读取作用域限定为 Value，也不把 Thread identity
强转为 Product identity。raw 读取作用域/call 身份先于可能失败的完整 descriptor 转换保存；
转换失败不消除原 opaque 的关闭责任，关闭报告必须核原始身份。已受理命令的 result
转换参与原所有者的 join，但不使用普通只读 query 的关闭后取消检查丢弃已知提交阶段。
ConfigurationPort 完整实现具名读取、原配对、两种事件流与三个调用资源；构造不启动
来源、reload 或 probe，不在适配器重算 Start 策略或制造额外 observed/回执。
ModelsPort 同样由无构造副作用的生产适配器完整提供 Catalog/Templates 事件流、各自
具名 read、Models 来源-status 与精确 Delegation read 六类入口，复用上述机械所有者。
不以临时叶工厂冒充完整 port，不另加 probe/load mutation，不重算原生模型资格。
精确 Delegation read 单独提供原生读取作用域 ID，独立于完整 descriptor 转换与查询准入，
在 Clean/dispose 后仍可核验关闭报告。完整 identity/target 查询继续严格校验原配对；
查询失败不转成清理身份失败，不补造 descriptor，也不从关闭报告反推期望 ID。

目录发布完整成员与后端计算的类型资格。所有会话、Mode、系统角色与 Agent 使用同一公共
模型查询；GUI 不另算能力、预算或默认值，不满足资格的既有选择保留并显示原因，不自动换模型。
目录与配置 revision 独立，账号参数变化只更新受影响路由，旧响应不能回滚新目录。
编辑时的effort建议和新Profile的首个文本模型建议由原immutable目录读取作用域中的Rust纯查询
提供，不从Dart部分页选全局first或重写模型策略；建议结果携原查询目标，由原编辑意图
核验后消费。它们不读取最新配置，也不改变配置保存的严格effort校验或空值省略语义。

系统角色的配置存在性与缺省建议由 Configuration 的专用不可变配对读取提供。Rust 在
同一配置所有者捕获配置／完整模型目录及真实双水位，并发布可按需读取的配对引用；
任一来源改变都使配对目标更新，不要求普通配置字段随目录变化重新读取。旧读取作用域只读
原配对材料，不在读取时偷偷改用 latest 目录。原 role key 存在即返回原 route，包括空或
不可解析的 effort；只有该 key 确实缺失才建议完整目录中的首个文本模型，真实无候选与
未知／失败分开。UI 不从部分目录页推断全局 first，也不把 role 展示查询当最终 Start 解析。

账号模型的资料与最终评价详情使用同一 Rust 签发的配置／目录配对凭证，而非把两个独立
latest target 放入一个值就声称相容。详情请求还冻结 account/model；原生核验配对引用、
原配置与目录目标及双水位后 pin 原材料，已过期或不相容时明确失败，不替换成 current。
复用的是来源配对证据，详情仍使用具名 Models 读取作用域，角色查询不成为通用 resolver。
详情的执行资格由原配置捕获边界按既有原生规则确定，仅保留与原 account/model 成员
绑定的无密钥结果及不可用原因。凭据存在性、展示 descriptor 或编辑建议不替代实际
资格校验；不得在读取旧配对时重读 current，也不为此保留整份运行时配置或已解析路由。
资格变化参与原 Models 材料及成员版本判断；普通不可用是成员事实，不伪装成全来源
捕获失败。它不授权改变模型启用、连接、effort、凭据或工具能力的既有准入规则。
本地性能与评价窗口在该次详情读取作用域打开时捕获，之后只读该不可变窗口；这不承诺它们
与配置／目录属于同一个跨数据库事务。后续显式读取可以取得更新的评价窗口。

新建路由也通过独立的 Start 只读能力消费该原配置／目录配对。路由规则保持原产品行为：
先读当前 mode 的配置路由，缺失时使用 mode.simple；显式模型意图优先，非空 effort
意图优先，否则只在模型相同的情况下继承原 effort，最终空 effort 使用该模型的原生
默认。显式换模型的 effort 归一化复用模型层已有建议规则；缺失或禁用模型明确不可用，
不能选择全局 first 代替，也不把候选列表的类型筛选新增成此查询的准入条件。

Start 查询不读取 Mode 定义：上述规则只依赖 mode 标识与原配置／模型材料。Mode 的
实际存在、创建资格和执行定义仍由原创建命令检查，不新增虚假的 ModeCatalog 事务保证。
查询不会保存默认设置或修改路由。SDK 在提交前通过显式读取需求物化结果，原来源或
编辑意图改变即失去提交资格；submit 只同步冻结仍相容的已物化完整路由，不在首 await
之后重新解析或替换。读取失败保留原始编辑，晚结果不覆盖新意图。

Models 的不可变材料与成员身份连续性在原配置所有者的发布边界同步捕获和推进，再由
产品观察消费；latest watch 只能通知，不负责从最终值重建遗漏的删除／重建历史。即使
观察者未及时 poll，同 ID 删除后重建也必须取得新成员身份。材料寿命只由当前发布、原
未确认窗口、已固定的读取作用域与原命令调用承担，不建立无界日志或第二份配置事实源；查询不能
用 current 配置补旧引用。Models 捕获不携带账号密钥或整份 Settings 的序列化副本。

模型目录的全资源来源状态表示原配置所有者中已校验目录的可用性，不表示所有账号的
联网探测均成功。该状态由同一 ConfigRuntime 持有并在原发布边界推进；传输层不在
查询或订阅时临时构造 Ready，不借配置／目录业务 revision 充当来源状态 revision。
初始化成功才有 Ready，原所有者关闭产生 Stopped；成功发布更新原观察时间。初始化
失败不发布假空目录。逐账号 probing、缓存来源、检查时间和错误完整保留在账号目录中，
不聚合成没有真实操作所有者的 Loading／Refreshing／Degraded，也不制造全局探测 ID。
八态类型保持穷尽运输，但不要求一个只有同步目录发布的来源人为经历所有八态。

来源元数据、业务材料和投影交付的身份及水位相互独立，并在同次发布中相容捕获。
来源状态按需读取只读原不可变元数据，不发起联网探测或配置 reload。投影捕获失败、
预算耗尽与运输失败沿各自真实错误路径报告，不能冒充账号探测失败，也不能因来源仍
可用就发布缺损业务材料；恢复仍遵守失败后的成员身份失效与原引用寿命。

模型 key 使用 account ID＋model ID；显示名不是身份。统计先按该 key 接收权威汇总，
effort 是组内细分，发送／返回模型仅是冻结诊断；未知历史身份不能由当前目录补写。
账号模板只负责创建默认值，不参与已有账号或历史统计身份。

## 25.12 远端目录查询资源

`RemoteRepository` 监督远端目录查询，每个 `RemoteDirectoryQuery` 持有自己的游标、已接纳
请求和清理责任；类型化目录结果的 `nextCursor` 是唯一续页依据，不从偏移重新扫描目录。
目录选择器替换当前页，换目录、切换服务器或销毁时由查询所有者释放旧游标，以请求代次
拒绝迟到结果；晚返回的游标仍交回原所有者关闭，不能因不再展示就丢弃。

仓储关闭先封闭查询、等待已接纳请求交接，再并行关闭仍持有的游标；失败保留对应
所有者与恢复能力，不以页面销毁报告远端清理成功。游标、连接与关闭任务是运行时资源，
不放入 `Freezed` 视图状态；展示层不创建 SSH 连接。远端协议与清理语义遵循
[22](./22-ssh-remote.md)，不恢复旧操作门面或巨型客户端。

跨功能的 SSH 编辑、密码和远程目录弹窗通过设置功能的具名连接器入口复用同一呈现所有者的
身份分配与结束登记；工作区功能不导入私有视图模型或自建弹窗身份来源。添加远程项目的名称编辑在
原确认意图中冻结，与目录一起进入真实的打开、改名、激活批次，不在打开后补写名称；
成功返回只说明该原批次与本次查询借用已经完成，不触发第二次打开或第二个选择来源。

## 25.13 开放工具产物的呈现边界

`ThreadItem` 及其已知字段仍使用封闭类型化值；只有原工具的 `output_artifacts` 是有意开放的 JSON
值序列。Rust 保留原值，传输逐项编码，Dart 领域用具名不可变的不透明文本值表达，不在仓储
或归并器还原成动态协议对象。该边界不允许已知 DTO 退回 JSON 聚合，也不扩大时间线常驻或
详情读取预算。

网页卡片仅在专用呈现适配中使用标准 JSON 解码器，从已交付的开放产物提取原有最多六个
去重链接；保持原遍历顺序和 HTTP(S) 前缀选择语义，不新增 URL 过滤或自动读取完整大产物。
解码对象只是临时呈现材料，不进入权威镜像、视图状态、Driver 或另一个正文缓存。
原工具参数与原始载荷正文保留各自不透明文本语义，不被此边界自动解析。

模拟传输层实现的是原生侧线协议契约，它自有的
`base64url` 续页游标信封由自己写入并读取；解析该信封属于传输层内部行为，既不解释
业务载荷，也不扩展本节的产物边界。其他 Dart 侧位置仍不得解码已知协议 JSON。

## 25.14 附件二进制读取

附件二进制读取的唯一契约见 [25.8.1](#2581-附件原文件读取)，包括授权、同一文件句柄、
独立读取身份、块大小、共享预算、错误及真实关闭。字节计量与 JSON 详情预算分开，
不得捏造会话状态域修订。只读能力不改变附件准入、上传限额或草稿／操作双归属。

## 25.15 外部机器人产品域

Bots 与 Configuration／Models 同级的独立产品域，不从 Conversation 或 Settings 内部
借道。SDK 的 Bots 仓储是该域 Dart 权威镜像的唯一 writer：它持有类型化
product 主题的基线、事件与来源状态，并把命令回执、凭据操作和配对进度作为独立的
值发布。设置界面、启动路径与演示模式只消费该仓储暴露的值和动作，不自建
第二份 bots 状态、注册尝试队列或凭据缓存。

- 产品主题载荷以具体 bots 类型表达，不回退到通用动态 JSON；`BotsBaseline` 与
  `BotsStateChangedPayload` 属于产品主题联合的一部分，与其他域同样按最多两个未确认
  交付、明示来源版本和真实关闭责任处理。
- 命令动作覆盖保存、启用、连接重试、注册开始／取消、信任用户／会话，以及 bot 会话
  线程的创建与分页读取；每个动作冻结自己的目标、operation 与期望版本，回执只结算
  原操作，未知结果不自动重发，也不据错误文案推断未生效。
- 凭据操作、注册尝试与诊断是独立值：可用性、进行中操作和最终失败分别保留，不用
  一次成功快照清除仍在进行的凭据责任。
- 原生适配层只做 FRB 边界转换与类型映射；生产、演示与测试替身共用同一端口语义，
  不据 demo 数据伪造成功回执。App 侧以生成式 AsyncNotifier 承担编辑、校验、pending
  与最新意图，视图只消费不可变状态与类型化回调。
- 设置页的 Bots 分页、发布侧会话菜单入口与 Driver 投影都读取同一仓储事实；
  Driver 只暴露已发布值的只读投影，不新建第三条状态链。
## 25.16 产品域原生读链的分层

每个产品域（Configuration、Models、Profiles、Templates 之外的 Workspace、Bots、
Modes、AccountUsage/Statistics、Updates、Startup、Recovery、Persistence、Remote、
MCP、LSP、Skills）都按同一四层实现，不设通用产品内核：

1. **域内来源**：`pl-studio-runtime` 的各领域持有不可变材料登记，负责来源引用签发、
   实际发送与引用可达性的同次提交、有限历史固定，以及封闭准入和完成收束。
   引用要么由原事件流的真实发送暴露，要么由原命令自身的结果暴露；后续按 ID 查询
   current 不能替代这两条来源。
2. **领域事件流与读取**：打开操作返回类型化事件流与具名读取连接，共享既有交付窗口
   （含基线的两个未确认额度、连续前缀确认）与读取作用域预算；目录扩展沿
   原生分页边界，不重建偏移。
3. **协议 DTO**：跨 FRB 的读形状归 `pl-protocol` 的产品读模块，运行时构造、
   bridge 只做映射；同一形状不保留两套定义。
4. **Bridge 与 Dart 适配**：bridge 只映射句柄与错误，Dart 端口实现负责类型转换、
   冻结目标、回执校验与关闭责任；不为旧调用点保留兼容入口。

跨域 FRB DTO 名称必须互不重复，避免生成边界按 Rust 短名混淆不同领域身份。
会话配置形状以 `ThreadConfiguration` 前缀区分于
产品域的账号配置形状；产品目录查询与筛选以 `ThreadDirectory` 前缀区分于旧列表传输
形状。新增同名形状时应改名为带领域前缀的唯一名称并迁移消费者，不通过重命名生成物、
手工改生成代码或合并语义不同的 DTO 规避。

读取作用域预算以稳定的业务标签区分（如同一目录查询形状、单 Thread 元数据），
不得以引用、代次或事件流身份作为键绕开原配额。

### 25.16.1 恢复领域的外部读取

恢复登记与其不可变材料来源仍是唯一权威。FRB 与 HTTP 均通过该来源的类型化恢复事件流、
来源状态读取和具名材料读取交付；事件只含轻量头、来源身份及成员引用，不内嵌问题全文或
变更文件集合。问题、诊断文本与变更文件沿原读取作用域有界读取，未知列表仍为空值，
不是空集合。读取不得触发恢复扫描、文件系统检查、模型或工具执行。

HTTP 使用 `POST /api/v1/products/recovery/events` 建立单次事件流，返回原生事件流身份；
通过 `/api/v1/recovery-feeds/{feed_id}/` 下的确认与关闭接口管理该原生资源。
`POST /api/v1/reads/recovery` 与 `POST /api/v1/reads/recovery-source-status` 打开绑定原来源
和原引用的读取作用域；`/api/v1/recovery-reads/{scope_id}/` 提供具名查询与关闭。
查询身份失效时明确失败，不改读最新材料；确认只接受该句柄连续处理的前缀，拒绝
`Last-Event-ID` 重放，取消不受普通请求或数据窗口满额阻塞。传输层只持自己的任务、
读取和连接，不维护第二份恢复状态；退出先封准入并等待这些资源，未决责任留在原所有者。

显式恢复重试和安全清理继续调用原命令及原授权边界。重试结果保留命令实际签发的读取
目标和发布寿命，不通过回读最新状态伪造提交结果。旧恢复整表查询、旧产品主题中的恢复
变体及全应用聚合快照中的恢复字段退役，不保留兼容转发；仓库外消费者迁移至上述事件流
与读取接口。其他领域的既有服务端诊断接口不因此删除。

## 25.17 呈现保真与共享壳层契约

分层重构可以更换组件边界、状态形状与读取路径，但用户可见的呈现不得随之改变：
页面/面板的区块顺序与分组、控件类型、几何常量（内边距、间距、行高、图标尺寸、
圆角、断点、最大宽度）、入口位置、菜单项集合与窄窗行为都以重构前基线为准。
旧界面断言不得因实现改动而放宽；实现与断言冲突时改实现。基线新增能力（如委托
摘要行、自动选模、最终评价入口）必须保留，但其插入不得挤压原有呈现的既有地位。

设置页与交互区复用各自的共享呈现壳层，分页不另算几何或增加第二套布局。
具体尺寸、断点、主题与稳定诊断身份统一见 [19.8.2](./19-studio-ui.md#1982-共享呈现壳层)。

**交互读取的挂载准备。** 交互问题、选项、身份文本与应答记录独立分页，打开元数据头不代表
正文已经就绪。交互区挂载时幂等准备首屏问题、其选项和全部必需身份文本；读取必须有界且
持续推进偏移或字节，不推进即停止，不空转。应答记录只在终态结算视图按需读取。
提交准入依据实际已读材料是否完整，
不以「用户先点加载」为前提；显式重试走同一准备路径，且不重发任何已受理命令。

## 25.18 AST 边界门禁的判定锚点

边界门禁与反例 fixture 是 §25.10 的静态检查环节，只判定可判定的语法事实；运行时归属仍
由 §25.4、§25.5 的观察与关闭契约以及客户端、适配器套件证明。为避免把合法的新架构判成
违规，也不以类型名称拼写推断所有权，门禁与代码共同遵守以下锚点：

- **所有者由声明判定，不由名称后缀判定。** Freezed value、enum 及其生成的伴生名是值类型；
  即使名称以 `Owner`／`Connection`／`Binding`／`Controller` 结尾，也不构成运行时所有者。
  仓储、Session、资源许可、任务、连接、原生句柄与仅限界面 controller 才是资源
  所有者。领域值之间的引用属于值语义，不因命名相似被禁止。
- **UI 层声明的类型是 UI 词汇。** 功能 `views/`、`widgets/` 与 `ui/` 内声明的界面组件、
  State 与仅限界面的控制器是纯视图的合法呈现属性（§25.6），不是业务所有者；业务
  所有者只在领域包、适配器与应用装配层声明。功能内仅限界面的控制器与其纯视图
  同层声明，不放入 `state/`，也不进入 Freezed 视图状态。`vyuh_node_flow` 的图词汇
  （`Connection`、`Port`、`Node`、`NodeGraph`）只表示图形投影，仅在导入该包的文件中合法，
  不构成第二个业务所有者。
- **provider 生命周期只 detach 自身观察。** `ref.onCancel`／`onResume`／`onDispose` 内允许
  取消自身观察、终止自身计时器与合并 helper、清空自身集合、调用自身 `_dispose*` 私有清理；
  禁止关闭 Session、放弃草稿、取消已受理业务操作、释放 orphan、改变业务 demand、归档项目
  或写配置。门禁锚定这些具名业务动作，不把集合清理与自身 helper 释放当作业务关闭。
- **旧客户端门面不再准入所有者。** provider 不得通过旧客户端／传输层绑定按 id
  取用第二个所有者；仓储提供的会话与草稿等具名公共查询按 §25.2
  由仓储拥有并登记资源，是视图模型的合法领域入口，不属于该禁令。
- **适配器不写第二份权威。** 镜像写入锚定适配器的 `publish`／`markObserved`／
  `markDurable` 一类镜像发布动作；`dart:core` 的 `Iterable.reduce` 折叠、集合运算与自身
  缓冲区维护不是归并器。适配器向自己拥有并只读发布的 latest-value holder 写入是
  生产者侧的观察发布，不构成第二份权威。
- **手写 `part`／`part of` 不是模块边界，但可以是模块内部组织方式。** 允许范围限于与库
  文件同目录，且该库位于 `anywork_client` 领域 `data/` 模块或 `infrastructure/frb/` 适配层
  子树内；跨目录拆分、跨模块共享或在 `features/**` 内手写 part 仍被拒绝。生成物 part
  （`*.g.dart`、`*.freezed.dart`）由 §25.10 的生成边界负责，不在手写检查内。

需要调整以上锚点时先改本节，再改门禁实现与反例 fixture；不得通过删除规则、把规则降级为
warning 或把检查移出门禁来让代码通过。

## 25.19 ACP 接入的前端归属

ACP 认证与受管安装是两个独立产品资源，Dart 侧同样分域承载，不复用 Native 模型账号的命令通道。

- **SDK 领域。** `anywork_client` 的 ACP 领域公开不可变值、状态与 `AcpAuthRepository`、`AcpInstallRepository`，适配端口入口公开类型化帧、有界读取与仓储构造能力。两仓储分别承载认证、安装的权威镜像、观察租约、取消及关闭。账号保存和删除仍归配置领域，与认证共享设置提交边界，但认证结果不写配置；安装属于共享资产，不是账号字段。
- **传输适配。** FRB 与领域端口按职责映射；适配器只负责类型化转换及观察发布，不解析文本，也不保存第二份权威状态。
- **应用呈现。** 账号设置通过连接器、视图模型与纯视图承载 ACP 编辑、认证及安装准备。`acpAuth`、`acpInstall` 观察租约由账号页可见需求持有，离页只释放自身订阅。
- **呈现保留。** 认证阶段、失败类型、安装进度/资格与「准备后再保存连接」的操作顺序保持既有界面
  语义；不以本地 busy 布尔值推断登录或安装完成。

保存成功、连接检查进行中与检查失败可重试是三个不同阶段。检查进行中保留已保存事实和原表单，但不显示可执行的重试动作；检查失败后才启用重新检查，重试不得重放配置保存。明确取消仍可离开编辑器，并保留“已保存但未连接”的真实结果。表单保留的验证须覆盖实际编辑状态与导航，不能只证明某个结果判断函数返回预期布尔值。

安装准备与取消的在途状态均绑定原供应商及操作身份。原操作的取消尚未返回时，只阻止对
该操作的重复取消；权威状态推进到另一操作后，新操作仍能被显式取消。旧回执仅结算原
请求，不能解除新请求的在途状态、认领新安装结果或覆盖当前表单；离页仅结束自身观察。

### 25.19.1 类型化 FRB 推送与原生订阅身份

`acpAuth` 与 `acpInstall` 各有一个与 MCP/LSP 同构的原生事件流传输层：帧自带事件流 identity
（feedId/ownerEpoch/incarnation/resource）、投影戳、发布方 `baseRevision`、delivery 序号、ACK
与 close 报告。适配层不得用本地计数器、`readStudioState().ownerEpoch` 或「上一帧水位」顶替这些
事实，也不得把 ACK 退化为 no-op；需要新订阅身份时必须补原生传输层，而不是在 Dart 侧合成。

`AcpAuthSnapshot.revision`、`AcpInstallSnapshot.revision` 与 `AcpAccountSettings.connectionRevision`
是三个独立水位；适配层只做类型化映射，账号与连接的匹配（`accountId + connectionRevision`）
由仓储判定，适配器不做本地匹配或缓存。投影戳与快照 revision 的一致性只由仓储
判定一次，适配器不复制第二份校验。

### 25.19.2 证据语义的落点

ACP 命令若仅返回 `Result<Reply, BridgeError>`，普通调用失败不能证明未受理，必须表达为
`unknownOutcome`（不自动重发、不宣称未受理）。账号配置命令迁入下节的受管调用资源后，
只有原生明确的准入拒绝或提交前拒绝证据才可表达为 `Rejected`；传输异常本身仍不构成该证据。
原生已确认提交、随后转换或观察失败时，表达为 `committedButUnobserved` 并保留真实回执，
回执无法校验时单独表达其不可用性。缺失即缺失：`totalBytes`／
`bytesPerSecond` 为空只能显示不定进度，`sha256` 为空不得称已签名，`closing`/`cancelling` 是非
终态而非完成，`unchecked` 不是失败，`verified` 只证明当时观察。

### 25.19.3 Driver 事实的只读投影

Driver 诊断可读 ACP 事实，但只借用应用装配中已存在的两个所有者的权威镜像：
不注册观察者、不占预算资源许可、不请求同步或补读，也不启动检查、安装或取消。
JSON 形状挂在 `settings` 诊断下：`acpAuthLoaded` 与
`acpInstall{loaded, revision, installations[{provider, phase, stage, operationId,
failure{code, retryable}}]}`；未加载时 `loaded=false`、`revision/installations` 为 `null`（不用
空集合冒充"已加载且无安装"）。`phase` 由 sealed 状态的静态分支得出，`failure.code` 由类型化
枚举解析，不做文本解析或 dynamic 分发；投影不推进任何状态机，重复序列化结果稳定。

受管安装与认证旅程还消费原有的只读事实：`acpAuth` 包含加载状态、修订号、更新时间及按
账号与连接代次区分的认证状态；`acpAccounts` 与 `nativeTemplates` 分别来自账号页面已完成
的配置目录和模板读取。未读取时保持 `null`，诊断请求不能为了填满字段而发起读取或创建
页面所有者。呈现层只向诊断边界交付领域值，不让共享诊断依赖账号功能的私有视图模型或状态。
Driver 入口的采集适配可以借读已经挂载的页面状态，并据该次读取失败筛选可用事实；
传入共享投影与序列化层的仍只能是领域值。采集不能为了诊断创建页面、触发读取或复制状态，
也不要求业务视图模型增加仅供 Driver 使用的出口。

安装诊断保留权威进度、重试次数、固定发行身份、程序位置和复用标记；认证诊断保留操作、
可用认证方式及服务端身份。失败保留类型化类别、发生阶段、脱敏消息和重试资格，不从消息
推断状态。未知总量、速度或校验摘要保持缺失，不能补成完成百分比或签名保证；这些事实只供
验收观察，不形成第二份配置、凭据或安装状态。具体界面操作、截图与报告工具归验收入口维护。

### 25.19.4 配置目录的固定读取与受管调用

ACP 账号目录是配置材料的一部分，不通过完整设置与模型目录快照间接获取。原配置读取作用域的元数据头提供 ACP 列表引用；分页行包含可分块读取的账号 ID、名称、类型化供应商及连接代次。分页、文本块与关闭继续使用配置领域已有的作用域身份、预算和资源监督，不增设 ACP 专用读取登记表。读取固定原配置目标，账号连接代次仍来自 ACP 身份所有者，不能由设置版本、列表位置或认证最新状态推导。

目录投影的所有权、同设置版本捕获、发布顺序与提交后失败语义由 [20.1.2](./20-config.md#2012-设置变更的资源边界) 统一定义。SDK 只消费原目标已捕获的目录，不在发布后查询最新目录回填旧材料；来源未准备好与已知空目录必须明确区分，不以空列表或零连接代次补齐未知事实。

已物化目录保留原配置所有者与实例代次、材料引用，以及捕获时的设置业务修订和更新时间。
这些字段来自同一次固定读取，不在返回后补取最新来源。未完成读取用缺失值表达，不构造没有
来源的“空目录”对象；成功读取的零修订或空行集仍是有效事实。页面可以保留旧目录用于呈现，
但 Driver 的当前目录只接受来源、材料和业务水位均与当前配置相符且本次读取未失败的结果；
来源变化或刷新失败时输出不可用，不能把最近有效值与新设置事实混合后当作验收基线。

账号保存与删除复用配置领域已有的受管调用所有者、操作身份、原始结果查询和真实关闭机制，以独立的 ACP 账号调用种类表达，不建立另一套调用登记表。提交成功只返回真实的设置回执及本次提交捕获的配置读取目标，不携带整份账号目录，不伪造模型目录目标或模型资源回执。原调用在显式关闭前保留该目标的材料责任；SDK 从原目标完整读取目录后才能完成相应观察，读取失败保留提交证据与同步失败，不重新保存。

请求开始的响应丢失时，只查找和加入原操作的调用，不发起第二次提交。调用关闭封闭新查询，并等待已受理写入、结果读取及子作用域真实结束；未决资源继续留在原所有者名下以供显式重试。ACP 认证和安装的取消仍是各自独立业务动作，不因配置调用关闭而取消。

此调整不扩大 HTTP 写入能力：既有 ACP 保存、删除端点及其授权边界保持，内部受管调用种类的扩展不加入 HTTP 普通配置写请求的公开变体，也不新增可接受任意调用种类的写入路由。HTTP 同步配置作用域中的 ACP 分页读取与对应结构定义；现役 ACP 写端点继续消费同一设置所有者的真实提交结果，不恢复桌面侧已退役的一次性调用入口，也不维护第二份业务状态。

## 25.20 独立模型性能统计与完整快照

模型性能统计形成独立领域：Rust 计费所有者提供权威事实，统一产品协议交付汇总与历史的类型化事件和读取引用，统计仓储完成物化、校验与唯一归并，视图模型只管理筛选及呈现，连接器向纯视图传递不可变属性与回调。统计领域不依赖账号设置、全局客户端门面或其他功能的私有提供者；不可变领域值与视图状态沿用 `Freezed`，连接、任务和租约仍为资源所有者。账号额度与根会话费用保持各自职责、公共入口与关闭责任，不能因拆分统计而删除或合入全局历史。

### 25.20.1 来源配对与完整物化

汇总和历史沿用各自的产品事件流、投影水位、固定读取引用和有界分页能力。统计仓储内部处理这两路输入，只有两侧来自同一权威所有者及实例代次、业务发布版本一致且所需材料完整读取后，才原子发布新的统计快照。不同事件流的交付序号和投影版本不要求相等，也不能代替共同业务发布版本。业务版本一致时的完整性标记必须相容；不相容输入按协议失败处理，不能拼成混合快照。

每侧候选在首次异步等待前绑定原连接尝试、来源和材料身份；全部页、推理强度细分及身份文本在原作用域内连续读取。页偏移、集合版本、条目身份、重复成员、续页进展和文本字节连续性都须校验。每侧仅保留一个最新完整候选，完成本侧消费后独立确认原事件流，不等待另一路确认而占住交付窗口；配对失败或对方尚未追平时保留最近一次完整快照，不发布半份集合，也不把未加载状态显示为已知空集合。

材料引用及原所有者不变时复用已完整物化的值。仅发布状态变化不重新读取汇总、历史或推理强度页；材料变化只重新物化受影响部分。读取与物化继续遵守既有页、字节及资源预算，不新增静默截断，不缩小原历史窗口或模型集合。筛选条件的失效清理只能依据完整权威集合，不能依据尚未读完的页面推断模型或推理强度已不存在。

### 25.20.2 观察、可见需求与关闭

仓储提供只读状态观察和独立的可见性租约。观察登记同步返回当前值，取消观察只移除自身监听器；可见需求才决定是否打开统计事件流与启动物化。隐藏构建不创建需求，最后一个需求释放时退役原尝试并请求关闭；再次可见须先完成旧资源收束，失败则保留原责任与预算并提供显式重试，不另开连接掩盖未关闭资源。

对外通知可以同步重入。需求登记、尝试身份及关闭责任必须先于通知发布建立，回调中隐藏、关闭或重试不能使已退役尝试重新取得准入。已受理打开、页查询、消费、确认和关闭均由仓储登记；取消等待、超时或界面卸载不等于资源已结束。关闭报告继续复用统一未决资源与重试契约，不建立统计专用退出协调器。

### 25.20.3 呈现保真与统一消费

界面只消费完整统计快照及局部加载、失败状态，不承担分页循环或读取身份管理。内部按页读取不增加用户翻页控件、来源提示或额外视觉区域；统计页面的表格、卡片、筛选、空态、间距和诊断身份以 [19](./19-studio-ui.md) 为准。刷新与重连保留最近有效内容、滚动和筛选，已知空态只能由完整新快照证明。

每个应用实例独立装配统计仓储；演示模式、替身、Driver 与生产适配器消费同一公开契约。只读诊断借用已存在的快照，不创建观察需求、打开事件流或补读页面。替换完成后删除旧统计的混合导出、分页呈现接口与平行归并路径，不保留转发别名；其他领域仍在使用的账号额度和会话费用能力不得连带删除。

显式统计取证请求与普通快照采集分开：前者可以临时取得现有仓储的可见需求，观察完整就绪结果，
并在结束时取消本次观察和释放本次需求；底层共享连接的实际收束仍由仓储持有，不能为了结束
单次请求关闭其他页面正在使用的仓储。诊断完整结果以原所有者、实例代次、配对业务修订及
汇总／历史两侧材料引用标识；不把旧单一流编号、交付序号或材料修订冒充另一种水位。
尚未就绪、读取失败和已知空结果分别表达，不保留虚构身份字段作为旧协议占位。
