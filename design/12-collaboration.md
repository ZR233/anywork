# 12 - 智能体预设（Agent Profile）与协作编排

本文是智能体预设（`Agent Profile`）体系、子智能体（`child`）派发、可靠交付（durable delivery）、等待唤醒（`wait`）、审查门禁与原执行者返工契约的唯一权威源；权限与工作区安全边界见 [04](./04-security.md)，通用工具运行时见 [09](./09-tool-runtime.md)，任务模式状态图与阶段流转见 [11](./11-thread-mode.md)。

## 12.1 角色边界与双轴工作区模式

### 统一智能体声明模型

Studio 的普通桌面根智能体（`root`）、外部机器人根智能体、系统内置子智能体（`child`）与用户自定义子智能体共用同一套智能体定义、快照冻结与指令装配模型。每份定义包含稳定身份标识、显示名称、功能描述、适用任务场景、角色系统指令、定义来源、内容修订号以及允许的使用范围（根会话或子会话）：
- **编译期声明与配置边界转换**：内置的普通根智能体、飞书根智能体与系统子智能体源自编译进二进制的统一代码声明表（提示词通过 `include_str!` 嵌入，运行期不读取外部文件，启动前执行唯一性、非空与不变量校验）；用户自定义预设（`Profile`）在配置文件读取边界转换为相同的内部定义结构。
- **角色与工作模式正交**：智能体角色定义“我是谁”，工作模式（`Thread Mode`）定义“按何种流程执行”，两者的指令槽位相互独立。根会话可在空闲时切换工作模式而不丢失其根智能体角色；子智能体仅使用创建时冻结的智能体预设，不挂载根会话的工作模式或工作流状态机。
- **派发可见性隔离**：仅子智能体预设向用户开放 TOML 配置并进入可派发目录（`list_agent_profiles` 与动态生成的 `spawn_agent` 参数模式）；根智能体专属定义不进入子智能体目录或设置页，且拒绝被直接派发。

### 会话级工作区模式与子智能体隔离模式

工作区隔离由**根会话工作区模式（`ThreadWorkspaceMode`）**与**子智能体预设工作区模式（`Profile Workspace Mode`）**两条正交轴共同决定：

1. **根会话工作区模式（`ThreadWorkspaceMode`）**：在根会话创建时确定，之后只读不可变，对外统一暴露单一的规范工作区路径 `workspace_path`（子线程继承所属根会话的该路径与模式）：
   - **`local`（默认）**：直接使用项目的规范根目录。
   - **`worktree`（独立工作树）**：在创建会话时从项目 Git 仓库的当前 `HEAD` 派生出独立的 Git 工作树（checkout）作为该会话的工作区根目录。
2. **子智能体预设工作区模式（`Profile Workspace Mode`）**：定义子智能体相对于所属根会话工作区根（下称“会话根”）的隔离方式，共四种模式：
   - **`unrestricted`（无额外限制）**：子智能体直接使用会话根（若根会话本身为 `worktree` 模式，则子智能体同样严格受限于该会话工作树内）。
   - **`directory`（受限目录写）**：子智能体仍以会话根为工作区根目录，但通过 `writablePaths` 限制内置文件写工具仅能修改指定的相对子目录前缀（外加该线程自身的 `scratch/` 与 `artifacts/` 临时目录许可，见 [04](./04-security.md)）。这属于合作式工具边界而非操作系统沙箱，终端命令、Git 与 MCP 仍需依靠提示词纪律遵守边界。
   - **`worktree`（独立子工作树）**：为该子智能体创建独立的 Git 工作树，路径边界强制设为严格受限（`Confined`），工作树内部全部可写。主执行目录、干净准入与固定基线的升级由 §12.5 的并行协作重构契约定义；当前工作树身份独立修复阶段不宣称该升级已接入，也不自动合并子智能体提交。
   - **`review`（同境只读审查）**：在派发时直接绑定被审查子智能体（`reviewTargetAgentId`）冻结的工作区收据——若被审查者为独立工作树子智能体，则审查智能体同样严格受限于该工作树；若被审查者共享会话根，则审查智能体同样位于会话根。审查智能体不创建、不持有工作树租约，也不继承被审查者的 `writablePaths`；“只审查、不改业务代码”由审查预设提示词保障。

## 12.2 用户预设（Profile）与系统内置预设

用户自定义子智能体预设保存在 Studio 主目录的 `agents/` 子目录下（默认路径为 `~/.anywork/agents/<agent-id>.toml`），仅扫描首层普通 `.toml` 文件，文件名主干（stem）即为稳定的预设 ID（仅允许长度 `1..=64` 的小写 ASCII 字母、数字、`-` 与 `_`，且不得占用系统内置 ID）：

```toml
enabled = true
display_name = "Rust 执行者"
description = "实现和重构 Rust 模块"
when_to_use = "需要实施 Rust 模块或修复测试时"
workspace_mode = "directory"
system_instructions = """
遵循项目规范完成实现，并验证相关测试。
"""

account_id = "deepseek"
model_id = "deepseek-flash"
effort = "high"
```

- **系统内置预设**：主智能体（根智能体）保留内部标识 `planner`（不可作为子智能体派发，亦不在智能体设置页暴露）。系统内置子智能体预设包括探索智能体 `explorer`（`unrestricted`）、审查智能体 `reviewer`（`review`）、目录执行智能体 `executor`（`directory`）与工作树执行智能体 `worktree_executor`（`worktree`）。系统预设的 ID、名称、用途、提示词与工作区模式只读不可改，用户在设置页仅可配置其启用开关与专属模型路由（未配置专属路由时的默认继承规则见 [20.3](./20-config.md#203-根路由与系统-profile)；历史遗留的 `planner` 子会话仅供只读浏览历史，拒绝恢复续跑）。
- **创建期完整冻结与上下文独立**：每个子智能体在创建（`spawn_agent`）时立即冻结预设 ID、系统指令、工作区分配快照以及最终选定的账号、模型、推理强度与派发模式。子智能体始终拥有完全独立的上下文，绝不继承父线程的对话历史、附件、计划（`Plan`）状态机或厂商私有状态；父智能体必须将子智能体所需的背景基线与任务要求完整写入 `spawn_agent.message`。首次派发消息与后续通过 `send_message` 发送的补充指令在子智能体时间线中统一标记为来自“主智能体”（`parentAgent` 通道）：对运行中的子智能体调用 `send_message` 会先请求中断当前轮次、待清理收束后携带新消息继续执行；对空闲子智能体则直接启动新轮次；而 `interrupt_agent` 仅停止当前执行而不自动续跑。

## 12.3 子智能体派生（`spawn_agent`）与动态参数模式

调用 `spawn_agent` 派生子智能体时，必须遵守以下参数与动态模式校验规则：
- **必填任务概要与自包含指令**：必须提供非空且折叠空白后不超过 **80 个 Unicode 字符**的 `taskSummary`（直接作为子会话的初始规范标题保存，后续消息不覆盖该标题）以及完整、自包含的 `message`。根智能体与所有子智能体遵循统一的可见进展契约：在非平凡任务的首次工具调用前、关键发现、阶段切换或阻塞等待时，输出 1–3 句简明进展说明（`commentary`）。
- **按工作区模式严格区分专属参数**：
  - **`writablePaths`**：仅 `directory` 模式预设接受该可选字段（省略表示整个会话工作区可写，传空数组 `[]` 表示业务目录只读但保留本线程 `scratch/` 与 `artifacts/` 临时目录可写；路径必须为工作区内的相对目录前缀，严格拒绝绝对路径、`..` 与不安全符号链接）。其他工作区模式传入该字段直接返回参数错误。
  - **`reviewTargetAgentId`**：仅 `review` 模式预设接受且必填该字段，值必须为当前根智能体直接派生的某个同根会话子智能体 ID，且该被审子智能体的工作区收据与物理工作树仍然有效。宿主直接将被审者的工作区收据冻结为审查智能体的工作区，不发生工作树租约所有权转移。
- **动态 `oneOf` 工具参数模式生成**：模型可见的 `spawn_agent` JSON Schema 从本轮冻结的可用预设快照动态生成为对象联合（`oneOf`），每个分支通过 `profileId` 常量精确绑定一个预设，并严格按该预设的工作区模式与会话派发模式（固定路由或自动选模）暴露合法字段（所有分支均设置 `additionalProperties: false`）。若当前无任何可用的子智能体预设，则本轮不注册 `spawn_agent` 工具。
- **会话树容量上限与立即拒绝**：当达到单棵会话树内的线程数量上限（含正在准备中的预约名额）时，`spawn_agent` 立即拒绝派发且不进入排队等待；错误回执保留当前树上限数值，并明确指引主智能体先调用 `close_agent` 关闭闲置或已完成的子智能体以释放名额，再重新派发。`spawn_agent` 的工具声明同步描述该容量约束，但不在声明文本中硬编码具体上限常数。
- **协作工具批处理边界与全量状态枚举**：只读协作查询（如 `list_agents`、`list_agent_profiles`）允许与普通只读工具同批共存（`Coexist`）；而创建（`spawn_agent`）、发消息（`send_message`）、中断（`interrupt_agent`）与关闭（`close_agent`）子智能体会改变协作状态，必须独占批次（`Solo`）单独调用。`list_agents` 完整列出调用方会话树内的全部子智能体：除已驻留内存与保存在目录中的子智能体外，已预约名额、正处于物理准备／装配或冷激活阶段的子智能体也以显式的 `preparing` 状态列出（仅投影身份标识与父子关系，不虚构模型绑定或运行态），确保列表口径与会话树容量计数严格一致。

## 12.4 任务模式（Task Mode）协作编排契约

### 任务拆解、依赖图与就绪前沿（Ready Frontier）调度

在任务模式（`mode.task`）中，根智能体负责建立任务依赖有向无环图（DAG）、划分文件写入所有权并把控集成验证边界：
- **只读探索并行化**：跨目录代码检索、历史考证与相互独立的事实收集，优先并行派发只读探索智能体（`explorer`）；根智能体负责汇总事实、权衡方案并亲自维护 `design/**` 设计文档。
- **实现模式选择（`directory` vs `worktree`）**：
  - 边界清晰的单点实现、或多个修改文件集合完全互斥的并行子任务，优先派发 `directory` 模式的执行智能体（`executor`），并为每个子智能体指定最窄且互不重叠的 `writablePaths`。
  - 涉及修改共享接口、`Cargo.toml`/`pubspec.yaml`、锁文件、生成文件或高风险 Git 状态的子任务，派发独立工作树执行智能体（`worktree_executor`）。工作树子智能体在创建新文件后必须先用只读工具确认路径与内容无误，再分步独立执行测试、`git add`、`git commit` 与提交复核（严禁使用 `&&`、`;` 或管道将多步拼成单条 `exec` 命令）。
  - 对于改动极小的单文件平凡任务，根智能体可在计划获批后直接完成修改，并交由独立审查智能体完成审查，无需机械拆分多个执行子智能体。
- **就绪前沿（Ready Frontier）动态释放**：在规划阶段及每次收到子智能体交付后，根智能体识别前置依赖已满足、边界清晰且可独立验收的就绪节点并按并发容量派发；每当某个执行子智能体提交本轮终态报告，根智能体立即核对证据、派发对应的局部审查智能体，并在审查与合入完成后立即释放后继依赖节点，无需等待同批次其他无关子智能体全部结束。

### 轮次终态报告、等待唤醒与原执行者返工闭环

- **轮次终态报告与双元身份**：子智能体不挂载 `plan_*` 或 `request_user_input` 工具，遇到需要用户澄清的问题时直接结束当前轮次向根智能体汇报。`finish_turn({message})` 提交完整非空正文并结束当前轮次，自然生成 `final` 回复同样结束本轮（主动结束轮次须遵循下述未交付子智能体等待规则，结束后无需再调用工具或重复汇报）。子智能体轮次到达终态（`TurnState`）后，系统自动从该终态水位的已提交历史投影生成结构化报告（包含子智能体 ID、轮次/输入身份、停止原因、完整可见正文、未完成后台任务及权限审批记录），并以稳定幂等身份写入根线程邮箱。跨子智能体的完成证据统一使用 `(agentId, turnId)` 复合身份判别。
- **子会话停止与主智能体调度**：用户对子智能体的唯一操作是在会话列表中停止其当前执行；子会话页面只读，不提供输入、继续、发送、答题或审批入口。停止只影响该成员当前执行，不停止父或兄弟，不永久关闭，也不清理工作区；停止受理后显示等待主智能体调度，而不是继续按钮。子会话的继续与新指令全部由主智能体经 `send_message` 调度，统一走核心的认领、清理与保存流程，运行时不自行恢复。
- **子任务问题与审批的主会话处理**：子任务的问题与安全审批在主会话呈现，保留原请求身份、版本、类型与子归属，主智能体可解释和协调但不得改写审批参数或代签决定。子会话不挂载计划或用户澄清工具；子问题回答只保存决定并通知主会话，不自动启用子分支执行，普通回答之后的续跑由主智能体显式调度。安全批准只释放仍然存活且参数、工作区与权限代次匹配的那一次确切调用，已停止、已取消或进程重启后的旧批准不得复活调用。
- **未交付子智能体的强制等待规则（`wait`）**：
  1. 当当前任务所依赖的子智能体尚未完成交付（仍处于执行中、排队中或等待终态报告送达），且父智能体当前无其他可独立推进的工作时，父智能体必须调用 `wait` 保持当前轮次在线，严禁仅因暂时无事可做就输出 `final` 回复或调用 `finish_turn`（可先输出简短 `commentary` 说明等待对象，但不得以“稍后继续”等结束语代替等待；若存在可独立推进的工作则先行推进，不重复执行子智能体正在承担的任务）。
  2. `wait` 必须独占单次模型工具调用批次（详见 [14](./14-runtime-host.md) §14.4–14.5）。普通等待超时不代表子智能体已完成、失败或被取消；只要上述等待条件依然成立，父智能体应继续调用 `wait`，既不因正常超时提前结束轮次，也不改用轮询状态查询或发送催促消息代替等待。
  3. 收到任一子智能体终态报告后，父智能体先核对子智能体、输入与轮次身份，随即处理已就绪事项，无需盲目等待整批子智能体全部返回。若报告表明子智能体已停止（正常结束、失败、被中断或达到步数上限）但目标任务尚未完成，父智能体应依据证据处理阻塞、调用 `send_message` 安排续跑或发起必要决策，不得对已停止的子智能体无限空等。
  4. 当需要向用户澄清需求或请求批准计划时，应调用对应的交互工具；当不存在任何仍需等待的子智能体或后台任务、仅等待用户下一条输入时，则正常结束当前轮次并保留工作流阶段，不使用空 `wait` 等待用户输入。用户显式取消与运行时强制停止遵循实际生命周期语义，不受上述提示词等待规则阻塞。
  5. 轮次结束本身不会关闭会话线程、取消跨轮次后台任务或清理工作树；但底层资源可跨轮次存活并不构成父智能体提前结束当前协调轮次的理由。历史对账补齐仅在显式恢复时执行，单纯查询历史不会激活模型。
- **独立同境审查与增量合入**：
  1. 根智能体收到单个执行子智能体的完成报告后，立即携带 `reviewTargetAgentId` 派生拥有全新上下文的审查智能体（`reviewer`），将已批准计划、任务范围、执行者基线提交与差异摘要传入审查消息；审查期间原执行者暂停修改被审范围。
  2. 审查智能体直接在被审执行者的实际工作区内查阅代码并运行必要的验证命令，输出明确的批准结论或带证据的阻塞性问题（finding）。
  3. 局部审查通过且前置依赖满足后：`directory` 子任务的改动已位于当前会话工作区，直接标记完成；`worktree` 子任务由根智能体使用标准 Git 命令串行合入当前会话工作区，合入成功后标记完成并释放后继任务。
- **原执行者优先返工**：根智能体在最终整体验收完成前，保持所有已交付的执行子智能体处于空闲可续跑状态（不提前关闭子智能体或清理其工作树）。一旦局部审查或最终 `reviewing` 阶段发现代码问题，根智能体优先调用 `send_message` 唤醒负责该文件范围的**原执行子智能体**在原上下文与原工作区内修复，修复后再派生新的审查智能体复审；仅当原执行者不可用或原权限范围无法覆盖修复时才重新派生新执行者。所有报告均须附带真实的命令执行与测试验证记录（明确区分“本次实测通过”“复用未变更范围的已有证据”与“受环境阻塞未执行”）。全部验收通过后，根智能体依次调用 `close_agent` 关闭子智能体并清理工作树，最后将工作流转换至 `completed`。

## 12.5 Git 工作树（Worktree）生命周期与故障恢复

### 当前独立阶段：创建、稳定身份与观察

本阶段交付分支无关的工作树身份、detached 创建、类型化诊断与保全迁移。子智能体实际执行绑定、创建准入和最终关闭接口由并行重构负责，后文明确标记为待接入目标；本阶段不扩展旧关闭处置接口，也不提前启用归档清理或承诺其已完成。

本地项目与 SSH 远程项目均支持根会话级工作树（`<repo>/.anywork/worktrees/<root-thread-id>/session`）与子智能体级工作树（`<repo>/.anywork/worktrees/<root-thread-id>/<child-id>`）：
- **创建与路径**：根会话从项目 Git 仓库解析当前基线提交，Git 创建边界消费调用方已经固定的提交，以 detached HEAD 创建 checkout，不自动创建专属分支，也不在底层另行选择默认分支或项目 `HEAD`。Git 自身裁决创建冲突，不复制分支存在性预检。禁用 Git 钩子与凭据辅助程序，Git 操作超时上限 120 秒；Windows 本地 Git 沿用长路径配置。SSH 路径与工作区打开参数统一为 POSIX 绝对路径（见 [22](./22-ssh-remote.md) §22.3）。子智能体的基线准入升级见下文待接入契约。
- **身份与状态分离**：owner、项目及远端目标、所属仓库和受管路径构成稳定归属。当前分支、`HEAD` 和文件修改是可变状态，不属于归属条件；创建或切换分支、重命名、删除原创建分支、提交推进与 detached HEAD 都不改变资源身份。既有工作树就地复用，不自动 checkout、reset 或重建。任何清理操作均不删除 Git 分支，包括旧版生成的专属分支。
- **检查边界**：冷激活或首次绑定、显式恢复检查及物理删除前通过统一边界核验稳定归属，避免同一装配在发布前后重复整套验证。身份验证不扫描文件修改；状态预览、内容保全及下文子工作树创建准入各自按需要读取真实 Git 状态，不将一种检查的策略扩展到无关操作。Git 官方支持的绝对与相对链接表示按其各自基准目录解析，表示变化本身不构成身份冲突；仍须确认注册、所属仓库及管理目录反向关联均指向同一 checkout。真实目录缺失、注册缺失、所属仓库或 owner 不符明确失败，不降级到项目主目录。
- **持久归属与物理边界**：`studio_objects` 保留唯一的版本化资源归属与已有收束状态，不在 Git 元数据内再建一份 owner。已创建但发布失败的现场须保留可恢复归属，未知副作用不冒充完成，也不盲目再次创建。现役物理清理复用 Git 工作树删除能力，不增加自动分支删除、递归文件删除或双重 force 后备；入口授权与物理归属核验不可互相替代。

### 当前归档与独立恢复清理

独立身份修复阶段维持现行归档行为：收束并保存会话树的活动工作后更新目录可见性，不因本阶段升级自动清理工作树或新增永久关闭意图；取消归档不重建工作树、不切换到项目主目录、不隐式恢复执行。界面不能提前承诺尚未接通的资源清理。Recovery 独立安全清理仍核对修订、归属及非活动 owner，保护未提交、未跟踪和 ignored 内容；缺失、身份不一致或未知目标保留诊断与重试，陈旧卡片不授予删除权限。

### 待接入：权威执行绑定、派生与 reviewer

以下为并行协作重构与后续归档整合的目标契约，不能把独立身份修复的测试结果当作其已实现证明：

- **worktree 子智能体准入**：从主智能体权威执行绑定取得实际目录，普通仓库与根工作树遵循同一规则。staged、unstaged 或 untracked 待提交内容均拒绝，Git 正常 ignored 内容不算待提交修改；提示“主智能体工作区存在未提交修改，无法创建工作树子智能体。请先完成 commit，使工作区干净后重试。”无有效 `HEAD` 要求先有初始 commit。通过准入后固定该目录的真实 `HEAD`，不取 Project.path、展示路径或另一分支的 `HEAD`；身份或 `HEAD` 冲突明确失败，不偷偷换基线。不自动 commit、stash、复制脏文件、pull/fetch、清理用户文件或改忽略规则。此准入只适用于独立 worktree；前置拒绝无已发布 child、工作树或分支，后续副作用由既有受管所有者收束。
- **reviewer**：review 模式通过 `reviewTargetAgentId` 直接绑定目标权威实际目录，不按租约有无猜目录。保留目标关系、目标未最终关闭及绑定有效性检查，并持有实际借用使用权；可以审未提交改动，不创建工作树或分支、不取得目标所有权。关闭只停止自身执行并释放借用，不删除目标磁盘资源。
- **bot**：根与 child 共用同一受管根，拒绝 worktree 派发；review 只允许目标真实执行根与该 bot 受管根一致。不向上借外层 Git，不静默更换 Profile。旧不合规记录保留历史、身份和数据，不恢复执行、自动重绑或删除。

### 待接入：最终关闭与归档强制清理

- **产品接口**：`close_agent { target, force?: boolean = false }` 由并行重构统一实现并删除旧处置选择及其兼容别名。先耐久记录最终关闭意图、封闭新执行，与准备、续跑及评价按既有协作所有者排序；随后停止并等待轮次、后台工具和进程，完成历史、统计、终态报告保存并释放执行资源，再查询明确自有工作树绑定。
- **按绑定清理**：无自有绑定不做磁盘删除，包含 directory、unrestricted 与 reviewer。绑定不存在不重建、不猜路径、不扫描补删，注册或其他残留按实际事实报告。存在且身份一致时只通过 Git 删除这一处绑定 checkout 及该操作对应的注册信息；区分执行永久关闭与工作树已删除、不存在、不适用或清理失败，不宣称全部会话磁盘资源已回收。Git 分支、历史、附件及已有评价保留。
- **安全授权**：默认保护未提交/未跟踪修改及未交付提交，child `HEAD` 须被实际主智能体交付 `HEAD` 包含；无法证明的 cherry-pick/squash 保守拒绝，不自研补丁等价。`force=true` 仅放弃该绑定内的内容保全，不绕过归属、Git 锁、实际借用或新准备、进程退出及保存确认。复用既有工作区使用所有者，Git 拒绝保持真实错误，无双 force 解锁、递归删除或未来资源的平行登记表。
- **永久性与重试**：清理失败、取消或应用退出/崩溃不撤销已保存的最终关闭意图；之后仅对原绑定和授权重试工作树清理，不能 send、冷恢复或装配模型继续执行。身份改变保留现场并拒绝。旧 preserved 现场不因升级、浏览或扫描自动删除，未知旧记录不获得新授权。普通应用退出不是最终关闭，保证范围不扩大到机器断电或 OS crash。
- **归档授权**：归档确认明确传递 `force=true`，提示内容损失；收束范围内所有成员及真实借用后，再按绑定清理子工作树和根自有工作树，全部必要步骤成功才发布完整归档成功。local 根不删除项目目录，但其自有子工作树仍在范围内；未提交、未跟踪、ignored 文件及无其他引用的 detached 提交可能丢失，分支与会话资料保留。取消归档不撤销最终关闭或重建 checkout。界面接入契约见 [侧栏](./concepts/project-sidebar.md)。
- **失败闭环门禁**：归档须接续已准入但未发布分配的原创建责任，不能只枚举目录成员。合法私有 owner 即使初始 checkpoint 已耐久、目录发布失败，也必须能够保存、关闭并排空观察；不依赖不存在的公开目录关联，不提前公开 child 来解循环。原子替换后确认失败应在既有 canonical 边界裁决可能已提交的事实，不以旧内存缓存 absence 授权回滚或删除。已发布 checkpoint 缺失仍是故障，不推导为未发布许可。以上取消、清理失败、发布失败与进程重启窗口须在整合后取得真实回归证明。

## 12.6 桌面界面智能体配置中心

设置页中的「智能体（Agents）」页面是唯一的智能体配置中心。系统内置子智能体卡片展示固定工作区模式徽标、启用开关及模型路由选择器；用户自定义子智能体编辑器额外支持在四种工作区模式间选择。所有配置修改均携带 `expectedSettingsRevision` 执行 CAS 更新（详见 [19](./19-studio-ui.md)）。

当根会话接收显式新用户输入时，运行时会对尚未加载进内存的子智能体执行一次只读的检查点与终态历史对账，自动将遗漏的子智能体终态报告补齐至根线程邮箱，无需为此激活子智能体的模型会话；单纯打开历史页面浏览不会触发该对账或恢复执行。

## 12.7 分发模式、模型查询与最终评价

### 会话级派发模式与偏好提示词

根会话在创建时确定子智能体派发模式 `delegationMode`（固定预设路由 `profile` 或主智能体自主选模 `automatic`，默认为 `profile`）与选模偏好 `delegationPreference`（经济 `economy`、平衡 `balanced` 或快速 `fast`，默认为 `balanced`），保存在版本化的 `studio.delegation` 线程扩展中，创建后只读不可变：
- **固定模式（`profile`）**：直接使用子智能体预设所绑定的模型路由，`spawn_agent` 不暴露模型覆盖参数。
- **自动模式（`automatic`）**：已启用的子智能体预设仅提供角色指令与工作区契约（即使其预设固定路由不可用也不会从可派发目录中隐藏）；主智能体在调用 `spawn_agent` 时必须显式传入非空的 `modelSelection { accountId, modelId, effort? }`，创建成功后该路由即被冻结在子智能体快照中，后续续跑沿用该冻结路由。
- **偏好提示词引导**：选模偏好仅通过向主智能体注入对应的一段简短策略提示词实现，不使用硬编码排序器：首先必须满足任务难度、必需能力、上下文窗口与低返修风险要求；在此前提下，**经济偏好**优先选用订阅制（`subscription`）与不计费（`noCharge`）账号，并在同类账号内参考模型单价优先为简单任务选用高性价比模型；**平衡偏好**综合考量能力适配、质量、成本与耗时；**快速偏好**优先缩短端到端交付耗时（综合首字延迟 TTFT、吞吐率 TPS 与返修风险）。

### 候选模型查询工具与上下文预算

自动模式下向主智能体装配两个有界只读查询工具：
- **`list_delegation_models`**：仅返回通过文本类型过滤、已启用且路由可用的合格候选模型，支持按硬性能力、所属账号、计费类别（`billingKind`）及最低有效上下文窗口（`contextWindow`）过滤。默认每页 5 条、最多 10 条，游标绑定查询条件与目录水位；仅投影最多 240 字符的简短简介、能力摘要、价格/计费类别、实测吞吐样本与本地评价摘要。主智能体在进行经济性选模时，应先分别按 `billingKind = noCharge` 与 `subscription` 查询适配候选，避免默认全量分页遮蔽低成本账号。
- **`get_delegation_model`**：按精确的 `(accountId, modelId)` 查询单个模型的详细参考资料（最多 6 项出处来源）、可用性状态及最近 **10 条**本地任务评价记录。

### 子智能体最终任务评价（`evaluate_agent`）

主智能体在直接子智能体完成全部交付、审查与返修后（调用 `close_agent` 之前），调用独占写工具 `evaluate_agent` 对该子智能体的表现提交一次最终评价：
- **前置状态与串行裁决**：评价目标必须处于最新已提交的轮次终态，且无运行中任务、无未消费输入、无待决交互或权限请求；被评模型路由与预设身份由宿主直接从子智能体的冻结快照中提取，不接受调用方传参指定。同一子智能体的评价写入、续跑准入与显式关闭在协作所有者内部严格串行化：已显式关闭封口的子智能体拒绝新评价写入。冷子智能体评价仅以只读方式核对既有规范检查点与历史库，不触发模型激活或数据迁移。
- **评分维度与跨会话聚合**：评价结果取值为通过（`passed`）、失败（`failed`）或未评级（`notRated`）；前两者包含代码/成果质量与指令遵循度两个 `1..=5` 整数分项及非空且不超过 **300 个 Unicode 字符**的验收评语（`notRated` 不带分数且不计入均分）。每个子智能体仅维护一条有效评价记录（首次提交 `expectedRevision = 0`，若后续发生返修则可携带已有修订号绑定新的最终轮次更新原评价）。评价记录按 `(accountId, modelId)` 跨会话聚合，查询时按更新时间与稳定身份返回最近 10 条样本及其统计分布。
