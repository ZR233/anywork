# 01 - 系统总览

## 1.1 定位

Pure-Lang 是自然语言编译器，负责接收自然语言需求，将其编译为可执行的计划、代码生成意图与后续动作建议。
`anywork` 桌面应用的唯一业务核心是 `pl-studio-runtime` 内的 Studio 运行时；Flutter/FRB 桌面端与独立 HTTP 服务端只是挂载在同一运行时之上的两个传输层（transport），共享同一套运行时实例，不维护第二套业务状态。

## 1.2 运行路径

```text
Flutter → pl-studio-bridge ─┐
                           ├→ Studio 运行时 → Thread 工厂 → Thread 装配器
HTTP → pl-studio-server ───┘                                  ↓
                                                     pl-core Thread 所有者
                                                       ↙             ↘
                                               pl-model 会话      pl-tool 实例
```

上图的末端分支表示装配完成后的运行期调用关系；完整的 crate 依赖方向以 [02](./02-crates.md) 为准。

## 1.3 核心概念与事实源

### 领域模型

- **会话线程（`Thread`）**：通用执行所有者，每个线程独占模型会话、工具注册表和工具实例。
- **智能体角色与工作模式**：普通根智能体（`root`）、飞书根智能体与子智能体（`child`）均由 Studio 的智能体定义进入统一指令装配；智能体角色与工作模式（`Mode`）的执行方式正交，接入渠道自身不维护执行循环。智能体定义、路由冻结与派发边界见 [12](./12-collaboration.md)。
- **执行轮次（`Turn`）**：一次由输入驱动的有界执行过程；模型请求尝试（attempt）与工具任务各自维护独立生命周期。
- **上下文条目**：通用上下文条目包含角色、来源、文本、资源引用、不透明内容及工具调用关联。
- **产品层投影**：时间线条目（`Item`）、智能体预设（`Agent Profile`）、工作模式（`Mode`）、工作流（`Workflow`）与计划（`Plan`）均属 Studio 产品概念，由 Studio 从已持久化的核心事实投影生成。
- **交互与权限（`Interaction`）**：底层内核仅记录通用的待决（`pending`）、已决议（`resolved`）与已取消（`cancelled`）状态或权限决定；具体问题与回答正文由上层产品语义解释。

### 运行期并发与状态修改边界

模型推理与工具执行期间，线程所有者仍可受理新消息、读取日志并撤销待执行权限，但这些操作不会篡改当前轮次已冻结的请求输入。

运行时事实支持完整替换与按来源（`source`）原子局部更新（patch）：各独立生产方仅更新自身负责的来源槽位，传入空内容即清除该来源，未提及的来源保持不变。两种更新均在线程所有者的串行边界内执行；当存在待交付的工具调用时，拒绝修改运行时事实。

### 存储与时间线读取

活动线程的内存快照是唯一可写的执行事实源：
- **状态与历史持久化**：当前可恢复状态、最新上下文、累计计量与会话历史在每个线程独立的 SQLite 数据库中原子保存。
- **时间线统一协调**：会话时间线由 `pl-core` 的 `Session` 统一合并内存尾部、当前活动条目、可靠待落盘事实及该线程的 `history.sqlite`，对外提供无状态的键集（keyset）分页、有界尾部订阅和按身份读取的详情接口。
- **诊断与统计分离**：模型与工具诊断写入滚动日志文件，`calls.sqlite` 仅保存有界索引、吞吐速度摘要和累计统计投影。
- **前端按需加载**：桌面只为当前激活且展示的会话声明消息订阅，按需分页加载历史，由当前展示租约持有已访问消息并交给 Flyer 原生列表。GUI、HTTP 与飞书独立订阅同一会话广播；无订阅不组装或发送对外流帧，但执行和可靠保存继续进行。订阅契约见 [07](./07-streaming.md)，实时/历史模式及预算见 [26](./26-timeline-content.md)。历史模型正文直接读取提交时冻结的投影，不调用当前工具或当前配置重新生成。

## 1.4 恢复与关闭

- **冷恢复（Recovery）**：恢复阶段只读取并校验当前检查点（checkpoint），不创建模型连接、工具实例或触发外部副作用。恢复过程将遗留的运行中轮次收束为中断终态（`Interrupted`），保留待处理输入，并清空物理续接状态（continuation）与旧执行器授权；待会话显式激活时再装入当前服务实例。
- **优雅关闭（Shutdown）**：关闭流程先封闭新准入并取消当前执行代次，收束在途结果与待决交互，随后关闭模型会话与工具实例，等待历史写入到达固定水位并保存最终检查点。若关闭失败，则保留线程所有者、未落盘事实与显式重试入口。
- **会话归档（Archive）**：归档操作仅按目录加载冷历史，不为归档重新激活历史会话。若目标会话树已驻留内存，必须先终止其全部活动工作（中断当前轮次、取消运行中任务、丢弃未消费输入），待全部关闭成功后方可执行目录归档；无法正常终止或保存的会话保持显式失败状态。归档保留历史与物理工作区，不以工作树检查成功为前提；取消归档只恢复目录可见性，不重建工作树或隐式恢复执行。工作树的独立安全清理见 [12](./12-collaboration.md#125-git-工作树worktree生命周期与故障恢复)。
载入不等于执行：恢复只发布可读状态。根会话的中断等待用户明确继续，子会话的中断等待主智能体调度；用户对子会话的运行控制只有会话列表中的停止，继续与消息由主智能体负责。根会话的无内容继续是明确的类型化控制意图，带新内容继续复用普通输入；两者都保存继续点、复用现有队列与可靠保存，并在模型请求准入前确认认领已落盘（见 [14](./14-runtime-host.md)、[15](./15-session-storage.md)）。

`anywork` 的数据格式演进由 Studio 在正常业务启动前统一协调迁移，存储契约见 [17](./17-studio-storage.md)，配置与凭据关联迁移见 [20](./20-config.md)，核心状态、历史与调用记录契约见 [15](./15-session-storage.md) 与 [16](./16-core-contracts.md)。

## 1.5 工具目录的条件发布

MCP、LSP 等外部扩展异步准备工具目录时，可携带冻结快照对应的扩展水位进行条件发布：线程所有者在同一邮箱（mailbox）串行操作内校验水位，通过后原子替换完整工具目录；若水位已过期，候选目录保持未安装状态并交由移交方异步关闭，拒绝操作不会改动当前生效目录或权限状态。

线程独占装配阶段使用无条件注册；若旧工具实例关闭失败，保留类型化拒绝原因、清理来源与原实例句柄，供后续显式重试。工具身份、注册生命周期与并发批处理契约见 [09](./09-tool-runtime.md)。
