# 29 - 命令行宿主与 Harbor 接入

## 29.1 范围与所有权

`anywk` 是 Studio 的非交互式命令行宿主，使用生产 `Cli` 身份、原生配置、项目、会话、模型路由、任务状态及关闭流程。它不持有第二套智能体循环或完成判断。运行锁元数据中的宿主为 `cli`；同一 Studio home 的实例互斥仍由原生运行锁负责。

当前支持 `--help`、`--version`、Native `exec`、ACP `exec-acp` 与 `acp-options`；版本来自产品版本，与 Rust 工作区包版本分开。帮助和版本查询在初始化运行时前完成。执行命令只执行单任务并按终态退出；Native `exec` 传入 `--output-dir` 时启用面向外部分析的原子运行归档导出，未传时保持标准输出与退出行为完全不变。执行命令的标准输出只写最终助手文本，不能将其视为完整评测数据；`acp-options` 只输出对端实际声明的会话配置。Harbor 通过本地可选 Python 包与外层取消控制接入。没有交互终端界面、SSH 工作区、恢复执行或 ACP 服务端。

本地工具沿用原生执行器，不要求预装远端 SSH 辅助程序。远端辅助程序与宿主 MCP 的资源来源保持显式外部来源；命令行本身不启动 HTTP 监听器或调用后台更新入口。基准配置通过已有能力配置关闭不参与评测的 MCP、在线模型发现与自学习，不增加另一套子系统开关；隔离数据根不得放入已启用的机器人配置。

## 29.2 命令与输入

```sh
anywk exec \
  --studio-home /runs/profile \
  --cwd /workspace/task \
  --account benchmark \
  --model vendor/model \
  --reasoning-effort high \
  --mode mode.auto \
  --prompt-file /runs/prompt.txt \
  --max-model-steps 100 \
  --no-default-user-skills \
  --skill-dir /opt/evaluation/skills \
  --output-dir /runs/export
```

`--studio-home`、`--cwd`、`--account`、`--model` 与 `--prompt-file` 必须显式提供。`--output-dir` 为可选开关：省略时不创建任何导出目录或临时文件；传入时要求目标尚不存在或为已存在的空可写非符号链接目录，并在初始化运行时及获取运行锁前完成只读预检，失败以 `2` 退出且不改动既有文件。数据根必须已有原生 `config.toml`；任务目录必须存在且可访问，允许普通非 Git 目录，不自动初始化 Git 或创建工作树。模型 ID 原样交付，不按斜杠拆分。推理强度通过所选模型的现有路由能力校验，不设全局枚举，也不静默替换。工作模式默认 `mode.auto`，未知模式明确失败。

所有参数路径以进程启动目录为基准一次性转为绝对路径，词法消去 `.`、`..`，不改变全局工作目录或用户主目录。技能目录复用既有 `~` 展开规则；词法归一化不跟随链接，也不代替既有链接、重解析点及目录越界检查。运行时后续取得任务目录的原生物理身份，不重新解释其他参数。

任务文件必须为有效 UTF-8 且不能仅含空白；`--prompt-file -` 从标准输入读取到结束。正文不作为命令参数。`--max-model-steps` 为正整数，仅收紧根输入的现有预算；省略时沿用配置，不改变会话默认值或声明整棵任务树的总预算。子智能体分发方式与偏好继续继承配置。

### ACP 命令

`acp-options --studio-home <路径> --cwd <路径> --account <ACP账号ID>` 打开真实会话，读取服务端声明的配置与能力，然后清洁关闭；不发送 prompt、不登录，也不承诺模型可调用或额度充足。`exec-acp` 使用同样的三个显式参数，另要求 `--prompt-file`，支持重复的 `--config <配置ID=值ID>`、`--no-default-user-skills` 与 `--skill-dir`。配置ID和值均来自对端，不把显示名、Native模型路由或推理强度转换成ACP参数；不存在或不接受的选项明确失败，不静默换模。配置成功后核对当前配置再提交任务。

ACP账号仍从所选Studio home的正式用户定义加载，官方程序自行使用现有登录态；不导入凭据或修改账号默认配置。非打包执行沿原 `HostMcpSource::External` 要求 PATH 中存在与源码匹配的 `pl-studio-mcp`，不新增猜测路径或传输回退。`exec-acp` 不提供 Native 的步数预算、工作模式或 v2 Native 运行导出，不伪造ACP未报告的轮次、用量或持久化数据。

ACP执行使用原业务会话的打开、配置、prompt、更新观察、取消和关闭端口；终态关联实际 `AcpRunId`，最终文本来自该次原始助手内容更新。业务会话按 [ACP Host MCP 契约](./28-acp.md#2812-host-mcp-与宿主指令) 筛选并即时答复符合条件的权限请求。CLI 收到待用户确认的权限事件时，拒绝该请求并以退出码 `3` 结束。观察缺口、断连、失败和非正常停止明确失败。SIGINT/SIGTERM与初始化及关闭仍沿同一信号锁存和关闭预算，只有实际清洁关闭且排空后才写成功输出。ACP错误诊断保留类型及服务端原始消息，不以通用成功或空文本替代。

## 29.3 严格启动与凭据

宿主启动策略分为 `InteractiveRecovery` 与 `Strict`，不写入磁盘配置。桌面和 HTTP 宿主保持既有恢复行为；命令行固定严格启动。

严格启动要求配置在权威加载器内真实存在且可读。加载器在凭据恢复及配置迁移接续之前检查主配置，迁移之后重新读取；文件在输入预检后消失也不能转为默认值。未知版本、语法错误、无效引用、迁移失败和凭据恢复失败均保留原件并拒绝启动。可完成的具名配置迁移沿用原有保全机制；需要旧系统凭据复制或内联密钥导入时明确拒绝，不用进程内存冒充耐久迁移。

严格启动只读识别未完成的启动恢复记录，并报告 `recoveryRequired`，不接续原恢复、不移动现场、不创建启动备份或重置为默认配置。启动失败仍等待已打开的数据库、资源与锁清理完成。

命令行配置存储使用独立的进程内凭据能力，原生账号仅通过 `bearer_token_env` 引用当前进程环境中的非空值，不读取、写入或迁移系统凭据库。环境变量名保持引用，不写回密钥值或导出环境全集。需要 ChatGPT/OAuth、系统凭据或交互登录的账号与依赖角色明确失败。凭据必需性继续采用原生协议规则：OpenAI-compatible 可以无凭据，其余需认证协议缺少非空环境凭据时失败，不根据 localhost 猜测免认证资格。

## 29.4 任务完成与关闭

命令行先完成输入预检，再初始化运行时、打开项目，以固定非空标题和完整原生模型路由新建本地会话。受理回执保留真实线程 ID、输入 ID 和提交游标；受理成功不代表任务完成。

终态观察使用 History 的 canonical 输入/Turn 事件，按同一输入 ID 与固定 cut 匹配；Current 独立报告真实待交互状态，非交互宿主据此报告阻塞，不要求此时已有历史终态，也不补造终态。两域没有共同 ACK 或轮询器。正常完成后沿该轮最终助手事件的 `HistoryEventBodyRef` 分段读取长文本。任务先完成、随后才订阅时，从固定 History cut 读取 canonical 事实；Current 已经离开活动窗口不使历史丢失。请求用户交互或计划审批时不自动回答或批准；失败、预算和取消保留真实终态。

无论正常、失败或取消，都进入同一原生退出关闭流程，清理预算为 30,000 毫秒。成功必须同时确认 `Clean` 与 `Drained`；尚未安装运行时只允许报告 `NotStarted` 并保留原启动错误。

SIGINT/SIGTERM 锁存第一个信号；重复信号不启动第二个关闭所有者。初始化尚未返回时，命令行继续等待已有启动所有者完成，取得运行时后跳过任务受理并关闭，不丢弃初始化异步操作或截断其清理。原生平台支持范围内的信号由 Tokio 接收；Windows 使用原生 Ctrl+C。强制结束进程无法保证最终输出。

标准输出仅写最终助手文本，且在关闭完成后写入；运行诊断和追踪写入标准错误。退出码固定如下：

| 结果 | 退出码 |
| --- | ---: |
| 根任务正常完成且清洁关闭 | 0 |
| 参数、配置、凭据或路由无效 | 2 |
| 等待用户输入或审批 | 3 |
| 模型步数预算耗尽 | 4 |
| 模型、工具或任务运行失败 | 10 |
| 启动环境或内部错误 | 11 |
| 导出失败（指定 `--output-dir` 时写出、校验或封口失败） | 12 |
| 关闭失败或持久化未排空 | 13 |
| 其他原生取消 | 14 |
| SIGINT | 130 |
| SIGTERM | 143 |

错误叠加时优先级为关闭失败 13、导出失败 12、原任务或启动结果。原终态和信号仍保留，不能用成功覆盖取消。帮助和版本使用 clap 的成功退出，参数解析错误退出 2。

## 29.5 技能来源与权限

运行级 `SkillSearchOptions` 与磁盘 `[skills]` 分开，默认保留用户来源且不追加目录。来源优先级、冻结发现与写入边界统一见 [项目级技能](./10-skills.md#102-目录层级与同名覆盖优先级)。

`--no-default-user-skills` 仅取消隐式用户来源；关闭时不解析用户主目录，所以缺少 HOME 的容器不会因该来源失败。系统、项目、配置外部目录和显式追加目录仍按既有能力门控生效；显式 `~/...` 仍需可用的用户主目录。

`--skill-dir` 直接指定一个只读技能集合根，不自动附加 `.agents/skills`；追加在配置外部目录之后，按出现顺序保留。词法归一化后重复的命令目录只保留第一次；显式重新加入被关闭的默认用户路径时，它以 External 身份生效。显式目录必须存在、为可读目录且符合既有路径安全约束；每次发现重新核对，目录失效不能转为默认来源或完整空集合。

来源策略由运行时唯一技能目录所有者持有，进入提供方身份、授权身份与目录指纹。刷新可产生新快照，已冻结调用不扩大来源；根与子智能体共用运行级策略，Project 来源始终来自各自实际工作区。追加目录不增加工作区可写路径、命令权限或审批授权；技能管理仍只写已授权的项目技能目录。

## 29.6 运行轨迹、用量与关闭结果导出

指定 `--output-dir` 后，命令行宿主将运行事实写入独立的 V3 归档目录。`run.json`、`events.jsonl` 与 `result.json` 均声明 schema 3；运行标识为标准 UUID，内容寻址摘要使用 SHA-256。

工具原件导出沿用 [09](./09-tool-runtime.md#91-工具身份所有权与历史落盘栅栏) 的作者数据、模型内容与框架真实终态，历史中的实际交付不由当前渲染器重建。运行归档不是完整的线上请求抓包。需要核对生产请求正文时，使用 [06](./06-model.md) 的 `ANYWORK_WIRE_CAPTURE_DIR` 捕获入口并关联对应推理及供应商响应；捕获文件不包含认证头，其格式化文件长度也不是发送正文长度。提交前捕获的正文不能单独证明请求已经到达供应商。

- `run.json` 在运行时初始化及获取运行锁前原子写入，之后保持不变。它记录构建身份、解析后的调用参数、技能搜索策略，以及初始配置、角色和模式文件的逻辑名称与 SHA-256。可选的 `redactedSummary` 保持 `null`：配置允许命令参数、网址及扩展字段，按键名删除敏感项不足以保证凭据保密，因此不复制配置正文、凭据存储或环境变量值。
- `events.jsonl` 由单个写入任务按连续 `eventSeq` 追加。它覆盖运行开始、成员登记、冻结技能来源、调用账单、History 原件、执行生命周期、线程封口与运行封口。`source` 保留可用的 History event/seq、effect、Turn、attempt、tool call 与 Current owner/revision；文件次序不代替跨线程因果关系，未知值继续为空。
- `Completion` 事实由 `HistoryEventHeader`、`HistoryEntityHead`、canonical payload blob 和 Contents manifest 组成。HistoryReader 按固定 cut 以最多 128 个 canonical events 一页流式枚举；payload、metadata 与正文按最多 64 KiB 范围复制。Contents manifest 是独立的 NDJSON 正文目录内容，不内联到小头，也不把整组或整次运行的正文累计进内存。
- `contents/<sha256>.bin` 保存本次实际读出的原始载荷和正文；原生工具已截断的事实继续保留。重复内容核对长度与哈希，冲突或符号链接越界明确失败。History 事件逐页处理，不在内存中累计整次运行的原件或所有原始账单。
- `result.json` 在原生关闭返回后原子写入，是唯一最终完成标记。它保留执行终态、最终退出码、最终助手文本、独立的轨迹／用量／费用完整性、事件文件哈希、原生关闭报告和原始执行错误。缺少封口或最终标记的产物不能被判为完整；消费端的坏行、缺失内容及哈希验证由 Harbor 适配器验证。

导出器在新根线程及其所有子线程开始写入前登记成员，并为每个成员保留 HistoryReader cut。子线程提前关闭不会移除其成员资格或重建 History reader。最终补齐从同一固定 cut 读取所有仍是 canonical original 的事件，包括被界面隐藏的执行记录；导出任务真正停止后释放所有读取句柄，再关闭原存储。

入口采用有界背压，最多容纳 256 批次、16 MiB 冻结元数据；计量包括账单、成员身份与技能发现元数据的实际大小。正常拥塞计入真实任务墙钟时间，准入后即继续原有可靠交接，不等待写盘确认。永久写入错误、身份冲突或关闭期限到期均拒绝后续准入并唤醒等待者，取消本次执行，同时继续原有持久化与关闭义务。文件读写使用异步文件接口；关闭期限到期时取消并等待导出任务，不遗留继续读取存储或追加封口的后台任务。

关闭顺序为生产者停止确认、原持久化排空、导出补齐／对账／排空／刷盘、原存储关闭、命令行写结果；各阶段共用原有绝对清理期限。导出失败独立记录，不使原本可以安全完成的存储关闭失败。耗时中 `exportFinalizeMs` 是关闭区间的子区间，不能再次加到关闭耗时上。

账单按冻结调用身份去重，每个效果水位必须连续，包括无账单的效果；增量复用原生用量归并器，最终与每个线程自己的权威摘要逐字段对账。按冻结账号和模型分组，不重复累计父线程收到的子报告。未知值为 `null`，有效贡献的小计单列为 `knownTotals`；明确零值保持零，`NoCharge` 的费用为已知零，未定价、禁用和非 USD 费用保持未知。词元溢出不否定独立已知的费用，内容导出失败也不抹除已完整对账的用量证据。

轨迹完整而供应商缺少用量或定价时，正常任务仍可退出 `0`。多原因叠加时遵循 `shutdownFailed (13) > exportFailed (12) > 原任务或信号终态`，原始错误与执行结果均保留。强制终止不保证最终产物；不能将模拟供应商、单平台或文件结构检查外推为真实模型和跨平台验收。

当前导出格式为 V3/schema 3；run.json、events.jsonl 与 result.json 使用同一版本声明。原件头不再携带旧 Display V2 的展示字段，只保存真实 History 身份、event seq、typed head、来源和正文引用；旧 V2 消费方必须迁移，运行期不保留旧格式分支。

`ExecutionLifecycle` 与 canonical 原件消费同一个可靠 PreparedEffect 的 History 变化；没有正文的开始、真实恢复中断及前台移交仍可区分，未知时间、位置或引用保持 null。`PreparedEffect` 的 `retained_resources` 只记录本 effect 中真实 delivery／repair 的资源引用，并允许 `turn_id` 缺失，不复制 `latestTask`。只有明确启用导出时才把这些事实写入归档，不新增数据库事件表或 token 日志。事件准入、幂等指纹与队列预算同时涵盖账单、生命周期和正文交接。

## 29.7 Harbor 消费边界

整体目标是通过 Harbor 运行生产智能体，获得可复现的任务结果、耗时、调用用量与费用。运行时拥有执行和原始事实，导出器拥有版本化归档，Harbor 适配器拥有产物校验、ATIF 转换与评测错误分类；适配器不重新执行模型循环，也不以界面摘要、标准输出或滚动调用日志补造完整轨迹。适配器位于 `integrations/harbor`，继承官方 `BaseInstalledAgent`；导出成功本身不代表验证器奖励通过。

转换必须同时读取原生条目类型、来源和内容角色。根用户输入使用 `input`；父智能体发给子智能体的初始任务则是来源为 `inboxMessage`、通道为 `parentAgent` 的 `text`，其正文同样属于子轨迹的输入，不能误当成子模型输出。子轨迹通过登记事件的 `parentAgentId`、`parentThreadId`、`spawnToolCallId` 关联直接父轨迹中的真实工具调用，不能解析不透明标识或按事件文件邻接次序推断关系。

一个模型调用可产生多条文本、公开推理摘要和工具记录，调用计量仅按 `(threadId, inferenceId)` 附加一次。模型身份保留配置、发送、报告三个原始字段，不由根模型覆盖子调用。工具记录的 `attemptId` 可以为空；程序化工具内部的嵌套调用也不是额外模型推理。关联应依据同线程原生来源、效果位置和生命周期，未知关联继续保留未知，不能以字符串拆分补造调用身份。线程自己的用量只累计一次，父工具结果携带的子报告不再次计费。

模型账单中的编排计数只包含响应与传输已有的观测，不携带后续工具并发数、执行耗时、缓存收益或未采集的词元估算。V3 schema 中这组旧字段原本就是可选字段，新的归档不再写出它们；已有归档原样保留。分析工具并发应核对生命周期和真实任务结果，不能将字段缺失或旧归档中的默认零解读为没有并发。

适配器必须在 `run()` 返回前校验本次全新目录的版本、运行标识、真实退出码、原生关闭报告、事件连续性与哈希、成员与来源关系、内容长度与哈希、最终封口，并使用固定 Harbor 版本的官方类型及验证器验证 ATIF。`usageComplete` 或 `costComplete` 为假本身不使正常任务失败：未知值保持 `null`，已知小计不冒充总量。Harbor `ModelUsage` 的词元字段默认值为零，因此不完整模型组只保留原生已知事实，并显式填充 `model_usage` 字典（包括空字典），避免自动回填把未知值变成零。具体接入与取消契约见 [Harbor 实施议题](https://github.com/ZR233/anywork/issues/424)，官方类型基线见该议题固定的 [ATIF 类型](https://github.com/harbor-framework/harbor/tree/06d0e86a8cfbac213548e0caec533afc5d81ff31/src/harbor/models/trajectories)及 [AgentContext](https://github.com/harbor-framework/harbor/blob/06d0e86a8cfbac213548e0caec533afc5d81ff31/src/harbor/models/agent/context.py)。


## 29.8 本地评测与桌面分发

Harbor 固定提交为 `06d0e86a8cfbac213548e0caec533afc5d81ff31`，依赖锁定在 `integrations/harbor/uv.lock`。Harbor 只安装在本地 Linux 宿主；项目 Docker 镜像和持续集成不安装、不执行 Harbor。任务使用 Harbor 官方 Docker 环境，安装单一 CLI 二进制与显式原生配置，不复制用户 home。正常、失败、外层取消分别保留原生结果、类型化错误及有界进程回收证据。

正式原生 `build-gui` 将相同产品版本的 CLI 放入 `bin/anywk`（Windows 为 `bin/anywk.exe`，macOS 为应用内 `Contents/Resources/bin/anywk`），旁置版本、构建提交/环境、目标架构、SHA-256 和导出格式声明。打包与校验拒绝缺失或被篡改的 CLI。不新增独立发布资产。Linux Debian 包维护 `/usr/bin/anywk`；Windows 用户安装器默认提供添加 PATH 的可选任务，保留其他 PATH 内容，卸载只删除由其添加的目录；macOS 压缩包由用户显式配置终端路径。

`anywk-bench prepare/run` 与 `anywk-bench-summary` 负责冻结输入、单 trial 顺序投放、检查点与全量统计。A/B 固定模型比较执行框架，C/D 比较同候选配置的自动策略及开发集历史。种子持原生排他锁复制当前 `data/`，检查格式、清理与来源；不复制配置/凭据，禁止测试集反哺。费用未知、清理失败或产物失效停止后续投放；已完成尝试不覆盖，中断不自动重跑。

报告区分计划、已调度、有效和无效样本；有效奖励均值与全投放成功交付率使用不同分母。保留全部失败费用和未知值，单列模型/用途与阶段耗时；任务级配对 bootstrap 固定 10,000 次和 seed=20261113。开发子集不得冒充官方完整成绩，无付费合成验收不得作为模型性能结论。具体安装、smoke/dev/full、历史与报告命令见[本地 Harbor 指南](../integrations/harbor/README.md)。
