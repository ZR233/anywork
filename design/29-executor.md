# 统一执行器

`pl-remote-helper` 提供 `Executor / Command / Child`、目标路径、流式文件和通用 HTTP 接口。执行器表示一台执行机器或一条具体连接，不持有工作区、Thread、授权或项目配置。工作区适配负责绑定根目录，产品层持有并关闭执行器。不得用可变的全局当前目录或环境服务并发请求。

## 29.1 身份与生命周期

本地执行器冻结创建时的目录、环境和平台事实。远端执行器在已有认证传输上完成一次 Hello，核对精确 wire 版本，取得目标平台、主目录、初始目录和 shell；不读取桌面环境作为远端环境。路径绑定具体 `ExecutorId`，不能混用于另一个执行器。

`--stdio` 是新前台入口，一条 h2 连接承载多个并发程序。所有句柄绑定这一连接，关闭后永久失效；新建连接不会恢复旧句柄。`close()` 取消准入与受管工作，最多等待两秒，超时明确报告清理未确认。库保留任务所有者，不以丢弃任务句柄代替终止阻塞操作。前台二进制在自身清理超时后使用有界 runtime 退出；这不能证明自行脱离的后代都已退出。

当前产品迁移边界：本地与远端的普通 exec、MCP、LSP、Git／工作树命令及本地 ACP 已使用公共执行器。SSH 管理器已删除接续、心跳和自动重连；远端文件使用目标文件接口。工作区文件策略、补丁工具、技能来源与历史归档的统一适配仍在议题 #397 的同一分支迁移。最终契约须回写原领域文档并删除这份迁移说明，不能凭单个阶段通过验收宣称全项完成。

## 29.2 进程与输出

`Command` 传递结构化程序和参数，不插入 shell。模型提供的 shell 文本由产品层按执行侧 shell 构造参数。spawn 的标准流默认关闭；`output()` 并发收集双输出并等待根退出，保留原始字节。`status()` 拒绝管道和捕获配置，避免不能访问输出却被背压阻塞。内存收集失败保留已观察的退出、部分输出和捕获事实。

`Child` 是受管对象：Drop 请求终止，异步回收归已登记 owner。wait 只等根进程，先关闭仍持有的标准输入；已 take 的输入由调用方控制。取消 wait future 不取消进程，再次 wait 得到相同终态。输出 EOF 与根退出分别观察；根已退出时的 kill 不再触碰 PID。Windows Job 的生命周期延续到管道 owner 结束。产品命令任务分别保存根退出、双路预览结束和捕获完成；期限或取消可结束根退出后的排空，保留已有根退出事实并报告输出不完整。捕获失败不建立重构输出或再次执行命令的义务；桌面历史只重试保存已确认的原始前缀。

捕获在执行侧进行，双输出共用原始字节预算。`finish_capture()` 不替调用方排空输出。完整 EOF 且恰好达到额度仍为 Complete；超过额度、写入错误、reader 丢弃或断线分别结算，不能因为根已退出或传输 pump 收到 EOF 就提前把未消费捕获判为完整。

远端 spawn 用主流交付启动确认与根退出，三路管道各自占独立原始字节流，kill 使用控制流。普通准入为 240，控制保留 16；每流窗口 64 KiB，连接窗口 32 MiB。准入随真实 reader、writer、pump 和流控引用持有，传输 EOS 不能提前释放未读 reader 的额度。公开 AsyncRead 实际交付字节后才归还已 poll 的流控额度。

## 29.3 文件

文件接口不实现权限、工作区 confinement 或恢复协议；调用方负责授权和执行侧路径预检。目标 OS 解析路径，不在桌面词法折叠链接后的 `..`。

read 和 read_dir 增量返回。目录名称以结构化记录表示，支持换行等 UTF-8 名称；非 UTF-8 名称明确失败。单执行器复制在目标端一次执行，递归复制拒绝源符号链接；跨执行器由调用方把 reader 泵到 writer。

write 使用一次有界描述和原始字节。`flush` 不发布，`poll_shutdown` 返回 Unsupported；必须 `finish()` 才能正常结束请求、校验长度、flush 并发布。ReplaceAtomic 与 CreateNew 在同目录临时文件写完后分别原子替换或 no-clobber 发布；取消或不完整传输保留原目标。Append 可能留下已写前缀。缺少父目录不隐式创建。

ReplaceAtomic 替换最终目录项，包括符号链接本身；父目录链接由 OS 跟随。已有普通文件保留权限，新文件沿创建策略；不承诺保留所有 owner、ACL、扩展属性或断电持久性。响应丢失可能发生在实际发布之后，只报告未知，不重试或回滚。

patch 由目标端调用唯一 `pl-patch` 算法，保留有序变更及失败前已应用事实。16 MiB 请求限制与 1 MiB 报告限制分别预检，报告预留有限诊断空间。先 Add 再 Update 按原顺序执行，不作跨文件事务；最终符号链接写入明确拒绝。

## 29.4 HTTP

HTTP 在选定执行侧通过 reqwest 发起，DNS、代理、TLS 和 token 环境均在该侧生效。状态码与多值原始头交给协议消费者，过滤逐跳头；显式 Authorization 优先于环境补全。Host 默认只跟随同源 307/308，远端默认不重定向，可通过小型策略枚举显式选择。

HTTP 与文件共用起始描述和字节适配。合法提前响应不要求先消费完整上传。请求 reader 没有整条流的 reset 权；exchange owner 在放弃上传时禁止新读、取消并等待输入 pump、丢弃接收端并归还已 poll 的剩余 credit，同时保留响应直到完整 EOS。客户端并发上传和接收，响应 EOS 停止上传源；NO_ERROR 半向收束不覆盖完整响应。用户取消或响应 reader 提前丢弃才取消本次 exchange，不关闭共享连接。

## 29.5 当前证明范围

公共接口通过真实本地进程和同进程 h2 连接覆盖参数、并发环境、输入 EOF、根退出与管道分离、取消等待、双流捕获、未读流背压、准入归还、原子文件发布、结构化目录、目标端补丁及 HTTP 提前响应。产品 LSP 回归使用真实协议 fixture，真实供应商及真实 SSH 的证据由本次 PR 单独记录；这些证据不能外推为所有消费者和所有宿主平台已经迁移。
