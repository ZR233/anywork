# 29 - 会话公开输出与前端受众

本文是 Studio 公开会话产物、前端受众及公开内容投影的权威契约。Timeline 的页、尾部与
详情归 [26](./26-timeline-content.md)，资源持久化归 [17](./17-studio-storage.md)，飞书
协议、呈现限额及投递操作归 [27](./27-bots.md)。本契约是目标设计，具体交付能力须以实现
和对应验收为准；不能把文档存在当作已有平台送达证据。

## 29.1 所有权与事实源

core 拥有产品无关的 Thread、Session、工具结果和生命周期；不依赖 Studio DTO、外部
平台或受众授权。Studio 将同一 canonical effect 投影到既有 Timeline/history，并拥有
公开内容分类、公开产物和资源读取授权。GUI 与原生渠道适配器消费同一产品事实，不经
HTTP 回环，也不复制另一份完整会话历史、产物目录或模型执行循环。

前端是会话的输入输出渠道，不是模型工具目录的别名。模型正常公开输出由宿主呈现；
主动跨聊天发送仍是独立外部写意图，不成为正常回复的 transport。具体平台适配复用既有
连接、发送服务、资源库与受管任务，不建立消息 broker 或预留泛化插件框架。

## 29.2 公开内容投影

外部前端只消费经当前受众授权的公开事实：

| 事实 | 外部前端含义 |
| --- | --- |
| assistant Commentary / Final | 正常公开过程文本和答复，保留来源 channel |
| public artifact | 当前会话明确交付的可靠文件或媒体原件 |
| typed Turn / Interaction 状态 | 安全的执行、等待、失败、取消或完成摘要 |
| Thinking、指令、raw tool output、命令日志 | 不属于自动外发内容 |
| User、ParentAgent、子 Thread 内容 | 不因存在于时间线而自动广播 |

内容分类依据受信来源和类型，不从正文关键词、路径、工具名字或任意 `output_artifacts`
推断外发意图。平台看不到系统材料不意味着可以保证模型公开正文绝不会误写敏感信息；
当前公开受众须对 GUI 用户可见，渠道 Agent 指令须明确 Commentary 也可能被外部受众看到。

每个公开文本项沿用 canonical item identity、order、revision 和生命周期；Turn 是关联
组，不是把全部过程与结论拼成一个无界字符串的理由。内容修订可 Append、Replace 或
Remove，不能以已终态或文本缩短拒绝合法权威修订；退出观察缓存不表示业务删除。
宿主状态与模型正文分区，模型文本不能改变执行、交互、授权或送达状态。敏感交互材料不
因状态提醒自动公开，也不从“等待已展示”推导用户批准。

渠道可对呈现施加有提示的显示预算，但不得修改 canonical 正文、模型上下文或 GUI 全文。
内容完整性 `Full` / `Truncated` 与平台操作结果是独立事实；未能补齐来源不能伪装成有意
截断。具体平台的显示上限和提示语义只在该平台设计中定义。

## 29.3 显式产物发布

`publish_artifact` 表示把一个原件交付给本会话受众，不表示向某个机器人发送消息。
参数不接受 bot、chat、任意 Thread 或授权身份。输入使用 typed source：

| source.kind | 来源字段与证明 |
| --- | --- |
| `workspaceFile` | `path`：当前实际执行工作区内经文件后端校验的普通文件 |
| `threadResource` | `resourceId`：能够证明由当前 Thread 持久事实引用的可靠资源 |

可选 `displayName` 只覆盖展示文件名，不改变物理读取路径或资源身份；名称不是路径，
不得借路径分隔符或控制字符形成另一个文件定位。媒体类型、长度和摘要来自真实原件，
未知媒体类型按普通文件保留，不以展示扩展名改写字节。一次发布处理一份原件，沿用
[17](./17-studio-storage.md) 的单文件及资源准入预算；零字节原件合法。

workspaceFile 通过当前本地/SSH 物理绑定读取；不得用控制端路径代替远端工作区，也不
放宽 confined、readonly、writablePaths 或符号链接边界。threadResource 必须在当前
Thread 的持久引用中证明归属，不能凭内容摘要、资源 ID 前缀或可观察另一 Thread 取得权限。
文件读取、目录代次与执行身份的生命周期沿用 [09](./09-tool-runtime.md) 与
[22](./22-ssh-remote.md)，不另写文件传输后备路径。

工具输出通过 producer-owned 版本化回执表达已归档原件与发布意图。Studio 只从受信
注册的发布调用、成功提交的结果和合法资源证明产生 typed public-artifact 内容项；
任意工具输出伪造相同格式、模型写出资源 ID 或正文包含文件路径都不能产生该事实。
这属于产品投影，不为此让 core 解码业务 JSON 或增加平台专属控制值。

公开产物项在既有 ThreadItem 信封内保存稳定 publication identity、来源调用关联、可靠
resource reference、displayName、mediaType、byteLen 与 digest。Thread/Turn、顺序和
revision 沿用同一信封；不保存源工作区绝对路径、SSH 地址或外部收件人。
同一次调用/发布身份对应同一原件与名称，内容冲突拒绝；同一字节可复用内容寻址对象，
但内容相同不等于用户重复发布是同一个意图。

不扫描 `artifacts/`，不从 Markdown 链接或路径自动上传，不将输入附件重新发布，不把
生成图片、查看图片或任意工具归档自动改成外部交付。已归档生成产物可通过同一显式
threadResource 发布，无须重新生成字节。子 Thread 发布只属于其自身会话；父会话必须
通过受控交接或自己可读取的工作区形成父会话发布，不能借共享 checkout 转移资源归属。

## 29.4 发布、保存与送达

以下事实不可合并：

1. 原件已可靠归档。
2. 工具的发布意图已随 canonical 结果提交。
3. 对应 history revision 已获保存确认。
4. 一个具体外部前端已接受文件消息。

工具回执不承诺第 4 项；持久化未确认时 GUI 可以显示待保存，外部文件正式投递须等待
第 3 项。工具不能阻塞等待自己尚未返回的结果进入 history。只归档但调用失败/取消、
未形成合法发布事实的材料不自动交付；已提交事实不因后续模型失败或关闭被抹去。

GUI 的 typed 产物项提供文件身份、名称、大小和受控打开/保存能力。读取先验证当前
Thread 的已提交产物及资源引用，再校验长度/摘要；不得回读已变化的源路径补失踪原件。
冷读取不激活模型或重新执行发布工具。HTTP、FRB、Dart model 与 GUI 使用同一 typed
契约，不添加 raw JSON 兼容入口。

产物原件永不为平台限制而截断、改名绕限或自动转码。平台不接受空文件、大小或媒体
类型时，本地产物仍有效，渠道明确拒绝/未交付。资源保留由既有 history 与发送操作引用
证明，未终结投递引用不能被清扫；清理失败保留责任，不增另一份可编辑引用登记表。

## 29.5 受众授权与观察

受众是 Studio 产品事实，不是 Session 普通只读订阅的副作用。平台绑定的唯一权威行
保存 Thread、平台目标、revision、输出授权代次及生效区间；适配器不能凭任意 threadId
取得对外发布权。平台入站权限、前端受众授权和模型主动工具权限分别判定。

完整前端接收授权起点后该 Thread 的公开助手输出及明确产物，包括 GUI 后续输入产生
的输出；不自动镜像 GUI 用户输入、输入附件、旧历史或子 Thread。首次启用与恢复不把
tail 最新小页解释成待发全部历史；已有 Thread 启用在安全 Turn 边界生效，不半途扩大
原本未授权执行的受众。内容与 GUI 的公共性不等于对任意外部平台的授权。

暂停投递保留受众和补发义务，GUI 明示恢复后补发；关闭同步、撤权或替换绑定封闭旧
授权区间，禁止新平台写，包括卡片关闭。重新启用从新起点开始，不补发撤权空窗。
已经启动的请求可能无法撤回，结果或 Unknown 归原操作保留；撤权不是已回滚的证明。
前端断开或关闭不等于停止 Thread 执行。

## 29.6 恢复与背压

Session 内容与 Studio 执行/交互状态仍是唯一事实源。tail 是有界观察，订阅 version、
item revision、saved 与 terminal 各自独立；重连后的 subscription ID 不是投递幂等键。
适配器按授权代次、稳定内容身份/顺序/修订和具体操作身份恢复，并保留未完成项的修订
跟踪，不能只存最大顺序键而漏掉旧条目更新。

缺帧、重同步或重启从 canonical 页/详情及目标输入、Turn、交互事实补齐，不使用最新
Turn 代替原目标，不重放模型输入。事实未就绪与读取损坏、取消、明确无续接分别表达。
已对外展示但尚未保存的文本是预览；重启不能证明其权威正文时保留 incomplete/需处理，
不以平台快照制造新的本地历史。

投递 owner 与入站 owner 分离；前者有独立 claim/版本，后者只承担原输入可靠交接。
慢平台不得阻塞模型或 Session producer。观察、活跃实体、正文读取与待处理登记均有
预算，同项修订可合并为最新待处理位置；积压可见，不丢终态、不推进虚假送达游标。
账本只保留平台恢复必要的游标、身份、引用和有界操作材料，不保存第二份完整聊天正文。
关闭封闭准入、收束副作用并真实 join；丢弃等待 future 不丢失任务及结果所有权。
