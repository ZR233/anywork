# 29 - 会话公开输出与前端受众

本文是 Studio 公开会话产物、前端受众及公开内容投影的权威契约。Timeline 的页、尾部与
详情归 [26](./26-timeline-content.md)，资源持久化归 [17](./17-studio-storage.md)，飞书
协议、呈现限额及投递操作归 [27](./27-bots.md)。本契约是目标设计，具体交付能力须以实现
和对应验收为准；不能把文档存在当作已有平台送达证据。

## 29.1 所有权与事实源

core 拥有产品无关的 Thread、Session、工具结果和生命周期；不依赖 Studio DTO、外部
平台或受众授权。Studio 将同一 canonical effect 投影到既有 Timeline/history，并拥有
公开内容分类、公开产物和资源读取授权。GUI 与原生渠道适配器消费同一产品事实，不经
HTTP 回环，也不复制另一份完整会话历史、产物目录或模型执行循环。

前端是会话的输入输出渠道，不是模型工具目录的别名。模型正常公开输出由宿主呈现；
主动跨聊天发送仍是独立外部写意图，不成为正常回复的 transport。具体平台适配复用既有
连接、发送服务、资源库与受管任务，不建立消息 broker 或预留泛化插件框架。

## 29.2 公开内容投影

外部前端只消费经当前受众授权的公开事实：

| 事实 | 外部前端含义 |
| --- | --- |
| assistant Commentary / Final | 正常公开过程文本和答复，保留来源 channel |
| public artifact | 当前会话明确交付的可靠文件或媒体原件 |
| typed Turn / Interaction 状态 | 安全的执行、等待、失败、取消或完成摘要 |
| Thinking、指令、raw tool output、命令日志 | 不属于自动外发内容 |
| User、ParentAgent、子 Thread 内容 | 不因存在于时间线而自动广播 |

内容分类依据受信来源和类型，不从正文关键词、路径、工具名字或任意 `output_artifacts`
推断外发意图。平台看不到系统材料不意味着可以保证模型公开正文绝不会误写敏感信息；
当前公开受众须对 GUI 用户可见，渠道 Agent 指令须明确 Commentary 也可能被外部受众看到。

每个公开文本项沿用 canonical item identity、order、revision 和生命周期；Turn 是关联
组，不是把全部过程与结论拼成一个无界字符串的理由。内容修订可 Append、Replace 或
Remove，不能以已终态或文本缩短拒绝合法权威修订；退出观察缓存不表示业务删除。
宿主状态与模型正文分区，模型文本不能改变执行、交互、授权或送达状态。敏感交互材料不
因状态提醒自动公开，也不从“等待已展示”推导用户批准。

渠道可对呈现施加有提示的显示预算，但不得修改 canonical 正文、模型上下文或 GUI 全文。
内容完整性 `Full` / `Truncated` 与平台操作结果是独立事实；未能补齐来源不能伪装成有意
截断。具体平台的显示上限和提示语义只在该平台设计中定义。

## 29.3 显式产物发布

`publish_artifact` 表示把一个原件交付给本会话受众，不表示向某个机器人发送消息。
参数不接受 bot、chat、任意 Thread 或授权身份。输入使用 typed source：

| source.kind | 来源字段与证明 |
| --- | --- |
| `workspaceFile` | `path`：当前实际执行工作区内经文件后端校验的普通文件 |
| `threadResource` | `resourceId`：能够证明由当前 Thread 持久事实引用的可靠资源 |

可选 `displayName` 只覆盖展示文件名，不改变物理读取路径或资源身份；名称不是路径，
不得借路径分隔符或控制字符形成另一个文件定位。媒体类型、长度和摘要来自真实原件，
未知媒体类型按普通文件保留，不以展示扩展名改写字节。一次发布处理一份原件，沿用
[17](./17-studio-storage.md) 的单文件及资源准入预算；零字节原件合法。

workspaceFile 通过当前本地/SSH 物理绑定读取；不得用控制端路径代替远端工作区，也不
放宽 confined、readonly、writablePaths 或符号链接边界。threadResource 必须在当前
Thread 的持久引用中证明归属，不能凭内容摘要、资源 ID 前缀或可观察另一 Thread 取得权限。
文件读取、目录代次与执行身份的生命周期沿用 [09](./09-tool-runtime.md) 与
[22](./22-ssh-remote.md)，不另写文件传输后备路径。

工具输出通过 producer-owned 版本化回执表达已归档原件与发布意图。Studio 只从受信
注册的发布调用、成功提交的结果和合法资源证明产生 typed public-artifact 内容项；
任意工具输出伪造相同格式、模型写出资源 ID 或正文包含文件路径都不能产生该事实。
这属于产品投影，不为此让 core 解码业务 JSON 或增加平台专属控制值。

公开产物项在既有 ThreadItem 信封内保存稳定 publication identity、来源调用关联、可靠
resource reference、displayName、mediaType、byteLen 与 digest。Thread/Turn、顺序和
revision 沿用同一信封；不保存源工作区绝对路径、SSH 地址或外部收件人。
同一次调用/发布身份对应同一原件与名称，内容冲突拒绝；同一字节可复用内容寻址对象，
但内容相同不等于用户重复发布是同一个意图。

共享 wire 使用独立的 `ThreadItemState::PublicArtifact` / `ThreadPublicArtifactItem`，
不复用只有源路径语义的 `File` 项。产物载荷包含 `publicationId`、`toolCallId`、
`displayName`、`resource` 和 `publishedAt`；`resource` 是产品 DTO
`ThreadArtifactResource`，只含 `id`、`contentDigest`、`byteLen`、`mediaType`。
摘要格式沿用可靠资源的 `sha256:<64hex>`，资源元数据不在载荷外重复保存。protocol 不依赖
core；Studio 在已验证的 core 资源引用与上述 DTO 之间转换，FRB 和 Dart 显式映射同一类型。
该项表达已提交的发布事实，天然终态；`publishedAt` 不代表 history 已保存或渠道已接受。
新条目在正式 Thread wire 与 history 版本边界启用，旧条目原样保留，不将旧 `File`、
普通工具回执或归档资源批量升级成公开发布。

不扫描 `artifacts/`，不从 Markdown 链接或路径自动上传，不将输入附件重新发布，不把
生成图片、查看图片或任意工具归档自动改成外部交付。已归档生成产物可通过同一显式
threadResource 发布，无须重新生成字节。子 Thread 发布只属于其自身会话；父会话必须
通过受控交接或自己可读取的工作区形成父会话发布，不能借共享 checkout 转移资源归属。

## 29.4 发布、保存与送达

以下事实不可合并：

1. 原件已可靠归档。
2. 工具的发布意图已随 canonical 结果提交。
3. 对应 history revision 已获保存确认。
4. 一个具体外部前端已接受文件消息。

工具回执不承诺第 4 项；持久化未确认时 GUI 可以显示待保存，外部文件正式投递须等待
第 3 项。工具不能阻塞等待自己尚未返回的结果进入 history。只归档但调用失败/取消、
未形成合法发布事实的材料不自动交付；已提交事实不因后续模型失败或关闭被抹去。

GUI 的 typed 产物项提供文件身份、名称、大小和受控打开/保存能力。读取先验证当前
Thread 的已提交产物及资源引用，再校验长度/摘要；不得回读已变化的源路径补失踪原件。
冷读取不激活模型或重新执行发布工具。HTTP、FRB、Dart model 与 GUI 使用同一 typed
契约，不添加 raw JSON 兼容入口。
产物原件读取扩展既有按 Thread 和资源身份受控读取的端口，不新增任意路径下载入口。
授权来自当前 Thread 已提交的受信发布及其精确资源引用，而非客户端传来的 DTO；当前
未保存事实与可靠历史之间沿既有交接顺序取证，不因热条目淘汰漏掉已提交发布。

### GUI 本地保存与打开

公开产物提供显式“保存…”与“保存并打开…”动作。两者都先由用户在 GUI 所在机器的
系统保存对话框中选择目标；取消不读取原件、不写文件，也不记成失败或保存成功。
展示名称仅作为文件名建议，用户可另选名称，不据此改变资源身份、字节或媒体类型。
这与 Thread 的本地/SSH 执行工作区无关，不显示执行侧源路径，也不新增任意路径下载接口。

系统保存对话框沿用现有平台通道，使用 GTK/Windows 官方保存能力及标准覆盖确认；
不增加另一套文件选择组件。GUI 经既有 Client 受控资源读取取得完整原件，读取或校验
失败不能预先截断用户目标文件。文件写入、关闭完成后才报告保存成功，保留零字节、
未知扩展名及无扩展名原件，不转码、不自动加后缀或按渠道显示预算缩减内容。
动作所属 AppGraph 管理其有界在途工作；关闭封闭新动作并等待已受理操作收束。
展示观察退役不关闭 Thread、清草稿或删除用户保存的文件；迟到结果不发布到另一个会话。

“保存并打开”只在本次保存成功且动作仍有效时，将用户选择的本地文件交给既有
`url_launcher` 的桌面文件 URI 能力，使用系统关联应用；没有关联应用、返回失败或平台
异常均明确报告，不能把“已保存”改成“已打开”。不自行实现 shell-open 或命令行回退，
不建立自动打开用的第二资源缓存。正文链接仍受原 HTTP(S) 链接策略约束；`file:` 能力
仅由用户显式产物动作使用，不因模型给出路径、普通附件出现或产物到达而自动触发。
打开交给系统不等于内容已由外部应用读完，也不承诺文件安全；界面须明示将使用系统应用。

### 原件与渠道副本

产物原件永不为平台限制而截断、改名绕限或自动转码。平台不接受空文件、大小或媒体
类型时，本地产物仍有效，渠道明确拒绝/未交付。资源保留由既有 history 与发送操作引用
证明，未终结投递引用不能被清扫；清理失败保留责任，不增另一份可编辑引用登记表。

飞书复用已有文件发送器的操作快照，而非使发送账本永久钉住另一个 Thread store。
适配器须先取得精确公开产物项、revision 与 history 保存证明，并验证当前受众资格；
通用附件读取端口可读取其它附件的能力不构成这份外发授权。原字节通过受控资源读取后，
在既有机器人出站目录内冻结逐字节相同的副本，核对长度与摘要一致，再由原发送账本
接管。它既不是重新发布，也不是新资源库；不接受模型提供的任意 Thread/聊天目标，
不扩大文件输入或主动发送权限。原件、副本和平台消息各自的身份及保留责任遵循
[17](./17-studio-storage.md)。

## 29.5 受众授权与观察

受众是 Studio 产品事实，不是 Session 普通只读订阅的副作用。平台绑定的唯一权威行
保存 Thread、平台目标、revision、输出授权代次及生效区间；适配器不能凭任意 threadId
取得对外发布权。平台入站权限、前端受众授权和模型主动工具权限分别判定。

完整前端接收授权起点后该 Thread 的公开助手输出及明确产物，包括 GUI 后续输入产生
的输出；不自动镜像 GUI 用户输入、输入附件、旧历史或子 Thread。首次启用与恢复不把
tail 最新小页解释成待发全部历史；已有 Thread 启用在安全 Turn 边界生效，不半途扩大
原本未授权执行的受众。内容与 GUI 的公共性不等于对任意外部平台的授权。

暂停投递保留受众和补发义务，GUI 明示恢复后补发；关闭同步、撤权或替换绑定封闭旧
授权区间，禁止新平台写，包括卡片关闭。重新启用从新起点开始，不补发撤权空窗。
已经启动的请求可能无法撤回，结果或 Unknown 归原操作保留；撤权不是已回滚的证明。
前端断开或关闭不等于停止 Thread 执行。

绑定因 Thread 缺失、归属冲突或不可用而进入需处理状态时，必须在原绑定 CAS 边界封闭
相关输出授权，保留原操作与未终结投递事实，原因明确为 BindingUnavailable。迟到的旧
诊断不能改坏后继绑定，迟到 Saved 起点也不能激活已失效绑定；当前受众投影保持明确
不可用，并由原受管 owner 发布变化，而不是继续显示 Active。

受众目标的聊天种类也须有持久来源证明，不能依赖曾经执行过一条输入才变得可知。显式
新建的首次受理复用既有目标可见性核验：官方群列表的精确命中证明 Group，已可靠观察的
单聊与其非空操作者身份证明 Direct；可信名单只表达授权，不用于猜测聊天种类。首次
入站则使用已可靠受理消息的 typed 种类与身份。核验结果随原创建意图冻结，并在绑定完成
时与不可变创建来源一致关联；不增加第二份可写 chat→Thread 路由或查询触发的网络发现。
该创建期证明不构成永久群成员资格或发送许可，每个新平台写仍重新核当前授权及适用的
目标可见性。重试与重启只接续原已受理创建事实，不能联网重选目标或补种模型输入。
旧记录仅可从可证的原来源迁移目标种类；无法证明时保留明确不可证明状态，冲突拒绝，
不从当前信任配置、空字段或缺少入站推断 Direct/Group。

### 新授权起点的证明

新授权按 **Turn 开始** 划界，不按输入的受理时间划界：已经受理但尚未开始的排队输入，
以及尚未开始的合法 continuation，其新 Turn 可以进入新授权；起点时已经开始的 Turn
则整轮排除，不能只排除其起点前正文而把同轮稍后的 Final 外发。新建 Thread 必须在首
输入执行前准备起点；已有 Thread 的启用可以显示待下一轮生效，但不得为此暂停模型。

新会话在目录中可见，不代表其首次前端初始化已经完成。Studio 的公开本机输入准入也须
检查原创建/授权 owner 的就绪事实，不能只在飞书入站提交前检查。初次准备尚未完成时，
返回可重试的未就绪结果，不提前消费草稿、附件或提交 core 输入；已有受理身份的重复请求
仍按原幂等回执处理，不因新增检查把 Accepted 改成未受理。该判定只读原持久事实，不以
查询启动初始化，也不新增另一份可写 readiness 事实源或长期持有 Thread 准入闸门。

首次初始化已完成，或已明确关闭/替换而转为本机处理的会话，继续沿用本机输入语义；
RequiresUpgrade 的旧会话也不因此失去本机工作能力。后续 Enable 的 PendingStart 不阻断
这些已有会话的执行。与此不同，飞书入站 owner 在新会话起点保存并按原 CAS 生效前，只
保留受管受理工作，不启动首个模型输入；关闭或待升级期间也不借本机输入许可自动执行
新平台消息。缺少、冲突或不可读的创建归属不能被猜成普通未绑定会话。

新建绑定的首次初始化也受当前启用与信任范围约束：没有输出许可，或准备期间许可已被
撤销时，保留本机 Thread 与原创建结果，沿原授权记录明确封闭本次初始化，不留下等待
将来启用/加信任就自动授予输出的 Pending。封闭不是平台已发送或初始化起点已保存的
证明；后续外部同步仍需用户显式建立新授权，不能借“首次准备”绕过关闭与重新启用规则。

Studio 与 bot owner 之间使用窄的只读 `read_thread_input_readiness` 契约，输入为已核实的
冻结 bot owner 与 Thread 身份，结果区分 `Ready`、`Preparing` 和真实读取/归属错误。
该结果只表示本机新输入是否可准入，不表示受众授权或平台消息可执行；不复用依赖聊天
展示、投递统计及平台可用性的受众摘要作门禁。`Preparing` 映射为原 Studio `Busy` 且
`retryable=true`，缺失或冲突的证明明确报错，不以诊断文案作为机器判定协议。

判断依据是原创建归属和授权持久事实：可证的创建中或新绑定尚无首次起点，保持
`Preparing`；已经保存并激活的起点、明确封闭的授权、可证的替换或旧会话升级状态允许
本机继续。曾完成初始化或明确转本机的事实不因后继新一代 `PendingStart` 回退为未就绪。
读取保持有界且不写入；不能只检查当前授权头，也不能用无授权记录推断已关闭。
单次首次输入就绪判定最多核验 16,384 条相关历史来源记录，覆盖授权及创建归属证明实际
依赖的来源；不能把“冲突查询返回至多一行”当作扫描成本上限。超出预算时返回明确的
不可用/需处理结果，不基于已检查前缀判为 Ready，不删除旧义务来恢复准入。预算裁决和
证明读取必须观察同一事务快照；无关 Thread 的历史不占本次额度。
公开普通输入与 queued 输入共用此检查，放在原驻留/持久幂等回执之后、配置调整和附件
准备之前；重复 Accepted 仍返回原回执，未就绪请求不产生新的 core 输入或附件准备债务。
等待首次起点属于正常推进而不是失败：`Preparing` 的入站只延后重派，不消耗失败次数与
退避预算，也不因此在附件准备阶段取用任何平台资源。该等待有独立的持久上限（当前为
900 秒），起点必须随受理记录持久保存，并在可重试失败、宿主关停中断与重启后继续沿用，
不被新的诊断文本覆盖或从当前时间重新计时。上限到达后只把该入站收束为明确的需处理
状态并给出区别于失败预算的诊断，不据此关闭仍在准备的授权、不伪造平台结果；恢复仍走
本机显式动作。等待期间的清理与收束使用与受理认领相同的 fencing，失去认领的旧所有者
不得写入终态。

Studio 通过原 Thread owner 的通用 opaque 扩展提交起点意图；该意图不进入模型事实，
不向 core 增加受众、飞书或发布控制语义。起点证据由同一 canonical effect 及其对应状态
产生，绑定 Thread、操作/授权身份、扩展修订、实际 commit sequence 和当时已开始的 Turn
身份；不能先读 snapshot 再把稍后写入当作同一个原子边界。调用返回不等于保存确认。
扩展命令沿 Thread owner 既有的串行处理边界提交，不抢占正在执行的 Turn。机器人侧
已经持久准备而该命令仍排队时保持 PendingStart；不能要求运行中的模型让出前就已有
切点回执，也不为启用同步暂停模型。切点提交时已终态的旧 Turn 由开始序号排除，不要求
每个启用操作都捕获一个仍在 Running 的排除项。

每个 Turn 的开始证据来自其真实开始 effect，并在原 history 事务中不可变保存，独立于
会随进度、终态或修订更新的 Turn item revision。公开项须以真实 `turn_id` 关联此开始
证据，证明开始 sequence 严格晚于该授权起点，且不属于起点捕获的已开始 Turn；不能用
最新 Turn、墙钟、裸最大 ordinal、tail 首帧或可变 Turn revision 代替。旧记录没有开始
证明时保持未知，不依据当前状态回填或给旧历史补授公开权限。

当前起点意图只占一个可替换扩展，不按历史操作永久增加扩展条目。每次操作与每个 Turn
的证明沿原 history fact receipt 保存；同一身份的回执内容及开始 sequence 不可改写，
重试同一提交只重读原事实。当前意图已指向同一操作但尚未保存时保持待定，不重做起点；
已由后继授权替换的旧操作不能覆盖新意图。回读核对持久来源、载荷摘要、身份和覆盖水位，
缺少证明与已证明不符合授权分别表达，不通过扫描旧 journal、最新 Turn 或显示页补证。

绑定 owner 先保留未生效的授权操作，待精确起点证据随 Thread history 保存后，才在原
binding/authorization CAS 下启用。Thread 提交已发生但绑定尚未启用、等待者取消或进程
中断时，受管操作保留两侧实际事实；恢复只按同一操作/授权身份接续，不凭迟到成功开启
已关闭、已替换或另一代授权。起点后的合格新 Turn 在激活前产生的内容仍从 canonical
history 补齐，起点时那一轮不因此获准外发。失败不回放输入，也不长期持有 Turn 准入闸门。

### 本地受众观察

当前 Thread 的轻状态基线与增量携带小型 typed 受众投影，供标题和输入区共同消费。
投影从绑定/授权 owner 的本地事实派生，包含目标显示身份、受众种类、绑定 revision、
授权代次/起点、同步状态及有界投递摘要；没有绑定与暂时无法证明绑定是不同结果。
绑定替换后，旧 Thread 的已封闭受众与未终结操作仍可解释，不以当前映射缺失伪造
“从未对外同步”。该观察不复制另一份可写绑定事实，也不携带正文或全量投递记录。

GUI 复用当前 `StudioThreadSession` 的状态观察生命周期，不为受众显示再建立一份执行
订阅或遍历机器人聊天页。冷读取按本地已保存事实提供同一投影，不激活模型、工具或
机器人连接；只有原本的显式会话激活动作仍沿其既有生命周期。受众变化由授权/投递
owner 发布，不能等待下一次模型输出才更新，也不由全局机器人管理快照猜测。

单项渠道状态通过当前 Thread、明确授权代次和稳定 item 身份的有界 typed 查询取得，
单次最多 100 个身份，不读取正文，不复用 Timeline 游标作为投递水位。返回权威内容
revision、呈现完整性、平台操作结果与独立的投递状态版本；尚未投影、未获授权、来源
不完整及结果未知不得混同。已接受旧 revision 不表示新 revision 已送达。Thread 轻状态
中的投递版本变化只使当前已展示身份的有限状态查询失效，不驱动全历史轮询或模型执行。
Client 按 Thread/授权代次/item 身份合并，并在展示 lease 退役时释放相应镜像和查询责任。
已关闭授权不再为当前内容给出可投递资格；历史平台回执仍独立保留。没有可靠关闭边界
证明时不能只凭开始 cut 许可关闭后的内容，也不能以墙钟补出授权终点。

### 共享观察与命令接口

Thread 轻状态的 `audience` 为必填 typed `ThreadAudience`，使用 `Unbound`、带明确原因的
`Unavailable`、或 `Known(BotThreadAudience)`；占位快照不能默认声称无受众。增量使用原
`ThreadNotification::AudienceChanged` 与既有 envelope，新增形状在 Thread wire **17**
启用；history 的公开产物版本 9 不因只读快照字段变化重复迁移。

受控创建路径下，每个 Thread 只属于一个 bot/chat，授权可以有多代。Known 仅携单一目标
的机器人名称、可选聊天名称、Direct/Group 种类、Current/Replaced 位置、当前同步状态、
最多一条最近关闭授权及投递/旧有限 Final 的小摘要。旧结构没有反向唯一约束不能当作
可忽略的问题：读取和迁移须证明 current、历史授权及原来源指向同一目标；矛盾返回
`Unavailable(InconsistentScope)`，不取第一条，也不扩成广播目标数组。

同步状态为 `PreparingThread`、`RequiresUpgrade`、`PendingStart`、`Active`、`Paused`、
`Closed`。PreparingThread 只用于创建尚未完成的绑定管理回执，不能伪造已存在 Thread 的
起点；PendingStart 有真实受管操作但尚无有效保存起点。授权身份使用完整
`BotAuthorizationId { bot_id, chat_id, generation }`，另有独立授权控制 revision；
binding revision、授权控制 revision、摘要/投递版本和内容 revision 不可替代。旧 Thread
被替换后不暴露新 Thread 的活动授权或可写 CAS，但继续解释自己的关闭与未终结义务。

`read_thread_closed_authorizations` 是单独的只读关闭历史查询，默认 16、最多 32 条。
opaque keyset cursor 绑定 Thread、经核实的单 bot/chat、首次页最高授权键和 before 键；
不能借 Timeline 游标查询另一授权。历史页空结果需要完整本地覆盖证明，归属未知、损坏
或数据库不可读均不返回空页。轻摘要计数饱和于 16,384 并带 `counts_capped`，表示至少
该数量而非精确计数；此显示上限不删除或缩减持久义务。
各状态计数分别按真实匹配事实饱和，不能先抽取一批条目再把子集计数称为总量。旧有限
义务还包含没有卡片的已受理入站/续接链；覆盖无法证明时，投影明确不可用或需处理，
不能给出“零未完成、无需处理”的完整结论。迁移须比较来源中所有可证明的 Thread、
目标、项目、创建身份与绑定修订；缺失证明不填猜测默认值，已知字段冲突则事务回滚。
入站恢复要求处理的未知工作状态，不能因为不在已知未完成状态列表中就被摘要忽略。
同一聊天只有持久受理身份而缺少对应工作记录时，历史归属与义务无法证明，摘要也须
明确不可用或需处理；不能按当前绑定补造归属、当作已完成，或清除原记录来得到零计数。

`read_thread_audience_items` 输入 Thread、完整授权身份及 1..=100 个非空、不重复 item ID，
按原顺序逐项返回。每项分为 canonical 当前 revision/saved/资格，与账本已观察、已投影、
已接受的 revision/完整性及平台操作状态；查询不能只返一个“已发送”布尔值。Missing
映射来源不可用，只有真实 Remove 证据才表示 Removed；两种情况均保留旧平台回执。
文本完整性为 Full/Truncated，文件没有 Truncated。Card 只给当前恢复相关操作的种类和
结果；文件的 upload/message 阶段分别提供事实，任一 Unknown 保持 Unknown，上传成功
而消息拒绝为 Partial 而非送达。仍由 owner 持有的在途状态与重启遗留 Unknown 分开。
本地空文件/大小/预算/材料拒绝与平台 Rejected 分开，不伪造平台返回。

只有 accepted revision 与本次 canonical revision 及 Client 当前展示身份相符，才可
标为当前修订已接受；Create 成功不等于卡片已发，Settings Unknown 不抹去先前正文
Accepted。查询不声明跨 Session/机器人库全局原子快照；scope 变化、元数据失效或无法
对应的版本须明确不可用，不以旧响应覆盖新修订。最小接口不携卡片 ID、UUID、file key、
原始平台请求或跳转消息 ID。

Client 缓存的新鲜性同时受展示身份、完整授权及 summary/delivery/control 版本约束。
相关版本一旦失效，立即停止把旧缓存当作当前投递状态展示；即使旧查询仍在等待，也须
表达正在读取或不可用，不能因为正文 revision 未变而继续显示旧的当前 Accepted、Unknown
或 InFlight。迟到旧响应不得恢复失效缓存；后继读取仍只消费最新的有界可见需求。
展示退役或关闭时，观察适配器不能重新订阅已关闭的状态源；须先停止新观察，再由原
owner 等待实际查询收束。仍挂载的 UI 不延长受众授权，也不承担重新打开 Session 的责任。

`change_bot_thread_sync` 是本机 typed 命令，action 为 Pause/Resume/Close/Enable；请求
携 stable operation ID、当前 Thread，以及 binding revision 和完整 authorization head
CAS。它只操作已证明归属的当前绑定，不接受任意新目标 Thread/bot/chat，也不装配成模型
工具。结果为 Settled、PendingStart 或 Superseded，并携原命令 receipt 和当前受众投影。
已保存 prepare 的 durable receipt 不等于同步生效；迟到 cut 不能把后继 Close 或 replace
改回 Active。同操作同输入回读真实进度，变更输入冲突。Active/Paused 不借 Enable 换代，
RequiresUpgrade 仍只复用 `createBotConversationThread`；原 SetBotEnabled/config CAS 不变。
命令的持久受理与切点生效分开：已有 Turn 尚未让出 owner 时，本机 Enable 应能返回
PendingStart 的真实受理回执，由受管 owner 继续接续切点，而不是把调用方一直扣在模型
结束前。后继 Close 或替换仍可按当前 CAS 封闭该准备，不能排在“等待 Enable 生效”的
前端串行队列之后；迟到准备结果只按原操作保存，不能覆盖新的用户意图。

同步命令的观察水位按 Thread 与授权代次分域，回执资源键为
`bot-audience:<threadId>:<generation>`，revision 使用该授权自身的控制 revision，owner
epoch 仍来自原 Studio 命令宿主。新授权不能被上一代较大的 revision 提前确认为已观察。
Client 确认时仍核完整 bot/chat/generation 和 Thread 身份；资源键仅用于水位比较，不是
授权证明。PendingStart 的持久受理、当前授权的实际生效与被后继操作取代分别表达。

HTTP 与 FRB 共用上述 typed 请求/回执；HTTP 沿原本机 Studio 授权边界提供 POST 接口，
不因此增加模型工具。操作身份与路径固定如下：

| 操作 | HTTP 路径 |
| --- | --- |
| `bots.readThreadClosedAuthorizations` | `/api/v1/bots/threads/closed-authorizations` |
| `bots.readThreadAudienceItems` | `/api/v1/bots/threads/audience-items` |
| `bots.changeThreadSync` | `/api/v1/bots/threads/sync` |

冷定位先验证已冻结的 `studio.bot-owner` 和渠道身份，再只读一个 bot 的本地账本；缺
owner 不自动等于普通会话。可信普通根或 child 可证明 Unbound，legacy/损坏/冲突保持
Unavailable，不为查询遍历网络聊天或补写归属。每个已管理 bot 只保留一个带 owner epoch
和版本的 watch，先订阅再读当前 Thread 基线；无接收者仍保留最新值。当前 Thread 状态
订阅复用该失效通知重读自己的小型本地投影，真变才发 AudienceChanged；慢消费者合并
最新通知而非轮询全历史。失效通知的接收与投影读取完成是不同事实：读取等待被取消后，
复用同一订阅仍须重读尚未完成的版本，不能提前确认观察水位而永久跳过该次变化；读取
期间再出现的更新也必须留给后续重读。成本受现有活动展示/查询预算限制，不新建永久 per-Thread topic
或 locator；释放 receiver 只结束观察，不关闭 bot/Thread 或投递 owner。

## 29.6 恢复与背压

Session 内容与 Studio 执行/交互状态仍是唯一事实源。tail 是有界观察，订阅 version、
item revision、saved 与 terminal 各自独立；重连后的 subscription ID 不是投递幂等键。
适配器按授权代次、稳定内容身份/顺序/修订和具体操作身份恢复，并保留未完成项的修订
跟踪，不能只存最大顺序键而漏掉旧条目更新。

缺帧、重同步或重启从 canonical 页/详情及目标输入、Turn、交互事实补齐，不使用最新
Turn 代替原目标，不重放模型输入。事实未就绪与读取损坏、取消、明确无续接分别表达。
已对外展示但尚未保存的文本是预览；重启不能证明其权威正文时保留 incomplete/需处理，
不以平台快照制造新的本地历史。

投递 owner 与入站 owner 分离；前者有独立 claim/版本，后者只承担原输入可靠交接。
慢平台不得阻塞模型或 Session producer。观察、活跃实体、正文读取与待处理登记均有
预算，同项修订可合并为最新待处理位置；积压可见，不丢终态、不推进虚假送达游标。
账本只保留平台恢复必要的游标、身份、引用和有界操作材料，不保存第二份完整聊天正文。
关闭封闭准入、收束副作用并真实 join；丢弃等待 future 不丢失任务及结果所有权。
