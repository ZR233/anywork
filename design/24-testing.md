# 24 - 测试与人工验收

本文描述现有测试基础设施、模拟对端、观察工具与证据边界，不规定开发工作流、允许新增测试的范围或每次修改的必跑清单。命令入口见 [AGENTS.md](../AGENTS.md)，方法可参考 `test-quality`；CI 的实际执行以工作流配置为准。

`PR Quality Gate` 在 PR、`merge_group` 与 `main` 推送时总是启动，并对同一 `github.sha`（PR 为合并测试提交）执行检查，不用顶层路径过滤跳过整个 required workflow。路径分类按实际消费者选择职责：协作说明、技能说明和普通文档只需文档策略；发布元数据和发布脚本只需发布配置检查；Client 与 App 分别选择自己的前端检查；桥接、原生 runner、生命周期和构建输入选择对应生成、集成或平台编译。嵌入 Runtime 的技能与资源仍是产品输入，不按仓库协作说明跳过。混合变更取职责并集，重命名与复制同时检查来源和目标路径；未知路径、不完整差异、共享 CI、工具链和产品 fixture 保守选择完整适用检查。

同一 PR 的新提交取消其旧运行。`main` 推送按该次推送差异选任务，因此保留各次运行：不能让后一次仅修改文档的推送取消前一次尚未完成的代码检查。镜像发布只由 `main` 的环境输入变化或显式 `workflow_dispatch` 启动；功能分支由 PR 内的环境解析、候选构建和 smoke 验证，不再额外触发镜像发布。

Rust 日常检查保留功能、故障恢复和真实进程生命周期证明。大规模索引与流式成员碎片化
由 `Rust Scale Checks` 每日定时或手动执行；其工作流修改时也在 PR 中验证。小规模与大规模用例复用同一行为断言，仅输入规模不同，
不能以日常结果声称大规模通过。专项检查只选择明确标记的规模用例，不运行真实供应商或
SSH 环境的其他 ignored 测试。运行失败须由该工作流继续报告，不计入普通 PR 的必需检查。

Linux Rust 缓存位于 checkout 之外，并以相同路径挂载进构建容器，防止缓存组件将第三方
依赖误认为工作区源码并清理。Rust 质量作业允许保存当前 PR 合并引用下的缓存，供后续提交
或同提交重跑复用；它不能覆盖主线缓存。其他作业仍只在默认分支保存缓存。工作区格式、
独立依赖契约、Clippy、辅助进程构建、测试编译、执行及服务端构建分开计时，保留原始失败。
没有可执行文档示例的内部 Runtime、协议与桥接库关闭空文档测试；工具作者示例、下游
编译失败契约和其他库的文档测试继续由原入口发现。

| PR 检查职责 | 执行与证据边界 |
| --- | --- |
| 独立工具接口与作者特性 | 无默认特性和 typed-only 独立运行，typed+macros 与宏诊断由 workspace 测试覆盖一次；外部 downstream 保留重命名依赖与脱离 workspace 的消费证明。工具集合 downstream 用一次 `cargo test --all-targets` 覆盖编译与媒体执行，不先重复 check。真实 binding 保存重开证明原参数、完整结果、错误阶段、冻结展示与不重执行；Linux MCP peer/生命周期用例不由其他平台的零用例替代 |
| Flutter 静态、Client、应用单元和组件集成 | 在项目 Linux Docker 镜像内安装锁定 Pub 依赖。`pr-quality-flutter.sh --client` 执行 SDK-only 依赖边界、格式、分析和 Client 测试；`--app` 执行 App 格式、分析、Client/UI 导入闭包及一次 `flutter test --no-pub test/unit test/ui`。Client 生产接口或被 App 复用的 `test/support/` 变化同时检查 App，单改 Client 用例或 App 时只运行所属范围。无参数仍检查两者；应用测试无设备、无 Rust bridge |
| Rust 质量与公共语义 | Rust 或共享构建输入受影响时，Linux 执行 fmt/clippy、无数据库的 core 检查与 workspace SQLite 测试；Windows/macOS 只执行各自宿主的 clippy，不运行 Rust 测试 |
| GUI 生成一致性 | 桥接或生成输入受影响时，在 Linux 经 canonical 入口检查一次；应用编译不重复生成检查 |
| Linux 构建输入 | 生成检查需要工程工具；原生集成和 GUI 编译才需要双架构 helper。仅平台 Clippy 不触发准备作业，也不因其 skipped 而连带跳过。工程工具与所需 helper 复用一次镜像恢复与构建缓存，分别归档并保留源码、摘要和环境身份校验；消费者不以缓存或重新编译替代同次运行的交付产物 |
| Linux 桌面与原生集成 | desktop full 确定性分片到独立 runner，native full 同步独立运行；与工程工具并行的准备作业集中编译 acceptance 和开发配置 bridge，经既有受控构件交接供各 runner 只读消费。release/profile bridge 仍由场景所属 runner 编译。各 runner 内顺序执行，不并发改写同一 Flutter 工作树。功能与生命周期信号独立，不因共用 harness 删除独特断言 |
| Windows/macOS 应用检查 | 仅包含宿主 Rust clippy 与 `cargo xtask build-gui --debug` 两类检查，按路径分别选择。Rust 生产输入改动选择两者；crate 根 `tests/` 下测试及其专用数据改动只选择 Clippy；仅平台 runner 等非 Rust 改动只选择相应编译。debug 仍编译真实 App、Rust bridge、插件与 helper 资源，保留链接与平台装配检查；不在每个 PR 重复做 release 优化和打包。helper 与 Flutter 工具链只在 GUI 编译时恢复，不运行各平台重复业务测试 |
| Linux server 构建 | 后端或共享构建输入受影响时提供 server 编译信号，不以 GUI 测试代替 |

Linux 测试只提供该宿主的运行行为证据。Windows/macOS 的 Clippy 与 debug GUI 编译成功只证明对应宿主的静态检查、编译和链接，不证明 release/AOT、该宿主的运行行为、原生窗口生命周期、AppKit 终止或签名。`build-gui` 默认仍为 release；RC/稳定发布继续构建并验证 release 成品。debug 输出只留在 Flutter 的 build 目录，不写入 `dist/anywork-release`，不能作为发布输入。

纯 Rust 集成测试路径按 crate 根 `tests/` 的结构识别，包含其专用 helper 和 fixture 数据；不能仅凭 `src/` 中的文件名含 test 推断它不会参与生产构建。产品共享 fixture、工程工具、验收工具和共享构建配置仍保守检查。混合生产改动恢复生产编译职责，不因同时包含测试而缩减覆盖。平台作业是否运行，与其中是否需要 GUI 编译分别由分类结果决定。

集成分片沿用同一发现、full/smoke 与显式启用规则，按稳定排序后的序号分配；所有分片无重叠且完整覆盖未分片的选择集合，不维护第二份场景名单。分片索引从零开始，必须与正数分片总数成对提供；索引越界、空分片或与单场景选择混用均失败，列举与执行消费同一选择结果。各分片的失败、取消与缺失均阻止 gate 通过，各自保留报告与日志，但不归档隔离配置、home 或数据库。真实账号入口 `acp_real_login`、`chatgpt_real_login` 和 `acp_agy_conversation` 只在对应环境显式启用时进入 full；agy 要求 `ANYWORK_AGY_LIVE=1`，不先构建原生程序再靠测试内 skip 报成功。desktop smoke 保留真实跨层的 `wait_events`。

Linux CI 的桌面与原生测试输出按本次运行及重试编号隔离，避免构建缓存恢复的旧目录阻止新测试启动。报告与日志从同一本次输出归档，旧目录不作为通过证据，也不通过删除共享缓存解决路径冲突。

桌面失败证据包含测试报告、脱敏后的模拟对端请求与消费状态，以及时间线连续性诊断；不得因主日志只有外层退出码而丢弃已生成的内部失败证据。

一次 desktop 套件运行在执行场景前准备一次原生环境、锁定的 Flutter 依赖、debug bridge 与 helper；仅复用不可变构建输入，不复用场景 home、fixture、报告或进程。跨 harness 子命令的准备回执位于 `target/test-project-preparation/` 下的本次临时目录，由父运行持有独占文件锁并在退出时释放和清理。子命令须核对活跃租约、规范工作区、Git 源码状态、宿主/构建配置及构件摘要；缺失、过期或不匹配直接失败，不静默重建。回执仅通过本次子进程环境传递，不是持久依赖缓存、全局“已准备”开关或跨运行复用入口。单独运行场景仍自行完成准备；native 套件的不同入口和构建模式不消费 desktop 回执。

Linux 的 Cargo 源码与编译缓存按镜像身份与作业职责隔离，只从受信默认分支写入；宿主缓存动作与容器 Cargo 显式消费同一独立缓存目录，不挂载用户 Cargo 配置或凭据。缓存命中仍须经过 Cargo 的源码与锁文件核验，不是已验证程序或测试通过的证据。

Linux 自动集成可通过 `ANYWORK_CI_TEST_INPUTS` 显式消费同次 workflow 的验收工具与开发配置桥接库；这是 CI 工程输入，不是用户配置或持久缓存。交接沿用精确构件 ID、归档摘要、源码、编译工作区和不可变镜像校验，消费时再核对实际 Rust/Cargo 工具链、平台、构建配置、运行编号及各文件摘要。设置入口后缺失、损坏、源码有修改或身份不匹配均直接失败，不回退编译；未设置时保留普通本地 Cargo 构建。仅共享固定只读文件，不共享 Cargo target、Flutter 输出、进程、fixture、场景数据或报告；每个 runner 自己创建和释放调用内准备租约。下游重跑可复用同一 workflow run 的精确生产者构件，不接受跨 run 构件。

同次运行交接的只读工程工具、验收输出与私有桌面会话目录放在 Cargo target 及 Cargo 缓存之外；先完成编译缓存恢复，再校验和恢复本次工具。缓存恢复不能清理本次工具，也不能把旧证据目录冒充本次输出。交接与验收仍拒绝覆盖已存在目标，不以删除未知目录、重编译或路径兜底掩盖归属冲突。

原生关闭验收通过 `shutdown` 场景执行一次真实启动与正常关闭。同一应用实际持有 MCP、语言服务、后台命令及其后代进程；关闭前记录进程身份，关闭后核对原生退出码为 0、所属进程均已消失且启动器未代为强制回收。准备与退出只有防卡死期限，不断言精确耗时，不编排多阶段故障、第二实例、正文或数据库恢复检查，也不人为创建脱离受管进程组的额外后代；启动器仍观察全部实际后代，任何强制回收均判失败。语义查询与工具目录发布继续由 Rust 的 `runtime_lsp_configuration` 回归证明。

Linux 原生宿主首次加载打包桥接库时使用系统 [dlopen](https://man7.org/linux/man-pages/man3/dlopen.3.html) 的 `RTLD_DEEPBIND`，优先从桥接库及其依赖解析符号，避免系统与 Flutter 导出的栈展开函数混用。该库由进程持有，随后 Dart 重开同一库，不另建加载器或桥接实例。

轮次终态与时间线接纳独立推进。保存内容的库存读取须先等当前 Main 接纳该轮受理的输入，再固定原读取窗口；固定后仍严格核对窗口、轮次、输入、完成记录与正文身份，不能在读取失败后改用另一窗口或旧轮次内容。

启动与原生退出回调可能属于不同的 Dart 错误隔离区。启动 owner 须在原隔离区登记覆盖成功与失败的收束通知，关闭方只等待这项真实完成事实；启动调用方仍接收原始失败，未完成的初始化仍须在退出期限内如实报告为未收束。

无显示的 Flutter widget 测试仍执行依赖的官方 native-assets hooks。Linux 前端作业消费
同次解析并校验的项目 Docker 镜像；`cnativeapi` 所需 C++、pkg-config、GTK 3 / X11 / Xi
开发依赖在镜像制作时预装和验证，不在消费作业中补装。这不引入 Rust bridge 或原生 GUI
测试；纯 UI 变更只增加环境解析依赖，不选择 Rust、helper 或桌面构建作业。

始终运行的 `ci-gate`（`if: always()`）只接受分类计划明确允许的 skipped；必需作业因上游失败或取消被连带 skipped 时 gate 失败。建议把仓库 required check 配成稳定名 `ci-gate`；修改 workflow 本身不会自动配置 required check。

独立验收工具由一次锁定的 Cargo 构建提供可执行产物消息与实时可读诊断；产物位置由 Cargo 报告，不通过第二次构建定位，也不推算固定 `target` 路径。构建失败或缺少目标可执行产物必须失败。

| 入口 | 环境与可观察边界 |

| `pl-core` | 脚本化模型与工具、临时历史后端和 SQLite，用于观察 Thread、Session、取消、恢复与持久化行为；crate 依赖方向见 [02](./02-crates.md) |
| `pl-model` | 本地回环协议对端，用于观察模型请求、流、目录、计量及故障传播 |
| `pl-studio-runtime` | 真实临时 SQLite/Git 与受控保存故障，用于观察迁移、工作区身份、关闭及历史保全 |
| `pl-patch` | 公开补丁接口和真实临时文件系统，用于观察解析、应用、移动及部分失败语义 |
| `anywork_client` 与应用适配 | 可控传输、Future 和时钟，用于观察状态归约、身份、通知、草稿及资源所有权 |

### 24.1.1 Client 证据边界

纯 Client 和应用适配测试可以证明受控输入下的状态与所有权关系；它们不加载或不能完整覆盖真实 Rust 动态库、原生窗口、输入法与操作系统进程。Flutter 内容捕获、截图和原生退出回执分别提供这些边界的观察信息，不能彼此替代，也不是要求每次修改都执行的五层流程。

`verify-client` 负责 SDK-only Client 的依赖与导入边界、格式、静态分析和纯 Dart 测试；应用适配逻辑与组件由前端应用测试证明，不将纯 Client 检查外推为应用侧通过。

应用测试按实际依赖而非用例名称选择层级：领域规则、适配、生产 owner 与受控传输的查询交错进入无设备单元或组件测试；原生桌面集成保留真实 AppGraph、FRB、持久化与窗口交互增加的独特信号。不需要原生边界的用例不因使用 `WidgetTester` 而启动完整桌面程序。各入口必须实际发现并执行测试，缺失套件或内部失败不得报告通过。

GUI 判定优先表达可观察关系：内容受父布局约束、同列对齐、层级递进、控件可操作，以及窄窗和大字号下不溢出；交互则核对操作前后变化、边界钳制、恢复默认和界面与保存状态一致。视口、字号与合成内容可以是具体输入，但不重复锁定无业务意义的像素快照。真实协议、无障碍要求和产品行为边界仍需严格验证；删除或下移测试不得撤销其独特的失败信号。

### 24.1.2 Waiting 的分层集成证据

Waiting 由 Core/Runtime 公开 API、生产 widget 集成和官方桌面 `integration_test` 分层证明。替换旧测试时保留业务覆盖，而不是保留脚本阶段数；专属观察镜像、状态机和仅测试这些辅助实现的用例随旧入口一起删除。

| 行为 | 最小充分的观察边界 |
| --- | --- |
| 任一目标完成而另一目标仍运行、already-ready、空目标只等消息、固定超时、取消等待不取消目标 | 真实 Core/Runtime 公开 API；用受控工具、Tokio 虚拟时钟与显式进入/释放屏障断言返回快照，不以 GUI 读取速度证明交错 |
| 取消请求受理与物理完成/join、工具与 Thread 身份及错误传播 | 真实任务所有者；取消回执后继续观察原任务终态，错误不转成超时或空结果 |
| child 消息唤醒、报告唯一交付、后续请求不重复投递 | 真实 Runtime 调度与 provider 请求边界；消息文字出现不单独替代报告身份和次数 |
| Waiting、完成、超时、取消的呈现，当前集合与完成历史分离、启动收据与终态不同身份、代次失效 | 真实生产 widget、展示 owner 与串行接纳链的组件集成；只控制输入事实，不重写产品状态机 |
| 展开/收起、公开 JSON、滚动与窄窗口几何 | `WidgetTester` 操作真实控件并读取已布局子树；业务 ready 与帧推进分别等待，无限动画期间不调用 `pumpAndSettle` 等待业务结束 |
| FRB、SDK、持久化到实际生产界面的关键路径 | Flutter 官方 `integration_test` 的独立场景；保留真实 `AppGraph`，不注入业务状态、不建立第二订阅或消息镜像 |

桌面项目集成通过 `cargo xtask test-project --suite desktop` 复用现有 bridge/helper 准备和进程树所有权，再调用官方桌面 `flutter test -d <当前平台>`。它与 demo、capture、profile/native-launch 和已有 release 运行模式互斥；不是性能采样入口。`wait_events` 与 `conversation_read_work` 的隔离 home、fixture 与预置历史由 `pl-studio-acceptance` 的对应 `--preset` 持有：`test-project` 在环境变量未齐时子进程调用该 harness，harness 注入环境后再以内层 Flutter-only 路径跑同一 case。各场景独立发现、单独报告失败和收束，不因前一条断言失败而将后续场景全部当作已覆盖。

同次桌面准备复用原 `pl-xtask` 执行入口：父入口持有既有 preparation lease，将准备目录与原执行文件的规范路径一起交给 harness；七个场景共用命令构造，内层直接运行同一入口，不重新经过 Cargo／rustup 改写 `PATH` 或工具链环境。原 workspace、源码、配置、bridge/helper 产物及 lease 校验在实际消费前集中执行一次，不在外层调度和内层消费重复求值；借用时核对入口路径，不另增逐用例的 xtask 自身摘要或另一套准备记录。已存在准备交接而缺失执行入口时明确失败，不退回重新构建；独立人工入口没有借用准备时仍使用正常工程入口建立自己的准备。每个失败用例直接输出用例身份和完整错误链，报告保留同一错误链，不为单次字段组装新增辅助层；没有指定报告目录不得使真实首错消失，最终汇总仍失败且继续收束其它已选用例。

测试 binding 唯一负责测试断言与异步错误，不能通过生产入口替换其错误处理器来吞掉失败；应用与原生资源仍经生产关闭所有者收束。场景输入使用官方 `TestTextInput` 的配对注册/注销，避免 `enterText` 注入与真实 IME 同时修改编辑状态；这不替换产品草稿或提交链路，也不构成原生输入法兼容性证据。必要的观察窗口由测试 provider 的下一响应屏障或受控工具提供，记录到达后才释放；不放慢生产路径、不延长超时制造成功。工具返回时的快照、UI 后来读取的不可变结果、保存完成是不同证据，后续 Turn 已结束不使已取得的早返回证据失效，也不能事后补造早返回事实。

官方入口及行为依据：[集成测试](https://docs.flutter.dev/testing/integration-tests)、[`pumpAndSettle`](https://api.flutter.dev/flutter/flutter_test/WidgetTester/pumpAndSettle.html)。既有原生历史规模和性能证据只在实际输入或依赖受影响时补验，不因更换 Waiting 测试组织方式自动失效。

普通功能集成验证操作后的可观察结果，不给宿主调度增加性能门槛。双击等有输入时序要求的手势使用官方 [`PointerEventRecord`](https://api.flutter.dev/flutter/flutter_test/WidgetTester/handlePointerEventRecord.html) 发送有效事件：首次按下满足最小间隔后，将首次释放与第二次点击放在同一事件包内，再核对真实界面与持久化结果，不要求 CI 两次异步调度之间的墙钟时间小于双击窗口。重新解码的不可变事实按完整业务字段比较；局部作用域、订阅等资源所有权仍按真实身份核对。测试层级遵循 Flutter 的[测试分层建议](https://docs.flutter.dev/testing/overview)，已有单元或组件测试能完整证明的规则不重复提升到原生桌面测试。

会话语言服务的原生用例使用 `cargo xtask test-project --suite desktop --case thread_lsp_status`。运行器通过现有隔离验收工具的 `thread-lsp-status` 场景自动准备全新 home、两个同名服务的项目目录和 `pl-provider-fixture`，不依赖会话临时脚本。界面状态、弹窗观察生命周期和重载交互由生产组件的视图模型及 Widget 测试证明；原生用例仅验证真实 Rust／FRB／Client 的主题与命令往返、会话绑定、另一项目进程不变与关闭回收，不重复界面断言或截图；证据保存在该次输出的 `thread-lsp-artifacts/`。当前进程身份核验仅覆盖 Linux。

十三个概念场景使用同故事本次原生页面对照。工具一个语义入口、思考组展开即读，真实多附件与三次单图调用区分；读图调用及图片/文字/错误结果证明留在原工作组成员内、不拆组。工具读取失败和媒体加载失败分别证明。性能分别报告首批有效内容可见（参考 p95≤500ms）与填满/EOF 总耗时、item 页数、成员页数、原子数/字节、正文加载量。长历史按展示 item 逐页经过；折叠组只占一条 item、成员页单独计成本，不将首批目标外推整体补满常数成本；不为填屏预读隐藏成员全文/媒体、COUNT 或 flush。

首内容布局不等于满屏。集成采样须在同代次有效、可见且正尺寸的真实视口完成布局后，分别记录几何已满或明确 EOF；测试观察到的完成帧是带采样精度的上界，不冒充更早的内部完成时刻。主批次接纳 item 数、实际读取请求数、累计返回 item/成员原子数和驻留展示单元数分别命名，重复读取计入成本。`conversation_work` 的批次校验日志复用预算所需的编码长度，记录完整产品 JSON 批次字节及 Atom/Source 条数；它不是传输 ACK、FRB 编码字节或物理磁盘 IO。Inline 载荷返回量和正文 range 请求/返回量分别汇总，失败或缺失记录不填零。

SQLite 查询工作量优先复用 SeaORM 的官方 metric callback，在实际执行连接上记录不含绑定值的语句、耗时与失败；不能给连接副本安装回调后冒称已观察原连接。种子写入、库存审计、Main、成员页和显式正文读取分别划定测量阶段，回调收集有界且溢出即证据无效。折叠大组的 Main 证据须实际命中摘要查询，并确认该阶段没有成员表或正文表查询；成员页返回量与 SQL 实际取回量分别报告，不能从可见 Widget 数反推。此类测试观察不增加生产查询、持久统计表、后台计量任务或新的业务接口。

存储工作量样本使用固定规模和原事实/原投影/原读取路径，分别保留重建耗时、源与派生写入量及成员索引空间的口径；库文件总体大小不是成员索引大小。SQL 调用、返回行、正文返回字节和物理磁盘 IO 不是同一指标，未观察的项明确标为未测。测试构建中的单次存储耗时不能冒充生产原生首内容可见 p95，后者仍使用同代次真实布局与固定平台/构建的独立采样。

时间线组件测试以不可变呈现数据驱动真实组件，覆盖静态尾卡、活动提示、折叠展开、遮蔽与同代次资源保留；分页与分组归约在视图模型或所属运行时验证。原生概念场景只保留实际桥接、执行释放、保存重开及媒体资源交接，不在 Flutter 层重新实现原件消费和成员分页协议。 `timeline-history` 的 2,000 项种子保留原生页面布局、分页和重开交接，原件逐字节完整性复用 Runtime 的积压测试；256,000 字节正文仍验证真实桥接连续读取及作用域关闭。回合终态与尾组封存分别判定，已完成回合可保留静态尾组；混合来源组的测试定位按实际成员分页查找，不能以首条成员代表全组来源。 后台结果与活动推理同时可见、摘要无正文时不产生展开控制，复用组件测试；原生实时场景只核对真实后台原件交付、界面工具输出及同一前台执行仍活动时的受限摘要读取，不重复实现双滚动视口的同帧捕获协议。

原生首内容采样复用 `manual-gui --preset conversation-read-work --profile-read-samples` 的隔离环境、原写入器种子和进程所有权；默认未传此标志的功能集成入口不变。采样使用独立的 provider 预置脚本生成两条各至少 20,000 个 Main item 的会话；每条会话固定以 200 个正常轮次、每轮 100 段独立完成的文本生成共 20,000 段模型正文，每段正文仍为 32 UTF-8 bytes，轮内事件间延迟仍为零。每轮按下文固定目标确认保存后才开始下一轮；不直接写 SQLite，不提高容量、不插入输出节流或故障恢复重试。原十轮 × 2,000 段的累计增长压力场景保持原批次和 pacing，不用读取性能预置替代其证据。两条会话保存、准备完成并关闭种子所有者后，分别采集 20 个新应用进程的普通冷读和 20 次同进程 A→B→A 切换。报告分别记录模型正文段数、正常输入轮次数和真实 Main 库存，不将事件、token 或用户输入补足模型正文分母；实际 item 数、Flutter Profile 与 Rust 桥构建配置及构件身份、操作系统缓存未受控等条件随报告记录；不将播种、审计扫描或重建纳入有效读模型的首内容时间。

大历史种子及后续增长仍经过生产上下文准备。严格 fixture 在已有历史的批次间至多安排一次可选文本压缩响应，复用现有压缩请求的精确末条提示匹配，不接纳任意请求、不新增原生压缩兼容分支；首个种子及独立参考会话没有这一历史前置。压缩可发生也可不发生，但不能替代任何必需批次或计入已写入的 Main 库存；各场景按自身约定保持批次数、逐项正文、身份、请求容量和 pacing，不截取另一场景的步骤充当完整预置。不得通过提高模型上下文或预算、关闭自动压缩、改写数据库或放宽匹配来准备数据；准备失败仍保存完整未执行分母，只有完成原真实库存审计后才进入采样。

Profile 播种的每批 `TurnCompleted` 只证明原轮次完成，不代替保存确认。收到同一输入的成功终态后，固定同一 Thread 快照的提交 revision，在原单批 900 秒操作期限内等待现有持久化协调器报告该 Thread 的历史与检查点耐久水位均覆盖这个固定目标，再提交下一必需批次；等待不进入性能时钟，不新增保存接口、恢复重试或第二写入器。每批保留原输入、轮次、目标及实际水位回执；未知水位不补零，真实故障立即失败并保留已取得的回执，不因队列随后排空而自动解除故障，也不提高容量、运行中自适应缩批或通过固定睡眠宣告保存成功。此预置证明累计历史的读取性能，不证明单次零延迟超容量输出可被无条件接纳；后者仍遵循生产在途增量计费、容量拒绝、材料保全及显式恢复合同。

`run-gui --native-launch --profile --inspect --capture` 仅为显式非发布观察装配官方 Flutter Driver extension，普通发布入口不包含它；debug 的 MCP 组件树能力不外推到 profile。操作沿官方 Driver 的查找、点击与滚动，不恢复 `test_driver/`、`requestData`、自定义控制消息或第二套 UI。仅在非 release 且启用 `ANYWORK_CAPTURE` 时注册只读 `ext.anywork.timelineLayout`：同步借用当前可见、已挂载且未退役的原展示 lease，返回会话/选择/展示代次与已有首内容布局时间戳；未布局为 pending、无有效窗口为 unavailable，不触发读取、分页、执行或布局，也不以零值代替未测。

每个样本保留原 `selectionStartedMicros`、`layoutCompletedMicros`、selectionId、generation 和 itemId，严格在同一 owner 时钟内计算 elapsed。采集端观察到结果的时间不是布局完成时间；旧选择或旧代次不得成为新样本。两类样本独立报告样本数、失败/未执行数、p50、nearest-rank p95 和最大值，完整有效样本的 p95 目标保持 500 ms；缺失、模式错误或超时使采样失败，不丢弃失败样本或补零。关闭请求受理、Driver 连接释放、原生进程真实退出和所属后代收束分别确认，原有 20k 库存人工入口的 notMeasured 结果不因此自动升级为性能通过。

原生关闭验收区分正常协调关闭与隔离层阻塞后的强制退出。正常关闭继续核对所属资源停止与原生退出，不能用裁判强制回收冒充产品自行收束。强制退出阶段仅裁判真实退出状态和单一 30 秒期限，分别保存退出时仍存在的后代、观察结果及裁判清理；统一 native 执行器不再为每个业务进程创建独立 subreaper，应用强制结束后不能运行其异步析构，因此不把后代回收列为该阶段已证明的产品保证。相关机器检查标记为不保证，不能写成全部进程树已回收。

Linux 主进程的退出计时以实际停止运行为界，已进入 zombie 状态不能因父进程稍后 reap 而继续累计退出耗时；裁判仍须等待启动器并核对真实退出码。子进程树清理继续要求原 PID／启动身份消失，不能用“已退出但尚未回收”代替完整回收，也不改变原有关闭时限。

## 24.2 模拟对端与真实模型观察

本地模拟供应商服务（`pl-provider-fixture`）同时支撑自动化测试与 GUI 人工验收：仅监听本地回环动态端口，按固定提示词、协议及期望轮次返回预设的 HTTP/SSE 或 WebSocket 事件流，严格校验请求关键字段、调用顺序与鉴权头，对未登记或错序请求直接返回失败。模拟服务仅证明当前实现与约定协议样本的行为一致，不替代真实厂商线上接口兼容性验证。

既有受控消费者区分后台工具通知、子轮次报告、审查异常与完整反馈；`Task task:` 通知匹配不放宽成任意 user 文本，工具受理不冒充执行完成。报告、异常和反馈复用各自的类型化解码及真实关联身份；正文及元数据可包含合法空行，不能凭第一个空行错误截取正文。消费者只调用当前实际装配的工具；文件发现与读取迁移到获授权的 `exec` 后，不保留调用已移除 `read_file`、`list_files` 的现役脚本或兼容分支，也不把文件许可当作命令许可。受控输入不是可验签的来源凭证，也不能代替真实宿主调度证据。

真实模型、协作及更新器观察复用产品入口和上述实验方法，不保留专项 `examples` 采集程序或长期提交的一次性实验脚本。涉及真实账号、费用或外部写入须先获具体授权；使用已有配置及凭据关联，不复制正在写入的历史库，不另造业务运行时。

需要从用户设置读取选定账号的观察入口显式指定源 Studio home，并通过 `ConfigStore::for_studio_home` 保留原凭据关联；隔离运行的写入 home 仍由 `StudioRuntimeOptions.studio_home` 单独指定。源目录解析不依赖测试进程的临时 `HOME`，也不复制配置或添加链接来修复路径错误。远端测试显式注入 SSH 配置句柄，使目录解析与实际 OpenSSH 命令使用同一份文件，不能仅凭设置临时 `HOME` 就声称已隔离 SSH。

受控真实观察沿生产提交入口设置执行预算：原生 Rust 调用者可通过 `StudioSubmitPromptOptions.max_model_steps` 为本次提交指定非零上限，直接交给原 Thread 的 `InputDriverOptions`，不另建计数器或通过提示词模拟限额。省略时保留原有根会话不限步数、子会话固定上限的行为；对子会话指定的预算只能收紧既有上限。该选项不是用户配置或线协议字段，不改变已接纳 input 的执行预算；场景期限、调用次数和关闭收束仍分别记录。

MCP 的真实模型观察须经过生产 Thread、工具注册与 MCP owner，不以直接 SDK 请求或单独启动服务代替产品验证。多智能体场景用不同项目根及可区分的符号／诊断验证会话隔离，只中断本次拥有的一个服务或 SSH 连接，检查其失败、显式重建、状态重新设置和后续调用，同时确认兄弟成员不受影响。协议夹具可证明超时、目录换代与取消等确定性交错，不能外推为官方 Dart MCP 或真实模型已通过。证据分别记录真实 account/model、版本、执行端、连接／进程身份、调用次数与结果，失败仍保留脱敏日志；关闭必须核对所属任务、I/O 与进程退出，不把脚本结束或取消受理当作清理完成。临时项目、故障注入脚本与产物使用本次会话目录，不修改真实用户配置或无关连接。

模型策略、业务结果、事件采集、持久历史和资源关闭分别取证。绑定真实 Thread/Turn/task 身份和版本；只有连续消费并确认覆盖区间的通知才声称完整，缺口或未出现的路径保持未知。工作流完成、执行静止、存储健康且耐久水位追平、物理资源回收不是同一事实。实际工作区的前后版本及差异只读记录，不通过 reset、stash 或提交改变实验输入，不重复运行挑选漂亮样本。

## 24.3 原生 GUI 观察与隔离

原生 AI 观察通过专用 debug `--inspect` 入口启用官方 Flutter Driver extension，MCP 连接已运行的应用；正式入口和 `integration_test` binding 不注册该交互扩展。Inspector 与 MCP 不提供操作系统显示服务：Linux 无显示环境使用 Xvfb，Windows 使用可运行桌面应用的会话；Flutter 层操作和截图不证明原生输入法或系统菜单。

原生工程启动区分构建准备与产品启动。通用隔离入口复用 native launcher 已有构建路径，
准备完成、构件校验后才发布启动边界；沿现有 `startup_stage` 诊断表达这一工程阶段，
不新增 CLI、UI 调试协议或平行 builder。VM 就绪期限从启动边界开始，保持现有期限；
不能从外层 Cargo 启动时计入首次 helper/bridge/Flutter 编译，也不因超时反复重跑热缓存或延长就绪期限。
准备仍受原命令的取消与调用方总预算约束，fixture/构建进程退出立即失败，保留实际首错。

`test-project` 的 desktop 与 native 套件共用调用内的准备租约，父进程等待全部场景结束后才释放。
native 套件只准备一次 debug bridge、helper 和 Pub 依赖；按实际 Flutter 构建参数区分入口、capture、版本与模式，
每种配置首次构建后完整复制到租约目录，后续启动校验源码、宿主、构建环境、工具链及程序包内容、权限和符号链接。
配置切换不能覆盖已有程序包；profile/demo 不消费这份 native debug 准备。租约失效、产物缺失、变化或准备中断均失败，
不回退为隐式重建，也不跨调用、跨作业复用。独立 `run-gui --native-launch` 未继承准备时仍执行正常构建。
公共准备、首次构建、校验复用分别记录 `startup_stage` 耗时，原生运行时间仍来自真实退出报告。
每次场景独立启动进程；home、fixture、共享重开阶段、退出期限和进程树回收责任保持原有归属。

失败收尾按实际阶段承担责任：未到产品启动边界时停止、等待所属构建进程，不要求尚不存在的
产品退出报告，也不称为正常产品退出；一旦跨过边界仍须等待原生 owner 与报告屏障。
阶段事实由实际 native 启动路径单一发布，不能以日志安静、固定 sleep 或文件存在猜测准备完成。

Linux 准备阶段在直接 child 已回收、所属构建进程组已消失后重读最终阶段日志，
确认没有跨过产品启动边界，才按“产品未启动”收束；查询失败仍是未知，不把 root 退出当作整树退出。
Windows 每次验收启动使用独立 Job，依赖负责在子进程恢复执行前完成关联并保留显式 creation flags；
这不等同于创建进程时的原子 Job 关联。root 状态、终止请求与 Job 为空分别观察；
取消准备时终止该 Job，在原清理预算内确认 root 已回收且活动进程数为零，再重读最终阶段日志。
Job 查询使用 Windows 官方 accounting API，失败保持未知；不以完成端口通知、`taskkill` 成功或 PID 快照代证完成。
进程级 Job 只作最后后备，不能用于判断单次准备树为空。等待预算属于调用方，析构不启动第二轮等待。
Linux／Windows 跨过产品启动边界后仍要求原生 owner／退出报告屏障；其他宿主始终保留该屏障。
Windows 后台 launcher 没有可定向的控制台信号；产品 VM 就绪后，EOF／取消收尾复用已有
产品退出请求，并与 Job 完成查询共享原清理期限，不重启等待预算，原会话仍判失败。
缺少报告时保持失败及回收未确认，不用不存在的报告证明成功。

本地模拟 GUI 人工验收由独立工程工具 `pl-studio-acceptance` 编排（通过 `cargo xtask manual-gui --preset` 按需编译并透传参数，复用 `pl-dev-support` 的路径与进程树管理，并在服务就绪计时前完成固件编译）。真实厂商与模型的原生人工观察使用 `cargo xtask run-gui` 读取用户已有配置，不能把模拟供应商结果外推为真实模型行为。按实际入口核对真实窗口截图、界面组件树（widget tree）、权威快照、必要请求/诊断和所属进程真实回收；没有模拟服务的观察不虚构模拟请求记录。脚本退出码仅表示采集流程完成，最终视觉与交互结论由人工核查截图后独立判定（默认标记为“待评审”）。

通用 MCP 实验允许管道 stdin，不要求 TTY 或手动重复记录 UI 动作。人工验收复用已有 debug
native launcher、同一个官方 `inspect_main.dart` 和 `anywork-native-exit/1` 报告，以取得产品
真实退出码及后代回收证据，不以 Flutter resident 工具的零退出码代证产品正常退出。
MCP 可通过本次 VM Service 直接附着；此验收载体不提供 resident 热重载，纯界面迭代仍用预览，
确需跨层开发热重载时才使用普通 `run-gui --inspect`，其退出码不充作原生验收。

截图在操作时由官方 MCP 采集，`done` 只请求产品正常退出、等待所属启动器并校验原生退出报告；
EOF、取消、报告缺失、非零退出或强制回收残留均保持失败。系统 `xvfb-run` 持有虚拟显示，
必须等待原命令终态，不把退出请求或截图成功当作进程已回收。自定义内容捕获只服务现有自动化及
原生测量，不作为平行人工截图入口；不新增调试协议、状态镜像或另一套 runner。

多阶段原生旅程的诊断归档与阶段成功判定独立：已经产生的 GUI 日志在阶段失败时仍须脱敏保留，不能因该阶段未进入成功清单而随隔离环境删除。日志归档不补造未观察到的退出状态，不改变原始失败退出或后续阶段的准入条件。

FRB 慢消费者的严格等待证据来自同一 producer 的实际 credit 等待：通知 future 被轮询为 `Pending` 时，还须核对该订阅仍占满一个普通批次的未确认窗口并保持开放，才记录这次等待。每次等待调用至多保留一条诊断，只含订阅身份与 sent/acknowledged 计数，不复制正文、不消费通知、不改变 ACK、取消或关闭语义。验收在隔离 GUI 进程中仅为该诊断目标启用日志，并在原有收尾内归档其有界元数据；缺失、截断或无法关联到同次运行的持有订阅都不能判为已进入等待。未出现后继 Dart 回调、拒绝未来 ACK 或在 `await` 前记录意图仍保留为各自证据，不能单独替代真实等待信号。

计划详情的正文呈现须由实际正文子树的渲染文字证明，不能仅回读计划快照或匹配面板标题。验收读取已布局的 `Text`、`RichText` 或其公开扩展；缺失、截断或不匹配的正文仍为失败。

活动成员的展开验收绑定真实条目身份和已挂载标题，读取其纯视图公开的展开属性；官方展开组件仍读取其公开控制器。未知或缺失的状态不得解释为收起，详情入口中复用的活动行不得替代成员标题。展开与收起通过真实指针触发，并结合正文尺寸、滚动几何及同一展示代次判定，不为验收创建领域所有者或额外生产状态。

人工验收 harness 使用官方 Cargo `release` profile 构建独立的 `pl-provider-fixture` 可执行文件，构建和产物定位仍由 Cargo 负责并在服务期限开始前完成；这不改变 GUI 的 debug/profile 选择，也不改变自动化测试链接 fixture 库的构建模式。优化构建用于避免大型完整请求证据的序列化成本挤占退出预算，不允许因此删减记录、改变受控协议步骤或放宽既定停止期限。最终证据仍须完整写入并原子发布，且必须观察到供应商进程真实退出；两者缺一均视为验收失败。

PR 中适用的 functional 与 native 生命周期由独立 Linux 作业通过 xtask 的 `test-project` 两类 suite 并行执行，桌面功能使用完整集合的确定性分片；Windows/macOS 仅按分类执行 clippy 与生产应用编译。目标宿主的运行行为可通过显式本地 `cargo xtask test-project` 验证，PR 标签不追加平台测试或截图采集。人工观察仍用 `cargo xtask manual-gui --preset`，人类 verdict 保持 pending。

Linux 自动桌面与原生作业除 Xvfb 外，还须显式提供可初始化的系统凭据服务：在作业自有隔离目录内使用独立 D-Bus session、仅启用 secrets 组件的 GNOME Keyring 及私有 XDG 数据、配置和运行目录，不访问操作者已有凭据库。复用官方 `dbus-run-session` 管理 bus 生命周期，等待 `org.freedesktop.secrets` 注册后再运行原 xtask；服务名就绪不替代产品实际初始化和业务验收。精确 Linux 镜像声明相应命令依赖，不依赖宿主恰好已有桌面登录会话。

依赖 X11 的 PID 归属窗口控制须与 GUI 实际后端一致。`xvfb-run` 只设置显示与认证变量，不限定 GTK 后端；即使没有 `WAYLAND_DISPLAY`，GTK 仍可能连接继承运行目录中的默认 Wayland socket。此类 Linux Xvfb 验收用命令级 `GDK_BACKEND=x11` 明确后端，例如 `GDK_BACKEND=x11 xvfb-run -a cargo xtask test-project --suite desktop --case realtime_presentation`；不改全局环境、不清除用户运行目录，也不把生产应用强制为 X11。继续验证真实 PID、唯一可见窗口及实际尺寸，不能以 `DISPLAY` 存在或查询连通代替窗口归属证明。官方后端选择语义见 [GTK 3 环境变量](https://docs.gtk.org/gtk3/running.html)。

背景结果正文、前台概要和工作组标题的同帧共存由组件测试挂载真实 `CompletionRunView` 与 `TimelineMemberAtom`，保留字形、各层裁剪和命中断言；原生测试证明跨桥接来源、实际概要观察、原件正文与任务生命周期。仍需在原生场景证明的同帧多目标可见性须固定并核验真实原生视口，不能仅记录请求尺寸，也不能让是否输出截图决定场景几何。复用既有原生窗口控制和 Flutter 官方字形定位，保留原 ScrollPosition 身份、实际滚动轴向、所有裁剪层的可见性与命中检查；反向列表的滚动起边不等于屏幕上沿。程序定位只准备几何，用户阅读意图仍由真实滚动输入产生；手势须符合官方测试控制器的拖动阈值，不能通过直接派发阅读模式或替换控制器伪造“返回最新”旅程。

隔离服务的启动失败使该命令失败；正常或失败结束都须终止并等待自有 daemon，保留被包裹命令的原退出状态，再清理自有目录。服务就绪、业务与退出分别判定，不延长既有场景期限，不把凭据服务不可访问改成条目缺失或内存凭据成功。Keyring 的 `NoDefaultStore` 可以表示其一次原生初始化失败，不能单凭该类别推定具体 D-Bus 原因或缺少手动注册。

独立 bus 结束不等于其私有运行目录内的 FUSE 挂载已经消失。退出清理先核对本次新建根目录的身份和所属用户，使用 util-linux `findmnt` 的结构化挂载信息，只对该目录内精确的 `runtime/doc`（`fuse.portal`）和 `runtime/gvfs`（`fuse.gvfsd-fuse`）、且 `user_id` 属于当前用户的挂载调用一次官方 `fusermount3 -u`。挂载已自然消失则不卸载；未知挂载、身份变化、普通卸载失败或复核仍有挂载时保留目录并明确失败，不使用强制／懒卸载、不操作用户会话挂载、不跨挂载递归删除。只有该私有根目录内已无挂载，才删除本次自有目录。清理失败不覆盖原命令的非零退出码；原命令成功而清理失败时，包装命令必须失败，不能把业务与资源收束合并成成功。

实时工具的运行态观察不依赖测试在有限命令结束前碰巧展开成员窗口。并行命令与 host-cwd 命令复用严格环回 fixture 的既有 observer gate：对端先交付一个已完成的 reasoning 前缀，测试通过原 UI 打开并稳定布局该 Turn 的唯一工作组，冻结原 Main、成员窗口和正文 scope 身份后才释放原工具调用。内核按顺序启动每个 exec，前台等待一秒后转入后台，因此不要求两个前台成员同时 Active。放行后须在这些原观察对象上证明精确 exec 的后台交接、typed `backgroundStarted`、不同的非空 task 身份及实际布局，不以同组 wait-call 替代；交接只证明任务已受理，实际后台交错与最终成功由后续独立来源结果证明。原命令、cwd、时长、预算、收据交付及后续正文读取与 UI 关闭门槛保持不变。gate 只控制模拟对端的事件交付，不写产品状态、不新建产品 reader／owner，也不通过延长命令或观察期限制造通过。

实时工具的最终回执从原工作组成员读取。前台交接成员只建立 call 与 task 身份关联，后台最终结果必须来自同一 Turn、call 和 task 对应的独立来源工作组；交接不等于成功。正文读取绑定原 Main 工作组、成员引用、正文窗口及实际挂载行，同时保持原 Main 滚动实例与成员内部滚动实例的身份，继续验证成功退出、完整正文和关闭后的资源撤销。回执诊断随 Linux 场景报告归档，不以诊断数据替代真实界面读取。

完成答案的验证区分 Main 已接纳目标与目标已在当前视口布局：先按原 Turn、文本种类、最终答案渠道及完成终态资格确定唯一 Main item，再复用既有原 UI 揭示路径和 canonical 行身份检查，要求该行的真实答案正文可见；不能把屏幕当前未挂载当作历史中不存在，也不能以别的 Turn、缓存副本或后台工具正文代替。保留原生产“返回最新”交互，目标资格、揭示和正文检查共用原两分钟答案期限，揭示还受既有六十秒上限约束，不为每一步重置或叠加等待预算。只传播剩余期限，不增加 reader、读取旁路、直接滚动坐标或失败后的替代路径。

Main 揭示区分外层 canonical `ChatMessage` 已挂载、原 controller metadata unit 已接纳、
内部 `ChatItemView` renderer 已就绪及实际裁剪可见。外层行、connector、内层分别诊断，
不得把 metadata 加载占位误判成没有行，也不得把占位当成功；沿同一 Scrollable、lease、
generation 和原期限等待真实 renderer，错误明确失败，不加 sleep、泛重试或放宽命中门槛。
Main 接纳先于界面帧切换时，实时区域可以暂留同标识片段；揭示只在原 Main Scrollable
子树定位目标及工作组标题，继续核对原 metadata 和 canonical 行，不借用实时区域的片段或更换滚动实例。

依次读取已完成的独立工具回执时，原 UI 关闭须先证明当前挂载标题的展开态已变为 false，再确认原正文窗口撤销；下一项的 Main 揭示在折叠动画和随后的滚动修正完成后开始。该完成态场景复用 Flutter 官方 `WidgetTester.pumpAndSettle`，只使用原六十秒窗口撤销期限的剩余额度，未收束或框架错误明确失败，不在揭示失败后追加点击或滚动重试，也不以目标卸载代替关闭成功。

概念场景的读图验收分别核对原前台开始、封存观察和真实最终结果：四十条思考与四次读图调用保留真实唯一关联，展示行数按当前组内合并和跨组新结束记录确定，不硬锁为一个四十四成员组。封存时尚未结束的记录不因后来结果变化，后台交接保留 `backgroundHandoff`／`transferred` 及非空任务身份，真正结果按同一 Turn、call 和 task 定位新记录，交接本身不满足成功或失败。三份真实媒体及一次真实错误从最终呈现读取，不能为旧计数回填旧组或构造 Atom。沿原 UI 揭示成员或 Main 回执，继续验证图片加载、Viewer、媒体丢失、错误正文及原范围与资源撤销；最终资格纳入原等待期限，不增加替代读取或预算。

实时场景先在 Windows 执行真实目录身份回归，确认普通盘符路径与扩展路径可指向同一实体，并仍拒绝工作区内路径及错误目标。目录等价复用 `dart:io` 的文件系统身份能力，不以解析后的路径字符串必须一致作为额外条件；Linux 跳过 Windows 专项不算目标平台通过，目录回归也不替代原生工具执行与实际 cwd 的交付证明。

CI 在场景启动前显式完成同次源码、相同 Cargo 配置的 Rust bridge 构建：profile 场景使用 `release`，debug 场景使用默认开发配置。独立构建步骤保留完整编译失败，不让首次冷编译占用原生 VM 就绪期限；场景仍由 xtask 校验并消费构件，原有就绪、交互及退出期限保持不变。预构建成功不证明原生程序已启动或任何验收通过。

CI 采集的 profile 帧与截图只代表该 Windows runner、构建模式和场景，人工结论仍须独立核对，不能外推为用户硬件的稳态性能。工作流仅归档正式场景证据，排除隔离环境目录、home、数据库及保留环境清单；截图作为 PR 图片交付前仍须检查内容并按仓库附件规则上传回读。未产出的指标和未执行场景保持缺失，不由工作流退出成功补造。

升级恢复验收可通过 `cargo xtask manual-gui --preset gui --seed-home-copy <DIR>` 消费已关闭、经 SQLite backup API 制作的一致性 home 副本。工具只读复制该输入到自有隔离环境，拒绝带 WAL/SHM 或符号链接的输入；保留项目、会话及账本事实，将账号端点切换为本地模拟供应商，并在启动前禁用机器人外发、MCP、LSP 与 ACP。来源副本和真实数据根都不修改；截图、快照、迁移前后数据库核对及进程回收共同构成证据。副本模式通过原生启动器运行，人工操作结束后请求产品退出，并核对原生退出报告中的退出码和子进程回收结果。

## 24.4 呈现诊断与受控账号对端

Widget Previewer 可以提供纯呈现证据，不装配 Client 或 Rust bridge 的预览不证明真实保存、订阅或原生资源行为。实时状态及时间线的产品契约见 [25](./25-frontend-state.md) 和 [26](./26-timeline-content.md)，此处不另设全领域验收矩阵。

账号组件预览直接消费生产 View/Widget、不可变呈现值及生产主题与本地化，观察宽窄布局、错误与未知状态、局部草稿和菜单回调。源码变化、同页渲染变化及恢复状态可提供热更新证据；预览动作不等于 canonical 保存，真实 bridge、凭据和持久化仍由对应原生观察提供证据。

账号只读诊断只读取已经装配的领域镜像和已存在的呈现实例：读取详情、编辑或模型资料前确认对应 ViewModel 已存在，不为诊断初始化 provider、创建详情槽、发起查询或声明可见需求。领域来源、具体目标、版本及过期状态分别表达，未观察的信息保持未知；已退役的整卡字段与兼容占位键随所有旅程消费者一起删除。验收专用呈现诊断只暴露选择、编辑身份、dirty、保存阶段、草稿修订及已有资料读取阶段，不序列化凭据、原始密钥输入或资源所有者。人工与测试交互复用生产控件的带账号类型与模型复合身份的稳定 key，业务变化仍由真实界面动作触发；测试脚本不通过直接修改 provider 或调用仓储命令制造成功。

普通 Native 账号的人工旅程使用显式鼠标事件覆盖列表菜单与编辑入口，并验证菜单不会误触详情。文本复制分别经过标准快捷键与真实右键菜单的 Copy 动作，以不同的合成文本回读平台剪贴板，不能直接写入期望内容来制造通过。主键、修饰键的按下与释放走真实键盘；鼠标主键与次键由 Flutter 官方指针派发处理。旅程继续核对模型三标签往返保留草稿、显式保存、恢复自动及离页时继续编辑／放弃的 canonical 结果；进程中断、断言失败与未执行的 fixture 主步骤均单独记录，不合并成完整通过。

账号模拟对端允许在同一进程生命周期通过显式受控动作切换目录清单、单账号失败及请求闸门，用于证明无需重启的同步、重复请求合并与迟到结果隔离；不通过重启 GUI 或直接改产品状态制造成功。控制只作用于本次隔离环回对端，保留请求计数、命名状态和闸门释放证据，不记录真实凭据。控制文件仍是启动输入，修改文件不隐式改变运行中的对端；等待由明确请求/释放信号驱动，退出必须唤醒并回收所有闸门等待者。

目录对端控制证据每个供应商实例最多保留 **256 个已受理请求身份**、最多 **16 个同时等待的闸门请求**，完整状态响应上限 **64 KiB**。达到任一边界后在受理前明确拒绝，不增加受理计数或遗留等待登记；身份和计数使用受检递增，不回绕复用。已受理证据在预算内完整保留，不静默截断；闸门等待登记在请求完成、传输取消与关闭时释放，不能把已取消记录当真实在途证据。无参数控制动作同样拒绝额外字段，HTTP 语法/结构错误沿框架原始错误分类返回。

## 24.5 显式统计管线性能基准

统计保存、读取与发布的性能对比使用 `pl-studio-runtime` 的 `statistics_pipeline` Criterion benchmark，仅通过非默认 `benchmarks` feature 启用。基准目标使用独立 harness 并关闭普通测试准入；默认 `cargo test`、`cargo clippy --workspace --all-targets`、GUI/Client 验证与 PR CI 不运行性能采样或压力负载，不以机器敏感的耗时比率作为日常 CI 门槛。

```sh
cargo bench --locked -p pl-studio-runtime --features benchmarks --bench statistics_pipeline -- --save-baseline before
cargo bench --locked -p pl-studio-runtime --features benchmarks --bench statistics_pipeline -- --baseline before
```

基准直接调用实际生产链路；数据准备、编译和迁移不混入正常读写测量，不关闭 SQLite 或文件同步保证换取速度。基线在生产重构前以相同 benchmark 和观察钩子实际采集，保存源版本、负载身份、锁文件、工具链、运行配置和原始样本；不在生产代码中保留旧实现作为对照。

比较使用同一机器、文件系统、优化级别、种子、数据规模、并发和同步设置，预热后至少三轮独立采样。对等场景先核对完成工作量与结果身份，语义有意变化的场景单列，不以少返回数据获取表面加速。覆盖历史窗口 `0/100/3000`、单条/批量落盘与轮转、无计费变化效应、多 Thread 干扰、多 root 费用及读写并行。

报告同时保留耗时分布、吞吐、95% 置信区间和操作量，单操作 p50/p95 不得用批均值分位数冒充。采样前固定噪声阈值 `5%`，主要瓶颈需可重复改善，对照场景的显著回退必须分析处理；不择优报告或事后变更负载、门槛。内存查询计划、操作计数、Rust 基准和 Linux 模拟分别有证据边界，不能替代真实磁盘、GUI 帧率或跨平台结论。

允许少量正常波动的优化任务，噪声范围内的变化与必要成本下界可记为持平，不要求每个观察项都显著下降，也不把持平描述成改善。宽置信区间、受扰或未完成的对照属于证据有限；单次同步等待或少量尾分位样本不能直接定性为产品因果，但明确持续的明显回退仍须分析。保存模型移除冗余诊断义务后，基准须分别命名可靠保存与真实诊断完成条件，验证两侧保存相同的可靠事实并披露完成条件变化；不得把新场景冒充旧空诊断水位场景的完全等价结果。

Linux 基准同时读取本进程 `/proc/self/io` 的 `read_bytes`、`write_bytes`、`cancelled_write_bytes`，按独立观测区间报告存储层字节及 MiB/s，而非将应用记录吞吐当作磁盘字节吞吐。区间不含夹具准备、关闭与报告写入，包含操作和结果校验；不清系统缓存，缓存命中的零磁盘读取是实际结果。内核取消写回单列，不将计数冒充设备介质吞吐或全机 I/O。非 Linux 明确记录不可用，不补零；Linux 读取失败使基准失败。依据 [proc_pid_io(5)](https://man7.org/linux/man-pages/man5/proc_pid_io.5.html) 解释内核记账、截断及非原子读取边界。

队列年龄在真实 calls 写者取批时，由既有受理时刻直接观测，记录条目数、年龄总和与本操作最大年龄，不用受理至耐久完成的延迟替代。此值不含本次取批后的 append/sync/SQL；重试时仍基于原受理时刻，可能包含先前尝试，须与无故障场景区分。补充观测需要历史对照时，在隔离的历史源码上只增加相同观测钩子，另存实际版本、差异和新轮次；原前测及缺失字段保持原样，不倒填历史数据。

合成数据库使用执行会话 scratch；基准工具的标准结果保留在其实际输出入口，对比汇总与交付副本使用 artifacts。源码仅保留通用基准、负载与运行说明，不沉淀一次性数据库、机器日志或会话绝对路径。功能和故障回归仍可进入普通 CI，与显式性能验收分离。

### 有界短诊断

标准基准与有界诊断使用显式区分的 profile；标准入口、负载及参数不因短诊断而变化。短诊断使用 Criterion 的 10 个样本、250 ms 预热目标、500 ms 测量目标、100000 次 bootstrap、95% 置信水平与 5% 噪声阈值，另取 4 次真实操作分布。必须报告实际次数和时长，不能将目标采样时间当作进程墙钟保证，亦不能以如此短的分布证明稳定尾延迟。

每个问题在执行前固定假设、对照版本、场景、参数、顺序与停止条件；定位和修后实验累计不超过 60 秒，夹具准备、校验和收尾均计入墙钟预算，构建与负载预检单独记录。优先复用既有定位证据，超时、失败或受扰后保留现场与结果，不追加轮次择优报告。预算内无法完成原场景时，可使用另行命名的真实子链诊断或如实标为未覆盖，不能把子链结果冒充原场景或完整矩阵通过。

诊断对照两侧使用相同方法并记录源码、二进制、环境、工作量与参数身份；方法不同的短诊断与标准轮结果不直接混合计算百分比。同步调用内等待、覆盖其前处理的耐久区间与实际写入工作量分别报告，不把等待在测量边界内外重新分配直接认作代码缺陷，也不通过延后同步美化单个指标。缺乏统计功效、未证实改善或仍有回退的项目保持原始结论，不以操作次数下降替代实测。

## 24.6 其他观察入口与证据范围

- 机器人本地协议对端、真实平台授权和客户端渲染是不同边界，见 [27](./27-bots.md#279-验收边界)。模拟平台或 CLI 自发自读不能证明真实产品回复；真实账号操作仍受明确授权与凭据脱敏约束。
- ACP 安装和认证观察见 [28](./28-acp.md#2810-登录验收)。固定发行的发布摘要不可用合成 ZIP 替代；协议/Client 受控回归和真实官方准备、浏览器授权、额度及重启验证分别报告。受控网络对端不授权关闭 TLS、摘要校验或扩大生产下载来源。
- 工作树关闭、存储迁移、上下文恢复及账号隔离的行为分别由对应产品设计定义。本地样例、旧接口结果和未完成采集不构成这些行为已经验证的证据。

### ChatGPT 登录与额度

账户认证和额度界面的受控回归位于 `test/ui/chatgpt_auth_test.dart`，ACP 认证旅程位于 `test/ui/acp_auth_test.dart`：使用真实 AppGraph、Client、路由、Riverpod 和生产组件，只控制外部认证／额度回复，覆盖取消与迟到事件、重复点击、认证切换、保存身份、额度刷新、页面返回、删除后新建不复用身份。这些旅程不连接 Rust/FRB，也不验证原生窗口，由官方 widget 测试执行即可；共享受控 transport 位于 `test/support/`，不再为它们构建原生桌面程序。协议签名、凭据轮换和网络归属仍在 Rust／纯 Client 所有者边界验证；纯 Client 编码断言归 Client 测试。Windows 凭据协调器另以唯一测试别名验证跨配置同名冲突不覆盖、大体积 OAuth 保存与重新打开、事务清理，不触碰用户已有别名。真实账号授权仍由下述显式原生验收验证。

真实人工验收也由 `cargo xtask test-project --suite desktop --case chatgpt_real_login` 启动，使用隔离的应用数据根和系统凭据关联。`ANYWORK_CHATGPT_ACCEPTANCE=login` 完成官方浏览器授权、真实保存、额度和在线模型查询；同一数据根的 `restart` 阶段重新加载凭据并查询。该场景须显式选择并提供阶段变量，不进入默认 CI 套件。WidgetTester 操作生产控件，人只操作官方浏览器的账户、验证码和同意授权，不依赖 Driver、requestData 脚本或固定人工等待期限。`ANYWORK_CHATGPT_EVIDENCE` 指定工具产物目录，截图在编码前遮蔽 email／workspace；列表通过生产搜索框筛选验收账户，不采集其他账户的余额。两次运行分别检查生产关闭报告的 completed、clean、drained；实际平台、授权、额度与推理覆盖独立报告。

## 24.7 流式输出的现实规模基准

## 24.8 Linux 累计两万历史与持续增长观测

累计历史容量与单次模型输出是两种工况。Linux 的 `timeline-history-20k` 复用既有原生验收、模拟供应商、正常 writer、Flutter 内容捕获和帧记录入口：先在同一会话用十轮、每轮 2,000 个独立完成文本 item 累积历史并确认保存，再退出所属进程并以同一隔离 home 冷重开。每个合成文本正文固定为 32 个 UTF-8 字节；报告同时列出 20,000 个文本展示 item 与包含用户输入等事实的精确历史总数、正文总字节及数据库规模，不把成员原子、事件、token 或正文块数当成展示 item 数。该形态侧重历史 item 与元数据容量，不替代大正文、Markdown 或图片工况。

冷加载样本在同一已保存基线上运行独立 GUI 生命周期，构建时间不混入加载时间。分别记录进程启动、内容捕获可观察、选择原会话、同代次首个实际内容布局及视口填充边界；轮次间核对数据库/会话身份。明确报告进程冷启动、样本量和未清除 Linux 页缓存，不称物理磁盘冷缓存。首屏/静置的 controller 消息数、before 和页请求数证明未载入全历史。旧页用真实滚轮/滚动条触发，记录每页延迟、加载增长、cursor 和顺序；显式 load-older 不单独替代滚动证据。旧版三生命周期观测只代表其实际版本，不充作新协议 p95 样本。

冷打开比较按稳定顺序读取的完成记录、history item/turn 的身份、顺序和完整 payload，不只比较行数。applied_write_seq 是 effect 保存水位，不是条目数。被动只读打开不新增执行生命周期 effect，打开/滚动区间的 history admitted 水位应不变；已有保存允许追平，真正执行/显式关停产生的变化按事实单列，不能为保留旧断言激活执行。

进程冷读的保存队列证据须来自已接纳且连接有效的原产品基线，未收到基线不能编码成空队列。当前格式、没有既有执行 source 的独立冷读生命周期要求采样时没有 Thread writer 行及待保存义务；它没有可报告的 live H/D，不补造零值。结合关闭前后的完整库存与 `applied_write_seq` 严格相等，证明读取未新增并保存 effect；仅最终队列排空不能替代该比较。真正执行的增长工况按原目标 Thread ID 读取其唯一 writer 行，不把其他会话的水位归给当前选择。

增长首次提交的输入操作完成不等于后端受理或 writer 投影已可见。启动阶段在原提交计时与完成期限内持续观察有效队列基线，保留原始队列及提交状态；原目标 writer 尚未出现的观察不是 H/D 样本，不补零、不借用其他 writer。目标 writer 首次真实出现即开始严格采样，不等 Turn 完成，也不重置时钟或增加期限；一经观察到，该增长生命周期后续各批仍要求其持续存在，缺失、重复或水位无效立即失败。未观察到目标 writer 不能接受完成；失败报告保留未完成批次已获得的证据，不重放提交补造结果。

增长工况在上述历史基数上另开运行窗口，经同一正常会话继续二十轮、每轮 100 个独立完成文本 item，不写 SQL 注入完成记录，不以未完成 token 增长替代已完成 item 增长。分别观察跟随最新与阅读旧历史/滚动分页期间的完成追加，保留阅读位置、既有 item 身份与保存义务。采样范围须标明原有/新增 item 数、窗口时长、完成与耐久吞吐、接纳至保存时延及积压水位。

History 阅读不冻结完成集合：遵循 [26](./26-timeline-content.md) 的同一 controller 批次接纳语义，旧事实身份/顺序/字节不变，新完成只能扩展尾部。不能用全 ID 列表相等阻止正常增长，也不能只检查 ID 存在而放过改写/重排；thread、原 lease/selection generation 和阅读位置独立保持，内部 seq/源代次由 Rust 诊断而非展示协议核对。

沿既有入口分窗口记录 build/raster/total 的分位数、最大值与慢帧数，不把初始化、静置、分页和增长混成稳态流畅度结论。存储报告区分队列 pending/in-flight 字节、DB/WAL 文件占用和实际 GUI/内嵌 Runtime 进程的 `/proc/<pid>/io` 区间差：三者分别是队列计量、逻辑文件规模与整个进程的存储 I/O，不能互相替代或把序号当作事务数。已有事务观测可单独报告；未采到的指标保持缺失。性能数值属于明确机器、构建模式和合成形态的观察，不新增机器敏感的日常 CI 时限或擅自放宽产品预算。失败保留原始工况、错误与已采样数据，不降为 2,000 item 冒充通过。

模拟供应商的请求读取容量不是产品时间线预算：普通 fixture 默认仍为 1 MiB，`timeline-history-20k` 通过既有 fixture options 显式使用 16 MiB 的有界请求容量，以容纳累计历史向供应商的正常上下文回放；不禁用读取上限、不删历史或压低 item 数来绕过 HTTP 413。该容量仅属于合成环境，须在验收报告中披露，不外推真实供应商的上下文或请求容量。

## 24.9 按需打开、交付与保存的证据口径

目标契约归 [26](./26-timeline-content.md)。分层证据覆盖 pending 足页零 page/existence SQL、按 scope 补缺、commit/清 pending 交错、固定 cut、冷源 ABA、完成前缀与 Activity 因果、单项不兼容、范围内容、暂停 credit 翻页、A→B→A、关闭及非空迁移。受控屏障构造并发，不能用 sleep、未失败压力循环或零用例冒充证明。原生 B→正文→A、后台结果、段展开/切换与 HTTP/bot 消费须穿真实生产入口，不只测 DTO。

同一证据范围还覆盖排队 Accepted 即一次可见、消费/恢复不重封存、同 ID 重试/异内容冲突/新 ID 同文、inbox 接收与后续消费去重、Bot 不双发布、同 effect 单一顺序、外部文本不升权；订阅前/冷打开 Plan 与待决交互引用可用；Plan/集合独立 revision、token 零业务引用通知、翻页变化局部 stale、隐藏续接无重复；业务失败/重试与冷读事务切面、坏引用错误、慢 Chat 时独立查询、ABA、FRB/HTTP/内容工具及真实 Plan/问答 UI 端到端。已有测试复用，新增需命中真实生产入口，不能把该清单当已通过。

原 writer 合批必须观察真实事务边界、逐 effect 保存/回执等价、只确认实际连续 D、current 不超提交前缀，flush/关闭不等待依赖本批 durable 的后续 handoff。非空旧库保存 identity/seq、未知工具业务字节/公开 manifest、执行上下文/回执；迁移时间独立于普通打开。工具换形状后仅更新当前契约，SQL schema/迁移记录不因工具业务变化而改变；真实存储/恢复错误不降级为工具不兼容。

测量以真实 selection 和同 generation 实际内容布局关联 trace ID，skeleton、仅选中、收到 Set 或 controller 更新不等于已显示。FrameTiming 使用各帧实际时间/单调时间，不能用批回调到达的 DateTime 代替各帧完成时间；Rust/Dart 时钟不直接相减。产品已自动打开时继续观察真实布局，不等待不存在的打开按钮并误归为数据库耗时。

报告区分进程冷启动、read-scope 冷打开、普通切换、OS 页缓存条件、硬件/平台/构建模式、数据规模/隐藏活动/上下文大小、样本量/p50/p95、视口填充和 build/raster。参考环境迁移完成后，冷打开及普通切换实际内容 p95 目标为 500ms；样本不足、环境失败和不达标保持明确缺口，不由检查退出成功补造。机器敏感目标属于原生验收而非普通单元测试墙钟断言。

工作量记录 full_context_rows、quick_check、execution_activation、tool_or_ssh_initialization、query_triggered_flush（普通当前格式打开均零）、SQL/pending 候选与返回量、正文/媒体/FRB 字节、writer 事务、未落库引用、controller 操作与构建行数。1、100、10,000、100,000成员工作段请求同样段数，Main 成本不能随成员数线性增长；EXPLAIN QUERY PLAN 证明索引跳转，工作代表正文/媒体字节=0，纯活动历史枚举=0，同段追加只更新尾卡。身份/首次 seed 查询单列，不混入 page SQL。已加载消息随浏览增长，关闭释放；惰性 Widget 不证明缓存恒定。

逐请求证据复用现有诊断与平台观察能力：Rust 读取 span 关联原读取资格、操作和需求，沿真实 pending、SQL、内容及编码入口记录工作；Flutter 使用官方 `integration_test`／`WidgetTester` 读取生产 controller 与实际挂载行，并关联同一会话的选择代次。SQL 候选数指驱动实际返回的索引头，pending 候选数指内存选择实际检查的索引头；头部解码数、最终返回数与实际搬运字节分别报告，不把 SQLite 内部访问页数或完整 payload 声明长度当作已搬运正文。零值须有启用的观察入口及完整请求边界支持，缺失日志、未命中场景或未执行不能补零。执行恢复、完整性检查、执行装配和 flush 保留各自真实入口事件；独立迁移计时从实际迁移开始到返回，成功和失败均保留，不混入已迁移会话的打开样本。诊断只记录身份、计数和时长，不复制业务正文，不形成消息镜像或新的运行控制开关。
