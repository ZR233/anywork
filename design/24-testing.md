# 24 - 测试与人工验收

本文定义测试责任、证据层级和验收判据，不记录当前提交的通过状态，也不维护场景脚本或操作手册。领域行为以相应设计文档为唯一权威源；执行入口、门禁与环境约束由 [AGENTS.md](../AGENTS.md)、领域技能及仓库工具维护。具体场景、阶段参数和历史覆盖记录保存在项目报告中，不能反过来替代产品契约。

## 24.1 自动化责任

测试从宿主实际可调用的接口进入，判断完整结果、状态、效果与错误，不依赖私有布局或为测试扩张生产公共接口。优先复用已有证明；只有缺少独立失败信号时才新增用例。修复应由同一回归区分缺陷实现与正确实现，不能通过弱化断言、跳过执行或扩大超时取得绿色。

- **模型与内核。** `pl-model`、`pl-core` 的常规行为测试只使用公开 API。模型测试通过严格的本地协议对端验证请求、流、计量、取消、恢复及会话装配；内核测试使用脚本化模型、工具与临时历史后端，验证执行、并发、输入准入、等待、内容读取和恢复，不依赖账号适配实现。
- **可靠保存与迁移。** Studio 的专项故障测试使用临时真实 SQLite、文件与既有受控故障点，证明事务结果、身份、水位和恢复；故障注入只控制交错，不替被测系统完成持久化。不得以模拟队列自测或配置回读代替真实保存证明。存储与迁移合同见 [15](./15-session-storage.md)、[17](./17-studio-storage.md)、[20](./20-config.md)。
- **原生流与资源生命周期。** 运行时及 bridge 的确定性契约测试覆盖其真正拥有的投送额度、关闭登记、唤醒与实际完成，不为测试新增生产接口。可脱离 Flutter 引擎验证的部分不只留在人工旅程；实际原生投送与 Dart 端口仍须另行取证。
- **Dart 领域与应用适配。** 仓储、会话和领域归并行为由纯 Dart 公共契约测试负责；应用注入、视图模型编辑与操作、FRB 转换及连接器到纯视图的适配由应用契约测试负责。应用层不重复证明领域算法，也不为旧测试恢复全局状态或兼容门面。
- **门禁边界。** 其他 Rust crate、Flutter 组件／集成场景、Driver 和发布脚本不因此自动成为新的常规行为测试门禁。上游技能自带测试保持原样，是否执行遵循项目规范。格式、静态分析、构建和生成一致性各自保留失败传播，不能相互替代。

并发用例通过屏障、可控 Future 和受控时钟安排交错，不能用任意延迟碰撞。真实网络与暂停时钟共用时，时间推进不得在等待实际 I/O 期间偷偷耗尽业务预算；成功、失败与取消都须回收所属任务。用例和外层运行器均须识别零测试、缺少必需测试集、取消和执行失败。

### 24.1.1 Dart 领域与呈现的五层证明

| 层级 | 应证明的边界 | 不能代替的证据 |
| --- | --- | --- |
| 纯 Dart 领域 | 唯一归并、来源与尝试身份、回执观察、草稿冻结、预算和关闭 | Flutter 路由、原生句柄、系统交互 |
| 应用适配与视图模型 | 类型转换、编辑隔离、可见需求、迟到结果、双实例隔离、观察者不销毁业务资源 | 实际 Rust 动态库及真实宿主行为 |
| 真实宿主路由 | 启动、设置往返、内容连接与草稿保留、最新导航意图 | 仅由受控宿主完成的自动路由测试不能冒充此层 |
| 原生桥接 | 真实基线与增量投送、连续前缀确认、额度、取消、关闭与进程收束 | Dart 替身和静态扫描 |
| 平台可见交互 | 正常／窄窗口、键盘与输入法、滚动、菜单、逐帧呈现、平台退出 | 最终稳定截图、其他平台结果 |

各层围绕 [前端状态契约](./25-frontend-state.md) 保留缺陷敏感的证明：旧提交不能清除新编辑；旧尝试不能污染新连接；未知非幂等结果不能自动重放；合法零修订不等于未加载；来源、业务版本、材料和交付水位不能混用；关闭失败不能伪称资源已回收。测试应证明真实公共行为，而不是重新实现同一归并器或仅检查替身收到调用。

命令受理、观察、生效和持久化分别取证。可靠历史的真实证据不能由客户端替身替代，FRB 契约通过也不能证明系统剪贴板、界面几何或真实厂商兼容。源码中存在用例、运行器实际执行用例、用例通过是三个不同事实。

## 24.2 模拟账号与隔离协议环境

停止与继续沿同一分层取得证据：核心公开接口证明准备期与轮次执行身份一致、目标停止、
单次继续、原输入不复制、批次认领与消费同提交，以及重启不自动执行；真实 SQLite 证明认领
待保存、已保存未建轮次、已建轮次未准入和已准入阶段的恢复。原操作回查、重复请求不解除
后续停止、旧控制被继续或消息替换时只开一轮，均须有受控交错证明。
客户端与应用适配验证主按钮矩阵、目录中未选中成员的停止不切页、子详情只读、直接对子目标
发送／继续／作答在激活和附件准备前被拒，以及主会话答复子问题后不会自动恢复子执行。
原生界面另验停止、继续、重开和运行时说明，不能用替身替代真实旅程。

本地模拟服务只监听环回动态端口，使用隔离配置与数据根，按登记的协议和期望顺序响应。未登记、错序、超额或格式错误的请求必须失败，不回退到成功文本，不访问真实账号。对端只提供外部环境与独立期望，不导入生产编码常量或代行授权、幂等、恢复、正文筛选及状态归并。

共享协议采用共同样本，厂商专属选项、上传、搜索和计量差异由独立样本覆盖。测试检查实际请求、身份、参数省略与显式空值、错误正文、取消、超时和终态；不镜像整个生产模型名单、价格表或默认值。新增或删除协议能力时同步维护证明范围与明确缺口。接口与路由资格以 [模型契约](./06-model.md) 为准。

### 24.2.1 飞书与外部智能体

飞书协议观察通过隔离对端与真实产品 API／原生桥进入生产链，覆盖注册、认证缓存、握手与心跳、分包与确认、授权、幂等、发送、交互续接和关闭。必需步骤须全部消费，禁止请求须确实未发生，不能用总请求数或采集器退出码代替。请求、权威状态、持久化和进程证据联合判断；本地截图不证明飞书客户端渲染。行为与隔离传输边界见 [27](./27-bots.md)。

ACP 使用独立标准输入输出对端及受控分发服务，复用生产协议、下载、归档解码、文件锁、发布与进程监督。固定发行策略、认证资格、归档安全和配置迁移以 [28](./28-acp.md)、[20](./20-config.md) 为准。不得新增生产假登录、任意程序、任意下载地址、跳过校验或关闭 TLS 验证的入口；构建包源与受控分发流量保持独立。

ACP 证据必须区分准备、保存、认证与清理，并覆盖未知总量、断流续传、取消后重试、已安装复用、并发争用、来源／摘要／归档拒绝及发布失败。合法 ZIP64、数据描述符和空成员通过真实安装，实际数据损坏仍拒绝。准备失败不得产生可运行资产或提前保存账号；保留已有账号基线，以免空环境掩盖覆盖错误。取消、重试与复用保持同一暂存资产的连续证据，不以旧操作的终态证明新操作成功。

### 24.2.2 环境与证据完整性

模拟环境使用自身凭据服务、配置、临时目录与受管进程，不能读取或改变操作者凭据。固定来源、无额外下载或未发生禁止请求的结论，必须建立在完整日志与独立请求计数一致的证据上；记录缺失、结构错误或计数不符不是“零请求”。

场景的构建与依赖准备在服务就绪计时之前完成；就绪期限只度量进程启动和握手，不包含编译或缓存锁等待。运行、失败和取消均沿同一进程树所有权收束。分阶段产物具有唯一阶段与操作归属，后续阶段不得覆盖早期引用；不可捕获的瞬态应如实标为未观察，不延迟生产状态来制造截图。

模拟只证明当前实现与协议样本的行为。真实服务、官方程序认证及未运行平台均需独立证据，不能由模拟通过外推。

## 24.3 GUI 人工证据

原生验收使用真实 bridge、正常应用装配和 Flutter Driver，不用演示状态代替生产行为。工程工具职责与依赖见 [02](./02-crates.md)；具体启动、注入、场景参数和产物位置由工程入口及领域技能维护，不在本章复制。

人工判定结合实际操作、可见截图、界面树、类型化快照、请求、日志、持久化与所属进程回收。截图必须实际查看；控件已构建、截图文件存在或脚本成功都不等于视觉通过。失败阶段仍保留原始诊断与已观察退出结果，归档失败与原始错误共同报告，不能替换错误或免除回收责任。

界面行为依据 [19](./19-studio-ui.md)、[25](./25-frontend-state.md)、[26](./26-timeline-content.md) 核对。重构前后的入口、区块、布局、间距、断点、可用性与功能必须保真；正常和窄窗口、长内容、文本放大、焦点、输入法及键盘路径分别观察。只操作已确认属于隔离应用的窗口，并在成功、失败或中断后恢复原尺寸，不影响其他应用。

### 24.3.1 退出与进程树

退出请求、Driver 返回、虚拟机断开、原生进程退出和资源回收是不同事实。验收必须核对同一操作系统进程的稳定身份及真实退出状态，不能采用开发启动器的固定返回码或向已回收的旧数字 PID 发信号。产品自身回收和验收工具最后强制回收分别记录，后者不能伪装为正常关闭。

覆盖正常退出与历史重开、重复退出、初始化未就绪或失败、订阅错误、持久化阻塞、外部服务无响应及界面线程挂起。总期限、清理预算、退出码及降级语义以 [18.5](./18-studio-state.md#185-优雅关闭) 和 [19.1](./19-studio-ui.md#191-边界) 为准：重复请求不得续期，缺失关闭报告不能伪装为空资源集合，已知未收束状态不能声明可靠保存成功。

MCP、LSP 和工具进程树分别由真实产品调用启动。关闭前证明资源确实存活；有独立关闭链阻塞时，其他资源仍应在原生进程退出前由产品自行回收，不能以总耗时推断并发关闭。正常退出、协调降级及原生硬期限强退分别判定，未知或缺失进程证据保持失败。

单实例观察覆盖同数据根重复启动、不同根隔离、路径别名、首帧未就绪、退出中激活及崩溃恢复；权威依据为操作系统实例所有权、窗口状态、实际请求与可靠保存。Windows 托盘隐藏与 Linux 退出分别报告，隐藏不等于退出，未运行平台不算通过。

### 24.3.2 结果声明

采集状态与人工结论分开，人工结论默认为待评审；必须区分通过、失败、未运行和未观察。证据绑定实际提交、原生库、工具链与平台，不能用旧提交的绿色替代新实现。真实账号只在明确授权的范围内使用，不覆盖、注销或外泄用户凭据；模拟、真实服务和平台结论分别记录。

截图与一次性日志不提交源码。PR 视觉证据须使用实际附件并回读核验引用，不把本地文件存在或链接占位当作已交付。只读 Driver 诊断只借用已有事实，不为填满字段而创建观察、查询、页面所有者或额外业务动作。

## 24.4 实时新鲜度矩阵

逐域矩阵属于验收追踪记录，不是第二份架构定义。它覆盖会话运行时、执行／活动／保存、时间线、草稿、配置、模型、账号额度、模型统计、会话费用、各资源域、更新、恢复及启动／退出。每行关联当前提交、权威设计、实际生产事件、可见结果和失败恢复证据；无缺陷领域也保留核对结果，不因类名存在而跳过。

所有权、独立时钟与生命周期分别引用 [18.10](./18-studio-state.md#1810-权威状态新鲜度不变量)、[18.11](./18-studio-state.md#1811-设置与模型目录的独立时钟) 和 [25](./25-frontend-state.md)。验收要求如下：

- 每个受影响的可见域至少证明一次真实后端事件使同页内容更新；不能靠切页、重新进入或前端轮询补成事件证据。
- 快照保留来源、资源版本、尝试与操作身份，旧代次、缺口、失败和未知不能变成健康空值或零值。
- 高频速度只更新相应消费者，不夹带正文、计划或目录；实时样本和已确认样本不能混配。无完整计量保持未知，计量语义正确不意味着模型生成更快。
- 隐藏、重新可见、重新打开资源及关闭分别验证其责任；取消页面观察不能清草稿、关闭当前会话或冒充原资源完成。
- 状态、读取、命令回执与实际保存分别取证，保留失败与原始责任；客户端、适配器和原生证据不能互相冒充。

诊断不暴露图片字节、凭据、不透明原载荷或内部数据库。真实剪贴板、实际平台输入和原生资源仍须单独观察，受控替身只证明它覆盖的边界。

## 24.5 单一内容链路验收

时间线页、尾部订阅、详情、展示租约与实时／历史模式以 [26](./26-timeline-content.md) 为准。静态审查只证明结构连接，Dart 替身证明客户端行为，原生组件样板证明组件路线，真实 bridge 才证明跨层交付；真实供应商另验。

验收覆盖正文、推理、工具参数与结果、图片、交互、保存及失败，核对稳定身份、完整原文读取／复制、有界详情、页边界和取消。后台输出不得改变冻结历史；显式回实时、切会话与关闭后，旧展示集合及详情应可释放。不能通过另一列表路线、像素补偿或自动全量预热掩盖缺陷。

呈现稳定性必须在持续输出、保存确认、滚动、切换与重连的真实中间帧上判断。只在动画静止后截图不足以证明没有空白、频闪或阅读中断；帧率正常也不证明动画正确。调试构建的耗时不能替代正式性能结论。

### 24.5.1 存储职责重构验收

升级恢复使用已停止且经 SQLite backup API 制作的一致性副本，在隔离环境中保留项目、会话
与账本事实；拒绝带 WAL／SHM 或符号链接的输入。模拟端点、机器人外发、MCP、LSP 与 ACP
在启动前完成隔离，源副本和真实数据根保持不变。迁移前后数据库、截图、快照和原生进程退出
共同证明恢复，具体复制与场景参数由验收工具及技能维护。

通过真实事务和重启证明历史、检查点、上下文及计量各自职责：确认丢失和重试不重复执行工具，保存故障不推进虚假水位，迁移中断可接续，日志或统计故障不破坏可靠历史。已确认保存与恢复执行分别证明；不得清空历史、恢复默认或重新运行旧工具换取通过。

长任务核对常驻状态不保留全部历史请求、增量更新不反复序列化历史前缀，并分别记录驻留内存、数据库／WAL、日志和写入量。原生观察覆盖历史回看、连续压缩、重开后继续与统计展示，实际平台单独报告。详细保存语义引用 [15](./15-session-storage.md)、[17](./17-studio-storage.md)。

### 24.5.2 上下文连续实施验收

公开接口回归覆盖事实追加与失效、完整输入预览、冻结水位、取消与冲突、指令来源及完整工具批次。真实请求和持久化恢复核对独立根、父子与兄弟会话的归属，不仅比较提示词常量。计划批准、非初始阶段、连续两次压缩、继续执行与重启后不得重复批准、回退阶段、重放续接或工具；计划契约见 [13](./13-plan.md)。

重启后的新答复必须关联本次已受理输入与对应轮次，旧历史或待提交状态不构成继续成功。缓存对照固定端点、模型、任务、工具、推理强度和预热规则；累计缓存读取词元除以累计输入词元，辅助调用单列，缺失计量保持未知。模拟使用量不证明真实缓存命中率。

### 24.5.3 规模与计量

大历史基线为 **20,000 条具有独立稳定身份并真实进入持久化历史的条目**，由正常模型适配和保存链建立，不直接灌库。历史场景以每秒 **1,000 条**保留交互窗口，压力基线约每秒 **5,000 条**；实际词元、事件和独立条目数量分别记录，不能把少量条目上的大量增量当作两万条历史。

长历史、长正文、长轮次与多会话分别取证；多会话基线保留 **16 个独立会话**。冷开小页、深游标、持续输入期间翻页、显式回实时及窗口变化均经过真实 HTTP／FRB 与界面链路。具体滚动样本、阶段同步和操作参数由验收工具维护，不因文档精简缩小既有场景。

记录查询数量、原始解码量、协议字节、保留载荷、Flutter 堆与原生进程 RSS，各指标不能相互冒充。Rust bridge 与 Flutter 引擎的合计 RSS 只用于同条件前后比较，不宣称单层分配或任意负载上限。协议计量与权威解码边界见 [26.2.4](./26-timeline-content.md#2624-预算计量边界)。

## 24.6 账号、额度与 MCP 隔离验收

账号与模型验收保护稳定账号身份、同名模型跨账号隔离、配置／预设／凭据迁移保全、来源与成员资格、目录撤下和重现、迟到响应拒绝及在途路由冻结。不把当前目录或价格回填为历史，不以默认值相等消耗用户覆盖。原生能力与配置合同分别见 [06](./06-model.md)、[20](./20-config.md)。

阈值、启用与计费等窄意图验证真实保存、并发兄弟字段保留、失败反馈及旧回执不清新编辑；配置与目录双水位分别核对。历史账单不因删除手动模型或调整目录而改写。客户端只证明后端解析结果的忠实投影，不能替代原生资格和容量校验。

账号额度按 [25.7.1](./25-frontend-state.md#2571-账号用量需求) 验证自动可见需求、身份去重、隐藏／重现、删除竞态及应用实例隔离。快账号必须能在慢请求或认证失败请求结束前独立展示；表单编辑、保存及其他功能不等待全部额度查询。名称、默认值或无关目录通知不得引起全量重查，迟到结果不得复活删除项。

模型统计与会话费用按 [25.20](./25-frontend-state.md#2520-独立模型性能统计与完整快照) 及 [18](./18-studio-state.md) 验证完整快照、配对、状态独立性、预算和关闭。独立账号额度能力不得被统计替代。模拟调用、实际历史、界面汇总及重开结果交叉核对，写入缺口不是已知空集合。

MCP 凭据门控、轮换、清除、禁用和在途租约复用使用真实配置与通用协议链，不为固定端点模拟放松 TLS、修改系统解析或增加生产后门。线上代表性账号使用有界调用；无可用授权的厂商标为未执行，不以其他账号成功替代。
