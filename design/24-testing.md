# 24 - 测试与人工验收

本文定义 `anywork` 自动化门禁、本地模拟账号、原生 GUI 人工验收与实时状态新鲜度矩阵的唯一权威契约。客户端与前端生命周期见 [25](./25-frontend-state.md)，时间线内容与预算计量见 [26](./26-timeline-content.md)，飞书机器人与 ACP 接入验收见 [27](./27-bots.md) 与 [28](./28-acp.md)。

`PR Quality Gate` 在 PR 与 `main` 分支推送时使用 GitHub 原生路径过滤：仅修改 `design/**` 时跳过整个工作流，包括自动化测试与静态检查；包含目录外文件的变更仍执行原有门禁。

真实模型工具观察复用 `collaboration_observe`，显式指定用户已配置的账号与模型，在独立 Studio 数据根和工作区内运行。SSH 观察同时指定 `ANYWORK_OBSERVATION_SSH_ALIAS` 与 `ANYWORK_OBSERVATION_SSH_WORKSPACE`，别名使用已有 SSH 配置，工作区须预先独立创建；观察器不改写用户 SSH 配置。通过 `ANYWORK_OBSERVATION_HELPER_BUNDLE` 指向标准构建生成的 helper 资源目录，沿生产 SSH 项目与工具装配路径执行。采集完成与模型自述均不构成通过判定，须独立核对真实回执、原始字节、资源摘要及进程回收。

## 24.1 自动化测试责任

### 子智能体退休与恢复影响的证明边界

恢复影响隔离通过 Client 公开行为测试证明：非阻塞的 preserved child 提示不禁止健康 root 导航、打开与提交；真实访问/执行故障仍拒绝相应操作，错误保留对象、原因和恢复动作，草稿附件不丢失。覆盖重复恢复快照、多个问题并存和项目/会话作用域，不以某个字段或错误文案匹配代替完整动作断言。

最终关闭意图、现有保存 ACK、确认前取消、工作树删除后结果保存失败与旧版标记保全属于既有 Studio 历史保存/迁移专项：使用真实 SQLite 与私有可控故障边界，证明可靠封口、统计/报告/历史保留、原绑定清理幂等及无执行复活。本阶段不验证或引入精简归档、历史/附件删除及跨存储移交流程，不为该产品流程在其他 Rust crate 新增常规自动化测试。

历史格式整合还需证明：旧 `v2` 内容经显式准备后才由当前格式读取；迁移与完成记录原子提交，损坏时回滚；嵌套在关闭记录中的旧工作树绑定与顶层租约分别升级而不改变封口、force、删除结果或未决责任。关闭后工作树缺失仍可打开完整历史；内容准备不装配执行模型，也不以新写入器代替原存储代次的 join 或报告 ACK。正常 ignored 内容不能误挡工作树派生，独立安全清理仍保护 ignored 内容，二者分别验证。

终态交付责任的历史故障证明必须经过真实生产终态投影、保存移交和受管 operation：分别在终态保存、交付所需预算及异常事实保存处制造故障，再经原恢复或真实容量释放接续。普通报告与有回送授权的审查均核原消息自动到达、字节与身份不变；不得调用 collector、公开 settle、最终关闭或冷重开来替代自动接续。故障后的审查来源保持降权，无目标原回执时不首次发送，独立异常须真实保存并通知；不可恢复错误、取消等待、无容量改善和关闭阻塞不能被空闲标签或重复轮询掩盖。仅测试底层 receipt 写入或独立 CAS，不足以证明终态移交后的责任连续性。

受限工作区准入的验证按真实能力分层：已有完整资源的冷本地恢复须保同一 usage、原目录与布局、封口和交付基线；缺失资源不得顺手补建。SSH 冷目标缺原 binding 与常驻目标原 client 不可用，应分别核整条准入调用链不会进入普通连接或工具重装配；返回 Disconnected 本身不能证明零建连尝试。实际连接尝试和绑定发布的动态观测仅使用已有受控入口及可核验记录，未取得时明确保留未测边界，不为验证扩大生产 API 或另建测试框架。已有回执在目标后来关闭或断连时仍优先复用，普通显式恢复的正常连接行为另行保留。

真实派生与关闭沿既有 `manual-gui` 子智能体旅程验收：普通根与根工作树均从主智能体实际目录的干净 HEAD 派生；暂存、未暂存、未跟踪改动和无初始 commit 均拒绝并保留现场，无新 child/工作树/分支残留。reviewer 指定目标后实际同目录、不创建分支，能审未提交改动且关闭不删除目标。

最终关闭只清理自有且存在的绑定工作树：干净且已交付时默认删除；脏或未合入时默认保留并报告失败；force 不绕过锁、归属或真实借用；无自有绑定或路径已不存在时不猜测补删。独立分支/ref、完整历史、可靠附件及工作树外 SessionFiles 保留。跨重启核对原历史、报告、用量/费用和已有评价仍可读且不重复；最终封口不可续跑，普通退出的未封口 child 仍可恢复，旧 preserved 不阻塞健康 root。结合 Git 注册、路径、日志与所属后台命令及 GUI/Driver 的真实退出判定。Linux 本地、真实 SSH、Windows 分别报告，模拟供应商通过不等于真实供应商或未运行平台通过。

### Rust 公开 API 测试与 Studio 专项集成测试

自动化测试按 crate 职责严格分层，不通过读取私有实现或添加测试专用公共接口扩大生产 API：
- **`pl-core` 公开 API 测试**：仅使用测试侧的脚本化模型、脚本化工具与按锚点查询的临时历史后端，验证会话（`Thread`）的执行、并发控制、取消、恢复、效果（effect）提交、`Session` 分页/尾部订阅/详情读取、轮次准入闸门（Turn admission gate）及可选 SQLite 持久化契约，不依赖 `pl-model` 账号适配器。内容测试覆盖新旧修订号落盘确认竞争、未落盘与历史记录无空洞合并、首帧与登记交接、尾部连续增量与慢消费者重同步、热缓存淘汰非删除、查询错误、详情版本与 UTF-8 游标、取消及所有等待者关闭。效果窗口（effect window）仅按存储后端压力报告中的类型化持久化水位（durable receipt）释放，且该水位仅能越过会话唯一实时投影所有者已接管并交回可靠保存通道的提交（见 [15](./15-session-storage.md) §15.3）。统一等待（`wait`）公开 API 用例通过可控阶段与测试时钟构造交错，验证订阅前后已就绪、任一任务或未消费消息唤醒、固定截止点与就绪竞争、正常超时、取消/关闭、权限与身份错误以及常驻任务淘汰后的持久化终态读取。存储暂停用例严格区分短暂压力（队列/字节预算触顶，在安全间隙自动恢复）与真实落盘故障（轮次停在准入点，必须经显式 `resume_storage(generation)` 核验通过后才恢复下一轮模型或工具工作，过期代次明确拒绝，且重试落盘成功不自动恢复执行）。
- **`pl-model` 公开 API 测试**：从单模型运行时与会话模型适配公开入口出发，通过本地回环（loopback）模拟服务验证 Responses HTTP/WebSocket、Chat Completions、OpenAI 提示词缓存选项、文本与推理流、函数/自定义/编程式工具、托管搜索、图片输入、图像生成（`Images` 请求与响应协议）、DeepSeek 文件上传与搜索/抓取工具接口（`pl-model/tests/deepseek_tools.rs`）、智谱 Chat 与 Coding Plan、远程压缩、在线模型目录同步与来源归类（`online`/`bundled`/`manual`）、上下文压缩阈值解析、词元吞吐率（TPS，识别长首字等待后集中输出的分母边界）以及 WebSocket 断线恢复与粘性回退。
- **`pl-studio-runtime` 历史保存与数据迁移故障注入专项**：仅在历史保存与数据迁移边界允许使用临时真实 SQLite 与测试条件编译的私有可控故障点，验证队列满返还并保留原批次、取批后退出与提交后确认前退出的幂等性、并发在途结果按序写入、持续故障与按代次恢复、检查点/大对象（blob）发布失败后的历史围栏（fence）、写入器仅按提交身份确认而不回读正文、投影所有者接管票据屏障、可变正文与驻留字节预算计量、停止或注入统计消费者崩溃（panic）后历史保存独立完成并由监督器恢复消费、旧会话隔离，以及配置结构版本（如 `18 → 25`）与会话布局跨版本保全迁移。
- **`pl-studio-runtime` 工作树与归档生命周期专项**：允许在 `tests/` 中通过公开 API、真实临时 Git 仓库和 SQLite 验证该窄范围能力。覆盖 detached 创建、切换/重命名/删除原分支后的原工作树冷恢复与重查、真正的目录缺失/外仓库/注册冲突拒绝及现场保全、租约/回执迁移保全与幂等、工厂类型化错误传播；分支身份解耦不能削弱默认交付祖先保护、force 限定或终态替代路径拒删。模型替身仅提供可控输入，不重写业务；判据核对真实 Git 注册/checkout、分支与历史，迁移只消费真实已发布格式，不为测试扩充生产公共 API，不把旧关闭处置测试当作新接口证明。
  - **协作关闭与当前归档回归**：验证 dirty 准入、固定实际 HEAD、reviewer 借用、bot 拒绝、热冷永久关闭及上文关闭安全边界；当前归档只停止并保存活动工作、更新目录可见性，工作区故障不妨碍无工作区依赖的归档，取消归档不重建或复活执行。两种操作分别验证，不能以归档通过代证最终关闭。
  - **待接入的归档强制清理回归**：后续接线落地时验证 local 根带子工作树、归档结果与部分失败重试，同时核对执行/进程收束、保存事实、物理资源及历史保全。必须覆盖未发布 child 首次清理失败后归档接续，以及初始 checkpoint 已耐久但目录发布失败时私有 owner 的保存与关闭；原子替换前失败和替换后同步失败须区别裁决。取消、应用退出/崩溃及重启窗口不扩展成断电或 OS crash 承诺；不能通过删除 guard、提前公开、跳过保存或丢弃 pending 责任换取绿色。
  - **门禁与证据**：已落地的专项纳入 Studio 自动门禁，未接通的归档测试及探针保留作整合材料，不伪报通过或以空实现占位。GUI 分支观察与后续归档确认分别使用对应阶段的真实原生 Driver 旅程；真实 SSH、跨平台进程回收按实际边界提供证据，不把单平台或旧接口结果外推。
- **`pl-patch` 补丁语义一致性专项**：仅在 `code/pl-patch/tests/` 允许通过公开 API（`apply_patch` 与 `PatchBackend` 实现）与真实临时目录验证补丁解析与应用语义：上下文行保留文件原文、删除/新增行按补丁原文写入（含纯缩进变化）、`*** End of File` 与 heredoc 处理、无效补丁头与多补丁块拒绝、移动与覆盖写入、失败与部分应用摘要。用例语义与 Codex `apply-patch` 保持一致；`*** Environment ID:` 前导、完全空行上下文、尾部空行缩短匹配与 `*** End of File` 属于双方共同契约，不得标为本地差异；有意的本地差异（更宽松的无前缀上下文行、JSON 属性键保留匹配、重复边缘上下文缩短候选，以及本地拒绝诊断与重试指引文案）必须在用例中显式断言并注明差异来源与对照结论。该专项只消费公开 API 与真实文件系统，不为测试扩展生产接口、不引入测试专用分支，也不把临时目录之外的宿主状态纳入断言。真实模型的典型补丁工况另用 `code/pl-studio-runtime/examples` 的人工观察入口记录（隔离 Studio home、真实账号与系统凭据），人工结论默认待评审，模拟或单元证据不得替代该观察。
- **其他 crate 与上游技能边界**：除上述专项外，其他 Rust crate 与发布工作流不新增常规行为测试门禁；代码格式、静态分析、确定性构建、生成一致性与发布配置检查独立运行。上游预置技能自带的测试源码保持原样，不纳入项目门禁。

### 飞书机器人与统一智能体定义扩展验证

- **飞书机器人协议与产品观察**：原生飞书机器人遵循统一测试布局，不在其他 Rust crate 新增自动化门禁。非 GUI 显式协议观察入口为 `cargo run --locked -p pl-studio-acceptance --example bots_protocol_observe -- <参数>`，通过独立的本地回环平台对端（loopback peer）与受限调试传输描述（绑定隔离数据根与同一回环来源，见 [27.9](./27-bots.md#279-验收边界)）驱动真实 Studio HTTP 产品接口与生产运行时（Linux 下隔离控制脚本使用 Python 3.9+ 标准库的进程与 `pidfd` 能力，并使用场景私有 D-Bus/Secret Service 与 `HOME`/`XDG` 目录）。观察覆盖：扫码注册各终态与取消后迟到结果；令牌缓存与并发刷新；WebSocket 握手、心跳、重复/冲突分包、ACK、退避与停止；未授权输入零执行、真实 `@提及`、消息幂等与并发首次映射；桌面交互续接、`post.md` 富文本与 CardKit 2.0 流式卡片（单次创建、单次发送、正文更新先于轮次结束、序号单调、终态关闭确认）；分页、发送拒绝/部分成功/结果未知、重启恢复与进程树真实回收。
- **统一智能体定义与动态派发验证**：覆盖普通根会话、飞书根会话、系统子智能体与用户自定义子智能体的真实装配与模型请求，验证角色来源（`Agent`）、工作模式来源（`Mode`）、路由与权限归属；验证系统子智能体缺失专属路由时整体继承 `mode.simple` 且不将继承值回写为持久覆盖；验证 `spawn_agent` 动态 `oneOf` Schema 的配置模板身份、工作区模式专属字段、必填项校验与额外字段拒绝；验证历史指令快照迁移后有效正文、标签、顺序与水位保持一致。

### 24.1.1 Client 五层证明与门禁

前端与桥接层按五个独立层级分别交付验证证据，严禁以底层替身（fake）、静态扫描或单张界面截图互相替代：

| 验证层级 | 被测边界 | 核心证明目标 | 证据形式与门禁范围 |
| --- | --- | --- | --- |
| **1. 纯 Dart Client** | `anywork_client` 公开 API 与可控传输层 | 唯一归约器、`attempt` 所有权、回执与观察顺序、草稿同步冻结、内存预算、原子观察与幂等关闭 | `code/anywork_client/test/` 纳入 `verify-client` 正式门禁；不加载 Flutter 或原生库 |
| **2. 应用适配层（Adapter）** | FRB DTO/句柄适配、`Riverpod` 只读观察、`AppGraph` 注入、行派生映射 | 内容基线、增量缺口、分页/详情、迟到句柄、取消/关闭、双实例隔离、观察者销毁仅取消自身观察、工具条目到时间线行类型的映射 | `code/anywork/test/client/` 纳入 `verify-client` 正式门禁（使用 `flutter test --no-pub`）；替身通过不代表真实原生层通过 |
| **3. 真实宿主 Flutter 路由** | 应用启动、设置页/标签页往返、连接器与视图 | 只为可见会话订阅、离页退订与返回新基线、草稿身份保留、提交期间继续编辑输入、旧意图结果不覆盖新值 | 通过 Flutter Driver 与人工旅程取证；受控宿主的路由契约归入应用适配层门禁 |
| **4. FRB / 原生桥接层** | 实际 Rust 动态库、数据汇（sink）、句柄与退出协调 | 真实 `open → events → acknowledge`、双帧在途上限、控制回执、单一内容出口、关闭唤醒、汇合（join）与子进程树回收 | 原生模拟固件（fixture）与类型化退出诊断单独记录 |
| **5. 平台与可见交互** | 实际宿主窗口、滚动/菜单/输入法及应用退出 | 时间线 `Live/History`、键盘快捷键、流式逐帧无频闪观感、原生系统资源收束 | 人工验收按 Linux / Windows 分别记录；未运行的宿主平台明确标记为未验证 |

`cargo xtask verify-client` 是 CI 的正式门禁之一：锁定解析两份依赖快照，检查 `anywork_client` 纯 Dart SDK 依赖与导入边界，执行格式检查、静态分析与纯 Dart 单元测试，再运行应用侧 `code/anywork/test/client/` 套件。Client 自动化测试使用同步屏障、可控 Future 与虚拟时钟（fake clock）构造确定性并发交错（不依赖延时 `sleep` 碰撞），重点覆盖：
停止与继续的证明按同一分层交付：核心公开接口证明停止只收束目标执行、继续只开启一个轮次且不复制用户内容、认领与消费在同一提交、重启不自动执行；Studio 侧证明身份与配置跨重启保留、用户对子目标的提交与继续在激活前被拒绝、子问题决议只保存并通知主会话；Client 与应用适配证明在途与已受理区分、重复点击不双发、目录停止不影响选中项；原生界面另行记录停止、继续、重开与运行时说明的真实旅程，模拟与真实供应商分别记录。
| 风险 | 层级与判据 |
| --- | --- |
| 原输入已消费后空队列继续仍只开一个新轮次、不复制用户正文 | 核心公开接口轮次用例 |
| 重复认领、停止与完成或关闭竞争、旧身份不影响后继执行 | 核心公开接口，以通道或屏障控制交错 |
| 认领待保存、已保存未建轮次、已建轮次未准入、已准入四个崩溃点 | 核心真实 SQLite 与 Studio 历史保存专项 |
| 响应丢失后按原操作身份回查，重发不重新授权、不解除停止 | 核心身份持久化、Client 契约与原生旅程 |
| 输入、控制输入与已消费报告同批消费，不额外开启轮次 | 核心请求内容与消息水位断言 |
| 旧控制被空继续或真实消息替换时只开一轮，真实内容不丢失 | 核心两条相邻原子转换 |
| 重启只载入不执行，旧工具不重跑，旧权限不继承 | 快照、交互与权限的既有公开接口 |
| 主按钮矩阵、子列表未选中成员停止、点击不切页、目录未知状态、子详情只读 | Client 与适配契约，原生界面补真实证据 |
| 用户直接向子会话继续、发送或作答被拒绝且不激活、不准备附件 | Client 与桥接契约、原生产品接口验收 |
| 子会话问题在主会话回答后不自动启用子执行，原交互只决议一次 | 核心交互、Client 与桥接契约及原生旅程 |

- 设置页与多标签往返后草稿身份与内容保留；修订号 `8` 提交后继续编辑至 `9`，旧确认回执（ACK）仅清理 `DraftStamp + OperationId` 冻结的所有权，不清空新文本、新路由或新附件。
- 页面路由契约测试必须经过生产 GoRouter 注册及实际页面入口，覆盖机器人详情、聊天、平台工具、输入区机器人设置入口的参数和返回栈、栈顶重复进入、无效目标、离页守卫及被覆盖后退订、返回后新基线；不以测试中手工压入假页面证明生产接线正确。对话框不撤销底层会话需求，隐藏页面和过期导航不得重新激活目标。
- `A → B → A` 快速切换时第一次 `A` 的迟到打开句柄由原 `attempt` 关闭；在打开、首帧、流消费、ACK、查询、命令与关闭各异步等待点交错退出时无死锁或预算提前释放。重复 ACK 幂等，越过未发送帧或跨句柄 ACK 明确拒绝。
- 新内容订阅首帧基线使用独立版本域；增量补丁 `from` 不匹配时仅重同步当前连接，拒绝 `to <= from`；分页查询不推进尾部基线，`EOF` 或错误不触发死循环加载。
- 回执先到、事件帧先到，以及 `Applied` 帧已观察且回执版本相等时，均按操作身份与生效点（`effect point`）准确结算；快速 `X → Y` 切换中 `X` 的迟到结果不清除 `Y` 的待确认覆盖层（overlay）。
- `UnknownOutcome`、`AwaitingObservation`、`SyncFailed` 与 `Rejected` 严格区分；结果未知的非幂等提交不自动重放，已受理但尚未落盘的附件仍由明确所有者保留。
- 两个 `Client`/`AppGraph` 实例完全隔离；读取快照与注册观察之间零漏帧；重复退出共享首次绝对期限，关闭失败保留未解决报告（unresolved report）。

## 24.2 模拟账号与受控协议观察

本地模拟供应商服务（`pl-provider-fixture`）同时支撑自动化测试与 GUI 人工验收：仅监听本地回环动态端口，按固定提示词、协议及期望轮次返回预设的 HTTP/SSE 或 WebSocket 事件流，严格校验请求关键字段、调用顺序与鉴权头，对未登记或错序请求直接返回失败。模拟服务仅证明当前实现与约定协议样本的行为一致，不替代真实厂商线上接口兼容性验证。

既有受控消费者区分后台工具通知、子轮次报告、审查异常与完整反馈；`Task task:` 通知匹配不放宽成任意 user 文本，工具受理不冒充执行完成。报告、异常和反馈复用各自的类型化解码及真实关联身份；正文及元数据可包含合法空行，不能凭第一个空行错误截取正文。消费者只调用当前实际装配的工具；文件发现与读取迁移到获授权的 `exec` 后，不保留调用已移除 `read_file`、`list_files` 的现役脚本或兼容分支，也不把文件许可当作命令许可。受控输入不是可验签的来源凭证，也不能代替真实宿主调度证据。

Task 协作策略、停工及审查反馈工况采用独立的真实模型人工观察，不以预设回复、固定工具调用序列、通知数量或全分支脚本矩阵作为完成门槛。复用现有观察入口，以规模有限、成果可检查的任务判断能否大体推进、交接、修复并完成；模型可选择不同的合理策略，不因没有采用推荐人数或时序判失败。未出现的路径记为未观察，模型不确定性、实际产品缺陷和采集状态分开记录，不通过反复更换提示词逼出固定结果。发现阻止正常推进的流程问题及时修复并定向复核；已确认的权限、身份、持久化和资源安全缺陷不能以“大体完成”忽略。

自主派发的定向观察以实际创建的 `automatic` 会话及子智能体冻结路由为依据，提示中的模型偏好或固定预设运行不能代替选模事实。轻量流程验收可选择当前合格目录中的快速模型与小规模模块化任务；若要求并行编码，应核对实际实施任务的生命周期重叠、独立代码产物和最终整合结果，仅并行探索不构成该工况。根智能体直接完成必要局部工作符合建议性职责约定，不因直接执行命令而判失败；检查重点仍是任务推进、成果、交接和资源收束。

不为上述观察维护专用的整份运行时输入窗口 matcher、技能补段期望或冷本地固定脚本链；无消费者辅助能力随调用方清退。已有协议消费者、§24.1 的存储/迁移及工作树回归和正常工程门禁保留，不将这项取舍扩大成禁止自动化测试。已有受控场景可用于独立协议诊断，但不替代真实模型人工结论，也不要求为本次协作观察逐一重跑。

专项场景的受控模拟与原生取证规则如下：
- **ACP（Antigravity 1.4.1）安装与认证观察**：认证观察使用独立 `stdio` 模拟智能体通过官方 SDK 响应握手与认证；安装准备观察使用受控本地回环网络对端模拟固定 Google 官方分发地址（通过标准代理服务器与隔离子进程 CA 信任将官方地址导向本地回环，严禁关闭 TLS 证书校验或在生产代码中添加自定义下载 URL 开关），完整验证真实字节进度、断点续传、取消重试、已安装复用、并发文件锁争用、ZIP64 数据描述符兼容与损坏包拒绝、启动入口校验及退出收束（契约见 [28](./28-acp.md)）。
- **时间线两万条长历史场景（`timeline-history`）**：单次受控回复按每秒 `1,000` 条速率交付 **20,000 条**具备独立稳定身份的消息与推理条目，经真实模型适配、`Session` 发布与历史写入器落盘（`stress` 压测场景则保持每秒 `5,000` 条速率并额外创建 16 个会话）。结合 `timeline_adaptive_journey.dart` 覆盖六种窗口尺寸、侧栏拖动/方向键/`Home` 键调节与草稿增高，独立记录核心层统一准入计量、实际协议编码字节、冷读权威解码峰值与进程常驻内存（RSS，计量边界见 [26](./26-timeline-content.md#预算计量边界)）。
- **工作树（Worktree）协作观察（`collaboration_observe`）**：在隔离 Git 项目中以根会话 `worktree` 模式派发目录与工作树执行者，核对工具终态、物理检出路径、文件内容、目录越界拒绝与子进程回收。
- **Task 策略与审查回送观察**：新建真实 `mode.task` 会话，使用实际可用路由、预设及凭据关联，在隔离的数据根和业务仓库中按所选分发方式人工观察；不要求每次遍历固定与自动模式，也不得用简洁模式、统一覆盖所有路由或到时退出冒充 Task 完成。记录必要的提示词/构建身份、实际模型、计划交互、工具与终态证据、代码版本和进程回收。一般任务按成果、风险和效率判定，未采用推荐工作区、拆分、集中整合或审查策略本身不是缺陷；定向操作只说明实际覆盖，不升级为全局约束或固定模型脚本。
  - **停止与清理边界**：场景截止时间与操作者中断共同阻止新增观察工作和决议准入，完成判断前再次核对停止事实。允许取消的只读等待受相同边界约束；已经准入、可能产生副作用的操作保留所有者并取得真实回执，不因停止请求丢弃责任，返回后也不继续批次中尚未准入的决议。最终证据导出使用独立且明确的有限清理预算，不能无限阻塞运行时关闭；超限、取消及未能确认回收分别记录，不把丢弃 future、任务句柄或强制退出当作成功回收。
  - **采集进程所有权与平台**：本轮 `collaboration_observe` 采集器以 Linux 为受支持执行平台，其他平台在启动业务与复制配置之前明确拒绝，不把单平台证据外推。准备及取证的 Git 复用现有本地 process-worker 所有者、分离的取消能力与可接续等待，保留真实业务终止、监督者退出和输出排空责任；不在 example 中重新实现进程树监督，也不以可取消后重建的第三方 wrapper 等待代替原等待完成。Linux 使用与本次构建匹配的 `pl-remote-helper`，沿既有外部 helper 安装及预检要求，不提供裸进程后备。准备阶段的 Git 同样纳入绝对期限和中断边界。
  - **采集完整性**：事件证据以已确认的初始快照和精确的终态 Turn 身份及修订号界定覆盖区间，只有连续消费并确认所声明的终态通知才可标记该区间完整。订阅通知修订号与权威快照的提交水位属于不同版本域，不能相互比较；首帧之后重放的保留终态通知也只证明该语义锚点已被观察，不证明覆盖了全部 canonical commits。最终权威快照、持久 Turn 与完整时间线独立取证，不能由事件区间完整性替代。生产投影同步、局部订阅取消或正常写文件结束均不代替消费确认；无初始帧、缺口、提前终止、无终态锚点或无法确认末端时明确标记未知或截断。逐成员采样不是跨 Thread 原子快照，不据此宣称零竞态全局观察。
  - **工作区版本证据**：运行前后只读保存实际 HEAD、状态、暂存区与未暂存差异；允许预置脏工作区不等于允许丢弃其原始内容证据。未跟踪内容的采集范围、缺失及预算边界必须明确，不能仅凭路径列表声称能够还原全部初始现场；错误或超限保留部分证据并标记不完整，不通过 reset、stash 或自动提交改变已有 fixture。
  - **完成与持久性证据**：工作流终态、执行静止、持久历史验证、显式资源关闭和采集覆盖是独立事实。根会话与未关闭成员继续要求真实存储投影健康且持久水位追平受理水位。仅对同树、目录与快照均已关闭且无执行、活动或待决交互的子会话，存储投影缺失时可另用公开 Turn 历史访问已通过持久 checkpoint 栅栏、非空终态身份及同步前后稳定观察构成关闭历史证明；缺失投影保持缺失，不伪造数值水位，不将快照提交修订号当作 history fence。已有存储投影的故障、暂停或未追平状态仍阻塞，历史验证失败或空页也不能默认健康。候选确认继续同步投影、重读目录与快照、重新验证历史及终态身份，任何变化均重新采样；事件锚点与完整导出保持独立判据。已关闭成员允许保留的历史欠工作仍单独记录，不称为无欠账。此证明不表示物理资源已释放；物理关闭需绑定真实成功关闭交付与退出回执。工作流已完成但采集证据未齐时，应明确报告两者，不能误称工作流未完成或事后为旧运行补造完成证明。
  - **有界订阅负载诊断**：可以复用现有回环供应商与观察入口，在合成配置、独立凭据服务及自有运行时目录内施加高吞吐负载，区分主动消费时的交付积压与真正慢消费者的有界溢出。记录实际发出数量、流是否结束、订阅缺口与回收；只执行脚本前缀时必须保留未完成场景的失败，不冒充完整通过。真实 `lagged` 仍使连续区间不完整，不通过扩大缓冲、忽略缺口或拼接重订阅抹去失败。
- **停工、建议与裁定观察**：真实任务遇到设计矛盾或信息缺口时，人工核对执行者是否在继续实施/试验前通过现有 `finish_turn` 提交完整停工报告并结束本轮；没有遇到的分歧不强造为必跑场景。报告原要求、事实、问题、影响、现场和所需决定，有建议可附候选、理由和假设，不能先行实施。按实际进展观察主智能体裁定及新 Turn 续跑，不只凭停工判全任务完成。模型遵循失败、业务结果及采集完整性分开记录，接受模型不确定性不回写旧失败，也不要求反复修订提示直到每轮遵循完美。
- **结构化审查产品链的受控诊断**：既有真实装配与受控供应商可用于核对三态结论、非 review 拒绝、目标关系、忙/关闭/新输入拒绝、缺结论与异常终态不批准、稳定身份去重和恢复、父紧凑报告与全文按需读取。受理、结果未知、拒绝及修复完成分别判断；不把模拟报告证明外推为真实模型能合理审查，不将所有受控分支通过作为上述人工观察的前置条件。保存/迁移专项继续按 §24.1 的许可边界验证，不为本产品链新增其他 crate 的自动化门禁。
  - 受控场景扩展既有 `manual-gui` delegation 供应商、真实工具回执驱动与 Driver 旅程，不另造宿主或报告重投接口。各独立根会话使用有界调用序列，从实际 spawn、消息、终态与公开历史取身份；供应商响应闸门只控制外部回复时机，用真实目标状态证明忙碌、新交付或关闭，不以等待时间猜测交错。
  - 父紧凑报告不等于上下文压缩：在父主动读取全文之前，检查独特正文标识不经 review 正文、commentary 或最后工具参数进入父请求；同时确认完整正文仍在执行者回送与审查者公开历史中。父随后显式按需读取全文是授权读取，不当作默认投影泄漏。既有 delegation 审查旅程同步消费结构化结论，不继续把自然 final 的文字当批准。
  - 原终态报告与实际投递分别取证：核对结论报告同终态保存、原字节不被之后回执改写，`needsChanges` 仍给创建者简短通知，只有冻结授权的需要修改结论启动目标。目标拒绝、适用性失败或发送未知通过独立异常通知呈现；核对原身份关联、同字节去重和分别的持久确认，不把原报告 ACK 当异常已送达。现有保存专项覆盖异常应用事实的 CAS、提交后取消、writer/观察自等待及关闭门锁交错，不为此新建工具、队列或测试专用生产接口。
  - 工作树物理观察与审查反馈是正交受控场景，各自保留实际 Git、工作区、关闭和重开判据。物理观察 reviewer 的结构化结论只评价明确分配的观察范围，不冒充业务代码批准；需要完整 Git 证据时，通过既有公开历史按真实 agent/turn 显式读取，不将大正文放入摘要或默认父报告。合成审查文件属于隔离 fixture 初始提交，不能以未跟踪脏文件破坏工作树创建准入，也不由此授权自动提交真实业务改动。
  - 正常关闭重开后，通过公开产品流程检查已保存报告身份、目标输入和供应商请求没有重复，冷对账不新增回送或唤醒。没有公开入口可构造的 observer 崩溃及未移交窗口，明确保留为代码审查与许可的保存专项覆盖，不通过私有注入、直接改库或伪造报告宣称完成实测。
  - 身份证据以公开接口实际提供的事实为限：可观察的原消息身份、执行者实际模型请求中的完整 wrapper/正文摘要、随后新提交的 Turn 及重开前后请求计数共同支持正常链判断；原紧凑结论不再承载实际 forward 回执，不能据其身份推断消息已受理，未公开的回执也不补造。现有终态报告的 `messages` 不是完整 inbox 清单，消息触发的 Turn 可以没有 `inputId`；不从 opaque 字符串反推不存在的输入身份，也不为验收增加反馈输入历史卡片或生产查询工具。全文历史证明针对 reviewer 的原始交付；上述组合证据不宣称逐 inbox 消费账本或任意崩溃窗口均已公开可观测。
- **计划跨重启恢复场景（`plan-recovery`）**：在同一隔离数据根中提交真实 `plan_submit` 计划确认、正常关闭并等待进程回收后重启重开，分别验证批准路径（含通过状态栏「更多」菜单打开已批准计划面板、并排拖动分栏宽度）与修改反馈路径，确认重启前后计划正文与交互身份一致且无重复续跑（continuation）。
- **应用退出与子进程树回收场景（`shutdown`）**：通过 `cargo xtask run-gui --driver --native-launch --native-exit-report <PATH>` 直接作为原生 GUI 进程的父进程采集真实操作系统 `waitpid` 状态、原生 PID（配合 `/proc/<pid>/stat` 启动时间防复用）与未被产品自身回收的后代进程集合（`reclaimedDescendants`）。分阶段（phase）验证：正常保存退出码 `0` 与重开历史核对；同数据根单例激活转交（第二进程退出码 `0` 且无重复窗口）；重复退出请求不重置首次 30 秒总期限；Driver 挂起时原生守护线程在 30 秒到期强制返回退出码 `1`；运行时初始化失败、SQLite 写锁阻塞、外部模拟服务冻结时的有界退出；以及本地 `stdio` MCP、LSP 与后台 `exec` 工具派生的忽略 `SIGTERM` 独立进程组孙进程在强制退出后由产品自身监督器完整回收（`reclaimedDescendants` 为空）。Windows 系统托盘隐藏与恢复作为独立窗口壳层验收单独记录。
- **上下文重放与调用生命周期恢复（`context-replay-recovery` / `websocket-recovery` / `call-lifecycle-recovery`）**：分别覆盖 Responses HTTP、WebSocket 与 Chat 跨重启重放、WebSocket 断线重试与退避期间停止、工具目录刷新失败保留有效工具、压缩耗尽后继续以及取消后 31 秒静默窗口无多余请求。

## 24.3 GUI 人工验收证据

本地模拟 GUI 人工验收由独立工程工具 `pl-studio-acceptance` 编排（通过 `cargo xtask manual-gui` 按需编译并透传参数，复用 `pl-dev-support` 的路径与进程树管理，并在服务就绪计时前完成固件编译）。真实厂商与模型的原生人工观察使用 `cargo xtask run-gui --driver` 等现有真实入口，不能把模拟供应商结果外推为真实模型行为。按实际入口核对真实窗口截图、界面组件树（widget tree）、权威快照、必要请求/诊断和所属进程真实回收；没有模拟服务的观察不虚构模拟请求记录。脚本退出码仅表示采集流程完成，最终视觉与交互结论由人工核查截图后独立判定（默认标记为“待评审”）。

多阶段原生旅程的诊断归档与阶段成功判定独立：已经产生的 GUI 与 Driver 日志在阶段失败时仍须脱敏保留，不能因该阶段未进入成功清单而随隔离环境删除。日志归档不补造未观察到的退出状态，不改变原始失败退出或后续阶段的准入条件。

计划详情的正文呈现须由实际正文子树的渲染文字证明，不能仅回读计划快照或匹配面板标题。验收复用官方 Driver 渲染诊断，适应 Markdown 组件使用 `Text`、`RichText` 或其公开扩展的呈现方式；缺失、截断或不匹配的正文诊断仍为失败。

活动成员的展开验收绑定真实条目身份和已挂载标题，读取其纯视图公开的展开属性；官方展开组件仍读取其公开控制器。未知或缺失的状态不得解释为收起，详情入口中复用的活动行不得替代成员标题。展开与收起通过真实指针触发，并结合正文尺寸、滚动几何及同一展示代次判定，不为验收创建领域所有者或额外生产状态。

长历史流式冻结后的分页重试遵循 [26.8](./26-timeline-content.md#268-客户端与展示租约边界) 的覆盖资格，而不以后台执行完成或落盘就绪推断旧资格重新有效：资格仍有效时，验证同一冻结代次的有界前插；若返回明确的 `protocol`／`timeline-page-continuity` 失败，验证原代次、正文与水位仍冻结，再通过真实“回到实时”操作取得成功的新基线。两条路径都须继续完成新资格下的深页读取与同一持久化身份冷重开；其他错误、缺少新基线或缺失后续分页证据不能降级为通过。

人工验收 harness 使用官方 Cargo `release` profile 构建独立的 `pl-provider-fixture` 可执行文件，构建和产物定位仍由 Cargo 负责并在服务期限开始前完成；这不改变 GUI 的 Driver/debug/profile 选择，也不改变自动化测试链接 fixture 库的构建模式。优化构建用于避免大型完整请求证据的序列化成本挤占退出预算，不允许因此删减记录、改变受控协议步骤或放宽既定停止期限。最终证据仍须完整写入并原子发布，且必须观察到供应商进程真实退出；两者缺一均视为验收失败。

升级恢复验收可通过 `cargo xtask manual-gui --scenario gui --seed-home-copy <DIR>` 消费已关闭、经 SQLite backup API 制作的一致性 home 副本。工具只读复制该输入到自有隔离环境，拒绝带 WAL/SHM 或符号链接的输入；保留项目、会话及账本事实，将账号端点切换为本地模拟供应商，并在启动前禁用机器人外发、MCP、LSP 与 ACP。来源副本和真实数据根都不修改；截图、快照、迁移前后数据库核对及进程回收共同构成证据。副本模式通过原生启动器运行，Driver 收束后请求产品退出，并核对原生退出报告中的退出码和子进程回收结果。

关键界面与交互领域的专项人工取证要求包括：

## 24.4 实时新鲜度验收矩阵

账号功能的纯视图预览作为呈现边界的独立证据：使用官方 Widget Previewer 直接渲染生产列表、详情、编辑与关键组件，只有合成不可变展示值、本地动作和生产主题/本地化，不装配 Client、Repository、ProviderScope 或 Rust bridge。实际验证预览发现、Web 编译、资产/中文、热更新、局部交互、截图与进程回收；覆盖空态、刷新/保留数据的失败态、余额/订阅、Native/ACP、模型展开、长名称及文字缩放。它不构成真实原生数据或保存证明，不新增 widget/integration 门禁。

现有 Client 语法边界检查同时约束账号纯入口、呈现值、View、Widget 与预览的直接依赖：禁止引入 SDK、业务 Provider、Connector、ViewModel 或平台数据层；共享依赖仅限主题、本地化与品牌呈现。ViewModel 不导入 Flutter Widget 层、界面模块或具体 adapter，呈现值不导入 Flutter/状态管理层，也不声明异步资源类型；功能模块仅允许生成器拥有的 `part`。检查覆盖相对路径、包路径及条件导入/导出，以有效 Dart 程序证明拒绝和允许行为，不将注释或字符串当作代码。此检查是可判定的语法门禁，不推断任意别名、动态对象或间接资源所有权；实际依赖闭包、生命周期与可预览性仍由代码审查、应用契约测试和官方 Web 运行证据共同证明。

原生账号验收另行核对宽/中/窄窗口下的全主区详情、搜索/滚动恢复、模型开关对齐和所有管理入口；用量失败保留结果、模型同步重复/配置变化/删除迟到、编辑离页与旧保存保护，以及 ACP 安装/认证取消和失败恢复都需沿真实 bridge 验证。界面树、截图、领域快照、请求与真实进程回收共同构成结论。自动化优先迁移已有 Client/adapter 契约测试，边界检查复用现有 analyzer 入口而非另建框架。

账号 Driver 只读取已经装配的领域镜像和已存在的呈现实例：读取详情、编辑或模型资料前确认对应 ViewModel 已存在，不为诊断初始化 provider、创建详情槽、发起查询或声明可见需求。领域来源、具体目标、版本及过期状态分别表达，未观察的信息保持未知；已退役的整卡字段与兼容占位键随所有旅程消费者一起删除。验收专用呈现诊断只暴露选择、编辑身份、dirty、保存阶段、草稿修订及已有资料读取阶段，不序列化凭据、原始密钥输入或资源所有者。Driver 交互复用生产控件的带账号类型与模型复合身份的稳定 key，业务变化仍由真实界面动作触发；测试脚本不通过直接修改 provider 或调用仓储命令制造成功。

账号模拟对端允许在同一进程生命周期通过显式受控动作切换目录清单、单账号失败及请求闸门，用于证明无需重启的同步、重复请求合并与迟到结果隔离；不通过重启 GUI 或直接改产品状态制造成功。控制只作用于本次隔离环回对端，保留请求计数、命名状态和闸门释放证据，不记录真实凭据。控制文件仍是启动输入，修改文件不隐式改变运行中的对端；等待由明确请求/释放信号驱动，退出必须唤醒并回收所有闸门等待者。

目录对端控制证据每个供应商实例最多保留 **256 个已受理请求身份**、最多 **16 个同时等待的闸门请求**，完整状态响应上限 **64 KiB**。达到任一边界后在受理前明确拒绝，不增加受理计数或遗留等待登记；身份和计数使用受检递增，不回绕复用。已受理证据在预算内完整保留，不静默截断；闸门等待登记在请求完成、传输取消与关闭时释放，不能把已取消记录当真实在途证据。无参数控制动作同样拒绝额外字段，HTTP 语法/结构错误沿框架原始错误分类返回。

统计模块 `StatisticsRepository` 的公开行为测试独立于旧版 Client 与聚合引导快照（Bootstrap），覆盖固定来源的完整窗口物化、未变更统计材料复用、版本／代次隔离拒绝迟到回包、读取失败保留最近有效数据（`last-good`）、页面隐藏／重新打开、读取容量预算与真实关闭汇合等待。呈现层适配测试通过直接注入 `StatisticsRepository` 验证筛选状态与可见观察需求，不使用旧版存储（Store）作为测试夹具旁路；架构审查同步核对领域层、端口（Port）、适配器、视图模型（`ViewModel`）与纯视图（`View`）的单向依赖方向、唯一公共导出路径及旧接口清理，确保不残留重导出或新调旧兼容层。原生桌面端验收另行核对推送流确认（ACK）、不可变分页读取与关闭回收，比对重构前后相同窗口尺寸下的截图、组件树（Widget Tree）、模型／推理强度／模型不匹配筛选及列表滚动行为。

## 24.5 单一时间线内容链路验收

时间线分页、尾部订阅与详情读取按 [26](./26-timeline-content.md) 执行端到端收敛验证：
- **单一内容源与无空洞交接**：历史分页查询无缝合并未落盘内容与持久化历史，尾部订阅 `initial` 与接收登记无间隙交接，会话轻量状态流不夹带正文帧；HTTP 与 FRB 共用同一类型化转换。
- **增量独立性与并发安全**：条目内容修订号、尾部 `from/to`、落盘确认（`saved`）、传输消费 ACK 与轮次终态相互独立；首字到达与终态收束立即发布，常规合帧不重复拼接词元；慢消费者与断流显式建立新基线，热缓存淘汰不删除前端已加载消息；挂起的推送等待与未 ACK 帧不阻塞分页查询或连接关闭。
- **恢复准入与准备重试**：分别验证域内内容重同步与整条组合连接重建的身份边界；等待期间转为读取阻塞时，已捕获基线与已就绪数据也不得越过交付前检查。历史保存故障专项覆盖父报告准备失败后重试同一提交，确认复用已准备批次、内容修订及原始报告不因重试重复投影而变化，且原保存、重试和关闭责任未被提前释放。
- **零订阅与广播隔离**：没有消息订阅者时仍可执行并可靠保存，但不组装、编码或发送对外消息流帧；后来订阅读取完整当前基线。两个消费者同时观察同一会话时各自连续，慢端重同步不影响快端，关闭一端不停止另一端或写入器；最后一端关闭后无消息事件泵遗留。GUI 离开会话页释放其需求，飞书仍可独立完成回复，不为全部侧栏会话开启正文订阅。
- **原生消息类型与保真**：同一助手消息从流式到终态保持 ID、原始字符与换行，活动流状态随结束释放；图片/文件使用官方组件且授权读取不越界。工具、计划和问答保持领域判别与脱敏，不因原生消息映射丢失状态或将停止改为错误。
- **原生逐帧呈现稳定性**：针对持续纯文本流、持续推理摘要与长篇 Markdown 输出，以及历史滚动、落盘确认、会话切换与断线重连场景，**必须在动画尚未静止（settle）的中间帧上进行判定**，确认连续流式输出期间无中间空白帧、活动摘要无淡入淡出频闪叠影、落盘确认不改变正文几何尺寸、后台新输出不打断历史阅读位置。

飞书实际消息另按 [27](./27-bots.md) §27.9 使用 CLI 独立回读产品生成的消息。CLI 可证明的发送者、正文、关联与平台消息身份，与产品请求记录证明的卡片流式时序分别报告；模拟平台、CLI 自发自读或原生 Studio 截图均不能替代真实产品回复核验。真实账号测试限定明确的验收目标和合成输入，认证或权限缺失属于未完成项而非通过。

## 24.6 存储职责重构验收

长耗时任务验收须证明会话常驻内存状态不保留历史请求完整输入，最新上下文以增量方式追加写入而不反复序列化整段历史前缀。同一确定性回归测试遵循“先红后绿”验证，并记录内存占用、SQLite 数据库与 WAL 文件体积、日志大小及总写入字节数。覆盖场景包括：上下文压缩后的工具身份去重、最新请求重试、重启后不重复执行已完成工具、历史记录与检查点同事务原子提交、确认丢失重放、数据迁移中断接续以及诊断日志按时间与容量上限自动淘汰（日志写入故障或清理绝不改变会话累计词元用量与恢复结果）。

## 24.7 上下文连续实施验收

确定性公开 API 回归测试覆盖运行时事实追加与失效、完整输入预览、冻结水位、取消与冲突拒绝、系统指令更新能力、指令来源约束及完整工具批次闭环。原生 GUI 场景通过 `context_state_journey.dart` 驱动真实界面：在任务模式下批准计划、推进至非初始工作流阶段、连续触发两次上下文压缩、继续执行任务、正常关闭并重启应用，验证无重复计划批准弹窗、无阶段回退、无工具重复执行，并核对独立根会话与父子、兄弟智能体会话之间的上下文与指令快照严格隔离。

## 24.8 账号、额度与 MCP 隔离验收

账号架构迁移与隔离验收覆盖以下确定性回归与原生观察：
- **账号架构与跨版本保全**：验证同名模型在不同账号实例间严格隔离、各厂商目录与协议解析独立、账号 ID 稳定不变、配置/智能体模板/系统凭据跨版本升级完整保全、迁移提交中断后重启可接续，以及既有 v2 会话扩展与调用统计库完整保留。
- **账号自动额度并行加载**：按 [25.7.1](./25-frontend-state.md#2571-账号用量需求) 验证进入账号标签页后无需点击刷新即按实例并行发起额度检查；当慢速或返回 `401` 的实例尚未结束时，快速实例已独立展示成功结果，且期间账号编辑保存、新增/取消、切换设置标签及新建会话均不受阻塞。修改默认路由、账号显示名称或筛选条件不会触发全量实例重查；隐藏期间新增或更换密钥的实例在重新可见时精准补查，迟到响应绝不复活已删除账号。
- **智谱 Coding Plan 内置 MCP 凭据门控**：在权威配置合成边界验证空密钥、普通智谱模板或域名不匹配时不连接不暴露工具、存在多个 `zhipu-coding-plan` 实例时按账号 ID 稳定选取首个有效凭据实例，以及密钥轮换、清空、删除账号与显式禁用开关的实时联动。
