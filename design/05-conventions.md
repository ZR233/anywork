## 5.1 参数与类型设计

- **线协议命名与基础类型**：序列化类型统一使用 `#[serde(rename_all = "camelCase")]`，Rust 字段保持 `snake_case`。ID 使用 `String`，内部按需解析 UUID；时间戳使用 Unix 秒 `i64`，字段命名为 `*_at`。
- **消除布尔参数歧义**：核心接口不暴露语义模糊的裸布尔参数；前端输入在 `anywork` 边界处统一转换为语义明确的枚举或值对象。
- **工具参数模式与分页游标绑定**：工具的参数模式（schema）必须完整描述影响参数有效性的全部约束。分页游标（cursor）只能与生成该游标的请求投影配套使用；翻页请求必须保持游标所绑定的过滤条件、目标路径与匹配参数不变，一旦工作区发生变更，旧游标立即失效。
- **补丁控制前缀转义**：Codex 补丁（patch）的 `Update` 块（hunk）中，每行首字符固定为控制前缀（空格表示上下文行、`-` 表示删除行、`+` 表示新增行）；当代码行正文自身以 `-` 或 `+` 开头时，正文字符必须紧跟在控制前缀之后（例如删除 `- old` 写作 `-- old`，新增 `- new` 写作 `+- new`）。

## 5.2 模块与导出

- **单路径精确导出**：模块默认保持私有；稳定的领域边界通过清晰的命名空间组织，仅对少量高频入口做精确重导出（re-export）。同一公开接口只保留一条规范（canonical）导入路径，不维护根模块与子模块双轨导出，严禁使用通配符（`*`）将内部底层实现暴露到公共边界。
- **按内聚职责拆分文件**：单一职责模块保持单文件结构；仅当存在多个真实、内聚的子职责时才拆分为子模块，禁止建立仅做符号转发的空壳目录层。
- **严守跨层导出边界**：`pl-core` 仅导出自身通用契约，不镜像模型厂商、具体工具或产品线协议（wire）类型；`pl-model`、`pl-tool` 与 Studio 层仅在公共函数签名直接引用时精确重导出所需依赖类型，不构建整套 API 转发门面。

## 5.3 生命周期状态机模式

具备严格时序关系、非法转换约束、终态封闭或故障恢复语义的领域对象，统一建模为单一状态机聚合（aggregate）：

- **状态内聚封装**：对象身份与跨状态共享的上下文保存在聚合根结构上，唯一的可写生命周期状态定义为携带状态私有载荷的标签联合体（tagged enum）。仅在特定状态下有意义的时间戳、失败原因、进度或计算结果必须封装在对应状态变体内部，禁止提升为聚合根上的平行可选字段、布尔标志位或第二个状态枚举。
- **纯领域转换决策**：状态变更只接受语义明确的命令（command），由纯领域函数校验并返回包含「下一状态、持久化效果（durable effects）、外部副作用（external effects）」的转换决策（decision）。状态机模块本身不执行 I/O、异步等待、加锁或外部回调，由外层适配器在事务与生命周期边界统一解释并执行效果。
- **转换封闭与幂等判别**：禁止提供通用的强制设值（`set_state`）、预判查询（`can_transition`）、零散字段拼装（`from_parts`）或动态状态分发入口。终态不可继续向外迁移，故障恢复必须定义为从指定可恢复状态出发的显式命令。重复的操作 ID、邮箱消息或修订号仅在完全匹配幂等身份时作为无操作（no-op）返回原结果；其余同态命令或携带过期修订号的请求一律返回类型化的状态转换错误。
- **跨语言序列化与存储映射**：公共协议中的生命周期状态统一采用 `kind`/`data` 判别的标签联合体（字段名使用 `camelCase`），Dart 端映射为封闭联合类型（sealed union）并执行穷尽匹配。SQLite 对需要按状态过滤的记录保存完整状态 JSON，索引判别列仅能从 JSON 判别字段派生生成。普通的静态分类、配置项、能力标志、作用域、传输类型、日志级别、解析游标以及无状态转换规则的一次性结果继续使用常规枚举，不为追求形式统一而过度引入状态机。

## 5.4 命名口径

- **产品与技术标识**：面向用户界面与智能体系统提示词统一使用产品名「糊来帮」（英文 `anywork`）；代码仓库与底层技术标识保持为 `pure-lang`。
- **包命名规范**：Rust 库 crate 统一以 `pl-` 开头；Flutter 桌面应用包名为 `anywork`，纯 Dart 客户端包名为 `anywork_client`。
- **协议归属**：产品级线协议类型集中定义于 `pl-protocol`；内核通用契约在 `pl-core` 各自的领域模块内定义。

## 5.5 后台进程与外部服务

- **Linux 子进程监督与整树回收**：Linux 命令监督器由单线程子进程负责接管与回收，通过标准进程信息接口及稳定的进程句柄确认所属后代进程，不依赖可选的内核子进程列表特性。进程信息解析优先复用成熟组件；已经自然退出的无关进程可直接忽略，但真实的权限拒绝或解析失败必须显式上报，严禁在无法证明子进程树已完整回收时报告成功。
- **跨平台后台进程创建策略**：桌面运行时派生 shell、Git、MCP 服务、LSP 语言服务器等后台子进程时，Windows 平台必须附加 `CREATE_NO_WINDOW` 标志以禁止弹出命令行黑框（Job Object 托管路径在创建进程前合并该标志），Unix 平台则创建独立进程组以便整树信号回收。上述进程创建配置由 `pl-remote-helper` 的统一进程工厂提供，原生路径与 Job Object 路径均从该工厂获取等价策略，`pl-lsp` 等其他 crate 不得复制实现。
- **标准输入输出型（stdio）MCP 启动规范**：`stdio` 类型的 MCP 配置保存跨平台命令名，不硬编码平台扩展名，也不统一包裹外层 shell。Windows 平台按 `PATHEXT` 解析可执行文件并保持直接启动语义；标准的 `npm`/`npx` 启动器必须直接展开为 `node` 加目标 CLI 脚本，不得让长期运行的 MCP 连接挂载在临时 shell 包装进程（shim）下，且派生子进程时须显式隐藏窗口。子进程的 `stdin`/`stdout`/`stderr` 必须全部通过管道接管并消费，禁止继承 Studio 宿主终端；`stderr` 输出仅以有界、脱敏的形式附加到启动诊断错误中。
- **MCP 协议版本协商与回退**：MCP 客户端优先发送 `server/discover` 协商已知协议版本；仅当对端明确返回 `METHOD_NOT_FOUND`、证实为传统协议实现时，才回退至标准 `initialize` 握手。若流式 HTTP（Streamable HTTP）传输层将发现阶段的终止 SSE 流折叠为已关闭的响应，客户端必须建立全新的传输连接重试标准 `initialize`；该兼容回退不得扩大到鉴权失败、超时或其他协议错误，亦不得针对单一厂商编写硬编码版本特判。
- **启动期慢能力异步化**：启动路径中的慢速操作（如 MCP 服务连接探测、LSP 二进制探测）一律在后台异步执行，探测结果通过产品事件流增量推送，绝不阻塞主界面骨架首帧渲染。单个 MCP 服务的启动或探测失败仅归属到该服务自身的运行时健康状态（投影为不可用及有界、脱敏的错误摘要）；配置的启用开关与运行时的可用状态严格区分，单一外部服务故障不得阻塞 Studio 主界面运行。
