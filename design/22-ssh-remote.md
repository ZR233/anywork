# 22 - SSH 远程开发

## 22.1 架构边界与实例生命周期

SSH 远程开发是本地运行时的宿主扩展能力，而非第二套远端运行时。Flutter 前端仅调用类型化 Studio 接口并展示权威快照；SSH 服务器管理、连接状态机、远端辅助进程（helper）安装、通信协议、断线重连与远端工具后端均位于 `pl-tool`；`pl-studio-runtime` 仅实现 SQLite 存储、可选系统凭据库与辅助进程随包资产适配器。SSH 服务器配置不属于产品私有数据库数据，其唯一事实源是用户本地的 `~/.ssh/config`（Windows 下为 `%USERPROFILE%\.ssh\config`）。

远端辅助进程（`pl-remote-helper`）是宿主的物理执行底座。每个宿主运行时与 SSH 主机别名拥有独立的辅助进程实例；稳态下仅通过一条 SSH 标准输入输出通道（stdio channel）承载单条 HTTP/2 多路复用连接，所有工作区、命令执行、文件读写与控制操作均作为该连接内的独立流（stream）并发传输。首次平台探测与资产安装通过短期引导进程（bootstrap process）完成并在结束后立即回收；辅助进程的远端本机 IPC 不额外占用 SSH 连接。

辅助进程实例与连接代次分别管理生命周期：
- **接续凭证与心跳租约**：辅助进程实例通过私有 Unix 域套接字接受 SSH 中继（relay），接续凭证经加密通道传递，不进入命令行参数（`argv`）、日志或产品数据库。新连接代次接管后，旧连接代次不得继续操作远端资源。网络断线仅撤销传输通道；每 **5 秒**一次的有应答业务心跳维持 **30 秒**的实例租约，在租约有效期内重连可无缝接回原运行中子进程及文件句柄（底层 HTTP/2 `PING` 帧仅用于连接诊断，普通数据流与 `PING` 帧均不续期业务租约）。
- **租约到期与进程树回收**：当 30 秒租约到期或收到显式关闭指令时，辅助进程立即锁闭准入、回收子进程树与所属暂存文件，等待物理收束后退出。终止子进程时先发送 `SIGTERM` 并给予 **2 秒**优雅退出窗口，超时后升级为 `SIGKILL`；若回收失败仍保留清理责任，严禁将超时伪报为成功。

本地宿主掌握工具业务语义、命令构造、技能发现与递归复制所需的目录遍历、预算分配、故障恢复与归档策略；模型自主文件搜索与读取遵循 [工具运行时](./09-tool-runtime.md#97-文件发现与读取归属命令工具) 的显式命令契约。远端辅助进程不持有会话（`Thread`）、轮次（`Turn`）、工具结构定义、模型路由、Git 工作树策略或时间线状态，仅负责必须依据远端物理事实执行的文件路径边界校验、进程监督、物理文件偏移与落盘回执。输出捕获（capture）由宿主声明两个原始流目标与合计预算，由辅助进程直接写入远端文件并同步原始输出，避免将完整日志下载回本地再重新上传。辅助进程退出、应用重启或远端机器重启后不恢复历史后台任务。

## 22.2 传输协议、资源预算与并发控制

### HTTP/2 协议版本与流分类

远程协议当前固定为**版本 10**（双流原始捕获、每流确认偏移及启动剩余期限；不保留旧协议兼容分支）；未知协议版本直接报错拒绝，客户端与随包辅助进程同步升级。HTTP/2 协议栈统一负责帧封装、多路复用、流控与连接级错误检测：
- **控制流与数据流分离**：目录条目、文件内容与命令标准输出均承载于请求或响应消息体（body）中；生命周期管理请求与文件状态查询（`Stat`）则采用受独立字节预算约束的纯头部（HEADERS-only）交换，确保在 `DATA` 帧流控窗口耗尽时仍可即时确认业务心跳、取消指令与文件元信息。携带凭据的头部字段严禁进入 HPACK 动态表索引。租约续期、收尾清理与元数据操作拥有独立准入通道，慢速文件关闭不占用终止通道。
- **短流、长流与跨连接接续**：普通元数据请求使用短生命周期流，每个命令输出使用独立长流，文件内容直接作为二进制消息体传输；应用层逻辑分片与底层 HTTP/2 帧大小相互独立（`16 KiB` 仅作为 HTTP/2 的标准流控进展单位）。HTTP/2 `Stream ID` 不作为跨连接身份；断线重连后的操作接续依据实例身份、操作身份、物理文件偏移与输出序号执行。

连接驱动层不阻塞等待业务消费者、子进程退出或磁盘落盘。命令启动返回句柄后立即释放普通请求准入配额，运行中的子进程另行持有运行租约；`stdin`、`stdout`、`stderr`、进程退出监听、输出捕获与取消指令各自独立推进。HTTP/2 `RST_STREAM` 仅结束当次传输交换，远端物理子进程由显式终止操作及其所有者负责回收；任务终态仅在子进程退出、输出交接完成且必要落盘结束后发布一次。

### 动态资源预算与防饥饿流控

本地宿主在所有 SSH 连接之间共享统一资源预算，远端辅助进程实时上报实际资源占用与可用余量：
- **预算计算与按需分配**：`ResourcePolicy` 综合系统可用内存、`cgroup` 限额、相对份额与宿主显式上限（ceiling）计算总预算，再按各连接的实际需求动态分配；连接级流控窗口与独立控制池均从同一宿主总预算中预留。等待队列登记按实际元数据字节计入预算，取消等待时同步归还登记配额；控制交换池耗尽时仅暂停新的控制交换，防止等待登记与正在完成的控制消息争用同一子池。收缩预算时先削减未来准入配额与窗口信用额度（credit），继续承接已授予但尚未确认的在途数据，待空闲后释放容量。
- **分片公平准入与防饥饿**：连接级与流级窗口共同纳入预算管控，数据流不得占满控制请求的流准入与完成资源。大文件读写按可推进分片申请准入，防止整文件大额预留阻塞并发小请求；同时，字节等待队列允许小请求绕过暂不满足的大额申请，但当绕过的累计字节达到最老等待申请的一个进展分片（progress chunk）阈值后，即优先为该最老申请累积释放额度，防止持续小请求导致大文件传输饥饿。
- **建连合并与无锁等待**：建立连接与断线接续的在途结果由连接管理器共享，单个等待者取消不会中断其他并发需求。工作区单次在途打开操作先发布弱引用缓存再移除在途登记，并在调用返回前等待结果生产者关闭。内部互斥锁仅保护极短的内存状态变更，严禁跨网络 I/O、磁盘读写、进程等待或外部回调持有锁；资源准入先于副作用执行，一次性预留下一步所需的全部资源，消除“持有一类配额等待另一类配额”的死锁风险。

### 增量目录读取、原子文件传输与阶段计时

- **单层增量目录游标**：远端辅助进程以可释放的单层目录迭代句柄增量读取目录项，不在远端执行递归遍历、通配符展开、技能扫描、过滤或全量排序。本地宿主为技能发现和递归复制编排遍历，为目录选择编排过滤与分页；底层游标绑定辅助进程实例与所属工作区或目录浏览操作，切换目录、取消或显式关闭当前页时释放底层读取器，关闭所属工作区或辅助进程时回收其剩余目录句柄。不另维护模型目录工具的递归分页状态及空闲租约。
- **文件完整性校验与原子发布**：文件操作仅接受常规文件（regular file）。文件下载绑定源文件身份与字节偏移，结合文件变更信息与 SHA-256 摘要校验完整性；文件上传先写入当前操作独享的临时文件，确认完整分片后推进偏移。新建（`Create`）、覆写（`Overwrite`）与追加（`Append`）由本地宿主编排，辅助进程返回真实写入、刷盘（`fsync`）与原子重命名发布回执；断线重连后先查询远端物理事实，严禁盲目重发追加、发布、`stdin` 写入或进程派生指令。`Append` 操作在路径级提交锁内构造完整替换文件并原子发布，若源文件并发变化或复制失败则不遗留部分追加内容。`copy_file_from` 与 `copy_file_to` 直接桥接异步读写流，无需将整个文件载入内存。
- **命令输出背压与单调时钟诊断**：每个运行中命令的未确认输出按序号保留并计入内存预算，触顶后仅对该命令施加背压，本地宿主确认交接后即释放缓冲；终态回执确认后立即移除登记，不保留历史墓碑。请求回执携带远端以单调时钟计量的准入、接收、进程操作与文件 I/O（含摘要校验）各阶段耗时，`DATA` 尾部帧（trailers）携带发送流控等待耗时，本地宿主另行记录自身准入、交换与回执释放耗时（诊断记录不含敏感凭据或文件正文）。

握手响应返回协议版本、辅助进程构建号、操作系统与 CPU 架构、能力集以及实际 Shell 描述符（shell descriptor）。Linux 实例首次创建时通过受监督的 Shell 环境采集机制提取一次用户导出环境变量，断线接回同一实例时不重复执行登录启动脚本；新建实例时重新采集。常规命令、Git 与 LSP 共享同一采集环境（显式传入的请求级 `env` 最后覆盖），不继承 Shell 别名（alias）、函数或依赖交互式终端（PTY）的状态。

## 22.3 本地工具集成与 SSH 主机管理

`pl-tool` 中的 SSH 管理器负责服务器配置校验、系统 OpenSSH 调用、架构探测、随包辅助进程引导部署、Shell 描述符握手、连接状态维护与自动重连，并向上层返回带执行环境的远端工作区宿主（workspace host）。该宿主实现或组合既有的文件、命令、Git、工作树、技能与 LSP 后端，经由统一工具安装入口注册标准工具——模型侧看到的工具名称与本地项目完全一致，绝不暴露 `remote_read`、`remote_exec` 等远端专用工具名。

### `~/.ssh/config` 管理块读写契约

SSH 服务器列表直接读取并解析用户的 `~/.ssh/config` 文件；新增、修改与删除受管服务器时，以带标记的管理块原子写回该文件，未触及的内容（含原始注释与行尾换行符风格）逐字节原样保留。管理块采用以下定界符包裹 `Host`、`HostName`、`Port`、`User` 与 `IdentityFile` 指令：

```sshconfig
# BEGIN anywork server: <alias>
Host <alias>
    HostName <hostname>
    Port <port>
    User <user>
    IdentityFile <path>
# END anywork server: <alias>
```

`Host` 别名即服务器的唯一身份（创建后不可改名，必须为非空单词元且不含通配符或否定字符）。配置解析遵循 OpenSSH 的首次匹配语义（每个关键字取块内首次出现的值，`HostName` 缺省回退为别名）；包含通配符、多模式或 `Include` 指令的复杂条目不进入可选列表，用户手写的普通 `Host` 条目以只读方式展示，编辑与删除仅对 `anywork` 管理块开放。新建别名若与文件中已有 `Host` 冲突则自动分配无冲突后缀；运行时内部发起的 `ssh` 调用仅传递 `Host` 别名，端口、用户名、私钥与跳转配置（`ProxyJump`）全部交由系统 OpenSSH 根据配置文件解析，运行时不维护第二份连接参数。

### 远端工作区、POSIX 路径归一化与连接状态机

文件匹配、Git 工作树编排、技能组装、工作区指令解析、图片归档与 LSP 客户端等与环境无关的逻辑均保留在本地执行：
- **媒体归档与补丁应用**：工具读取的远端图片由本地媒体宿主归档至本地，时间线列表与大图查看仅读取当前会话持久化引用的本地归档资源，展开图片时不重新连接 SSH 或读取远端原始文件；`apply_patch` 在本地完成上下文匹配后通过远端原子写入提交；LSP 客户端运行在本地，语言服务器作为远端受监督进程运行。
- **冻结端点与管理目录核验**：工作树执行、身份检查及清理始终使用原工作区冻结的远端端点身份，不因 SSH 别名配置变化而重绑。读取 Git common-dir 与管理目录反向关联所需的额外元数据工作区也必须通过同一端点核验，不能只验证执行目录而在元数据路径改连另一端；这不会扩大业务执行目录或获得新的清理授权。
- **远端会话工作区模式（`local` 与 `worktree`）**：SSH 项目同样支持 `local`（使用远端权威项目目录）与 `worktree`（在远端仓库按创建时解析的 `HEAD` 检出 `<repo>/.anywork/worktrees/<root-thread-id>/session`，租约记录 `ssh_alias`）两种工作区模式。远端工作树的变更预览、执行准入与独立安全清理复用同一套租约状态机（见 [12.5](./12-collaboration.md#125-git-工作树worktree生命周期与故障恢复)）；SSH 离线只表示无法检查，不推断目录已缺失。归档和取消归档不访问或删除远端工作树，离线不阻止目录归档；执行或清理须待连接恢复后按相同前置条件重试。启动期的“未注册工作树”后台审计仅扫描本地文件系统，不为远端项目主动建立 SSH 连接。
- **原生后端错误边界**：远端文件元数据与命令执行的原生接口保留已有远端客户端错误分类及其来源，调用方可以区分路径验证、连接或认证、辅助进程响应、进程启动、输出读取、等待与超时收束阶段，而不解析显示文本。只有明确的 `PathNotFound` 可映射为路径不存在；通用文件工具端口在其适配边界转换错误，不能先抹掉原始类型再要求工作树诊断猜测原因。原生接口与通用端口共享同一请求与资源生命周期，不引入第二套远端请求或取消实现；现有端口确实没有提供的更细原因保持未知，不把未知伪装为可重试或已清理事实。
- **跨端 POSIX 路径单点归一化**：远端路径在所有跨端边界（租约中的 `repository_root` 与 `path`、会话工作区根、工作区打开参数、身份比较以及传给远端 Git 或辅助进程的参数）上一律表示为标准 POSIX 路径字符串，严禁混入本地 Windows 反斜杠或盘符前缀。远端绝对路径规范化由 `pl-tool::remote::normalize_remote_absolute_path` 单点负责：将反斜杠转换为 `/`、折叠重复分隔符与 `.`，并拒绝空路径、相对路径及包含 `..` 的路径。
- **后台进程工厂与关闭依赖顺序**：SSH 连接、平台探测、资产上传与协议握手统一通过后台进程工厂启动系统 OpenSSH，固定禁用伪终端（`-T`）与 X11 转发（`-x`）。在应用关闭编排中，SSH 传输层的真实关闭严格排在依赖它的远端 MCP、LSP、工具停止请求以及驱动远端工具的生产者停止确认**之后**（同时与本地数据库写入链并发推进，见 [18](./18-studio-state.md) §18.5），避免提前切断通信导致远端资源正常退出被误判为失败。会话顶栏的外部「终端」入口则属于用户主动启动的独立交互式 SSH 会话，不承载辅助进程协议，亦不随 Studio 退出而终止（见 [18.9](./18-studio-state.md#189-顶栏工作区打开菜单)）。
- **连接状态机与指数退避接续**：连接状态穷尽定义为 `disconnected`、`connecting`、`ready`、`reconnecting` 与 `failed` 五态。超时阈值固定为：SSH 建连 **15 秒**（存活探测每 15 秒一次，连续 3 次无响应判定断开）、平台与资产探测 **30 秒**、资产上传 **120 秒**、辅助进程握手 **25 秒**、目录重开 **15 秒**。传输通道意外断开时，在途操作进入接续等待，本地宿主按 **`1, 2, 4, 8, 15, 30` 秒**退避序列尝试接回原辅助进程实例（受剩余租约与操作截止点约束）：接续成功则保持工作区与子进程身份不变，仅递增连接代次；若远端实例租约已过期，则旧操作明确报错，后续新任务建立新实例并通知活跃根会话与子会话刷新工具绑定、Shell 描述符及 LSP/技能状态。
- **混合技能目录**：SSH 工作区的技能目录由远端项目源（默认远端 `<workspace>/.agents/skills`）与本地只读源（用户目录 `~/.anywork/skills`、主目录 `.agents/skills`、内置系统技能与显式外部目录）在共享注册表中按标准优先级合并而成（见 [10](./10-skills.md)）。

## 22.4 凭据、路径与持久化

系统直接调用 `PATH` 中的系统 OpenSSH，完整复用用户的 `ssh_config`、`known_hosts`、`ProxyJump`、`ssh-agent` 与显式配置的代理转发（agent forwarding）：
- **密码凭据存储与 `SSH_ASKPASS` 非交互注入**：认证支持 `ssh-agent`、公钥文件及可选的 SSH 密码。SSH 密码与模型供应商 API 密钥共用同一套操作系统凭据库（`CredentialStore`，账户键名为 `ssh:<alias>`，编辑语义支持 `Preserve`、`Replace` 与 `Clear`）或当前进程内存会话租约，严禁写入 `~/.ssh/config`、SQLite、DTO、日志、辅助进程参数、环境变量或远端协议；删除受管主机时同步清除对应系统凭据。当存在可用密码时，本地 OpenSSH 子进程通过受控临时 `SSH_ASKPASS` 脚本（配合 `SSH_ASKPASS_REQUIRE=force`）从本地子进程专属环境变量完成非交互密码注入。
- **免密优先探测与服务端认证方式判据**：每次建立连接固定遵循“免密优先”顺序——先以 `BatchMode=yes` 非交互探测 `ssh-agent` 与公钥文件（含默认私钥、`IdentityFile` 与 `ProxyJump`）；若免密探测成功则直接完成连接，不弹出密码输入框。仅当免密探测以认证失败结束，且 OpenSSH 失败诊断 `Permission denied (<methods>)` 表明服务端接受密码类认证（方法列表包含 `password` 或 `keyboard-interactive`，或方法列表缺失）时，才通过 `StudioError` 的 `details` 字段（`sshErrorKind: "authenticationFailed"` 与布尔值 `sshPasswordOffered`）通知 GUI 弹出密码输入框；若服务端仅公布 `publickey` 等非密码认证方式（`sshPasswordOffered: false`），GUI 不弹出密码框，而是就地提示需配置密钥或 `ssh-agent`。前端与 SDK 仅消费这两个类型化字段，不解析 OpenSSH `stderr` 原始文本。
- **远端路径受限边界（Confinement）**：远端文件后端与命令工作目录 `exec.cwd` 始终处于受限（confined）边界内，`full-access` 权限模式不会放宽该限制（见 [04](./04-security.md)）。核心层在所有远端内置文件写操作（`write_file`、创建、删除、复制目标、移动源与目标、`apply_patch` 写入与删除）上先按工作区相对 POSIX 路径执行 `writablePaths` 策略校验，远端辅助进程继续执行权威工作区根路径与符号链接（symlink）越界防护。SSH 项目的 `exec.cwd` 仅接受工作区相对 POSIX 路径（工作区根目录传 `.`，拒绝绝对路径与 `..`）。
- **打开远程项目窗口契约**：Studio 的「打开远程项目」窗口绑定 `~/.ssh/config` 中的一个 `Host` 别名，仅接受该服务器上的绝对 POSIX 目录路径（不解析 `~`、相对路径、`ssh://` URI 或 `user@host:path`）。目录导航与手动输入路径均须先经 `browseRemoteDirectories` 获取权威目录列表；仅当路径已验证且与当前输入一致时才允许提交给 `openRemoteProject`，并在目录刷新及显式选中意图采纳该权威项目后才关闭窗口。浏览与打开操作严格串行化，失败时保留窗口与用户输入供原地修正重试。
- **产品数据库结构与历史迁移**：Studio 数据库不设独立的 SSH 服务器表，远端项目通过 `projects.ssh_alias` 可空列直接引用 `~/.ssh/config` 中的 `Host` 别名（本地项目按 `path` 唯一，远端项目按 `(ssh_alias, path)` 唯一且保存权威 POSIX 路径）。在数据库版本 `v20 → v21` 升级时，启动协调器先备份产品库，再将旧 `ssh_servers` 表中的记录幂等迁移为 `~/.ssh/config` 管理块，并在同一事务内将 `projects.ssh_server_id` 重写为最终别名后删除旧表。

## 22.5 辅助进程资产构建与随包分发

`pl-remote-helper` 编译为去除符号（stripped）的静态链接 `musl` 可执行文件（覆盖 `aarch64-unknown-linux-musl` 与 `x86_64-unknown-linux-musl` 两种 Linux 架构），由 `cargo xtask` 独立构建并使用 `zstd` 压缩后随 Flutter 桌面发行包分发，不嵌入 Rust 桥接动态库内部。Windows 与 Linux 的 CMake 构建脚本将资产安装至应用可执行文件同级的 `data/remote-helper/<target>/` 目录下，每个目标架构包含 `pl-remote-helper.zst` 与 `pl-remote-helper.metadata.json`（采用 `camelCase` 记录 `target`、`workerProtocolVersion` 与原始可执行文件的 `sha256` 摘要）。

随包资产的解析、校验与远端部署遵循以下规则：
- **宿主解析与外部模式隔离**：桌面桥接层根据应用可执行文件位置解析资产根目录，并通过显式运行时启动选项注入；非打包服务端、开发调试与人工观察入口显式使用外部辅助进程模式（在 Linux 本地从 `PATH` 查找 `pl-remote-helper`）。在随包模式下，若发生文件缺失、解压失败、目标架构或协议版本不匹配、SHA-256 摘要不符，必须明确报告资源路径与失败原因，严禁静默回退至系统 `PATH`、开发目录或网络下载（若宿主未启用任何本地 `stdio` MCP 服务或远端项目，则辅助进程资产缺失不阻断应用启动，仅在实际需要启动本地工作进程或远端辅助进程时报错）。
- **按内容摘要幂等上传与原子发布**：远端目标架构由 `uname -s` 与 `uname -m` 穷尽映射。连接建立后，核心层先探测远端架构，请求宿主适配器解压唯一匹配的辅助进程字节流，并上传至远端共享资产目录 `$HOME/.anywork/remote-helper/<version>/<digest>/`（若该摘要下已存在可执行文件则直接复用，免去重复传输）。每次上传在目标目录内创建具备私有权限的独立临时文件，校验接收字节数等于完整资产长度后原子重命名发布，防止因连接提前中断而缓存截断残片；该目录仅存放辅助进程资产，禁止模型将其用作临时工作区（scratch）。
- **Linux 本地工作进程复用与启动预检**：Linux 本地 `stdio` MCP 与 LSP 监督复用同一随包资产来源，持有匿名不可变可执行镜像与文件句柄租约，使运行中会话不受外部文件替换影响。构建期预检对当前宿主架构执行真实的 `Ready` 握手验证，对交叉架构校验静态元数据；运行期同一物化辅助进程若启动失败则在当前运行时生命周期内保持不可用，待重启后重新准入。
