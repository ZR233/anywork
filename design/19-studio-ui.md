# 19 - anywork 桌面界面与交互契约

桌面产品中文名称为“糊来帮”，英文及其他语言环境回退名称为 `anywork`。窗口标题、系统入口与应用界面按各自语言环境显示对应名称。应用图标以猫咪原图为基础，保留完整蓝色圆角主体、移除外围留白并将圆角外部设为透明。Flutter 工程与 Dart 包统一命名为 `anywork`，Rust crate 继续使用 `pl-*` 前缀。Linux 发行包（bundle）携带桌面入口文件与图标，窗口图标内嵌于原生启动器（runner）；用户可显式运行发行包中的桌面登记脚本将当前程序登记至 XDG 用户应用目录，构建与运行过程不自动修改宿主桌面环境。

## 19.1 架构与宿主边界

### 会话排序与前端分层架构

会话列表在当前分组及筛选范围内按最近用户消息时间倒序排列，优先取权威会话的 `lastUserMessageAt`，缺失时回退至 `createdAt`，同秒内按会话 ID 降序稳定破平。用户消息成功受理（含进入排队）后会话自动前移；模型回复、工具执行、运行状态变化、自动标题生成及配置更新均不改变排序。会话列表、分页合并、搜索结果与归档后的候选会话选择共用同一排序规则，不从本地草稿或流式事件猜测时间戳。旧目录记录缺失 `lastUserMessageAt` 时按创建时间排序，待下一次成功发送后更新，不扫描历史记录回填时间（迁移与元信息保存边界见 [17](./17-studio-storage.md)）。

桌面发行包同时携带预构建的 Rust 桥接动态库与独立远程辅助进程（helper）资源；资源的定位与消费属于 Rust 宿主边界，不由 Dart 层加载后传输（分发、校验与工作进程生命周期遵循 [22](./22-ssh-remote.md)）。

`anywork` 是基于 Material 3 的 Flutter 桌面应用，视觉主题见 §19.7；应用实例隔离、类型化边界、单向数据流和页面导航统一遵循 [25](./25-frontend-state.md)，不在本文另设分层契约。
- **原生能力边界**：UI 不直接读取 SQLite、智能体 TOML 或技能文件；Flutter Web 仅用于演示模式集成验收，不伪造原生账号、文件系统或进程能力。
- **原生文件选择与附件拖放**：附件拖放直接消费平台插件的类型化文件条目，仅接收常规文件，不将目录、纯文本或 URL 解释为本地附件。异步拖放回调持有当次传输资源的借用期，所有文件读取及 Rust 附件草稿准入必须在回调返回前完成；后续提交仅消费已入库的草稿，不持有平台临时路径或外部句柄。文件与项目目录选择由桌面原生宿主持有，分别调用 Windows 原生文件对话框、GTK 原生文件选择器与 macOS AppKit 文件选择器；Flutter 通过平台通道提交扩展名筛选条件并接收本地路径，用户取消时返回空选择，原生失败按平台错误传播。宿主不读取文件内容，附件校验与复制仍由 Rust 草稿准入逻辑负责。
- **渲染后端策略**：Windows 原生宿主显式选用 Skia 渲染后端，以规避 Impeller GLES 在高分辨率大窗口下的栅格化延迟，且在 `debug`、`profile` 与 `release` 构建中保持一致。未来若评估切回 Impeller，须在同机普通窗口、最大化、还原及大尺寸窗口下完成帧耗时及实际显示、输入、滚动结果验证；升级 Flutter 版本时须同步核对原生渲染后端配置接口。
- **验收只读观察**：内容捕获与只读诊断读取生产领域所有者的可见投影，不维护平行业务状态；证据边界见 [24](./24-testing.md)。

### 窗口关闭、系统托盘与单例激活

Windows 平台上点击标题栏关闭按钮、`Alt+F4` 或任务栏关闭窗口执行“隐藏到系统托盘”而非应用退出：当系统托盘图标真实可见时，原生宿主仅调用 `ShowWindow(SW_HIDE)` 隐藏窗口，不调用 `begin_runtime_exit`、`shutdown_runtime` 或 `AppGraph` 收束，不启动退出倒计时，也不取消正在执行的轮次、工具、模型流、订阅或持久化保存。窗口隐藏期间 Flutter 可暂停帧渲染调度，但 Dart Isolate、FRB 订阅与 Rust 运行时继续运行；恢复窗口后直接展示最新权威投影，无需重放或补发请求，待确认的用户交互亦保持等待状态。托盘图标支持左键单击或双击恢复窗口，右键菜单提供「显示主窗口」与「退出」；仅当点击托盘「退出」、操作系统会话结束或托盘不可用时关闭窗口，才进入应用退出协调器。Linux 平台暂不实现托盘隐藏，保留既有 `delete-event` 直接关闭入口。macOS 窗口关闭和应用退出（含 `Cmd+Q`、注销与系统关机）进入同一退出协调器，复用独立于 Flutter 引擎的原生退出期限。AppKit 终止请求返回 `NSTerminateLater`，清理确认后回复允许终止，不以取消请求阻断系统注销或关机；在 `applicationWillTerminate` 中以协调器确认的真实退出码完成原生退出，防止 AppKit 默认成功码掩盖失败。重复终止请求共享首次清理与绝对期限；窗口关闭仍由同一协调器直接完成。当前不实现菜单栏托盘隐藏。

Windows、Linux 与 macOS 桌面端均以 Studio 数据根目录（Studio home）为单实例运行边界。重复启动进程在创建 Flutter 引擎前向原实例转发窗口激活请求并立即结束自身；指定不同数据目录的实例允许并行运行。Windows 复用托盘的窗口恢复入口，Linux 通过 `GApplication` 的 `Activate` 信号呈现已有 `GtkWindow`；macOS 通过数据目录实例键命名的本地消息端口确认激活，并由 AppKit 恢复窗口。若原实例首帧窗口尚未就绪，则合并保留一次激活请求并在首帧渲染后执行，不重建 `AppGraph` 或重发业务请求；若原实例正在退出，则仅显示原退出窗口，不取消退出流程也不自动重启。入口发现与窗口激活共用 10 秒总期限；文件锁已释放时新进程可重新竞争，仅获锁者继续启动。转交成功返回退出码 `0`；若锁占用者为服务端进程、其他桌面会话、无响应进程或激活转交失败，则记录诊断并静默返回非零退出码，不弹出第二个窗口或占用报错页。桌面重复启动在原生入口直接完成激活转交，服务端模式则保留类型化 `instanceBusy` 错误。

### 应用退出与桥接关停协同

应用退出必须等待 `AppGraph` 幂等收束及类型化关停（shutdown）完成，并回收 Flutter、DTD、MCP、LSP 与本地子进程树；远端辅助进程在 GUI 退出或 SSH 断开后由心跳租约自行清理，窗口不等待远端退出确认。应用退出设有单一总期限 30 秒，由原生宿主在首个退出请求前独立启动守护线程计时，重复退出或重试均不延长；到期后强制终止进程并返回退出码 `1`，正常完成返回退出码 `0`。

桥接层以 `BridgeShutdownReport`、`BridgeShutdownOutcome`、`BridgePendingPersistence` 与 `BridgeShutdownIssue` 镜像运行时的类型化关停报告（结构定义见 [18](./18-studio-state.md) §18.5.1）。应用退出前，Dart 侧与原生桥接按以下顺序协同：
1. **早期退出信号（`begin_runtime_exit(remaining_ms)`）**：与退出闸门的锁闭原子地观察已发布运行时，固定同一首次绝对期限，在已安装的运行时上同步锁闭领域准入，并向所有独立在途所有者（含活动轮次、模型调用与工具执行）广播一次取消信号；同时预先广播桥接侧内容流订阅与更新操作取消，将真实错误汇入同一收集器。此步骤仅发送信号，不触发初始化、不执行阻塞停止或汇合、不关闭会话、不发布 `Stopped`。
2. **Dart 侧有界外部取消**：Dart 有界完成并观测自身持有且桥接层无法代持的外部取消（产品流、会话流、更新操作与关机进度流），将任何未确认的类型化 `BridgeShutdownIssue` 随剩余预算 `remaining_ms`（上限 28 秒）一并传入 `shutdown_runtime(remaining_ms, external_issues)`。关机进度流使用自持令牌，不受早期广播提前终止，并在运行时收束前完成取消确认。
3. **统一运行时关停与诊断收尾**：桥接层并入自身订阅与更新取消结果，与运行时阶段共用同一编排、同一首次绝对期限及同一 `Clean` 前置条件。桥接侧彼此独立的所有者组并发观测，任一组汇合阻塞均不影响其他组取消。诊断收尾独立于运行时初始化状态，`finish_shutdown_diagnostics` 在安全释放前或退出前调用，确保运行时未安装或安装失败时也能回收诊断资源。订阅取消仅在桥接层仍可用时调用原生取消接口，严禁在 `RustLib.dispose()` 之后调用任何 FRB API。

启动失败的错误码集合（如 `cancellationTooLate`、`overloaded` 等）在 Dart 侧通过穷尽 `switch` 映射为稳定的本地化文案与诊断编号，不因未知变体抛出解析异常而掩盖原始类型化错误。关停失败时不阻塞在用户确认弹窗或提供无限重试，而是将失败阶段聚合成带 `code` 与 `correlation_id` 的脱敏诊断后继续退出流程。更新安装的空闲判定与关闭启动属于同一原子步骤：运行时在任何取消前完成原子空闲检查，随后桥接层通过注入同一严格编排的适配器钩子解除并等待自身订阅；若会话正忙，则既不取消订阅也不改变运行状态。

### Markdown 排版与上下文状态栏

时间线 Markdown 支持自动链接、引用块、图片与超链接展示；具体渲染库及适配 API 由实现选择，不构成页面行为契约。外部链接点击须通过 HTTP(S) URL 校验，远程图片仅允许 HTTPS 且须由用户主动点击加载；图片替代文本（`alt`）从结构化 Markdown 节点读取。

链接交互按实际目标分别授权：仅为通过 HTTP(S) 校验的普通链接绑定打开动作，拒绝的 scheme 保留为可阅读、可选择的非交互文字，不显示可点击提示，也不调用外部 launcher。引用标记沿用组件原有的引用芯片外观，并使用相同的 URL 策略；缺少 URL 或目标被拒绝时不绑定打开动作。构建器遵守所用组件的公开 span 与回调契约，不通过全局点击回调使拒绝的目标获得交互，也不以空手势、吞异常或修改第三方断言掩盖适配错误。最终打开边界仍须再次校验目标，并保留原有失败反馈。

Markdown 阅读排版以 [VS Code Markdown Preview](https://github.com/microsoft/vscode/blob/main/extensions/markdown-language-features/media/markdown.css) 为主要基准，并以 [Zed Markdown Preview](https://github.com/zed-industries/zed/blob/main/crates/markdown/src/markdown.rs) 交叉核对，采用通用文档样式而非独立卡片化设计：
- **标题与段落节奏**：标题采用相对正文字号的递进字级，`H1` 与 `H2` 带细分隔线；正文、段落与块级元素保持自然阅读节奏，避免默认块间空行与额外内边距重复叠加。自定义标题作为块级选择单元参与外层连续文本选择，不通过独立文本编辑控件隔离标题或打乱跨段选择复制顺序。
- **列表、代码与表格**：列表续行与条目正文左对齐，条目间距小于段落间距。行内代码以等宽字体与浅底色区分，避免粗重描边打断中文阅读，不通过插入额外空格、换行或切分选择片段的布局占位改变原文复制结果，长代码片段随正文自然换行。引用块采用左侧竖线、低对比背景、弱化文字与适度内边距，保留内部多段与嵌套结构。代码块采用简洁低对比容器、常规内边距与小圆角，语言标识不使用强调色顶栏；表格采用清晰表头与细分隔线，保留文本选择与长行横向滚动。上述规则统一覆盖消息、推理与计划等阅读表面，颜色继承现有主题角色。

状态栏上下文指示器仅显示紧凑图形进度轨，不常驻显示百分比或词元数字：
- **进度计算与未知占位**：图形填充比例取运行时已用词元数除以最终自动压缩阈值；悬停详情展示精确百分比及超出阈值状态。当阈值未知（含非正值）时，图形仅显示中性底轨，详情及无障碍读数以 `—` 占位，不报告虚假的 `0%`；当阈值有效且用量为零时正常显示 `0%`。进度读数本身不宣称上下文压缩已经发生。
- **立即压缩操作**：上下文悬停详情的进度条旁提供「立即压缩」按钮，通过 Client 动作请求当前会话执行一次强制压缩，复用自动压缩的准备、提交、计量与持久化路径，不发送隐藏用户消息。该按钮仅在会话空闲且存在可压缩历史时可点击；执行期间展示进度并防止重复触发，失败保留错误提示，成功后刷新权威上下文读数。
- **上下文详情分区**：顶部展示已用词元、压缩阈值、百分比与距阈值余量，下方分区展示模型身份及最大上下文容量、会话累计输入与输出词元、调用次数、缓存统计以及按币种分组的费用与缓存节省金额。当有效上下文窗口与模型最大窗口不同时分别展示；未知值保留 `—`，无模型最大能力事实时不以有效窗口冒充。窗口与阈值统一消费请求绑定的权威投影（见 [18](./18-studio-state.md#188-产品投影与观察)），不在前端按账号硬编码或回填历史。

### 文件展示与阅读

统一文件展示以等宽缩略图／图标和下方文件名呈现在时间线，沿用当前主题及图片点击放大；常规宽度横向排列，较多文件和窄窗自然换行，长名省略但可查看完整名称。按文件名扩展名选择 Markdown、文档、压缩包、音视频及未知类型图标；图片解码失败、读取失败和不可预览状态明确可见，不以占位图冒充成功预览。

点击 `.md`／`.markdown` 在当前会话右侧打开只读文件面板，提供文件名、滚动正文、关闭和读取失败后的主动重试。复用已有 Markdown 安全规则与 Plan 分栏／窄窗阅读区域，但文件不具有计划状态或决议语义。两者共用阅读正文的宽度与选择行为：正文占满面板实际可用宽度，仅保留必要边距，不设固定最大内容宽度；分栏拖动、窗口变化、文字缩放与全宽切换后重新布局。段落、长链接、长单词和代码行按可用宽度自动换行，表格单元格适配可用空间，不能靠裁切隐藏内容；支持选中文字及复制，视觉换行不改写原始复制文本。切换面板不卸载原时间线，关闭或切换文件／会话后的迟到结果不能覆盖新内容。

右键和可见／键盘菜单提供用户主动操作：SSH 来源为“下载”，本地来源为“另存为”“在文件管理器中显示”；没有有效本地来源的归档附件只能保存，不伪造源路径。保存使用精确归档字节及当前设备的原生保存对话框，取消不创建文件，覆盖须确认。定位仅使用经本地来源校验的路径，原件消失或系统调用失败明确报错，不将远程路径交给本机文件管理器。

## 19.2 动态工作模式与工作流状态

新会话默认选用 `mode.simple`。输入区（Composer）的模式选择器读取工作模式目录快照，以稳定的 `modeId` 作为标识、`displayName` 作为显示文案，不硬编码 `Simple` 或 `Task` 枚举。工作模式切换命令仅在根会话空闲且无待处理交互时可用；旧活动运行实例由运行时归档，被拒绝的切换由权威快照恢复界面显示。工作模式不出现在普通技能设置或按需调用列表中，两个内置工作模式不可删除或覆盖（见 [11](./11-thread-mode.md)）。

起始页与已有会话的模型、推理强度及会话设置遵循以下规则：
- **模型与推理强度选择器**：起始页选择器展示 Client 起始草稿的当前意图（按逻辑草稿与项目身份保留，不随路由观察者销毁而丢失）；未显式选择时读取当前草稿工作模式在 `modeModelRoutes` 中的默认值，切换工作模式立即展示该模式最后保存的路由选择（草稿与权威状态的组合规则见 [25](./25-frontend-state.md)）。提交首条消息时在首次 `await` 前冻结完整路由，不采用“先改全局默认设置、等待响应、再读缓存构造会话”的方式。已有根会话的选择器仅读取会话运行时中的 `modelRoute`，修改时同时更新当前会话与所属工作模式的默认路由，不影响其他会话；子会话继续只读展示创建时冻结的配置模板路由。当路由不可用（`unavailable`）时保留原选择项并显示告警图标，点击告警展示运行时提供的不可用原因（无具体原因时展示通用说明），不在 Flutter 侧自动改选其他账号或模型。根会话非空闲时不打开模型或推理强度菜单，点击时提示当前状态不可切换的原因；须观察到当前轮次真正结束且权威会话快照确认空闲后才恢复可切换状态（活动工作流本身不限制模型切换）。
- **选择器权威同步约束**：选择器触发器文案与弹出菜单的选中态必须源自同一个权威事实并同步变化。工作模式、推理强度或模型切换完成后，主界面无需退出或重新进入任何页面即可立即反映新值；严禁依赖页面跳转、菜单开关或浮层重建来触发显示更新（见 [18.11.1](./18-studio-state.md#18111-thread-身份的单一来源)）。
- **选择器锁定与可见原因**：能否配置会话（工作模式、模型、推理强度）与能否提交相互独立。工作区准备中或暂不可提交时，模型与推理强度仍可先定下草稿路由；工作模式随工作区草稿保存，非项目会话准备好内部归属后同样可用，不要求先添加用户项目。进入已建根会话后，不同配置项按生命周期分层反馈（运行期各锁定分支参照 [会话运行时输入框与配置锁定概念稿](prototypes/session-composer/index.html)）：轮次运行中、正在压缩或正在停止收束期间，工作模式、主智能体模型与思考强度全部锁定；图工作模式处于活动运行阶段且当前轮次已空闲时，仅锁定工作模式以保护阶段图与已批计划，主智能体模型与思考强度保持可切换并在下一轮生效；所选模型不支持推理强度时仅思考强度单独锁定；外部机器人托管会话将模型与强度收敛为「由机器人统一设置」只读指示；绑定路由不可用（`unavailable`）时阻断发送但保持模型选择器可点击以原地换模恢复。所有当前不可更改的选择器均保留原位并省略锁形图标，保持与可交互态一致的触发器几何尺寸与下拉箭头占位（思考强度保持最小定宽占位），以无边框、无悬停高亮的置灰不可交互外观（配悬停原因提示）呈现，确保状态切换时工具栏零位移，且不得出现看似可点却静默吞掉点击的控件。
- **起始页外层会话环境栏与已建会话单层输入卡**：起始页与已建会话复用同一个内层主输入卡组件，起始页采用聚焦输入列（最大宽度 `760 logical px`，与会话时间线 `1040 logical px` 共享同一中心轴）及“外层会话环境栏 + 内层主输入卡片”的双层同心包边容器，按生命周期将会话创建期一次性冻结的环境配置与每轮输入控制分离（视觉参照见 [新会话起始页概念稿](prototypes/session-start/index.html)、[会话运行时输入框与配置锁定概念稿](prototypes/session-composer/index.html) 与 [会话输入组件化、起始页环境栏与运行期配置锁定设计](concepts/session-start-layout.md)）。创建卡外层圆角 `16 logical px`、左右及下方包边 `4 logical px`、内层圆角 `12 logical px`；运行期单层输入卡圆角 `14 logical px`，不改变其他页面的全局圆角：
  - **目标项目与草稿身份**：全局新会话与项目行新会话进入同一页面，仅初始目标不同。环境栏提供可搜索的项目选择入口，按名称、路径及 SSH 别名筛选已有项目，并提供「无项目」与调用既有添加项目向导的「新建项目…」。无项目映射既有非项目工作区，不表示缺失归属；取消添加或选择失败保留原目标及其草稿，成功添加后选中新项目。切换目标沿用既有导航命令，展示目标工作区自己的文本、附件与创建配置，不跨目标搬移或清空草稿；具体所有权见 [25.8](./25-frontend-state.md#258-输入草稿与附件所有权账本)。环境准备或首条提交在途时锁定目标和外层创建配置，内层仍按原准入规则编辑后续草稿；无项目的工作区模式显示只读「固定本地目录」。
  - **外层会话环境栏（创建时冻结）**：采用 `surfaceContainerLow` 暖米色底栏托住内层主输入卡片。左起依次展示当前项目身份（含 SSH 远程主机标识，完整规范路径置于只读悬停提示）与紧凑无框的会话工作区下拉选择器，提供 `local`（默认，「本地目录」，直接使用项目目录）与 `worktree`（「新建工作树」，从项目 Git 仓库 `HEAD` 新建独立工作树，菜单项副标题说明基线检出语义），既在首屏直接外显当前工作区模式又避免分段开关占用过多横向空间；本地与 SSH 项目均提供 `worktree` 选项，若项目非 Git 仓库、缺少 `HEAD` 或远端不可用，则在提交时通过类型化错误就地反馈、原位保留草稿并提供一键切回「本地目录」入口。右端对齐展示带当前有效摘要（如“自动选模 · 平衡”或“固定模板”）的子智能体分发触发器，点击展开单层双区分组菜单（同层呈现分发模式“跟随默认 / 固定配置模板 / 自动选模”与自动选模偏好“跟随默认 / 经济 / 平衡 / 快速”及偏好说明，不使用多级悬停嵌套子菜单；固定模式下偏好项置灰保留所选值并标明仅自动选模时生效）。
  - **内层主输入卡与已建会话只读边界**：内层采用 `surfaceContainerLowest` 暖白表面承载附件草稿轨、多行输入区、就地诊断行与底部工具栏；底栏左端保留纯粹的附件添加入口，宽屏可显示快捷键提示，右端等高排列工作模式、主智能体模型、思考强度三联快捷选择器与唯一主操作槽位。窄窗、长名称与文字放大时允许工具栏和外层环境栏合理换行，主动作始终可见，不把创建配置塞回附件子菜单。已建根会话不再展示起始页外层切换栏（收敛为单层输入卡），其已冻结的工作区模式、分发模式与分发偏好直接消费权威目录事实并作为顶栏/侧栏只读上下文呈现；切入子智能体会话时整个输入区替换为只读状态底栏。设置页另提供新会话默认分发模式与自动偏好配置（默认为固定配置模板、平衡偏好），三种偏好的简要说明对应 [12](./12-collaboration.md) 的提示词语义，不承诺最低价格、最高质量或最快速度。
- **首条请求环境准备卡片**：起始页提交首条提示词后，输入框上方的欢迎区切换为环境准备卡片，沿用暹罗浅色主题、细描边与眼眸蓝活动指示。卡片按“检查项目 → 准备工作区 → 初始化会话 → 提交请求”展示各阶段状态，工作树准备阶段额外显示真实的仓库解析与物理创建子阶段，不显示估算百分比；折叠详情展示项目名称、冻结的工作区模式以及已分配的实际路径与分支（支持换行与选择复制）。准备期间用户仍可继续编辑后续草稿；创建成功后直接进入对话视图，不设最短展示停留时间，也不在时间线中遗留准备卡片；创建失败则停止活动指示并在原位保留失败阶段、原因、提示词与附件草稿；结果未知时明确提示尚未确认且不自动重发。
- **工作流状态栏投影**：会话运行时快照仅向 GUI 暴露状态栏所需的通用工作流投影（`mode`、`run`、`revision`、`lifecycle` 与当前阶段名称）。未启动的图工作模式显示“未开始”，`Simple` 模式仅显示模式名称；GUI 不展示完整状态图、转换历史或人工阶段跳转入口，也不执行本地乐观转换。

## 19.3 通用交互与计划确认

Composer dock 统一呈现 UserInput/ToolApproval，Plan 仍使用 plan_confirmation 的通用 UserInput，不新增交互协议。当前计划四态取领域只读投影；待决表单绑定原交互，历史使用独立冻结回执，不从当前状态猜旧决定。常规澄清继续分步问答，计划阅读与专用反馈栏的完整交互见 [13](./13-plan.md)。

计划只读入口与正文统一依赖已接纳 State 的 `businessRefs.plan`，不能以热 `runtime.plan`
是否存在决定冷会话能否阅读；无文档的真实计划头保留相应空态，缺计划头不伪造入口。
待决确认仍由原交互独占动作资格，业务引用只提供阅读身份和阶段，不授予批准或修改权限。

`plan_confirmation` 是计划确认专用的问题标识，普通提问必须在生成交互记录前拒绝使用，不能等到界面投影时才校验。旧普通问题若误用该标识，原历史仍按普通问答事实保留供只读核查，待决交互读取明确报告结构错误；不将其猜测为计划，也不通过计划入口决议。

普通提问在时间线历史中展示为只读问答回执，不重复渲染可提交表单：
- **折叠与展开形态**：回执默认折叠，已回答状态以完成图标、「用户已回答」标题、问题数量与右侧对齐的展开箭头构成紧凑头部（整行头部均可点击切换展开态），辅助行提供简短问答摘要；展开后按原问题顺序逐组呈现题目标题、完整问题正文与「你的回答」。选项回答使用浅色回执标签，自由文本保留原始换行并支持选择复制，多道题目之间以细分隔线与统一缩进区分。
- **权威状态与隐私保护**：回执仅消费工具条目携带的类型化问答投影（见 [18](./18-studio-state.md) §18.8），按原工具身份独立成行，不藏入普通活动组。仅权威 `resolved` 状态显示「用户已回答」；待回答、已取消与缺失回答分别显示各自真实文案，不凭工具执行成功推断用户已回答。标记为敏感的问题回答统一显示「敏感回答已隐藏」，摘要、展开正文、复制内容与无障碍语义均不包含原始敏感值。
- **子任务交互的主会话投影**：子智能体的提问与安全审批统一在主会话呈现，卡片标注来源成员并原样转发原始请求身份、版本与类型化决定；子会话的计划请求按其自身诊断事实保留，既不进入主会话的可决议投影，也不能经该投影决议。子会话页面只读展示，不提供答题、审批或提交控件。受理只表示请求已被接收，界面以权威回执确认后才推进卡片状态；冲突或过期决定保留原卡并显示原因。
- **计划确认专用回执**：计划确认复用同一类型化历史通道，但渲染为计划专用回执而非普通问答表单：主标题表达批准、请求修改或取消决定，副标题呈现计划标题，展开后显示完整用户反馈；待确认期间不在时间线重复渲染计划历史卡。

## 19.4 智能体（Agents）设置

智能体设置页是唯一的子智能体配置模板（Profile）管理中心；主智能体的模型与推理强度在会话界面配置，不在此页重复展示。页面分区展示系统子智能体与用户自定义子智能体：
- **系统子智能体**：名称、用途说明、系统指令与固定工作区模式均为只读且不可删除；允许配置启用开关（`enabled`）、路由（`account_id` / `model_id`）及由模型声明驱动的推理强度（`effort`）。
- **用户自定义子智能体**：按单个 TOML 文件原子创建、保存或删除，支持选择四种工作区模式（其中 `review` 模式表示工作区在派生时跟随被审智能体，须配合 `reviewTargetAgentId` 使用）。无效配置文件以独立诊断条目展示，不阻断页面其余配置项。保留工作树（preserved worktree）恢复区展示修订号、分支、基准与头部提交、未提交变更文件预览及显式清理操作。运行期智能体目录与配置模板目录严格分区；所有变更均携带设置修订号执行 CAS 校验，并以返回的权威快照原子刷新界面（见 [12](./12-collaboration.md)）。
- **浮层交互与路由稳定性**：智能体设置页中的模型选择弹层与推理强度选择弹层均归属于当前设置页；打开、选择或关闭锚定浮层仅改变浮层自身可见性并更新当前智能体配置投影，不触发设置标签页切换、`TabBarView` 重建或返回聊天页的页面级路由转场。
- **界面文案本地化规范**：智能体导航、配置页、工作树恢复及配置模板详情中的固定界面文案必须跟随 Studio 语言环境，由统一本地化目录（l10n catalog）提供。配置模板 ID、`account_id`、`model_id`、`effort`、工作区模式持久化枚举值，以及分支、路径、提交哈希、工作树状态与诊断数据均保持权威原值。中文界面产品术语统一使用“智能体”，`subagent` 统一译为“子智能体”，不混用“代理”、`Agent` 或 `Subagent`（`ssh-agent` 等操作系统专有技术概念除外）；常规概念不夹杂英文单词，MCP、LSP、SSH、HTTP、URL、API、Git、OpenAI、DeepSeek、TOML 等标准缩写与产品名保留原文。

## 19.5 联网搜索设置

通用（General）设置页将 OpenAI Web Search 与 DeepSeek 联网搜索呈现为两张独立配置卡片：
- **OpenAI 搜索卡片**：保留搜索模式、上下文大小、域名过滤与地理位置等配置项，文案明确标识仅作用于 OpenAI 搜索。
- **DeepSeek 联网搜索卡片**：仅提供「联网搜索」与「网页抓取」两个独立开关，不展示结果条数、正文开关、搜索模型或官方未承诺的缓存、域名、位置及上下文选项，也不维护本地输入草稿。卡片展示所选 DeepSeek 模型账号，并说明系统优先使用其他可用搜索后端，仅当其他搜索未配置、不可用或调用失败时才由 DeepSeek 兜底，且搜索与网页抓取均按请求次数计费。

两张卡片统一消费桥接层返回的 `configured`、`effective`、`availability` 与 `account` 状态（官方 DeepSeek Responses 路由显示账号不支持，可搭配 OpenAI 独立搜索使用）。每个开关各自提交一条携带设置 CAS 修订号的类型化命令，并以返回的完整权威快照原子更新界面，不在前端推演后端仲裁、凭据有效性或模型能力（仲裁契约见 [20](./20-config.md)）。

## 19.6 会话标题与侧栏详情展示

### 智能体切换菜单与自动标题更新

列表状态列只展示短标签：英文尽量一个词，中文使用简短状态词，例如“运行中 / Running”“停止中 / Stopping”“待调度 / Waiting”“失败 / Failed”“未确认 / Unknown”“待批准 / Approval”“待输入 / Input”。完整调度说明、停止失败原因、未确认提示及故障详情保留在悬停提示和辅助语义中，不将长句或原始错误直接放进固定宽度状态列。恢复诊断及重试在状态列内部始终预留位置，不因出现或消失而移动四列边界。

子智能体创建时以调用方传入的 `taskSummary` 作为初始标题。会话顶栏智能体切换菜单采用固定四列对齐网格（定宽选中对勾槽位、双行标题与角色/模型摘要列、定宽右对齐运行状态列、定宽尾部停止操作槽位）：每一行均单行显示权威会话标题（根会话行同样显示自身标题，无标题时回退显示角色标签或空态）并在悬停时展示完整文本提示；第二行展示角色名称与实际模型名称或 ID（账号与推理强度在紧凑辅助信息或悬停提示中区分，不拼接冗余括号后缀导致截断）；无论成员处于进行中、正在停止或已完成，状态列与尾部定宽操作槽位始终保持同一纵轴对齐，状态变化不引发文字错位。会话顶栏内的徽标、返回入口与下拉按钮统一采用等高规格，子会话返回按钮置于顶栏左侧，避免主/子会话切换或子智能体启停时顶栏右侧控件跳动。子会话时间线完整展示主智能体下达的初始任务、补充消息与子智能体的阶段性回复，最终关闭、切换或重开历史后保持一致。

最终关闭的成员仍可从菜单打开原完整历史，只读展示任务、冻结身份、真实终态、报告、累计用量/费用和已有评价，不提供发送、继续或新评价入口。本阶段不提供精简归档视图或“完整历史已回收”文案。界面分别表达“执行已关闭”与绑定工作树已删除、不存在、不适用或清理失败；失败保留具体原因和真实重试入口，不连带阻止健康根会话，不将工作树删除说成全部会话磁盘资源已回收。

最后报告的来源轮次与最终停止轮次分别展示其真实身份；若最新轮次没有报告，仍允许读取此前最后已提交报告，但不得将其显示为最新轮次成功或用它替换取消、失败等真实终态。

子智能体的模型信息取自运行时发布的冻结路由摘要（固定配置模板与自动选模模式口径一致），修改当前配置模板不会改变已有子智能体条目；无法解析模型展示名时保留模型 ID，旧历史记录确无绑定时显示“模型未记录”，不读取当前配置模板猜测补齐。打开智能体列表不激活全部子会话，也不预加载时间线、评价正文或模型资料。菜单成员与计数来自当前根会话的权威智能体目录（涵盖未驻留、已结束与已关闭的子会话），不受侧栏会话分页窗口或当前热会话集合过滤；仅在用户点击某个成员后才按需打开对应会话（数据来源边界见 [25](./25-frontend-state.md)）。
智能体切换菜单同时是子会话的唯一停止入口：每一行只为确有待处理、等待准入或运行中执行的成员提供停止按钮，绑定该行的会话身份与执行编号，点击不触发行选择、不打开子会话、不发送消息；受理后显示「正在停止」并禁用重复点击，中断后显示「等待主智能体调度」，不提供继续或消息入口。成员数量只统计未关闭成员，已关闭成员不计数但仍可在菜单中查看。子会话页面保持只读，用户对子任务的新要求统一在主会话表达，由主智能体调度原成员。

新根会话首条提示词提交后，侧栏与会话页眉立即显示提示词摘要作为临时标题；后台 `Explorer` 模型生成的最终标题通过 `ThreadDirectoryChanged` 增量事件更新，两处始终从同一个状态投影渲染，界面不展示独立的“正在命名”状态（见 [18](./18-studio-state.md) §18.6）。

### 侧栏会话行悬停提示与操作菜单

侧栏会话行（Thread tile）在悬停时提供详情提示与行内快捷操作（仅含置顶与更多菜单）：
- **重命名、归档与删除**：重命名对话框提交类型化重命名命令，空标题及超过 80 个字符的输入在前端与运行时两侧双重拒绝。未归档会话的更多菜单提供归档及删除，已归档行提供删除按钮。两项操作分别在点击后的确认框中说明自己的影响，不增加常驻说明或混入另一项操作的提示：归档说明停止会话树、清理专属工作树（包括未提交内容）和临时数据，并保留宿主记录及可靠附件；删除明确目标会话及子会话，列明会话记录、附件、产物、统计等全部会话数据和专属工作树将永久删除且不可恢复。取消确认不发命令，确认后以类型化命令提交，执行中防止重复点击；真实失败显示原因，不提前移除会话或导航。完整数据范围见 [17.16](./17-studio-storage.md#1716-会话归档与临时数据清理)。项目或会话存在恢复诊断问题（recovery issue）时，诊断详情优先于普通名称提示。
- **恢复影响与导航**：提醒项保留可见标记和详情，但不禁用健康会话行；仅执行受阻仍允许打开安全的历史或归档视图。仅访问受阻才禁止相应导航。问题按真实 owner 显示，汇总 child 提醒不得使 root 呈现为访问失败。发送被拒绝时展示具体原因、受影响资源与恢复动作，保留输入和附件；不以清理工作树作为继续健康根会话的前提。
- **只读提示与菜单解耦**：侧栏只读悬停详情使用 Material `Tooltip.richMessage`，提示浮层忽略鼠标指针、不抢占输入焦点、不包含复制按钮等交互控件；完整项目路径与会话工作区路径通过各自的更多菜单复制。项目与会话操作菜单独立使用 `MenuAnchor` 与 `MenuItemButton`，并收敛自身尺寸约束，避免长路径横向撑满窗口。提示显隐、菜单开合、键盘导航与焦点恢复完全交由 Flutter 框架处理，不维护自定义悬停定时器或互斥状态机。
- **打开方式二级菜单与工作树图标**：会话更多菜单将 VS Code、Zed 与终端入口收敛为一级「打开方式」`SubmenuButton`，二级菜单使用 `MenuItemButton` 展示单行应用名称与宿主原色徽标，并与顶栏「打开工作区」菜单复用同一徽标组件。侧栏会话行只读消费会话的工作区模式：`worktree` 会话在右侧固定状态区显示工作树图标及本地化说明，`local` 会话不显示该图标；会话级打开操作与路径复制均采用权威会话工作区路径 `workspacePath`（见 [18](./18-studio-state.md) §18.9）。

## 19.7 视觉主题与布局

### 启动等待页与存储诊断横条

应用启动初始化及主界面快照尚未就绪期间，窗口居中展示暹罗猫双爪交替敲击键盘的透明背景循环动画、当前语言的应用名称与加载指示（系统开启“减少动画”时展示静态帧）。真实初始化阶段由启动专属进度流推送，就绪后直接进入主界面，不设最短停留时间。主界面就绪后，后台继续运行工作区恢复检查：智能体设置页显示局部检查进度，会话页仅在检查失败时显示原因与重试入口，未完成检查前不显示“没有问题”。首屏就绪后若已有选中会话，则自动打开该会话并加载首个历史分页窗口。

常规持久化排队与后台落盘不显示诊断横条；仅当发生保存降级、恢复中、阻塞或因存储压力暂停新推理时才展示诊断横条。横条中的「重试保存」与「继续」为两个独立动作：「重试保存」仅将积压事实写入磁盘，不自动恢复模型或工具执行；硬故障重试成功后会话仍保持暂停，唯有后端将 `ThreadStorageState.canResume` 置为 `true` 时「继续」按钮才可点击，且点击后后端仍会按故障代次与目标持久化水位执行二次核验。短暂存储压力（队列或字节预算触顶）在安全间隙自动等待并恢复，不显示「继续」按钮。

### 暹罗浅色主题色板与排版规范

主页、会话、详情面板与全部设置页固定采用统一的暹罗浅色主题（奶油底色、海豹棕主操作、眼眸蓝点缀），不提供深色主题或跟随系统外观选项。

会话视图采用居中阅读列布局：时间线、活动栏与输入区共享同一中心轴，最大宽度为 `1040 logical px`。侧栏展开时以剩余主内容区为中心，侧栏隐藏时以完整主内容区为中心；窄窗口下按可用宽度对称收缩留白，不为滚动条显隐改变内容宽度。助手回复正文直接使用阅读列内的可用宽度；用户消息与父智能体消息采用右对齐、最大宽度 `680 logical px` 的紧凑气泡。主时间线、实时状态栏内部（当前工作组列表与流式正文区）、项目会话侧栏、多行输入区及弹出菜单的滚动条统一采用无常驻轨道、无箭头按钮的 Material 3 胶囊滑块：静止时隐藏、滚动或悬停拖拽滑块时显示、停止后按原生机制自动淡出。

字体选择遵循宿主平台约定：Windows 英文界面使用 `Segoe UI`，中文界面及中文缺失字形回退使用 `Microsoft YaHei UI`，其他平台保持系统默认字体；代码块、行内代码、命令、技术路径、JSON 与工作流源码编辑区以及代码式工具输出统一使用随包分发的 `JetBrains Mono` 等宽字体。

### 原生 Material 组件复用与侧栏响应式布局

按钮菜单、设置选择字段与状态悬停详情统一复用 Material 官方组件：交互菜单使用 `MenuAnchor` + `MenuItemButton`（触发按钮绑定 `MenuAnchor.childFocusNode`），表单下拉字段使用 `DropdownMenu`，只读状态悬停详情使用 `Tooltip.richMessage`，文本输入使用 `TextField`，设置导航使用 `TabBar` 或 `NavigationRail`，焦点与快捷键遵循官方 `Focus`、`Shortcuts` 与 `Actions`（参考 [MenuAnchor.childFocusNode 契约](https://api.flutter.dev/flutter/material/MenuAnchor/childFocusNode.html) 与 [FocusNode 生命周期约定](https://docs.flutter.dev/ui/interactivity/focus#best-practices-for-creating-focusnode-objects)）。弹出菜单依据触发控件真实布局定位，打开期间随权威状态实时刷新内容，模型选择菜单打开时将当前选中项滚入可见区域，账号分组标题与模型条目按真实内容高度自适应布局。

主界面侧栏采用项目优先结构，项目下嵌套根会话：
- **非项目新会话**：项目列表上方常驻“新会话”按钮，复用 Material 按钮和既有起始页输入区。没有可恢复选择时默认准备并显示非项目新会话，不要求先添加项目；保留已有项目和会话的正常恢复。准备为显式导航命令，失败原地展示真实错误并允许重试，不在 build 或查询中创建目录。此页面复用模式、模型、推理强度、附件及分发设置，但工作区固定为 `local`，在外层会话环境栏中展示只读的固定本地文档目录标识而不提供 Git 工作树切换器。欢迎说明明确无需选择项目、工作文件将保存在用户文档目录，不将内部归属伪装成用户项目。
- **独立会话目录**：`standalone` 归属不作为项目行、项目计数或项目操作目标展示，其根会话在项目列表下方以“非项目会话”列表单独呈现；侧栏顺序为“全局新会话 → 实时搜索 → 全部／运行中／待处理三态筛选 → 项目树 → 非项目会话 → 并排归档与设置底栏”。新建、搜索和筛选固定在顶部，两类目录共享既有滚动区域，不挤占固定底栏。复用现有会话行、状态、打开、置顶、重命名、归档、过滤、搜索与分页。没有用户项目时仍保留该区域及新会话入口。当前会话的实际目录仍只显示 canonical `workspacePath`；顶栏不显示内部项目名称。点击全局“新会话”与项目行的新建操作是不同导航意图，迟到准备结果不能覆盖较新的选择。
- **紧凑侧栏与组件复用**：视觉及信息层级参照[共享侧栏概念稿](prototypes/project-sidebar/index.html)，沿用暹罗浅色主题的暖白新建按钮、浅拿铁选中底色和眼眸蓝竖条；新建按钮不采用大块深色填充。项目与会话保持单行，长标题省略，完整内容由只读提示展示；会话行前导 `16px` 状态槽位与项目图标列纵向对齐，会话标题左边界与项目名称左边界纵向对齐；本地项目不常驻冗余“本地”标签，远端保留 SSH 身份。空闲会话在前导状态槽位保持留白而不显示完成对勾，右侧状态与操作区固定对齐工作树标识、置顶与更多菜单；置顶状态与操作不重复占用两处行内入口。悬停、键盘聚焦或触控时提供可达的操作，菜单、焦点恢复与提示生命周期交由 Flutter 官方组件处理。头部、筛选、项目／会话行、分页状态、菜单和底栏按职责复用，独立公共呈现组件及整侧栏提供官方 Widget Preview，预览使用生产组件及真实主题／本地化，不复制界面或另建交互控制器。状态所有权见 [25.6](./25-frontend-state.md#256-只读模型与细粒度呈现)。
- **宽度调节与响应式抽屉**：侧栏默认宽度 `336px`，桌面端支持在 `300–440px` 范围内拖动调节（分隔条支持聚焦，左右方向键按 `16px` 步进调整、`Home` 键恢复 `336px`，并为对话区保留至少 `600px` 宽度）；窗口宽度小于 `960px` 时自动切换为保留完整目录树的覆盖式抽屉。宽度变更在键盘释放、失焦或拖动结束时通过 Client 串行通道提交至设置权威状态，旧代次提交完成不会覆盖更新代次的拖动草稿。
- **项目归档与添加向导**：归档必须经由确认对话框触发，文案明确提示该会话树在 `worktree` 模式下的工作树及其未提交、未整合内容将被一并删除。添加项目向导支持选择本地目录或 SSH 远程目录：SSH 连接先探测免密认证，仅当免密失败且服务端公布密码类认证方式时才弹出密码输入框；若服务端仅接受公钥，则就地提示需配置密钥或 `ssh-agent`（见 [22.4](./22-ssh-remote.md#224-凭据路径与持久化)）。SSH 服务器行常驻「重新连接」按钮，操作状态按服务器实例隔离，结果以桥接层返回的权威快照为准。

完整交互、响应式断点与异常状态约定见 [项目侧栏设计](concepts/project-sidebar.md)。

## 19.8 设置页组织与 Dart 展示边界

工作目录故障集中在“通用”的可折叠“工作目录检查”区域，展示真实失败、未知归属及未决清理，继续消费后端授权的重试和清理动作；智能体配置页只管理配置，不承载工作树恢复列表。每项诊断只展示一次原始原因，待提交文件与被版本管理忽略的本地文件分别列出。绑定状态 `active` 显示为“已绑定”，不能据此宣称任务正在运行。正常归档保留不作为恢复故障，用户可从归档会话查看和复制原工作目录及远端标识；该目录记录不证明路径当前存在，也不触发恢复、激活或删除。

### 界面语言

“通用 → 外观”提供“界面语言”选择，选项为本地化的“跟随系统”、固定自称“简体中文”和“English”，持久化契约见 [20](./20-config.md) §20.2。默认跟随系统；手动选择在设置命令成功返回权威快照后立即作用于全应用，重新启动后继续使用已保存选择。保存期间不把尚未确认的选择发布为应用语言，失败保留已确认状态并展示错误。

语言解析统一交给 Flutter：跟随系统时不指定应用 locale，系统语言变化自动刷新界面；手动选择中文或英文时显式指定对应 locale，不受系统语言变化影响。受支持语言保持中文和英文，系统语言不受支持时沿用 Flutter 根据受支持语言列表的默认解析（最终回退英文）。主题字体消费同一已解析 locale，不维护独立语言状态。

### 页面观察生命周期与无轮询原则

产品事件流按 [18](./18-studio-state.md) §18.2.1 的类型化主题与作用域组合，由 Client 领域所有者统一管理订阅与归约；统计模块则采用同篇 [§18.2.2](./18-studio-state.md#1822-统计观察与不可变读取) 的独立 `StatisticsRepository` 与强类型推送流（Feed），不经全局 Client 主题分发。主外壳（Shell）观察导航目录、公共配置与诊断摘要；设置外壳仅观察导航与公共配置，各设置标签页通过连接器按需声明统计、智能体模板、MCP/LSP 服务、技能或账号用量的可见观察需求，标签页隐藏时可释放对应观察租约。`Riverpod` 观察者的销毁、暂停与重建仅取消自身观察订阅，不关闭当前会话内容连接、不清空输入草稿或取消在途命令。

仅在初次尚无数据时展示骨架屏或整页等待；后续刷新、重连与错误均保留已有内容、滚动位置、筛选条件与编辑草稿，仅展示局部进度或错误提示。模型统计落盘期间的 `pending` 暂态不渲染页头提示行，避免插拔导致页面跳动，仅用于抑制过早显示“暂无调用历史”；`gap` 与 `readFailed` 等稳定异常则在固定页头轻量展示。启动与日常刷新均无 GUI 定时轮询。

### 原生账号（Native）与 ACP 接入管理

账号设置采用统一的“列表 + 添加账号页 + 详情卡 + 模型资料页”结构，标签与入口统一命名为“账号 / Accounts”，模板选择命名为“账号模板 / Account template”：
- **品牌标识与模型压缩阈值编辑**：账号品牌标识仅以模板目录（catalog）下发的 `iconKey` 字符串作为跨层契约，由 Flutter 侧品牌资产注册表（`AccountBrandMark`）渲染白底圆角着色图标，未知或缺失 `iconKey`（如 `openai-compatible`）回退显示名称首字母。智谱通用账号与 Coding Plan 统一使用[智谱官网](https://www.zhipuai.cn/zh)公开标识中的黑色「Z」符号，不使用旧 ChatGLM 图案；模板选择、账号列表及详情中的同一品牌保持一致。账号详情卡的模型列表按来源分组展示在线名单（`online`）、内置默认定义（`bundled`）与用户手动模型（`manual`），并作为上下文自动压缩阈值的唯一编辑入口（支持比例预设或输入精确正整数词元，点击「保存」按钮显式提交，避免输入中途触发误保存）。手动模型额外提供经二次确认的删除操作（删除仅移除目录声明，不改写历史调用与账单）。词元与上下文容量在界面上统一采用十进制紧凑格式（小于 `1,000` 显示整数，千级使用小写 `k`，百万级及以上使用小写 `m`，四舍五入保留最多两位小数并去尾零，如 `212.32k`、`1.2m`）。
- **模型启用开关与连接方式覆盖**：模型启用即时保存，来源、计费、能力、性能样本及最近 10 条评价按需在独立模型资料页读取。绑定目录的内置模型始终在配置列表展示；存在成功在线名单时，线上缺失的内置项默认关闭，用户可通过同一开关明确开启。界面说明这种开启覆盖名单缺失，但实际调用是否受支持由服务端决定；开关状态以后台权威快照为准，不通过新增手动模型或本地草稿伪造启用。新建账号使用独立页面，通过带实时搜索与分组标签的下拉模板选择器切换模板并重建默认草稿，且在添加 Native 账号时即可配置计费方式（默认跟随模板自动策略，支持显式覆盖）；账号 ID 创建后稳定。按模型仅在协议支持多种连接方式（如 `Responses API` 支持 `HTTP/WS`）时展示连接方式选择器，仅支持单一连接方式的模型不展示多余切换控件；自定义模型显式指定协议与模式并拒绝 `Chat + WS`。更新 API 密钥留空保留原凭据。模型区提供「同步目录」，显示进度、最近检查、来源与可重试错误，无发现能力则明确说明；刷新失败保留已有模型与配置（同步契约见 [20.5](./20-config.md#205-账号与模型目录)）。
- **ACP（Antigravity）账号准备与认证流**：ACP 与原生账号共用同一个独立「添加账号」页面的可搜索下拉模板选择器。Antigravity 仅支持产品固定 `1.4.5` 版本的自动受管安装，新建表单包含账号名称与紧凑服务器准备面板，不提供 Native 计费字段、自定义程序路径、启动参数或本地文件选择。当受管服务尚未安装时，新建表单主操作为「下载并准备」（展示字节进度、阶段名称与取消下载入口，返回页面仅释放观察而不中断后台下载）；准备就绪后主操作切换为「创建并检查连接」（先保存账号再发起连接检查，检查失败时保留已保存账号并就地提示“账号已保存，连接未完成”）。详情页状态区按权威状态在未检查、检查中、需要登录、登录中、验证中、收束中、认证通过、已取消与失败之间切换，每阶段突出唯一主操作（完整契约见 [28](./28-acp.md)）。需要登录时保留原连接及操作身份，提供服务端实际声明的方法选择、继续登录和取消；登录响应成功后自动复核，页面离开只释放页面观察，返回显示同一流程当前进度。
- **机器人设置标签页**：追加在设置导航末尾，提供列表与详情、扫码或已有应用首次配对、可信联系人与群聊授权、会话浏览与消息发送功能，全部通过类型化 Client 交互（见 [27](./27-bots.md)）。

### 账号列表、详情与编辑的呈现契约

账号列表、新建、Native／ACP 详情与编辑、独立模型资料统一进入应用唯一的类型化路由树；设置分区和模型资料标签也从路由选择派生，不以账号 ViewModel 或本地标签索引另建页面导航。显式返回／取消与系统返回共享退出保护，页面被覆盖不等于草稿退役；路由、参数及资源边界的唯一契约见 [25.4](./25-frontend-state.md#254-观察注册与页面导航)。模板切换仍是同一新建页内受保护的草稿替换，不新增另一种页面导航。纯呈现回调、官方模态确认和局部滚动／焦点状态保留。

主线新增的工作模式目录、全屏工作区及资料页、机器人详情及聊天页与账号页面共用该路由树；保留原入口行为、父子上下文、领域草稿和页面恢复身份，不因账号整合复活旧工作模式编辑页或删减机器人聊天能力。具体地址和退出职责统一见 [25.4](./25-frontend-state.md#254-观察注册与页面导航)。

账号视觉基准为 [issue #168](https://github.com/ZR233/anywork/issues/168) 与 `design/prototypes/` 下的 Material 3 暹罗浅色原型稿。在既有暹罗主题内，页面暖色底与接近白色、保留暖色倾向的分组表面形成可辨识层次；标题、账号名称和关键金额优先，说明、时间与来源次级呈现，状态和正文不能因默认紧凑字号而失去可读性。卡片细边框、行分隔、圆角、按钮高度及内边距保持一致，不通过更换全应用主题实现局部视觉对齐。稿中示例数据不构成新增模板或伪造供应商能力的要求，模型同步以当前无需重启的能力为准。

账号摘要的 `brandKey` 与模板的 `iconKey` 表达同一品牌身份，由账号实际模板的目录定义投影，不能用模板 ID 或账号名称代替。智谱两个模板共享 `zhipu`，MiMo API 与 Token Plan 共享 `mimo`；缺失或未知品牌继续回退首字母，不增加模板别名注册表。

账号列表在宽窗口按账号、状态、余额与额度对齐，窄窗口自然堆叠且无需横向滚动操作。品牌、名称与默认标记构成身份区；模板、ID、协议、模型数量及常驻凭据徽标不进入列表，必要信息保留在编辑或高级信息。搜索、添加和全部刷新位于工具栏，每行菜单提供单账号刷新、默认、编辑和删除，菜单点击不得触发详情导航。

计费类别和查询健康独立：不支持、缺凭据或失败均不解释为不计费。主状态标签使用同规格与同列位置；余额按币种分别保留可用、赠金与充值金额及原始精度，不相加不同币种、不将未知补零。订阅按真实额度展示剩余、进度、重置时间和低额度提示，不套用货币模板。首次加载、空列表、搜索无结果与局部刷新分别表达；失败保留最近有效内容及时间和重试入口。

列表使用摘要密度：空间足够时，同币种的三项余额和三项额度分别并列，不因重复币种说明、可换行的长标签或多余列内留白造成宽屏额度换行。币种在同一摘要组内明确标注且不重复堆叠；放大文字或长精度值超出可用空间时允许自然重排，不缩小字号、截断金额或照搬原型过窄的竖排标签。窄列表的身份与计费／接入状态在空间足够时同排，菜单保持独立点击目标，空间不足时再换行。工具栏仅在已有目录结果时显示当前实际呈现的账号数量；初始加载或初次失败尚无结果时不将未知显示为零，已加载的空目录或搜索空结果仍可显示零。没有列表级权威更新时间时不合成统一刷新时间。

选择或添加账号后在任何窗口宽度完整替换主内容区，不同时保留列表、不采用抽屉或主从分栏；全局侧栏不变，返回恢复原搜索和滚动位置。详情按名称与端点、余额或订阅额度、接入设置、模型目录单列组织，避免身份与凭据状态重复。高级信息保留 ID、模板、协议；计费覆盖可恢复自动，并说明不计费仅为应用估算策略，订阅不保证有效额度或免除额外收费。ACP 共用骨架但仅展示真实安装/认证能力。

宽屏详情的设为默认、编辑账号与删除图标按钮与品牌标题同排，不再使用包含重复动作的溢出菜单；窄窗随内容换行而不裁剪动作。余额区将标题与状态、更新时间及刷新组织在同一头部，金额和额度按可用宽度分区，重要读数与说明形成清晰字号和字重差异。状态胶囊使用一致规格及语义颜色，始终保留文字而不只靠颜色区分；低额度提示和刷新错误不覆盖计费类别。账号设置按标签与值对齐呈现，计费更改与恢复自动保持明确入口，不将所有候选项常驻铺开。

详细余额密度按读数角色分区：同币种所有实际金额可读地并列时保持宽屏同排；空间不足且存在可用余额时，主金额独占一行，赠金与充值按各自读数所需宽度独立决定并列或纵排，不让主金额的大字号强迫较短副金额各占一行。副标签允许换行，不通过缩字号或截断金额换取并列；单列仍不足的极长读数保持完整内容并允许换行。缺失项不占空位、不补零，可用余额缺失时不将第一个副金额升级为主金额。此规则只作用于详细余额，不改变列表摘要的读数宽度规则或订阅额度的独立布局。

模型按来源分组展开，所有头部的折叠箭头在左：收起时朝右，展开时朝下，方向跟随组件的实际展开状态，包括返回页面后的状态恢复；尾部仅保留唯一的「详情与评价」入口与启用开关，展开区内不再重复放置规格与评价跳转按钮。展开区聚焦上下文自动压缩阈值配置（预设比例芯片 + 精确词元输入框 + 显式「保存」按钮）：操作组按配置卡片内容区右边界对齐，窄屏按可用宽度自然换行，不裁剪输入或操作；连接方式选择器仅在多协议传输可选时展示。完整规格、阶梯价格、实测性能样本与使用评价统一收纳于独立的模型资料页。手工模型编辑与删除仅对 `manual` 显示并二次确认。

模型资料页在同一账号功能内完整替换主内容，通过「规格与性能」「阶梯价格」「使用评价」三个 Material 标签组织，只按账号与配置模型 ID 的复合身份读取资料；返回恢复原账号的滚动、折叠与未提交阈值草稿。价格保留真实币种、阶梯、来源及缺失值。使用评价展示实际返回的最近 10 条任务样本、通过／失败／未评级结果、任务类别、质量与指令遵循两个分项、评语及时间；均分、分布、筛选和排序明确限定于该窗口，未评级不计入均分。概念稿中的示例任务标题、评价者、自由标签、样本数及性能数据不构成真实事实，不从名称或评语推断补齐，但已有真实字段仍应按概念稿的布局与层次呈现。

规格标签按模态与能力、上下文与阈值、协议与模型来源组织清楚的图标、分隔和内容层次，再展示真实性能样本。语义分组来自类型化呈现，不在视图分析已格式化文案；模型来源不冒充目录同步健康，缺失事实保持未知。窄窗允许分组内自然换行，不照搬概念原型自身的逐字竖排或横向越界。

阶梯价格按输入、缓存读取、输出、缓存写入排列，未知项保留缺失提示，币种、阶梯范围、来源及核验信息不丢失。宽屏阶梯标题与单位对齐，窄屏自然换行；不补造缓存节省率或任务费用示例。评价保留全部真实筛选维度与双评分，排序控件处于工具栏末端，空间不足时按语义组换行；卡片层次与密度参照概念稿，不删筛选或缩小字号换取同排。

资料页身份、完整说明与读取错误参与页面的协调滚动，长名称、多行说明、窄内容区及文字放大不能挤尽标签内容或造成纵向溢出；标签入口保持可用，各标签的滚动身份继续按账号与模型隔离。不以缩小字体或裁剪整页隐藏问题。计费控制中的「自动」表示清除覆盖；没有独立权威自动值时只显示该动作，不把当前覆盖后的生效类别标作恢复后的结果。

未落地的 Native 创建草稿在未显式覆盖计费、且端点仍为当前目录发布的原始模板默认值时，呈现该模板已知的默认计费，而非丢失为未知；端点改变后不能保证该默认值仍适用，未获权威结果时保守显示未知，不在前端复制端点归一化或模板分类规则。显式计费值（包括未知）始终优先；已有账号继续展示当前已保存摘要，不将其冒充尚未保存的新草稿的推导结果。

阈值输入与 25%、50%、75%、90% 比例预设只修改待保存草稿；比例填写辅助仅在已知有效上下文窗口时可用。保存通过既有窄命令提交精确正整数；「恢复自动」是独立的清除覆盖操作，不将所有模板默认值等同于 90%。最终有效阈值及安全调整仍以模型领域的权威解析为准；界面保留输入意图并解释实际有效值，不静默改写原输入。账号内的详情／资料导航保留草稿，真正离开账号上下文前须完成保存、放弃或取消的决策；保存失败保留输入，未知结果不自动重发。

离开有修改的编辑页，包括切换标签、返回列表或聊天，均需选择保存、放弃或取消；失败保留输入，旧保存结果不清除新编辑。账号保存、设为默认或保存后连接分别报告真实结果。编辑草稿与业务操作归属见 [25.14](./25-frontend-state.md#2514-账号分域与可预览呈现)，组件销毁不替代业务取消。

新建页在同页组合可搜索模板选择器与配置表单，Native／ACP 以类型化目录值区分。切换模板先完成旧草稿的离页决策，再建立独立编辑身份和模板默认值；不得把旧模板的密钥输入或模型声明带入新模板。已有账号保持稳定身份与模板。概念稿以对话框示意的编辑字段、分组和操作层级在正式独立编辑页中还原，不为模拟对话框简化既有草稿保护。

模板输入框跟随所在表单的有限横向约束，占据可用内容宽度；弹出目录沿输入框锚点展开，并保留官方搜索、筛选、焦点与菜单滚动能力。模板条目的类型化身份用于同一真实可操作候选，不以不可见的布局测量内容代替已展开菜单中的选择目标。

Native 创建尚未得到保存的权威确认时，标题与提交文案使用新建／添加语义，高级信息不把预留的创建目标 ID 当作已保存账号展示。创建已确认后，即使后续设默认仍待完成，也按已有账号呈现标题、提交文案和账号 ID，同时保留明确的部分成功反馈及尚未完成的创建后操作；未知结果继续保留未确认提示与禁止重发约束，不由界面文案推断后端未发生创建。

ACP 新建标题及高级账号 ID 遵循相同的已确认身份边界，提交动作仍为「保存并连接」。安装就绪或认领已就绪安装不改变新建身份；配置保存确认后，即使连接检查失败，也按已有账号呈现并分别报告结果，保留同一编辑上下文。保存结果未知或同步失败时保留输入、显示未确认提示并禁用再次保存，不能把一般异常当作账号肯定未创建；放弃本地编辑前明确说明已发送操作仍可能更新。

Native 创建页可选择「创建后设为默认」，默认不选；创建得到权威确认后才调用现有设默认窄命令。该命令只写入普通模式的新会话默认路由，不改其他模式、显式角色路由覆盖或已有会话的冻结路由。未配置专属路由的系统子智能体继续按 [20.3](./20-config.md#203-根路由与系统-profile) 继承当前普通模式默认，其未来新建实例的有效路由可随之改变；不能把有效继承值的变化解释为显式覆盖被改写，也不为设默认固化原继承值。创建成功而设默认失败时明确显示「账号已创建，设为默认未完成」，保留账号和当前编辑上下文；已知拒绝可重试未完成步骤，不重复创建，结果未知不得自动重发。ACP 不是 Native 模型默认路由候选，也没有 Native 计费配置语义，因此不显示虚构的默认开关或计费字段；共用页面只展示其真实受管准备、保存与认证能力。

列表可在名称下展示由配置所有者发布的安全端点摘要，限定为 URL 的协议、主机与必要端口，不含用户信息、路径、查询或片段；无法安全解析时省略，不回退到原始配置字符串。ACP 不伪造 URL。模板选择摘要从同一权威模板目录消费协议、默认地址、默认计费与目录／用量查询能力，按概念稿的标签和值组织，不按品牌或模板名称推断。Native 与 ACP 使用类型化呈现分支，ACP 不出现 Native 协议、计费或查询能力假值；用量查询能力未提供与明确不支持分别展示。查询支持不代表凭据或套餐有效，模型发现支持亦不代表已经同步成功；字段所有权与目录修订见 [20.5](./20-config.md#205-账号与模型目录)。

列表身份区的端点副标题使用单行摘要，空间不足时在尾部省略，悬停提示仍只使用同一安全端点字符串；不改写呈现值、不按原始配置 URL 补全，也不为完整端点挤占名称、默认标记、状态或独立菜单空间。副标题不建立与行详情入口竞争的文本选择手势，点击仍归属该行的详情导航。该副标题布局与身份区的品牌尺寸独立，详情标题及其他完整事实继续保留可选择复制的全文，不因列表省略策略而截断。

宽列表的计费与 ACP 状态标签须完整可见，有限状态列内允许自然换行并随内容增加行高，不把端点省略策略用于状态。保留共享列对齐与父级响应式布局，使用官方标签控件的内容能力表达可换行变体，继承现有文本样式、方向、本地化及文字缩放；不缩写状态、不缩字号、不仅依赖悬停提示。详情和模板选择等其他标签消费者保持各自既有布局。

账号页面以复用的纯呈现组件组合：身份、状态、账号行、余额／额度、模板选择、表单共同字段与操作栏、模型行、阈值编辑、规格／价格与评价各有明确职责。同类职责只保留一份生产实现；用语义明确的布局／密度枚举、类型化内容变体或纯 Widget 插槽表达差异，不按供应商品牌复制页面或建立万能表单引擎。计费类别、查询健康、内容形态与操作状态保持独立，支持真实的混合余额／额度；共享组件复用官方 Material 控件、现有主题及本地化，不维护业务事实或原生资源。

官方 Widget Previewer 直接复用生产视图，覆盖所有内置 Native 模板及 ACP，而不是只按品牌去重：普通模板与套餐模板分别检查选择器、列表、详情及编辑入口。计费类别、查询异常、多币种、多额度、长名称、窄窗与字体缩放另作为状态维度检查。视觉验收须实际对照设计稿与渲染截图；预览中的合成品牌字段不能替代原生摘要投影的验收，原生验证仍须确认目录到真实界面的品牌一致性。

每个有独立职责的公共呈现组件及整页均提供可发现的官方预览入口，使用同一生产组件与合成不可变展示值；私有布局辅助随所属组件验证，不复制一套预览 UI。设计还原是独立验收目标：实际打开概念页面，以可比的主内容区尺寸、字号和内容形态核对信息顺序、宽度与列比例、标题／读数层级、间距与密度、卡片、状态标签、按钮位置、展开区及表单。明显可修复的视觉偏差必须修正并重新截图；仅使用 Material 3、功能通过或无溢出不能代替视觉通过。平台绘制、真实数据及既定架构导致的必要差异须记录原因，证据与对照规则见 [24.4](./24-testing.md#244-呈现诊断与受控账号对端)。

### 统一模型选择器、性能统计与双栏会话状态栏

会话输入区、新会话草稿、系统智能体角色配置与用户智能体模板编辑统一复用同一套紧凑模型选择器组件：选项按账号实例 ID 分组并以账号名称为组标题，模型行仅展示模型名称与输入能力徽标（文本、视觉等能力严格依据目录声明渲染，不从模型名称推断）。切换模型时，推理强度自动归一化为新模型声明的默认值（无显式默认值时取首个候选值，不支持推理强度的模型置空并禁用控件）。

模型性能统计页与状态栏统一以 `(account_id, 配置的 model_id)` 为顶层聚合身份，展示包含首字等待在内的输出吞吐率（TPS，计算规则见 [06](./06-model.md) §6.12），并在顶层汇总下按请求期推理强度（`effort`）展示细分读数。调用历史列表的“模型”列以配置模型为首行；当实际发送模型或上游响应模型不同时，通过缩进箭头 `↳` 与橙色「模型不匹配」徽标分层展示，并提供「仅看不一致」筛选复选框；每个历史条目只呈现完成时间、模型身份与性能读数单行，不内联展示用途、调用身份等样本诊断，保持性能对照的行密度。账号额度查询在账号标签页首次可见时按实例并行发起，逐卡更新结果；DeepSeek 账号余额遵循官方 [`/user/balance`](https://api-docs.deepseek.com/zh-cn/api/get-user-balance/) 语义，按币种独立展示 `total_balance`、`granted_balance` 与 `topped_up_balance`。

聊天主界面采用左侧项目会话栏与右侧主聊天区的双栏布局，底部状态栏左侧放置当前智能体身份、`Auto / Plan` 模式、当前模型与推理强度选择器，右侧放置上下文进度、按币种分组的费用估算以及技能、MCP、LSP 数量（悬停共享同一个只读详情浮层，「更多」菜单在窄窗口下收纳折叠读数并提供已批准计划的只读查看入口）。根会话下的智能体数量、运行状态分组排序与会话切换统一通过顶栏唯一的 `n agents` 菜单表达，底部状态栏不重复展示子智能体列表。

## 19.9 当前活动、工具过程与确定回执

会话保留居中阅读列、用户紧凑右对齐气泡、助手正文铺开、默认折叠过程轨和既有输入区。Native 历史按实际完成顺序出现，不等待整组、不将迟到记录插回旧段；Flutter 原 controller 按后端明确的 MainPresentation 与 run.start_seq 唯一组合连续段。一段一条 Message.custom，不维护持久组状态。读图调用及其结果留在工作明细，不因媒体拆组，见 [26](./26-timeline-content.md)。

时间线与实时栏沿用[概念稿](prototypes/live-status/index.html)的暹罗主题、紧凑过程文字、图标列和细导轨。标题约28 logical px自然最小行高，缩放可增高；参数/结果保留代码样式，用户气泡右下收束，助手正文文档式阅读。概念稿仅为视觉参考，旧整组移交场景不再是生产契约；完成即进入历史，原生证据不能由模拟器替代。

等待实施计划确认或用户回答问题时，原有计划详情、确认入口及问答表单承担交互展示，输入区上方的实时状态栏不展示内容，也不保留空白占位；不得重复呈现计划或问答工具的参数、回执、旧思考摘要及未交接正文。可见性只依据当前类型化待决交互事实，不解析工具输出或凭活动标题猜测；交互决议后按当前实际执行状态恢复正常实时展示。此规则只控制呈现，不清空 current、改变历史提交条件或伪造终态，不改变工具权限审批语义。

实时状态栏位于输入区上方，呈现思考、工具进度、流式正文和压缩；允许多个未终结 part，前一 reasoning 不遮后续正文。完成记录进入历史后退出对应实际活动，不等组封口。空完成正文不画卡也不分段，仅附件保留；正文仅开始不分隔历史段。后台工具最终结果在实际完成位置相邻组合，不回填原调用段。

统一前置活动图标、字级、导轨和间距：流式文本输出使用分层书写图标，纸面线条固定，仅笔沿短笔画轻微移动；其他活动状态使用趴卧猫轮廓图标，身体、耳朵、闭眼和前爪固定，仅垂落的尾巴以中段转向、尾尖滞后和短暂停顿表达持续工作。动画沿用 Flutter 标准生命周期，减少动态效果时保留对应静止图标。当前状态行在等待下一步且仍有执行资格时可继续活动标识，会话暂停或执行资格结束时静止；已完成 Run 卡片不因同 Turn 仍运行而重获活动身份。状态与耗时只来自真实活动事实，失败/停止分别用错误/中性图标，不通过动画伪造计时或终态。无具体内容时显示不可展开“思考中”和真实耗时，压缩使用真实开始/结束。

实时区统一使用 `ConversationActivityBar` 外壳，标题行、活动成员与正文分别由同一套生产纯视图承载，官方 Widget Previewer 直接装配这些组件。连接层只传入已接纳的展示值、正文子树和同步交互回调，继续管理内容读取与资源撤销；预览不加载原生桥或建立另一套活动状态。状态栏沿用输入框的 `1040 logical px` 阅读列，标题、图标、耗时与展开箭头按父级约束布局，窄窗或文字缩放时统计自然换行，不能省略状态名称。短内容保持自然高度；成员区与正文区的常规高度上限分别为 `186`、`196 logical px`，标题保持在各自正文滚动区之外。

活动与只读交互详情共用 footer 在问答／输入区布局后剩余的有界视口；总内容超出时通过标准外层滚动逐项到达，不挤出下方操作控件，也不靠永久裁切隐藏详情。外层滚动可以移动整个活动标题，区别于标题与内部正文的相对布局。展开详情不改变原问答提交资格，折叠仍同步撤销并汇合原读取；有限视口验收需将目标完整带入实际滚动视口，而非只检查它与整个窗口相交。

工作卡与活动详情首次默认折叠，不因内容变化自动展开。历史工作标题固定“工作记录 · N 项”，后台为“后台结果 · N 项”，N来自代表 ordinal；只有1项也保持工作卡。尾部增加同段记录只更新代表/计数，保留 key 和展开意图，不要求活动 Widget 整体迁移。折叠在动画前撤销读取资格。正文共用主题感知 Markdown 渲染器，流式输出初始跟随，向上滚动/选择暂停，经“跟随输出”恢复。

最早操作晚终态时只保留它的真实活动，后续已完成记录立即进入各自完成段，不在实时栏积累“已完成待提交”片段。活动观察和正文窗口保持有界，未读取内容使用原加载/重试交互，不伪造完整集合或总数；退出窗口先撤销资格，见 [26](./26-timeline-content.md#2682-活动与成员展开的资源边界)。

实时栏使用低对比主题表面、细边框与紧凑标题，正文、活动详情及回执沿同一阅读轴展开；只有真实可展开内容才显示箭头。流式正文区与活动详情区的滚动条遵循 §19.7，不常驻轨道或滑块，也不因为滚动条显隐改变阅读宽度。

实时栏与历史卡复用活动行、状态图标、耗时、展开标记和细导轨等纯组件。历史折叠头不展示未经读取证明的全组耗时、失败数、类别统计或思考摘要；明细统计只标“已加载部分”。单项可显示其真实状态/时间。共享组件不承担业务分类、完成归约或内容读取所有权。

阅读交互参考 [Apple 滚动视图指南](https://developer.apple.com/design/human-interface-guidelines/scroll-views) 与 [W3C 内容重排说明](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)：每个阅读区保持一条纵向滚动路径，利用概要和显式展开控制初始信息密度；整行触发展开，标题与输入区不随内部正文滚走。窄窗优先换行，避免阅读每行时反复横向移动。

主时间线条目由聊天组件统一提供 `12 logical px` 的前置间距，首条不重复留白；作者相同、时间相近和工作组边界不改变该间距，不再使用聊天气泡的紧邻分组间距。普通正文按内容自然增高，不套用活动行的最小高度。成员列表只借用聊天组件的消息分发，直接呈现生产成员视图，不再叠加顶层消息的缩进、对齐和垂直留白；活动行本身拥有自然最小行高，组导轨拥有展开区缩进。

嵌套成员区透明、自然收缩，历史明细随主时间线滚动，不给少量成员留空白。展开参数、结果、诊断与代码按阅读列换行自然增高。成员经 Run 有界读取，折叠连代表的参数/结果/思考正文/媒体也不预读；复用原组件，不复制全量成员或接管像素补偿。工具保持一个真实 call 语义入口；思考成员有概要显示概要，有正文才可展开，未知耗时不补造，折叠撤销正文资格。

主聊天区用 Main 段代表分页，每页布局后判断满屏，未满且 continuation 可继续就读下一页，无固定总页数。折叠卡高度不变不等于无数据进展；满屏/EOF停止，不为组头或总数额外读取。错误暂停，显式重试恢复；零尺寸、不可见与退役暂停，布局变化触发检查，不逐帧轮询。首批不等补满，补载成本另报。

正文保留原始顺序、空白和换行，不 trim 或加分隔符；有限阅读列内自然增高，到响应上限用标准内部滚动，不显示假折叠箭头。current 仅有界预览和引用，展开时订阅需要的正文窗口，Rust 组装窗口，Flutter 不拼原始 delta。工具/思考复用标准折叠，参数/结果按字面代码显示；build/计时不触发全文查询或二次归约。

问答结果、计划决定、压缩回执、停止/失败和非工具后台结果为独立 Single，分隔相邻工作段。后台工具结果各自不可变，UI只组合相邻结果、局部更新尾卡，不回写旧记录。失败/停止用独立默认折叠终态元素，停止保持中性语义，展开查看真实原因。Turn完成不伪装后台任务结束，活动仍按实际 owner 显示。

### 问答和 Plan 卡片

会话各呈现模块的分工与资源所有权遵循 [25](./25-frontend-state.md) §25.15；本节只规定显示与交互。

待决问题/审批/计划留交互 dock，结束后才进历史。回答卡明确区分问题、可选项、实际多选/自由回答和取消等决定，按 question ID 对应，默认紧凑折叠、展开按题排列。复用标准卡片、列表和折叠组件，长内容换行且可选择复制；敏感/redacted 只显示隐藏事实，不泄露到正文、详情、复制和无障碍。

Plan 当前态、确认决定、文档版本与历史快照遵循 [13](./13-plan.md)。所有运行态及已结束决定使用封闭 typed 状态映射，不以非 pending 等同批准；历史冻结原文和反馈，不带当前确认/编辑动作。摘要只显示必要标题/状态/版本，详情完整阅读当时内容，不在回执里重复列举机器协议标记。

问答与 Plan 的历史回执采用与过程轨一致的默认折叠摘要，展开后才呈现冻结问题、答案、文档与反馈。摘要只使用真实公开的决定和数量，不从任意正文推断成功或补造缺失内容。各独立呈现职责与组合时间线提供官方 Widget Previewer 入口，直接复用生产视图、主题与本地化；预览数据及其证明范围见 [25](./25-frontend-state.md) §25.15 与 [24](./24-testing.md)。

## 19.10 原生列表、Markdown 与连续阅读

文本、媒体和领域回执的展示身份与更新语义统一见 [26](./26-timeline-content.md)；本节不指定聊天组件库或消息类。助手流式正文留在实时区，不逐词元插入历史消息、裁剪换行、延迟终态或将正常停止改写为错误正文。

Markdown 渲染器消费所在子树的既有主题，不在内部重置标题字号或分隔线策略。常规正文沿用基准主题与组件公开默认值；Plan 文档的紧凑标题和无 H1 分隔线仅由其局部文档主题特化，不能改变普通 Markdown，也不能被更内层通用渲染覆盖。

列表复用已有 ChatController/Chat 的公开能力，一条 item 含正文和附件时仍是一消息，内部复用媒体，不扩展附件兄弟拓扑。Set/Prepend/Append/Update 的唯一应用语义见 [26](./26-timeline-content.md)，后台结果组头的 Update 使用组件公开的原位更新能力，保留展开意图及原成员读取 scope；不自写 controller、通用列表、像素修复或全历史 diff。不兼容/Deferred 是可读且非零高度的独立卡片，不消失、不伪造历史作者/时间。

所有生产正文入口——消息、实时栏、问答、Plan、展开详情——由父布局提供有限宽度。优先用 Flutter Text/RichText softWrap、Expanded/Flexible、LayoutBuilder 及现有 Markdown 的公开配置/builder；段落、长中文、长英文/URL、行内代码、代码块与表格按可用宽度自然换行，不横向撑破阅读列、不用 clip/ellipsis 隐藏完整正文。只有明确的摘要行可省略，展开内容完整可读。

视觉换行不插入字符、不改权威缩进和换行，选择/复制保留原文；安全链接无手势绕过、远程图片仍显式授权加载，原图按需读取。沿用项目主题、平台字体与等宽代码字体、低对比引用/代码背景和清晰表格细线，不通过新主题掩盖布局问题。

用户阅读旧位置时事实继续接纳，回最新用组件公共能力，不重建订阅或清消息；旧页只局部更新受影响段，不重验全部历史，也不固定只前插页首。文本缩放、窄窗口、键盘/滚动条、焦点、展开成员、大正文/图片和阅读位置须原生观察。实际加载 Message 保留到切换/关闭，惰性 Widget 不等于恒定数据内存；概念稿不证明 bridge、持久化或供应商行为。

旧 `show_image` 仅保留历史图片展示语义：真实工具状态、授权图片与可选说明；缺失 typed 图片附件时明确不可用，不从路径猜图。历史说明仍取完整冻结参数中的字符串 `caption`，去首尾空白并限制最多 240 个 Unicode 标量值，不改写原文，不完整参数不显示说明。现役展示统一使用 `show_files` 的版本化专用回执，按本章“文件展示与阅读”呈现；不恢复旧工具入口，也不将专用回执解释为通用可执行 JSON。

详情查看器定向观察目标原子与字段的不可变内容身份；条目不存在、读取 scope 关闭或展示退役不能切断失效通知。确定失效时清空已读正文与续传位置，禁止复制及重试；临时连接失败保留合法续读能力，不将实时领域 revision 带入冻结详情。安全 Markdown 分类采用保守边界，多行块语法（含有序、无序列表）不作为无语法普通文本显示。

读取文件的紧凑行继续显示读取图标、真实状态和文件名，并以提示保留完整目标路径；该路径来自当前活动或完成原子的已知工具参数，不恢复通用参数 JSON 解析，缺失或无效时不猜文件名。单段思考在展开所属组后显示一行概要或真实耗时，存在正文时允许展开阅读；读图调用及图片、文字和错误结果留在所属工作组成员内，只保留一级明确的展开意图，不生成图片专用工作组。重连提示保留内容而不提供重复重试按钮，明确失败才允许用户重试。

活动标题可使用已有有界思考概要与单行 Markdown，支持粗体/斜体/代码/链接标签，超长省略但不启用媒体或链接动作；整行点击仍为展开。历史标题仅为“工作记录 · N 项”或“后台结果 · N 项”，不显示未加载成员的思考概要/全组耗时。无概要活动显示真实状态与已知耗时。

## 19.11 运行中发送消息与剪贴板粘贴

主会话运行期间用户仍可继续编辑草稿、添加附件并发送新消息：
- **唯一主操作槽位定宽多态切换与草稿冻结**：输入区右下角仅设一个固定圆形尺寸的主操作槽位（交互参照 [会话运行时输入框与配置锁定概念稿](prototypes/session-composer/index.html)），所有状态切换仅在圆钮内原位更换图标与配色，不改变槽位宽度、不挤动左侧选择器——运行中且无草稿与附件时显示中性色「停止」（`■`）圆钮；停止收束期间显示禁用旋转圆钮（文字提示置于底栏左侧辅助区）；已停止且存在未消费继续点（`Continuation`）、无草稿与附件时显示强调色「继续」（`▶`）圆钮（仅由显式点击触发恢复，空输入框按 `Enter` 不触发继续）；无论空闲、运行中或已停止，只要输入文本或添加附件（且路由可用）即原位切换为强调色发送/「发送并继续」（`↑`）圆钮；空闲无继续点且无内容时为禁用态（`↑`）。输入框获得焦点时按 `Esc` 键可停止当前运行并保留草稿。点击发送或按下未带修饰键的 `Enter` 键（处于输入法组词区间时除外，`Shift+Enter` 插入换行）会在首次 `await` 前同步冻结 `DraftStamp`、文本、完整路由、参数、项目与会话身份及附件 ID 集合，并分配稳定的 `OperationId`；用户随后继续编辑会产生新修订号，旧提交的确认回执仅清理该次提交冻结的值，不会误清用户新输入的文本或附件。
- **停止收束、继续与在途区分**：运行中点击停止受理后显示「正在停止」禁用过渡态，在后台清理真正结束并发布权威空闲快照前既不提供继续也不允许提交。按钮与状态文案只从命令板的受理回执和权威执行快照派生：请求在途但尚未受理时保持对应入口的禁用态，不提前显示「正在继续」；继续受理后才显示进行中，失败或结果未确定时保留可重试原因，不重复提交同一操作。
- **剪贴板图片直接粘贴与缩略图大图弹层**：当输入区聚焦且可编辑时，按下 `Ctrl+V`、`Cmd+V` 或 `Shift+Insert` 优先读取系统剪贴板图片，规范化为 PNG 格式后经由现有本地附件准入通道进入权威草稿；剪贴板无图片时保持常规文本粘贴行为。粘贴或本地选入的图片在输入框上方附件栏中以紧凑圆角缩略图呈现（右上角提供独立移除按钮，避免与预览点击冲突）；点击缩略图即弹出模态大图预览层查看完整高分辨率图像（支持多张草稿图片切换、适应窗口或原始尺寸查看，按 `Esc` 或点击遮罩关闭且不丢失当前输入草稿与焦点）。

## 19.12 配置变更命令与选择器投影

输入区与「设置 → 安全」页均不提供权限模式选择，执行策略固定为 `full-access`（见 [04](./04-security.md)）。

账号、默认账号、单个工作模式路由的模型与推理强度、单个智能体角色的模型与推理强度、通用设置与联网搜索各自使用独立的类型化意图（typed intent）；复合编辑页在提交时按实际修改字段拆分为最小命令，共享同一个设置操作通道（operation lane）以满足 CAS 顺序，不将同页未修改控件的旧值重新写回。命令确认的资源通过 Rust 类型化响应或所有者事件帧进入对应 Client 归约器，不在命令成功后回读整棵 `StudioState`。

模型、工作模式与推理强度选择器投影分为 `canonical`、`pending`、`resolved` 与 `unavailable` 四种状态：`pending` 仅提供即时视觉反馈，失败时回滚至 `canonical` 并保留可重试错误提示。快速连续切换（如 `A → B → C`）时，旧操作仅更新自身真实结果，不得清除最新意图 `C` 的待确认覆盖层（pending overlay）。模型选择器的可用性取自活动会话的实时状态，准备请求期间临时借出会话不触发模型不可用告警。

## 19.13 实时投影与局部细粒度更新

UI 的权威只读镜像由 Client 各领域只读模型更新（见 [25](./25-frontend-state.md)），`Riverpod` 仅观察职责内不可变且按值相等的投影，再由连接器交付视图；统计页面则由独立的 `StatisticsRepository`、`ViewModel` 与纯视图组件（View）消费统计领域状态（边界见 [25.13](./25-frontend-state.md#2513-独立统计领域与呈现模块)）。状态栏吞吐率读数（throughput readout）与上下文读数各自使用独立的只读消费者（Consumer）按会话身份观察对应细粒度投影；外壳仅观察路由、工作流与能力等低频稳定字段，防止高频解码吞吐率变化触发整个 `AgentWorkspaceView`、时间线或输入区重建。

吞吐率读数的显示保持由后端权威累计摘要负责（见 [18](./18-studio-state.md) §18.8），前端组件不持有私有速度快照，也不在新模型尝试的早期部分观察到达时清空已有聚合速度。附件草稿准入采用两阶段更新：`admitAttachmentDrafts` 返回后先展示稳定的草稿元数据，随后按相同草稿 ID 异步补齐预览字节（补齐前重新校验项目与会话身份、提交修订号及附件代次）。账号列表仅呈现身份摘要、状态与余额/额度，不常驻模型数量或具体 `model_id` 清单。

统计模块的架构分层拆分不改变既有界面视觉与交互：完整保留原有的汇总／调用历史布局、宽窄屏自适应切换、筛选控件、文案与诊断身份，不在界面上暴露内部读取分页或来源元数据。`pending` 状态继续不占用可见状态行，`gap` 与 `readFailed` 仍在既有轻量区域展示；刷新期间保留最近有效内容与滚动位置，不因分批物化而短暂闪现空列表。模型、推理强度（`effort`）与模型不匹配（`mismatch`）筛选状态由统计呈现层所有者管理，纯视觉组件仅接收不可变属性（Props）与动作回调；设置外壳仅传递可见性状态，不持有统计快照、过滤规则或原生资源，共用的基础视觉组件也不夹带其他设置领域的状态依赖。

## 19.14 工作模式编辑器

设置页「工作模式」标签是模式目录页：仅提供搜索、新建、导入与目录列表（系统内置与我的模式分组），点击条目经 `mode-workspace` 路由进入独立的全屏工作区；工作区不常驻设置侧栏与模式列表，顶部 AppBar 提供返回、模式名、「内置·只读」/「未保存」身份标识与撤销、重做、重载、复制、删除、保存动作（只读形态收敛动作，详情为纯只读展示而非禁用的编辑控件）。

工作区以紧凑 TabBar 组织「流程 | 预演 | JSON | 设置」四个分区，流程画布始终是主视图。点击阶段卡片或连线即展开对应详情：宽屏（≥960）在画布右侧并排展示阶段详情（名称、技术标识、类型、阶段指令、完成标准与可前往阶段）或转换详情（来源、目标与完整转换条件），详情内的关联阶段/转换可继续跳转；窄屏进入 `mode-detail` 子路由页，返回时恢复画布视口与缩放。关闭详情后画布收回占用空间。

视觉层级遵循任务模式概念稿：顶部标签左对齐、图标与文字同行，只读模式隐藏撤销、重做及画布编辑工具；流程标题、统计与聚焦切换组成画布头部，缩放与适应视图固定在画布右下角。宽屏详情拥有独立布局空间，不能覆盖流程节点和画布工具；开合详情不重建画布控制器、不自动重置视口。详情以阶段名称或转换两端作为主标题，技术标识与类型使用次级徽标，指令、完成标准及后续去向分节展示；完成标准逐条排列，关联阶段使用可点击的卡片，底部保留带锁图标的只读提示。连线和连接端口也消费项目主题角色，选中态同时提供加粗边界与小型活动标记。

画布减负遵循“画布只放导航所需信息”：节点卡片仅显示顺序编号、阶段名称、类型图标与起点/终态徽标，技术标识与长文案进入详情；连线不常驻完整条件文本，未选中时仅显示方向标记，选中时显示极短摘要标签（hover 展示完整条件），选中提示通过标签高亮加粗与边框加宽呈现，不只依赖颜色。「聚焦所选 / 全部」SegmentedButton 提供聚焦视图：淡化与所选节点无关的节点与连线并提示已淡化数量；该过滤只影响呈现，完整视图下返工、停止等全部合法转换始终可达。

自定义工作流图支持阶段节点与转换连线的增删改查、画布缩放与平移、自环、循环及多后继分支，并在保存前实时展示 Rust 编译器的精确校验诊断；内置工作模式禁用节点拖动、连线与属性修改，用户可通过复制内置模式创建自定义工作模式。会话状态栏展示当前快照中的阶段名称，若原工作模式已从目录中删除则显示“已删除模式使用快照”。原生画布交互复用 `vyuh_node_flow` 核心组件，画布节点布局坐标不影响运行图逻辑身份。阶段/转换详情面板注册官方 Widget Previewer 入口（合成数据，不装配 Client）。
