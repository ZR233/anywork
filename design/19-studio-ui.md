# 19 - anywork 桌面界面与交互契约

桌面产品中文名称为“糊来帮”，英文及其他语言环境回退名称为 `anywork`。窗口标题、系统入口与应用界面按各自语言环境显示对应名称。应用图标以猫咪原图为基础，保留完整蓝色圆角主体、移除外围留白并将圆角外部设为透明。Flutter 工程与 Dart 包统一命名为 `anywork`，Rust crate 继续使用 `pl-*` 前缀。Linux 发行包（bundle）携带桌面入口文件与图标，窗口图标内嵌于原生启动器（runner）；用户可显式运行发行包中的桌面登记脚本将当前程序登记至 XDG 用户应用目录，构建与运行过程不自动修改宿主桌面环境。

## 19.1 架构与宿主边界

### 会话排序与前端分层架构

会话列表在当前分组及筛选范围内按最近用户消息时间倒序排列，优先取权威会话的 `lastUserMessageAt`，缺失时回退至 `createdAt`，同秒内按会话 ID 降序稳定破平。用户消息成功受理（含进入排队）后会话自动前移；模型回复、工具执行、运行状态变化、自动标题生成及配置更新均不改变排序。会话列表、分页合并、搜索结果与归档后的候选会话选择共用同一排序规则，不从本地草稿或流式事件猜测时间戳。旧目录记录缺失 `lastUserMessageAt` 时按创建时间排序，待下一次成功发送后更新，不扫描历史记录回填时间（迁移与元信息保存边界见 [17](./17-studio-storage.md)）。

桌面发行包同时携带预构建的 Rust 桥接动态库与独立远程辅助进程（helper）资源；资源的定位与消费属于 Rust 宿主边界，不由 Dart 层加载后传输（分发、校验与工作进程生命周期遵循 [22](./22-ssh-remote.md)）。

`anywork` 是基于 Material 3、`Riverpod`、`go_router` 与类型化 FRB 构建的 Flutter 桌面应用：
- **状态与依赖隔离**：Rust 持有业务权威事实；每个应用实例的 `AppGraph` 持有独立的纯 Dart `anywork_client`、FRB 适配器（adapter）与展示所有者。Client 统一管理资源、只读镜像、草稿与业务命令；`Riverpod` 仅适配只读观察，连接器（Connector）将不可变属性（props）与意图回调传递给视图（View）。Client 不依赖 Flutter、`Riverpod`、FRB 或 `Ref`，业务视图模块（`features/**`）不导入 FRB、适配器、传输层或 Client 私有实现（状态契约见 [25](./25-frontend-state.md)）。UI 不直接读取 SQLite、智能体 TOML 或技能文件；Flutter Web 仅用于演示模式集成验收，不伪造原生账号、文件系统或进程能力。
- **FRB 生成边界**：`lib/src/rust/` 为 FRB 独占的生成目录，不存放手写聚合导出（barrel）、转发函数或业务默认值。适配器需汇集类型化导出时，在 `infrastructure/frb/` 下维护手写导出入口并直接引用当前生成模块，不为已退役的接口保留转发。统一生成入口负责重建完整的 FRB 输出集合并清理已删除 Rust 模块遗留的孤儿产物，生成一致性检查同时比对文件内容与文件集合，任何生成失败必须原样透传错误。
- **原生文件选择与附件拖放**：附件拖放直接消费平台插件的类型化文件条目，仅接收常规文件，不将目录、纯文本或 URL 解释为本地附件。异步拖放回调持有当次传输资源的借用期，所有文件读取及 Rust 附件草稿准入必须在回调返回前完成；后续提交仅消费已入库的草稿，不持有平台临时路径或外部句柄。文件与项目目录选择由桌面原生宿主持有，分别调用 Windows 原生文件对话框与 GTK 原生文件选择器；Flutter 通过平台通道提交扩展名筛选条件并接收本地路径，用户取消时返回空选择，原生失败按平台错误传播。宿主不读取文件内容，附件校验与复制仍由 Rust 草稿准入逻辑负责。
- **渲染后端策略**：Windows 原生宿主显式选用 Skia 渲染后端，以规避 Impeller GLES 在高分辨率大窗口下的栅格化延迟，且在 `debug`、`profile` 与 `release` 构建中保持一致。未来若评估切回 Impeller，须在同机普通窗口、最大化、还原及大尺寸窗口下完成帧耗时及实际显示、输入、滚动结果验证；升级 Flutter 版本时须同步核对原生渲染后端配置接口。
- **单向数据流与验收驱动（Driver）读取**：Client 各领域归约器是 Dart 只读镜像的唯一写入者；FRB 适配器仅负责协议转换、传输与原生句柄收束。命令回执、镜像观察、生效与持久化分别表达，命令成功后不通过回读聚合状态补齐事实。组件（Widget）仅负责展示与发出意图，Flutter Driver 读取同一 Client 的可见投影与诊断信息，不维护平行业务状态。

### 窗口关闭、系统托盘与单例激活

Windows 平台上点击标题栏关闭按钮、`Alt+F4` 或任务栏关闭窗口执行“隐藏到系统托盘”而非应用退出：当系统托盘图标真实可见时，原生宿主仅调用 `ShowWindow(SW_HIDE)` 隐藏窗口，不调用 `begin_runtime_exit`、`shutdown_runtime` 或 `AppGraph` 收束，不启动退出倒计时，也不取消正在执行的轮次、工具、模型流、订阅或持久化保存。窗口隐藏期间 Flutter 可暂停帧渲染调度，但 Dart Isolate、FRB 订阅与 Rust 运行时继续运行；恢复窗口后直接展示最新权威投影，无需重放或补发请求，待确认的用户交互亦保持等待状态。托盘图标支持左键单击或双击恢复窗口，右键菜单提供「显示主窗口」与「退出」；仅当点击托盘「退出」、操作系统会话结束或托盘不可用时关闭窗口，才进入应用退出协调器。Linux 平台暂不实现托盘隐藏，保留既有 `delete-event` 直接关闭入口。

Windows 与 Linux 桌面端均以 Studio 数据根目录（Studio home）为单实例运行边界。重复启动进程在创建 Flutter 引擎前向原实例转发窗口激活请求并立即结束自身；指定不同数据目录的实例允许并行运行。Windows 复用托盘的窗口恢复入口，Linux 通过 `GApplication` 的 `Activate` 信号呈现已有 `GtkWindow`。若原实例首帧窗口尚未就绪，则合并保留一次激活请求并在首帧渲染后执行，不重建 `AppGraph` 或重发业务请求；若原实例正在退出，则仅显示原退出窗口，不取消退出流程也不自动重启。入口发现与窗口激活共用 10 秒总期限；文件锁已释放时新进程可重新竞争，仅获锁者继续启动。转交成功返回退出码 `0`；若锁占用者为服务端进程、其他桌面会话、无响应进程或激活转交失败，则记录诊断并静默返回非零退出码，不弹出第二个窗口或占用报错页。桌面重复启动在原生入口直接完成激活转交，服务端模式则保留类型化 `instanceBusy` 错误。

### 应用退出与桥接关停协同

应用退出必须等待 `AppGraph` 幂等收束及类型化关停（shutdown）完成，并回收 Flutter、DTD、MCP、LSP 与本地子进程树；远端辅助进程在 GUI 退出或 SSH 断开后由心跳租约自行清理，窗口不等待远端退出确认。应用退出设有单一总期限 30 秒，由原生宿主在首个退出请求前独立启动守护线程计时，重复退出或重试均不延长；到期后强制终止进程并返回退出码 `1`，正常完成返回退出码 `0`。

桥接层以 `BridgeShutdownReport`、`BridgeShutdownOutcome`、`BridgePendingPersistence` 与 `BridgeShutdownIssue` 镜像运行时的类型化关停报告（结构定义见 [18](./18-studio-state.md) §18.5.1）。应用退出前，Dart 侧与原生桥接按以下顺序协同：
1. **早期退出信号（`begin_runtime_exit(remaining_ms)`）**：与退出闸门的锁闭原子地观察已发布运行时，固定同一首次绝对期限，在已安装的运行时上同步锁闭领域准入，并向所有独立在途所有者（含活动轮次、模型调用与工具执行）广播一次取消信号；同时预先广播桥接侧内容流订阅与更新操作取消，将真实错误汇入同一收集器。此步骤仅发送信号，不触发初始化、不执行阻塞停止或汇合、不关闭会话、不发布 `Stopped`。
2. **Dart 侧有界外部取消**：Dart 有界完成并观测自身持有且桥接层无法代持的外部取消（产品流、会话流、更新操作与关机进度流），将任何未确认的类型化 `BridgeShutdownIssue` 随剩余预算 `remaining_ms`（上限 28 秒）一并传入 `shutdown_runtime(remaining_ms, external_issues)`。关机进度流使用自持令牌，不受早期广播提前终止，并在运行时收束前完成取消确认。
3. **统一运行时关停与诊断收尾**：桥接层并入自身订阅与更新取消结果，与运行时阶段共用同一编排、同一首次绝对期限及同一 `Clean` 前置条件。桥接侧彼此独立的所有者组并发观测，任一组汇合阻塞均不影响其他组取消。诊断收尾独立于运行时初始化状态，`finish_shutdown_diagnostics` 在安全释放前或退出前调用，确保运行时未安装或安装失败时也能回收诊断资源。订阅取消仅在桥接层仍可用时调用原生取消接口，严禁在 `RustLib.dispose()` 之后调用任何 FRB API。

启动失败的错误码集合（如 `cancellationTooLate`、`overloaded` 等）在 Dart 侧通过穷尽 `switch` 映射为稳定的本地化文案与诊断编号，不因未知变体抛出解析异常而掩盖原始类型化错误。关停失败时不阻塞在用户确认弹窗或提供无限重试，而是将失败阶段聚合成带 `code` 与 `correlation_id` 的脱敏诊断后继续退出流程。更新安装的空闲判定与关闭启动属于同一原子步骤：运行时在任何取消前完成原子空闲检查，随后桥接层通过注入同一严格编排的适配器钩子解除并等待自身订阅；若会话正忙，则既不取消订阅也不改变运行状态。

### Markdown 排版与上下文状态栏

时间线 Markdown 渲染采用 `gpt_markdown` 的现代解析管线与内置自动链接（autolink），不传递旧版 `components` 或 `inlineComponents` 参数；自定义引用块、图片与超链接通过构建器（builder）扩展。外部链接点击须通过 HTTP(S) URL 校验，远程图片仅允许 HTTPS 且须由用户主动点击加载；图片替代文本（`alt`）从结构化 Markdown 节点读取。

Markdown 阅读排版以 [VS Code Markdown Preview](https://github.com/microsoft/vscode/blob/main/extensions/markdown-language-features/media/markdown.css) 为主要基准，并以 [Zed Markdown Preview](https://github.com/zed-industries/zed/blob/main/crates/markdown/src/markdown.rs) 交叉核对，采用通用文档样式而非独立卡片化设计：
- **标题与段落节奏**：标题采用相对正文字号的递进字级，`H1` 与 `H2` 带细分隔线；正文、段落与块级元素保持自然阅读节奏，避免默认块间空行与额外内边距重复叠加。自定义标题作为块级选择单元参与外层连续文本选择，不通过独立文本编辑控件隔离标题或打乱跨段选择复制顺序。
- **列表、代码与表格**：列表续行与条目正文左对齐，条目间距小于段落间距。行内代码以等宽字体与浅底色区分，避免粗重描边打断中文阅读，不通过插入额外空格、换行或切分选择片段的布局占位改变原文复制结果，长代码片段随正文自然换行。引用块采用左侧竖线、低对比背景、弱化文字与适度内边距，保留内部多段与嵌套结构。代码块采用简洁低对比容器、常规内边距与小圆角，语言标识不使用强调色顶栏；表格采用清晰表头与细分隔线，保留文本选择与长行横向滚动。上述规则统一覆盖消息、推理与计划等阅读表面，颜色继承现有主题角色。

状态栏上下文指示器仅显示紧凑图形进度轨，不常驻显示百分比或词元数字：
- **进度计算与未知占位**：图形填充比例取运行时已用词元数除以最终自动压缩阈值；悬停详情展示精确百分比及超出阈值状态。当阈值未知（含非正值）时，图形仅显示中性底轨，详情及无障碍读数以 `—` 占位，不报告虚假的 `0%`；当阈值有效且用量为零时正常显示 `0%`。进度读数本身不宣称上下文压缩已经发生。
- **立即压缩操作**：上下文悬停详情的进度条旁提供「立即压缩」按钮，通过 Client 动作请求当前会话执行一次强制压缩，复用自动压缩的准备、提交、计量与持久化路径，不发送隐藏用户消息。该按钮仅在会话空闲且存在可压缩历史时可点击；执行期间展示进度并防止重复触发，失败保留错误提示，成功后刷新权威上下文读数。
- **上下文详情分区**：顶部展示已用词元、压缩阈值、百分比与距阈值余量，下方分区展示模型身份及最大上下文容量、会话累计输入与输出词元、调用次数、缓存统计以及按币种分组的费用与缓存节省金额。当有效上下文窗口与模型最大窗口不同时分别展示；未知值保留 `—`，无模型最大能力事实时不以有效窗口冒充。窗口与阈值统一消费请求绑定的权威投影（见 [18](./18-studio-state.md#188-产品投影与观察)），不在前端按账号硬编码或回填历史。

## 19.2 动态工作模式与工作流状态

新会话默认选用 `mode.simple`。输入区（Composer）的模式选择器读取工作模式目录快照，以稳定的 `modeId` 作为标识、`displayName` 作为显示文案，不硬编码 `Simple` 或 `Task` 枚举。工作模式切换命令仅在根会话空闲且无待处理交互时可用；旧活动运行实例由运行时归档，被拒绝的切换由权威快照恢复界面显示。工作模式不出现在普通技能设置或按需调用列表中，两个内置工作模式不可删除或覆盖（见 [11](./11-thread-mode.md)）。

起始页与已有会话的模型、推理强度及会话设置遵循以下规则：
- **模型与推理强度选择器**：起始页选择器展示 Client 起始草稿的当前意图（按逻辑草稿与项目身份保留，不随路由观察者销毁而丢失）；未显式选择时读取当前草稿工作模式在 `modeModelRoutes` 中的默认值，切换工作模式立即展示该模式最后保存的路由选择（草稿与权威状态的组合规则见 [25](./25-frontend-state.md)）。提交首条消息时在首次 `await` 前冻结完整路由，不采用“先改全局默认设置、等待响应、再读缓存构造会话”的方式。已有根会话的选择器仅读取会话运行时中的 `modelRoute`，修改时同时更新当前会话与所属工作模式的默认路由，不影响其他会话；子会话继续只读展示创建时冻结的配置模板路由。当路由不可用（`unavailable`）时保留原选择项并显示告警图标，点击告警展示运行时提供的不可用原因（无具体原因时展示通用说明），不在 Flutter 侧自动改选其他账号或模型。根会话非空闲时不打开模型或推理强度菜单，点击时提示当前状态不可切换的原因；须观察到当前轮次真正结束且权威会话快照确认空闲后才恢复可切换状态（活动工作流本身不限制模型切换）。
- **选择器权威同步约束**：选择器触发器文案与弹出菜单的选中态必须源自同一个权威事实并同步变化。工作模式、推理强度或模型切换完成后，主界面无需退出或重新进入任何页面即可立即反映新值；严禁依赖页面跳转、菜单开关或浮层重建来触发显示更新（见 [18.11.1](./18-studio-state.md#18111-thread-身份的单一来源)）。
- **选择器锁定与可见原因**：能否配置会话（工作模式、模型、推理强度）与能否提交相互独立。未选项目或暂不可提交时，模型与推理强度仍可先定下草稿路由；工作模式随项目草稿保存，无项目时明确禁用并提示先选择项目。被锁定的选择器必须给出可见原因（就地提示或明确的禁用外观），同排选择器遵循同一规则，不得出现看似可点却静默吞掉点击的控件。
- **会话设置菜单（工作区与子智能体分发）**：起始页附件按钮旁提供「会话设置」标准菜单，集中收纳会话工作区模式与子智能体分发选项（对话/任务模式、主模型与推理强度保留独立快捷入口）。会话工作区可选 `local`（默认，直接使用项目目录）或 `worktree`（从项目 Git 仓库 `HEAD` 新建独立工作树）；本地与 SSH 项目均提供 `worktree` 选项，若项目非 Git 仓库、缺少 `HEAD` 或远端不可用，则在提交时通过类型化错误就地反馈并保留草稿。子智能体分发模式可选“跟随默认”“固定配置模板”或“自动选模”，自动选模偏好可选“跟随默认”“经济”“平衡”或“快速”（固定模式下偏好标明不生效但保留所选值），触发器展示如“自动 · 经济”的紧凑有效摘要及悬停提示。已建会话的工作区模式、分发模式与分发偏好均为只读，直接消费权威目录事实。设置页另提供新会话默认分发模式与自动偏好配置（默认为固定配置模板、平衡偏好），三种偏好的简要说明对应 [12](./12-collaboration.md) 的提示词语义，不承诺最低价格、最高质量或最快速度。
- **首条请求环境准备卡片**：起始页提交首条提示词后，输入框上方的欢迎区切换为环境准备卡片，沿用暹罗浅色主题、细描边与眼眸蓝活动指示。卡片按“检查项目 → 准备工作区 → 初始化会话 → 提交请求”展示各阶段状态，工作树准备阶段额外显示真实的仓库解析与物理创建子阶段，不显示估算百分比；折叠详情展示项目名称、冻结的工作区模式以及已分配的实际路径与分支（支持换行与选择复制）。准备期间用户仍可继续编辑后续草稿；创建成功后直接进入对话视图，不设最短展示停留时间，也不在时间线中遗留准备卡片；创建失败则停止活动指示并在原位保留失败阶段、原因、提示词与附件草稿；结果未知时明确提示尚未确认且不自动重发。
- **工作流状态栏投影**：会话运行时快照仅向 GUI 暴露状态栏所需的通用工作流投影（`mode`、`run`、`revision`、`lifecycle` 与当前阶段名称）。未启动的图工作模式显示“未开始”，`Simple` 模式仅显示模式名称；GUI 不展示完整状态图、转换历史或人工阶段跳转入口，也不执行本地乐观转换。

## 19.3 通用交互与计划确认

输入区停靠面板（Composer dock）统一响应 `UserInput` 与 `ToolApproval` 两类交互。任务计划由 `plan_submit` 工具经固定计划状态机发起，在协议层仍属于通用 `UserInput`；GUI 的计划只读展示在待确认（pending）期间从稳定 ID 为 `plan_confirmation` 的唯一问题派生，批准后则从运行时快照的计划投影派生，两个来源严格互斥，不新增交互类型、持久化状态或第二套续跑机制。常规澄清提问仍由 `request_user_input` 工具发起并使用分步问答面板（计划摘要卡、右侧详情面板、批准后状态栏入口与替换式反馈栏的完整 UI 契约见 [13](./13-plan.md)）。

`plan_confirmation` 是计划确认专用的问题标识，普通提问必须在生成交互记录前拒绝使用，不能等到界面投影时才校验。旧普通问题若误用该标识，原历史仍按普通问答事实保留供只读核查，待决交互读取明确报告结构错误；不将其猜测为计划，也不通过计划入口决议。

普通提问在时间线历史中展示为只读问答回执，不重复渲染可提交表单：
- **折叠与展开形态**：回执默认折叠，已回答状态以完成图标、「用户已回答」标题、问题数量与右侧对齐的展开箭头构成紧凑头部（整行头部均可点击切换展开态），辅助行提供简短问答摘要；展开后按原问题顺序逐组呈现题目标题、完整问题正文与「你的回答」。选项回答使用浅色回执标签，自由文本保留原始换行并支持选择复制，多道题目之间以细分隔线与统一缩进区分。
- **权威状态与隐私保护**：回执仅消费工具条目携带的类型化问答投影（见 [18](./18-studio-state.md) §18.8），按原工具身份独立成行，不藏入普通活动组。仅权威 `resolved` 状态显示「用户已回答」；待回答、已取消与缺失回答分别显示各自真实文案，不凭工具执行成功推断用户已回答。标记为敏感的问题回答统一显示「敏感回答已隐藏」，摘要、展开正文、复制内容与无障碍语义均不包含原始敏感值。
- **子任务交互的主会话投影**：子智能体的提问与安全审批统一在主会话呈现，卡片标注来源成员并原样转发原始请求身份、版本与类型化决定；子会话的计划请求按其自身诊断事实保留，既不进入主会话的可决议投影，也不能经该投影决议。子会话页面只读展示，不提供答题、审批或提交控件。受理只表示请求已被接收，界面以权威回执确认后才推进卡片状态；冲突或过期决定保留原卡并显示原因。
- **计划确认专用回执**：计划确认复用同一类型化历史通道，但渲染为计划专用回执而非普通问答表单：主标题表达批准、请求修改或取消决定，副标题呈现计划标题，展开后显示完整用户反馈；待确认期间不在时间线重复渲染计划历史卡。

## 19.4 智能体（Agents）设置

智能体设置页是唯一的子智能体配置模板（Profile）管理中心；主智能体的模型与推理强度在会话界面配置，不在此页重复展示。页面分区展示系统子智能体与用户自定义子智能体：
- **系统子智能体**：名称、用途说明、系统指令与固定工作区模式均为只读且不可删除；允许配置启用开关（`enabled`）、路由（`account_id` / `model_id`）及由模型声明驱动的推理强度（`effort`）。
- **用户自定义子智能体**：按单个 TOML 文件原子创建、保存或删除，支持选择四种工作区模式（其中 `review` 模式表示工作区在派生时跟随被审智能体，须配合 `reviewTargetAgentId` 使用）。无效配置文件以独立诊断条目展示，不阻断页面其余配置项。保留工作树（preserved worktree）恢复区展示修订号、分支、基准与头部提交、未提交变更文件预览及显式清理操作。运行期智能体目录与配置模板目录严格分区；所有变更均携带设置修订号执行 CAS 校验，并以返回的权威快照原子刷新界面（见 [12](./12-collaboration.md)）。
- **浮层交互与路由稳定性**：智能体设置页中的模型选择弹层与推理强度选择弹层均归属于当前设置页；打开、选择或关闭锚定浮层仅改变浮层自身可见性并更新当前智能体配置投影，不触发设置标签页切换、`TabBarView` 重建或返回聊天页的页面级路由转场。
- **界面文案本地化规范**：智能体导航、配置页、工作树恢复及配置模板详情中的固定界面文案必须跟随 Studio 语言环境，由统一本地化目录（l10n catalog）提供。配置模板 ID、`account_id`、`model_id`、`effort`、工作区模式持久化枚举值，以及分支、路径、提交哈希、工作树状态与诊断数据均保持权威原值。中文界面产品术语统一使用“智能体”，`subagent` 统一译为“子智能体”，不混用“代理”、`Agent` 或 `Subagent`（`ssh-agent` 等操作系统专有技术概念除外）；常规概念不夹杂英文单词，MCP、LSP、SSH、HTTP、URL、API、Git、OpenAI、DeepSeek、TOML 等标准缩写与产品名保留原文。

## 19.5 联网搜索设置

通用（General）设置页将 OpenAI Web Search 与 DeepSeek 联网搜索呈现为两张独立配置卡片：
- **OpenAI 搜索卡片**：保留搜索模式、上下文大小、域名过滤与地理位置等配置项，文案明确标识仅作用于 OpenAI 搜索。
- **DeepSeek 联网搜索卡片**：仅提供「联网搜索」与「网页抓取」两个独立开关，不展示结果条数、正文开关、搜索模型或官方未承诺的缓存、域名、位置及上下文选项，也不维护本地输入草稿。卡片展示所选 DeepSeek 模型账号，并说明系统优先使用其他可用搜索后端，仅当其他搜索未配置、不可用或调用失败时才由 DeepSeek 兜底，且搜索与网页抓取均按请求次数计费。

两张卡片统一消费桥接层返回的 `configured`、`effective`、`availability` 与 `account` 状态（官方 DeepSeek Responses 路由显示账号不支持，可搭配 OpenAI 独立搜索使用）。每个开关各自提交一条携带设置 CAS 修订号的类型化命令，并以返回的完整权威快照原子更新界面，不在前端推演后端仲裁、凭据有效性或模型能力（仲裁契约见 [20](./20-config.md)）。

## 19.6 会话标题与侧栏详情展示

### 智能体切换菜单与自动标题更新

子智能体创建时以调用方传入的 `taskSummary` 作为初始标题。会话顶栏智能体切换菜单的每一行均显示权威会话标题（根会话行同样显示自身标题，无标题时回退显示角色标签或空态），采用单行渲染并在悬停时展示完整文本提示；第二行展示角色名称与实际模型名称或 ID（账号与推理强度在紧凑辅助信息或悬停提示中区分），运行状态占据独立列，固定宽度的选中指示列确保各行右边缘严整对齐。子会话时间线完整展示主智能体下达的初始任务、补充消息与子智能体的阶段性回复，切换或重开会话后保持一致。

子智能体的模型信息取自运行时发布的冻结路由摘要（固定配置模板与自动选模模式口径一致），修改当前配置模板不会改变已有子智能体条目；无法解析模型展示名时保留模型 ID，旧历史记录确无绑定时显示“模型未记录”，不读取当前配置模板猜测补齐。打开智能体列表不激活全部子会话，也不预加载时间线、评价正文或模型资料。菜单成员与计数来自当前根会话的权威智能体目录（涵盖未驻留、已结束与已关闭的子会话），不受侧栏会话分页窗口或当前热会话集合过滤；仅在用户点击某个成员后才按需打开对应会话（数据来源边界见 [25](./25-frontend-state.md)）。
智能体切换菜单同时是子会话的唯一停止入口：每一行只为确有待处理、等待准入或运行中执行的成员提供停止按钮，绑定该行的会话身份与执行编号，点击不触发行选择、不打开子会话、不发送消息；受理后显示「正在停止」并禁用重复点击，中断后显示「等待主智能体调度」，不提供继续或消息入口。成员数量只统计未关闭成员，已关闭成员不计数但仍可在菜单中查看。子会话页面保持只读，用户对子任务的新要求统一在主会话表达，由主智能体调度原成员。

新根会话首条提示词提交后，侧栏与会话页眉立即显示提示词摘要作为临时标题；后台 `Explorer` 模型生成的最终标题通过 `ThreadDirectoryChanged` 增量事件更新，两处始终从同一个状态投影渲染，界面不展示独立的“正在命名”状态（见 [18](./18-studio-state.md) §18.6）。

### 侧栏会话行悬停提示与操作菜单

侧栏会话行（Thread tile）在悬停时提供详情提示与行内快捷操作（仅含置顶与更多菜单）：
- **重命名与归档**：重命名对话框提交类型化重命名命令，空标题及超过 80 个字符的输入在前端与运行时两侧双重拒绝；归档操作从更多菜单进入确认对话框，确认后提交类型化归档命令。项目或会话存在恢复诊断问题（recovery issue）时，诊断详情优先于普通名称提示。
- **只读提示与菜单解耦**：侧栏只读悬停详情使用 Material `Tooltip.richMessage`，提示浮层忽略鼠标指针、不抢占输入焦点、不包含复制按钮等交互控件；完整项目路径与会话工作区路径通过各自的更多菜单复制。项目与会话操作菜单独立使用 `MenuAnchor` 与 `MenuItemButton`，并收敛自身尺寸约束，避免长路径横向撑满窗口。提示显隐、菜单开合、键盘导航与焦点恢复完全交由 Flutter 框架处理，不维护自定义悬停定时器或互斥状态机。
- **打开方式二级菜单与工作树图标**：会话更多菜单将 VS Code、Zed 与终端入口收敛为一级「打开方式」`SubmenuButton`，二级菜单使用 `MenuItemButton` 展示单行应用名称与宿主原色徽标，并与顶栏「打开工作区」菜单复用同一徽标组件。侧栏会话行只读消费会话的工作区模式：`worktree` 会话在右侧固定状态区显示工作树图标及本地化说明，`local` 会话不显示该图标；会话级打开操作与路径复制均采用权威会话工作区路径 `workspacePath`（见 [18](./18-studio-state.md) §18.9）。

## 19.7 视觉主题与布局

### 启动等待页与存储诊断横条

应用启动初始化及主界面快照尚未就绪期间，窗口居中展示暹罗猫双爪交替敲击键盘的透明背景循环动画、当前语言的应用名称与加载指示（系统开启“减少动画”时展示静态帧）。真实初始化阶段由启动专属进度流推送，就绪后直接进入主界面，不设最短停留时间。主界面就绪后，后台继续运行工作区恢复检查：智能体设置页显示局部检查进度，会话页仅在检查失败时显示原因与重试入口，未完成检查前不显示“没有问题”。首屏就绪后若已有选中会话，则自动打开该会话并加载首个历史分页窗口。

常规持久化排队与后台落盘不显示诊断横条；仅当发生保存降级、恢复中、阻塞或因存储压力暂停新推理时才展示诊断横条。横条中的「重试保存」与「继续」为两个独立动作：「重试保存」仅将积压事实写入磁盘，不自动恢复模型或工具执行；硬故障重试成功后会话仍保持暂停，唯有后端将 `ThreadStorageState.canResume` 置为 `true` 时「继续」按钮才可点击，且点击后后端仍会按故障代次与目标持久化水位执行二次核验。短暂存储压力（队列或字节预算触顶）在安全间隙自动等待并恢复，不显示「继续」按钮。

### 暹罗浅色主题色板与排版规范

主页、会话、详情面板与全部设置页固定采用统一的暹罗浅色主题（奶油底色、海豹棕主操作、眼眸蓝点缀），不提供深色主题或跟随系统外观选项。

会话视图采用居中阅读列布局：时间线、活动栏与输入区共享同一中心轴，最大宽度为 `1040 logical px`。侧栏展开时以剩余主内容区为中心，侧栏隐藏时以完整主内容区为中心；窄窗口下按可用宽度对称收缩留白，不为滚动条显隐改变内容宽度。助手回复正文直接使用阅读列内的可用宽度；用户消息与父智能体消息采用右对齐、最大宽度 `680 logical px` 的紧凑气泡。主时间线滚动条在静止时隐藏、滚动时显示、停止后按 Flutter 原生机制淡出。

字体选择遵循宿主平台约定：Windows 英文界面使用 `Segoe UI`，中文界面及中文缺失字形回退使用 `Microsoft YaHei UI`，其他平台保持系统默认字体；代码块、行内代码、命令、技术路径、JSON 与工作流源码编辑区以及代码式工具输出统一使用随包分发的 `JetBrains Mono` 等宽字体。

### 原生 Material 组件复用与侧栏响应式布局

按钮菜单、设置选择字段与状态悬停详情统一复用 Material 官方组件：交互菜单使用 `MenuAnchor` + `MenuItemButton`（触发按钮绑定 `MenuAnchor.childFocusNode`），表单下拉字段使用 `DropdownMenu`，只读状态悬停详情使用 `Tooltip.richMessage`，文本输入使用 `TextField`，设置导航使用 `TabBar` 或 `NavigationRail`，焦点与快捷键遵循官方 `Focus`、`Shortcuts` 与 `Actions`（参考 [MenuAnchor.childFocusNode 契约](https://api.flutter.dev/flutter/material/MenuAnchor/childFocusNode.html) 与 [FocusNode 生命周期约定](https://docs.flutter.dev/ui/interactivity/focus#best-practices-for-creating-focusnode-objects)）。弹出菜单依据触发控件真实布局定位，打开期间随权威状态实时刷新内容，模型选择菜单打开时将当前选中项滚入可见区域，账号分组标题与模型条目按真实内容高度自适应布局。

主界面侧栏采用项目优先结构，项目下嵌套根会话：
- **宽度调节与响应式抽屉**：侧栏默认宽度 `336px`，桌面端支持在 `300–440px` 范围内拖动调节（分隔条支持聚焦，左右方向键按 `16px` 步进调整、`Home` 键恢复 `336px`，并为对话区保留至少 `600px` 宽度）；窗口宽度小于 `960px` 时自动切换为保留完整目录树的覆盖式抽屉。宽度变更在键盘释放、失焦或拖动结束时通过 Client 串行通道提交至设置权威状态，旧代次提交完成不会覆盖更新代次的拖动草稿。
- **项目归档与添加向导**：归档必须经由确认对话框触发，文案明确提示该会话树在 `worktree` 模式下的工作树及其未提交、未整合内容将被一并删除。添加项目向导支持选择本地目录或 SSH 远程目录：SSH 连接先探测免密认证，仅当免密失败且服务端公布密码类认证方式时才弹出密码输入框；若服务端仅接受公钥，则就地提示需配置密钥或 `ssh-agent`（见 [22.4](./22-ssh-remote.md#224-凭据路径与持久化)）。SSH 服务器行常驻「重新连接」按钮，操作状态按服务器实例隔离，结果以桥接层返回的权威快照为准。

## 19.8 设置页组织与 Dart 展示边界

### 页面观察生命周期与无轮询原则

产品事件流按 [18](./18-studio-state.md) §18.2.1 的类型化主题与作用域组合，由 Client 领域所有者统一管理订阅与归约；统计模块则采用同篇 [§18.2.2](./18-studio-state.md#1822-统计观察与不可变读取) 的独立 `StatisticsRepository` 与强类型推送流（Feed），不经全局 Client 主题分发。主外壳（Shell）观察导航目录、公共配置与诊断摘要；设置外壳仅观察导航与公共配置，各设置标签页通过连接器按需声明统计、智能体模板、MCP/LSP 服务、技能或账号用量的可见观察需求，标签页隐藏时可释放对应观察租约。`Riverpod` 观察者的销毁、暂停与重建仅取消自身观察订阅，不关闭当前会话内容连接、不清空输入草稿或取消在途命令。

仅在初次尚无数据时展示骨架屏或整页等待；后续刷新、重连与错误均保留已有内容、滚动位置、筛选条件与编辑草稿，仅展示局部进度或错误提示。模型统计落盘期间的 `pending` 暂态不渲染页头提示行，避免插拔导致页面跳动，仅用于抑制过早显示“暂无调用历史”；`gap` 与 `readFailed` 等稳定异常则在固定页头轻量展示。启动与日常刷新均无 GUI 定时轮询。

### 原生账号（Native）与 ACP 接入管理

账号设置采用统一的“列表 + 详情卡 + 编辑页”结构，标签与入口统一命名为“账号 / Accounts”，模板选择命名为“账号模板 / Account template”：
- **品牌标识与模型压缩阈值编辑**：账号品牌标识仅以模板目录（catalog）下发的 `iconKey` 字符串作为跨层契约，由 Flutter 侧品牌资产注册表（`AccountBrandMark`）渲染白底圆角着色图标，未知或缺失 `iconKey`（如 `openai-compatible`）回退显示名称首字母。账号详情卡的模型列表按来源分组展示在线名单（`online`）、内置默认定义（`bundled`）与用户手动模型（`manual`），并作为上下文自动压缩阈值的唯一编辑入口（支持输入精确正整数词元或一键恢复自动，输入防抖后自动提交，无需进入账号编辑页）。手动模型额外提供经二次确认的删除操作（删除仅移除目录声明，不改写历史调用与账单）。词元与上下文容量在界面上统一采用十进制紧凑格式（小于 `1,000` 显示整数，千级使用小写 `k`，百万级及以上使用小写 `m`，四舍五入保留最多两位小数并去尾零，如 `212.32k`、`1.2m`）。
- **模型启用开关与连接方式覆盖**：详情卡每个模型行提供即时保存的「启用」开关，以及按需查看来源、计费类别、能力、性能样本与最近 10 条评价的资料入口。账号编辑页使用本地不可变草稿，切换模板时通过草稿工厂整体重建表单状态；账号 ID 创建后保持稳定。编辑页不为整个账号提供统一的协议或连接方式开关，而是在支持多传输模式的模型行上提供 `HTTP/WS` 覆盖选择（自定义模型须显式指定协议与模式，并在保存前拒绝 `Chat + WS` 组合）。更新 API 密钥时留空表示保留现有密文。支持在线探测的账号详情卡只读展示目录来源、同步时间与类型化错误，并提示“重启应用可重新同步”，不设手动刷新按钮。
- **ACP（Antigravity）账号准备与认证流**：ACP 与原生账号共用同一个「添加账号」模板选择器（确保常规桌面视口首屏即可看到 Antigravity 入口）。Antigravity 仅支持产品固定 `1.4.1` 版本的自动受管安装，新建表单仅包含账号名称与紧凑服务器准备面板，不提供自定义程序路径、启动参数或本地文件选择。当受管服务尚未安装时，新建表单主操作为「下载并准备」（展示字节进度、阶段名称与取消下载入口，返回页面仅释放观察而不中断后台下载）；准备就绪后主操作切换为「保存并连接」（先保存账号再发起连接检查，检查失败时保留已保存账号并就地提示“账号已保存，连接未完成”）。详情页状态区按权威状态在未检查、检查中、需要登录、登录中、验证中、收束中、认证通过、已取消与失败之间切换，每阶段突出唯一主操作（完整契约见 [28](./28-acp.md)）。
- **机器人设置标签页**：追加在设置导航末尾，提供列表与详情、扫码或已有应用首次配对、可信联系人与群聊授权、会话浏览与消息发送功能，全部通过类型化 Client 交互（见 [27](./27-bots.md)）。

### 统一模型选择器、性能统计与双栏会话状态栏

会话输入区、新会话草稿、系统智能体角色配置与用户智能体模板编辑统一复用同一套紧凑模型选择器组件：选项按账号实例 ID 分组并以账号名称为组标题，模型行仅展示模型名称与输入能力徽标（文本、视觉等能力严格依据目录声明渲染，不从模型名称推断）。切换模型时，推理强度自动归一化为新模型声明的默认值（无显式默认值时取首个候选值，不支持推理强度的模型置空并禁用控件）。

模型性能统计页与状态栏统一以 `(account_id, 配置的 model_id)` 为顶层聚合身份，展示包含首字等待在内的输出吞吐率（TPS，计算规则见 [06](./06-model.md) §6.12），并在顶层汇总下按请求期推理强度（`effort`）展示细分读数。调用历史列表的“模型”列以配置模型为首行；当实际发送模型或上游响应模型不同时，通过缩进箭头 `↳` 与橙色「模型不匹配」徽标分层展示，并提供「仅看不一致」筛选复选框。账号额度查询在账号标签页首次可见时按实例并行发起，逐卡更新结果；DeepSeek 账号余额遵循官方 [`/user/balance`](https://api-docs.deepseek.com/zh-cn/api/get-user-balance/) 语义，按币种独立展示 `total_balance`、`granted_balance` 与 `topped_up_balance`。

聊天主界面采用左侧项目会话栏与右侧主聊天区的双栏布局，底部状态栏左侧放置当前智能体身份、`Auto / Plan` 模式、当前模型与推理强度选择器，右侧放置上下文进度、按币种分组的费用估算以及技能、MCP、LSP 数量（悬停共享同一个只读详情浮层，「更多」菜单在窄窗口下收纳折叠读数并提供已批准计划的只读查看入口）。根会话下的智能体数量、运行状态分组排序与会话切换统一通过顶栏唯一的 `n agents` 菜单表达，底部状态栏不重复展示子智能体列表。

## 19.9 时间线工具过程与完整结果

思考过程、技能加载与工具调用在时间线中默认聚合为折叠的统一活动组（`wait`、`sleep` 与同轮相邻的思考、技能、普通工具一同分组，带类型化问答投影的工具则按 §19.3 独立展示为问答回执）：
- **统一轻量活动行形态**：展开活动组后，所有成员均采用“固定宽度语义图标列 + 次级短文案 + 紧邻文案的展开箭头”单行形态，整体相对组标题缩进一档并辅以低对比竖向引导线；被截断字段的全文读取入口同样采用该单行形态，点击打开 [26](./26-timeline-content.md) §26.2 的详情查看器。成功加载的主技能激活记录与原 `skill_view` 调用配对合并为单条技能行；折叠摘要分别统计工具与技能数量，不重复计数。
- **文件修改、命令耗时与思考耗时**：文件修改摘要单文件显示文件名、多文件显示首个文件名与其余文件数，补丁工具消费后端权威的有界变更文件预览；命令终态摘要展示由创建时间与权威终态时间计算的实际调用耗时；终态思考展示“思考了 X 秒 / 不到 1 秒”的自然耗时文案，纯思考组汇总各思考成员的有效耗时。
- **等待活动展示**：等待工具主文案明确说明“正在等待什么”（如“等待工具完成”“等待子智能体或新消息”或定时时长），展开后按并发来源逐行展示目标摘要、真实状态与等待规则（数据契约见 [18](./18-studio-state.md) §18.8.1）。
- **读取文件与图片媒体展示**：活动组内的 `read_file` 默认渲染为紧凑单行（书本图标 + 状态 + 文件名，悬停显示完整路径）。工具读取的图片（如 `view_image`）默认折叠为图片数量摘要，连续读图调用合并为同一图集摘要；点击后在下方展开 `120×120` 圆角缩略图网格，点击缩略图打开可缩放大图查看器（显示文件名与完整调用路径）。专门的展示类图片工具则使用占满时间线单行的独立大图卡片（最大高度约 `360px`），展示模型说明文案与状态胶囊。所有工具图片均消费权威工具输出中的类型化附件引用，通过 Client 的类型化附件查询接口按会话与附件身份加载字节，本地与 SSH 项目共用同一安全路径。
- **运行时说明**：继续后在上下文边界追加的运行时说明以独立来源渲染为单行说明，不并入原始历史记录，也不提供可展开载荷；无法解码的真实历史记录仍按原始记录展示。两者按条目自带来源区分，界面不从载荷是否为空推断。
- **轮次终态、活动条与无闪烁增量更新**：轮次的失败、取消与预算限制提示从持久化的类型化轮次条目派生并展示在权威位置；重订阅或冷恢复时后端通过 `turnCompleted` 补发最近一条持久化轮次终态（见 [07](./07-streaming.md) §7.2）。输入框上方的实时活动条直接消费类型化 `ThreadActivity`。统一活动组摘要条、实时活动条及任何持续追加的流式文本仅执行原地文本更新，不将动态文本作为组件 `Key` 触发进出场淡入淡出动画，彻底消除高频流式输出时的叠影闪烁。

## 19.10 连续历史阅读

时间线的内容源、实时与历史模式（Live / History）、分页游标与详情读取契约以 [26](./26-timeline-content.md) 为准，Client 所有权与释放规则见 [25](./25-frontend-state.md)。

### 原生列表、布局边界与超长文本分块渲染

- **原生列表与消息构建器**：固定使用公开的 `Chat`、`ChatAnimatedListReversed` 与 `InMemoryChatController`，展示租约持有唯一已加载消息集合；组内字段更新通过标准 `Listenable` 定向通知，不逐帧重建整份行表。实时模式（Live）自然位于反向列表底端；历史模式（History）冻结已显示消息，向前加载更早分页仅做前插而不淘汰另一端，滚轮滚至冻结列表底端不自动切回实时模式，唯有用户显式点击“回到实时”或发送新消息才创建最新小页与新列表代次。
- **视口自适应与无感补齐**：短内容不足一屏时自动逐页拉取补齐；窗口尺寸、换行或折叠状态变化后按真实可用视口重新评估分页需求，但不因此误入历史模式或改变当前阅读位置。
- **超长纯文本 6144 字符测量窗分块**：针对可能长达数十万字符的超长纯文本正文，在固定的完整 **6144 字符测量窗**内按相同样式、宽度、`TextScaler`、文本方向与语言环境选取安全行起点，一次性封存全部可封存前缀（单块长度优先接近 **4096 字符**），尾部不足完整测量窗的部分暂不封存。已封存的稳定分块复用同一个 `Text` 实例，流式追加仅重新布局新增块与尾块；非追加替换或包含从右向左（RTL / bidi）控制字符时清空已封存块并回退为单个 `Text` 实例。各分块按顺序拼接严格等于原文，确保跨块选择复制准确无误。
- **验收驱动（Driver）只读诊断**：Driver 诊断仅读取列表控制器与 Flutter 当前的滚动活动、列表代次、`Live/History` 模式及数据查询状态，不维护可写滚动位置副本；人工验收命令 `cargo xtask manual-gui --scenario tool-scroll` 同时覆盖本地与真实 SSH 项目的图片发送、工具读图、大图预览与惰性行回收。

## 19.11 运行中发送消息与剪贴板粘贴

主会话运行期间用户仍可继续编辑草稿、添加附件并发送新消息：
- **主按钮三态切换与草稿冻结**：输入区仅设一个主操作按钮——运行中且无草稿与附件时显示中性色「停止」按钮，输入内容或添加附件后切换为强调色「发送并继续」按钮，空闲且无内容时为禁用态。输入框获得焦点时按 `Esc` 键可停止当前运行并保留草稿。点击发送或按下未带修饰键的 `Enter` 键（处于输入法组词区间时除外，`Shift+Enter` 插入换行）会在首次 `await` 前同步冻结 `DraftStamp`、文本、完整路由、参数、项目与会话身份及附件 ID 集合，并分配稳定的 `OperationId`；用户随后继续编辑会产生新修订号，旧提交的确认回执仅清理该次提交冻结的值，不会误清用户新输入的文本或附件。
- **停止、继续与在途区分**：运行中点击停止后，清理结束前既不提供继续也不提供提交。按钮与状态文案只从命令板的受理回执和权威执行快照派生：请求在途但尚未受理时保持对应入口的禁用态，不提前显示「正在继续」；继续受理后才显示进行中，失败或结果未确定时保留可重试原因，不重复提交同一操作。
- **剪贴板图片直接粘贴**：当输入区聚焦且可编辑时，按下 `Ctrl+V`、`Cmd+V` 或 `Shift+Insert` 优先读取系统剪贴板图片，规范化为 PNG 格式后经由现有本地附件准入通道进入权威草稿，在输入框上方附件栏展示缩略图预览；剪贴板无图片时保持常规文本粘贴行为。

## 19.12 配置变更命令与选择器投影

输入区与「设置 → 安全」页均不提供权限模式选择，执行策略固定为 `full-access`（见 [04](./04-security.md)）。

账号、默认账号、单个工作模式路由的模型与推理强度、单个智能体角色的模型与推理强度、通用设置与联网搜索各自使用独立的类型化意图（typed intent）；复合编辑页在提交时按实际修改字段拆分为最小命令，共享同一个设置操作通道（operation lane）以满足 CAS 顺序，不将同页未修改控件的旧值重新写回。命令确认的资源通过 Rust 类型化响应或所有者事件帧进入对应 Client 归约器，不在命令成功后回读整棵 `StudioState`。

模型、工作模式与推理强度选择器投影分为 `canonical`、`pending`、`resolved` 与 `unavailable` 四种状态：`pending` 仅提供即时视觉反馈，失败时回滚至 `canonical` 并保留可重试错误提示。快速连续切换（如 `A → B → C`）时，旧操作仅更新自身真实结果，不得清除最新意图 `C` 的待确认覆盖层（pending overlay）。模型选择器的可用性取自活动会话的实时状态，准备请求期间临时借出会话不触发模型不可用告警。

## 19.13 实时投影与局部细粒度更新

UI 的权威只读镜像由 Client 各领域只读模型更新（见 [25](./25-frontend-state.md)），`Riverpod` 仅观察职责内不可变且按值相等的投影，再由连接器交付视图；统计页面则由独立的 `StatisticsRepository`、`ViewModel` 与纯视图组件（View）消费统计领域状态（边界见 [25.13](./25-frontend-state.md#2513-独立统计领域与呈现模块)）。状态栏吞吐率读数（throughput readout）与上下文读数各自使用独立的只读消费者（Consumer）按会话身份观察对应细粒度投影；外壳仅观察路由、工作流与能力等低频稳定字段，防止高频解码吞吐率变化触发整个 `AgentWorkspaceView`、时间线或输入区重建。

吞吐率读数的显示保持由后端权威累计摘要负责（见 [18](./18-studio-state.md) §18.8），前端组件不持有私有速度快照，也不在新模型尝试的早期部分观察到达时清空已有聚合速度。附件草稿准入采用两阶段更新：`admitAttachmentDrafts` 返回后先展示稳定的草稿元数据，随后按相同草稿 ID 异步补齐预览字节（补齐前重新校验项目与会话身份、提交修订号及附件代次）。账号列表卡片仅呈现账号级摘要、额度与模型数量，不渲染具体 `model_id` 清单。

统计模块的架构分层拆分不改变既有界面视觉与交互：完整保留原有的汇总／调用历史布局、宽窄屏自适应切换、筛选控件、文案与诊断身份，不在界面上暴露内部读取分页或来源元数据。`pending` 状态继续不占用可见状态行，`gap` 与 `readFailed` 仍在既有轻量区域展示；刷新期间保留最近有效内容与滚动位置，不因分批物化而短暂闪现空列表。模型、推理强度（`effort`）与模型不匹配（`mismatch`）筛选状态由统计呈现层所有者管理，纯视觉组件仅接收不可变属性（Props）与动作回调；设置外壳仅传递可见性状态，不持有统计快照、过滤规则或原生资源，共用的基础视觉组件也不夹带其他设置领域的状态依赖。

## 19.14 工作模式编辑器

设置页提供独立的工作模式（Mode）可视化编辑器，以模式目录与流程图画布为主工作区，支持流程图编辑、JSON 配置查看、模式参数设置与运行预演。宽屏下按需展开右侧属性面板，窄屏下在画布下方编辑属性。内置工作模式显示只读标识并禁用节点拖动、连线与属性修改，用户可通过复制内置模式创建自定义工作模式。自定义工作流图支持阶段节点与转换连线的增删改查、画布缩放与平移、自环、循环及多后继分支，并在保存前实时展示 Rust 编译器的精确校验诊断。会话状态栏展示当前快照中的阶段名称，若原工作模式已从目录中删除则显示“已删除模式使用快照”。原生画布交互复用 `vyuh_node_flow` 核心组件，画布节点布局坐标不影响运行图逻辑身份。
