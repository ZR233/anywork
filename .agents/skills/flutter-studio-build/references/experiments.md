# 无头实验与验证

所有实验采用同一取证方法；按问题选择最轻载体，不把预览、组件测试、原生应用排成必跑流水线。

## 1. 固定问题与载体

先记录版本、场景、输入、预期变化、实际视口、主题、语言、字号及停止条件。

| 目标 | 入口 | 不覆盖的边界 |
| --- | --- | --- |
| 纯界面调整、局部交互、截图 | `cargo xtask preview-gui --headless --no-devtools` | 不编译 Rust bridge，不创建 Client/AppGraph 或模型服务，不证明业务保存 |
| 确定性布局/交互回归 | 相关 `cargo flutter test --no-pub test/ui/...` | 不证明原生窗口、真实模型及物理进程退出 |
| 模型调用、保存重开、跨层资源 | `cargo xtask manual-gui --preset gui --inspect` | 模拟对端不证明真实供应商，Flutter 内容不覆盖系统菜单或 IME |

预览复用生产 View、主题、本地化及薄合成呈现值，不复制 UI。项目依赖/缓存适配见
[组件预览](widget-preview.md)，原生隔离与平台要求见[原生补充](manual-gui.md)。
专项性能或 OS 生命周期只在需要相应证据时执行，不为了截图构建完整原生程序。

## 2. 准备并启动一次

原生实验从仓库根使用对应 xtask 入口；组件预览按[预览入口](widget-preview.md)准备依赖，
随后可以直接使用官方 Flutter CLI。先核对实际命令的帮助。临时文件使用当前执行会话 scratch，
图片和报告使用 artifacts；工具已有明确输出入口时保持其布局。不要使用其他 Thread 的缓存或端口，
不要占用 `1420`，不要修改用户配置、凭据或正在写入的历史库。

纯界面预览无需 X11/Xvfb。只有原生 Linux 没有显示环境时使用系统 `xvfb-run`；
不使用 `script` 或伪终端绕过原生验收的 stdin 检查。预览的终端输入输出原样交给 Flutter，
实际支持的操作以当前 SDK 为准；退出后仍需核对所属进程。启动、构建、编译分别记录，首次构建等待同一任务，
不因长时间无输出重复启动。官方组件已有能力优先复用，不另造显示或截图服务。

## 3. 发现控件再交互

- 读取当前 Dart MCP/浏览器工具的实际能力和参数；注册本次工作区的 package root。
  Dart MCP 的 stdio 直接使用实际 SDK 的 `dart mcp-server`，不用会向 stdout 打印日志的 Cargo 包装。
- 对 resident/预览先发现属于本次工作区的 DTD，再连接并确认目标应用；原生验收的直接启动
  使用官方 VM Service 连接能力附着本次应用。DTD URI 用于连接 daemon，VM Service URI 用于
  选择/附着应用；不要混用，不连接邻居会话，也不把认证地址提交到 Git。
- 原生 debug 使用官方 Inspector 读取 widget tree，再用实际文本、tooltip、类型或 key 定位。
  同名控件限定业务作用域，动态身份以本次树为准；先滚动入视口，不猜坐标或直接调用 callback。
  后续诊断优先限定已发现的业务子树或 key，避免反复读取整棵树；仅按类型匹配可能命中多个控件，
  此时收窄作用域，不以重复点击补偿查询失败。
- Widget Previewer 不一定注册 Driver extension。按当前实际支持的 Dart MCP 能力及成熟浏览器工具
  检查预览，不为统一工具名称注入原生 bridge、私有协议或第二套测试入口。
- 明确等待可观察状态，不以固定 sleep、重复点击、停止全部动画或无条件重试补偿未确认的导航。
  预览 callback 只证明局部交互；保存必须在原生产品确认 canonical 结果，必要时保存后重开。

## 4. 迭代与取证

先记录操作前状态，改变一个相关输入，再检查真实画面、交互后状态和运行时错误。
预览复用官方热更新；确需真实跨层开发热重载时使用 resident `run-gui --inspect` 及 MCP。
隔离人工验收复用已有 debug native launcher，以真实退出报告证明关闭，不提供 resident 热重载，
也不为其新增 reload 服务。初始化变化按 SDK 限制重启；Rust/FRB/原生变化才经 xtask 构建并完整重开，
热重启不替换已加载动态库。

使用官方 MCP 或成熟浏览器工具截图，取得图片后必须实际打开，检查字体、裁剪、菜单、空态及溢出。
截图注明预览/原生、平台、实际组件约束、主题字号及覆盖内容；纯界面 PR 可直接使用预览截图，
不额外编译 Rust bridge。截图成功、工具成功或无错误都不是业务通过的充分条件。
临时热更新探针恢复后再次核对，不能留下测试文案或第二份生产状态。

## 5. 结束并报告

- 通用隔离原生实验通过 stdin 发送 `done` 请求正常退出；不再重复录入 UI 动作或隐式抓另一张图。
  EOF 和取消不是完成。等待原启动任务终态，校验 `anywork-native-exit/1` 的真实成功退出及
  后代回收；报告缺失、非零退出或强制回收残留都失败，不能只看 Flutter 工具退出码。
- 预览正常退出或取消也要等待，核对所属 Flutter、分析服务、DTD、浏览器退出。
  浏览器工具只释放自己的连接不等于启动者已回收浏览器；不使用无差别 `pkill`。
- Linux 进程指纹以 PID 与 `/proc/<pid>/stat` 的 starttime 关联原实例，读取前后核对身份。
  `/proc/<pid>/exe` 使用 readlink（Dart 为 `Link.target()`）保留链接原值，不要求其目标能
  canonicalize：memfd 和已解除文件链接的映像仍可正常运行。读取错误须记录为未知或明确的
  采样竞态，不能当作退出；只有原 PID/starttime 确认不存在或已被新身份复用才结束原实例观察。
  只观察本次拥有的进程树，不把旧 PID 对应的新进程当作清理目标。
- 报告实际版本、命令、场景/预期与结果、图片和日志位置、错误、未覆盖项及回收结果。
  分开说明功能通过、视觉核图、持久化、性能和资源关闭，不把工具 exit 0 当成人工批准。
  显示编号和端口可能被后续实例重用，按原启动身份、实际进程及本次显示授权关联回收证据，
  不因相同编号再次出现就终止另一个实例。
- 超时或失败保留原始错误及已取得证据，不通过改预算、减负载或重放有副作用动作掩盖失败。
  可复用经验写回项目技能；一次性截图、日志、URL、数据和临时脚本不进入源码或技能资产。
- PR 图片按根 `AGENTS.md` 上传为附件，回读正文并核对实际图片；本地路径不是交付链接。
