# Rust 错误与验证

## 1. 错误服务调用方决策

可恢复失败返回具有明确语义的 `Result` 或 `Option`，保留转换、重试、回滚与报告所需信息。不要用 `String`、`()`、panic 或日志代替业务错误。

公共错误遵循[类型与接口](../../rust-api-design/references/types-and-interfaces.md)：可以定义领域错误，也可以有意采用并精确重导出合适的第三方错误，不为改变来源增加无意义包装。非平凡自有错误优先使用工作区 `thiserror`；仅有明确依赖成本约束时手工实现。顶层命令和编排可沿用 `anyhow::Result`、`Context`、`anyhow!`、`bail!`，不把 `anyhow::Error` 泄漏到稳定库契约。

外部输入、资源耗尽、并发竞争或用户请求造成的失败必须明确传播；不猜测默认配置或后备路径，不伪造成功。`unwrap`、`expect` 和 panic 只用于测试或有证明的不可恢复内部不变量；一次性初始化也不能以此掩盖可报告的环境错误。`debug_assert!` 不承担发布正确性或安全校验。

## 2. 诊断与失败传播

说明失败的操作、对象和必要阶段，保留结构化原因；面向用户的边界只补充新的决策上下文，避免多层重复同一根因。不要输出凭据、用户内容或无界数据；轮询和重试诊断必须有界。

依赖 `downcast` 分类错误时，验证真实调用链上的每次包装和转换，而不只把原始错误直接传给映射函数。`anyhow::Error` 转为 `Box<dyn Error + Send + Sync>` 的常规转换保留显示信息，但不保证原始类型仍可下转；仅增加末端 `source()` 遍历不能修复上游类型擦除。优先保留领域来源，确需转换时核对当前依赖的官方契约及回溯取舍（如 [anyhow 的装箱转换](https://docs.rs/anyhow/latest/anyhow/struct.Error.html#method.into_boxed_dyn_error)），并从实际边界证明错误分类与安全原因仍然可见，不以解析文案补救。

运行器必须让内部失败传播到最外层退出状态。零退出码、文件存在或成功日志本身不是完整功能证明；必须核对实际目标行为及后置条件。

## 3. 验证方式

错误传播验证经过真实包装与调用链，并核对调用方仍能区分原失败；运行器验证最外层退出状态，跨进程或跨语言错误保留实际来源。旧入口、别名、重复解析和无消费者辅助代码是迁移核对线索。项目命令见 [AGENTS.md](../../../../AGENTS.md)。

## 4. 异步栈溢出定位

`size_of::<Future>()` 只说明 future 状态大小，不等于轮询时的调用栈占用；外层 `Box::pin` 也不会消除各层 `poll` 内的临时值。先用原失败用例和原栈设置复现，再由调试器的调用链、逐帧栈指针差值或当前二进制的函数序言，区分递归与多个大型栈帧累积，不凭类型大小猜测根因。

同一 `async fn` 的重型分支即使当前未执行，也可能增加每次轮询的栈分配。若证据指向该结构，可在原职责内分离按需执行的私有分支，在合适的所有权边界堆置 future；保持句柄、错误、保存顺序和取消责任，不为腾挪栈改成脱离原生命周期的后台任务。

修复后在原栈设置下重验原用例，并补足被拆分分支的成功、失败保全与重试证据。临时加大线程栈只能标作诊断条件，不能冒充修复；不修改测试栈或用易变的 future／帧字节数断言代替真实行为证明。
