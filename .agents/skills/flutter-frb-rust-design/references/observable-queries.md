# 可观察查询

## 先区分交付语义

- 小而可替代的当前态可观察完整最新值；允许合并中间变化。
- 可变、过滤、排序的列表观察固定 query/window 的完整结果，由权威 owner 决定成员、顺序、字段和边界。
- 不可变完成历史保留既有有序交付和实际消费后的确认；不能套 latest-only 语义。
- 一次性详情、导出或不需要持续更新的读取仍用普通查询；不要把所有 Future 改为常驻观察。
- 外部协议按正式能力适配，不为统一抽象增加保存、重放、ACK 或自动重试承诺。

具体 DTO、预算和业务边界由仓库权威设计与源码定义，技能不维护第二份。

## 一个固定需求，一个接纳入口

查询与窗口参数不可变且有值相等语义；改变参数建立新观察，而不是修改在途句柄。
结果应包含完整窗口及实际所属版本，SDK 整体替换本观察的只读模型。
已选实体可按 ID 独立观察，不把查询命中塞进全局缓存以补实体解析。
同一查询保留上次有效内容时同时保留错误状态；旧查询不能冒充新查询 ready。

首读、后续变化与版本必须来自同一个权威切面。先登记通知，再取初值；
值与版本在原 owner 的提交边界内形成，不能 clone 后另读“当前最新版本”贴标签。
恢复必须覆盖这个观察真实需要的窗口，不用首页提升更大旧窗口的有效性。

## 单飞 pull 与真实关闭

优先复用已有需求、只读模型、预算及 pull 生命周期，不建立万能同步框架。
同观察最多一个在途 next，消费者接纳后才发下一个。
在读取前消费已看到的通知，读取期间的新变化继续保持未消费状态；
不能先清 pending，再因 busy 丢掉读取资格。

允许返回本次一致结果后继续取最新值；不能不断丢弃结果直到系统安静，
也不能在页面堆防抖、补查、合并和无限重试来掩盖不完整观察。
用户搜索防抖是输入优化，不负责业务事实同步。

requestClose 同步封闭本观察准入并唤醒等待；close 等待原 open、next、读取与句柄收束。
页面释放自己的显示需求，不停止业务 Session、取消已受理命令或关闭其他需求。
迟到成功、错误和 finally 只结算原目标、owner 与观察身份。
不通过持续读取并灌入无界 Dart 队列冒充端到端有界。

## 窗口与读取成本

完整结果是请求窗口，不是全库。预算内可扩大需求，超过预算使用固定排序边界的 seek 窗口并释放离开范围。
不要把不同切面的可变 page append 后宣称整体最新，也不把稳定 ID 等同于像素位置。
任意文本搜索可能需要扫描摘要；分别度量扫描量、物化候选、结果字节、锁占用与在途资源。
使用已有轻量索引，避免小窗口先 clone/sort 全部匹配集合；不为观察迁移数据库或激活冷业务。

## 最小充分证明

用真实入口和可控交错检验首读、读取中变化、A→B→A、超过首页的恢复及在途关闭。
检查成员、排序、字段和版本的对应，不只检查内部计数或“无异常”。
只补实际变化的边界；已有有效证据不因换阶段失效，不为同一语义在所有层重复一套测试。
