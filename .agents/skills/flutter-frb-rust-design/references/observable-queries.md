## 1. 先分语义，再选读法

| 数据与需求 | 合适的交付 | 接纳方式 |
| --- | --- | --- |
| 可变当前态；页面持续依赖的可变列表 | 原 owner 提供有界查询结果的观察，首帧和后续共用契约 | 替换同一查询的完整当前结果；允许合并中间版本 |
| 一次性搜索、用户明确发起的检查、无需持续更新的详情 | 一次类型化查询 | 只提交给原请求；不额外建立长期订阅 |
| 不可变历史与其详情 | 既有游标分页、按需读取和必要的追加交付 | 按原身份和顺序接纳，不套用可变列表替换规则 |
| 持续变化的正文窗口 | 原内容 owner 的有界范围观察 | 显示最新窗口，不在界面累计另一份文本 delta |
| 命令及回执 | 操作 owner 提交并结算原操作 | 权威值进入原资源写入口，回执不成为第二条状态链 |
| 临时通知 | 按产品语义交付的事件 | 明确是否可丢弃、是否需重放；不要冒充可重建状态 |
| 草稿、选择、折叠与滚动 | 实际草稿／呈现 owner 的本地状态 | 不写回权威事实，不随无关查询更新重置 |
| 订阅、reader、controller 等资源 | 显式借用、取消与关闭 | 不放进值快照；保持真实释放责任 |

已有原子交接关系的字段仍由原 owner 同批交付。Native 完成项与 Main Current 的退役不能拆成
互不相关的观察；只在原交接允许的范围合并中间状态。保留原逻辑交接，不额外合成包含全部正文、
完成项与旧历史的大快照，也不新增逐帧渲染确认协议。不可静默丢弃完成条目；交付无法继续时
沿原协议显式结束并局部重开，不承诺无限重放，也不为独立历史读取增加实时流 ACK。

Native 数据由原 Rust 领域 owner 定义权威状态；外部协议中的事实由协议及对端定义。
ACP 等协议只按协商能力呈现与操作。对端没有提供版本、历史加载、可靠重放、ACK 或结果确认时，
不自行补成 Native 协议，不增加会话副本、周期查询或命令后的回读验真；本地传输取消和资源释放
仍须正确，但不提升为对端业务成功或可靠保存保证。

## 2. 一个观察对应一个固定查询和窗口

查询身份包括影响结果的资源范围、过滤、排序与窗口条件；身份值使用明确的类型和规范相等语义。
窗口可以是首段、固定排序边界附近或原协议定义的分页范围，不以全表为默认观察对象。
改变查询或窗口时替换原观察；旧请求成功、失败和 finally 都不能写入新观察。

列表结果不仅是行字段，还包括成员资格、顺序、窗口边界及必要 continuation。
这些由权威查询 owner 一起决定。界面不能把点查页再与另一份实时字典、临时删除集合或命令结果
拼成“更完整的列表”，也不能用实体 revision 证明某实体仍属于当前过滤结果。
选中实体的读取按 ID 和实际持续需求独立持有，不依赖它是否在某个列表窗口中，
也不为解析该实体把点查结果反向注入全局目录。

可变数据的多页必须声明一致性语义。需要持续更新的普通目录优先采用固定 query/window 的完整结果观察，
窗口变化后更换轻量观察；不拼接不同时点的 offset 页并宣称无漏无重。只有产品明确需要冻结时点
遍历时，才另外定义快照分页资格，不将它作为普通列表的默认要求。不可变历史仍沿原分页契约。
查询快照只覆盖所请求窗口，不要求推送完整表、完整正文或所有历史。
固定排序边界使用捕获的排序键与稳定 ID，不依赖锚点记录一直存在或保持当前位置。
结果物化与替换应随请求窗口大小有界；查询扫描与排序成本另行核对，不能由返回行数推断。
深度浏览采用明确的窗口移动和释放，不无限累计前缀。
不把目录窗口推广为 Rust 管理 Timeline 可见行、像素或滚动位置。

## 3. 首帧、版本和后续变化必须有共同切面

本节与下一节适用于确实承诺持续更新的观察；一次性读取和无观察能力的外部协议不套用。

原 owner 先登记变化观察，再捕获一致的首帧。登记、读取及发布之间发生的变化必须由首帧覆盖，
或保留为后续待处理变化；不能先读一次再订阅，也不能把调用 listen 当作原生登记已完成。

一个快照的内容、版本、来源身份和查询元数据必须来自同一可解释切面：
优先复用原 owner 的串行提交边界、数据库读事务，或锁内捕获的不可变状态引用。
不要先读数据、释放锁后再读取“最新 revision”贴标签；不要为观察另建独立写入的权威表或第二套可变事实。
若原生领域需要 generation／revision，其递增与公开必须遵循同一提交顺序，
不能先分配号码再由并发任务任意发送。

只读接纳 owner 对同一来源、同一查询提交结果；可替换快照允许跳过中间版本，
缺失中间 revision 本身不是错误。完整快照与必须连续的 delta 必须采用不同语义。
确需 delta 时才要求其基线、连续性与恢复覆盖，不能仅凭较大的数字接受不明增量。
来源换代时使用原资源身份明确重建基线，不能跨来源比较版本或借用旧窗口。

## 4. 原 owner 内合并失效，保证查询期间的变化不丢失

变化通知可以只唤醒权威查询 owner 重新读取所需窗口；它不必携带全部业务数据。
这是一种由变化驱动的观察实现，不是页面听事件后自行刷新，也不是定时轮询。
通知依赖须覆盖能改变成员、排序及行字段的来源；只监听当前命中行会漏掉窗口外记录的移入，
只监听主记录会漏掉查询所依赖的其他领域变化。

复用现有观察循环；只有同一目标的单次查询在途。合并器满足以下不变量：

- 变化发生时保留 dirty／源版本；正在读取不能作为丢弃变化的理由。
- 读取开始时捕获本次覆盖的版本；返回快照使用其真实切面，不能在结束时套用最新版本。
- 读取期间再次变化，完成后继续处理未覆盖变化；只有本次快照确实覆盖的 dirty 才能清除。
- 收尾检查、转为空闲与下一次唤醒之间不能留下失联窗口；失败不得被当作干净状态。
- 允许合并中间快照，禁止无限并发重读、无变化空转或追逐最新版本而阻塞首帧。
- 取消先撤销发布资格并唤醒等待；迟到结果由原操作收束，不因查询 key 相同而复活旧观察。

具体使用保留版本的 watch、事件循环或既有调度器由当前实现决定，不要求新建通用同步框架。
查询算法与通知所有者必须能共同证明无漏失；“有 debounce”“有 requestId”并不提供这个证明。

## 5. 一个只读提交入口，恢复范围与查询一致

Rust 负责业务读取与成员资格，FRB 做机械类型和句柄适配，SDK 的原领域 owner 接纳一次，
Riverpod／ViewModel 观察不可变切片，View 渲染并发出意图。优先复用现有
AccountObservation 一类按目标观察的模式，以及 ValueObservation 的只读借用接口；
只抽取已验证可共享的 open／consume／cancel／close 机制，保留领域目标与结果类型。
复用前核对其是否满足同切面、无漏失和关闭契约；已有实现若违反这些条件，应在原 owner 修正，
不能把“项目已使用”当作正确性证明，也不能为绕过缺陷复制一套观察实现。

只有领域契约已经选择命令回执作为权威交付的一部分时，回执中的资源值才进入该领域唯一
接纳入口，并遵守原来源和版本规则。已选择独立观察作为唯一交付的字段，回执只结算操作；
不在回调中修改另一份列表，不再为“保证刷新”同时 invalidate、reload 和重连。
乐观交互仅作为原操作的可识别 pending 展示，不能改写 canonical。
冲突是否重试按原命令契约决定，不把未知结果自动换 ID 重发。

恢复必须写清覆盖范围：某查询的新完整快照只替换该查询；局部页不能提升未覆盖旧行的有效性，
恢复基线须覆盖该观察的当前需求。增量缺口只能用明确覆盖缺口的基线恢复；命令冲突只更新相关资源。
不要因配置冲突重建历史窗口，或因正文翻页关闭无关列表。
旧快照如继续展示，必须明确它是尚未更新的结果；原错误、来源和重试状态不能静默变成成功。
来源恢复不重放业务命令，不清理无关草稿、附件或导航意图。

## 6. 复用背压和生命周期，不扩展协议保证

可替换状态优先复用“一个最新待取值、消费者处理完再取下一值”的观察方式。
持续推送若已有 credit／ACK 协议则沿原 owner 管理；不要把 ACK 加到每个简单查询。
FRB StreamSink 成功不等于业务消费；Stream、watch 和 Provider 也不自动保证跨语言队列有界。
根据实际负载约束窗口、在途操作和字节，复用既有准入，不复制容量常量或再建无界转发队列。

相同查询的共享观察由已有领域 owner 按需求借用。最后一个需求离开后收束该观察；
一次组件 dispose 不关闭共享执行或其他观察。正文、集合、查询窗口的取消范围与自身资源一致，
不要把无关资源绑在同一个退役开关上。

关闭沿用[原 owner 的取消与汇合](data-delivery-and-lifecycle.md#关闭的是谁)，覆盖空闲等待与在途读取。
无需求、无操作引用且已经释放的只读镜像应可回收，不能仅靠容量上限保留所有访问过的对象。
草稿和业务任务的保留使用其自身 owner，不能拿它们作永久保留查询镜像的理由。

## 7. 只验证本次改变的边界

按风险使用受控交错，优先验证：

- 订阅建立期间的变更被首帧或后续覆盖。
- 读取数据与修改版本交错，不产生“旧内容带新版本”。
- 查询执行期间再次变更，最终能得到覆盖该变更的结果。
- 过滤、排序、删除或窗口改变后成员资格正确，不混接旧页。
- A→B→A 后迟到结果与 finally 不能影响新的 A。
- 局部恢复不重建无关历史、草稿和观察；慢消费者与关闭仍有界。
- 外部协议不支持的能力保持不支持，没有被 Native 的默认路径补造。

验证证据的含义见 `{workspace}/design/24-testing.md`，命令入口遵循 `{workspace}/AGENTS.md`
和相关工程技能；本参考不复制完整矩阵。
先核查现有证明，新增测试只针对剩余风险；不为每层复制同一断言，不建立无关全量门禁。
快照算法、同步调度和 Flutter 呈现分别验证其所属责任。
