# 演进与验证

文中 `{workspace}` 指当前仓库根，与技能安装位置无关。

## 统一读取，不建立第二保存链路

本节适用于项目实际拥有持久化保证的 Native 数据。ACP 等外部协议的历史加载与保存能力
遵循原协议及协商结果，不创建替代保存链路，也不把本地传输完成解释为对端可靠保存。

存储保证见 `{workspace}/design/17-studio-storage.md`；
先理解现有 Session、HistoryStore 与 writer 的职责，前端不自行协调 RAM 与 SQLite。
不要为界面增加第二保存队列、定时器或历史数据库。

若领域采用“完成事实先可见、后可靠保存”，说明以下提交点而非笼统声称“已完成”：

1. 一次准备不可变载荷，整批加入可查询集合，再发通知。
2. 同一批交给既有 writer，与其执行事实、checkpoint、身份索引和附件屏障保持原事务保证。
3. 真实提交确认后才推进连续持久化前缀并回收对应 pending。

失败保留已接纳事实并显示原保存故障；条数和字节都计入可靠预算，
超限按既有安全点背压，不丢最旧条目或无限增长。可见而未可靠保存的 RAM 在崩溃时可能丢失，
不能同时承诺“不等可靠写入即可确认可见”与“崩溃后零丢失”。
数据库事务提交、WAL checkpoint 与机器断电保证也不能混为一谈。

### 有前提的交接证明

以下只适用于不可变记录、稳定身份及统一读取所有者，并非所有可变缓存的通用算法：

- 短临界区捕获代次、可见上界 H 和请求范围内有界的 pending 引用，不克隆全表。
- 锁外建立**新的**数据库读快照，只读不超过 H 的同一范围，合并、去重并校验身份／载荷一致性。
- 若 writer 在捕获后回收，读取仍持有不可变引用；若在捕获前回收，提交已完成，
  后开的数据库快照能读到。两处同时命中只返回一次。

复用捕获前的旧 SQLite 快照会破坏该证明；跨 await 重新解析到另一代 owner 也会混入不同数据。
读取须保持原 owner 与代次，重置则显式拒绝。必要数据库 I/O 不等于等待新事实落盘；
不要在 Dart 加二次查询或查询前强制 flush 来掩盖交接缺口。

## 展示聚合不改变原子存储

先区分业务事实结束、可靠保存、传输接纳与展示容器提交。展示段可在成员事实结束后继续开放；
分类、相邻聚合与呈现交接只由唯一呈现 owner 处理，不能从空列表、静默、文案或绘制时机猜终态。
该 owner 可保留需求内只读元信息和稳定内容引用，但不复制第二份完整历史。
实时、分页和重新打开使用同一规则；未知来源或缺失时刻保持未知，不自行补造恢复保证。

存储和读取保持原子语义，不持久化组、UI 提交时刻、展示前缀或展示排序，
也不把它们换名为来源证明下沉。只有真实生命周期事实或普通查询确有缺口时才迁移。
普通页允许切开聚合段，冷读先表达已知范围；当前 owner 内保持展示身份，不能为跨重开相同 key
要求数据库查找组头。补入旧原子可能影响显示中间的段，按真实来源位置局部更新，
不机械映射为列表头插入或全历史重新分组。

来源顺序与完成顺序交叉时，读取上界只能限制本次物化或合并候选，不能从结构判断中
删去已经观察到的分隔事实后再断言相邻。EOF 只消除对应读取范围的未知，
不覆盖已知正文边界；回归应包含较晚完成的分隔夹在较早完成的两个工作片段之间。

预算覆盖整个未提交范围及其派生持有者，而非每个展示段各领一份额度。
驱逐或合并移除片段时，先同步撤销其局部代次与借用，再取消和 join 原资源；
旧子树尚未卸载或迟到可见回调均不能恢复资格。折叠可重开与永久退役须明确区分，
不能仅以“当前没有绑定对象”推断永久失效。

聚合使原子数不再等于卡片数或显示高度。复用现有分页 owner，在每页布局后按实际视口需求
逐页补载，单次仍有界、同方向单请求，总次数由需求与 EOF 决定，不设固定总页数上限。
没有新增卡片或高度不变不表示数据无进展；分别检查 opaque cursor 和真实布局。
视口已满或 EOF 正常停止，零尺寸/不可见暂停，错误保留并允许显式重试后恢复。
需求检查由数据/尺寸变化驱动，不持续逐帧轮询；接纳 ACK 不等下一页、布局或展示封口。
分别度量首批可见和填满/EOF 成本，不把逐页经过长聚合段描述为常数时间。

## 迁移保证语义，不只是建表

使用现有 SeaORM migration 序列与事务边界。除字段存在外，还要验证真实主键、唯一性、
比较语义和游标回填次序，防止分页批次静默遗漏。旧迁移的校验只要求该历史阶段应存在的结构，
不能因新增表而让早期步骤提前依赖未来格式。

回填、校验、schema 与迁移完成记录应保持既定原子性，失败保留可重试现场；
所用版本的事务能力和连接必须实查，不假定每种后端都会自动包事务。
内容升级与生命周期准备分开，冷历史读取不为迁移启动模型或工具。
缺少来源、时间或因果顺序就保留未知，不能用当前时间、零值或最后修订伪造首次完成。

旧格式只在明确迁移边界解码；受影响消费者、映射、生成物和文档同步切换后移除旧入口。
不要为删除展示旧路径而误删执行恢复、审查或资源修复仍使用的事实。破坏性接口调整不授权清库，
现役数据和隔离旧目录的边界继续遵循存储契约。

## 用契约减少补偿逻辑

- 可变查询的成员、顺序与窗口由权威 owner 产生，方法见[可观察查询](observable-queries.md)。
  不以页面 merge、命令后刷新或增加重试掩盖不完整观察；先在原 owner 修正切面和交付范围。
- 不先换页面库解决状态协议问题；先核对已有组件公开能力，薄适配只承载领域语义。
- 对不可变、有序且只从两端扩展的集合，可用首尾边界投影代替任意重排与全表 diff；
  有可变或重排需求时不能机械套用。展示身份稳定不等于任意高度变化下像素位置不变。
- 一页数据即使全部并入已有展示分组、未增加可见元素，原始数据游标仍应推进；
  不按卡片数判断是否到达历史起点。
- 共享不可变引用不要求每层复制正文；逻辑冻结却引用可覆盖资源，也不能称为零复制优化。
  惰性构建只减少已构建 widget，不自动淘汰 controller 已加载的数据。
- 分开度量页面数据、传输缓冲、正文暂存、媒体缓存与可靠队列。
  明确条目、帧、字节、token 的单位，不能以一项预算冒充全部有界。

## 选择最小充分证据

界面设计对齐建议优先采用官方无头 Widget 测试和 Widget Previewer，直接复用生产组件、
主题和本地化；合成呈现值只提供环境，不复制分组规则、业务 owner 或第二份预览界面。
纯布局、展开和宽窄适配不必依赖原生窗口；FRB、持久化、原生插件和退出仍按实际风险补原生证据。
无头截图不代替明确要求的产品原生截图，测试虚拟时间和预览耗时不代证原生性能。
具体命令、浏览器与生命周期操作使用 `flutter-studio-build`，不在本技能维护第二套入口。

使用 `test-quality` 的已有证明分析，按变化选择边界，不把下表变成每次必跑清单：

| 风险 | 有效反例或证据 |
| --- | --- |
| 单一写入与冻结 | 外部集合被修改、重复同身份冲突，不能改变已接纳事实 |
| 查询通知与切面 | 查询期间变更不丢 dirty；内容捕获与版本更新交错，不产生旧内容带新版本 |
| 局部恢复 | 查询恢复、正文翻页或命令冲突只作用于所属资源，不重建其他历史、草稿或观察 |
| 路由与草稿 | 拒绝离页、等待中修改草稿、旧操作完成后新页面不跳转 |
| 消费与背压 | 前批未接纳而后帧 ready，确认不越界；超窗口快照无自锁 |
| 生命周期 | open 尚未完成即关闭、正在等 credit 时取消、回调重入，真实 owner 全部收束 |
| 存储交接 | writer 提交／回收与读快照交错，不漏不重；故障不伪装保存 |
| 迁移 | 非空旧库、跨批重复或比较语义错误、回填失败回滚，用户数据保留 |
| 呈现 | 分页与事件交叠、分组边界改变、只影响实际变化的消费者 |

用受控屏障或阶段信号证明交错，不以 sleep、压力循环未失败替代。
需要证明生产者被 credit 阻塞时，应观测其已进入等待，而不只看消费者暂停。
测试替身提供环境，不重新实现被测归约器。静态分析不证明交互，
widget 不证明 native 句柄和持久化，单平台／模拟对端不证明跨平台／真实供应商兼容。
构建、生成和原生观察使用 `flutter-studio-build`，复用未受影响结果，不惯性叠加全量检查。

### 真实链路的测试所有权

- 严格模拟对端的匹配形状应来自真实生产编码或已核实的保存输入，不能只用手写“最简合法请求”
  自证兼容。附件名文本、图片与其他内容 part 的顺序也是输入事实；修正 fixture 时保留数量、
  身份、格式和字节校验，不通过删去生产信息或兼容两种虚构结构制造成功。
  即时结果与异步任务交付按各自真实编码验证，受理回执不代表完成；完成通知与媒体须绑定
  同一任务和同一消息，不能凭文本前缀借用历史载荷。必要业务步骤完成由脚本状态确认，
  等待带来的额外请求单独计数，不把请求次数当作业务步骤进度。
- 合成模型路由也必须符合实际模型声明；没有 effort 参数时不自填候选值。
  从具体观察或目录建立目标事实，不能以创建了 fixture、选中了 ID 或填入旧查询页代替首帧接纳。
- 每个 Widget 测试使用独立的官方 `ProviderScope`／`ProviderContainer`，不跨测试复用 provider 图。
  业务 fixture 可以按测试目的共享，但呈现观察、router 和调度回调随各自挂载场景收束；
  不用生产 scheduler 补丁或额外 sleep 掩盖测试所有权错位。
- 清理前尚无可停止执行，与已经准入停止命令后等待身份证明是不同状态。
  后者须确认原目标、原操作和真实观察；缺行、无资格或取消请求本身都不能冒充完成。
- 先保存实际关闭报告和必要操作身份，再断言 clean／持久化／资源回收。
  失败同样保留诊断，不能因断言先抛出就丢失报告，或用进程退出替代应用自身收束。
