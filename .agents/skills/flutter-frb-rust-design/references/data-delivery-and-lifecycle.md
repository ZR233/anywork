# 数据交付与生命周期

文中 `{workspace}` 指当前仓库根，与技能安装位置无关；现役产品协议以
`{workspace}/design/07-streaming.md`、`{workspace}/design/25-frontend-state.md` 和
`{workspace}/design/26-timeline-content.md` 为准。下面的不可变完成集合、
独立历史读取和完成消费者接纳模式是有前提的设计方法；只有相应领域已经确定并迁移到该契约，
才能删除其旧修订、缓存或查询机制，不能仅在 UI 过滤终态就宣称完成改造。
Native 自有领域与 ACP 等外部协议的能力边界见[可观察查询](observable-queries.md#1-先分语义再选读法)；
这里的可靠封口、幂等与历史保证不自动扩展到外部协议。

## 先区分数据，再选通道

| 数据性质 | 交付方式与写入点 |
| --- | --- |
| 命令及回执 | typed action 经操作 owner 提交；回执结算原操作，只有契约选定的权威值才进入该领域唯一接纳入口 |
| 可变当前态与查询结果 | 按[可观察查询](observable-queries.md)选择完整可替换快照或确需连续的 delta；SDK 接纳一次，Flutter 只读投影 |
| 一次性详情与检查 | 普通类型化查询，结果归原请求；无需建立永久观察 |
| 不可变完成事实 | 原事实 owner 按稳定身份可靠发布，按完成序号读取；保留真实保存义务 |
| Native 连续段卡片 | Rust 提供不可变读取索引和明确呈现类别，Flutter 原 controller 唯一组合；不保存后端工作组 |
| 历史页与不可变详情 | 按需查询，绑定请求身份、游标与预算，不借实时流的 credit 完成查询 |
| 展示选择与资源 | 由实际呈现或资源 owner 管理，不冒充业务事实 |

持续变化的正文按原内容 owner 提供有界范围观察，见[可观察查询](observable-queries.md#1-先分语义再选读法)；
Native 用完成前缀绑定活动快照：固定目标补读完成，实际接纳后才交付同切面活动，
按 typed identity 退出对应活动，不等整组。不建立可靠展示 cut 队列，也不因此删除
原 Effect/HistoryChannel、唯一 writer 或 checkpoint 的可靠职责；具体算法只在 design/26 维护。
历史详情、大附件仍可按需读取，不能反向推导所有大载荷必须常驻推送。
对不可变完成页，SDK 可以持有有限的未交付批次，但不再另存一份历史窗口；
已加载代表卡片由原组件 controller 持有；Run 明细随独立窗口存活，不镜像完整原子历史。
Main 工作代表即使只有一项也不读取/内联成员正文或媒体；展开才按原范围能力读取。

## 不可变事实的前提

本节适用于已经采用可靠完成契约的 Native 事实；外部事件的终态、身份和保存语义由原协议定义。
完成必须有可靠来源，不能用标点、停顿、UI debounce 或“整个展示组看起来结束”来猜。
稳定元数据也属于冻结载荷；后续才确定的归属应进入其自身状态域，而非原地补写旧事实。
逻辑完成不等于每页搬运全文：有界预览、准确长度与稳定不可变详情引用可以共同表达完整事实。

同身份同载荷幂等，不同载荷明确冲突。不可变只读包装不保护仍被外部持有的可变集合，
也不保护引用到会被覆盖的文件／数据库行；在接纳边界封闭这些写入口。

仅在领域契约确实区分这些阶段时，分别处理启动回执、后台任务结束、业务完成、可查询、展示接纳与持久化；
普通成功响应不因此增加验证回读或确认屏障。
例如启动命令已经返回，不意味着跨轮次运行的进程已结束；历史快照不能绑定成当前可编辑状态。

## 身份与游标各司其职

下表解释现役契约中各类身份的用途，不要求每个查询或外部协议都新增这些字段。

| 身份或版本 | 用途 |
| --- | --- |
| 资源 owner／incarnation | 判断句柄及异步结果属于哪个资源实例 |
| 领域 revision | 同一领域基线内的新旧判断 |
| 活动 generation／内容 revision | 增量正文的基准与完整性 |
| 完成 epoch／追加顺序 | 不可变完成集合的排序、分页和恢复 |
| delivery sequence | 当前传输句柄的交付及确认 |
| 请求 generation／operationId／草稿修订 | 界面请求资格、命令幂等身份与输入归属 |

不要创建全局 revision 让统计更新重建配置、草稿和历史。
追加游标应在该事实加入可查询集合时分配：A 先启动、B 后启动但先完成，
若按启动顺序从 B 之后补发，就会漏掉晚完成的 A。来源顺序与交付顺序需分开。
若重启可能重用顺序号，恢复资格还要核对 epoch；仅比较 cursor 是否超过 head 不够。

## 接纳、确认与背压

本节的连续 ACK、完成事实接纳和分块 staging 只适用于领域已有的可靠交付契约。
可替换当前态使用[可观察查询中的最小观察方式](observable-queries.md#6-复用背压和生命周期不扩展协议保证)，
无需为简单查询增加 ACK；若原 feed 同时交付当前态与完成事实，仍保持原交接与确认语义。

- 唯一 feed owner 管理确认。明确每类帧的接纳提交点：当前态进入 Repository，
  完成批次进入唯一呈现消费者。转发到无界队列不是接纳。
- 只确认同一句柄已经 ready 的连续前缀。前批完成事实仍未接纳，不能因后帧状态已提交而越过它。
  恢复 cursor 同样取实际连续接纳位置，不取收到的最大序号、目标水位或服务端 head。
- 同一更新既交付完成事实又结束 live 时，先校验准备、接纳完成事实和提交当前态，再公开更新；
  不先清 live 后异步等历史补上。协调者不保存第二份镜像，不为此建立通用跨域事务框架。
- FRB `StreamSink.add` 没有等待 Dart 业务消费的提交语义。复用现有 credit、取消与 join，
  同时限制帧数、单帧字节和暂存总量；不要把 transport ACK 扩展成业务修订握手。
- 大快照分块进入受限 staging，中间块按实际接纳释放 credit，最终块原子替换快照。
  若快照超过窗口却等全部收齐才确认，生产者与消费者会互相等待。
- 同一可靠 feed 内只有不破坏完成交接的可替代状态可以合并；
  必须累积的文本 delta 和可靠条目不能任意丢弃。

## 建立基线、恢复与迟到结果

可变查询的登记、首帧切面与查询期间的 dirty 保留统一遵循
[可观察查询](observable-queries.md#3-首帧版本和后续变化必须有共同切面)，这里不维护第二套算法。
仅当原协议实际提供保留窗口和恢复资格时，同代恢复才从实际接纳位置补齐；
实时状态与可靠补发公平调度，不能让一方持续饿死。超出保留范围按原协议显式失败或局部重开，
不承诺无限重放，也不为外部协议补造保留窗口。
失配只恢复受影响域；历史 epoch 变化不清无关草稿和配置，重连不重放业务命令。
不可变历史分页与新增完成事实由同一呈现提交点串行接纳，不用请求发出时的旧展示分组覆盖最新状态；
可变查询按其完整结果替换，不混接不同时点的页。

持久化的未完成状态、展示位置和缺终态计数不能证明执行资源仍存活。跨重启恢复时，
活动动画、实时计时及依赖执行者的操作资格使用原 owner 明确提供的类型化资格；
保存片段和待决交互仍可读，不通过隐藏内容、清空计数或补造终态消除状态差异。

首次 await 前冻结目标、owner、operationId、预期版本及草稿／附件归属。
结果未知保留原意图并按既有幂等／CAS 契约恢复，不自动换 ID 重发；
只有原命令契约支持时才使用恢复查询，不为普通回执额外回读验真。迟到成功、失败和 `finally` 都只收束原操作，
尤其不能在 A→B→A 后写入第二次 A 或清掉新输入。

## 关闭的是谁

观察者只取消自己持有的租约；共享 feed、独立 read scope、业务 Session、UI Controller
各有显式 owner。独立历史查询不因 feed 关闭而无条件取消，业务任务不因页面 dispose 而结束。

关闭先同步封闭准入和迟到发布，唤醒等事件／credit 的任务，再等待本 owner 已准入的 open、
producer、sink、query、consumer 和底层句柄真实退出。迟到打开的句柄仍须被原 owner 收回。
分块 staging、未接纳批次及其许可均需有取消路径，不能提前 ACK 掩盖消费者脱离。
失败保留未解决资源与重试责任，超时、dispose 或“请求了取消”都不是回收证据。

同步回调可能重入：发布前形成不变结果，回调后重新核对资格；
不让同对象身份或复用的 Provider 为旧调用重新授予写入权限。具体同步证明使用
`rust-concurrency-safety`，内存与外部句柄安全使用 `rust-unsafe-safety`。

官方依据：[FRB Stream](https://cjycode.com/flutter_rust_bridge/guides/types/translatable/stream) 的返回与 sink 生命周期、
[Tokio watch](https://docs.rs/tokio/latest/tokio/sync/watch/index.html) 的最新值与变化通知语义。
按项目锁定版本核对 API；确认与关闭的具体协议仍由项目 owner 承担，不是第三方组件自动保证。
