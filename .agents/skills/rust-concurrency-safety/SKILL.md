# Rust 并发安全

先列出共享对象、所有者、全部读写执行上下文和允许的状态转换。执行上下文可以是线程、异步任务、回调或外部进程；是否并发取决于真实访问关系，不取决于是否使用 `async`。

## 按需阅读

- 锁、等待、通知、回调与关闭：参考[锁与生命周期](references/locking-and-lifecycle.md)。
- 原子、内存顺序、无锁状态、异步执行、超时与取消：参考[原子与异步](references/atomics-and-async.md)。
- `unsafe impl Send/Sync`、裸指针或 FFI 共享内存：同时使用 `rust-unsafe-safety`。

优先考虑不共享、消息转移所有权、共享不可变值、保护明确不变量的锁，再考虑可独立证明的原子状态。不能用 `Arc`、更强的内存顺序或“更快的锁”代替同步与生命周期证明。

## 大型 future 与栈

排查异步栈溢出时区分同步递归、future 构造／移动和嵌套轮询。沿实际调用链测量 future 类型与跨等待保留值；`Option::None` 不会消除大候选的静态布局，`tokio::join!` 也会内联保存各分支。先缩小快照作用域、复用轻量资源 guard，必要时在所有者边界用标准库 `Box::pin` 或堆上快照隔离大状态；不要仅装箱最外层测试、批量装箱所有 await，或用新增任务暗中改变取消与生命周期。

尺寸上限回归只能约束内联布局，不能证明累计调用栈安全；仍应保留默认宿主栈上的真实链路复现。增大线程栈不构成根因已修复的证据。可参考 [Rust Pin](https://doc.rust-lang.org/std/pin/) 与 [Tokio join](https://docs.rs/tokio/latest/tokio/macro.join.html) 的官方契约。

## 验收

从发布者到观察者追踪完整同步链，再检查取消、错误和最终释放。明确等待如何结束、完成竞争如何裁决、关闭如何拒绝新工作并等待在途工作。构造具体交错，不以“可能有竞争”或“压力测试没失败”代替结论。

`test-quality` 提供行为证明的分析方法，[项目入口](../../../AGENTS.md) 提供可选工具。
模型或 fake 只证明其实际覆盖的规则，不要求每次改动执行完整的生命周期场景。
