# Rust 原子与异步

## 1. 原子状态

为每个原子变量写清它承载的含义：纯计数、状态发布、所有权转移、代次标识还是唤醒合并。多个原子共同表达一个不变量时，说明它们如何保持一致；无法独立证明时使用锁或单一状态对象。

### 1.1 内存顺序

使用 Acquire、Release 或 AcqRel 时明确发布者写入的数据和观察者读取的数据。发布操作前完成受保护写入，获取操作确认状态后再读取。

`Relaxed` 提供原子性和该原子对象的修改顺序，但不发布其他内存访问。只需这些保证时可以使用，例如统计计数或正确处理回绕与复用的编号分配；其他数据已有独立同步边时也可使用。说明为何无需发布其他数据，或指出实际同步路径；不能从编号已分配推导对象已可见，也不能用当前架构的行为代替 Rust 内存模型证明。`SeqCst` 只在确有全局排序要求时使用；增强内存顺序不能修复丢失唤醒、复合状态撕裂或生命周期错误。

比较交换循环处理失败返回的新值，明确弱比较交换的重试条件，避免无界自旋。位图或标志更新说明各位是否独立，清除操作不能覆盖并发发布的新状态。计数减到零触发释放时防止下溢、重复释放和从零复活；代次标识考虑回绕与复用。

## 2. 异步执行

把每个 `.await` 视为潜在并发和取消边界。挂起前确认没有持有同步锁、不可跨挂起 guard，或其他生命周期／线程要求与挂起冲突的状态；普通合法借用本身不是禁止条件。异步锁是否跨 `.await` 由其契约决定，必须说明保护的不变量、持锁操作、重入与锁顺序、取消及关闭路径，不能仅因 guard 可挂起就认为安全。

异步运行时线程不直接执行无界阻塞 I/O、长时间计算或同步等待。使用项目已有的阻塞隔离边界，并定义关闭与取消。派生任务必须有所有者：等待句柄、纳入任务组、保留可观察 handle，或明确且受控的后台生命周期。

### 2.1 取消安全

每个挂起点都可能取消。部分写入、已取出队列项、已登记 waiter、临时文件和临时取得的能力必须保持一致或由 guard 回滚。无法取消安全的操作使用显式不可中断阶段或持久化状态机表达。

必须跨 `.await` 持有的 RAII 值应存入具名绑定；`_guard` 也是实际绑定，与 `let _ = acquire_guard()` 丢弃临时结果不同。带 `Drop` 值的释放遵循其 drop scope，不因最后一次读取或非词法借用生命周期分析而自动提前；不要为“防止编译器提前释放”添加空方法、假读取或多余原子访问。显式 `drop` 只用于确实需要提前结束的资源作用域，计数与其他归还义务同样覆盖 future 被丢弃的路径。
作用域规则见 [Rust Reference：Drop scopes](https://doc.rust-lang.org/reference/destructors.html#drop-scopes) 与 [Wildcard pattern](https://doc.rust-lang.org/reference/patterns.html#wildcard-pattern)。

超时包装不能让内部任务在后台继续修改调用方已视为失败的对象。若保留后台工作，返回可观察句柄并定义最终结果、资源与错误的所有者。

`JoinHandle` 被丢弃不会取消或等待任务。可重试的关闭或超时等待应把句柄留在 owner 槽内，借 `&mut` 等待，观察到终态后再移除；先 `take()` 再等待或按值交给 `timeout`，会在外层取消时遗失 join 责任。已观察到的 `JoinError` 同样是句柄终态，须保留失败诊断并清理该终态槽，不能再次轮询已完成句柄或以 `abort`／`Drop` 冒充回收。

终态清槽必须覆盖错误传播路径：先保存 join 结果、移除已完成句柄，再返回或 `?` 传播
错误；不能在清槽前对 join 结果使用 `?`，否则下一次关闭或启动可能二次轮询同一终态。

持久操作可能已在数据库或后台 worker 提交，而确认仍在返回途中；丢弃调用方 future
不等于回滚。让受管 owner 持有完整事务及必要接续到真实终态，调用方取消只放弃等候。
调用方的析构通知不能代替提交确认：若它先于后台写入完成，观察者可能只读到旧值。
任务登记与关闭封口须在同一边界重核；先收束在途写入并发布真实结果，再关闭发布器或
存储，不能仅靠一次正常返回后的通知覆盖取消和后继失败。

### 2.2 stream 与背压

说明 producer 停止、consumer 提前退出、channel 关闭和终态错误的语义。避免无界 channel 掩盖背压；缓存要有容量、丢弃或阻塞策略。终止事件只能发布一次，错误不能在中间层被日志吞掉后转换为正常结束。

有限公平应按持续就绪、持续满足发布门控的来源处理机会定义，并写清单次轮询有限和接收持续推进等前提；随机首选不能证明确定次数上界。复用成熟组合器时核对其轮换与终止契约，让仲裁状态跨接收和取消持久存在。暂时门控或等待槽为空不等于流终止；某些组合器收到 `Ready(None)` 后不会再轮询该输入。

数据就绪不等于获准发布。若两个来源必须同次交接，区分实际已交付位置、已公开状态的许可范围和当前分块事务的依赖范围，覆盖数据先到、事务中间块已发和单批跨多个事务边界的交错。不能只在 Commit 到队首后才保护依赖，也不能用优先轮询或当前生产 head 猜许可；已开始的分块事务不可静默替换。

需要等待交接的原结果由同一在途槽持续持有，不因一次接收取消而丢失。只有领域契约允许容器分段、且原子身份和载荷不变时才移动连续前缀；未交后缀耗尽前不启动下一读取，原结果与下一等待不得同时占有同一资源。门控不能吞掉来源错误或正常结束；依赖来源已失去且责任无法合法交付时明确失败。关闭既要汇合仍运行的等待，也要收回已完成结果保留的原句柄。

## 3. 审查证据

至少追踪一条完整发布/观察链、一条取消或错误链和对象最终释放。测试按 [test-quality](../../test-quality/SKILL.md) 复用或增强完整行为证明，不按线程数或循环次数机械新增。验证状态与后置条件；超时只防止测试永久挂起，不作为成功判据。压力、loom 或其他模型检查可以补充证据，但不能替代具体同步证明。
