# #440 生命周期总计划复核

复核对象是 [#440](https://github.com/ZR233/anywork/issues/440) 的四项实施计划：
[#441](https://github.com/ZR233/anywork/issues/441)／[#463](https://github.com/ZR233/anywork/pull/463)、
[#442](https://github.com/ZR233/anywork/issues/442)／[#465](https://github.com/ZR233/anywork/pull/465)、
[#443](https://github.com/ZR233/anywork/issues/443)／[#472](https://github.com/ZR233/anywork/pull/472)、
[#444](https://github.com/ZR233/anywork/issues/444)／[#476](https://github.com/ZR233/anywork/pull/476)。
四项均已合入主线。本报告记录源码契约、删除边界和可复算规模，不把议题关闭状态作为测试证据；
本次执行结果及最新提交的远端质量检查由关联 PR 正文记录。

## 结论与效果

作用域解决的是“谁负责资源、关闭请求是否发出、原资源是否真正关闭”：取消信号不再直接等于关闭成功。
Rust 的 bridge 和 runtime 已共同使用 `pl-lifecycle`；Dart 的原始句柄由传输作用域持有，
客户端消费端引用同一资源身份，页面只撤销自己的需求。创建中的资源、失败原件和尚未结束的消费者
继续由原作用域负责，显式重试只处理同一原件。

已实现的确定效果包括：取消失败不会允许新句柄绕过旧句柄；共享来源仅在最后需求离开后收束；
产品主题最后接收者离开后，通知通道可以回收；观察关闭不取消已经受理的模型执行、命令和可靠保存；
LSP 投影未确认完成时，LSP 与 SSH 服务继续保留。对应测试检查真实身份、调用次数、通道数量和关闭次序。

**代码总量没有减少。** 业务侧删除了重复生命周期实现，但通用作用域、身份去重、错误报告和行为证明
增加了代码。可以确认所有权更集中、重复登记减少；不能据此声称全局状态机更少、整体算法更简单、
性能更快或解决了范围外的退出崩溃。

产品主题回收测试 `dynamic_thread_and_workspace_topics_return_to_original_cardinality` 创建
256 个不同的动态主题，每个均建立广播及查询唤醒接收者，释放后恢复原数量，最终恢复为零；
其他测试分别保护双消费者、旧凭证晚释放、同名主题新代次、基线读取取消，以及快照／修订号／序列保留。
这是通知注册数量有界的证据，不是全应用内存或吞吐量测量。

本次新增的同步消费者关闭回归，在消费者回调内关闭所属作用域：预算耗尽时仍报告消费尚未完成，
在消费者真正退出前不调用原资源清理，退出后只清理一次。

## 本次清理与明确保留项

删除 `ClientScope` 中重复保存的创建 Future、消费者 Future、清理 Future、消费者启动标记和租约释放 Future。
创建与消费完成仍各有一个受持有的完成凭证；阶段诊断和关闭等待直接使用同一事实。
消费者凭证在回调执行前安装，保持同步重入安全。清理尝试、失败结果、原资源和身份索引继续保留。

删除 runtime 的 `ScopedObserverFactory` 单字段包装，直接注入原弱 `ScopeHandle`。
根作用域统一封门并向子树传播取消，删除对三个子作用域重复发出的请求；各关闭阶段仍分别等待自己的真实结果。
这两个实现文件合计净减少 41 行。计入公共契约说明及下述内联回归修正后，本次手写源码文件合计净减少 4 行，
独立回归测试新增 32 行，没有通过删除测试用例或生成文件缩减数字。

首次运行时全量检查出现 1 项失败：Host MCP 映像租约测试把 `/proc/<pid>/fd/<编号>` 路径仍存在
当作原句柄泄漏。关闭后编号可以立即被同进程的并发测试复用，单独的操作系统探针已确定性复现这一前提。
修正既有测试，使其观察原 `File` 对象的弱引用在最后租约释放后消失；原有真实子孙进程执行与字节一致性
断言继续保留，不降低关闭要求，也不修改映像的生产所有权。

| 保留对象 | 继续保留的责任 |
| --- | --- |
| 主题、账号与目录领域池 | 共享需求、查询窗口、代次、修订校验和业务重连；不是第二套实际句柄所有权 |
| 内容观察索引与读取器 | 业务观察身份、容量、读取信用及背压；原资源已由同一作用域或领域聚合所有者关闭，不重复登记 |
| 启动与关机进度作用域 | 寿命与普通内容不同；既有协调器分别取消并在原生终结前合并结果 |
| 会话执行、线程投影与可靠写入器 | 已受理工作的完成、持久化和完整交接；不能随页面或只读观察退出而中止 |
| MCP、LSP、SSH、更新及进程所有者 | 服务依赖顺序、外部完成确认和重试责任；观察作用域只负责自己的投影 |
| ACP 会话业务创建 | 业务创建与只读观察不同，关闭观察不能取消会话；四项实施计划明确保留此边界 |
