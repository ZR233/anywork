# PR #86 的设计与性能复核

审查日期：2026-10-16。原 PR head 为 `e211c18d1062d02c295bc800d7acd44de739124a`，本轮同步主线至
`85011757` 后修订。本文记录原实现的问题、最终设计与实际证据，不把旧 head 的 CI 当作修订后的验证。

## 结论

Turn gate 放在 core 的统一 Turn 准入点是合理的：它解决宿主切换执行环境时的调度边界，
不应知道 Mai 的引用、容器或鉴权业务。输出预算属于工具执行资源的生命周期，也适合由 PL 提供。
但原 PR 的冷任务历史扫描、远端预算执行位置与输出计量不能直接合并；本轮已按事实所有者修正。

本轮没有发现 gate 的失唤醒、忙等或随历史增长的 gate 开销。真正的性能问题是冷任务查询会随着
会话历史增长反复解码正文。索引修订大幅降低读延迟，同时增加事务写入成本；不能称为零开销。

## 原实现的确定问题与最终处理

| 问题 | 影响与证据 | 最终设计 |
| --- | --- | --- |
| SQLite 冷任务按身份读取却倒序分页扫描 effect | 10 万条历史中，最早任务热查询中位数约 1.67 秒；不存在的身份同样扫描全历史，并占用 writer 共用连接 | 任务身份、交付定位和资源补充与原 effect 同事务写入索引；点查原始交付，正文不重复存储 |
| 冷任务交付没有合并稍后的 `delivery_repairs` | 资源重试已完成，按身份读回的交付仍缺少归档引用；确定性测试在原 head 失败 | 独立资源补充索引，完整性校验、按原 call 合并及去重 |
| 输出额度只计原始流，且头部先写后检查 | 头部、块标签、补换行和合法副本使实际磁盘量超过声明额度 | Manager 后端必须提供精确、廉价、无 I/O 的成本函数；头部预算在创建文件和启动命令前检查 |
| helper 自己写盘，客户端计数却被当成磁盘限额 | 原 helper 对 20 MB 有限输出写出 20,039,145 字节，超过默认 16 MiB；停止传输不能限制远端继续写盘 | helper 在每次物理写入前执行同一额度，终态交回实际计费回执；Producer 客户端不维护第二套磁盘计量 |
| 先截断再按总预算截断 | 魔数预留、重复省略行，以及原始长度被中间展示文本覆盖；极小字节预算和 UTF-8 边界尤其难保证 | 最终预算先分配，再由 `pl-output` 对原始头尾片段投影一次；唯一省略行计入预算，原始字节长度独立保留 |

不保留“索引没有就扫历史”、旧协议分支、按接收流量估计远端磁盘量或对越界结果再硬裁剪。
索引损坏、effect 所有权错误、修订冲突与迁移中断都明确报错。没有 producer 回执时，初次归档和
显式归档重试共用的确认边界均拒绝把短文件保存为完整结果。

## 所有权与生命周期

- gate 的 mutex 是准入事实源，watch 只负责唤醒；等待方订阅后重新在 mutex 下取得许可。
  多个关闭原因各自拥有 RAII hold；许可跨整个当前 Turn 存活，关闭只阻止下一 Turn。
  等待仍通过原 mailbox 响应关闭、取消和持久化请求，不依赖队列暂停或轮询。
- Manager 模式由客户端共享计划接纳输出、唯一 writer 写盘；stdout/stderr 共享额度和有序修复计划。
  预期容量终止有独立 typed 类别，真正的本地写/flush 故障仍保留可靠保存义务。
- Producer 模式由 helper 执行磁盘额度；客户端保留有界头尾缓冲和流控窗口，不再复制完整捕获队列。
  `capture_usage` 在回执到达前为 `None`。回执早于客户端两路排空也不会丢失已接纳字节；
  终态仍等待物理退出、流关闭和捕获收束。
- LSP 与 Git/worktree 内部执行没有命令归档读者，明确使用无捕获策略。它们不创建命令日志，
  也不继承一次性 exec 的累计磁盘额度。20 MB 的内部执行结果已验证完整传输。

## 性能测量

本地环境：Linux 6.8、x86_64、i7-10700（8 核 16 线程）、Rust 1.99.0，`--release --locked`。
时间来自独立手工入口；没有用时间阈值充当功能测试。原始数值摘要见 [measurements.json](./measurements.json)。

### 冷任务读取

SQLite 内存库；历史中只有第一条承载目标任务，其余每条含 1 KiB 无关事实；每个规模读取 7 次取中位数。
“冷任务”表示身份已离开驻留任务集；这些数据是缓存热查询，不能当成物理磁盘冷启动数据。

| effect 数量 | 原版：最早任务 | 修订：最早任务 | 原版：未知任务 | 修订：未知任务 |
| ---: | ---: | ---: | ---: | ---: |
| 1,000 | 15.190 ms | 0.0759 ms | 14.694 ms | 0.0317 ms |
| 10,000 | 153.872 ms | 0.0877 ms | 161.597 ms | 0.0315 ms |
| 100,000 | 1,671.190 ms | 0.0765 ms | 1,543.004 ms | 0.0309 ms |

索引点查加一条交付 effect 的解码，成本取决于目标交付及其资源补充，不再取决于无关历史总量。
单连接池仍让短读事务与 writer 排队；不存在持有读事务再等待 writer 的调用环。

### 写入代价

每个样本使用新内存库，写入 200 条 effect，每 64 条 flush；每轮预热 1 次、测量 9 次，
原版/修订交错运行 3 轮，合计每种模式 27 个样本，取每条 effect 中位数。
两版都固定 CPU 2、`TOKIO_WORKER_THREADS=1`。未固定 CPU 的复测有明显宿主调度波动，不能据其单次中位数
宣称稳定的性能差异；下表是控制调度条件后的局部成本。
无任务 effect 含 1 KiB 事实；任务 effect 含一个终态任务与 1 KiB 结果。原版和修订使用相同公开入口。
两版最终测量使用独立的构建缓存，防止多个工作树共享 Cargo target 造成产物复用干扰。

| 模式 | 原版 | 修订 | 增量 |
| --- | ---: | ---: | ---: |
| 无任务 effect | 92.86 µs | 99.71 µs | 6.85 µs，约 7% |
| 终态任务及交付 | 100.87 µs | 169.14 µs | 68.27 µs，约 68% |

这是事务解码与索引维护的实际代价。对一次模型或进程调用，它是亚毫秒成本；高频合成写入仍可能受其影响，
因此不声称吞吐无变化。10 万条历史构建时的耗时不用于比较写入性能：已有 writer 的资源 ordinal 计算随
资源数线性扫描，且旧测量期间存在其他编译负载。

### gate

同进程、立即返回的脚本模型，单线程 Tokio；每个新 owner 连续执行 200 个 Turn；有/无 gate 交错执行，
预热后各测 11 次。无 gate 的每 Turn 中位数为 350.56 µs，开放 gate 为 354.36 µs，相差约 1.1%，
两组样本范围重叠，不能将中位数差当成稳定的回归幅度。单次许可获取及释放约 30.10 ns。
这是合成模型下的局部成本，不代表真实供应商的端到端延迟。

## 迁移与消费者升级

通用 core SQLite schema 升至 12；旧库由正常 open 明确拒绝，通过已有离线迁移入口显式完成 11→12。
空库结构与版本号一起提交；升级时新索引、回填与版本标记在同一事务提交，分页各 128 行；损坏信封、effect 链缺口会整步回滚。
原始 effect、条目、历史和会话不改写、不清空。大库迁移是一次 O(历史字节数) 的离线操作，
隔离文件库中 5,000 条 effect、500 个任务的回填耗时约 108 ms，迁移后数据库约 13.4 MiB，
`EXPLAIN QUERY PLAN` 确认任务主键索引点查；这不能外推大型生产库。
单事务的 WAL/临时空间与维护窗口应按实际库规模准备；不能把分页解码等同于无迁移成本。
Studio 自有历史索引仍走原本的按身份读取，此次不重复建立其正文事实源。

外部宿主升级需要同步所有 PL 依赖、锁文件与以下接口：

- `CommandBackend` 明确声明捕获所有权，Manager 按实际 chunk 字节计算全部存储成本；
  `prepare_output` 接收固定额度并在写入前检查；spawn 携带同一额度。
- Manager 进程退出不携带 producer 回执；Producer 必须交回回执。快照使用 `capture_usage`，
  不能把尚未确认的用量当成零或根据收到的 stdout/stderr 填充；主文件确认偏移与含全部副本的计费成本分开。
- SSH 协议升级至 8，helper 和客户端一起更新。旧版本明确拒绝连接。
- 输出投影以 `OutputExcerpt` 替代原 `TruncationStrategy`；磁盘捕获、模型正文和归档额度分别由各自 owner 声明。

Mai 的生产依赖仍固定在已部署的 `b4213a1f`，本轮不自动改锁文件或部署生产。

## 验证与边界

功能回归包含：资源补充缺失的先失败后通过；迁移中途损坏后整体回滚、修复后重跑；迁移前后原始字节相等；
拒绝 effect 缺口；会话删除清理索引；跨 Thread 隔离；目标读取不解码无关损坏 effect；损坏索引不能回落历史。

手工运行覆盖本地真实进程、独立 stdio helper，以及独立 SSH 工作区上的 stdin、双流、磁盘长度与回执相等、
容量终止、20 MB 无捕获传输、Git、LSP、断线重连与进程树回收；测试使用临时数据与任务所属资源。
模型投影覆盖 0..128 字节预算、跨片段 UTF-8、非法 UTF-8、双流滚动窗口、原始长度和唯一省略行。
缺少 Producer 回执的模拟后端必须返回失败，且归档调用次数为零。

仍需区分既有边界：远端文件系统写/flush 故障没有可重放的客户端完整捕获计划，本轮不伪造恢复义务或重新执行
命令；未确认捕获不会归档为完整。通用 SQLite writer 启动时仍加载全部不可变资源并线性计算资源 ordinal，
因此本次点查优化不意味着整个后端已具备恒定内存。内部 Git 执行仍按其既有接口收集完整 stdout/stderr，
其内存行为与有界 exec 投影不同。本轮不把这些既有边界写成已解决能力。
